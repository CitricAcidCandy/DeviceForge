# Rust 后端开发要求

## 范围与落点
- 当前项目为 `G:\Rust\DeviceForge\backend`。旧 Electron 工程仅用于取证，不向旧工程写入重写实现。
- 后端文档只放 `docs/`，前端文档和页面不得混入后端。注释、README 和说明使用中文与 UTF-8。
- 先查看 `docs/guides/架构与开发约束.md`、`docs/guides/迁移清单.md` 与相关接口文档，再实施能力。不可把旧 IPC 逐行转译为 Rust。

## 依赖与文件职责
- `domain`：实体、规则、错误、可替换端口；不依赖 HTTP、数据库、工具进程和宿主插件实现。
- `application`：用例、贡献注册、输入验证、任务生命周期；生产依赖不引用 infrastructure，通过领域端口接收适配器。
- `infrastructure`：实现领域端口，独占进程、文件、数据库等副作用；规则、解析与编排分文件，禁止万能工具模块。
- `server`：HTTP/MCP 边界与通用端口装配；既有平台装配按迁移清单迁出，不在通用任务路由编写业务分支。
- `plugin-sdk` 与 `data-codec`：独立公开契约和纯编解码；`plugin-runtime`：公开异步任务插件运行库，负责有界传输、合作取消与清理确认。以上公共模块不得依赖宿主内部模块。
- `tool-process`：独立公共异步工具执行、限额、绝对截止点和直接进程清理；不包含平台命令或协议帧。只允许基础设施和独立插件引用，领域/用例继续通过端口调用；丢弃 Future 不表示清理已确认。
- `android-package-core`：独立归档与 Android 包规则，不依赖宿主、SDK、Tokio、进程、HTTP 或数据库；只允许基础设施薄适配和独立插件消费。同步文件操作须由调用者放入受限工作池，传递原绝对截止点和只读取消回调；库不创建任务、分配产物 ID 或删除调用者目录。具体 profile、CRC 和资源规则遵守 `docs/implementation/包工具公共库第一批实施裁定.md`。
- `plugins/`：独立进程插件，生产依赖通过公开 SDK 和公共库接入，不引用宿主 domain/application/infrastructure/server；集成测试可以使用宿主。
- 新增模块先明确输入、输出、副作用和职责；跨模块变更先核对端口与调用关系。新增模块附中文 README 和关键行为测试。

## 基础平台与设备插件边界
- 开发前阅读 `docs/implementation/设备适配器插件架构.md` 与 `docs/implementation/设备提供者第一阶段实施.md`。离散设备第一阶段已有公开声明、目录、能力路由和原任务生命周期实现；实际验收以根 todo.md 为准。平台迁出、常驻会话、iOS 和真机仍未完成。
- 当前直接装配的设备实现是待迁移边界，不作为新增平台的模板。新增平台通过公开版本化设备提供者契约接入，不给 `DeviceTools` 或通用路由增加平台分支。
- 设备身份带提供者归属，能力支持与当前可用状态分开；同设备写操作在宿主统一互斥。不得用平台名称推断全部能力，不得按加载顺序覆盖提供者或静默回退到内置工具。
- 平台插件只依赖公开 SDK/公共库；通用宿主不得导入具体插件或直接调用平台工具。现有代码按迁移步骤收敛，并同步更新架构门禁，不能只移动文件就宣称完成插件化。
- 离散操作和常驻会话分别定义传输与资源所有权；开发前阅读 `docs/guides/运行中插件生命周期.md`。设备第一阶段复用通用插件的代际、取消与清理，新增贡献必须纳入所有权和目录撤销；每任务一个进程不表示常驻会话已完成。
- 空插件部署仍能启动、第三方模拟平台无需修改宿主可接入，作为设备插件化的必要验收；各平台真机和宿主系统支持另行验证。

## 契约、资源与执行
- 服务器固定采用 Tokio 多线程运行时与 Axum 异步框架，HTTP/MCP、插件传输和设备会话使用异步 I/O。不得用同步框架或在调度线程执行阻塞存储、文件与 CPU 密集解析；阻塞池、请求、任务及缓冲均须有界并实测尾延迟。
- 新 HTTP 客户端使用 `/api/v2`：成功 `{log_id,data}`，失败 `{log_id,error:{code,message}}`。`/api/v1` 保留实体/数组兼容；产物字节和标准 OpenAPI 保留原格式，关联头始终存在。OpenAPI 从 Rust 类型生成，HTTP 与 MCP 共用操作注册及任务层。
- 浏览器传产物 ID 和业务参数；工具路径、签名材料由部署者配置。在线插件安装接受包内容并从包内映射入口，不接受任意服务器目的路径或 shell 字符串；普通业务请求不选择服务器程序。
- 工具调用使用独立 argv；定义总期限、并发、输入/输出/结构上限，以及取消、Future 丢弃和服务退出后的清理。
- 阻塞文件、解析和数据库操作放入受限阻塞任务，禁止在异步调度线程长时间持锁或运行阻塞工作。
- 默认免鉴权，APK_API_TOKEN 可选，配置后执行令牌检查；不增加多用户权限或强制隔离。令牌和签名凭据不进入日志、任务结果或插件环境；在线插件按可信代码运行，不能宣称独立进程就是系统沙箱。
- 在线安装与部署删除遵守 `docs/implementation/在线插件安装架构.md`；安装、加载、运行卸载和部署删除分别记录，包发布原子化，删除不得与正在加载/执行的插件竞争。
- 任务终态不可被晚到结果覆盖，恢复逻辑不假装续跑旧进程。资源边界与数值精度必须有失败路径测试。
- 需要释放外部资源的任务插件遵守 `docs/contracts/合作取消插件协议.md`：协议 3 仍是每任务一个进程，保持输入流并发送取消控制；协议 1/2 兼容原行为。匹配响应、零退出与明确清理确认全部成立才确认资源已释放；无确认、清理失败或 Future 丢弃必须保留未确认标记。
- 需要本地执行上下文的独立插件遵守 `docs/implementation/插件执行上下文第四版裁定.md`，通过清单协议4显式接入Ready/Start及公开InvocationContext。C0固定在Ready发送前，Start等待消耗预算，不序列化Instant或接收后重启计时；本地检查与定时器使用同一单调时钟。旧协议1/2/3字节和处理器签名保持兼容，协议4不表示平台迁出已完成，资源确认仍独立验收。
- 历史 cleanup_failed/unresolved 只作告警，不得阻止独立新提交、排队任务、设备发现、性能采集、会话或真实排空后的重载，不得覆盖其他调用的成功。本次真实清理失败仍记录失败；新成功不清零旧诊断。禁止以重启服务或先点恢复作为正常使用前提。
- 后台恢复不得冻结普通准入或要求全插件债务先归零。只有实际活动进程、文件锁、同设备独占资源与真实容量可以形成相应范围的冲突；恢复任务间可合并或互斥，但不能据 recovering 布尔值禁用无关业务。确认直接进程退出且调用持有者结束后释放不再需要的工具读锁，外部债务进入独立有界历史，不占活动额度；退出不等于外部资源已释放。
- 所有宿主可等待的业务、清理与后台续办均需固定期限、有限重试和退出路径；按调用身份、设备及代际隔离旧债务，恢复确认只覆盖开始时的快照，不能清除新风险或新租约。详细裁定见 docs/implementation/资源故障隔离与后台回收裁定.md，实施导航见 docs/implementation/历史清理告警与新任务解耦.md；投屏内部由用户指定的其他代理独立处理。
- 完整日志框架由公共 observability 模块提供，开发前遵守 `docs/contracts/日志与关联契约.md`。MCP 使用标准兼容的元数据，二进制响应使用关联响应头。契约变更先定义版本兼容，不能静默改变现有数组响应或 JSON-RPC 结构。
- 日志关联请求、任务和插件调用；有界非阻塞写入须定义溢出、丢弃计数、轮转、保留和退出刷新。禁止直接记录令牌、签名材料、原始请求体或任意插件输出，以实测证明性能，不能以启用 tracing 声称完成。

## 必须执行的门禁
在后端目录执行并确认退出码；任一失败不得写成验证通过：
1. `node scripts/check-architecture.mjs`
2. `node --test scripts/architecture.test.mjs`
3. `cargo fmt --all -- --check`
4. `cargo clippy --workspace --all-targets -- -D warnings`
5. `cargo test --workspace`
6. `cargo build --workspace`
7. 涉及服务、插件或跨层契约时：`node scripts/runtime-smoke.mjs` 和 `node scripts/runtime-smoke.mjs --performance-plugin`。
8. 涉及日志、响应关联或退出：`node scripts/logging-smoke.mjs`；发布使用 `--release`。性能结论还需 `cargo run --release -p deviceforge-observability --example logging_bench`，明确构建模式和测量范围。
9. 涉及注册、插件管理或取消清理：`node scripts/plugin-lifecycle-smoke.mjs`；发布重建后另执行 `--release`，不得以旧运行包通过替代当前代码验证。
10. 涉及协议 3 或外部资源清理：`node scripts/cooperative-smoke.mjs`；发布重建后另执行 `--release`，覆盖合作确认、清理失败与无响应，HTTP/MCP 必须共享结果。
11. 涉及在线包安装、删除或静态资源：`node scripts/online-plugins-smoke.mjs`；发布重建后另执行 `--release`。覆盖真实上传、HTTP/MCP、安装失败无残留、运行删除保护与资源原字节。
12. 涉及设备提供者：在项目根目录执行 `node scripts/device-provider-smoke.mjs`；发布重建后另执行 `node scripts/device-provider-smoke.mjs --release`。使用第三方模拟提供者验证 HTTP/MCP、身份、精确错误、共享锁、取消和热装卸；不能代替平台真机验收。
13. 涉及嵌套输入产物：在项目根执行 `node scripts/nested-device-artifacts-smoke.mjs`，发布重建后追加 `--release`；真实 npx 验收还须安装两协议包并验证新声明、副本、输出、取消和代际，不以旧回显插件替代。

架构门禁检查生产依赖、公开 SDK 和路径边界；它不能代替线程、资源释放、真实性能及真机测试。报告区分编译/静态检查、模拟工具集成、真实设备与性能验收。
