# 剩余包操作独立验收矩阵

状态：独立验收设计，未实现本矩阵的测试，未运行构建、工具或服务。日期：2026-10-10。前三项 PackageAnalyzer 的 28 个公开 context 黑盒测试已独立冻结，真实结果由主代理验收；本文继续覆盖剩余四操作，不修改该测试写集，也不把它的计划数或将来的通过结果借记到本矩阵。

## 范围、输入与实际发现

规则来自 [包工具公共库第一批实施裁定](包工具公共库第一批实施裁定.md)、[普通操作总期限第一批契约](普通操作总期限第一批契约.md) 与 [包核心薄适配独立验收矩阵](包核心薄适配独立验收矩阵.md)。四项为 `android.package.build_apks`、`android.package.decode`、`android.package.scan_sdks`、`android.package.extract_splits`。Split 的设备安装不在普通包操作范围，不能以这一批取消/排空证明设备事务或真机安装。

Galileo 已发现 Bundle/Reverse/Split 清理失败被转换或丢弃的路径；本矩阵承接该缺陷，不重复登记另一编号。定点源码对照如下，仅说明设计时的旧路径，不宣称未来修复已经落盘或通过：

| 来源 | 已读的旧转换/编排 | 独立回归要求 |
| --- | --- | --- |
| `process.rs::map_error` | 公共 tool-process 的 CleanupFailed 映射到领域 CleanupFailed；其 cause 不应替代清理风险 | 保留该错误经过后续业务层，不回退 Timeout/Cancelled/Dependency |
| `bundles/mod.rs` 工具返回分支 | 显式保留 Cancelled/Timeout，其余归固定 Dependency；monitor 分支等待 running 后丢弃其结果 | 工具 CleanupFailed 精确透传；monitor 首因与清理结果分别记录，清理失败不得被 monitor 首因覆盖 |
| `reverse/mod.rs` decode | 正常工具分支传播错误，但 monitor 取消工具后丢弃 running 结果；后续打包/发布另有等待窗口 | 正常与 monitor 两路分别验证；清理未确认不得推进打包/发布或以提前返回称排空 |
| `splits/mod.rs::tool_error` 及 extract monitor | 仅保留 Cancelled/Timeout，其他转 Dependency；monitor 同样丢弃 running 结果 | 精确透传 CleanupFailed；不能把此修复自动计为 install-apks 真机验收 |

原源码定位由主代理/Galileo负责修复与版本登记，测试助理不改私有转换函数。新四操作 context 的公开签名尚未在本任务冻结；实施前由主代理明确增量，测试不得猜函数名、字段、注册预算或添加私有 hook。

## 观测模型与最小夹具

使用本次独立 TempDir、真实 FileArtifacts 种子和公开 ArtifactStore 包装。种子上传与验收下载直接走 inner；计数区分 download 进入、流实际首块、put 进入与 put 完成。工具拥有唯一控制目录，记录实际 argv、输入副本路径、本次 PID 与原子 ready，hold 到 release 或宿主取消；只探测本次直接 PID，不强杀未知进程，也不推断 Java 子树或共享 daemon 排空。

| 夹具 | 最小正向与坏样本 | 独立预期来源 |
| --- | --- | --- |
| Bundle 工具 | default/universal 生成带非空 toc 与符合模式 APK 标识的 APKS；坏 CRC、重复成员、空 toc、无 APK 标识及 universal 多 APK 分开 | 固定输入字节、预期成员、模式与数量，不调用核心生成预期。模拟 ZIP 标识不证明内层 APK 全 CRC、签名或可安装 |
| Reverse 工具 | 先进入运行态但必需文件尚未写，再生成非空 apktool.yml/AndroidManifest.xml 和固定 smali/资源；另有缺项、超量、链接或长度变化 | 固定目录文件与内容、排序摘要；运行监测和最终资格分别断言，不用最终规则提前拒绝合法在途目录 |
| SDK 目录 | 固定反编译 ZIP，smali 与 smali_classes2、内部类、前缀邻居、检测点和超过十条证据 | 预写规则/完整 findings；不依赖另一个 scan 实现，不把路径发现称内容 CRC/DEX/版本分析 |
| Split 工具 | 有效 APKS + 合法离线 DeviceSpec，生成固定两个结构 APK；空目录、非 APK、坏容器、额度超限分开 | 原 device_spec、排序 apk_entries、下载 ZIP 内容；结构 ZIP.apk 是结构正向，不证明 bundletool 真实设备匹配或安装 |

可只读复用已冻结的三操作 store/门闩/PID辅助和旧工具样本；获源码写权前不更改共享 helper、不复制整套宿主 smoke。不依赖公共核心的 ZIP writer 生成正向，CRC/长度坏样本注明改动位置与唯一破坏条件，避免先在安装/上传阶段失败而未到目标执行分支。

## CleanupFailed 透传与禁止发布

这里的清理失败必须来自真实返回的领域 `Error::CleanupFailed`，或生产负责人覆盖实际转换函数的定向测试；不能让工具打印 `cleanup_failed` 字符串、普通非零退出、ready 超时或 kill 意图冒充该变体。直接 ToolCommand 没有公开可注入工具执行端口，确定性 CleanupFailed 的独立黑盒触发方式仍需冻结。没有该触发方式时，精确映射由作者私有定向测试证明，独立集成保持“未覆盖”，不能借协议 3 的另一执行器路径关闭本适配分支。

| 编号 | 触发/门闩顺序与适用操作 | 精确断言与证据 |
| --- | --- | --- |
| RC-01 工具终态 | build/decode/extract_splits 工具 ready 后已生成足以成功的有限输出，清理接口返回 CleanupFailed | 公开执行结果只能 CleanupFailed，不能 Dependency/Timeout/Cancelled 或业务成功；后续校验/打包不启动、put=0/完成=0。只有零 put 的 scan 不用来代签这三项 |
| RC-02 monitor 首因 | 输出类型/额度使 monitor 已观察到失败，再请求工具取消；工具清理返回 CleanupFailed | monitor 首因单列有限诊断，执行保留 CleanupFailed；不得丢弃 running 收尾。put=0，资源未确认仍归实际 tracker/owner |
| RC-03 成功/失败对照 | 同一合法输出配套清理成功与清理失败两次独立运行 | 成功路径可验证并发布一个真实产物；失败路径不进入发布。两次 PID/目录分别记录，不能因失败本来就没有输出而虚假证明“禁止发布” |
| RC-04 外层取消/到期 | 已启动工具，cancel 或原 D 先结束业务资格，但实际清理随后失败 | 完成路径保留未确认风险，不能把外层 select 的 Cancelled/Timeout 当作确认排空。已提交终态不覆盖，风险与原首因分开记录；精确 Job/owner 落点由所属契约裁定 |
| RC-05 晚结果 | CleanupFailed 已确定后工具或 worker 晚到成功；后续新调用或队列获槽 | 不启动下一阶段或发布，不清除未确认状态；另一任务成功也不清除风险。普通 Job 队列是否受该旧适配资源状态阻止须关联实际执行器装配，不猜私有 owner 字段 |
| RC-06 scan 无工具 | scan 的准备/同步工作失败或被取消，不创建外部工具 | 不编造不存在的工具清理证明。若上游公开返回 CleanupFailed，精确保留且不开始新扫描；路径失败与清理失败变体分开，无 put/无伪成功 findings |

“禁止发布”在清理失败已知且 put 未开始时要求零 put；如果不可中断发布在失败确定前已经实际开始，则继续受跟踪、禁止最终成功和后续发布，不能宣称全部回滚或删除无关已发布产物。同步库没有 CleanupFailed 变体，不在核心解析错误表中吞掉资源风险。

## 四操作原 D、取消与公开队列矩阵

普通准入 D 贯穿提交存储、排队、准备、工具、同步核心、转换、发布和成功资格。预先取得注册快照和 effective budget，不把起点挪到 worker。Some(D) 不被旧 120 秒阶段刷新或截短；局部工具限额只能收紧到不晚于 D。设备 install 使用自己的预算，不借这四操作的普通默认值。

受控场景在每个公开入口记录原 context D；entered/release 来自 ArtifactStore、真实工具或公开测试执行器，观察循环持续可运行。若只有私有池或同步函数内部能定位该点，沿作者受控单测证明，不写第二套私有 Pool 测试。暂停 Tokio 时间只证明宿主调度；std Control 与真实文件/工具墙钟另计，不能把虚拟 61 秒冒称真实实耗时。

| 编号 | 适用操作 / 门闩 | 精确判据 |
| --- | --- | --- |
| RD-01 预过期/预取消 | 四项合法输入，原 D 已过或仅 token 已取消 | Timeout/Cancelled 精确区分，同时过期时 Timeout 优先；download、工具、同步首执行、put 均零。实际公共接缝冻结后才实施，不仅读取预算声明 |
| RD-02 准备耗时 | 四项 download 返回前或首块 hold，消耗部分 D 后 release；另有直到 D 的对照 | 后续仍沿同一 D。准备直到 D 时零工具/后续 worker/put；已有实际下载受跟踪，不声称数据库或文件零 I/O |
| RD-03 工具余量 | build/decode/extract_splits 准备先消耗预算，实际工具 ready 后仍 hold | 到原 D 严格 Timeout，直接 PID/工具跟踪分别排空；不重获旧 120 秒。D 前主动 cancel 保持 Cancelled，清理失败单独保留 CleanupFailed 风险 |
| RD-04 多个同步阶段 | build 完整 APKS 校验；decode 监测→最终规则→pack；scan 目录→规则扫描；extract_splits 源资格→Spec→monitor→pack | 原 D 在所有阶段不变，控制只读共享取消状态；到期不进下一阶段。成功摘要必须经过完整校验，未读 CRC 的路径扫描不冒称全部成员通过 |
| RD-05 发布余量 | build/decode/extract_splits 有完整合法输出，put entered 但未真实发布时到 D/主动取消 | 原 D 到期 Timeout，D 前取消 Cancelled；未开始实际发布则 completed=0，放开门闩不晚补跑，最终不成功。scan 正向和反向都 put=0 |
| RD-06 有效成功对照 | 四项各一次足够预算与已知输入，无清理风险 | 旧完整业务值、真实产物和单次调用正确；不靠延长生产 D 消除先前失败，不用错误码任意集合通过 |
| RQ-01 排队扣时 | 公开 Application 单 worker，A 在受控 Executor entered，B 四项分别入队；B 原 D 先到再放行 A | B 零实际 executor 首 poll/工具/put，精确 Timeout 诊断与终态按公开 Job 查询，原 input/id 保留；不以当前目录反补历史预算 |
| RQ-02 排队取消 | 同 RQ-01，B 在 D 前显式 cancel 后释放 A | B 不执行、不补跑、终态 CAS 不被晚成功覆盖；A 的物理工作跟踪独立，不用 B 的取消释放 A 许可 |
| RQ-03 清理风险与队列 | 实际拥有者的 A 标记未确认清理，B 尚未启动；新提交、获槽、卸载/重载分别覆盖 | 按真实 owner/执行器装配拒绝执行，不能清掉风险。旧直接适配没有可查 owner 时只证明其本身风险，不借另一个 ProcessPlugin 代签本路径 |
| RQ-04 成功资格 | 有效结果返回后等待终态存储槽；cancel/到期先于 claim，另有 claim 先于 cancel 两对照 | 资格前拒绝成功；已 claim 不可中断事务允许晚收敛，cancel 等其结果，不抢写 Cancelled。主代理已有内部 completion/CAS 测试关联版本，独立测试只走公开入口 |

RQ 用例可以由公开 Executor 包装真实四操作：先记录首 poll，再委托已冻结 context 入口，不用假执行器单独成功冒充工具链。队列自身通用预算策略已有普通任务测试时只关联它的原输入与结果，新增独立证明必须包含实际四操作 target，不机械复制私有单测。

## 许可/lease 关联和真实运行层次

私有共享池容量、等待者取消、Drop 后许可与目录 lease 到真实 worker 结束，由主代理的实际装配单测负责，本矩阵不复制 Pool 内部字段或添加 hook。公开四操作取消/Drop 时记录尚在途的工具、worker/发布和未确认资源；若公开接口无法区分物理退出，保持该观测未覆盖，不能把 Future 结束当清理完成。

后续根 smoke 写权另分配：HTTP/MCP 查同一 Job/历史和日志 ID，下载三种产物；协议 3 的控制 id/reason、匹配响应、zero exit 与 cleanup complete 分别实核，protocol 2 只记录直接 PID 退出；真实工具和已知 APK/AAB/APKS 样本再做 Android 语义对照。npx 使用当次原 TGZ 压缩 SHA、全部实际成员、shim 解析目标和真实 runtime 身份，不固定成员数、不用同源重打包替代。正向/受控失败均确认自有进程与两端口正常结束，失败保留原 stage/request/temp/样本与脱敏日志。

本地/线上错误层分别记录：坏业务输入可能提交前 Invalid，已创建 Job 的业务失败不改称 HTTP 包安装 400；MCP structured error 遵所属冻结 code，协议解码错误不冒充领域错误。没有新四操作 context 和部署/绑定契约时，不猜对应请求路径或传私有预算字段。
