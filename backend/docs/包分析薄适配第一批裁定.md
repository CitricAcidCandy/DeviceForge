# 包分析薄适配第一批裁定

日期：2026-10-10。模式：architecture-first，按 Hybrid 顺序验证契约接线与真实文件失败路径后集成。整体迁移已获授权，本文明确本批可实施边界，不新增确认流程。

## 目标与选择

先替换 manifest/signature 的重复解析和 extract_apk 的归档复制，保持原操作、输入模式及宿主 DTO；通过新增默认兼容 context 入口把 application 原标准库截止点传到副本、工具、核心和发布。选择独立薄适配与受限 worker，避免把解析规则继续留在异步工具编排中。七平台包操作与独立插件迁出继续后续实施，本批不修改另外四项或跨进程 SDK。

| 单元与所有者 | 职责、输入输出 | 副作用与边界 |
| --- | --- | --- |
| domain/packages，Galileo | 默认兼容三 context 方法及清理观测，接原 ExecutionContext | 不导入核心，不创建线程或刷新截止点 |
| application/packages，Galileo | 三操作传递原 context、原输入校验与 JSON DTO | 不执行工具或同步解析，旧 execute 委托 None |
| infrastructure/package_tools，主代理 | 核心值到旧 DTO、场景错误、副本/工具/复制/发布接线 | 同步核心只在受限 worker 执行；工具 argv 及部署来源保留 |
| package_tools/worker，主代理 | 最多四个真实阻塞工作、取消/截止点复核、工作退出观测 | permit 与目录 lease 由闭包保留；丢弃等待不释放实际许可 |
| server 与已有适配器测试构造，主代理 | 使用显式构造器建立工作池 | 不撤除平台装配或改变启动契约 |
| 独立接缝验收，Kuhn | 原输出/错误、原 D、取消及实际 worker lease | 不按猜测修改生产实现，不以纯解析证明真机 |

已有 package_tools/mod.rs 同时承担工具与复制细节，先拆出 worker 与 extract；manifest/signature 文件只保留 DTO 映射，删除旧解析循环。核心依赖只从 infrastructure 引用，架构白名单已允许该方向。

## 本批约束

- 新方法为 manifest_with_context、signature_with_context、extract_apk_with_context，末参数 ExecutionContext；默认实现委托旧方法。has_unresolved_resources 默认 false；PackageOperations 转发。不改既有 HTTP/MCP 字段。
- Some(D) 只转换时钟类型；input materialize_until、工具 run_until、worker Control 和发布前后复核都共享 D。None 保持旧调用约定，兼容阶段仍保留原 120 秒上限，不能称跨进程同 D 已完成。
- XML/签名无效保持既有 Dependency 文案，文本/节点上限 TooLarge；版本字符串、None、排序、原 XML/report 与标识字段保持。新 XML 实体拒绝不兼容旧缺陷。
- 输入归档全目录重名先拒绝，再精确选择；保持原缺失/重复及复制错误场景，create_new 输出、64 MiB 与 EOF/长度/CRC 检查。结构上限与复制上限分开映射。
- 每个 worker 状态跟踪实际闭包结束。取消由只读令牌观察；Future 丢弃发送取消，等待已丢弃而闭包尚未结束时报告未确认。普通执行中的其他 worker 不应被误判为清理失败。
- 目录 lease、许可及文件句柄移入闭包，先结束文件 I/O 再释放。核心 Archive 的输入是校验后私有副本，生命周期内不由工具改写。
- worker 的退出证据只覆盖阻塞闭包；Temporary 尽力删除、Java 派生树与任意设备资源继续独立跟踪，不借记为完整平台清理。

## 验证与写集

当前审查补充：package_tools/tool.rs 独占部署命令、截止点选择与直接进程清理观测，mod.rs 保留三操作编排；公开 ToolCommand 路径通过重导出保持兼容。Some(D) 工具阶段不截短到 120 秒，只有 None 使用兼容期限。每实例工具未确认标记在 Future 丢弃或 CleanupFailed 后保留，正常并发工具与已确认的普通失败不置位，后续成功不能清零；该标记不证明派生树和临时目录排空。按原裁定 architecture-first/Hybrid 实施，先验证原 D 与实际 Future 丢弃，再补完整门禁，不新增公开接口或鉴权。

Galileo 只写 domain/packages/mod.rs、application/packages/mod.rs、其 context 测试与所属 README；主代理只写 infrastructure 包适配与构造接入、Cargo/lock 和共同记录。Kuhn 的独立测试另授权新增文件，已有核心及验收测试冻结。前端 acceptance 独立推进。

必须验证：三 context 流实际收到同 D，旧仅实现者仍兼容；预过期/取消零端口调用；XML 三原缺陷经旧宿主 DTO 适配得到正确结果/错误；真实归档复制/CRC与重复；四 worker 占满后取消等待者不启动且不释放实际许可，Drop 后目录仍由线程持有并在真实结束后释放。取得新输入摘要后执行完整后端门禁及受影响运行集成，不能借记此前 520 项门禁。
