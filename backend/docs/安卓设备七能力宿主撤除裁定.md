# 安卓设备七能力宿主撤除裁定

日期：2026-10-10。实施模式：先确定架构再实现。依据《安卓设备插件第一批实施裁定》与《安卓设备七能力宿主撤除接缝》，本裁定允许本批实际源码实施；通过证据由根 todo.md 独立记录。

目标是将首批八个 Android 入口从 server 的内置装配撤除，通过独立 android-device 插件及公开设备契约提供。通用 HTTP/MCP、任务、设备目录、锁与插件生命周期保持所属职责。旧名称仅由显式格式2绑定恢复；插件缺失或卸载时无内置回退。安装、截图、APKS、性能及 Harmony 属于后续迁出范围。

选择专用残余执行器，而非为旧通用执行器增加可配置黑名单：固定白名单能够同时约束贡献发布和直接执行，防止后续旧贡献自动暴露。旧完整实现暂留兼容测试，不能再装配到生产宿主。无需新增公开协议、Cargo依赖或平台路由。

| 单元 | 责任与输入输出 | 副作用与边界 | 写入归属 |
| --- | --- | --- | --- |
| devices/harmony.rs 与所属测试 | HarmonyDeviceTools仅接收hdc，声明并执行harmony.devices和harmony.packages，保留原结果 | 固定HDC argv；不构造ADB命令、不增加平台选择参数 | 后端代理 |
| devices.rs | 导出专用执行器，按需共享已有HDC纯规则 | 保留旧Android兼容实现；不得覆盖其它改动 | 后端代理 |
| device_artifacts/remaining.rs 与所属测试 | RemainingDeviceArtifactActions私有封装旧执行器；四项固定白名单、两个执行入口均先验证再委托 | 仅Android安装/截图、Harmony安装/卸载；原context、result_format和资源观测转发，不补称底层清理已完善 | 后端代理 |
| device_artifacts/mod.rs 与所属README | 导出侧车、说明生产装配与旧兼容实现 | 不扩展本批安装期限、目录或锁承诺 | 后端代理 |
| server/main.rs | DeviceTools换为HarmonyDeviceTools，产物执行器换为残余侧车，停止InputOperations装配 | 保留APKS安装、性能、通用产物与三处残余APK_ADB消费；不导入具体插件crate | 主代理 |
| 新设备独立原帧测试与根服务驱动 | 手工协议帧、假ADB、实际宿主HTTP/MCP与装卸证据 | 生产与夹具互不导入；不代表真机、共享daemon或派生树验收 | 测试助理；命令由主代理执行 |

开发顺序采用契约先行与行为验收结合：先冻结两专用执行器及回归，再替换main，随后使用同一新二进制验证空首批插件部署、正式安装加载、八贡献与七能力、旧绑定、精确失败、锁和热卸载。普通缺陷逐验收项回流，阻断立即回流；测试期间只冻结实际读入范围。

最低证据包含：两HDC贡献的原行为；四残余流通过新侧车执行且被撤卸载两个入口零副作用；真实main未加载/卸载后的八旧名缺失与404/not_found；加载后当前owner/generation及无重复声明；三种发现入口各一Job/一次工具；HTTP/MCP同任务历史、明确日志ID、正常退出与端口释放。完整前后端门禁、新release、实际原包/npx另行验证。安装/截图/APKS/性能尚未进入新设备锁的缺口继续保留，不以本批八入口迁出覆盖整个设备层。
