## 七操作的最小业务对照

所有成功对照使用固定输入及独立预期值，不用新旧实现互相调用产生期望。产物 ID 每次新分配，比较来源、名称、大小、摘要与下载字节，不强求随机 ID 相等。数据库 ID、临时目录等不稳定值单列实际观测，不能把整个结果随意删字段后称等价。

| 编号 / 旧操作 | 最小正反样本与旧值断言 | 公共核心与边界 |
| --- | --- | --- |
| PA-01 `android.package.manifest` | APK 清单保留源 `artifact_id`、`format=apk`、`module=None`；AAB 省略 module 取 base，显式合法 module 原样保留；APK 带 module 和非法 AAB module 精确拒绝；版本和 SDK 字段保持字符串/None，权限排序去重及 XML 原文不丢 | `parse_manifest` 的结果没有源 ID/format/module，适配只从合法输入补归属。Android 命名空间、等价实体 URI、未定义实体和重复属性回归继续关联核心样本；不做资源标签求值 |
| PA-02 `android.package.signature` | APK 正向完整 `verified/signers/schemes/report`；警告保留，临时输入路径换展示名称；无 Verifies、无成功方案、签名者编号缺口或坏 SHA 精确失败，退出 0 不代替解析成功 | `parse_signature` 不分配源 ID；签名材料路径/密码不得进入结果、请求或日志。本项不扩展到 AAB JAR 或 APKS 所有分包验签 |
| PA-03 `android.package.extract_apk` | APKS 精确唯一 APK 成员成功，保留 `source_artifact_id/entry`；缺项、重复、非法相对名、选中 CRC/长度坏、输出不是结构 ZIP 分别拒绝；不存在/多匹配时目标尚未创建 | `Archive::open` 只作结构，`select_exact/copy_to` 才证明选中流完整。固定输出 `extracted.apk` 来自真实发布；未选中坏 CRC 不假称整包通过 |
| PA-04 `android.package.extract_splits` | 合法离线 DeviceSpec 原样映射，结果 `apk_entries` 排序；错误列表/数值先拒绝；输出空目录、非 APK、坏 APK 容器和超额树失败；发布 `selected-apks.zip` | Splits 的 1000 条、128 层和 64 MiB 规则独立于 Reverse。任意合法结构 ZIP 的 `.apk` 仅为结构正向，不证明可安装；不发现设备、不执行安装 |
| PA-05 `android.package.build_apks` | AAB default/universal 分别保留 `mode/source_artifact_id`、`apk_count/universal_entry`；缺 toc、重名、外层任一坏 CRC/长度、无 APK 标识或 universal 多项拒绝；发布 `built.apks` | `validate_apks` 完整读外层，累计展开限 256 MiB；不解析 toc 设备匹配，不证明 APK 内层全 CRC 或签名。缺部署签名/工具错误按确定阶段对照 |
| PA-06 `android.package.decode` | 模拟 Apktool 生成有效目录后发布 `decoded.zip`，核对 `source_artifact_id/files/unpacked_size`；运行中尚无必需文件仍可监测，最终缺/空必需项或超量、链接、源变化拒绝 | Reverse 的 10000 条、128 层、源总量与最终 ZIP 各 64 MiB；监测、最终必要项与打包是不同资格。framework 缓存不冒称已在输出树额度内 |
| PA-07 `android.package.scan_sdks` | 有效反编译 ZIP，规则与 `findings` 完整对照；smali 多 DEX、内部类、包前缀、检测点及最多十条排序证据；缺必要项或非法/重复规则拒绝，无产物发布 | 只观测目录路径，不读 DEX 或证明 SDK 版本。源 `artifact_id` 从合法输入补；smali 未读正文不能称该成员 CRC 已校验 |

七项只是迁出边界清单。第一段测试仅 PA-01/02/03；PA-04 至 PA-07 待各适配接口和写集冻结后实施。`install-apks`、设备锁、设备发现、常驻连接与真机不计入纯包薄适配，也不得因删除旧模块而一起误撤。

## 精确错误与失败阶段

核心错误与旧领域错误分别断言，不能接受“任意错误”、任意 4xx 或 open/copy 二择一通过。对外执行失败仍沿原 Job 生命周期，不把已经创建的任务错误改成包安装或请求提交错误。下面类别是对照目标；迁移后的具体适配函数、文案和少数阶段特例仍须冻结，不由测试助理代写默认映射。

| 编号 | 固定坏样本 / 阶段 | 核心精确结果与旧行为对照目标 |
| --- | --- | --- |
| PE-01 | 不安全精确名、坏路径/目录、ZIP64/分卷 | 核心 `InvalidArgument` 或明确发生在 open 的 `InvalidArchive`，每个样本固定其中一个；旧参数/容器错误为 `Invalid`，保留旧阶段文案 |
| PE-02 | 精确缺项 / 同名多项 | 核心分别 `EntryMissing` / `EntryDuplicate`；旧分别 `NotFound("APKS 内不存在指定 APK 条目")` / `Invalid("APKS 包含同名 APK 条目，无法确定选择")`；目标创建、worker 后续和 put 调用均为零 |
| PE-03 | Stored 声明展开 8、压缩 9，CRC 未改 | open 必须 `InvalidArchive("Stored 长度不一致")`，不进入 copy；此阶段由已修正归档测试独立证明，不能借记 thin adapter 已通过 |
| PE-04 | 固定 raw Deflate 实际展开 9、声明 8；选中 CRC 损坏 | open/select 必须成功，copy 只接受 `InvalidArchive` 且无 `CopiedEntry`；旧提取对应有限 `Invalid`，发布零调用；Deflate 固定夹具独立于生产 ZIP writer |
| PE-05 | APK 提取上限、树额度、XML/报告上限 | 核心精确 `LimitExceeded` 的 kind/limit；旧 `TooLarge`。刚好等于/超一必须成对，同一输入其他资格保持有效，避免先命中不相关错误 |
| PE-06 | XML 或签名正文坏但工具退出 0 | 分别 `InvalidManifest` / `InvalidSignature`；旧 `Dependency`，无成功业务值，不随意升级成 Invalid 或工具非零错误 |
| PE-07 | 打包快照后长度或资格变化；读写失败 | 分别 `SourceChanged` / `Io {stage,source}`；旧 `Conflict` / `Storage`。保留底层 I/O 原因用于受控测试，线上不得泄露任意绝对路径 |
| PE-08 | 工具未配置、Spawn/非零、非 UTF-8、两路或文件捕获超限 | 仍由工具执行与调用层适配，不送入核心错误表；明确 Dependency/TooLarge/Cancelled/Timeout 的对应分支，零退出 FAILED 诊断单测，不接受任意字符串 |
| PE-09 | 最终 decode 缺必要成员；scan_sdks 缺必要成员 | 核心 `InvalidArchive("反编译目录缺少必要成员")`；重复/目录/空值为 `InvalidArchive("反编译必要成员必须唯一且非空")`。旧 decode 缺必要文件为 Dependency，旧 scan 为 Invalid，须按业务阶段适配，禁止机械把所有 InvalidArchive 都映射 Invalid |
| PE-10 | 原 D 已过 / 仅显式取消 / 已取消终态后晚到期 | 核心前两项分别 Timeout / Cancelled；宿主已提交 Cancelled 不被晚结果改写。核心没有 CleanupFailed，清理风险归真实资源追踪层，不能靠错误映射抹掉 |

PA-03 应沿用已有固定 Stored 与 raw Deflate 夹具，不复制 ZIP 构造器。CRC 破坏必须只改 payload 或校验值；长度破坏注明 local/central 两字段、真实展开与压缩大小，保留合法原件正向。输出摘要、put 次数、临时文件存在与否分别记录；半文件由本次所有者持有，不以其被删证明复制成功。

## 原截止点与三操作的受控阶段

普通宿主准入使用 `D = min(t_admit + effective_budget, parent_D)`，库接 `Some(D)` 后只检查原点；工具允许 `min(D, t_step + short_limit)` 的局部收紧，不能重获阶段总额。父 D 的内部纯证明由主代理负责，本矩阵不要求私有注入入口。旧端口或直接调用 context None 的兼容模式单列，不能拿它验证宿主总期限。

时间观测统一命名：`t_admit` 为宿主首次存储等待前；`t_prepare_enter/exit` 为输入准备；`t_tool_enter/exit` 为工具；`t_pool_acquired` 为工作池许可；`t_worker_enter/exit` 为同步闭包实工作；`t_put_enter/exit` 为发布；`t_completion_claim` 为成功资格。各阶段若公开接口提供 context，记录其绝对 D 值并逐个等于准入 D；工具局部上界另记录。私有字段不可读取时，先提交最小观测需求，由主代理裁定，不能仅读取常量当贯通证据。

| 编号 | 最小门闩顺序与操作覆盖 | 必须断言 |
| --- | --- | --- |
| PD-01 预过期 | 使用公开新执行入口注入已过 D，分别调用 manifest/signature/extract；预先准备合法业务输入 | ArtifactStore 准备零调用、工具零启动、同步 worker 零首执行、目标零创建、发布零调用，精确 Timeout。接口尚未冻结前不猜函数签名 |
| PD-02 准备扣时 | 输入准备先发 entered，测试在门闩外耗掉部分原预算再 release；manifest/signature 进入工具，extract 进入池/复制 | 下一阶段收到同一 D，只获得剩余时间；到 D 后精确 Timeout，不取得新的 120 秒窗口。准备前到期与准备已实际开始后受跟踪分开 |
| PD-03 工具扣时 | manifest/signature 的模拟工具在 ready 后 hold；在原 D 前放行使解析仍有少量已知余量，另设直到 D 的失败对照 | 工具有独立 argv/实际 PID；原 D 到期停止接受新解析/成功，工具退出与任务终态分开。不能由工具固定 sleep 或看门狗猜阶段开始 |
| PD-04 同步池等待 | extract 的共享池被 A 占满，B 正常准备后等待许可，令 B 的 D 到期再释放 A | B 精确 Timeout，B worker 首执行和目标创建为零；A 结束前容量不凭 B 的取消/Drop 提前增加。若公有接口不能控制池，列为待接缝，不新增私有 hook |
| PD-05 同步 worker 扣时 | extract worker entered 后由受控工作或外部观察门闩暂停，到原 D/取消；闭包尚未 exit 时保留许可与目录 | 无成功 copy 摘要、无 put，新工作受限；原 D 未重置。实际阻塞 I/O 尾部可晚退，Job Timeout 不宣称 worker 已物理停止 |
| PD-06 发布扣时 | extract 完整复制且验证通过，ArtifactStore.put entered 后延迟；D 前成功与 D 到期两对照 | put 共享原 D/剩余预算，晚发布不得令 Job 成功；若不可中断发布已开始则继续跟踪。仅证明阻止后续发布，不声称多产物事务或自动回滚 |
| PD-07 资格前拒成功 | 有效执行结果已就绪，但等待终态存储槽；分别先 cancel 或先到 D，再 release | 不取得成功资格，精确 Cancelled/Timeout，晚成功不得覆盖。复用已有普通 Job 受控存储证据时注明输入版本，不当作三包操作阶段的新证明 |
| PD-08 已 claim 收敛 | 成功资格先 claim，存储事务 entered 后不可中断；cancel 在事务未退时发出，再 release | cancel 必须等待提交结果，允许晚收敛 Succeeded，不能抢写 Cancelled；不得要求已经 claim 的事务物理零 I/O。内部 claim 观察由主代理负责，不猜公共 hook |

纯宿主调度可暂停 Tokio 时钟；std 文件 I/O、同步 Control 和真实工具必须使用匹配的实际单调 D，不能用 `advance` 伪造墙钟消耗。暂停时钟测试明确 Tokio 到 std 的转换及 timer 毫秒刻度，只给观测唤醒刻度，不改变传入原 D。墙钟看门狗仅防止测试永远卡住，不表示尾延迟或性能验收。

## 许可、目录租约与真实结束

测试门闩必须位于可控适配器、存储或测试拥有的工具；`Control` 回调只读共享 Atomic/取消状态，不在回调里查文件元数据、阻塞等待、睡眠或重算 D。需要观察文件进度时，由独立观察线程更新共享状态；它不计为被测 worker，并在测试结束时有界回收。若公开接口不能确定进入/结束点，该项保持未覆盖，先回流需求，不假造内部事件。

| 编号 | 时间点和最小对照 | 物理资源断言 |
| --- | --- | --- |
| PL-01 运行取消 | A 实际持许可与本次目录，entered 后取消；异步调用可先返回，A 的退出门闩暂不放行；B 等同一受限池 | A 未实退前 B 不进入 worker，目录与句柄仍有效；A exit 后才允许 B，许可仅释放一次。取消错误与全部资源排空是两个观测 |
| PL-02 Future 丢弃 | 与 PL-01 相同，但 drop 等待 Future，不主动把闭包等同于取消终态 | tracker 继续持有 A，许可/lease 未提前回收；释放 A 后可正常排空，不留无人跟踪 worker，也不把 drop 返回称 cleanup complete |
| PL-03 排队取消/过期 | B 仅等许可、尚未实际工作；取消或过 D 后释放占池 A | B 零 worker/零目标，不在随后有空槽时重启工作；A 的跟踪与租约不受 B 收尾影响 |
| PL-04 发布持租约 | 完整输出进入受控 put，读取流尚在途时 cancel/到期/drop；删除检查在独立测试线程观察 | 发布真正结束前文件/目录仍归本次所有者；收尾不删除管理员材料、其它任务目录或无关产物。已发布项回收另裁定，不能假称全回滚 |
| PL-05 工具与监测排空 | 后续 decode/splits 工具 ready，监测 worker 也 entered；触发超限/cancel，分别延迟两者结束 | 停止接纳子工作，等待工具直接 PID 与所有 worker，关闭句柄后才清 scratch/报 complete；只停工具或只删目录都不能代替全部确认 |

池的容量、观测入口和 tracker 公共接缝尚需主代理冻结。不得每请求新建池来制造“B 不进入”的假全局限额，也不得仅观察 semaphore 字段变化代替真实 worker 结束。第一段 PL-01/02/03/04 优先使用 extract；manifest/signature 的工具取消另记录直接 PID，纯解析无需假造长 worker。

## 后续真实协议、服务与分发

这些项独立于当前三操作薄适配写集，根脚本未获授权前只保留计划。每层建立实际样本/工具/宿主/插件/归档摘要和运行前后输入清单，不引用另一次打包或旧 binary 代签。

| 编号 | 最小真实验证 | 必须保留的证据和限制 |
| --- | --- | --- |
| PH-01 工具 | 测试拥有的模拟工具先验证 argv、cwd、受限环境、非零/零退出坏文本、捕获限额与取消；再用已知 APK/AAB/APKS 和真实工具版本验证七操作 | 模拟请求/ready/PID/exit 与真实包期望分开；不杀未知 PID、不声称派生树/共享 daemon/设备事务全清理。工具/签名材料配置来自部署者 |
| PH-02 协议 2/3 | 同业务成功/确定失败；协议 3 主动取消和短 D 到期分别匹配控制 id/reason、响应、零退出、cleanup complete；协议 2 单列直接进程终止 | S3 到共享 D 时线上 reason 严格 timeout，不从本地 Cancelled 或 Job 状态反推控制帧。1250 毫秒、500 毫秒、外围 2 秒、卸载 10 秒原门禁不扩大，也不串联成新保证 |
