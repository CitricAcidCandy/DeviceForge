# 旧操作绑定迁出实施

## 状态与实施目标

本文件是 2026-10-09 平台迁出第 2 步的下一批实施建议，采用 architecture-first / Hybrid：先确认绑定、身份和结果兼容，再以替身测试推进独立插件。本文没有冻结新的公共字段、能力 ID、配置格式或服务接口；文中候选名称与新文件写集须由主代理完成契约审核和文件分配后实施。

上位方案见 [平台适配器迁出实施](平台适配器迁出实施.md)。公共工具执行首步已有独立验收记录；能力总期限源码正在本轮统一验收，不能把本文件的静态核对计作其测试结果。本次仅编写实施文档，不改源码，不运行构建、服务或真实进程。

目标是让旧操作和新设备能力在同一次 Job 内共享插件 owner、generation、队列、设备锁、绝对截止点及清理门禁，然后把 Android/Harmony 命令和包处理迁入独立插件。空插件宿主仍能启动；未部署或未加载目标时不发布对应旧入口，不隐式回退内置工具。

## 已核对的当前耦合

以下路径均相对 backend；它们是迁移取证与后续写集，不是本次编辑授权。

| 当前源码 | 实际职责与缺口 |
| --- | --- |
| `crates/server/src/main.rs` | 直接装配 DeviceTools、DeviceArtifactActions、AndroidInput、AndroidSplits、AndroidBundles、AndroidPackageTools、AndroidReverse；默认 AndroidPerformance，读取 ADB/HDC/Java/工具 jar 和签名配置 |
| `crates/application/src/registry.rs`、`registration.rs` | 内置贡献以 owner=None 注册；插件贡献限定自身命名空间，发布/撤销带 owner、代际与目录修订 |
| `crates/application/src/devices/rules.rs` | 根据实际目标 operation 查能力、校验封套和当前目录；owner=None 的旧入口不进入设备锁准入，不能只改显示名称 |
| `crates/application/src/devices/refresh.rs`、`registry.rs` | refresh 同提供者串行，提交发现任务并校验、发布目录；直接提交发现 operation 当前不会自动发布目录 |
| `crates/infrastructure/src/devices.rs` | 8 个发现/连接/应用/列表操作，零退出仍校验失败文本和连接成功文本 |
| `crates/infrastructure/src/device_artifacts/mod.rs` | 5 个安装/卸载/截图操作；安装读取宿主产物，截图直接返回宿主 Artifact 实体 |
| `crates/application/src/{device_input,splits,bundles,packages,reverse}/mod.rs` | 9 个输入、分包安装和纯包操作，通过领域端口调用平台适配器 |
| `crates/application/src/performance/{mod,operations}.rs` | 8 个性能会话操作；服务持有 probe，采样任务及历史由宿主管理 |
| `crates/infrastructure/src/performance_plugin/mod.rs`、`crates/server/src/main.rs` | 所选性能插件绕独立设备准入执行，当前通过 protected 阻止卸载；不能以旧操作别名关闭这个缺口 |

## 操作映射清单

下表覆盖当前 30 个操作：15 个设备操作、7 个纯包操作、8 个性能会话操作。设备表的目标后缀是候选，Android 使用 `plugin.android-device.` 前缀，Harmony 使用 `plugin.harmony-device.` 前缀；插件 ID、能力 ID 和精确版本须另行确认，不从平台字符串推断目标提供者。

设备能力统一映射为 `{device_id,input}`：设备范围使用原 local ID；提供者范围显式 `device_id:null`；input 为业务对象，去掉旧顶层 device_id。发现输入仍为 `{}`，不伪造成普通能力。

## 同一次任务的通用绑定方案

建议在应用注册层保存旧入口与真实目标快照的关联，采用数据化输入/结果转换；宿主转换器不拼命令，也不根据 Android/Harmony 编写工具分支。部署配置显式允许旧名称及其目标，插件只能声明自身 `plugin.<id>.` 操作，不能通过清单自行抢占旧名称。配置来源、保存形式、默认是否启用和内部模型签名均待确认；本批不自增运行期配置 API。

1. 准备加载时编译目标 schema、旧入口 schema 和有限转换规则，确认目标贡献存在、能力精确版本及范围匹配。旧名称重复、与已有内置入口冲突、转换无效或操作总容量超限，均拒绝整次发布；迁移开关与旧实现退出要协调，禁止顺序覆盖。
2. 在现有注册写锁内原子发布目标、别名、owner 和一次 revision 更新；别名持同一 owner 和本代目标快照。卸载按 owner 同时撤销别名、目标及设备目录。加载/卸载、别名变更和包删除沿 PluginService 共用串行变更锁，不能另建可竞争的配置写入路径。
3. 提交时记录准入时刻，校验旧 input、映射业务封套，再校验目标 schema 和标准设备封套。能力范围、访问方式和预算由目标声明决定；校验不以固定 `{}` 或任意 device ID 推断业务 schema 可满足性。
4. 历史 Job 保留客户端提交的 operation/input；内存执行计划持目标 operation、映射 input、owner/代际和结果转换。任务与事件只创建一份，复用同一队列与执行槽。当前按 `registered.operation.id` 查能力和快照的调用处需显式区分入口与目标，不能将目标 Registered 的 id 直接覆盖成旧名称。
5. 对目标执行当前设备准入，获锁后及执行 Future 首次 poll、下一次 I/O 前复核 cancel、deadline、当前 owner/代际及 cleanup_failed。资源锁、产物目录与清理守卫保留到真实退出/清理收敛，Future 被丢弃不等于确认清理。
6. 目标成功且产物发布结束后，按已验证结果规则生成旧格式。失败、取消或超时终态不能被晚到结果覆盖；原任务结果与事件不因卸载或换代重写。执行调用沿 execute_with_context 传递同一绝对截止点。

禁止把别名做成 owner=None 的桥 Executor，再在其 execute 内提交 DeviceService/Job；这会拆成两份任务或在持设备锁、占执行槽后等待自身。也禁止旧 HTTP/MCP 直接调用 ProcessPlugin 绕过应用准入。日志沿原请求/Job/插件调用传播，只记录必要标识，不记录原始输入、凭据或任意工具输出。

## 兼容缺口与必须先确认的契约

### 身份与发现

旧 device_id 只有本地标识。建议按旧入口明确绑定的提供者解析当前代，而新设备 API 继续显式 DeviceRef；两个提供者有同名 local ID 时不得按平台或加载顺序猜测。旧请求只能承诺提交时命中当前代，不能证明旧客户端之前所选代际；若要求客户端防陈旧选择，须另做版本化请求加法，本文不自行添加字段。跨提供者同一物理设备的协调仍未解决。

旧 `android.devices`/`harmony.devices` 必须同一次 Job 复用“发现执行、结果校验、目录发布、旧输出转换”。现 refresh 内已有同提供者串行与发布流程，需要提取共享编排，不能在别名内部调用 refresh 产生第二个 Job。建议声明的发现目标、旧发现入口和 refresh 共用串行门禁与结果后处理；直接 jobs 发现是否同步具有目录发布语义，必须在实施前明确并测试。目录失败沿当前冻结规则清空；取消、到期、卸载后的晚结果不得发布。

旧 Device 的 state 可为 device/offline/unauthorized/recovery/sideload/bootloader；公开 ProvidedDevice 当前只有 online/offline/unauthorized/unknown，没有 raw_state 或 metadata。online 可映射 device，其余细分状态无法无损恢复。必须确认版本化原始状态加法或单独兼容发现结果载荷后，才能声称旧状态等价；不擅自给现 DTO 添字段、不把 unknown 伪装成 device。目录缓存与旧数组应基于同一实际观测，不能再次运行工具制造两份状态。

### 产物、结果与额度

设备安装声明 `/input/artifact_id`，保留原业务 ID，通过 SDK artifacts 上下文读取本次受控副本；纯包仍用顶层 artifact_id。插件只写本次 output directory，不引用宿主 ArtifactStore、不接受业务请求指定工具路径或服务器文件路径。遵守 [插件嵌套输入产物实施](插件嵌套输入产物实施.md) 的选择器、最多 8 个实际输入/输出及输入总量 64 MiB 等现有规则。

协议 2/3 宿主结果为严格 `{result,artifacts}`，协议 1 保留裸结果。是否解包由目标协议和绑定 profile 决定，不能遇到任意业务 JSON.result 就解包。需要输出产物的迁出操作使用协议 2/3，不能用协议 1 自填路径/Artifact ID 模拟宿主产物。

截图建议要求唯一命名输出 `screenshot.png`；extract_apk、extract_splits、build_apks、decode 各自需要确认输出角色、文件名与数量，再将宿主已发布 Artifact 元数据嵌入旧实体。转换选择器只关联该次结果中的真实输出，不取第一项、不信插件自填存储 ID；源 artifact_id、device_id 等旧回显字段从可信任务输入核对。新能力结果可以保留包装，只有旧入口应用兼容转换。

临时路径脱敏、trim stdout、非零退出、零退出失败文本、APK/HAP 格式、ZIP 路径/链接及解压炸弹限制都要迁到插件或公共包库。缺失/重复输出必须失败，不能返回 installed=true/dispatched=true 代替缺少证据；dispatched 仅表示命令已发出，不表示设备界面已响应。

旧包构建、反编译和分包存在 120 秒阶段期限，普通协议 2 默认为 60 秒；这类非设备长任务不被本轮设备预算自动解决。应先确认在现契约下缩窄支持边界还是新增有界任务期限，不能无意截短后称等价迁移，也不能静默提高宿主额度。64 MiB 产物额度保持现规则，大包和真实安装耗时另行取样。

多产物发布当前不是事务：后续发布失败或到期时可能已有产物写入。文档和任务错误需保留这个边界，不能承诺失败全回滚；阻塞解析或复制收到外层取消后仍可能收敛，必须保留临时目录所有权和工作名额，不以丢弃等待 Future 声称后台已经停止。

### 错误与部署

沿现设备准入精确规则：未知提供者/精确能力版本/设备为 404 not_found；旧代、未观测、离线、能力不可用或 cleanup_failed 为 409 conflict；语法、缺字段、非对象 input、非法版本/schema 为 400 invalid_input；错误发现、重复 local ID、非声明能力为 502 dependency_failed。刷新取消沿 409 cancelled；测试不得用任意 4xx 兜底。

上述是准入/刷新错误，不能把已创建 Job 的执行失败改成相同 HTTP 失败响应。当前 SDK Response.error 是字符串；平台结构化错误及旧客户端对失败文本的要求须单独确认，保留任务状态和现有 v1/v2/MCP 包装。默认免鉴权、可选 APK_API_TOKEN 不变。

工具路径、签名材料和共享 ADB/HDC daemon 归部署配置，不由业务调用者选择。插件资源清理与借用 daemon 分开；卸载不能误杀部署者共享服务。签名不完整等配置检查移到对应插件配置/执行边界，空宿主不触发平台检查。可信独立插件不等于系统沙箱，进程退出不证明外部设备事务回滚或派生树全部退出。

## 依赖迁移顺序与下一批写集

此节只划分后续职责。当前能力期限/取消清理源码和已有本轮文档仍由原所有者验收；不以本方案重新接手其文件。以下新模块名均为建议，尚未创建或授权实施。

| 顺序 | 交付物与依赖 | 进入下一步的条件 |
| --- | --- | --- |
| A：确认最小契约 | 确认部署绑定来源、能力精确版本、有限输入/结果转换、发现副作用、原始状态、纯包长期限和性能拆批边界 | 主代理记录确认结论；未确认事项不能靠实现默认值冻结 |
| B：domain 纯规则 | 必要的绑定声明/转换规则及纯兼容 schema；不引入 Tokio、工具、存储或平台适配器 | 输入输出及错误回归可独立验证；若模型只供应用内部使用，不为目录齐全强造公开 domain 类型 |
| C：application 注册与准入 | 旧入口和目标同 owner 原子注册；单 Job 执行计划、同代校验、共享设备锁/截止点、结果转换与发现发布 | 不依赖真实 ADB/HDC 的替身测试证明原子性、互斥、卸载、历史与失败路径 |
| D：公共库与独立插件 | 共用包规则先冻结库边界，再按三个插件互不重叠写集迁移业务；只依赖 SDK、tool-process 和公共包库 | 模拟工具真实进程证明原行为、产物、期限和取消；无私有宿主生产依赖 |
| E：server 通用装配 | 显式部署绑定注入；旧名称通过通用操作目录暴露；HTTP/MCP/直接 jobs 共用 C 的准入 | 逐项停止旧注册、拒绝冲突；空插件与安装后热加载均验证，路由无平台分支 |
| F：性能及宿主收口 | 会话 owner/代际与采样排空完成后移除默认 probe/protected，再删除无引用平台装配与实现 | 8 个性能操作覆盖、历史保留；旧 trait/源码确认无生产引用才删，不能仅把 main import 去掉 |
| G：完整交付 | 架构门禁、接口生成、受影响 smoke、当前 release/平台包和 npx | 实际退出码、报告、摘要及未验收边界齐全；不沿用旧二进制通过结果 |

下一批建议先做 A–C 的通用绑定，不等待真实平台工具：替身覆盖普通结果、provider write、device read/write、发现和输出产物五类路径。插件使用公开示例 schema，验证旧 input 到封套、严格输出角色选择及同一 Job 历史；源码审核和目标测试冻结后再并行 D，避免同时修改公共注册层与平台插件。

## 必须验收的行为与证据

先以替身完成通用注册与准入，再以模拟工具真实进程证明插件边界，最后验收当前发布包。测试助理与主代理统一串行调度构建/服务，插件角色交冻结检查点，不因本计划启动额外进程。

### 通用绑定目标测试

- 原子注册：重复旧名、缺少目标、越命名空间、schema/转换错误、容量超限都不半发布；卸载同时撤销旧/新入口并变更目录修订，重载新代不接收旧快照。
- 单任务：旧入口的 Job.operation/input/事件保留原形，executor 实际收到目标 operation/封套；HTTP、MCP 和直接 jobs 使用相同入口，不能出现隐藏子 Job、锁内再次排队或 owner=None 绕过。
- 验证：业务 schema 必填字段能注册，缺字段提交明确失败，合法字段成功；封套 input 类型和 device_id 范围错误被拒绝，读写标志及预算不能由 input 指定。
- 共享互斥：旧别名与新能力写同一 provider/local ID 串行；跨代仍同锁；provider write 阻止 device read/write，device read 能力也持 provider 屏障；弱引用锁池并发创建/升级不产生双锁。
- 生命周期：新任务和获锁后的排队任务都拒绝 cleanup_failed/撤销 owner；真实清理成功后任务可继续。取消/到期发生在首 poll 前不得执行工具，Future 丢弃保持未确认资源并拒绝重载。
- 期限：准入时开始计时，队列、锁、输入副本、执行和多个输出发布扣同一预算；APKS 长能力不被非合作 60 秒截短。取消与截止点同时到达按已冻结规则判断，不延长清理窗口换取成功。
- 发现：旧入口与 refresh 串行语义一致；发布前再次复核 owner/代际和取消/期限，卸载不得留下晚目录；坏发现/重复 local ID/非声明能力精确失败，缓存按当前清空规则执行。
- 结果：协议 1 裸业务 result 字段不误解包，协议 2/3 只按目标协议解包；缺失/重复输出不映射成功，输出 Artifact 来自本次真实发布；旧成功、失败、取消历史及下载在卸载后保留。

### 独立插件与空宿主验收

- 无平台包、ADB/HDC/Java 不存在、签名配置缺失时宿主仍能启动通用接口；平台旧入口不发布。明确选择无效插件配置的错误另行验证，不能靠隐式回退启动。
- 在线安装独立平台包但不自动加载；加载后旧别名/新能力同时出现。HTTP、独立 MCP、直接 jobs 完成操作，卸载后都撤销；清理未确认时卸载、包删除及同 ID 重载继续受门禁保护。
- 模拟工具逐项覆盖设备 15 项和纯包 7 项：独立 argv、工作目录/环境、零退出失败文本、非零 stderr、断线、输出/文件额度、APK/HAP/APKS 受控副本与摘要、截图/提取/解码下载实体及摘要。
- 连接测试分清借用 daemon 和插件自有连接；取消/超时/Future 丢弃覆盖真实直接 PID 退出、临时目录和阻塞工作收敛，不能用日志中的 cleaned 字样代替资源确认。需要外部资源的插件按协议 3 确认，无确认保留 cleanup_failed。
- APK/AAB/APKS/HAP 的文件、容器、输出数量和大小保持有界；非法路径/链接、解压炸弹及缺输出失败。模拟样本需记录范围，超过当前额度的大包不得写成已支持。
- 性能 F 批另验收 8 项操作、逐样本设备锁、暂停/恢复、在途卸载、采样清理失败、旧代不续新代、服务重启恢复及历史分页；本批设备别名通过不能替代此项。

### 统一门禁与发布

完成源码集成后，在 backend 串行执行六门禁并记录真实退出码：

```text
node scripts/check-architecture.mjs
node --test scripts/architecture.test.mjs
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build --workspace
```

在 backend 追加受影响的 `runtime-smoke.mjs` 两模式（默认、`--performance-plugin`）、logging、plugin-lifecycle、cooperative 和 online-plugins smoke；在工程根追加 device-provider、nested-device-artifacts 及生产 browser smoke。现有模拟夹具依赖旧内置平台装配的，应切换为独立包安装/加载及显式绑定，不能通过保留测试专用生产回退让测试继续绿。

主代理按公开 DTO 实际变化生成接口并执行前端门禁；本方案不授权前端新 UI，也不手改生成类型。源码冻结后重建当前 release/runtime、三个独立平台包与 CLI tgz，再跑支持 `--release` 的受影响 smoke 和同一真实 npx 安装/加载/旧操作/新能力/产物/卸载场景。记录构建版本、包摘要、命令退出码及报告路径，历史阶段证据原样保留。
