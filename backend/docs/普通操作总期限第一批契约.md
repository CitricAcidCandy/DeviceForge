# 普通操作总期限第一批契约

状态：主代理冻结实施方向，2026-10-09；实现、测试与分发尚未完成。来源为后端《非设备长任务执行期限方案》与前端《非设备长任务消费方案》。本契约是下一批实施输入，不把设计交接或历史设备期限测试记作本批通过。

## 架构裁定与兼容

采用架构先行模式，覆盖公开 SDK、领域模型、注册快照、任务用例、插件副作用映射、生成 API 与前端公开适配。开发顺序采用契约驱动加竞争场景测试：先冻结纯声明，独立实现映射和确定性矩阵，再串行执行真实进程与分发验收。

选择贡献中的可选版本化声明；不把预算放入业务 input，也不建立另一套任务路由。声明跟随实际 operation 的注册快照，旧别名继承同一目标的有效预算、owner 与 generation。HTTP/MCP 不允许客户端延长或覆盖预算。

SDK 的 `Contribution` 新增可选 `execution`：省略或 null 表示未显式声明；非空为严格对象 `{api_version: 1, total_timeout_ms: u64}`。最小 1 毫秒，最大 3600000 毫秒；零、越界、非整数、非数字、未知版本及未知字段拒绝为 invalid_input。普通未声明操作统一采用 60000 毫秒总预算。便携 native/Node 清单保留此声明；浏览器包不套服务器操作预算。首批采用固定部署上限，不新增命令行配置。

设备发现与设备能力保持各自既有预算，不被普通缺省截短；性能专用采样沿其自身契约。判断来自实际贡献关联。上述特殊贡献不得重复声明普通 `execution`；一个插件同时声明设备贡献，不影响它的其他普通操作。本批先覆盖普通宿主 Job 和 ProcessPlugin；内置执行器内部工具是否完整使用上下文须逐项核对，未覆盖项保留迁移缺口。

领域 `Operation` 新增可选公开 `execution`：非空为 `{api_version: 1, total_timeout_ms: u64, source: "default" | "declared"}`。普通目录在注册时固化有效值，设备等专用预算继续由所属契约表示；别名复制实际目标元数据。SDK 独立消费映射为可选 `{apiVersion: 1, totalTimeoutMs: number, source: "default" | "declared"}`，不得向提交参数添加字段。旧 JSON 缺省/null 保持可读，未知版本或非法值不得猜测补正。

新增 Rust 字段需要同步内部结构体构造处；JSON 可选字段不是 Rust 源码构造兼容。旧宿主严格清单解析可能拒绝新字段，不承诺新插件可加载到旧宿主。现有 Job、事件和进程 Request/Response 不变；不新增进度、幂等键、Job 预算快照或 owner 字段。历史任务不从当前目录补写预算。

时间语义有明确迁移：旧协议 1/2 分阶段窗口和协议 3 的低层默认一小时，不再是普通宿主 Job 的总期限；长任务必须显式声明。底层直接调用 context None 保留既有兼容，不作为宿主 Job 绕过策略的入口。显式长预算不得被旧 60 秒传输窗口再次截短。

## 一个截止点与成功资格

准入起点为注册目标快照已取得后、首次等待提交存储池前。当前异步入口已在等待前 prepare，扩展此处，不能把起点退回阻塞闭包。同步兼容、直接插件、HTTP/MCP 和旧别名共用纯策略。

普通 `D = min(t_admit + 有效预算, 已有父截止点)`；没有父截止点只取前者。D 贯穿验证、创建、排队、输入准备、执行、转换、逐输出发布与成功资格。单调时钟值只在宿主内传播，不能序列化给插件；子步骤与父子调用不刷新预算。到期不启动新副作用或首次轮询执行器。

截止点已过时诊断为 Timeout，否则显式取消为 Cancelled；已提交终态受 CAS 保护，后续到期不得改写已提交取消。取消与到期并发的诊断选择不能覆盖资源未确认风险。

成功资格必须在取得终态存储槽之后、实际提交副作用之前复核 D、取消、当前目标和 owner 风险，并与 request_cancel 使用同一个短时门禁排序。已取得成功资格的不可中断事务允许稍后收敛，仍由任务和 owner 跟踪；取消已先取得资格则晚成功不得提交。不得持全局注册表或准入锁等待数据库 I/O。

创建开始前到期不得创建；已经开始的不可中断创建必须继续受跟踪，并通过已有补偿收敛，不留下无人跟踪的 Queued。阻塞工作许可、目录 lease 和 tracker 留至实际工作结束，Future 超时或丢弃不是工作物理停止。存储池等待取消时必须区分工作是否已开始，禁止超时后重新等待并启动新创建。

多产物不是批量事务；部分发布后到期应阻止后续发布与最终成功，不宣称全部回滚，不删除无关产物。部分发布的独立回收政策留后续，不扩大本批 Job DTO。

## 清理与资源边界

复用现有取消树、代际与清理协议。执行预算不延长外围 2 秒清理、协议 3 合作 1250 毫秒/终止等待 500 毫秒及卸载 10 秒门禁。清理失败、Future 丢弃或缺少匹配确认保持粘性未确认状态，另一任务成功不能清除。

未确认后新任务及排队获槽任务拒绝执行；卸载保持 draining/cleanup_failed，同 ID 重载和运行包删除保持保护。已确认直接进程退出与已确认外部资源清理分别记录，不相互替代。队列容量、工作池、产物及输出限制不随长预算扩大。

## 验收和异步交接

第一段冻结公共声明与领域类型；第二段完成注册/准入/终态及副作用映射；第三段执行确定性测试和真实进程。每段交接列精确文件和 SHA-256，主代理接收后记入验收队列，原角色立即继续不冲突的已分配下一项。

最小证据包括：省略/null 和非法声明；native/Node 安装保持声明；别名继承；存储池耗时计入 D；排队到期执行器零调用；Running 更新后到期零首次 poll；成功资格等待中到期/取消；阻塞许可实际结束才释放；同一 D 传入准备、传输与逐产物；合作清理风险不被成功覆盖；卸载与关闭排空。

协议 2/3 显式长预算必须分别验证。暂停 Tokio 时间可证明宿主调度规则，真实进程不随暂停时间跳时；至少一项真实执行越过旧 60 秒并成功，才能关闭真实长执行判据。旧设备 120 秒回归、HTTP/MCP、生产浏览器、全量门禁、新 release/runtime 与实际 npx 分层记录；未执行项继续保持未验证。

普通缺陷每个验收项结束汇总并去重，阻断立即回流。共享工作区不具备独立源码快照；运行前后核对完整输入，门禁只暂停其实际读取范围。主代理统一运行 Cargo/npm/Node 与真实服务，其他角色继续独立实现或设计。开发完成不等于已验收，局部通过不等于整体迁移完成。
