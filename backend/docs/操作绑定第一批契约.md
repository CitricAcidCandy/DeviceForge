# 操作绑定第一批契约

## 门禁与范围

本批采用 architecture-first / Hybrid：先冻结部署配置、纯输入/结果转换与注册所有权，再实现同一任务准入和真实进程回归。影响 application 注册、提交和执行，server 部署配置，以及所属测试/文档；不新增 HTTP、MCP、设备 DTO 或浏览器预算参数。

选择由宿主显式配置绑定、把旧入口和目标贡献原子注册到同一 owner。将旧名称写成无归属的桥执行器并再次提交任务会产生嵌套任务、锁和执行槽等待，故不采用。配置属于部署者，插件只贡献自己的命名空间操作，不自行占有其他插件或旧入口。

## 本批冻结规则

- 部署环境变量 APK_OPERATION_BINDINGS 指向可选 JSON 文件；不配置时为空。文件最多 64 KiB，format_version 固定 1，bindings 最多 256 项，不提供运行中配置变更接口。
- 每项包含 operation（id/title/input_schema）、target、input、result。Operation 沿现有本地 JSON Schema 门禁；重复别名、非法字段、目标格式或转换规则为 invalid_input，已加载贡献冲突为 conflict。
- 配置中的别名预留名称。启动内置贡献遇到同名入口时不发布该入口；目标未安装或未加载时别名不可发现、提交为 not_found，不回退内置执行器。多个提供者的同名设备由配置中的 plugin_id 明确选择。
- target 的 kind 为 device_capability（plugin_id/capability/version）或 operation（plugin_id/operation）。能力必须精确匹配已加载提供者的能力版本；普通操作只能指向该插件自己的实际贡献，不能以此绕过设备能力或发现声明。
- input 为 identity 或 device_envelope。后者仅用于设备能力：设备范围取旧顶层 device_id，余下字段进入 input；提供者范围移除缺省或 null 的 device_id，封套 device_id 为 null。实际旧输入和转换后的目标输入分别验证，不用假参数验证业务模式。
- result 的 kind 为 identity、value（wrapped）、artifact（filename）、object（wrapped/fields）。wrapped 显式选择严格宿主 result/artifacts 包装，不按任意业务对象的 result 字段猜测。artifact 必须来自本次宿主已发布产物且精确文件名唯一匹配。
- object 的 fields 最多 32 项，唯一 name，source 为 input（pointer）、value（pointer）、artifact（filename）；optional 缺省 false。JSON Pointer 最多 128 字节，使用合法转义，无脚本、路径访问或表达式。optional 为 true 时，指针字段缺失或命名产物零匹配均省略该字段；显式 null 保留为 null。必填缺失、重复命名产物或包装格式错误始终执行失败，optional 不能吞这些错误，不伪造 Artifact 或取第一项。
- 历史 Job 保留旧 operation/input；内存执行计划保存目标贡献、转换后输入及结果规则。所有入口只创建一份 Job，共享目标 owner/generation、取消树、设备屏障/写锁、执行槽、期限和清理守卫。
- 能力别名使用目标声明的默认 30 秒或显式 1–120000 毫秒总预算；排队、锁、副本、执行和发布共用准入起截止点。普通非设备操作保持原期限；不将本批声称为 120 秒包工具迁移完成。
- 别名和原贡献同一注册修订原子发布和撤销；未确认清理拒绝新任务及排队执行，重载不能复用旧注册快照。目标缺失、转换不兼容时插件加载整体失败，不能留下半份贡献。
- provider 范围拒绝非 null 的旧顶层 device_id，不静默丢弃。加载只校验配置中 plugin_id 属于本次插件的绑定，不让其他尚未加载的目标阻断无关插件；配置全局语法、重复项和旧模式仍在启动时验证。

旧发现入口本批明确不能绑定。现 API 1/2 无原始设备状态载荷，不能无损表达 recovery/sideload/bootloader；发现副作用与原始状态的版本化加法将在下一批一起实施。本批也不发布虚假的发现兼容入口，不计为旧操作或平台整体迁出完成。

## 文件职责与所有权

| 单元 / 所有者 | 输入输出与职责 | 副作用与不负责内容 |
| --- | --- | --- |
| application/operation_aliases / Galileo | 配置类型、纯验证、输入/结果投影 | 无 I/O，不访问注册锁、不提交任务、不实现平台命令 |
| application/registry、submission、execution、lib / 主代理 | 原子绑定、目标快照、双模式验证、单 Job 准入与执行 | 保留既有存储、锁和清理；不读取配置文件或编写平台规则 |
| server/operation_bindings、main / 主代理 | 有界异步配置读取、装配 Application | 不决定投影和设备路由，不接受业务请求指定配置路径 |
| frontend operations 与 app 装配 / Kepler | 操作目录失效、晚到拒绝和重查 | 不增加绑定 API、平台映射或 UI |
| 根验收脚本与回归 / Kuhn | 真实配置/提供者、单任务、锁、装卸和报告元数据 | 测试不修改生产期限；构建/服务由主代理执行 |
| 契约审核 / Lagrange | 配置边界、同任务与撤销闭环审核 | 只读反馈，不重复修改上述实现 |

提交和执行编排从 application/lib.rs 拆出 submission.rs、runner.rs，再接入绑定；纯转换不堆到路由或注册发布锁内。配置验证和模式编译在既有受限阻塞池或启动阶段完成，发布仍持短时锁。

## 验收判据

先验证配置/投影失败路径及真实旧输入到目标输入，再验证一份 Job、所有权原子发布/撤销、同设备旧/新共享锁和 provider 屏障、排队/锁扣时、过期零执行、取消与清理未确认、代际重载与历史不改写。真实 HTTP/MCP 使用相同配置与任务层，精确错误不能以任意 4xx 兜底。

目标冻结后执行后端六门禁、受影响设备/生命周期/合作/在线回归及前端四门禁，随后当前 debug/release 浏览器和新 runtime/npx。真实平台、旧发现、非设备包长期限、性能会话及常驻连接分别继续，不以通用别名通过代替。用户既有开发授权覆盖本批，无需额外确认。

## 宿主结果来源补充门禁

静态审查发现协议 1 业务 JSON 可以伪造 result/artifacts 外形。仅凭反序列化不能证明产物由宿主发布，本批加入显式结果格式端口；这是领域端口到基础设施适配器的加法，不增加 HTTP、SDK 或插件清单字段。

| 单元 | 职责和输入输出 | 副作用与边界 |
| --- | --- | --- |
| domain/executor_result | 普通 JSON、宿主已发布产物包装两种结果格式；Executor 默认普通 JSON | 纯声明，无 I/O，不由在线插件请求自报 |
| infrastructure/ProcessPlugin | 按已验证的协议与实际宿主发布分支提供格式 | 协议 2/3 的外层包装由宿主生成；协议 1 业务对象不能取得此格式 |
| application/operation_aliases | 纯判断投影是否需要宿主包装 | 不访问存储、不判断生产者真实性 |
| application/registry_aliases | 加载准备时要求目标格式匹配投影 | 不匹配整体拒绝发布，不通过解析业务对象猜测来源 |

选择注册时校验宿主适配器的结果格式，保留纯映射职责；不依赖伪造对象中的 ID 去查询存储，因为已存在的其他任务产物仍不能证明属于本次调用。普通 JSON 的 identity 和未包装 value/object 保持兼容。最低验证为协议 1 伪造包装拒绝、协议 2/3 真实产物投影继续通过、错误绑定无半份贡献，以及全量门禁。

本批 android.devices、harmony.devices 旧发现名称也禁止作为别名发布，不能以指向普通贡献避开发现延期边界。该拒绝与真实发现目标拒绝共同验证。
