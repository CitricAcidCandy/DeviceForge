# 市场插件依赖集成验收

日期：2026-10-26，Windows x64。本轮实施采用 architecture-first：纯契约、依赖用例、文件/仓库/探测适配器与 HTTP/MCP 边界分离。工作区有并行改动，用户明确允许保留 resource-server/Cargo.lock；未恢复、提交、公开发布或操作真机，投屏内部保持原所有权。

## 实施范围

- 公开依赖库及 SDK 导出；独立组件 dependencies.json 与完整发布 v2，同名 release/server/browser 目标隔离和组件归属归并。
- 环境、PATH、声明用户位置、全仓库索引及已登记本地工具发现；跨插件实际版本/入口匹配，不按安装者或内置插件名单分支。
- 正常安装先检测并复用，只下载缺失必需项；可选依赖显式补装，启动和普通重新检测不下载。高级手动覆盖不是前置步骤。
- 本地工具只登记内容身份、不删除原文件；共享工具不可变包修订、独立消费者引用、活动租约与失败保旧。
- 脚本组件通过公开 runtime dependency 引用启动解释器；实际解释器随本次资源快照取得租约，不将 helper 子进程冒充插件本体。
- 正常安装失败保留部署及 dependencies_required，补救成功按原启用意图恢复；失败诊断独立于有效绑定，不为显示错误破坏旧快照。
- 在线依赖保存市场基址、同源解析相对摘要；离线归档使用既有资源缓存；完整性失败直接报告，不换源掩盖。
- HTTP/MCP/CLI 共用用例；初始 CLI 使用运行包明确能力及宿主准备模式，不另建工具仓库或启动监听。
- 市场 v1/v2、打包器、十八份官方声明与指南 v3。无可信来源的工具不伪造摘要或下载地址。

## 真实运行进展与失败原件

冻结 01、02 的每次运行均使用独立用户根、随机端口和新 run ID。已确认一次 A 安装仅下载一次运行时，B 安装零网络复用相同入口；脚本本体 PID、父 PID、argv、实际程序摘要和宿主生成 marker 对应。环境与声明用户目录空配置发现、三类同名目标、组件归并、摘要错误/缺入口真实失败且保留旧配置，以及本地补救自动恢复也分别取得新宿主证据。

早期失败原件全部保留：夹具 MCP 协议误用、Windows 扩展路径字符串、完整发布目录与脚本修订路径断言、安装等待不足、以及网络失败 Job 被夹具误认为 succeeded。修正夹具后须完整新 run，不能拼接各轮局部通过。

独立 npx 冻结 01 的完整双缓存重跑报告 `artifacts/plugin-dependencies-npx-smoke-debug-bbce7e6e-cb27-4ae1-9015-39246e080895/report.json` 为 passed；第二缓存换业务根后恢复相同用户根。该输入不包含后续宿主失败诊断和初始 CLI 准备能力，不能替代冻结 02/后续新包。
