## 行尾与拒绝边界

| 输入边界 | 静态行为及依据 |
| --- | --- |
| `LF`、`CRLF`、`CRCRLF` | 按 LF 划分完整行，再按最长后缀优先剥离一次；不全局删除 CR |
| 三种行尾混用及合法空行 | 每行独立处理；合法设备顺序和输入资格能力预期保持不变 |
| 无换行的合法末行 | 保留既有兼容行为；这不是新增第四种换行协议 |
| 行内 CR、制表符、其他控制符 | 剥离明确行尾后，剩余控制符统一报错，不先修剪或拼接设备 ID |
| 末尾裸 CR 或裸 CRCR | 没有 LF，不能匹配三种后缀；剩余 CR 被拒绝 |
| 三个及更多 CR 后接 LF | 最多剥离两个 CR 和 LF，残留 CR 被拒绝，不循环剥离 |
| 空标记或空白行夹带非法 CR | 必须先报控制符错误，不能经 `trim()` 或 `[Empty]` 跳过 |
| 有效首行后出现非法后续行 | 立即返回错误，已构建的局部设备向量不作为成功目录发布 |

固定控制符错误保持为 `工具依赖失败：HDC发现输出含非法控制符`。重复 ID、未知诊断、128 条及 200 字节边界沿用已有规则和测试，本轮未修改。

## 协议覆盖补充

已有协议用例已经包含 CRCRLF 空标记、普通设备顺序及资格能力，以及第二设备行中的行内 CR、裸 CR、裸 CRCR、制表符、三个 CR 和终端转义控制符；这些用例原样保留。

本轮新增于 `backend/plugins/harmony-device/tests/cases/discovery.rs`：

1. `mixed_line_endings_keep_order_and_qualified_input_capabilities`：同份输出混合三种行尾、三种合法空行和空标记，断言两个设备原序及公开输入资格能力。
2. `control_characters_in_empty_markers_and_blank_lines_reject_entire_directory`：七个负例均以前置有效设备开头，覆盖空标记后的裸 CR、空标记后的多余 CR、只有裸 CR/CRCR 的末行、只有多余 CR 的空行、空白中间的 CR，以及制表符空行；全部要求固定错误而非局部目录成功。

这两项补足的是回归保护缺口，不表示已发现当前生产解析存在同类错误。未改写夹具、输入资格逻辑或已有期望。
