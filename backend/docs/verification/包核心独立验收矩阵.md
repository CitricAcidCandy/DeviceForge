## 最小夹具族与独立判据

本轮仅设计下列夹具，不创建文件。所有坏包只改变一个目标条件，记录原字节 SHA256、变更偏移、变更前后字段与独立期望；不要让路径错误先遮住待测 CRC，或让声明超限先遮住待测 EOF。

| 夹具族 | 最小内容与变体 | 独立判据 |
| --- | --- | --- |
| F-Z：小 ZIP | 固定 Stored 两普通成员、一目录，另有固定 Deflate 成员；包含中文和空格名称。预制 local header、central directory、EOCD 字节 | 测试侧按 ZIP 字段计算偏移和长度；CRC32 使用固定已知向量与测试侧独立算法。不能用核心或同一读取实现回算期望 |
| F-Z坏：单字段坏包 | EOCD 截断/范围越界、分卷字段、ZIP64 标记、路径、Unix 链接类型；仅 payload 翻位的 CRC 坏包、声明长度增减、截断压缩流；local/central 名称同步改成重名 | 每个变体保留其它条件合法；结构、精确复制、完整 APKS 分层测试 |
| F-B：数值边界 | 10000/10001 条目录；声明展开 2 GiB/多 1 字节；精确输出 64 MiB/多 1 字节；APKS 压缩 64 MiB 和展开 256 MiB 边界 | 声明限额可用小 header 夹具验证拒绝；实际 EOF/CRC、实际展开边界使用有界真实流，不把伪声明成功当实际复制成功 |
| F-T：私有树 | Reverse 与 Splits 各一棵最小树，乱序创建；可调目录计数、层深、文件长度；独立输出文件位于源根之外 | 预期排序列表与字节和由测试规格给出；Stored ZIP 头和中央目录独立复核，不能只重新调用核心 open |
| F-A：小 APKS | 非空 toc.pb、两个有 ZIP 标识的 APK；Universal 变体仅一个 universal.apk；附加非 APK 普通成员 | 固定原文、apk_count 和 universal_entry；坏包放在 APK、toc 或最后一个无关成员分别覆盖全外层读取 |
| F-M：XML | 旧 manifest.xml 原字节及最小缺省 XML；改 Android 前缀、假命名空间、实体、重复主要节点、深度/节点/字节边界 | 固定全字段、None、权限排序去重及原 XML；不从工具退出码推解析成功 |
| F-S：签名文本 | 旧 signature.txt 原字节；多 signer、warnings、缺 DN；失败标记、scheme/编号/摘要坏值、1 MiB 边界 | 固定编号、方案排序、SHA256 小写及原 report；无密钥、密码或真实签名材料 |
| F-D：smali 目录 | smali 与 smali_classes2，多于 10 个匹配路径，检测点排在前 10 之外；相邻前缀包和假根 | 固定规则顺序、class_found 的 None/布尔值与 10 条排序证据；路径观测不能算 DEX/版本识别 |

大边界用例单独标记资源成本，不能扩大生产限额使小夹具“等效通过”。深路径、符号链接、重解析点需记录系统能力；无法建立则明确未执行，不能把 skips 计为通过或新建外部目录来绕过权限。所有临时项均由测试所有者创建和回收，失败保留本次原件，不触碰用户目录。

## 归档与精确复制

| 编号 | 公共调用与触发 | 必须断言 |
| --- | --- | --- |
| K-Z01 | F-Z → Archive::open(Structure) | 有界目录与固定成员描述；Stored/Deflate 均可；中文/空格保留。成功只证明结构/路径/声明 |
| K-Z02 | EOCD 缺失/截断、中央目录范围越界、local/central 不一致的结构坏包 | 精确 InvalidArchive 及有限格式/阶段；不 panic，不返回 Archive |
| K-Z03 | 分卷标记、ZIP64 EOCD/locator 或要求 ZIP64 的条目 | InvalidArchive；各自独立夹具，不把未知压缩法错误充作 ZIP64 拒绝证据 |
| K-Z04 | 绝对、点穿越、反斜杠、冒号、控制字符、符号链接及不支持类型 | InvalidArchive；目录之外无新路径。重复名不并入这一组 |
| K-Z05 | Structure 条目 10000/10001、声明总量 2 GiB/多 1 字节 | 等于限额可结构打开，超过为 LimitExceeded，匹配实际有限 limit；不能要求结构打开读取 2 GiB payload |
| K-Z06 | 合法结构但一个成员 CRC 坏；另一个成员合法 | Structure 可成功；精确复制合法成员可成功；不能称全 ZIP 已通过 CRC |
| K-E01 | select_exact 的精确名称不存在/有两普通成员同名 | 分别 EntryMissing/EntryDuplicate；调用方只在选择成功后 create_new，两个失败分支都没有创建目标 |
| K-E02 | 合法结构保留两个同名成员，再选择另一唯一成员 | Directory 不静默去重；唯一成员可选、可复制。APKS 的重名拒绝另测 |
| K-E03 | 精确名 UTF-8 字节长度 500/501、安全相对路径与 APK 后缀资格 | 通用 select 的精确匹配与调用方 APK 参数资格分别记录；候选 API 未给 APK 专用 selector，不能把后缀规则强加给通用 Archive。500/501 和非 APK 的业务拒绝须由后续明确调用层测试承担 |
| K-E04 | 唯一选定成员复制到 create_new File，限制等于实际长度/少 1 字节 | 成功 CopiedEntry 的 name/bytes、目标原字节完全一致；超过为 LimitExceeded，半文件不能取得 CopiedEntry |
| K-E05 | 所选成员 payload 翻位、声明长度增减、Deflate 截断 | InvalidArchive，分别标明 CRC/长度/解压阶段；必须读到 EOF，不能只比较已写字节数或开头 ZIP 标识 |
| K-E06 | 仅未选定成员 CRC 坏，选定成员合法 | 选定复制仍按独立规则成功；与 validate_apks 的整包失败形成正反对照 |
| K-E07 | 有效选择后使用只读目标 File 或已关闭底层访问条件的受控 I/O 失败 | Io 保留原 io::Error.kind()/source；不变成 InvalidArchive/Cancelled，不泄漏任意正文到报告。只读 File 是最小公开故障，不需要私有 writer hook |

E03 的缺口是公开能力定位，不是允许放宽精确 APK 资格。Archive 的任意名字精确匹配、APK 业务入参校验和复制限额是三项职责；未来调用层授权后才验证“参数拒绝先于创建目标”。输出 File 已由调用方打开，核心不能证明 create_new 的打开动作是自身完成的，也不负责删除失败半文件。

## 树 profile 与完成摘要

| 编号 | 最小触发 | 必须断言 |
| --- | --- | --- |
| K-T01 | 两种 profile 各自乱序创建目录/文件，scan 后 pack | 相对名排序、文件数与普通文件字节和精确一致；输出 Stored，archive_size 等于已完成文件实际长度；目录条目不冒充文件数 |
| K-T02 | 文件加目录总数 Reverse 10000/10001、Splits 1000/1001 | 等于限额可扫描，超过 LimitExceeded；同一棵 1001 条合法树 Reverse 可接受而 Splits 拒绝，防止两个 profile 互换 |
| K-T03 | 深度 128/129；根目录/子项 symlink 或现有 reparse；非普通项与非法相对名 | 深度超过为 LimitExceeded；其它精确错误须与公开树错误表冻结后匹配，不先假定全是 InvalidArchive。Windows 建立能力单列 |
| K-T04 | 文件总量恰好 64 MiB/多 1 字节；另一棵总量小于 64 MiB 但完成 ZIP 加头和中央目录超过 64 MiB | 超出总量或完成 ZIP 大小均 LimitExceeded；总量等于限额可 scan，不保证可 pack；不能用当前 seek 位置替代最终文件长度 |
| K-T05 | scan 返回后，单文件改成长/短，或改为目录/链接，再 pack | SourceChanged 的已冻结长度变化分支；类型/路径变化的具体类别待公开错误表定位；不返回 PackedTree，不继续复制后续成员 |
| K-T06 | scan 后同长度内容替换 | 记录核心保证仅含路径/普通类型/长度复核；可以观察结果，但本批不把“必须识别”设为通过条件，也不宣称句柄级竞态免疫 |
| K-T07 | Reverse 工具期目录尚无必要文件；最终缺/空 apktool.yml 或 AndroidManifest.xml；随后补全 | 通用监测扫描不提前要求完整业务输出；最终 android::validate_decoded 才拒绝缺/空项；补全后通过。具体最终错误待公开表冻结 |
| K-T08 | Splits 最终空树、非 APK、坏 APK 结构；最小合法 APK 树 | 最终业务资格分别拒绝；合法结果 APK 名排序，不能要求 Reverse 两必要文件。最终 Splits 组合入口未在最小 API 单独命名，先核对公开 README，不借私有函数伪造覆盖 |
| K-T09 | 源根外的输出 File；打包写入/收尾发生 I/O 故障 | Io 保留原错误；无 PackedTree。sync 失败能否独立注入另列能力缺口，不使用系统磁盘填满或修改外部共享目录制造故障 |

快照需通过 scan 取得，不从字段、serde 或私有构造器伪造。T05 的删除源文件可能先得到 Io，不能混入确定长度变化的 SourceChanged 用例；每种触发单独列错误期望。目录与 APK 内容验证的结果、树机制结果分别记录，不能用一个总成功值模糊两层。

## Android 解析与 APKS

| 编号 | 最小触发 | 必须断言 |
| --- | --- | --- |
| K-A01 | Default 与 Universal 的 F-A；Default 可无 universal.apk | apk_count 与 universal_entry 精确；Universal 只有唯一 universal.apk 时成功，不解析 toc.pb 设备选择 |
| K-A02 | 空/缺 toc.pb、无 APK、APK 缺 ZIP 标识、重名 | InvalidArchive；与 Structure 保留重复的行为区分。不从 APK 标识推内层完整 CRC/签名 |
| K-A03 | 最后一个无关普通成员 CRC 坏、toc 长度坏、APK 外层压缩流坏 | 整次 InvalidArchive，无 ApksSummary；证明完整读取所有外层成员，不能只复制第一 APK 或只看目录 |
| K-A04 | 压缩输入 64 MiB/多 1 字节、实际外层累计展开 256 MiB/多 1 字节 | 合法等于边界可完成，超过 LimitExceeded；计数含非 APK 成员，逐成员共用 Control；溢出路径不绕过限制 |
| K-A05 | outer 完全合法、inner 只有当前规则要求的 ZIP 标识，或 inner CRC 坏但 outer CRC 正确 | 按冻结外层/标识规则裁定，不额外要求全内层 CRC；报告明确没有验签、设备匹配或真机安装证据 |
| K-M01 | 旧 manifest.xml、等价 Android 命名空间前缀、缺省最小 manifest、假命名空间属性 | 正确 namespace 的字符串字段；假 namespace 不冒充 Android 属性；缺省 None；权限排序去重；xml 原文不变 |
| K-M02 | 多根/错根/重复 uses-sdk 或 application；重复同 namespace 属性、未知前缀、DTD、未定义实体、非法文本 | InvalidManifest；已定义 XML 转义属性可还原，资源标签保持字符串，不尝试资源解析或二进制清单 |
| K-M03 | XML 字节 1 MiB/多 1，节点 20000/20001，层深 128/129 | 构造其它条件合法的边界 XML；超过为 LimitExceeded，有限 limit 匹配，不接受 InvalidManifest 遮住资源边界 |
| K-S01 | 旧签名、warnings、多 signer、无 DN 的完整摘要 | verified=true，连续编号，方案排序，SHA256 小写，report 原文及警告保留。DN 为 None 的旧值不能因迁出丢失 |
| K-S02 | 缺 Verifies、全部 scheme=false、DOES NOT VERIFY/ERROR、重复 scheme/count、编号空洞/重复或 0/33、坏摘要 | InvalidSignature；每个变体只破坏一个必要条件；进程退出 0 与库解析无关，不启用新 -Werr |
| K-S03 | 合法 1/32 signer 与超过 32，签名报告 1 MiB/多 1 字节 | 1/32 成功；编号/计数超界 InvalidSignature；文本超界 LimitExceeded。区分规则边界和输入体积，不假定库验证真实证书 |
| K-D01 | 合法 multidex 根、相邻包前缀、假根，规则无 class/有 class | 包边界不误命中；合法 smali_classesN 的 N>=2；findings 保留规则顺序，class_found 无 class 时 None，否则精确布尔 |
| K-D02 | 同包超过 10 条证据、指定检测点排在前 10 外 | 每条最多 10 个排序相对路径，指定检测点仍出现；不以额外读 smali 内容当作兼容保证 |
| K-D03 | 0/100/101 规则、重名/非法标识符；独立取消 | 合法 100 通过；旧规则至少一条，0/101/重名/非法标识符均 InvalidArgument；取消为 Cancelled，不返回部分 findings |

解析输出上限与跨进程 SDK 响应上限不等价。1 MiB 的 XML/report 加 JSON 转义和字段可能超过 runtime 额度；本批 K 层只测核心输入边界，后续 T/H 层必须实测响应完整性和精确超限失败，不静默截断或扩大协议额度。

## Control、停止边界与返回前检查

Control 使用 `std::time::Instant` 和同步取消回调，不引入 Tokio 或虚拟时钟。计划中的门闩由测试所有者控制，墙钟看门狗只负责报告卡住，不作为吞吐、尾延迟或生产预算证据。不按私有 check 的调用序号注入，不把偶然调度顺序固定成契约。

| 编号 | 控制与可观测门闩 | 必须断言及证据边界 |
| --- | --- | --- |
| K-C01 | 同时设置过去的 D 与 true 取消回调，直接 Control::check 及各带 Control 的入口 | Timeout 优先；只有未过期且已取消才 Cancelled。预过期不靠 sleep 与精确等点竞争 |
| K-C02 | 有效小输入已由调用方打开；预取消/预过期再 open、select、copy、scan、pack、解析及 APKS/SDK 调用 | 精确 Cancelled/Timeout，无成功对象/摘要；已创建的空目标保持零字节，库不创建新路径。不能把测试准备阶段的 File::open 算作库新 I/O |
| K-C03 | None + false/true 回调 | 分别继续正常规则/Cancelled；没有 deadline 不能偷偷补 30/120 秒。短调用只能证明当前行为，不能靠等待数分钟来证明实现没有隐式计时器 |
| K-C04 | 多于两个 64 KiB 块的合法复制；回调观察本次目标长度达到一块后切换取消 | 下一控制检查为 Cancelled，不返回 CopiedEntry；记录实际写入量，限定为有界合作停止。不要要求“一定恰好一块”或从半文件推已停止所有外部资源 |
| K-C05 | 同一 Control/D 先用于受控阶段 A；测试回调在可观测门闩等待真实 D 已过，再继续或开始 B | Timeout，B 无新输出/成功；记录同一个 D，不每成员/阶段重算。公开回调可等门闩，但这是测试的受控阻塞，不是库的工作池 |
| K-C06 | APKS 最后成员或树最后文件已开始后切换取消 | 整次 Cancelled，无 ApksSummary/PackedTree；不继续下一成员。成员推进可观测性不足时先回报，不能只固定第 N 次回调来假定成员序号 |
| K-C07 | 独立预期长度的成功输出；回调通过另一个观察句柄的 metadata 发现完整输出已落盘后切换取消 | 捕获“输出完成附近仍须拒成功”的公开证据；如 Err(Cancelled/Timeout) 只发生在 finish/sync 前，不能标成严格返回前检查已证明。最终检查的精确定位单列待补 |
| K-C08 | 解析/复制最后检查处需要确定取消或 D 已到期，并保证不返回成功 | 若公开接口无法建立该阶段门闩，保留“严格返回前复核：未独立定位”。由主代理裁定只读源码证明加受控自测，或后续另授权可观测测试入口；本角色不新增 hook、不缩短输入或移除断言来补造通过 |
| K-C09 | 复制/pack 已产生半文件后取消、CRC 或 I/O 失败，随后测试所有者检查私有目录 | 核心不返回部分摘要、不删除输出/调用方目录；只由本次所有者清理。目录存在或被删都不单独证明 worker、进程或外部资源排空 |

公开 File API 不能注入计数 Reader/Writer，因此 C02 的“目标零写/无新路径”与实现义务“零新 I/O”分别记录。克隆句柄的游标或文件时间没有变化不足以证明未做 read/seek；另一个句柄只观察 metadata，避免共享游标干扰被测输入。严格物理零 I/O、sync 故障及返回前精确阶段需要更强可观测性，未获得前不得关闭这三项。

`android::validate_decoded(directory)` 的最小签名没有独立 Control 参数：先用受控扫描形成有效有界 directory，再做纯目录规则校验。不能凭该函数单独声称带 D 的 I/O 已被验收；如实际公开接口发生变化，记录新输入而不是在测试里猜测参数。

阻塞池许可、lease、Future 丢弃、工具直接 PID、协议 3 cleanup complete 和宿主终态 CAS 不属于 K 层。后续 T/H 必须另证许可一直持有到实际 worker 返回，清理未确认不报 complete；本库同步函数结束不等于调用方资源排空。SDK 仍无跨进程 D/剩余预算，库 Some(D) 的结果也不能扩大为插件已精确继承宿主 D。

## 本次冻结与下一步定位

本版因 LONG-NPX-EXIT-001 优先修复而冻结交接。已形成独立核心夹具族、归档/CRC/树 profile/Android/Control 与旧行为矩阵，尚无测试源码或动态通过项。主代理安排未来独立写集后，先实现不依赖未定错误表的 K-Z/K-E、纯解析与 Control::check 组；每个参数化变体逐项计数，不把一个总测试函数当全部边界已覆盖。

剩余定位集中为三项：

1. 精确 APK 参数资格及 Splits 最终组合的公开调用位置；不得让通用 Archive 承担隐藏 Android 后缀规则，也不绕过最终资格。
2. 树非法内容、类型/路径变化与 decoded/Splits 最终失败的精确公开 Error、有限 format/limit/stage；未确认前相关行保持待实施，禁止接受任意错误。
3. 严格物理零 I/O、sync 故障及精确返回前门闩的可观测证据；C02/C07 的公开子证据不得扩大到 C08。

后续报告记录冻结来源、夹具原 SHA256、实际 profile、Error 变体、目标长度/字节、阶段和退出码；保留第一失败与原件，不用清理成功覆盖业务失败。库内自测、独立黑盒和全工作区门禁分开列数。现有普通期限 HTTP/npx 是另一输入与验收项，不可借记为包核心完成；真实包、工具、宿主适配、资源排空和分发继续留 T/H 后续授权范围。
