# 设备页接口核对（2026-10-14）

本轮仅只读核对当前后端、前端运行时和设备页面；不修改后端实现、不启动设备、不运行共享 Cargo。本文记录可消费契约与页面缺口，不代表真实服务或真机验收通过。

## 已存在的服务器接口

统一使用 `/api/v2`，成功封套为 `{log_id,data}`，失败封套为 `{log_id,error:{code,message}}`。页面通过现有运行时消费公开类型，不自行复制 DTO。

| HTTP 接口                                                    | 页面调用                                                | 实际行为                                                          |
| ------------------------------------------------------------ | ------------------------------------------------------- | ----------------------------------------------------------------- |
| `GET /api/v2/device-providers`                               | `runtime.devices.refreshProviders(signal)`              | 查询当前加载的提供者、运行代次与能力声明；不会执行设备发现        |
| `GET /api/v2/devices`                                        | `runtime.devices.refreshDirectories(signal)`            | 前端先刷新提供者，再查询当前已观测目录；不会重新执行 ADB/HDC 发现 |
| `POST /api/v2/device-providers/{id}/refresh`，`{generation}` | `runtime.devices.refreshProvider(id,generation,signal)` | 触发一次当前代提供者发现，等待本次回执并更新目录                  |
| `POST /api/v2/device-actions`                                | `runtime.devices.invoke(action,signal)`                 | 精确能力准入，返回共享任务；返回任务不表示动作已完成              |

入口位置：`crates/server/src/device_routes.rs`、`crates/server/src/lib.rs:226`；前端映射为 `frontend/src/services/api/device-endpoints.ts`、`frontend/src/app/device-gateway.ts`。

统一发现是 `application/devices/admission.rs`、`refresh.rs`、`attempt.rs` 中共用任务准入与回执的内部机制，没有另一个全量刷新 HTTP 端点。所有发现共用最多两项在途上限，同提供者串行。全量重新发现按钮应先刷新提供者，再串行或以受限并发调用每个 `refreshProvider`，逐项保留失败原因，不发送无界并发。

## 页面可真实展示的数据

| 对象         | 已公开字段                                                                   | 展示含义                                   |
| ------------ | ---------------------------------------------------------------------------- | ------------------------------------------ |
| 提供者       | `id`、`generation`、`version`、`definition.platform`                         | 当前运行来源、代次、版本与展示平台         |
| 能力声明     | `id`、`version`、`operation`、`scope`、`access`、可选 `executionTimeoutMs`   | 精确能力与读写范围；不能从平台名称推断能力 |
| 观测目录     | `provider`、`observedAt`、`discoveryJobId`、`devices`                        | 观测时间为 Unix 毫秒；可连接发现任务与日志 |
| 设备         | `reference.providerId/generation/localId`、`state`、`rawState`、可空 `model` | 完整设备身份、归一化状态及原始状态         |
| 当前可用能力 | `id`、`version`、`available`、可空 `reason`                                  | 设备此刻能否执行精确能力及拒绝原因         |

归一化状态为 `online/offline/unauthorized/unknown`。型号缺失时显示本地设备标识；原始状态用于保真展示。目录没有系统版本、容量、电量、手机缩略图或传输类型字段，不应将设计稿的示意数字写成实际设备数据。Android 性能采集里的设备观测属于单独采样业务，不能冒充目录内的实时电量。

数据依据：`crates/domain/src/devices/mod.rs:58`、`:93`、`:105`；时间定义为 `crates/domain/src/lib.rs:167`。

## 连接、选择与能力动作

设备选择是前端共享状态 `runtime.devices.select(reference|null)`，没有服务器选择接口。刷新会先撤销该提供者的旧本地观测，旧选择随目录清除而失效；如页面需要恢复选择，只能在发现成功后核对仍存在的完整身份再恢复，不能仅按序列号匹配。

网络连接与断开通过设备提供者声明的 `connect@1`、`disconnect@1` 执行，范围为 `provider`、访问为 `write`。公开前端动作使用 `{providerId,generation,deviceId:null,capability,version:1,input:{address}}`，网关映射为后端 snake_case；不依赖已有设备观测。

Android 地址支持 IPv4/DNS 或方括号 IPv6 加端口，端口运行时要求 1–65535；Harmony 当前声明为 IPv4/localhost 加端口。页面依据实际操作输入结构启用表单，最终地址资格由提供者校验。现有 `DevicesConnect` 已接通这两项任务及断开确认，连接成功后仍需重新发现，成功任务本身不会刷新目录。

应用等设备级动作必须具备：当前加载提供者与相同代次、当前观测设备、`online`、声明的精确能力/版本、同版本 `available=true`。同设备写操作、提供者级写屏障由宿主管理，页面不绕过能力接口提交平台命令。

| 已有前端消费入口                               | 用途                                                                   |
| ---------------------------------------------- | ---------------------------------------------------------------------- |
| `features/device-apps/capabilityGate`          | 同时核对声明、可用状态和真实操作输入结构；当前业务表单消费第 1 版      |
| `features/device-apps/deviceAction`            | 从完整引用和已允许能力构造设备动作                                     |
| `features/device-apps/executeDeviceTask`       | 提交动作、等待共享任务终态、传播取消、撤销换代/切换后的旧结果          |
| `decodeDeviceBusinessResult` / `decodeAppList` | 消费 `{result,artifacts}` 业务封套及兼容应用清单；不把未知诊断行当应用 |
| `runtime.tasks.get/cancel`                     | 查询和取消共享任务；取消等待不能证明外部设备副作用未发生               |

依据：`frontend/src/features/device-apps/models/apps-contract.ts:53`、`:190`、`:243`、`:318`；Android/Harmony 当前声明为 `plugins/android-device/manifest.json`、`plugins/harmony-device/manifest.json`。

## 当前页面缺口与边界

1. 原设备页“刷新设备”按钮仅调用 `refreshDirectories`，读取缓存而没有执行发现。首次空目录和插拔变化须接实际 `refreshProvider`。
2. 连接任务成功没有自动刷新当前提供者，目录需要明确刷新并报告本次失败，不能继续显示旧观测为最新连接结果。
3. 原设备页“读取应用列表任务”只返回提交结果，可复用已有 `executeDeviceTask` 与 `decodeAppList` 提供真实等待和可读清单，或明确导航到已接能力的应用页面。
4. 页面可以从目录计算真实设备数、在线数、未授权数和已观测提供者数；不得写固定演示数字。
5. `packages`、`screenshot`、`input`、应用操作及 Android 性能/Root 能力由服务器插件公开声明驱动，前端界面只负责合适的交互和路由。平台名用于展示，不能充当准入规则。
6. 浏览器扩展组件/模块/面板由 `runtime.extensions` 与 `webPlugins` 的公开挂载系统提供；它们不是设备目录接口，也不等于所有设备能力都应渲染成插件面板。

本次未发现必须新增后端业务或手写 DTO 才能完成设备页基础交互的缺口。Root 真机、真实 ADB/HDC、局域网另一台主机、媒体播放与性能精度仍独立验收；本轮只读核对不外推历史 smoke 到当前界面。
