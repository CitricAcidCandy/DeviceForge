# 设备发现故障记录（2026-10-23）

## Harmony：HDC空目录的CRCRLF行尾兼容

本轮用户发现鸿蒙设备失败，业务错误为“HDC发现输出含非法控制符”。主代理取得的有界真实 `hdc list targets` 回执为退出码0、134毫秒、标准输出10字节 `[Empty]\r\r\n`、标准错误0字节；证据为 `artifacts/device-discovery-20261023/hdc-list-report.json`。该回执只证明此次没有HDC目标，不证明设备连接、输入资格或其他设备业务已通过。

`plugins/harmony-device/src/operations.rs` 在工具捕获成功、UTF-8有效且标准错误诊断检查通过后，将标准输出传给发现解析器。原实现使用 `str::lines()`，只消去末尾一组CRLF，因此上述行尾残留一个CR，在控制符检查处被拒绝；错误发生在输入资格观测之前。守护进程启动消息或ANSI转义并非本次已确认根因，不增加相关忽略规则。

修复仅位于 `plugins/harmony-device/src/discovery.rs`：按包含换行的原始行拆分，依次识别精确CRCRLF、CRLF和LF结尾。无换行的末尾CR、行内CR、Tab、ANSI及多余CR继续拒绝；设备ID校验、顺序、重复检查、128条上限和能力映射保持原契约。解析依赖失败与资源清理失败分别处理，不将此兼容修改用于解除其他插件的清理保护。

### 回归与证据边界

先添加回归，再由主代理串行执行 `cargo test -p deviceforge-harmony-device-plugin --lib crcrlf -- --nocapture`。红测日志为 `artifacts/device-discovery-20261023/harmony-crcrlf-red.log`，结果1通过、2失败、退出码101：CRCRLF空目录及多设备回归按预期失败，非法控制符负例通过。之后再修改解析实现，尚待主代理记录绿测和所属门禁结果。

单元回归覆盖空目录、多行有效ID及顺序/八项初始能力，并拒绝行内CR、单个/两个末尾裸CR、CR分隔伪行、Tab、三个CR后换行及ANSI。`tests/cases/discovery.rs` 同步覆盖真实插件协议路径中的空目录、带输入资格的多设备结果和非法控制符整批拒绝。该协议测试使用受控工具夹具，不能代替真实鸿蒙设备业务验收。
