# 旧操作绑定验收矩阵

## 状态与依据

本文件是平台迁出第二步的最小真实集成验收设计，尚未实施或运行别名测试。依据 [平台适配器迁出实施](../implementation/平台适配器迁出实施.md)、[设备提供者第一阶段实施](../implementation/设备提供者第一阶段实施.md)、[运行中插件生命周期](../guides/运行中插件生命周期.md) 及既有设备操作文档。Galileo 负责后端绑定方案，主代理冻结公开契约，Lagrange 审核协作边界、负责共同协作规则；本矩阵不新增配置字段、管理 API 或错误类别。

验收对象是通用旧名称绑定：在同一次 Job 中将旧输入转换为当前提供者贡献，沿原任务执行、代际准入、取消、锁及结果映射完成调用。不得再次提交嵌套 Job，不得以旧内置执行器或按平台猜测的路径回退。新能力本身通过、旧文档存在、源码映射函数通过，均不能直接记为旧绑定真实集成通过。

## 冻结前需明确的断言

| 契约点 | 已有约束 | 需方案冻结的细节 |
| --- | --- | --- |
| 绑定与选择 | 显式选择提供者及精确贡献；同名 localID 不按目录、platform、加载顺序猜测 | 配置载体、字段、校验时点；缺失/重复/歧义绑定的稳定错误码；是否允许运行时改变配置 |
| 同一次 Job | 输入、执行和结果映射不再次提交任务；历史任务保留原操作和结果 | 新旧入口的任务 operation、owner/generation 记录方式；可审计的调用关联字段 |
| 原子注册与撤销 | 同一 owner/generation；旧捕获快照不能经重载转投新代 | 别名与原贡献的统一发布/撤销时点；配置无目标时是否保持宿主启动并隐藏别名 |
| 旧结果兼容 | 裸结果与协议 2/3 的 result/artifacts 包装分别映射；历史不改写 | 每个操作的字段、类型、可选值和错误映射；截图无输出或多个输出如何拒绝；旧设备特殊状态如何保留 |
| 共享锁 | 同 provider/localID 的 device write 共享 Mutex；所有 device action 持 provider 读屏障 | 别名解析后的锁键和 access/scope 必须来自绑定贡献，不能信任旧请求中的绕过字段 |

新设备入口既有错误继续精确断言：未知 provider/能力精确版本/设备为 404 `not_found`；旧 generation、未观测、离线或能力不可用为 409 `conflict`；非法输入为 400 `invalid_input`。这些码不自动套到尚未冻结的别名配置错误。矩阵中的别名歧义必须拒绝，但公开码须冻结后填入断言，不能接受任意 4xx。执行失败与提交准入错误分别记录，不能把 HTTP 已接受任务误当作业务成功。

## 最小真实夹具与记录

使用一个真实 Rust HTTP/MCP 宿主和两个独立 Node 提供者 A、B：都发现 localID=`same`，A 另发现 `other`；platform 标签相同。通过显式配置将代表性旧操作绑定 A 的精确能力，B 保持可调用，用来检测误路由与锁过宽。宿主默认免鉴权，Node 入口是管理员可信配置；不证明隔离。协议 2 和 3 参数化关键成功/产物测试，涉及合作取消用协议 3。

夹具提供 discover、device read、device write、provider write 以及生成固定 PNG 的能力。每次调用记录独立 label、提供者、请求关联、标准封套、真实 PID、ready、release、response_written、stdin_eof 和自然退出；协议 3 另记录取消原因及 cleaned。释放文件属于本次管理员临时目录，不由业务请求选择任意路径；不派生后台进程或调用 ADB/HDC/Java。

基础发现单独完成后固定任务基线。按用例记录提交前后的持久化 Job ID 集合、HTTP/MCP 返回 ID、Job.operation/状态/结果、事件序列、日志关联、当前 generation、进程调用记录和产物摘要。查询至少覆盖本次新增任务全集，不能因 `limit` 或分页漏掉隐藏任务。一次旧调用应增加恰好一个 Job 和一次目标能力调用；发现 Job 不计入该增量。协议 request_id 与 Job ID 不要求字面相等，需通过日志或调用标签建立关联。

并发断言先观察第一任务真实 ready，再提交第二任务；用门闩释放决定阶段，不以固定睡眠或请求耗时证明互斥。确认第二任务已被宿主接受，并用有界事件观察及释放前后事件顺序核对未执行；另设跨设备/跨提供者任务作可运行对照。业务期限沿已冻结能力总预算，清理期限独立，不为验收扩大生产期限。失败保留本次目录、最后请求路径/状态、Job/events 和进程标记，不记录敏感正文，不删除首轮失败证据。

## 最小集成矩阵

以下 10 组可以按独立验收快照顺序执行；每组只引用当前构建和固定配置快照，结果不跨构建拼接。HTTP/MCP 都应读取共享终态。通过协议、操作或入口参数化覆盖，不另搭第二套任务流程。

| 编号 | 操作与步骤 | 精确通过证据 | 入口与参数化 |
| --- | --- | --- | --- |
| B01 同一 Job 与旧输入 | 显式绑定旧写操作到 A；提交旧 device_id/业务参数，等待真实调用完成，再以另一传输查询同一 ID | 新增 Job 恰好 1 个；调用 A 恰好 1 次、B 0 次；夹具收到标准 `{device_id,input}` 且业务字段无丢失；原 Job 完成旧结果映射；日志和事件都指向该 Job，无隐藏嵌套任务 | HTTP jobs 提交、MCP 查询；MCP 旧同名工具提交、HTTP 查询；协议 2/3 |
| B02 旧结果与产物 | 旧安装/卸载、截图、输入及 APKS 代表操作分别走实际绑定；截图下载输出原字节 | 严格比较冻结的旧 result 字段与类型，不向旧结果泄漏 result/artifacts 双层包装或服务器路径；截图返回的 id 对应唯一实际输出，HTTP 下载 size/hash/原字节一致；错误结果不误选产物或映射为成功 | 旧操作集合见下一节；协议 2/3 产物包装 |
| B03 显式选择与歧义 | A/B 同 platform、同 localID；反转加载顺序；显式绑定 A 后执行；再以独立配置快照覆盖缺失、重复或歧义绑定 | 显式选择始终只调用 A；拒绝分支精确等于冻结错误码或启动配置错误，无能力进程、无半份别名；不能按顺序选择 B 或回退内置；原有效注册不被失败配置污染 | 配置若仅启动读取则每个配置独立宿主；不假设存在热改配置 API |
| B04 原子贡献发布 | 加载含多个旧绑定的目标，制造贡献名冲突或一项无效映射；随后加载完整有效目标 | 失败后 operations 和 MCP tools/list 均无半份新增贡献/别名；已有注册保持；成功时旧入口与目标贡献来自同一快照、同一代际 | HTTP/MCP 操作列表和加载管理 |
| B05 撤销与排空 | 旧别名写任务真实 ready 后持门闩；排队第二个旧任务；请求卸载 A，同时观察旧/新入口 | 两入口同步停止准入；排队任务无进程；运行任务经取消到唯一终态，响应不能晚到覆盖；卸载返回成功时清理确认与实际 PID 退出均成立，目录撤销；历史结果/产物保留 | 旧 HTTP/MCP；新 device-actions/直接贡献；协议 3 |
| B06 重载与旧引用 | 保留 A 的旧 generation 与测试内捕获的旧绑定快照，卸载重载；未刷新、成功刷新后分别调用 | generation 改变；新入口旧 ref 精确 409 `conflict`；应用集成中的旧捕获绑定不得转投新代；未观测新代不能执行；刷新后旧名称的新提交按新绑定成功；历史 Job/结果不改写 | 真实服务验证公开 ref；内部捕获快照由应用集成补足，旧裸输入不假装携带 generation |
| B07 同设备共享写锁 | 旧别名写 A/same 到 ready；分别提交新 device-action、直接 jobs 同目标贡献和 MCP 新贡献写，逐次释放 | A/same 写调用事件串行，后一个 started 在前一个确认结束之后；旧/新入口互换首任务也成立；每提交仍只有一个 Job；等待者取消后永不启动 | 旧别名 ↔ 新能力/直接贡献，覆盖 HTTP/MCP |
| B08 provider 写屏障与并行对照 | A 的 provider write 到 ready；提交旧别名 device read/write；同时提交 B/same；另测 A/other 写和同设备两个读 | provider write 阻止 A 的全部 device action，包括旧别名读；B 可并行；无屏障时 A/other 写与 A/same 写可并行，同设备读彼此可并行；不能增加全局锁冒充共享互斥 | 旧读/写别名 + 新 provider/device 入口 |
| B09 失败与取消映射 | 在旧绑定中制造未知/不可用/未观测目标、非法旧输入、真实执行失败；运行后取消；夹具另设拒绝合作 | 准入错误精确匹配冻结码且零能力调用；执行失败保留同一 Job 的失败/取消终态，不能伪造成功旧结果；合作取消确认 PID 退出；拒绝合作精确 `cleanup_failed`，资源未确认保持 draining，旧/新入口均拒绝、重载不能绕过 | 旧 HTTP/MCP 与新入口对照；合作清理/拒绝合作协议 3 |
| B10 空部署与缺失目标 | 无平台包/平台工具启动宿主；使用独立配置快照指向缺失目标，再在线部署加载 A、刷新、卸载 | 空部署不因别名探测或启动平台工具；缺失目标依冻结规则明确隐藏/拒绝，不隐式执行内置；加载后才可调用，卸载后不可调用；运行中加载/卸载宿主 PID 与启动标记不变 | 配置规则若要求缺失目标启动拒绝则单独记配置失败，不把它冒充空部署服务通过 |

## 旧输入与结果的最小映射样本

以下是旧接口依据，不表示已批准把所有平台行为映射到某一通用模拟能力。方案应先给出逐项映射，再以真实协议夹具返回不同哨兵值核对，避免只测空对象。

| 旧操作族 | 旧输入/结果依据 | 最小对照与不可遗漏项 |
| --- | --- | --- |
| `android.app.install`、`harmony.app.install` | device_id、artifact_id → artifact_id、output，见 [设备产物操作](../contracts/设备产物操作.md) | Android/Harmony 分别显式绑定；标准封套内产物 ID 保持；协议 2/3 嵌套副本字段来自声明；旧结果产物 ID 和受控 output 正确，不泄漏副本路径 |
| `android.app.uninstall`、`harmony.app.uninstall` | device_id、package → output | package 不丢失，不退化为原样转发整个旧对象；非法 package/额外字段拒绝；不同提供者同 localID 不串线 |
| `android.screenshot` | device_id → 裸 Artifact：id、filename、media_type、size、sha256、created_at | 指定哪份输出映射为旧 Artifact，不能任意取第一项；零输出/多输出错误规则需冻结；返回 ID 可通过现有内容接口下载原 PNG |
| `android.input` | device_id、action → device_id、action、dispatched，见 [设备输入接口](../contracts/设备输入接口.md) | 至少 tap 与 text 两个带值样本；特殊字符按字面保留，额外字段拒绝；dispatched 不解释为真机响应或回滚完成 |
| `android.app.install_apks` | artifact_id、device_id → artifact_id、device_id、installed，见 [APKS 设备匹配接口](../contracts/APKS设备匹配接口.md) | 布尔 installed 和原 ID 保持；新绑定声明及共享期限与原长安装要求分别验证，短调用不证明实际长安装或真实包兼容 |
| `android.devices`、`harmony.devices` | 旧设备数组及平台特有状态，迁出文档明确关注 recovery/sideload/bootloader | 先冻结新发现到旧数组的映射及扩展信息来源；现行通用设备状态不足以表示这些旧状态时，列为兼容阻塞，不能静默折叠为 online/unknown 或宣称全映射通过 |
| `android.packages`、`harmony.packages`、启动/停止、连接/断开 | 既有 DeviceTools 操作及具体平台结果 | 逐项补结果样本后才扩展 B02；无 device_id 的连接操作需冻结 provider scope 映射，不可因共用旧名称便套 device write；不宣称 Harmony 有尚未实现能力 |

协议执行失败当前可能只是字符串 error，不能据此设计不存在的平台结构化错误。旧操作结果转换只在目标执行成功、响应协议有效、输出发布成功后产生；取消、超时、发布失败或资源清理未确认不得进入成功结果转换。对已持久化终态保存 JSON 快照，卸载/重载后逐字段对照，排除迁移时重写旧结果。

## 流水线交接与判定

先冻结配置/结果规则，再按 B01–B04、B05–B06、B07–B10 分批验收；每批写独立报告，包含源码/构建标识、包摘要、配置摘要、用例 ID、精确预期/实际、失败路径与退出结果。配置摘要不能包含工具凭据或任意业务正文。批次交接后文件冻结，下一项可独立准备，真实服务与 Cargo 构建仍由主代理串行协调。

每组报告区分“设计待冻结”“已落盘静态核对”“编译通过”“真实模拟集成通过”“失败待定位”。只列编译或 mock 结果不得标为真实服务通过；之后某次通过不能抹掉此前未确证的间歇失败。宿主关停、监听释放、本次夹具 PID 全部退出及失败目录保留均需记录，不能仅凭 cleaned 或 HTTP 200 判断资源完成。

本矩阵不包括平台插件业务实现、真实 APK/HAP/APKS、ADB/HDC daemon、常驻连接、真机事务、跨提供者物理设备统一身份及性能会话热卸载。A/B 同 localID 仅验证提供者选择和局部锁键，不证明同一物理设备经两个提供者暴露时已经共享锁。

本次文档只做 UTF-8、链接目标、行末空白和差异静态检查，未执行 Cargo、服务或真实夹具。据主代理本轮交接，19 项设备期限集成、后端 278 项测试及 Clippy/build/架构已通过；这些结果属于既有期限与后端门禁，不能作为旧操作绑定通过证据。本文旧绑定矩阵仍为设计交付，尚未实施、尚未运行。
