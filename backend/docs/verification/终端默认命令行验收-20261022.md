# 终端默认命令行验收

日期：2026年10月22日。用户要求终端打开普通命令行；原默认模板只有 `python -u -i`，所以页面选中的第一个档案进入Python解释器。

## 实施与当前配置

源码清单及示例改用Windows PowerShell档案 `powershell`，固定 `-NoLogo -NoProfile -NoExit -Command`，启动时将标准输入、输出和外部程序输入设为UTF-8。保持既有profile选择、受限环境、原字节会话、直接进程资源范围，不改公共工具执行器或会话协议。

当前预览清单同步默认值，再经公开配置重置接口按预期修订写入。最终 `revision:2`、`applied_revision:2`、`source:managed`、`compatible:true`，用户根 `C:\Users\柠檬果\.deviceforge\plugin-configurations\server\terminal` 的 `state.json` 和 `2.json` 均实际复读一致。已正常结束原Python会话，历史记录保留；没有重启宿主。只为当前明确要求切换的用户配置执行重置，默认模板升级不会自动覆盖其他已有档案。

最初尝试CMD：启动、ASCII命令及切换目录成功，但UTF-8代码页的管道中文输入使其提前正常退出。独立Node进程在CRLF及LF两种输入下均复现，因而最终默认选择PowerShell。受限环境没有 `OS` 变量，第一轮用 `%OS%` 作为验证条件也不成立；该失败与中文失败分别保留，不修改环境白名单。

## 实际验证

- 当前7031真实HTTP打开PowerShell、等提示符、执行 `echo`、切换用户目录并复读目录、中文命令输出、`dir`、`exit`，七项检查通过。输入使用页面相同的UTF-8和LF；输出断言匹配独立结果行，避免误将命令回显当作执行成功。
- 最终结果退出码0、无业务错误、`cleanup:complete`、`process_exited:true`。仅删除本次测试会话记录；复读原有两个历史记录仍存在，均为已结束且清理完成。
- 终端插件库14/14、所属包fmt、全目标Clippy和debug build均退出0。后端架构及6项规则测试退出0。
- 全工作区fmt失败，差异来自其他会话正在修改的资源/安装模块；API生成也因这些开发中的重复模块声明、缺失文件、未补齐字段而编译失败。未接手这些文件，不将定点结果记为完整workspace门禁通过。

证据根为 `artifacts/terminal-cmd-20261022/`：`report.json`、`command-output.txt` 是最终成功；`report-first-failure.json`、`report-cmd-chinese-failure.json`、`encoding-probe.json` 保留原失败，`powershell-probe.json` 为独立真实进程对照，`powershell-configuration-reset.json` 为公开配置操作结果。输入和原输出仅保留在本轮忽略目录的验收材料，没有写入生产诊断日志。
