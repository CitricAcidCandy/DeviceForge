# 普通操作真实长进程验收方案

状态：LONG-TEST 的独立验收设计交接，尚未编写根脚本、构建夹具或运行进程。唯一实施输入为《普通操作总期限第一批契约》，SHA-256 `6CBE0F61F84D52617AE6939C3FE630303251F44CC37D9777733D8A0336A40914`。此前 17 项公开应用测试已释放给主代理统一格式化、执行和登记；本方案不修改该写集，也不预判其结果。

本方案面向协议 2/3 的普通操作，不是设备能力、常驻真机或性能负载验收。历史 P1/P2 回归、内部父 D、成功资格失败复位及 shutdown 资格竞争由主代理处理，不在这里重复接管。根脚本和真实部署进程目前没有本角色写入或运行授权。

## 真实测量与唯一身份

普通宿主 Job 使用注册时固化的 execution 元数据和一个总 D。旧协议说明中的 60 秒分阶段窗口、协议 3 一小时默认值不能拿来解释本次普通 Job；直接执行器 context None 的兼容边界另记。D 不增加到 SDK Request、业务 input 或 Job DTO 中。HTTP 端无法直接读取精确 t_admit/D，本方案不从请求发送时间或当前目录反推历史 Job 的预算快照。

两份自包含可信 Node 包分别固定 `protocol_version=2` 和 `protocol_version=3`，使用不同 plugin_id。每份至少声明 long（execution 120000ms）、short（显式短预算）和 default（省略 execution）普通操作。short 候选 10000ms，最终值在夹具冻结时登记，属于测试包声明而非调大生产期限。默认包同时带设备贡献不是本次最小夹具要求；专用预算禁止重复声明的验证沿所属纯规则测试。

包内程序经管理员装配的本次控制根写 ready/release/诊断 marker；控制根和 Node 程序路径不由公开业务 input 指定。业务 input 只使用有限 case_id 等合法字段，不传延长预算或 shell。真实在线包按现便携 package.json.deviceforge 与 plugin.json 契约构造，复用已有 archive 工具，不复制 TAR 构造器；后续根脚本需要单独分配写集。

每次执行建立唯一证据行，字段最少如下：

| 字段 | 来源与断言 |
| --- | --- |
| run_id / case_id / protocol_version | 本次冻结夹具与业务案例，隔离控制文件并防旧 marker 复用 |
| plugin_id / version / generation / public_operation / request_operation | 实际加载目录、公开操作与 SDK Request.operation 分别登记；依冻结映射核对两者，不假设名称相同。重载的 generation 另存，不给 Job 补 owner 字段 |
| job_id / original_input 摘要 | HTTP/MCP 实际提交结果及 GET/history/events；保留原 operation/id，输入只比较合成测试字段或摘要 |
| request_id | SDK `Request.request_id` 原值、匹配 `Response.request_id`；它不是 HTTP log_id，也不假设等于 job_id |
| pid | 夹具实际 process.pid 与本次启动 marker，须关联到对应 request_id；不按进程名收集或结束其它 Node |
| submit_log_id / cancel_log_id / query_log_ids | 各次真实响应；提交关联执行日志，查询和取消各有新 ID，逐条经 job_id/request_id 连接 |
| 运行身份 | 真实 Rust executable 路径/SHA、Node 实际路径/版本、插件原 TGZ SHA 与部署入口 SHA；CLI 分发另核对 shim target 与实际 HTTP host |

ready 在合法 Request 已解析、request_id 已校验、夹具清理处理器已准备后写入。marker 至少带 case_id、protocol_version、request_id、operation、pid 和单调时钟值。采用每进程单调时钟，不把不同进程的绝对计数直接相减；纳秒值用十进制字符串持久化，避免 JSON number 精度损失。

报告分开记录插件 ready→release_observed 的实际耗时，以及验收驱动 ready_observed→release_written 的实际耗时。前者来自夹具自身单调计数，后者来自驱动自身单调计数；两者互证，不能只以宿主轮询持续 61 秒证明子进程持续执行。正常完成时在匹配响应的有限业务摘要中返回 request_id、pid 和 elapsed_ms，核对其与 marker 一致，不保存任意插件正文。

夹具事件最少含 ready、release_observed 或 cancel_control_received、cleanup_started/cleaned（协议 3）、response_written、stdin_eof、process_exit。response_written 需等真实 stdout 写入完成回调，不能在调用 write 前记作已发送。process_exit marker 只证明退出回调发生；实际退出还需自有 PID 存活检查或可用的真实退出句柄及宿主传输结果。没有直接退出码观测时写明来源或未记录，不能把 marker 或 PID 不存在伪写为 OS exit0。

## 两协议真实进程最小矩阵

| 编号 | 触发与放行 | 必须通过的断言 |
| --- | --- | --- |
| L2 | 协议 2 long；真实 ready 后，驱动保持未放行至少 61000ms，再写该 request_id 专属 release | 插件实际 ready→release_observed 也至少 61000ms；匹配协议 2 响应；同一 Job Succeeded、有限测量摘要正确、仅一次 request/实际 PID；实际直接 PID 退出 |
| L3 | 协议 3 long；独立 ready/release 和单调测量，同样至少 61000ms | 同一 Job Succeeded；匹配的 CooperativeResponse、cleanup=complete、受控 cleaned、宿主确认正常传输收尾与实际直接 PID 退出；与 L2 独立计证 |
| S2-D | 协议 2 short；确认真实 ready，始终不 release，让原总 D 到期 | 同一 Job Failed，error 精确为“执行超时”，不改为成功/取消；无合法晚成功；实际直接 PID 退出。stdin EOF 是协议 2 正常输入边界，不能称合作清理 |
| S3-D | 协议 3 short；确认真实 ready，让原总 D 到期 | 同一 Job Failed/执行超时；实际收到匹配 command=cancel、reason 精确为 timeout，清理响应匹配且 complete；cleaned 与实际 PID 退出分别成立。记录线上原值，不接受 cancelled 或任意值集合；没有匹配控制帧不能仅凭 EOF 通过 |
| S2-C | 协议 2 short；ready 后且预算尚有余量时显式取消，不 release | 取消先于成功资格，同一 Job Cancelled、无成功结果；实际直接 PID 退出；进程终止不是外部资源确认 |
| S3-C | 协议 3 short；ready 后且预算尚有余量时显式取消，不 release | 同一 Job Cancelled；实际收到匹配 reason=cancelled，cleanup=complete、cleaned 与直接 PID 退出成立；迟到结果不得成为成功 |
| M2/M3 | 各协议 default 做一次受控短调用；分别读取操作目录与 finite result | 普通目录 execution 为 api_version=1、60000/default；long/short 为 declared 和冻结值；请求 input/SDK Request 不新增预算覆盖或绝对 D 字段 |

L2/L3 是各协议的跨旧窗口证明。冻结契约的最低真实判据是至少一项实际跨 60 秒；本最小方案选择两协议都跨 61 秒，避免以协议 2 的实测替协议 3 收口。若主代理确认宿主至少有两个 worker，可在同一服务并行两个受控 Job 节省总墙钟；两者分别记录实耗时、请求、PID 和结果，不能合并为一条长执行证据。服务生命周期和构建仍由主代理串行调度。

短 D 的 ready 若未在预算内出现，应以原失败阶段保留证据，不能延长声明或生产期限补过。成功长调用在 120000ms 总预算内放行，准备/队列已消耗的时间不会另补。外层 Job 观察窗口按该操作的总预算和既有清理窗口有界设置；单次 HTTP/MCP 请求限时、设备既有 30 秒期限、协议 3 的 1250ms 合作/500ms 终止及外围 2 秒清理、10 秒宿主退出均不因此扩大。

M2/M3 的目录加短成功不单独证明默认 60 秒的真实到期行为；本矩阵也不真实等待一小时上限。默认/上限及父 D 的纯规则与受控时钟证据单独关联，需要真实默认到期时另由主代理排程，不能从读取 60000 或 120000 字段宣称已经测过对应执行期限。

SDK 协议 2/3 的 Response 是进程线上的结构，Job.result 可含宿主已发布产物包装。实现验收函数时按真实公开结果格式固定提取测量摘要，不凭业务 JSON 出现 result/artifacts 推断宿主包装。本最小夹具没有文件输出时，精确断言其产物为空；部分发布及输入副本剩余 D 的受控存储证明由所属基础设施验收关联，不能由长时间 hold 的成功替代。

协议 3 的 complete 是可信夹具对本次 synthetic_demo 清理的声明；marker 只证明受控文件资源，不代表真机恢复、常驻会话结束或操作回滚。清理失败/无响应的粘性风险、排队拒绝、draining 和同 ID 保护必须另关联最终宿主上的合作回归；不能以 L3 或 S3-C 成功关闭这些失败分支。若出现 cleanup_failed，不把它放宽为此表的正常 Timeout/Cancelled 通过。

S3-D 的线上 reason 已由主代理核对后冻结为 timeout：`backend/crates/infrastructure/src/process/cooperative.rs:85` 的 `cancellation_reason(shared_deadline)` 在共享 D 已到期时返回 Timeout，token 即使先被消费也不能掩盖原因；同文件的取消 select 分支使用该判断。来源包括 `cancellation_at_shared_deadline_is_timeout_but_earlier_cancel_is_cancelled` 和真实 Node 用例 `real_timeout_and_outer_cancel_keep_timeout_reason_and_confirm_cleanup`。本角色只读核对源码，没有运行这些测试；历史实现证据不替代本批动态复验、Application 或 HTTP/MCP 实际包链。宿主 Job 的 Timeout 与进程控制帧的 reason 仍是两份独立观测，不能由前者反推后者，也不能由 EOF 替代控制帧。

## HTTP/MCP 共用 Job 层

最小一轮采用下列分配，不机械展开所有协议、操作、入口的笛卡尔积。当前只是计划，尚无实际 Job 或请求数量。

| 案例 | 提交入口 | 跨入口观察 |
| --- | --- | --- |
| L2 / L3 | L2 经 HTTP，L3 经 MCP | 两个 Job 均经 HTTP 查询及 MCP 现有 Job 查询工具读取，核对同一 id/operation/input/status/result；每个 Job 只有一次实际插件 request |
| S2-D / S3-D | S2-D 经 HTTP，S3-D 经 MCP | 同一个失败 Job 的历史和事件在两入口一致，error 精确为执行超时；S3-D 控制 reason=timeout 另外实核，缺帧或不符不得计通过 |
| S2-C / S3-C | S2-C 经 MCP，S3-C 经 HTTP | 经相反入口显式取消，并从两入口核对同一 Cancelled；取消响应的关联 ID 不覆盖提交 ID 或原失败请求 |
| M2 / M3 | M2 经 HTTP，M3 经 MCP | 比较实际操作目录 effective execution 与合法短结果；确认业务 input 未带预算覆盖字段 |

拟共 8 个 Job，各对应一个实际 request/PID，成功与失败计数按该轮真实结果生成。HTTP 使用现有 v2 包装和公开任务端点；MCP 使用标准 tools/list、tools/call 及现有 Job 查询/取消工具。脚本实施时从冻结公开路由和实际工具 schema 固定名称、参数与响应路径，不创造工具名，不修改 driver 接口，也不向标准 Tool 顶层猜加 execution 字段。

HTTP 操作目录记录 api_version、total_timeout_ms、source；MCP 工具列表记录真实名称、输入 schema 和已有元数据。如果 MCP 当前列表没有独立预算元数据字段，应明确记其目录观测边界，不能从 arguments schema 推算预算。MCP 实际 L3 和 S3-D 等运行结果仍须独立证明使用同一普通任务策略，HTTP 目录读取不能替它计证。

提交成功获取 Job 后，GET 返回 HTTP 200 和一个 Failed Job 不等于“请求返回 timeout 错误”；分别保存请求层状态和任务层 status/error。HTTP/MCP 的领域失败须精确核对冻结 code、状态和 log_id，不以任意 4xx 或 MCP isError 就通过。对控制帧、响应、Job 历史和日志记录的对应关系按 request_id/job_id 建立索引，查询次数或日志行数不能扩大为逐 Job 关联成功数。

基线采用默认免令牌的真实本地宿主，普通调用不发 Authorization。可选令牌授权/拒绝仍由主代理既有回归保留，不由本方案新增鉴权规则。若长执行中服务停止，需记录其真实退出原因与本次进程证据；不得靠重启再跑把原失败覆盖为成功。

## 报告、失败保留与收尾

每轮报告独立记录 profile（debug/release/npx）、execution_id、UTC 采集区间、完整实际输入清单的范围/算法/SHA、宿主与包身份、case 明细和 cleanup 明细。UTC 只用于关联定位，真实耗时采用上述各进程自身的单调时钟。本方案不固定输入文件数、请求数、日志行数或进程数量；期望 Job 数来自本轮启用矩阵，实际数按唯一 id 重新统计。

每个 case 至少有这些独立检查：公开预算与输入、同 Job 历史、request 匹配、ready/release 或取消事件、实际耗时、直接 PID 退出、协议 3 清理确认（适用时）、真实日志关联。长成功、到期、取消分别计数；请求数、唯一 Job 数、唯一 request 数和观察到的直接进程数分别列出，不将轮询数扩大为逐 Job 证明。共享宿主内并行只影响调度，不能合并两协议 case 的计证。

日志在正常 shutdown 刷新后实核。按每次 submit/cancel/query 的 log_id 和对应 job_id/request_id 建索引，列实际文件、大小、SHA 和命中的受限关联字段；只采目录和少量端点不能称成功/取消内部门禁原子性证明。终态先于查询的事件、晚到回调、取消/成功短时门禁仍关联主代理的受控应用及内部测试，不能由 HTTP 采样代替。

失败立即保存 primary_failure：case/stage、请求方法/路径或工具名、关联 ID、有限结构化错误、最后明确成功的门闩和进程观测。不得保存环境、Authorization、原始请求正文、任意响应正文或插件 stderr。finally 的 shutdown/清理错误追加记录，不替换 primary_failure；原失败 report/checkpoint 不覆盖为复跑结果。

只清理本次创建且绝对路径确认在控制根内的资源，只操作自己启动的进程句柄或已验证的本次 PID 身份。失败时保留临时根、原归档、marker/checkpoint 及脱敏日志，并在报告写真实路径和 SHA。正常成功若删除临时根，先归档实际使用的 TGZ 原字节及必要证据再核对复制 SHA；不能重生成同源包补造当次身份。

收尾独立记录所有真实 shutdown attempts 的状态/log_id、Rust 与 npx 的实际终态、是否强制兜底、每个本次插件 PID 退出观测和双端口分别释放。宿主退出等待仍 10 秒；若失败需保存原证据，不能默认扩大限时或结束未知 PID。协议 2 的被终止直接进程不要求伪造 exit0；正常成功以及协议 3 传输的零退出确认注明具体来源。无活动进程、清理 marker 存在和正常 shutdown 是不同检查。
