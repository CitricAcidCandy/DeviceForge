## 当前4Job与原runtime的互补

4Job分别为HTTP旧manifest、MCP新manifest、HTTP新extract_apk、MCP旧extract_apk。每次提交新增恰一Job，旧operation/input保留；HTTP/MCP读取同一Job和事件，唯一成功终态，卸载后历史不变。manifest核完整XML、字符串版本及显式null；extract核本次宿主Artifact元数据和实际下载原字节/SHA/响应logId。

两份manifest输入字节各自唯一，真实工具在不同私有目录ready后保持门闩；核两Job仍Running再release。工具记录实际argv、工具PID、父插件PID及执行路径，以私有副本摘要关联同一Job，结束后独立观察两PID不可见、私有目录消失和scratch空。两个无工具extract没有直接采集插件OS PID，只有各自Job/request/log关联。退出意图标记不能替代实际PID观测，PID不可见也不能提供OS退出码或派生树保证。

原runtime已覆盖的业务断言以当前源码为依据：APK清单包名/转义版本名，AAB默认base；签名证书摘要；default构建两APK和null、universal一APK及universal.apk；离线分包条目/规格及下载摘要；decode计数/输出名与下载摘要；MCP扫描命中和缺失类；提取与后续模拟设备安装。它主要验证旧入口业务链，不能说每项都已同时验证旧/新两入口、完整DTO、每个产物原字节或每个Job实际插件PID。

4Job额外检查七对贡献目录、预算复制及卸载撤销，但另外五项只有目录观测。HTTP/MCP目录采样不证明注册原子性、内部门禁竞态或提交资格。

## 七操作服务增量候选

下表每行业务变体各调用旧alias与新target一次，HTTP/MCP交错提交、反向查询，共18个正向Job。每对使用同一上传Artifact和相同业务input，分别有自己的Job、插件request及产物；“同Job”指每次提交没有嵌套Job，不指两次提交共享Job ID。18个是后续完整独立批次的候选规模，不能把历史4Job与新14Job拼称同一次18Job。

| 编号 | 业务输入和工具输出对照 | 需要补充的服务断言 |
| --- | --- | --- |
| S01 | APK manifest；独立固定XML含实体、原字符串版本与缺省字段 | 旧DTO等于新target宿主包装内value；XML原文及module/其它可空字段保留，不只比较包名 |
| S02 | AAB manifest；省略module默认base，另一规格可在后续补显式模块 | 核format=aab、module=base及完整DTO；真实bundletool固定argv进入私有副本，不把APK路径当AAB链证据 |
| S03 | signature；固定完整证书报告 | verified、所有signer/scheme、显式null与report完整；任务私有路径已替换为原filename，无配置/密码泄漏 |
| S04 | extract_apk；APKS中精确universal.apk固定二进制 | 旧source_artifact_id/entry/artifact与新value/发布列表对应；extracted.apk必须是本次发布，下载等于预置原成员字节 |
| S05 | build_apks default；假工具产生固定两APK容器 | mode、apk_count=2、universal_entry=null；built.apks实际下载等于工具固定原件，产物ID由宿主产生 |
| S06 | build_apks universal；假工具产生唯一universal.apk | mode、apk_count=1、universal_entry精确；与S05分别验证，不能以其中一种构建代替另一种 |
| S07 | decode；固定必要文件及含中文/二进制的输出树 | files/unpacked_size对应固定树；decoded.zip独立读取成员、CRC及原文件字节，完整下载摘要等于宿主metadata |
| S08 | scan_sdks；用S07本次真实下载/发布Artifact作为输入，规则含命中、缺失、class_name省略或null | findings完整、class_found可空与证据排序；不从测试重造另一份ZIP冒称decode→scan链 |
| S09 | extract_splits；使用S05本次built.apks，显式设备规格 | 私有spec实际为工具camelCase格式，结果保持原snake_case；selected-apks.zip成员列表及每个APK原字节与预置固定样本一致 |

输出ZIP由核心打包时不预设时间戳、压缩实现或全ZIP字节必须等于另一归档器结果。S07/S09用独立有界ZIP读取核成员原字节与CRC；整个实际下载的SHA/size再与本次宿主metadata核对。S04/S05/S06的固定原件可直接比较全部字节。不能调用生产核心生成期望。

共同证据为：启动前Job基线；每次提交新增一Job；HTTP/MCP同历史原文与唯一终态；旧/新结果严格按真实宿主 `{result,artifacts}` 区别投影；响应及下载logId退出后落盘；每Job唯一插件调用开始/结束和request ID。工具类操作保留私有目录、工具PID、父插件PID、真实argv与唯一输入摘要，观察ready时存在及结束后不可见。无工具S04/S08的插件PID若没有直接采集，报告必须明确缺项，不能由日志生成一个OS PID。

## 真实工具与正式验收资格

独立std-only工具或runtime假Java只提供真实进程/argv/产物链证据。真正apkanalyzer、apksigner、Java/bundletool/apktool另记录可执行文件/JAR版本及摘要、系统、公开测试APK/AAB/APKS原件摘要、预期包名/证书/可用模块/已知分包，并核同一业务字段和下载原字节。签名只用专门测试密钥，报告不保存密码或原签名argv。

真实工具验收至少包含APK/AAB清单、有效签名及明确无效签名、default/universal构建、decode→scan、构建APKS→精确提取/离线规格选择。结构ZIP或工具输出正向不等于可安装APK；设备安装另走保留的设备能力及真机，不加入本七操作通过计数。不同OS及Windows批处理工具入口也不能由当前原生exe样本反推兼容。

每次动态批次须保存：实际命令/session终态；模式与宿主/插件/工具摘要；执行前后输入清单；本次包/配置/aliases身份；每个新增Job的operation/input/唯一终态与request/log；所有真实产物metadata、下载关联ID及字节核对；已观察PID与各自退出边界；服务正常退出和监听释放；失败原件。看门狗不是性能指标，暂停Tokio时间不证明真实子进程墙钟，声明120/240/480秒不代表已经经过该时长。
