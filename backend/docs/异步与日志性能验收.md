# 异步与日志性能验收

## 实现范围

服务器采用 Tokio 多线程运行时与 Axum，HTTP/MCP 共用任务层。任务和性能数据库分别由 4 槽阻塞工作池访问；许可在阻塞闭包中持有，取消请求不能提前释放仍在执行的工作名额。文件上传下载采用异步流，内容校验已有独立资源限制。

宿主日志使用生产 INFO JSONL 格式化、有界非阻塞队列及独立写线程，按日轮转并保留文件。默认每秒 120 请求和 128 个在途响应，与任务队列容量和执行并发分别限制。测试调高请求速率不会关闭其他资源边界。

## 行为证据（2026-10-09）

- 后端架构门禁及 2 项规则测试、fmt、全工作区 Clippy、123 项 Rust 测试和构建通过。后续只调整了日志测量示例的统计字段，示例所属 crate 的全部目标 Clippy 与 release 运行再次通过。
- 单线程 Tokio 下挂起同步数据库查询，健康检查仍可响应；保留 128 个未读响应会拒绝新请求，关闭一个响应后恢复。响应完成、流错误、断开均释放名额。
- 真实服务验证 v2 成功/失败、MCP 成功/协议错误/传输拒绝、请求到任务及插件请求 ID、鉴权诊断、正常退出刷新。日志不包含测试令牌与敏感哨兵，所有落盘行均为合法 JSON。
- 两种 runtime-smoke 通过，设备工具为模拟进程，性能插件使用合成采样。前端生成类型、检查（0 错误/警告）、7 项测试和构建通过；前端仍无业务客户端。
- Windows x64 release 运行包重建，根 Node 10 项测试、真实 npm pack/npx 插件安装与调用、两个本机地址、独立 MCP 和正常退出刷新通过。

## 本机短时 HTTP 基线

最新报告为根目录 `artifacts/logging-smoke-release.json`（2026-10-09T04:42:06Z）。真实 release 服务、SQLite、INFO 日志、回环连接，每个接口 2000 请求、32 并发，测试部署限流 100000/s；本轮同机同时执行其他集成检查，结果只作为短时观察，不能用于宣布稳定容量或生产上限。

## 日志突发饱和测量

报告为根目录 `artifacts/logging-benchmark-release.json`；四线程共尝试提交 30000 条生产格式记录，默认 8192 条队列。提交 p50/p95/p99 为 3.0/4.6/6.9 μs；提交尝试约 104 万次/秒。

实际落盘 9476 条，队列丢弃 20524 条，正常退出刷新约 222 ms；包含刷新的落盘速率约 3.77 万条/秒，写入错误为 0。提交尝试速率不能作为完整写入吞吐；突发超出写线程处理能力时，系统选择维持请求响应并暴露丢弃计数。

队列溢出、强制终止和磁盘异常允许丢日志，当前日志是诊断体系。若后续需要不可丢失的审计记录，应单独定义持久确认、配额和背压，不能沿用本队列语义。

## 未验收范围

慢磁盘、长时间生产负载、另一台局域网主机、其他系统、真机工具及真实 FPS 尚未验收。通用进程插件动态管理的当前证据见 [运行中插件生命周期](运行中插件生命周期.md)，后端测试已增至 132 项；设备提供者 SDK、常驻插件与设备层热拔插仍为待实施目标。异步服务器和日志基础通过检查不能代表整体业务迁移完成。
