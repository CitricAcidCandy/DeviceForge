# 统一插件安装 v1 冻结契约

本轮采用领域 `plugin_installations` 模块的 Rust 类型作为唯一 DTO 来源。HTTP/MCP 接线和生成器由主代理维护，浏览器沿用 snake_case 字段。基础设施通过 reqwest 0.12（rustls-tls、stream）下载资源；新增公共 `tool-repository` 工作区成员，独占不可变工具内容、仓库锁、引用与运行使用保护，不依赖宿主、网络或具体插件。

## 发布与来源

`release.json` 使用 `format_version:1`、`host_api_version:2`，包含 id、version、name、description、components、tools、requirements。组件为 `{id,kind:server|browser,version,variants}`；每个变体为 `{platform,path,sha256,size,format:zip|tgz}`。组件归档沿用已公开的便携 `package.json.deviceforge` 格式。

市场来源固定 `{kind:market,source_url,release_id,version,manifest_sha256}`。source_url 是 release.json 的完整 HTTP/HTTPS URL，path 是它的相对 URL；以原始清单 SHA-256、发布 ID 和版本三重匹配。离线来源固定 `{kind:offline,artifact_id}`，产物为 ZIP，根目录包含 release.json 及其 path 指定的全部资源，不访问网络。

宿主另以 `open_with_sources` 配置可信市场目录根 URL，最多 128 项。目录根 `/subdir` 与 `/subdir/` 等价，只允许同源且处于 `/subdir/` 目录边界内的发布清单和资源；不会把无尾斜线目录解释成文件并扩大到其父目录。空集合拒绝在线安装，离线安装仍可用。所有网络请求禁止重定向。

工具为 `{id,version,required:true,variants,bindings:[]}`，required 缺省 true；变体另有 `entries:{资源键:归档内相对文件}`，允许 zip、tgz、file。file 格式固定保存为 payload，因此 entries 的值必须为 payload。绑定固定 `{component_id,config_pointer,entry}`，entry 为该工具 entries 中的稳定键。平台优先当前宿主，其次 any；必需工具缺平台失败，可选工具缺平台略过。选中可选工具的下载或完整性失败仍报错，避免静默隐藏损坏。

requirements 为 `{component_id,config_pointer,any_of?:[],title,description,sensitive:false,required:true}`，声明账号或用户必要输入。`any_of` 是同组件的额外 JSON Pointer，最多16项，与主 `config_pointer` 去重；主指针或任一额外指针的原值已填写即满足该条。省略或空数组继续使用原有单字段规则；多条必需声明之间仍须全部满足。用于本地供应清单与远端清单二选一等通用条件，不按官方插件ID分支；相互排斥和其他形状约束继续由组件配置模式验证。安装器不写入用户输入，也不根据工具绑定修改配置原值；启用前由应用/宿主核对必要输入，敏感字段只读取资格布尔值。

## 用户目录和资源接缝

构造器接收已解析 `<home>/.deviceforge`，不读环境变量。目录固定：

- `plugins/<component_id>/manifest.json` 为服务器活动视图；真实程序位于其 `revisions/<release_sha256>/`。
- `browser-plugins/<component_id>/manifest.json` 为浏览器活动视图；资源位于其 `revisions/<release_sha256>/`。
- `tools/<tool_id>/<version>/<host_platform>/<variant_sha256>/` 为共享且经校验的工具内容，平台段使用实际宿主平台。
- `installations/releases/<release_id>.json` 为持久状态，`transactions/` 为恢复日志，暂存始终位于用户根内。
- `installations/resources/<sha256>` 为已核对大小和原始摘要的下载缓存；后续发布复用组件归档和工具时不再次下载。`identities/<kind>/<id>/<version>/<platform>.json` 固定版本摘要，卸载后也拒绝同版本替换成另一内容。
- `installations/manifests/<release_sha256>.json` 保存通过验证的发布清单，用于计算缓存引用；`installations/previous-<release_id>.json` 保护上版恢复资源。
- `plugin-configurations/server` 和 `browser` 不属于安装器写集，升级和删除均不清除配置。

活动视图包含 manifest.json、market.json、installation.json、resources.json。resources.json 使用 `{format_version:1,release_id,revision,tools:{工具ID:{version,platform,entries:{资源键:绝对文件}}},bindings:[{tool_id,component_id,config_pointer,entry}]}`，仅供宿主与 SDK，不从安装查询返回本机路径。配置 overlay 使用组件不可变 revision 目录内的 resources.json，按 component_id 与 config_pointer 将默认工具名替换为对应绝对文件；用户显式路径优先。market.json 包含 metadata_version、id、version、name、summary、description，身份与对应组件清单一致。

工具入口覆盖只产生有效配置快照，不改变用户保存值和修订。带标签工具对象可按本地模式的必需 `const` 自动补齐缺失标签，支持本地引用及组合模式；已有标签冲突、不同候选无法唯一确定时明确拒绝。该选择器依靠必需常量和已有判别常量选择分支，不是完整模式推理器：若必须依靠其他相邻字段的 `enum`、正则或数值约束才能从不同候选中回选，须先由用户明确判别字段。全部绑定完成后再用完整 JSON Schema 校验最终快照，避免多入口尚未补齐时提前失败。

浏览器不可变资源 URL 固定 `/api/v2/plugin-installations/browser/<component_id>/revisions/<release_sha256>/assets/<relative_path>`；存储 `asset` 方法核对已安装版本与受控相对路径。服务接线可将此 URL 作为浏览器包 entry_url 消费，不走旧包部署目录写入。

## 生命周期与接线

InstallationStore.plan 返回 `actions`（download/reuse/verify/install/preserve_previous）、`issues`、`resources`（kind、id、version、platform、sha256、size、reused、required）和 `download_size`；总下载量按尚未缓存的不同摘要去重。prepare 先完成网络/产物流、哈希、解包和便携组件校验，返回 PreparedInstallation；commit 在插件生命周期串行门禁中核对实际发布 ID 对应的 expected_revision。创建要求 null，更新要求旧 SHA-256。新安装满足 requirements 后默认 enabled，否则为 configuration_required；更新保留旧 enabled 意图。服务器敏感输入通过配置存储原值布尔门禁检查，不检查遮蔽值。

当前服务器文件存储覆盖 `requirements_configured`，同时检查原值、配置版本与完整模式；领域端口的默认实现依赖 `get().values`，以后若新增返回遮蔽视图的适配器，必须同样覆盖该方法。浏览器保存记录使用原值判断候选是否填写，启用门禁没有服务器同等的配置版本和完整模式检查；浏览器配置兼容性及组件激活结果仍由具体客户端单独反馈，不得由服务器 enabled 状态推断已通过。

InstalledRelease 字段见领域类型，revision 为清单原始字节 SHA-256，enabled 为持久启用意图，status 为 installed、enabled、configuration_required 或 recovery_blocked。恢复受阻时保留 enabled 原意图，并以可空 `failure:{phase,reason}` 记录有界失败阶段和原因；拒绝更新、启停和对外删除。文件事务日志会在下次启动重试恢复；无法读取或验证的日志仍使初始化明确失败。应用加载和撤销导致的阻断不会在没有修复证据时自动清除。

基础设施构造器：`FilePluginInstallations::open_with_sources(user_root, artifacts, node_binary, trusted_market_sources).await -> Result<Arc<Self>>`；旧三参数 `open` 委托为空可信来源。应用构造器：`InstallationService::new(store, plugins, server_configurations, browser_configurations) -> Arc<Self>`。应用方法 install(source,expected_revision)、list、get、set_enabled(id,expected_revision,enabled)、delete(id,expected_revision)、cleanup_resources(dry_run)、asset(component_id,revision,path)。

旧 plugin_packages 开放 crate 可见的归档/便携映射委托，统一发布使用独立展开限额，旧上传包仍保留原有小包限额。服务器 lifecycle 提供串行门禁内的 load/unload 方法，主程序调用 `plugins.bind_installations(store.clone())?` 后旧 load/unload 拒绝托管组件。`restore().await` 在监听前恢复持久启用；`install_cancelled` 在准备阶段响应取消，提交开始后继续持有门禁至稳定状态。启停、删除和清理分别提供同参数加 CancellationToken 的 `set_enabled_cancelled`、`delete_cancelled`、`cleanup_resources_cancelled`，在取得生命周期门禁后先检查取消，避免已过期的排队操作随后写入；开始写入后仍等待稳定结果。

事务先保存旧活动视图和旧状态，全部内容完成校验后才发布版本目录及活动视图，最后原子发布新状态；重启以持久状态的新 revision 判断事务完成，否则恢复旧活动视图。上一个组件版本保留，删除仅删活动视图及安装记录，版本与共享工具保留作复用与恢复。工具复用必须同时核对内容清单，不能只凭目录存在跳过。

发布清单最多 256 KiB；单资源最多 2 GiB；离线上传 ZIP 最多 4 GiB；每份归档展开总量最多 8 GiB、32768 条目。下载事务总期限 600 秒，无重定向，仅允许无凭据 HTTP/HTTPS 和同源相对资源。文件工作池、准备并发、资源读取并发分别为 2、2、8；用户目录由排他文件锁单宿主占用。资源下载采用有界共享协调，锁内重新核对缓存，避免两个准备任务重复获取同一摘要；等待仍消耗原始期限，取消等待者不影响下载者，发布工作取消后仍由实际文件工作持锁至结束。准备阶段使用目录租约，取消不会提前删除仍被阻塞文件工作使用的目录或释放准备配额；最后一个工作退出后异步清理目录并归还配额。启动恢复后回收上次中断的暂存目录。

`cleanup_resources(dry_run)` 是显式资源回收，没有自动垃圾回收。应用在生命周期门禁内读取真实运行组件 ID，再调用存储端口的同名方法，客户端不能传运行集合或删除路径。报告为 `{dry_run,items:[{resource,bytes}],total_bytes}`，resource 仅为安装器产生的相对标识。保护当前、上一版、未决事务两端及所引用工具、组件和摘要缓存；准备或事务尚未结束时全部保留。任何服务运行时保留全部展开工具；同组件运行时保留其所有历史版本；浏览器资源流仍被读取时保留全部浏览器版本。旧记录没有保存清单时保守保留全部缓存。所有候选先验证受控路径并计算总量，再逐项核边界删除，拒绝链接和目录越界。配置、身份摘要账本与保存清单不参与回收。

工具供应插件的托管模式与安装器共用 `tool-repository`。旧自定义根继续使用原语义；托管选择、活动发布、上一发布和未决事务写入各自引用。实际进程与常驻会话持有使用租约，调用 Future 被丢弃不提前释放租约；移除共享内容仍检查其他引用和运行使用。

托管模式允许省略 `install_root` 或使用 null，运行时读取宿主资源描述。自定义模式及省略模式的旧配置仍须提供本机有效绝对路径，不自动搬迁旧工具；公开模式容许跨平台绝对路径前缀，实际调用还会按本机规则检查并拒绝控制字符，因此保存成功不等于其他平台路径可以在本机执行。切换模式不会自动撤销无法确认的旧引用。
