# 统一插件安装 v1 冻结契约

本轮采用领域 `plugin_installations` 模块的 Rust 类型作为唯一 DTO 来源。HTTP/MCP 接线和生成器由主代理维护，浏览器沿用 snake_case 字段。新增依赖仅为基础设施 reqwest 0.12（rustls-tls、stream），不增加 workspace 成员。

## 发布与来源

`release.json` 使用 `format_version:1`、`host_api_version:2`，包含 id、version、name、description、components、tools、requirements。组件为 `{id,kind:server|browser,version,variants}`；每个变体为 `{platform,path,sha256,size,format:zip|tgz}`。组件归档沿用已公开的便携 `package.json.deviceforge` 格式。

市场来源固定 `{kind:market,source_url,release_id,version,manifest_sha256}`。source_url 是 release.json 的完整 HTTP/HTTPS URL，path 是它的相对 URL；以原始清单 SHA-256、发布 ID 和版本三重匹配。离线来源固定 `{kind:offline,artifact_id}`，产物为 ZIP，根目录包含 release.json 及其 path 指定的全部资源，不访问网络。

工具为 `{id,version,required:true,variants,bindings:[]}`，required 缺省 true；变体另有 `entries:{资源键:归档内相对文件}`，允许 zip、tgz、file。file 格式固定保存为 payload，因此 entries 的值必须为 payload。绑定固定 `{component_id,config_pointer,entry}`，entry 为该工具 entries 中的稳定键。平台优先当前宿主，其次 any；必需工具缺平台失败，可选工具缺平台略过。选中可选工具的下载或完整性失败仍报错，避免静默隐藏损坏。

requirements 为 `{component_id,config_pointer,title,description,sensitive:false,required:true}`，声明账号或用户必要输入。安装器不写入用户输入，也不根据工具绑定修改配置原值；启用前由应用/宿主核对必要输入。

## 用户目录和资源接缝

构造器接收已解析 `<home>/.deviceforge`，不读环境变量。目录固定：

- `plugins/<component_id>/manifest.json` 为服务器活动视图；真实程序位于其 `revisions/<release_sha256>/`。
- `browser-plugins/<component_id>/manifest.json` 为浏览器活动视图；资源位于其 `revisions/<release_sha256>/`。
- `tools/<tool_id>/<version>/<variant_sha256>/` 为共享且经校验的工具内容。
- `installations/releases/<release_id>.json` 为持久状态，`transactions/` 为恢复日志，暂存始终位于用户根内。
- `installations/resources/<sha256>` 为已核对大小和原始摘要的下载缓存；后续发布复用组件归档和工具时不再次下载。`identities/<kind>/<id>/<version>/<platform>.json` 固定版本摘要，卸载后也拒绝同版本替换成另一内容。
- `plugin-configurations/server` 和 `browser` 不属于安装器写集，升级和删除均不清除配置。

活动视图包含 manifest.json、market.json、installation.json、resources.json。resources.json 使用 `{format_version:1,release_id,revision,tools:{工具ID:{version,entries:{资源键:绝对文件}}},bindings:[{tool_id,component_id,config_pointer,entry}]}`，仅供宿主与 SDK，不从安装查询返回本机路径。配置 overlay 使用组件不可变 revision 目录内的 resources.json，按 component_id 与 config_pointer 将默认工具名替换为对应绝对文件；用户显式绝对路径优先。market.json 包含 metadata_version、id、version、name、summary、description，身份与对应组件清单一致。

浏览器不可变资源 URL 固定 `/api/v2/plugin-installations/browser/<component_id>/revisions/<release_sha256>/assets/<relative_path>`；存储 `asset` 方法核对已安装版本与受控相对路径。服务接线可将此 URL 作为浏览器包 entry_url 消费，不走旧包部署目录写入。

## 生命周期与接线

InstallationStore.plan 返回 `actions`（download/reuse/verify/install/preserve_previous）、`issues`、`resources`（kind、id、version、sha256、size、reused、required）和 `download_size`；总下载量按尚未缓存的不同摘要去重。prepare 先完成网络/产物流、哈希、解包和便携组件校验，返回 PreparedInstallation；commit 在插件生命周期串行门禁中核对实际发布 ID 对应的 expected_revision。创建要求 null，更新要求旧 SHA-256。新安装满足 requirements 后默认 enabled，否则为 configuration_required；更新保留旧 enabled 意图。服务器敏感输入通过配置存储原值布尔门禁检查，不检查遮蔽值。InstalledRelease 字段见领域类型，revision 为清单原始字节 SHA-256，enabled 为持久启用意图，status 为 installed、enabled 或 configuration_required。

基础设施构造器：`FilePluginInstallations::open(user_root, artifacts, node_binary).await -> Result<Arc<Self>>`；应用构造器：`InstallationService::new(store, plugins, server_configurations, browser_configurations) -> Arc<Self>`。应用方法 install(source,expected_revision)、list、get、set_enabled(id,expected_revision,enabled)、delete(id,expected_revision)、asset(component_id,revision,path)。

旧 plugin_packages 开放 crate 可见的归档/便携映射委托，统一发布使用独立展开限额，旧上传包仍保留原有小包限额。服务器 lifecycle 提供串行门禁内的 load/unload 方法，主程序调用 `plugins.bind_installations(store.clone())?` 后旧 load/unload 拒绝托管组件。`restore().await` 在监听前恢复持久启用；`install_cancelled` 在准备阶段响应取消，提交开始后继续持有门禁至稳定状态。

事务先保存旧活动视图和旧状态，全部内容完成校验后才发布版本目录及活动视图，最后原子发布新状态；重启以持久状态的新 revision 判断事务完成，否则恢复旧活动视图。上一个组件版本保留，删除仅删活动视图及安装记录，版本与共享工具保留作复用与恢复。工具复用必须同时核对内容清单，不能只凭目录存在跳过。

发布清单最多 256 KiB；单资源最多 2 GiB；离线上传 ZIP 最多 4 GiB；每份归档展开总量最多 8 GiB、32768 条目。下载事务总期限 600 秒，无重定向，仅允许无凭据 HTTP/HTTPS 和同源相对资源。文件工作池、准备并发、资源读取并发分别为 2、2、8；用户目录由排他文件锁单宿主占用。启动恢复后回收上次中断的暂存目录。共享工具与历史版本保留，当前没有自动垃圾回收。

验证尚待主代理统一执行 Cargo；本模块不自行运行共享构建或启动服务。
