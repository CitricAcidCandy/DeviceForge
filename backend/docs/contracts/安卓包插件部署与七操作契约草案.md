# 安卓包插件部署与七操作契约草案

## 状态、实施依据与范围

日期：2026-10-10。本文件冻结后仅作为可评审草案；插件 ID、部署配置、七项清单预算、工具政策与下文新写集均须主代理裁定，未据此实现生产插件。主代理已回报协议 4 新版后端六门禁 exit0、651 项测试、426 项输入零差异，报告标记为 025535；这属于公共 SDK/运行库及宿主版本的证据，不是安卓包插件、真实包或 npx 迁出的验收。

沿用《插件执行上下文第四版裁定》《普通操作总期限第一批契约》《包工具公共库第一批实施裁定》《剩余包操作薄适配第二批裁定》《包工具退出与目录租约裁定》。以下将既有七项纯包操作接入独立进程，不搬运宿主领域 trait、产物存储或工作池。`android.app.install_apks`、ADB、设备发现、性能和常驻连接不归包插件；不能把整个 splits 模块搬入本插件。

候选插件 ID 为 `android-packages`，协议固定选择 4，每任务一个进程。七个贡献使用 `plugin.android-packages.<后缀>` 命名，均为普通操作，显式声明 execution，不声明 devices/performance。不新增 HTTP/MCP、业务路径字段或父期限字段；旧名称由现有通用操作绑定接入同一 Job、owner、generation 和预算，没有第二次任务提交或内置回退。

## 部署配置：具体候选与注入方式

建议首批采用插件自行读取的有界 JSON 配置，不给宿主 main 增加 Java、包工具或签名分支。配置类型、路径政策和下面默认规则都是本草案候选，尚无对应实现。

| 注入入口 | 候选规则与归属 |
| --- | --- |
| 缺省 | 插件以 `std::env::current_exe()` 的父目录为基准，读取旁置 `android-packages.config.json`，不以宿主 cwd 为基准。便携包可带无签名配置样例；配置文件缺失等价于 tools 空对象、signing=null。 |
| 部署清单参数 | 允许唯一 `--config <绝对配置文件路径>` 覆盖缺省文件。使用现有 Manifest/PortableServerManifest.args，原样 argv 注入；只允许部署者修改清单，不提供 Job input 覆盖。便携安装只映射 executable，不会自动映射这个绝对参数；不得把开发机路径写入可跨机器分发的包。 |
| 环境 | 不新增读取 APK_* 的宿主桥，也不假定受限插件环境会继承自定义配置变量。可执行文件的非绝对名称仅依赖部署环境已经继承的 PATH；不提供 shell 或任意命令字符串。 |
| 读取时机 | 在有效 Start 后的 handler 中检查上下文，再读配置；安装、加载、进程握手均不启动 Java/工具、不验证签名密码。每任务读取一次，不在阶段切换时重新读或重置期限。 |
| 文件边界 | 候选上限 64 KiB，UTF-8 JSON，根及各层对象拒绝未知字段、错误版本和类型。显式文件缺失、链接/非普通文件、超限或语法坏配置返回固定配置失败；不回退另一来源。 |

配置 wire 候选如下。示例路径只表示字段用途，不是现存部署路径或可运行配置；签名密码内容不出现在示例、包、结果或日志中。

```json
{
  "format_version": 1,
  "tools": {
    "java": "java",
    "apkanalyzer": {"kind": "executable", "executable": "apkanalyzer"},
    "apksigner": {"kind": "java_jar", "jar": "G:/DeviceForgeTools/apksigner.jar"},
    "bundletool": {"kind": "java_jar", "jar": "G:/DeviceForgeTools/bundletool.jar"},
    "apktool": {"kind": "java_jar", "jar": "G:/DeviceForgeTools/apktool.jar"}
  },
  "signing": {
    "keystore": "G:/DeviceForgeSecrets/release.keystore",
    "alias": "release",
    "store_password_file": "G:/DeviceForgeSecrets/store.pass",
    "key_password_file": "G:/DeviceForgeSecrets/key.pass"
  },
  "scratch_root": null
}
```

| 字段 | 候选类型、缺省与校验 |
| --- | --- |
| format_version | 必填严格整数 1；其它值拒绝。配置缺失时由插件构造 format_version=1 的空配置，不把坏文件当缺失。 |
| tools | 对象，省略为空；每项可省略/null。缺少某工具只阻止实际依赖该工具的操作，不阻止其它六项或宿主启动。 |
| tools.java | 非空字符串，省略/null 表示未配置；java_jar 实际调用要求它存在。绝对程序路径或 PATH 中的单一程序名，不能含 shell 命令。 |
| tools.apkanalyzer | 仅 `kind=executable` 和 executable 字符串。不在本批发明其 JAR 启动参数；Windows 的实际可执行入口必须单独验收，不能默默加入 cmd /c。 |
| tools.apksigner | executable 或 java_jar 二选一；后者只有 jar 字段。不得允许同时提供 executable/jar 或额外 prefix/argv 字段。 |
| tools.bundletool、tools.apktool | 仅 java_jar；jar 必须为绝对路径，实际调用前检查普通文件且不接受链接。argv 前缀固定为 java、-jar、jar。 |
| signing | null/省略表示未配置；非空对象四项同时必填，路径为绝对路径、普通文件且拒链接，alias 非空有界字符串。仅 build_apks 使用；不从业务请求取密钥或密码。候选 alias 上限 200 字节、所有配置路径/程序字符串上限 4096 字节且拒 NUL/控制符。 |
| scratch_root | null/省略使用系统临时目录；非空为部署者指定的绝对目录。每任务在其中创建独占随机子目录，不接收业务目的路径，不清扫其它任务目录。 |

签名调用沿旧 BundleSigning 语义使用密码文件参数，固定 build-apks argv 和 `--max-threads=2`；不把密码读取为 argv 明文，不把完整工具 argv、配置路径或 stderr 原文写入公开日志。签名文件是部署者长期资源，插件只读，不属于任务目录租约，也不能在任务清理中删除。

可执行文件不自动下载，包安装不执行脚本或 npm 安装；配置缺少工具时实际调用确定失败，不隐式回退到宿主旧适配器。可信代码部署及可选鉴权的边界保持当前规则；独立进程不等于隔离。

## 清单与授权产物入口

便携 package.json.deviceforge 使用现有 server/native entrypoints 规则，按已支持的目标键映射绝对入口。首批具体发行目标需主代理选择；不能以一个开发机二进制宣称所有系统可用。独立 manifest 省略 executable，交由安装器按入口映射，protocol_version=4、args 使用上面的候选部署注入。

七项共用现有声明：`artifacts={"input_fields":["artifact_id"],"input_pointers":[],"outputs":true}`。每次业务 input 只有一个顶层产物 ID 和下文参数；handler 必须在 SDK ArtifactContext.inputs 中唯一匹配 field=artifact_id 及相同 artifact_id，核对元数据、普通文件和 64 MiB 限额，不能根据业务字符串拼接宿主路径。没有匹配、重复匹配或不一致均失败。

工具只能接插件私有副本，不能把 SDK 输入副本或宿主输出目录交给仍可能存活的子工具。纯核心读取同一个 File 也不等于不可变字节快照：私有输入在归档/解析生命周期内必须保持稳定且不交给写者。输出只声明固定 filename；真实 Artifact 实体由宿主校验后发布，插件不得返回伪造 Artifact ID、哈希或私有 wrapper。

## 七个 operation 与输入 schema

下表是待冻结的完整 schema 组合规则。每项独立 schema 的根为 draft 2020-12、type=object、additionalProperties=false，将表中 properties/required 原样放入根，并将下面公共定义整体放入该根的 `$defs`。引用全部是该份 schema 的本地引用，不指向远端文件；实现可以等价展开，不能依赖宿主领域 DTO 生成它们。

| 旧 operation | 候选插件 operation | properties | required |
| --- | --- | --- | --- |
| android.package.manifest | plugin.android-packages.manifest | `{"artifact_id":{"$ref":"#/$defs/artifact_id"},"module":{"$ref":"#/$defs/module"}}` | `["artifact_id"]` |
| android.package.signature | plugin.android-packages.signature | `{"artifact_id":{"$ref":"#/$defs/artifact_id"}}` | `["artifact_id"]` |
| android.package.extract_apk | plugin.android-packages.extract_apk | `{"artifact_id":{"$ref":"#/$defs/artifact_id"},"entry":{"$ref":"#/$defs/entry"}}` | `["artifact_id","entry"]` |
| android.package.build_apks | plugin.android-packages.build_apks | `{"artifact_id":{"$ref":"#/$defs/artifact_id"},"mode":{"$ref":"#/$defs/mode"}}` | `["artifact_id","mode"]` |
| android.package.decode | plugin.android-packages.decode | `{"artifact_id":{"$ref":"#/$defs/artifact_id"}}` | `["artifact_id"]` |
| android.package.scan_sdks | plugin.android-packages.scan_sdks | `{"artifact_id":{"$ref":"#/$defs/artifact_id"},"rules":{"type":"array","minItems":1,"maxItems":100,"items":{"$ref":"#/$defs/sdk_rule"}}}` | `["artifact_id","rules"]` |
| android.package.extract_splits | plugin.android-packages.extract_splits | `{"artifact_id":{"$ref":"#/$defs/artifact_id"},"device_spec":{"$ref":"#/$defs/device_spec"}}` | `["artifact_id","device_spec"]` |

公共 `$defs` 的候选内容如下：

```json
{
  "artifact_id": {
    "type": "string", "format": "uuid", "minLength": 36, "maxLength": 36,
    "pattern": "^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$"
  },
  "module": {
    "type": "string", "minLength": 1, "maxLength": 80,
    "pattern": "^[A-Za-z][A-Za-z0-9_]{0,79}$"
  },
  "entry": {"type": "string", "minLength": 5, "maxLength": 500},
  "mode": {"type": "string", "enum": ["default", "universal"]},
  "spec_token": {
    "type": "string", "minLength": 1, "maxLength": 80,
    "pattern": "^[A-Za-z0-9_-]+$"
  },
  "device_spec": {
    "type": "object", "additionalProperties": false,
    "properties": {
      "supported_abis": {"type": "array", "minItems": 1, "maxItems": 16, "uniqueItems": true, "items": {"$ref": "#/$defs/spec_token"}},
      "supported_locales": {"type": "array", "minItems": 1, "maxItems": 100, "uniqueItems": true, "items": {"$ref": "#/$defs/spec_token"}},
      "screen_density": {"type": "integer", "minimum": 1, "maximum": 10000},
      "sdk_version": {"type": "integer", "minimum": 1, "maximum": 10000}
    },
    "required": ["supported_abis", "supported_locales", "screen_density", "sdk_version"]
  },
  "sdk_rule": {
    "type": "object", "additionalProperties": false,
    "properties": {
      "name": {"type": "string", "minLength": 1, "maxLength": 100},
      "package_path": {"type": "string", "minLength": 1, "maxLength": 200, "pattern": "^[A-Za-z_$][A-Za-z0-9_$]*([.][A-Za-z_$][A-Za-z0-9_$]*)*$"},
      "class_name": {"type": ["string", "null"], "minLength": 1, "maxLength": 100, "pattern": "^[A-Za-z_$][A-Za-z0-9_$]*$"}
    },
    "required": ["name", "package_path"]
  }
}
```

JSON Schema 的 maxLength 是字符数，不能代替旧 UTF-8 字节限额。插件纯规则在读输入文件/启动工具前补齐字节数与语义预检：entry 最多 500 字节、相对安全成员名、后缀 `.apk` 不区分大小写，拒绝绝对路径、越界/空路径组件、反斜杠及控制符；不对任意 entry 自动选择首项。rules 的 name 非全空白、无控制符、最多 100 字节且唯一，package_path 最多 200 字节，class_name 最多 100 字节；后两者遵守表内 ASCII 标识符规则。class_name 缺省/null 保持 None，不伪造空字符串。

业务格式资格也在插件内校验：manifest 只接 APK/AAB，APK 不接受 module，AAB 省略 module 时取 base；signature/decode 只接 APK；extract_apk/extract_splits 只接 APKS；build_apks 只接 AAB；scan_sdks 只接含有效必要成员的 decoded ZIP。后缀不是内容证明，仍执行相应公共核心验证。设备规格属于离线选择参数，不查设备目录、不拿设备写锁。

## 业务 value、outputs 与旧结果投影

SDK 输出沿协议 4 `CooperativeResponse{response,cleanup}`，response 中 result 是下表业务 value、outputs 是现有 `ArtifactOutput{filename}` 数组；不由插件再添加 result/artifacts 包装。宿主发布后形成严格 `{result,artifacts}`，别名只处理这份宿主包装。

| 后缀 | 插件 result 的候选字段 | outputs 固定文件名 | 旧结果投影 |
| --- | --- | --- | --- |
| manifest | artifact_id、format（apk/aab）、module、package_name、version_code、version_name、min_sdk、target_sdk、application_label、debuggable、permissions、xml | 空列表 | `value(wrapped=true)`，保持 PackageManifest 字段与 null；version_code 等保留原字符串，不转整数。 |
| signature | artifact_id、verified、signers、schemes、report | 空列表 | `value(wrapped=true)`，保持 PackageSignature；signer 为 number/distinguished_name/certificate_sha256，scheme 为 scheme/verified。 |
| extract_apk | entry | extracted.apk | `object(wrapped=true)`：source_artifact_id←input:/artifact_id，entry←value:/entry，artifact←已发布 extracted.apk。 |
| build_apks | mode、apk_count、universal_entry | built.apks | `object(wrapped=true)`：source_artifact_id←input:/artifact_id，mode←value:/mode，artifact←已发布 built.apks，apk_count/universal_entry←同名 value 指针。 |
| decode | files、unpacked_size | decoded.zip | `object(wrapped=true)`：source_artifact_id←input:/artifact_id，artifact←已发布 decoded.zip，files/unpacked_size←同名 value 指针。 |
| scan_sdks | artifact_id、findings | 空列表 | `value(wrapped=true)`；finding 为 rule/package_found/class_found/evidence，class_found 保持可空，evidence 最多 10 项且顺序沿核心。 |
| extract_splits | device_spec、apk_entries | selected-apks.zip | `object(wrapped=true)`：source_artifact_id←input:/artifact_id，device_spec←value:/device_spec，artifact←已发布 selected-apks.zip，apk_entries←value:/apk_entries。 |

manifest 的 module/可空解析字段、signature 的 distinguished_name、build_apks 的 universal_entry、finding 的 class_name/class_found 都显式保留 null。Default 构建的 universal_entry=null，Universal 为 universal.apk 且唯一资格须通过核心检查。输出产物的 source_artifact_id 来自原输入；插件不自行实例化宿主 Artifact。计数是有界非负整数，unpacked_size 不超过既有 64 MiB；返回完整 XML/报告仍受总响应 1 MiB 上限，不截断后伪装正常结果。

旧绑定文件继续由部署者配置 `APK_OPERATION_BINDINGS`，只追加对应七项并保留已有 bindings/format_version；未加载目标时旧入口 not_found，不回退。input 的实际 wire 是字符串 `"identity"`，不是 `{"kind":"identity"}`。普通 target 使用 `{"kind":"operation","plugin_id":"android-packages","operation":"plugin.android-packages.<后缀>"}`；operation.id 是对应旧名称，input_schema 与原旧公开模式相容，预算从目标复制，不在别名声明另一个 execution。

下列 extract_apk 投影是精确 wire 示例，可组合进现有绑定项；其它三项产物投影按表列字段逐一配置，所有字段 optional=false：

```json
{
  "input": "identity",
  "result": {
    "kind": "object", "wrapped": true,
    "fields": [
      {"name": "source_artifact_id", "source": {"kind": "input", "pointer": "/artifact_id"}, "optional": false},
      {"name": "entry", "source": {"kind": "value", "pointer": "/entry"}, "optional": false},
      {"name": "artifact", "source": {"kind": "artifact", "filename": "extracted.apk"}, "optional": false}
    ]
  }
}
```

必填源缺失、严格包装畸形、同名产物零匹配/重复匹配均失败，不取列表首项；显式 null 保留。Protocol 4 的真实宿主发布格式端口必须在注册时匹配这些投影，不能仅凭插件业务对象外形认定来源。直接 plugin operation 返回宿主包装；旧名称返回旧 DTO，二者差异是明确的接口语义，不是一份私有包装猜测。

## 候选总预算、工具短限额与同一个截止点

清单中的 execution 候选为 `{api_version:1,total_timeout_ms:<下表>}`。这些值沿已有预算取证清单供裁定，不是按旧阶段相加证明的等价端到端预算；宿主排队、模式校验、输入副本、握手和最终发布也消耗预算。客户端不覆盖，工具配置中也没有 timeout 字段。

| 后缀 | 候选 total_timeout_ms | 实际工具 | 原旧入口 context=None 的工具短限额 | 协议 4 本草案的工具期限候选 |
| --- | ---: | --- | ---: | --- |
| manifest | 240000 | APK 的 apkanalyzer / AAB 的 bundletool dump | 每笔 120000 ms | 不另建短点，直接使用本地 D_L；一笔工具最多消耗该次任务剩余预算。 |
| signature | 240000 | apksigner verify | 120000 ms | 同 D_L，不按 now+120s 截短显式长预算。 |
| extract_apk | 360000 | 无 | 不适用 | CRC/复制/解析使用同 D_L，没有外部工具限额。 |
| build_apks | 120000 | bundletool build-apks | 120000 ms；原 None 完整 work 也是 120s | 同 D_L；准备、工具、监测、验证及输出移交共同消耗这一次 120s。 |
| decode | 480000 | apktool decode | 120000 ms | 同 D_L；反编译后扫描/打包不新建期限。 |
| scan_sdks | 240000 | 无 | 不适用 | 规则预检、ZIP 资格和扫描使用同 D_L。 |
| extract_splits | 120000 | bundletool extract-apks | 120000 ms；原 None 完整 work 也是 120s | 同 D_L；APKS 校验、规格、工具、监测和打包不逐段再授 120s。 |

这里刻意区分已冻结 Some(D) 语义与旧 None 基线：现有第二批裁定要求传入 Some(D) 时不取 min(D, now+120s)。协议 4 始终有本地 D_L，因而本草案建议不加独立工具短限额；每笔工具仍受原本地截止点和有界输出限制。若主代理选择为新平台插件增加明确的 120s 工具阶段政策，必须单独裁定其数值、`min(D_L, t_tool+短限额)` 和兼容变化，不能借旧 None 常量默默截短长声明。本文件不自行冻结该变更，也不修改旧宿主入口的 None 行为。

宿主固定原 D；运行库握手给出 D_L=C0+R，两者不序列化 Instant、不承诺精确同点。插件只读取 `InvocationContext.deadline()`，不根据清单总预算再次计算 now+total。所有异步工具 `ExecutionOptions::new(tokio::time::Instant::from_std(D_L))`、同步核心 `Control::new(Some(D_L), &取消状态回调)`、输入复制、监测、文件输出和响应资格沿用 D_L；取得 permit、首次 poll 及下一笔 I/O 前重查上下文。回调只读令牌，不 I/O、不刷新期限。

到期与取消同时发生由 InvocationContext.check 报 Timeout。宿主最终发布/成功资格仍检查原 D；已清理失败的风险不得被 Timeout/Cancelled 覆盖。单次成功输出不表示部分发布具有事务回滚；本插件每项至多声明一个产物，但宿主既有部分发布政策不因此扩大。

各工具固定 argv 候选沿旧行为：apkanalyzer `manifest print <私有输入>`；bundletool `dump manifest --bundle=... --module=...`、`build-apks --bundle=... --output=... --mode=... --max-threads=2` 或 `extract-apks --apks=... --output-dir=... --device-spec=...`；apksigner `verify --verbose --print-certs <私有输入>`；apktool `decode <私有输入> --output <decoded> --frame-path <framework>`。java_jar 只在这些 argv 前加固定 `-jar <部署 jar>`；私有规范路径由插件生成，不能接 input.path、input.executable 或自由追加参数。

工具使用受限环境、独立 argv 和每路默认 1 MiB stdout/stderr；显式文件标准输出按调用方固定 file_limit，不把文本限额放宽为包文件限额。非零退出始终失败，零退出失败诊断仍按旧语义拒绝；build 签名 stderr 使用固定脱敏错误，signature 的 report/xml 作为业务结果前也必须去除任务路径。业务 D 不包含重新授予的清理预算：公共工具库最多 2s、宿主合作 1250ms/直接终止等待 500ms 等既有边界不扩大。

## 目录、工具租约与跨进程容量归属

| 资源 | 实际所有者及释放资格 | 不具有的保证 |
| --- | --- | --- |
| SDK 输入/输出目录 | 宿主 InvocationFiles；宿主负责授权副本和发布。插件只读输入，最终合格文件复制进输出目录后才声明固定 filename。 | 插件的 Arc 不能延长宿主目录 owner 的生命周期；不能把子工具留在宿主目录内再称租约安全。 |
| 插件 scratch | 插件在 scratch_root 创建本次随机独占目录，含自己的输入副本、spec、decoded/framework 与工具输出；所有使用者持 Arc 目录 lease。 | 工具不会修改部署签名文件或 SDK 输入；不清扫历史/其它任务目录。进程被强制终止后可能留下私有目录，不自动证明已经删除。 |
| 直接子工具及管道 | 公开 capture_with_lease/capture_to_file_with_lease 持 Child+Arc 到真实 wait 成功；未确认转后台所有者，插件保留失败诊断。 | kill_on_drop、取消令牌或 PID 标记不等于真实退出。Arc 与后台 waiter 只在插件进程内有效，不能越过插件被杀或运行时结束。 |
| 同步核心 worker | 插件私有有界许可和目录 lease 移入实际 spawn_blocking 闭包，检查同 D_L/取消，真正结束后才释放。 | 不复用/复制宿主 private Pool，不因外层 Future 丢弃就释放槽位，不把 abort 当线程已停止。 |
| 输出监测 | 受追踪的 async 任务，必要扫描复用同一 worker；只允许一份在飞扫描，不堆积周期任务。 | 工具结束不代表监测已经结束；最终树扫描必须等工具/监测停止写入后进行。 |
| 发布产物和旧 Job | 宿主按原 D、owner/generation 和终态资格发布；插件不访问 ArtifactStore/JobStore。 | 不伪造宿主 Artifact、不从另一任务借产物证明本次输出，也不把自己的 cleanup 标记当平台资源证明。 |

私有 scratch 必须独立于 SDK 目录。需要外部工具的操作先有界复制到自己的输入文件，再把这个私有路径交给工具；这样强制终止插件后，宿主回收 SDK 副本不会直接删除仍被子工具使用的文件。正常路径仅在全部工具、worker、监测确认结束后释放 scratch。异常强制终止可能遗留私有 scratch；首批禁止启动时自动递归清扫，由后续保留/回收裁定处理，报告不能宣称目录全部排空或派生树已退出。

输出建议先在私有 scratch 校验完成，再以 create_new、受限复制和同 D_L 写入 SDK output_directory 中的固定文件名。scratch 与宿主目录可能不同卷，不能宣称 rename 原子；未完成复制不声明 outputs。PureCore 的 TreeSnapshot/Directory 不是不可变内容快照，最终复制前后按既有长度/变更资格检查；core 与 tool-process 都不负责宿主发布。

首批容量候选：每次请求只有一个插件进程、一槽同步 worker、至多一个在飞子工具，监测复用该槽。宿主使用现有共享 Job 执行槽限制同时活跃 handler，不另给每个 operation 分四槽；例如宿主配置四执行槽时，活跃请求的同步闭包最多四份，但这不是跨进程公共 semaphore，也不是宿主包 Pool 的直接复用。取消后存活子工具、其它插件/服务实例和外部 Java 内部线程不被这个算术约束覆盖。

因此“全系统真实阻塞工作共享四槽且孤儿也持槽到退出”尚无公开跨进程许可协议，不能计为已完成。如果必须把宿主现有四槽包 Pool 的精确跨进程语义一并保留，需主代理另裁定通用 reservation/lease 接缝或公开公共库；本插件不能读取私有 Pool、自增宿主平台分支或伪造已确认。首批建议明确保证上述单任务局部边界，另以 owner cleanup_failed 阻止同 ID 新/排队工作，而不宣称系统全局孤儿总量上界。

监测失败、取消和到期先停止新业务工作，取消工具与 worker，使用一次不刷新的有界清理点并发等待。真实确认全部结束时才 `Execution::complete`；任何工具 CleanupFailed、worker/监测未结束、资源 lease 不明都返回 `CleanupOutcome::Failed`、无业务成功和 outputs。失败不能被后续成功清零。运行库会等待 handler 返回，不替插件判断哪些资源已排空；宿主的匹配响应、零退出、cleanup=complete 三条件仍独立成立才确认。

## 限额、坏包和错误兼容边界

公共核心原 profile 不改：Reverse 含目录最多 10000 项，Splits 含目录最多 1000 项，树深度 128，工作普通文件累计与完成 ZIP 分别受 64 MiB 限额；APKS 压缩输入 64 MiB、展开总量 256 MiB；通用 Structure 的声明展开 2 GiB 不代替工作限额。精确成员复制必须读至结束并验证长度/CRC；全目录重复成员仍拒绝，不能只检测所选 entry 的重复。

APK/APKS/tree/XML 校验直接使用公开核心：Archive::open/select_exact/copy_to，parse_manifest/parse_signature，validate_apks，tree::scan/pack，validate_decoded/scan_sdks。Structure 成功不证明每个成员 CRC、签名或可安装。工具最终 Reverse 缺/空必要文件、Splits 无 APK/非 APK/坏 APK、Universal 不唯一等按已有场景拒绝；监测期缺尚未写完的必要文件不提前当完成坏包，监测期越界/链接/规模仍应早拒。XML 命名空间实体、等价 URI 与 expanded 属性判重沿当前核心，不能复制旧缺陷解析器。

当前公开 Response.error 只有字符串，不承载宿主 Error 的 Invalid/Storage/TooLarge 等类别。故旧成功 DTO 可以用上面的纯投影兼容；旧运行时坏包的精确 HTTP 错误码不能靠错误文案推断或宿主新增安卓分支来保持。宿主 schema 阶段发现语法/缺字段/额外字段等仍是 invalid_input；插件内部坏包、缺工具、配置错误或工具失败沿通用插件错误返回 dependency_failed，超时/取消/cleanup_failed 由既有总期限及资源通道识别。

这是一项必须裁定的错误兼容变化，未获裁定不得宣称旧错误分类完全等价。如果要求运行时坏包仍精准保留原 invalid_input/too_large/storage 分类，需先冻结公开版本化错误 DTO 与宿主通用映射再实现，不在本插件或旧别名中猜字符串。首批建议采用当前公开错误形状，固定有界中文诊断且不泄漏工具路径/签名材料，在精确回归中单列变化。不能让测试接受任意 4xx/5xx，也不能造伪 CleanupFailed 覆盖无法真实触发的分支。

集成所有权另列：主代理负责 workspace Cargo/lock、架构依赖白名单、构建/打包、部署绑定及 server/main 原装配撤除；插件实现角色仅新目录。七项模块可按“三项→四项”分段冻结，但只有全部操作及对应输入输出真实验收后才关闭七项迁出。公共库有实际缺口时先回流最小公开接口裁定，不能用复制宿主算法填补。

切换顺序建议：

1. 先冻结配置、元数据/预算及资源/错误选择；实现可启动的协议 4 插件，未配置工具仍可完成握手并对实际依赖项确定失败。manifest/signature/extract_apk 三项冻结即供独立测试，不等另外四项文档。
2. 完成 build_apks/decode/scan_sdks/extract_splits，并验证四固定输出的实际文件。旧名称先用显式通用绑定接入，同一个注册修订原子发布，目标缺失则旧入口不可用。
3. 通过新插件任务/旧别名的 HTTP/MCP、日志、取消、卸载、真实工具模拟及真实包验收后，由主代理撤除 main.rs 的 AndroidPackageTools、AndroidBundles、AndroidReverse 和离线 Split 提取装配。不能删除 AndroidSplits.install 仍依赖的设备安装路径或声称 Android/Harmony 全迁出。
4. 精确删除已无消费者的宿主重复包编排及其平台工具配置读取，按通用 host 源码/架构检查确认没有新增安卓包分支。旧库或 core 单独通过、当前六门禁通过都不代替新插件发布验收。

## 主代理需立即裁定的三组选择

1. **部署配置**：是否采用旁置缺省文件 + 清单唯一 `--config` 绝对路径；冻结本文字段、限制、无配置策略和首批 native 目标。不采用未继承的自定义环境变量或新的 main 平台分支。
2. **七项元数据**：冻结候选 ID、全部输入/schema/value/固定输出、七预算、旧绑定；确认 Some(D_L) 工具直接用同点，或显式裁定新的阶段短限额及兼容变化。段上限算术不能证明等价。
3. **资源与错误**：接受单请求一槽 worker/一工具、host Job 容量与跨进程全局许可的区别；冻结 handler 清理收口、私有 scratch 异常保留，以及当前 Response.error 导致的运行时错误类别变化。若要求全局孤儿持槽或旧类型错误完整兼容，先补公开通用契约，不让插件自行实现宿主私有机制。

这些是供主代理直接裁定的具体候选，不是再次请求用户批准，也不是实现角色自行冻结公共 SDK。裁定后可立即开放上表插件生产写集与独立测试写集。
