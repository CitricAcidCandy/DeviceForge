# 性能采样插件协议

## 能力与部署

任何语言插件可以实现公开性能声明。API 1 兼容协议 2 的独立采样请求 / 响应，并在部署清单中声明：

```json
"performance": { "sample_operation": "sample", "fps": true }
```

sample_operation 必须存在于 operations。操作输入模式须接受 device_id / package 对象，宿主按该模式验证目标；模式仅允许文档内引用，不允许 $id 或外部资源。采样插件不能同时声明产物输入 / 输出能力，采样响应 outputs 为空。

API 2 使用协议 4 和设备 API 3，绑定同插件的精确设备能力，例如：

```json
"performance": {
  "api_version": 2,
  "sample_operation": "performance.sample",
  "fps": false,
  "device_capability": { "id": "performance.sample", "version": 1 }
}
```

对应能力必须指向同采样贡献，范围为 device、访问为 read、预算为 10000ms。输入采用 `{device_id,input:{package}}` 封套；宿主验证当前设备、来源代际和精确可用能力。API 2 允许同插件其它贡献拥有产物权限，但采样有效授权必须为空，不能由整个清单的授权放行采样输入或输出产物。Android 插件没有 `android.performance.sample` 旧别名。

通过 APK_PLUGIN_DIR 部署插件，APK_PERFORMANCE_PLUGIN 填写清单 id 显式选择默认采样源，每次实时调用查询当前注册。未配置或指定来源尚未加载时允许服务启动，start/capabilities 返回 not_found，不回退 ADB；加载后新调用可用。排空返回 conflict，已知清理风险返回 cleanup_failed。非法声明、模式或重复 ID 在插件加载时拒绝；请求不能选择可执行程序或插件路径。

默认来源 ID 在服务启动时固定，同 ID 插件可在线卸载和重载；卸载使其 Running、Paused 及启动中会话收口 interrupted，新代只用于新会话。普通贡献 plugin.<id>.<operation> 仍公开，直接调用得到 result / artifacts 包装，且不建立性能历史；通过 android.performance.* 会话调用时，宿主解包、验证并持久化样本，不创建嵌套 Job。

## 请求与样本

API 1 的 Request.input 为公开 SDK 的 PerformanceTarget；API 2 的同一目标放入前述设备封套：

```json
{ "device_id": "emulator-5554", "package": "com.example.app" }
```

Response.result 为 PerformanceSample，例如：

```json
{
  "captured_at": 1791468000000,
  "pid": 123,
  "process_start_ticks": 900,
  "process_ticks": 100,
  "system_ticks": 1000,
  "logical_cpus": 2,
  "pss_kib": 2048,
  "rss_kib": 4096,
  "frame_window": { "frames": 60, "duration_ms": 1000, "source": "synthetic_demo" }
}
```

此 JSON 数值仅是结构示例，不能直接发送：captured_at 必须为当前观测完成时间（Unix 毫秒），范围为宿主当前时间前 60 秒到后 5 秒。CPU 计数必须采用统一单位，system_ticks 是全机累计计数，process_ticks 是目标主进程累计计数；process_start_ticks 用来识别进程重启，logical_cpus 是采样时核数。PSS / RSS 为 KiB，RSS 可空。未知样本字段拒绝，PID、核数及系统总计数必须有效。

FrameWindow 可省略，表示本次未得到 FPS 观测；fps=true 表示支持该能力，不保证每次返回数据。未声明 FPS 却返回窗口会失败。duration_ms 为 1–60000 毫秒，frames 为实际观测帧数，source 为 1–80 字节 ASCII 字母 / 数字 / 点 / 下划线 / 连字符。frames 不超过 duration_ms，等价于最高 1000 FPS 的接口边界。零帧表示窗口内实际观测到零帧，缺少观测不能填零。

窗口结束时间采用 captured_at。宿主计算 fps = frames × 1000 / duration_ms，并同时保存原始 frame_window，让调用方理解口径和来源。不同窗口可能重叠，FPS 是各窗口速率，不能把帧数直接累加。插件需明确统计渲染、提交或展示帧，不混用不同来源；宿主不验证设备测量真实性。

## 生命周期与边界

每次采样创建独立插件进程，无宿主常驻插件状态。采用现有请求关联、环境去令牌、独占临时目录与 stdout / stderr 上限。单样本期限取准入加 10 秒、会话期限与能力预算的最早值，贯穿等待、工具、解码与提交，不在插件启动或恢复时续期。后台性能会话由 application 管理；取消使用唯一 2 秒清理窗口，来源卸载使用既有 10 秒排空规则。

插件支持的 FPS 值及帧窗口作为可选字段加入 PerformanceReading；旧会话 JSON 缺少这些字段仍可读取；Android 实采的展示帧来源和真机资格见 Android游戏FPS采集实施.md，支持能力不保证每样均有窗口。会话 source 可选且不可变，固定记录来源插件与代际；旧记录不反填，历史读不依赖插件在线。capabilities 动态返回当前 source、fps 和指标列表。

插件按可信代码运行，没有操作系统沙箱；直接进程取消有约束，完整派生进程树回收尚未实现。需要派生设备工具的插件必须负责取消与清理，不能创建后台常驻进程。设备型采样持 provider 读屏障，允许与同设备 write 并行，阻止 provider/write；屏障在真实清理确认或风险登记后释放。启动、worker、控制和真实数据库闭包均归来源排空；慢存储或已丢弃 await 不表示工作已经结束。本接口仍不提供常驻插件会话、每会话自选来源或跨插件调用。

## 示例与验证

plugins/performance-demo 只依赖公开 SDK，输出 synthetic_demo 合成数据，用于展示跨进程契约；没有真实 Android FPS 实现。Android独立插件已实现展示帧采集，具体版本的工具和真机证据见Android游戏FPS采集实施.md及根交接文档，不能借合成示例成绩。

cargo test -p deviceforge-performance-demo-plugin 覆盖清单、模式、真实进程样本、FPS 持久化、时间 / 窗口 / 类型错误、未声明能力、取消和 10 秒超时。

cargo build --workspace 后运行 node scripts/runtime-smoke.mjs 与 node scripts/runtime-smoke.mjs --performance-plugin，分别验证无默认来源时的精确失败和 API 1 插件会话、卸载与换代历史；两种模式复用 HTTP / MCP 会话操作。API 2 Android 实采由根 `scripts/android-device-smoke.mjs --performance` 独立验证。源码/单元、模拟工具服务、当前分发和真机结果分别记录，以根交接文档及 artifacts 报告为准。

## API2可选部分缺测

设备型来源在performance声明partial_metrics:true后，才可发送metric_missing。旧声明缺省false，API1拒绝此能力；宿主按当前代次复核。缺测对象api_version固定1，cpu和memory可省略/null，但至少一项真实诊断；条目为source、access和reason，access为adb_shell/root_shell，reason为permission_denied/unsupported，source为1–80字节稳定ASCII标识。

CPU缺测时system_ticks与logical_cpus同时null；内存缺测时pss_kib与rss_kib同时null。值与诊断必须精确对应，旧完整数字样本仍可读；PID、进程启动时间和首末进程计数仍必须确认。缺测样本保留同次FPS、环境及画面，不填零、不复用旧指标。CPU恢复首样只建立新基线，下一有效样本恢复差分；SQLite继续存JSON，无列迁移。

Android仅对固定只读命令完整的已确认权限/不支持诊断降级。非零仅code1且完整stderr匹配；有效正文混诊断、未知错误、结构/数值/身份异常、离线、取消、EOF、到期、限额和未确认清理仍硬失败。具体职责、回归和证据见Android指标部分缺测实施.md。
