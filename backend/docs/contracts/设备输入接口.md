# Android 设备输入接口

## 操作与端口

公开任务操作 android.input 通过 DeviceInput 领域端口执行。服务启动时装配 AndroidInput，ADB 入口仍由管理员配置 APK_ADB；请求不接受服务器路径、程序或任意命令。

HTTP 使用 POST /api/v1/jobs：

```json
{
  "operation": "android.input",
  "input": {
    "device_id": "emulator-5554",
    "action": { "kind": "tap", "x": 120, "y": 300 }
  }
}
```

MCP tools/call 使用同名工具 android.input，arguments 直接传 input 对象。任务状态、查询、事件和取消沿用共享任务接口。

## 动作与范围

| kind | 参数 | 范围 |
| --- | --- | --- |
| tap | x、y | 0–32767，整数 |
| swipe | x1、y1、x2、y2、duration_ms | 坐标同上；时长 1–10000 毫秒 |
| keyevent | key_code、long_press | 按键码 1–65535；long_press 默认 false |
| text | text、enter | 1–1024 个可打印 ASCII 字符；enter 默认 false |

未知参数拒绝。输入模式直接从 Rust 类型生成，适配器再次验证，直接调用领域端口也不能跳过约束。坐标按当前屏幕方向填写，不做屏幕尺寸推断或缩放；按键码数值有效不代表具体设备支持。

文本包含空格、引号、反斜线、反引号、美元符号或 shell 运算符时按字面量传递。空格使用 AOSP input text 的 %s 约定；字面量 %s 在相邻调用间拆开，避免变为空格。Unicode、换行、控制字符需独立设备端输入法适配，当前会拒绝。

## 结果、并发和失败

成功结果：

```json
{ "device_id": "emulator-5554", "action": "tap", "dispatched": true }
```

dispatched 表示所有命令以成功退出且未出现诊断信息，不证明焦点、应用接收输入或界面变化。不同设备并行，同一适配器对同一设备的整个输入动作串行，包括所有文本分片和回车。等待设备锁与执行共用 30 秒期限，取消不会继续发送回车。锁表只保留活跃调用，不持续积累设备编号。

输入不是事务，也不具备幂等性。失败 / 取消可能已有部分事件发送，宿主不自动重试；其他设备工具或外部操作不受该输入锁协调。文本上限使分片数量有界，最坏的重复 %s 可产生 513 个文本命令，仍受总期限约束。

使用 ADB 非交互 shell -T，需要设备支持相应 shell 协议。标准输出 / 错误中的非空诊断、非零退出、超时或取消均失败。适配器用通用失败消息避免设备诊断回显文本；任务系统仍按现有约定持久化原始请求，文本会存入任务数据库，不是秘密输入通道。

## 验证与剩余验收

- cargo test -p apk-application --test device_input：生成模式、类型边界、未知字段、取消与端口调用。
- cargo test -p apk-infrastructure device_input：真实模拟进程参数、特殊字符、空格 / 字面量 %s、回车顺序、诊断、非零退出、超时、运行中取消及设备锁边界。
- node scripts/runtime-smoke.mjs：真实 HTTP 服务三种数值输入、MCP 文本输入、设备端参数解析后的观测记录、诊断失败与非法输入拒绝。

模拟 shell 解析只验证宿主产生的引用形式。仍需真实 Android 验收：不同版本 / 键盘布局、非 ASCII 输入法扩展、焦点 / 旋转、断线、权限失败、外部操作和取消后的部分效果。Harmony 输入、自动化录制 / 回放仍待迁移。
