# 合作取消插件协议与 Frida 迁移前置条件

## 2026-10-23 当前准入策略

历史清理告警不再永久拒绝整个插件的新任务，也不覆盖另一笔成功。合作取消、每次真实清理结果与有界回收继续保留；新独立调用按真实活动资源和当前代际准入。2026-10-26 已同步下文现行契约，长期硬约束与回归见[资源故障隔离与后台回收裁定](../implementation/资源故障隔离与后台回收裁定.md)，实施导航见[历史清理告警与新任务解耦](../implementation/历史清理告警与新任务解耦.md)。投屏内部由用户指定的其他代理处理。

## 架构门禁

模式 architecture-first，采用契约先行与行为回归结合。目标是让独立进程插件在任务取消、超时、卸载或宿主连接关闭时收到清理信号，并让宿主区分已确认清理和仍有不确定资源。旧 Frida 包含部署、注入、权限 hook 与日志，不把增加一个命令入口算成完整迁移；具体设备提供者 API 仍是候选设计。

比较两条路径：继续只杀插件进程无法执行 script.unload/session.detach 或关闭自有连接；使用版本 3 的开放输入流与合作取消可以给插件有限清理窗口。选择后者，协议 1/2 的一次请求和输入 EOF 行为不变。版本 3 仍是每任务一个进程，不冒充常驻、多会话或设备提供者协议。

| 单元 | 输入/输出与职责 | 不负责 | 副作用 |
| --- | --- | --- | --- |
| plugin-sdk/cooperative.rs | 版本 3 控制帧、响应与清理结果 | 宿主内部类型、进程或运行时 | 无 |
| plugin-runtime | 公开异步一次任务运行库，读取有界请求/控制，传取消令牌，输出确认 | 设备工具、宿主存储、业务规则 | 标准输入输出 |

| infrastructure/plugins.rs | 协议选择、产物包装、不可确定资源标记 | 设备服务管理 | 调用进程与产物端口 |

先拆独立传输和公开运行库，通用 HTTP/MCP 不增加平台分支。Frida 下一步直接依赖公开运行库，部署和设备资源清理由该业务插件拥有，不引用宿主模块。

## 协议与资源边界

协议 3 第一行沿用 Request，stdin 保持打开。取消帧含 protocol_version=3、request_id、command=cancel、reason（cancelled/timeout/transport_failure）。响应为 `{response: Response, cleanup: complete|failed}`；只有匹配的响应、零退出和 complete 才确认插件已执行清理。它是可信插件声明，不证明真实设备已恢复或操作已回滚。

请求最多 512 KiB，控制帧最多 4 KiB，标准输出/错误各最多 1 MiB。版本 3 执行总期限为 1 小时，仍受任务队列/并发限制；协议 1/2 保持 60 秒。取消后最多 1250 ms 合作窗口，留出宿主现有 2 秒执行器清理预算。失败、无确认或 Future 丢弃标记 unresolved；直接进程强制退出不能代替外部资源确认。

运行库在正确取消、stdin EOF、损坏或不匹配控制帧时通知处理器清理；无效控制不能成为成功结果。处理器须在返回前卸载脚本、分离会话、停止自有进程或关闭连接，再显式声明 complete。取消后不接受产物发布或晚到成功。

PluginInfo 的 cleanup_failed 保留诊断，管理成功包装不变。本次清理未确认如实记录失败；卸载撤销操作并有界等待真实在途工作，draining 不作为历史债务的永久容器，排空后可以同 ID 重载。独立新调用不等待后台恢复成功；未声明恢复能力的旧插件也不得仅因历史告警被全局冻结。不猜测性自动重放、不隐藏本次失败，真实独占冲突只约束对应资源。2026-10-23新增的显式协议4资源恢复遵守[插件资源恢复第一版](插件资源恢复v1.md)，确认仅覆盖固定旧代债务快照，不清除新风险、改写旧任务或以重启代替外部资源确认。Frida持久资源台账仍需独立实现。

协议 3 可使用协议 2 的产物能力与结果包装。性能来源 API 1 使用协议 2，设备型 API 2 使用协议 4；其预算与合作监督按[性能采样插件协议](性能采样插件协议.md)执行，不能沿用早期“只允许协议 2”的限制。

## 最低验收与剩余工作

先证明输入/控制/输出上限及版本兼容，再验证真实独立进程收到取消后完成资源标记；无响应、清理失败和 Future 丢弃保留 unresolved。真实在途未退出时不得丢弃 owner；历史债务则独立保留，不阻止排空后的重载。必须证明 A 清理失败后 B 独立调用真实执行且成功，A 的诊断仍可查，HTTP/MCP 对真实排空与历史告警口径一致。再执行两端门禁、真实服务、release 和 npx。

本阶段完成后，Frida 的服务部署/进程所有权、会话注入、权限脚本、自定义 hook、实时日志和真机验收仍须逐项实施。公开运行库不代表 Frida 或常驻设备层已迁移完成。
