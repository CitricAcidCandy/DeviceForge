# 浏览器插件用户配置契约

用户配置根由启动装配统一解析：默认 `<home>/.deviceforge`，显式隔离使用 `DEVICEFORGE_USER_DIR`。浏览器插件保存在其下 `plugin-configurations/browser/<id>/state.json`，服务器插件使用相邻 `server` 目录。配置文件不随初始插件包或在线部署目录保存，也不跟随 `APK_DATA_DIR` 切换。存储模块只接收已解析路径，不自行读取环境变量。

## HTTP 接口

- `GET /api/v2/browser-plugin-configurations/{id}` 返回 `{log_id,data:{record:null|BrowserConfigurationRecord}}`。合法 ID 即可访问；无需已在线安装插件，因此初始随包浏览器插件也能持久化配置。未保存时返回 `null`，读取不产生插件子目录。
- `PATCH` 同一路径，必须显式提交 `{expected_revision:null|string,record:BrowserConfigurationRecord}`。返回同样的视图。`null` 仅匹配不存在的记录，字符串必须与当前 `record.revision` 完全一致；冲突返回 409。省略 CAS 字段、非法记录或插件 ID 返回 400；超限返回 413；未装配服务返回 503。
- 成功及失败均沿既有 API v2 响应与日志 ID 规则包装，不将本地路径、原始配置或解析载荷写入日志或错误。

记录字段沿用浏览器结构：`{version:u32,values:JSON对象,revision:string,applied:string,sensitivePaths:string[]}`。`revision`、`applied` 接受历史 `defaults` 或 UUID；`sensitivePaths` 接受空字符串或以 `/` 开头的路径。完整记录及历史敏感路径原样保留，不由宿主生成新修订或推断已应用状态，允许在同一修订上更新 `applied`。`values` 是供可信浏览器插件 SDK 运行的原值；用户界面继续按配置声明和历史敏感路径遮蔽。此接口不提供浏览器配置模式校验或插件生命周期管理。

## 资源与存储边界

完整记录单文件上限 256 KiB，HTTP 请求仍受既有 256 KiB 整体上限约束。文件副作用放入最多两个工作的阻塞工作池，接纳满时返回冲突，已接纳工作在进程内互斥。阻塞工作持有许可直到完成，即使调用方取消也不提前释放名额。

每个存储根持有 OS 独占文件锁，第二个宿主不能同时打开同一根目录。目录和状态、锁文件拒绝符号链接、Windows 重解析点及非普通文件；插件子目录限定在规范化根的直接子级。写入使用同目录临时文件、刷新、原子替换，读取拒绝损坏或超限文件，不以默认值覆盖损坏记录。

本模块不执行旧 LocalStorage 或服务器旧配置迁移。迁移发起方通过同一 CAS 接口首次导入；若服务端已有记录，必须先读取并遵守当前修订，不能盲目覆盖。

## 装配与验证

`BrowserConfigurationService::new(store)` 接收领域存储端口；`FileBrowserConfigurations::open(root)` 接收 browser 子目录。旧 `router_with_configurations` 保持签名，新增 `router_with_browser_configurations` 在其参数末尾追加浏览器配置服务。OpenAPI 由领域类型与独立路由贡献生成，客户端由主代理统一生成。

定点命令：

```text
cargo test -p apk-infrastructure --lib browser_configurations -j 1
cargo test -p apk-server --lib browser_configuration -j 1
```

本轮实现代理未启动共享 Cargo、宿主服务或设备；以上测试待主代理统一执行。跨进程锁探针只由对应父测试启动，常规测试列表中标为忽略，以避免无测试根目录时被单独调用。源码和静态检查不能替代真实用户目录迁移、浏览器 SDK 或分发运行验收。
