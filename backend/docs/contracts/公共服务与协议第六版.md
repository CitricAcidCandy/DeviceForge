# 公共服务与协议第六版

日期：2026-10-27。模式：architecture-first，按已批准公共服务目录、调用与协议 6 范围实施。本文冻结公开线格式，不把源码或内存管道测试列为真实服务验收。生成接口、Cargo 与服务门禁由主代理统一安排。

## 职责与兼容

| 单元 | 负责 | 不负责 |
| --- | --- | --- |
| plugin-sdk/services | 精确服务引用、契约、入口级依赖、协议 6 纯帧 | 时钟、进程或宿主依赖 |
| domain/services | 服务目录、调用参数及 ServiceCaller 端口 | HTTP、宿主实现或 SDK 依赖 |
| application/services | 目录与注册原子性、入口依赖、嵌套取消/期限/代际/容量 | 插件进程或网络旁路 |
| infrastructure/plugins/services | 清单短名到公开操作/会话 ID 的映射与模式校验 | 创建额外业务队列 |
| infrastructure/process/cooperative/services | 双向帧、有界输入、直接进程与工具租约清理确认 | 平台命令或业务判断 |
| plugin-runtime/services | 类型化句柄、固定 C0、合作取消与清理终态 | 宿主内部模块或 HTTP 客户端 |
| server/services | HTTP/MCP 薄边界、OpenAPI 节点 | 重复业务实现 |

旧任务、产物、交互会话和协议 1–5 保留。普通任务顶层可显式选择 6；独立会话仍声明 5，不把会话帧混入任务流，也不新增常驻服务进程。选择“映射已有 operation”而非另建常驻 RPC；不允许插件通过 HTTP 偷绕宿主调度。

## 冻结的线格式

字段为 snake_case，浏览器 SDK 的 camelCase 映射由前端适配器完成。以下名称已注册到 OpenAPI components，可由主代理生成客户端，不手改 generated。

```typescript
type ServiceRef = { id: string; version: string };
type ServiceContract = { input_schema: unknown; output_schema: unknown };
type ServiceProvider = { id: string; version: string; generation: string };
type ServiceInfo = {
  service: ServiceRef;
  contract: ServiceContract;
  operation: string;
  provider: ServiceProvider;
  available: boolean;
  unavailable_reason: string | null;
};
type ServiceCallRequest = {
  version: string;
  input: unknown;
  generation?: string | null;
};
```

服务版本为非空字符串，最多 128 字节，纯空白也拒绝；不做 trim 后匹配、数字转换或 SemVer 范围解析。`"1"`、`"1.0"`、`"1.0.0"` 是三个不同的精确值。协议版本仍为整数 `protocol_version=6`，与服务契约版本完全独立。服务 ID 为不超过 128 字节的小写字母、数字及 `._-`。

- `GET /api/v2/services` 返回 `200 {log_id,data:ServiceInfo[]}`。
- `POST /api/v2/services/{id}/calls` 接收 ServiceCallRequest，返回原有 `202 {log_id,data:Job}`，不是同步结果或第二种任务模型。
- Job 查询、事件、取消、终态不可覆盖、产物封套均沿用原接口。版本不存在为 not_found，旧代际或入口依赖不满足为 conflict，输入结构/模式错误为 invalid_input。
- `generation` 可选；指定时必须与当前提供者代际一致，省略时绑定提交当时的 Registered 对象。排队后撤销及晚到结果仍由当前代际门禁拒绝。
- `deviceforge.list_services` 参数 `{}`；`deviceforge.call_service` 参数为 `{id,...ServiceCallRequest}`。MCP 与 HTTP 调同一个应用用例、返回同一个 Job，不直接等待业务完成。
- `available` 只表示服务及其映射入口必需依赖链当前可用，不承诺工具、设备或本次运行一定成功。历史 cleanup_failed 不使目录全插件不可用。

## 清单声明

部署 Manifest 与 PortableServerManifest 均接受可选 services；省略时序列化省略，旧清单不新增必填项。

```json
{
  "services": {
    "provided": [{
      "service": {"id":"example.text.normalize","version":"1.0"},
      "operation": "normalize",
      "contract": {"input_schema":{"type":"object"},"output_schema":{"type":"object"}}
    }],
    "required": [{
      "service": {"id":"example.text.normalize","version":"1.0"},
      "operations": ["compose"],
      "sessions": []
    }]
  }
}
```

operation、operations、sessions 在插件清单中使用本插件短名，适配器补 `plugin.<插件ID>.`。provided 只能映射已存在普通 operation；输入 schema 与操作输入模式必须一致，输出 schema 在注册阶段编译，并在结果接受前验证业务结果。一个服务精确版本只允许一个提供者，热装卸与操作贡献原子发布/撤销。

required 必须至少指定一个已存在的 operations 或 sessions，不能用全插件开关。依赖不存在不会拒绝插件加载；仅相关入口在准入时失败。无关入口照常可用，依赖恢复后重新准入。目录派生当前注册快照，检测依赖循环与深度，绝不按加载顺序静默覆盖提供者。

## 协议 6 帧与状态

每帧为换行结束的 UTF-8 JSON，标准输出仅用于协议。首帧沿用 Request 字段并设置 protocol_version=6，其余帧使用独立 ServiceFrame，不使用协议 4 的严格版本解析器。

```json
{"protocol_version":6,"request_id":"root","operation":"compose","input":{"text":"FORGE"}}
{"command":"ready","protocol_version":6,"request_id":"root"}
{"command":"start","protocol_version":6,"request_id":"root","remaining_timeout_ns":1000000000}
{"command":"service_call","protocol_version":6,"request_id":"root","call_id":"1","service":{"id":"example.text.normalize","version":"1.0"},"input":{"text":"FORGE"}}
{"command":"service_result","protocol_version":6,"request_id":"root","call_id":"1","outcome":{"status":"succeeded","result":{"text":"forge"}}}
{"command":"finished","protocol_version":6,"request_id":"root","execution":{"response":{"protocol_version":6,"request_id":"root","result":{"text":"FORGE: forge"}},"cleanup":"complete"}}
```

替代结果为 `outcome={status:"failed",error:{code,message}}`；显式 JSON null 是合法成功结果。局部撤销使用 `command=service_cancel` 加原 call_id；根撤销使用 `command=cancel`。finished 内沿用 CooperativeResponse 的结果/非空错误互斥、outputs 和 cleanup=complete/failed，不把独立子调用的业务失败伪装成清理失败。

- 插件在写 Ready 前固定 C0，Start 截止点为 C0 加原剩余纳秒预算；等待 Start 消耗预算，不重启时钟。预算最多一小时，握手固定五秒，旧上下文入口不变。
- 首帧最多 512 KiB，握手帧最多 4 KiB，运行帧最多 1 MiB；单进程最多 1024 个子调用 ID、累计收到最多 16 MiB，通道容量 8、最多 4 个未结束子调用。重复或未知结果 ID、坏版本、坏关联及未知帧严格失败。
- 行读取保留跨 select 的半帧缓冲。写入超时或部分写入失败后不向半帧拼接 finished，保持清理未确认。
- 根取消、到期或输入失效后撤销新调用，合作清理使用首次固定的 1250 毫秒窗口；直接进程强制结束与等待另受 500 毫秒上限约束。处理器未确认清理必须输出 failed 或使传输失败，不把丢弃 Future 当成功。
- 宿主必须同时取得身份/载荷有效的 complete 终态、无多余输出和直接进程零退出，才确认当前资源释放；取消后业务结果不能改成成功。未确认保留本次风险，不能封锁同插件的独立后续调用。

## 嵌套调度与公开运行库

`serve_once_with_services(handler)` 与 `serve_io_with_services(reader,writer,handler)` 的处理器参数为 `(Request, InvocationContext, ServiceClient)`，返回原有 Execution。`services.service::<Input,Output>(ServiceRef)` 创建 `ServiceHandle<Input,Output>`，`handle.call(&input).await` 进行类型化序列化和结果解码。调用 Future 被丢弃时尝试发送 service_cancel；撤销队列不可用则取消本调用，不产生无管理的网络请求。

子调用在父任务调度槽内执行，不再次获取 Application.workers，不创建第二份顶层 Job。它复用父日志关联并记录目标服务、深度与结果类别，绝对截止点取父截止点与目标原预算的较早者，取消来自父调用与本子调用，并监听目标 owner 卸载。

每根任务最多 4 个同时活动的后代，深度最多 8；配额满时立即返回明确 conflict，不排队等待祖先释放自身额度。该并发计数包含仍在等待后代的祖先，因此长链也受真实 4 活动调用限制。重复祖先操作明确拒绝；同提供者写屏障或同设备独占锁若已由祖先持有，明确拒绝自等待，其他设备与只读操作不扩大封锁。

启动前与成功接受时复核 Registered 身份，目标重载不接受旧代结果；历史清理告警不参与准入。普通输出验证的是业务结果；顶层 Job 保留原宿主产物封套，反向句柄收到契约业务值，产物仍由原调用发布层管理。
