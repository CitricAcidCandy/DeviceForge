# 接口设计

## 协议边界
新客户端使用 `/api/v2`，成功返回 `{log_id,data}`，失败返回 `{log_id,error:{code,message}}`；`/api/v1` 保留实体/数组和 `{code,message}` 兼容。公开实体由 Rust 类型生成 JSON Schema；两个版本的 openapi.json 都返回完整 OpenAPI 3.1。导出命令：`cargo run -p apk-server --bin export-openapi`。前端通过生成脚本读取这个输出，不维护第二份手写 DTO。产物下载与 OpenAPI 格式例外见 [日志与关联契约](日志与关联契约.md)。下表的 v1 业务路径同时提供 v2 对应路径。

默认免鉴权，包括健康检查、接口模式和 MCP。如设置 APK_API_TOKEN，业务/管理请求使用 `Authorization: Bearer <令牌>`。业务请求体不超过 256 KiB；默认全局每秒 120 请求，部署者可用 `DEVICEFORGE_HTTP_RATE` 在 1–100000 调整；最多 128 个在途响应，响应结束或关闭释放名额。任务队列容量 128，并发执行 4。队列容量包括运行中的任务，满队列返回 409。

运行诊断：`GET /api/v2/diagnostics/logging` 返回日志写入、丢弃与错误计数；`POST /api/v2/system/shutdown` 触发任务/会话收敛、监听退出和日志刷新。这两个入口只在 v2 提供，部署令牌可选，没有细分管理权限。

| 方法与路径 | 输入 | 结果 |
| --- | --- | --- |
| GET `/api/v1/health` | 无 | 服务状态和 API 版本 |
| GET `/api/v1/operations` | 无 | 内置和插件贡献的 ID、标题、输入模式 |
| POST `/api/v1/jobs` | `operation`、`input` | 202，持久化的排队任务 |
| GET `/api/v1/jobs` | `limit=1..200`，默认 50 | 最近任务，当前不提供历史分页 |
| GET `/api/v1/jobs/{id}` | 任务 ID | 状态、输入、最终结果及失败原因 |
| POST `/api/v1/jobs/{id}/cancel` | 任务 ID | 取消状态，已完成任务保持原状态 |
| GET `/api/v1/jobs/{id}/events` | `after` 递增游标，默认 0 | 最多 200 条状态事件 |
| GET `/api/v1/openapi.json` | 无 | 公开接口模式 |
| POST `/mcp` | MCP JSON-RPC | SDK 协商及工具结果，见 MCP 文档 |

事件存入数据库。客户端使用最后一条事件的 `sequence` 继续读取；没有新事件返回空数组，慢客户端不阻塞执行器。当前是游标轮询，不是日志推送流。取消后结果不能覆盖终态。服务重启时遗留任务标为失败，不自动重放设备写操作。

错误实体：`{code,message}`。400 输入无效；401 无令牌；404 资源不存在；409 状态冲突或队列满；413 请求过大；415 媒体类型错误；429 限流；500 存储异常。插件和工具执行失败写入任务的失败状态。

## 已接入设备操作
`android.devices`、`harmony.devices`、`android.connect`、`android.disconnect`、`android.app.start`、`android.app.stop`、`android.packages`、`harmony.packages`。枚举与写操作统一走任务。输入模式通过 operations 查询；设备连接服务器所在主机。工具部署参数来自环境变量，HTTP 输入无法修改可执行文件。

## 后续接口
产物上传下载已采用产物 ID，见产物接口.md；后续 APK 分析将返回结构化元数据；配置按工作区和用户划分；性能、Frida、投屏等采用插件任务及会话接口。上述后续业务能力尚未实现，不在 OpenAPI 中冒充可用能力。设备行为仍需真机验收。

产物上传下载和 ZIP 条目预览现已实现，详见产物接口.md。只有上传端点使用单文件 64 MiB 限制，其他 JSON 接口仍保持 256 KiB；上传不接收 multipart。
