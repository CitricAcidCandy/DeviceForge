# 工具进程完整范围公共契约

日期：2026年10月12日。主代理负责公共库与分发，后端继续AI SDK私有编排，测试角色独占多代原生夹具。本文批准调用形状和资源职责；公开接口及Windows Job首批实现已接入并通过库编译和Clippy，原生API行为由测试角色并行验证。Linux与macOS完整范围仍未取得资格，不报告三平台工具树清理完成。

## 问题与边界

既有`spawn_stream`、`StreamingProcess`和`StreamExit`只持有直接进程。AI SDK通过Rust启动真实CLI时，提供者可能派生命令工具；直接CLI退出不能证明这些后代退出。新增能力落入`crates/tool-process`，不在宿主添加AI命令分支，也不依赖私有SDK模块。

旧接口和默认直接进程语义保持兼容；新完整范围显式接入。启动前必须取得原生成员归属，不能先正常spawn再按PID追绑、用PID消失代替稳定OS身份或把kill成功当退出。

## 批准的公开调用形状

新增`ScopePolicy::OwnedTree`、`ScopeCompletion::{Complete,Failed}`和`ScopedStreamingProcess`。提供`spawn_scoped_stream(command, options, cancel, policy)`与`spawn_scoped_stream_with_lease(command, options, cancel, policy, lease)`，返回`Result<ScopedStreamingProcess>`；沿用`ToolCommand`、`StreamOptions`与`Arc<T>`租约，不引入平台命令字段。

新进程对象保持`input/recv/cancel/wait`模式，输出仍是有界原始双流。`wait`返回`Result<ScopedStreamExit>`，其中`direct: Result<StreamExit>`保留真实直接退出或原业务错误，`scope: ScopeCompletion`单独记录完整资源范围。外层监督失联或不可确认必须失败，不能提升为Complete。

业务取消、到期、非零退出和资源是否已释放分开。Complete须实际直接进程、所有拥有的后代、管道及所属监督工作均结束；只有这些条件成立才释放lease。Drop撤销输入和业务，后台继续确认；失败保持资源与租约所有权，不用丢弃Future或后台任务句柄提前解锁。

## 原生监督与分发要求

Windows须在暂停创建、Job绑定之后恢复执行，不允许breakaway；持有Job/实际句柄并核对ActiveProcessZero与active=0。Linux使用每调用独立subreaper监督，保持受控组身份、实际wait/reap至完整空集合，禁止在共享宿主全局waitpid抢Tokio子进程。macOS受控SDK的组、sentinel和kqueue/libproc方案只证明固定无detached/unref档案，不能扩大为任意CLI后代资格；未取得可靠全树归属/退出方案时明确unqualified，三平台完整目标仍待。

若采用监督可执行入口，其位置由固定包映射提供，浏览器业务输入不能选择入口。公共库拥有通用监督协议与平台执行，包内入口不得装载SDK或平台业务。监督输出与真实CLI双流分离且有界；最终回执还须核对监督自身实际退出。具体helper启动与包映射仍须在实施时冻结，不把一个不运行的接口当实现。

沿用原业务绝对截止点；首次故障固定一次清理截止点，并行停止各拥有资源，不连续追加窗口。AI SDK内部1000毫秒窗口及1250毫秒宿主合作窗口保持；公共cleanup_timeout不得超过既有2秒。

## 必要证据

测试包含父先退出而子孙仍存活、两代后代、取消/Drop、继承管道、迟到退出、归属失败、breakaway与丢失监督。逐个稳定OS身份确认退出，校验租约直到实际范围结束才释放；普通错误与清理失败分别断言。Windows、Linux、macOS原生实际验证分别记录，不借记固定SDK Node测试、单一平台或假回执。
