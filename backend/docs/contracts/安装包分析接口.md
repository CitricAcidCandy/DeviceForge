# APK / AAB / APKS 分析接口

## 调用与模型
通过 `POST /api/v1/jobs` 提交操作，返回任务 ID；查询任务终态获得分析结果。MCP 自动发现同名操作，复用任务层。结果模型 PackageManifest、PackageSignature、ExtractedApk 从 Rust 领域类型生成在 OpenAPI components.schemas，前端类型由 generate:api 更新。

| 操作 | 输入参数 | 结果 |
| --- | --- | --- |
| android.package.manifest | artifact_id，可选 module | 包名、版本、SDK、应用名称、debuggable、权限、完整解码 XML |
| android.package.signature | artifact_id | 验证通过、签名方案、签名者、证书 SHA-256、工具报告 |
| android.package.extract_apk | artifact_id、entry | 来源产物 ID、精确条目名、新 APK 产物元数据 |

```json
{"operation":"android.package.manifest","input":{"artifact_id":"上传返回的 UUID"}}
```

manifest 只接受 APK / AAB。APK 不接受 module；AAB 默认分析 base，module 限定为字母开头的字母、数字、下划线，最多 80 字节。manifest 中资源引用和预览 SDK 名称保留字符串值，不假定一定是数字；应用名称可能是 @string 引用。

signature 只接受 APK，工具验证失败时任务失败，不返回成功模型。通过代表 apksigner 对包中声明的平台范围验证成功，当前不提供自定义 min/max SDK；此结果不构成来源可信或恶意代码检查。保留工具报告，默认允许工具警告。

extract_apk 只接受 APKS。先通过 artifact.archive.entries 找到目录条目，再传精确 entry（最多 500 字节），例如 universal.apk 或 splits/base-master.apk。所选条目完整解压并验证 CRC，新文件通过受控产物服务保存；可对新 artifact.id 继续分析或调用 android.app.install。分包可能依赖其他分包，提取成功不保证单独安装成功。

## 扩展与资源界限
服务器配置 APK_APKANALYZER、APK_APKSIGNER 或 APK_APKSIGNER_JAR，以及 APK_JAVA、APK_BUNDLETOOL_JAR。配置属于部署者，HTTP / MCP 不接受任意命令和服务器路径。工具不可用时相关任务明确失败，不阻止其他能力启动。

输入产物在调用工具前流式核对大小和 SHA-256，单文件最大 64 MiB；各准备、工具、解压及发布阶段最多 120 秒。工具标准输出 / 错误各最多 1 MiB；Java JAR 固定最大堆 256 MiB。XML 最大 1 MiB、20000 节点和 128 层，拒绝 DTD 和实体定义；按命名空间取字段。解析结果大小仍受 XML 输出上限控制。

APKS 条目不会解压到用户指定路径，重复同名目录条目拒绝。取消工具或任务会触发临时资源清理，解压线程逐块观察取消。ZIP64 和分卷限制沿用产物服务。
