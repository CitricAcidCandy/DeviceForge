# 插件资源核对与恢复第一版

## 架构裁定

模式为architecture-first，采用契约先行与失败行为回归。插件负责设备资源台账与逐资源核对，宿主仅提供可选恢复端口、代际检查、有界监督和确认发布；HTTP/MCP使用同一应用用例。不能由宿主直接调用ADB，也不能仅重置清理标记。2026-10-23 新策略取代全插件冻结准入：历史清理告警与新调用解耦，恢复在后台进行。

选择显式声明的协议4恢复调用。没有声明的插件仍保留真实清理告警，但不会因此冻结独立新调用。恢复不重放设备输入、录制或其他业务。

| 单元 | 输入输出与职责 | 不承担 | 副作用 |
| --- | --- | --- | --- |
| SDK recovery | 可选声明、有限报告与校验 | 宿主状态、设备命令 | 无 |
| domain恢复端口 | 公开视图、请求与执行器恢复方法 | 平台实现 | 无 |
| infrastructure/plugins/recovery | 协议4独立进程与真实清理确认 | 决定资源已消失 | 有界进程调用 |
| application/plugin_recovery | 核对代际、有界后台回收、按风险修订确认 | 冻结普通调用、删除设备资源、重放业务 | 监督恢复工作、发布报告 |
| mirroring私有恢复 | 持久台账、租约、精确归属核对、控制状态恢复 | 清理外来ADB资源 | 文件、ADB |
| HTTP/MCP与前端 | 薄映射与可读恢复入口 | 直接改状态文件 | 请求与反馈 |

## 声明与报告

清单可选 `recovery: {api_version:1,operation:"runtime.recover",timeout_ms:30000}`，仅协议4可声明，操作不混入普通贡献。声明超时范围为1000至30000毫秒。

恢复输入为JSON对象；结束后的后台回收传原会话输入，手动页面传设备标识，空对象表示核对全部已登记资源。打开不先等待全插件恢复。恢复不能将局部成功报告成整个插件资源已确认。

恢复结果为 `{coverage:"plugin",inspected,remaining,status:"recovered"|"blocked"|"busy",message,checks:[{resource,status:"confirmed"|"blocked"|"busy",message}]}`。最多64项，每条文本有界，完整计数不能因展示截断而丢失。只有全插件覆盖、remaining为零、检查非空且全部confirmed、协议响应匹配、直接进程退出及清理Complete全部满足，才允许宿主解除风险。旧故障历史和会话终态保留。

## 公开入口与互斥

GET `/api/v2/plugins/{id}/recovery` 返回当前代际、是否支持、清理风险、是否正在恢复及最近报告。POST同路径接受 `{generation,input:{}}` 并返回相同视图。代际不匹配为409；不支持为明确冲突，不能清风险。重复恢复在途时返回busy视图，活动调用不阻止回收其他失活资源，也不被回收终止。

恢复登记与停止、换代短暂共用应用准入锁；执行时不持锁、不要求活动调用排空、不冻结普通任务、设备发现、性能和会话。每插件同时最多一份、宿主最多两份恢复；任务登记宿主及owner凭据，HTTP等待取消不丢弃真实清理。卸载取消并等待该任务；不以历史风险拒绝卸载。全部恢复共用固定截止点，不能收到部分输出后重新授时。会话结束后最多三次后台续办，退避零/250/1000毫秒。发布时校验风险修订，新增失败不能被旧成功清除；旧owner结果不写新owner。插件负责唯一资源代际及逐资源租约，跳过仍活动的资源，不按进程名杀外来工具。

## 验收要求

覆盖不支持、旧代际、未排空、并发恢复、新会话竞争、真实失败不清标记、错误/超时/掉线、明确成功再开、重启持久台账、活跃租约、PID复用及外来转发。模拟进程、浏览器页面、视觉与真实设备分别记录。默认不变更用户ADB/HDC服务或其他工具会话。
