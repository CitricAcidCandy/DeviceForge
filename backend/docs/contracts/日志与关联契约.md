# 日志与关联契约

## 实施决策

模式为架构优先，采用契约先行与行为测试结合。目标是 HTTP/MCP 请求、后台任务和插件调用可通过服务端生成的日志 ID 关联，并以有界非阻塞队列写入结构化 JSONL 日志。设备提供者的具体 API 不在此次实现范围，日志服务为宿主公共能力。

选择新增 `/api/v2` 统一响应，保留 `/api/v1` 实体/数组契约；拒绝静默改变现有数组为对象。MCP 使用标准元数据，不增加 HTTP 响应包装。二进制内容和 OpenAPI 文档保留原协议，通过响应头关联，OpenAPI 文档另提供合法扩展字段。

## 模块职责

| 落点 | 职责 | 输入/输出、副作用 |
| --- | --- | --- |
| `crates/observability` | 请求关联上下文、日志配置、有界写入、轮转和统计 | 配置到日志运行句柄；写日志文件，不依赖业务 crate |
| `server/src/correlation.rs` | 生成可信请求 ID、外层审计、响应关联 | HTTP 到 span/响应；不记录请求体、查询和令牌 |
| `server/src/responses.rs` | v2 流式 JSON 包装和二进制保留 | 序列化数据流到公开包装；不解析完整成功响应 |
| `server/src/mcp_observability.rs` | 在 SDK 服务边界传播上下文并附标准关联元数据 | SDK 请求/响应；不改变 JSON-RPC 协议 |
| `application` | 排队、运行、终态、取消和停止的关联事件 | 任务状态；不依赖基础设施日志写入实现 |
| `infrastructure` 插件模块 | 关联插件 ID、版本、请求 ID 与执行状态 | 插件调用；不记录输入、输出、环境或工具参数 |
| CLI | 输出日志位置、请求自有后端优雅退出并保留退出兜底 | 固定回环服务；不打印令牌、不关闭无关进程 |

公共可观测性 crate 是跨层支撑依赖，禁止引用业务层或公开插件 SDK。公开插件协议 1/2 暂不新增日志字段；宿主通过插件请求 ID 关联旧协议，后续版本化会话协议再传递日志上下文。

## 公开响应

- v2 业务成功：`{"log_id":"...","data":...}`，数据可为对象、数组或空值。
- v2 业务失败：`{"log_id":"...","error":{"code":"...","message":"..."}}`。
- 所有宿主 HTTP 请求响应均携带 `x-deviceforge-log-id`；客户端提交同名头不会决定服务端 ID。
- v1 保留原数据形状，关联 ID 从响应头读取；新客户端使用 v2。
- 产物下载不修改字节，包含 JSON 类型产物；OpenAPI 成功文档保留标准结构并带 `x-deviceforge-log-id` 扩展。
- MCP 业务响应在 `result._meta["deviceforge/log_id"]` 返回 ID，协议错误在 `error.data.log_id` 返回。HTTP 鉴权或传输失败返回关联头与诊断体，不伪造 JSON-RPC 请求 ID。
- 每次查询产生新的请求日志 ID；任务执行继承提交请求 ID，查询/取消事件携带任务 ID，用于跨请求查找。

## 写入与资源策略

默认在数据目录下 `logs` 写入 JSONL，固定日志文件命名空间；按日轮转并限制保留文件数。允许部署者指定日志目录、等级、队列容量和保留文件数，非法配置启动失败。

队列有界，写入线程独立；满队列丢弃日志并累计计数，不阻塞请求等待磁盘。记录写入字节和 I/O 错误，鉴权后的诊断接口提供统计。正常退出持有 guard 并刷新；强制终止、磁盘错误和队列溢出可能丢日志，不能作为不可丢失的审计账本。

仅允许宿主受控日志目标输出，禁止通过第三方 SDK 的 debug/trace 日志泄漏请求载荷。宿主事件记录类别、状态、耗时和受限身份；不记录访问令牌、签名材料、请求体、完整 URL、设备地址或插件原始标准错误。日志只在部署数据目录持久化；工具调用简报不写入源码。

## 最低验证

覆盖成功/错误/数组/鉴权/限流/404/405、二进制原样下载、OpenAPI 合法结构、MCP 初始化/工具列表/调用/协议错误、异步任务上下文及插件请求关联。覆盖配置拒绝、轮转保留、队列溢出计数、I/O 错误和正常退出刷新；真实服务验证日志确实落盘且敏感测试哨兵不出现在记录中。

性能单独测量生产路径的日志格式化与队列提交，记录事件数、耗时、丢弃和写入量；其结果不等于 HTTP 负载、慢磁盘或真机性能验收。

## 部署与测量命令

| 环境变量 | 默认值 | 约束 |
| --- | --- | --- |
| `DEVICEFORGE_LOG_DIR` | 数据目录/logs | 部署者配置，不由业务请求选择 |
| `DEVICEFORGE_LOG_LEVEL` | info | tracing 等级 |
| `DEVICEFORGE_LOG_QUEUE` | 8192 | 1–65536 条，每条最多 8192 字节 |
| `DEVICEFORGE_LOG_FILES` | 14 | 2–365 个本模块日志文件 |
| `DEVICEFORGE_HTTP_RATE` | 120 | 1–100000 请求/秒，HTTP/MCP 共用 |

`GET /api/v2/diagnostics/logging` 返回计数，需要部署令牌。`POST /api/v2/system/shutdown` 同样鉴权，用于正常收敛与日志刷新；当前部署身份没有细分管理权限。

执行 `node scripts/logging-smoke.mjs` 验证真实 debug 服务；release 先构建 server 和 echo，再加 `--release`。报告分别生成到根项目 artifacts/logging-smoke-debug.json 与 logging-smoke-release.json，包含模式、并发、吞吐、延迟、丢弃、写入及敏感哨兵核对结果。

日志单独测量：`cargo run --release -p deviceforge-observability --example logging_bench`。示例使用生产格式化和有界队列，在本机临时目录测量 4 线程共 30000 条记录；输出提交延迟与队列计数。单次短时测量仅作为本机基线，不能推断持续负载、另一台主机、慢磁盘或真机性能。
