# 插件调试器 v1：实施契约与边界

状态：2026-10-27 开始分批实施。本文不是首期生产验收报告。

## 架构裁定

采用 `architecture-first` 与契约先行、失败回归结合的 Hybrid 模式。
选择“官方浏览器插件＋宿主公开底座”，不把 UI 检查、执行器、安装与日志拼成新的万能调试服务器。
复用原任务、会话、安装与产物服务，减少两套运行事实及回归面。

| 单元 | 输入与输出 | 职责 | 不负责与副作用 |
| --- | --- | --- | --- |
| application/debugger | 实例、目标、会话、命令、回执、事件 | 有界状态、期限、一次领取、旧代拒绝 | 不调用 DOM、不安装插件；仅内存与异步通知 |
| server/debugger | HTTP/MCP 参数与同一用例结果 | 真实回环、来源、模式、关联响应 | 不创建另一执行器；复用已有业务端口 |
| 浏览器观测底座 | 指定插件、DOM、公开语义登记 | 树、查询、差异、断言、受约束动作 | 不读 Fiber/Props，不把 DOM 冒充扩展点 |
| 浏览器桥与装配 | 本机端点、明确实例、命令与回执 | 心跳、按会话采集、有界交换 | 不自动重放变更，不选择任意标签页 |
| 官方 Debugger 插件 | 公开服务结果 | 悬浮球与面板 | 不读宿主私有代码，不新增安装体系 |

已有装配文件只追加依赖注入与路由注册，具体逻辑拆入新模块。生成类型由主代理统一生成。

## 协议与目标

- 协议版本为 `1`，能力清单按真实实现返回；没有能力明确拒绝，不返回伪空成功。
- HTTP 根路径为 `/api/v2/debugger`，沿用真实日志关联与 v2 包装。
- 公共浏览器服务为 `host.debugger@1`；`context.debug` 为可选能力，旧插件不强制升级。
- `context.debug.registerSession?(sessionId)` 显式登记调试工具已取得的会话，返回关闭并回收登记的释放函数。宿主独立执行每项最多两秒的关闭，不借用已撤销的插件 SDK，也不关闭其他工具或 MCP 未登记会话；每插件至多64项活动登记，旧宿主缺入口不能宣称自动回收完整。
- 短暂内存锁竞争单独返回 `debugger_busy`，与真实容量耗尽 `debugger_capacity` 区分。桥的登记、心跳与领取仅对此明确未受理响应在同一期限内最多退避六次；网络未知、回执和业务动作不重放。
- 目标必须指定运行实例、插件与当前代次；宿主结构概览不等于对全部插件开启详细采集。
- 浏览器页面刷新产生新实例。队列命令仅领取一次，未确认结果不自动重放。
- 真实回环检查独立于原“同机网卡”判断，不信任请求转发头；浏览器来源也必须是回环来源。
- 市场本地导入与 MCP 导入继续走共同安装用例，不提供 `debug_upload`、`debug_install`。

## 有界性与诚实状态

- 会话默认闲置 30 分钟；实例、会话、队列及历史均设容量，退出和过期撤销相应等待。
- 每浏览器最多 4 项在途、32 项排队；读取默认 5 秒，动作与条件等待默认 10 秒。
- UI 树每页最多 500 节点、响应最多 1 MiB，最近 10 个快照。事件页最多 200 条，缓冲最多 10,000 条或 16 MiB。
- 断线、取消、超时、换代和重复回执分别返回原因。已派发不等于业务成功，取消等待不等于取消原 Job。
- 断言返回通过、失败或无法判定。截断、虚拟列表、不透明结构与未知遮挡必须保留，不能据不完整树断言不存在。
- 默认只存元数据，不采密码、输入值、凭据及任意网络载荷。主动试调用另作脱敏，不能声称识别所有秘密。
- 旧清理告警只作历史诊断，不能封锁独立新调用；不承诺识别未登记的全局副作用。

## 交付门槛

先证明显式目标、容量、超时、不重放、旧代拒绝、脱敏及不完整树断言的直接单元行为。
新 UI 必须先有 Ardot 可编辑设计、落盘并取得用户确认。
只在该功能需要时进行最小本机桥接联调，不操作设备，不替换用户服务，不扩大到全仓回归。
可导入插件、共用导入更新与恢复、报告产物、第三方独立示例和真实闭环未全部验收前，不标记生产可用。

## 2026-10-28 数据与 Agent 自动调试增量

本批数据工具只对明确选择的浏览器插件生效。服务器插件继续通过已有公开服务或操作返回原 Job；没有服务器数据登记端口时明确返回能力不可用，不伪造空目录或成功写入。HTTP `/api/v2/debugger/call` 与 MCP 使用相同工具、输入校验和桥接命令。

| 工具 | 输入 | 返回与约束 |
| --- | --- | --- |
| `deviceforge.debug_data_catalog` | `{session_id,parameters:{}}` | 只列主动登记的数据源及 schema、是否可写、持久化与生效策略，不触发读回调；敏感 schema 属性由浏览器投影省略，并声明不完整 |
| `deviceforge.debug_data_read` | `{session_id,parameters:{source_id,query?}}` | `{source_id,revision,value}`；正文为插件声明的业务投影，已知秘密脱敏；不恢复隐藏字段 |
| `deviceforge.debug_data_write` | `{session_id,parameters:{source_id,expected_revision,value,confirmed:true}}` | 完整替换该数据源的业务投影后回读；插件写回调必须原子校验修订，宿主写前检查不能替代插件 CAS；失败及未知结果不自动重放 |
| `deviceforge.debug_automation_run` | `{session_id,parameters:{steps,confirmed,stop_on_failure?}}` | 整段作为一条浏览器桥命令，浏览器依次执行并保留步骤结果；不在后端递归调用 MCP 或另建任务事实 |
| `deviceforge.debug_command` | `{session_id,command_id}` | 只读原命令回执；核对结果的原会话归属，关闭、断线或换代后仍可查有界历史；不会重新派发或更改状态 |

每个步骤为 `{id,label?,tool,parameters,bind?}`，标识唯一且只能引用之前的步骤。`label` 为可选业务展示名称，具体字符约束见下文；`tool` 只允许 `inspect/data_catalog/data_read/ui_tree/ui_query/ui_assert/ui_action/data_write/invoke`，不允许重载、脚本和嵌套自动调试。界面断言使用独立 `ui_assert` 步骤；每项原有禁用、确认、校验和未知副作用约束继续生效。包含变更动作的运行要求外层 `confirmed:true`，并保留对应步骤自己的确认参数。

`bind.target_from_step` 只用于 `ui_action`，引用先前的 `ui_query` 唯一节点，投影到 `parameters.action.target`；查询为空或多项时不能任意取第一项。`bind.revision_from_step` 只用于 `data_write`，引用先前同一 `source_id` 的 `data_read.revision`。绑定与对应静态目标或修订不能同时提供；缺失、前向、错类型和跨数据源绑定均拒绝，不支持任意路径或表达式。

自动调试最多32步，后端从入队起总预算30秒，浏览器内部使用28秒以留出回执收尾；排队不重启期限。读取默认5秒，数据写入默认10秒。单个写入 `value` 编码最多256KiB，写入参数含封装最多260KiB；自动调试整体参数最多1MiB，每个写入仍独立执行256KiB正文限制。普通旧工具的64KiB输入限制不扩大。凭据原文仍被拒绝，数据写入使用无敏感字段业务投影，不将脱敏占位符当作恢复秘密的协议。

超时、断线和关闭只说明宿主等待或桥接会话结束，不能证明已派发的插件写入停止。未知结果通过原 `command_id` 查询；不以新命令重放、清历史、重启或永久禁用整个插件解决。CAS冲突作为原失败回执保留，旧代回执不覆盖新目标。

自动调试回执的每个 `steps[].result` 独立保持500个 UI 节点上限，整份仍共用1MiB、32步和有限结构节点预算。只有明确数据读取／写入结果的 `value` 业务子树不套用 UI 节点计数；敏感字段、深度和256KiB正文限制继续执行，不因普通业务字段名为 `nodes/children` 误拒。

本批最小单元证据：`cargo test -p apk-application --lib debugger::tests::data_automation` 最新八项通过，随后新增的 `debugger_automation_response_keeps_ui_budget_per_step_and_global_structure_limit` 单项通过，合计九个不同应用专项；`cargo test -p apk-server --lib debugger::tools::` 十二项通过。首轮服务器测试夹具使用未启用的暂停时钟特性导致编译失败，移除该测试专用属性并关闭夹具自有会话后定点复验通过，没有扩大产品依赖。只对改动文件执行 Rust 格式化，差异空白检查通过。未执行全仓测试、完整构建、真实服务、浏览器、设备或分发验收，也未修改运行中的用户服务。

## 2026-10-28 业务步骤名称与目标级只读活动

自动调试步骤增加可选 `label`，完整形态为 `{id,label?,tool,parameters,bind?}`。名称由调用工具的 Agent 提供，最多80个Unicode字符，不能是空白或含控制字符；显式null或其他类型拒绝。旧调用省略时兼容。名称只用于显示，不参与绑定、准入、回执状态或检查通过判定；关联仍使用唯一 `id`。例如 `{"id":"read","label":"读取当前配置","tool":"data_read","parameters":{"source_id":"aliases"}}`。

`deviceforge.debug_activity` 为额外只读工具，输入为 `{session_id,limit?,before?,command_id?}`，不使用 `parameters` 封装。默认20条，最大50条；`before` 为排他的正整数序号游标，不能与详情 `command_id` 同时使用。观察会话必须还在有界会话历史中，可为已关闭、到期或换代状态；读取不会续期、选择新目标或派发命令。

活动按观察会话的 `target_kind / instance_id / plugin_id / generation` 精确匹配原命令目标，可以观察其他会话对同一目标发起的调试调用。返回 `{target,items,next_before,gap,retained_only:true}`；每项为 `{sequence,command_id,tool,state,steps:[{id,tool,label?}],response}`。序号按入队固定，倒序分页，状态更新不改变序号。列表 `response` 始终为null；明确 `command_id` 的详情只返回该目标下的一条已有回执，并再次执行原回执结构、脱敏和字节校验。没有可信调用来源标记时展示“外部工具调用”，不能声称“Agent在线”。

投影不返回原命令的会话ID、写入业务值或其他原参数；自动步骤只额外保留最多32项的标识、工具和名称。底层沿用现有命令条数和结果字节历史上限，淘汰过任何历史后保守返回 `gap:true`，不据当前列表宣称完整历史。服务器工具仍执行原入口，未经过浏览器桥的服务器调用不会被伪造为活动记录；持久化、实时步骤事件和跨重启恢复不在该视图范围内。

`deviceforge.debug_command` 仍严格核对原会话归属；新活动投影没有放宽该接口或返回另一个会话的完整原始命令。HTTP与MCP继续共用同一服务与18个调试工具，不增加第二执行器。

本增量验证：`cargo test -p apk-application --lib debugger::tests::activity` 五项通过；`cargo test -p apk-server --lib debugger::tools::` 十三项通过，覆盖原命令回执归属与新增跨会话只读活动边界。专项先建立缺实现的失败回归，绿轮修正缺少的类型导入及测试夹具对非Debug错误使用unwrap后通过；不增加产品依赖。仅执行本批限定单元、定点格式化与差异检查，未构建主程序、未启停用户服务，未执行全仓、浏览器、设备或真实运行验收。

接口生成集成后补齐新活动输入的显式模式默认值，确保只有 `session_id` 必填，`limit` 默认20，`before/command_id` 可省略；不改旧请求模式。新增 `debugger_activity_schema_requires_only_session_and_defaults_page_size` 定点专项一项通过，后端累计19个不同直接用例分批通过；生成类型由主代理重新同步，不手改生成文件。
