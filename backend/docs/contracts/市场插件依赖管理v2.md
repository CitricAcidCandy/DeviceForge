# 市场插件统一依赖管理

## 安装与复用

本契约覆盖完整发布、独立服务器组件和独立浏览器组件。原生程序、脚本运行时和第三方插件使用同一公开声明，不在宿主维护插件名单。

用户点击一次安装插件，宿主先检测本机环境及用户根共享工具，再仅下载缺失的必需依赖。兼容的已有依赖不得重复下载。成功后自动生成有效配置并按启用意图应用。管理页的依赖安装入口用于失败重试、后来失效或可选工具补装，不是正常安装的额外必需步骤。

自动重新检测不下载。宿主启动先检测，工具缺失时保留部署与真实状态，不在后台无提示地联网安装。账号、授权、Root 和签名材料不属于可下载依赖。

## 声明归属

公开类型由 `deviceforge-plugin-dependencies` 提供，插件可经公开 SDK 的 `dependencies` 导出使用。独立组件包根携带 `dependencies.json`，内容为版本一的 `DependencyManifest`；完整发布第二版在 `dependencies` 字段携带同一对象。第一版发布保持原工具安装语义，不能在第一版加入第二版依赖字段。

每项依赖声明稳定标识、名称、兼容版本范围、必需入口、配套依赖、发现规则、版本探测、下载来源及配置绑定。配套依赖不得循环。发现规则包括环境变量、PATH 程序名和相对宿主用户根的位置；不能在请求中覆盖程序、下载地址或安装目的路径。

没有声明表示没有可推断的工具依赖。浏览器插件依赖仍由后端管理，浏览器只通过公开宿主接口消费服务，不直接执行服务器工具。

## 用户目录和绑定

用户根由 `DEVICEFORGE_USER_DIR` 决定，默认 `.deviceforge`。共享工具仓库、索引、独立绑定与用户配置均不依赖 npm 缓存或业务数据目录。所有插件共享按稳定工具标识、平台及兼容版本查询的工具视图。

自动候选优先使用兼容的本机环境工具，再使用用户根中的工具。用户主动保存的高级工具配置保留覆盖权，但不作为自动发现前置条件。自动结果不得改成用户保存的显式路径。

外部工具只引用，不移动、覆盖或删除。托管工具引用与真实进程租约保持独立；一个插件卸载只释放自身引用，其他使用者仍受保护。索引可以从仓库元数据重建，索引存在不代表工具内容已校验。

资源快照仍兼容 SDK `ManagedResources`。可选 `managed_tools` 映射稳定工具标识到实际仓库包修订，用于混合外部和托管工具；缺少该字段的旧快照保持旧含义。托管租约校验包身份，插件运行配置使用实际工具版本。

## 接口与修订

统一路径为 `/api/v2/plugin-dependencies/{target_kind}/{id}`，目标种类为 `release`、`server`、`browser`。组件属于完整发布时归并所属发布，响应的目标可能为 `release`，客户端以规范化目标继续操作。

- `GET` 查询依赖视图，包含当前声明及绑定修订、每项状态、来源、实际版本、可安装性和缺失原因。
- `POST /scan` 提交重新检测任务。
- `POST /install` 提交依赖准备任务，先重新检测并复用，再安装指定缺失项；未指定依赖列表时处理缺失的必需项。
- 写请求包含 `expected_revision`，可选 `dependency_ids`；旧修订拒绝，不用晚到结果覆盖新插件声明。

写操作走公共任务及事件框架，HTTP、MCP、CLI 共用 `dependency.scan`、`dependency.install` 用例。日志 ID 与任务 ID 分开。取消客户端等待不等于服务器回滚，应重查真实状态。

## 下载与失败

市场优先、官方来源兜底，每个来源分别固定版本、平台、大小、原始摘要及入口。市场与官方原包不同可以保存为不同不可变包修订，不覆盖已存在的同版本内容身份。

连接失败、资源缺失或有界网络超时可以转官方来源；摘要不匹配、解压失败、版本不符或入口不完整不能被换源掩盖。安装只写独占暂存并在验证后提交；取消、失败和仓库忙不损坏旧版。

插件已落盘但依赖未准备完成时，完整发布保持 `dependencies_required`，与 `configuration_required` 和文件事务恢复状态分开。失败必须进入真实任务错误，不能将已安装程序等同于插件可用。

## 验证边界

最低验收包括第三方无白名单接入、空配置发现、跨插件零下载复用、不同版本共存、混合工具租约、损坏与取消不破坏旧版、组件归并、双 npm 缓存复用以及真实页面操作。当前实现和各门禁结果见本轮交付记录；本契约不代表尚未执行的验收已通过。
