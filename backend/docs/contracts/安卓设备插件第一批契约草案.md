# 安卓设备插件第一批契约草案

日期：2026-10-10。版本：草案 v1。模式：architecture-first / Hybrid。本文件只把已交接的独立插件边界收敛为可裁定实施输入；新增名称、能力组合、配置政策与预算均为候选，尚未冻结，不授权修改生产。沿用已实现的设备 API3、统一发现、设备锁和协议4，不复述平台总迁移清单。

目标是独立 `android-device` 插件承担 Android 离散设备操作，生产只引用公开 SDK、plugin-runtime、tool-process 及基础库。宿主不增加 Android 路由或工具分支；已有 owner/generation、Job、发现目录、设备准入、锁、期限与清理仍由通用宿主负责。第一批不包括 APK/APKS 安装、截图产物、Harmony、性能采样或常驻会话。

七项能力的计数口径明确为 connect、disconnect、packages、app.start、app.stop、app.uninstall、input；discover 是独立发现贡献，不计能力。因此候选清单共八项 operations，devices.capabilities 恰好七项。这比上一条最小接线候选增加两个不依赖产物的既有行为（卸载和输入），旨在落实本次“首7离散能力”要求，不能默认为范围已经裁定。若主代理采用其它首批集合，须先改本草案，不能靠实施时自行替换。

## API、协议与名字边界

| 层次 | 候选值或已存在规则 | 对接要求 |
| --- | --- | --- |
| 插件归属 | id=`android-device`，首批 Windows x64 候选 | 只用本插件自己的目录和公开 SDK；不能由包名推导设备归属。 |
| 设备声明 | devices.api_version=3、platform=android | 声明版本与传输协议独立；raw_state 与能力预算规则沿 API3。 |
| 传输 | protocol_version=4 | Request → Ready → Start，公开 InvocationContext；不是新的常驻协议。 |
| 清单贡献 | name 为 discover、connect、disconnect、packages、app.start、app.stop、app.uninstall、input | 这些都是短名，不写 plugin.android-device 前缀。 |
| SDK设备映射 | discover_operation=`discover`；capability.operation 为对应短名，capability.id 同短名、version=1 | infrastructure 映射一次命名空间；不同能力版本不是预算版本。 |
| 对外注册 | plugin.android-device.discover / connect 等完整 ID | HTTP/MCP、直接 jobs 与普通 target.operation 用完整 ID。 |
| 真实请求 | Request.operation 为上述短名 | 插件精确匹配短名；误发完整外部 ID 拒绝，不加双前缀或 fallback。 |
| 旧绑定 | android.devices；android.connect 等 | 配置保持旧 ID，真实目标按 provider/capability 或显式 discovery 解析，不以名字后缀猜目标。 |

所有贡献 schema 严格 object，未知字段拒绝。发现 schema 必须编译成功并接受 `{}`，运行时三个发现入口也只接受空对象。发现与七设备能力不得另填 Contribution.execution 普通预算；发现仍是既有30000毫秒总期限，能力只用 devices.capabilities[].execution_timeout_ms，省略/null 默认30000，显式1至120000。清单操作名和设备映射同源，不给设备贡献增加另一套普通期限。

直接 Job 使用完整外部 operation 及实际贡献 input；标准动作入口沿已有 DeviceActionRequest：provider_id、generation、device_id、capability、version、input。宿主向插件交严格 DeviceActionInput `{device_id,input}`，不把 provider_id/generation 再塞进业务对象。设备 ref 由宿主当前 provider/generation/local_id 构成，插件只观察并接收稳定 local ID，不自行创造 generation。

## 发现 DTO 与状态矩阵

discover 固定 argv 为 `adb devices -l`。插件返回公开 PluginDevice 数组，不构造宿主 Directory、DeviceRef 或私有包装。protocol4 由运行库生成公开 Response，再由宿主产物结果通道形成真实包装；发现解码按 ExecutorResultFormat，不把任意 JSON.result 当宿主证据。

每项含 id、state、raw_state、可选 model 和 capabilities：id 是稳定 ADB serial；state 仅 online/offline/unauthorized/unknown；raw_state 是该行原始状态 token，原样保留，不 trim/转小写/截断。首批候选要求每项都提供原文，以支持旧 android.devices profile；API3 本身仍允许其它提供者缺失/null，此插件政策不修改公共模型。

原文沿已冻结规则：非空、非全空白、最多100 UTF-8字节、无 Unicode 控制符；任一坏设备或重复 local ID 使整次发现失败，不过滤坏行后发布局部目录。解析只排除可明确识别的标题/空行/ADB daemon 诊断，不因状态不在旧白名单就丢弃设备；不能把未知格式正文一律当标题。model 仅从结构化 model: token 取得，不从工具诊断猜测。serial/schema 与宿主标识资格必须一致，候选最多200字节、已有 ASCII identifier 字符集合；不靠设备 label 充当稳定 ID。

| 原始 token | 候选归一 state | 五项 device 能力可用 | 原文与旧数组要求 |
| --- | --- | --- | --- |
| device | online | packages/start/stop/uninstall/input 均 true | raw_state=device；旧 state 仍为 device。 |
| offline | offline | 均 false | 原文保留；已有设备但离线动作 conflict。 |
| unauthorized | unauthorized | 均 false | 原文保留；不尝试绕过设备授权。 |
| recovery / sideload / bootloader | unknown | 均 false | 三种原文各自保留，不映射为 device、不放行特殊模式动作。 |
| 其它合法未知 token | unknown | 均 false | 原文原样保留，不能静默删设备；不猜测已支持工具能力。 |
| missing/null/空白/超100字节/控制符 | 不发布 | 不发布 | 本插件发现失败；不补 unknown 原文来满足旧 profile。 |

provider 范围 connect/disconnect 不出现在单台设备的 availability 列表，不受当前是否有在线设备决定；仍受 owner、清理状态、准入和 provider 写屏障。每设备 availability 只包含本次声明的精确 capability ID/version，给出有限固定 reason，不把 stdout 或任意请求字段作为 reason。上述状态可用矩阵待主代理随首批冻结；本草案不发布 recovery/sideload/bootloader 的动作支持。

显式 refresh、直接 discover Job、android.devices 绑定共用既有三入口单 Job/单执行与发布门禁。旧绑定采用格式2、target.kind=device_discovery、plugin_id=android-device，result.kind=device_discovery、platform=android，input 为字符串 identity；每设备 raw_state 有效才形成同次旧数组 `[{id,platform,state,model}]`，model 缺省归 null。connect/disconnect 不自动嵌套 refresh，不把命令成功冒充新目录；客户端后续显式发现。

## 七能力 DTO、访问与固定命令

以下 DTO 都是候选插件模型，不导入宿主领域类型。封套、业务子对象、input.action 每层拒绝未知字段；类型、范围和业务资格在读取配置或启动工具之前再次纯验证。version 统一候选为1。

| capability ID / 短 operation | scope / access | 插件实际业务 input | 固定 argv（ADB程序由部署配置决定） | 成功 result / 旧 ID |
| --- | --- | --- | --- | --- |
| connect | provider / write | `{address}`；封套 device_id 必须 null | connect、address | `{output}` / android.connect |
| disconnect | provider / write | `{address}`；封套 device_id 必须 null | disconnect、address | `{output}` / android.disconnect |
| packages | device / read | `{}`；封套 device_id 为当前 serial | -s、serial、shell、pm、list、packages | `{output}` / android.packages，不改成包数组 |
| app.start | device / write | `{package}` | -s、serial、shell、monkey、-p、package、-c、android.intent.category.LAUNCHER、1 | `{output}` / android.app.start |
| app.stop | device / write | `{package}` | -s、serial、shell、am、force-stop、package | `{output}` / android.app.stop |
| app.uninstall | device / write | `{package}` | -s、serial、uninstall、package | `{output}` / android.app.uninstall |
| input | device / write | `{action}`；action 见下表 | -s、serial、shell、-T、input 后接固定子命令；必要时多笔 | `{device_id,action,dispatched:true}` / android.input |

provider 封套必须显式 null，缺字段或非 null 拒绝；device 封套必须是非空、合法 serial，null 拒绝。外部动作示例仅使用已有字段：

```json
{
  "provider_id": "android-device",
  "generation": "<本次GET返回的generation>",
  "device_id": null,
  "capability": "connect",
  "version": 1,
  "input": {"address": "192.168.1.10:5555"}
}
```

对应真实 Request.input 为 `{"device_id":null,"input":{"address":"192.168.1.10:5555"}}`；Request.operation 仅 connect。设备动作同形状，顶层 device_id 取当前 local_id，不把旧输入中的 device_id 留在内部 input 里。

address 候选严格为至多200字节的 ASCII host:port，端口1至65535，支持 IPv4、DNS host 或方括号 IPv6；拒控制/空白、空 host、自由参数、无端口或未加方括号的歧义 IPv6。package 候选至多200字节、必须点分隔，每段首字母且余字符仅字母/数字/下划线，沿旧卸载安全规则；旧 start/stop 原字段规则更宽，这里的收紧必须列兼容变化，不能宣称原所有字符串等价。

| InputAction.kind | 必填字段与范围 | 可选字段 | 命令/结果边界 |
| --- | --- | --- | --- |
| tap | x/y：整数0至32767 | 无 | 一笔 tap；不自动缩放或猜屏幕方向。 |
| swipe | x1/y1/x2/y2：整数0至32767；duration_ms：1至10000 | 无 | 一笔 swipe，参数全部转确定十进制字符串。 |
| keyevent | key_code：整数1至65535 | long_press：bool，省略false | true 时固定追加 --longpress。 |
| text | text：1至1024字节可打印 ASCII | enter：bool，省略false | 原空格→%s；字面量%s分段与单引号引用保留，enter 最后追加 keyevent 66。 |

bool 显式 null 或其它类型拒绝。多笔 text 子命令共同消耗原截止点，不能逐段再给30秒；任何失败禁止继续下一笔或返回 dispatched=true。dispatched 只表示工具命令都完成，不证明界面收到输入或发生预期变化。实现应提取/复验旧 `device_input` 的设备端引号和 `%s` 规则，ADB shell 会重拼 argv，不能仅凭宿主独立 argv 宣称设备端文本无需转义。此逻辑不依赖 android-package-core。

除 input 固定回执外，成功 output 保持 trim 后的有界原文本。不返回配置、自由文件路径或签名；业务结果允许旧包列表/连接文本，生产日志与错误不得包含原始输入文本或任意工具输出。stdout/stderr 每路候选保留 tool-process 默认1 MiB，非零退出总是失败。

旧 DeviceTools 的 failed/unable/cannot/error:/no devices/device offline/monkey aborted/no activities 诊断资格需要精确回归；connect 还须以 connected to 或 already connected to 开头明确成功。uninstall 沿旧 failure/failed/error/unable/cannot/offline/no devices 拒绝并要求独立行 Success；input 每笔要求零退出且无诊断输出。诊断检查只在对应业务中使用，不能给发现或包列表擅加一份万能关键词规则。错误采用固定有界中文，不保存可能包含 text 的诊断原文。

七能力旧绑定使用 Target.DeviceCapability 的 plugin_id、capability、version=1 与 InputMapping 字符串 device_envelope；result 为 Value wrapped=true。发现使用专用格式2 profile，不能把 android.devices 绑定普通 echo。插件不新增私有 response wrapper，宿主发布包装与旧纯值投影保持来源端口约束。错误类别沿现有规则：未知 provider/能力精确版本/device 为404 not_found，旧代/离线/不可用/未观测为409 conflict，坏发现为502 dependency_failed，提交语法/schema为400 invalid_input；插件内部工具错误不能靠字符串还原宿主 Invalid 类别。

## 共享锁、期限和清理资格

所有 device 动作持宿主 provider read 屏障；device write 另持 provider ID + stable local ID 的 Mutex，键不含 generation。provider write 持屏障 write，必须阻止同提供者的 device read/write。锁由真实执行和清理生命周期持有，不能在请求 Future 丢弃时提前释放。直接 jobs、能力动作、旧绑定均沿真实目标固定 scope/access；调用者不得自行传写标志。插件不创建另一套按 PID/本进程区分的“共享设备锁”。

发现继续使用现有全局两额度、稳定 provider 串行与接受门禁；本批不增加发现动作屏障。因此不能声称 discover 与所有 device action 已互斥，更不能用 provider 锁证明系统中其它 ADB 用户不存在竞争。

能力从准入起覆盖排队/共享槽/设备锁/模式/握手/工具/结果处理，宿主固定 D，本地上下文为公开握手产生的 D_L。插件只读取 InvocationContext.deadline，不按清单或 now 刷新总预算；每笔工具是否另设更短期限见第三项裁定。每次启动、取得许可和下一 I/O 前复核，Timeout 与 Cancelled 同刻按公开上下文优先 Timeout。失败/到期不能覆盖未确认清理。

直接 ADB 客户端经 capture_with_lease 等公开端口等待真实 PID 退出；私有目录、worker或后台 waiter 到真实结束才释放。没有产物输入不表示所有命令无外部副作用：connect/disconnect 已改变远程连接，start/stop/uninstall/input 已改变设备，不承诺取消回滚。工具清理失败、未确认任务或必要目录删除失败应返回 cleanup=failed；匹配响应、零退出与 cleanup=complete 只证明声明范围的清理，不证明共享 daemon 或设备状态恢复。

多宿主实例、其它 adb 客户端和 daemon 内部线程不受本插件单任务许可限制；卸载不擅自 kill-server、不切断其它用户连接。该政策最终须由第二项裁定冻结，当前只列风险，不暗选自动启动或 daemon 所有权。

## 三项需主代理冻结的选择

这三项是下一批生产实施前的具体依赖，不是重新要求用户批准。主代理可依据已有授权裁定，但草案不替主代理做默认选择。

1. **部署路径来源与首批写集集合。** 候选采用二进制旁 `android-device.config.json`、仅清单 args 的 `--config <绝对路径>` 覆盖，格式1/64 KiB/逐层未知字段拒绝，空配置可握手但实际依赖缺失为确定失败。候选形状为 `{format_version:1,tools:{adb:<绝对可执行路径或单一程序名>},scratch_root:<绝对目录或null>}`；最终需冻结 adb 是否允许 PATH 程序名、文件/重解析点检查、受限环境白名单及是否有部署级固定 server endpoint。业务不得选择路径、shell 或端点，不继承 APK_ADB/ADB_SERVER_SOCKET 等任意旧环境。七能力集合、地址/package 的安全收紧以及 Windows x64 首发也在此项确认；不靠未知配置字段临时补策略。

2. **共享 ADB daemon 的所有权。** 三种不同政策不能混写：要求已存在的管理员服务；允许标准客户端按部署政策启动共享服务且明确非任务所有；或另行设计插件拥有的私有 server。第一种必须证明所选客户端方式在无 server 时失败且没有启动副作用，不能仅省略 start-server 就当已证明。第二种必须明确由谁保留/停止服务及 cleanup=complete 的声明范围；第三种须另有配置、端口、任务间 owner 和卸载排空契约，不在本草案直接实现。需冻结本批选哪种、无 server 的精确结果、取消/卸载时共享服务风险以及外部连接是否属于清理承诺；禁止暗选 kill-server 或把客户端 PID 退出当 daemon 已退出。

3. **能力总预算、工具短限额和状态可用政策。** 发现既有总30000毫秒不改。候选能力与旧基线如下，全部未冻结；不得把工具旧阶段期限当已证明端到端等价。需明确工具短点是否采用 min(D_L,tool_start+limit)，省略短点时直接同 D_L，以及新七能力/归一状态的 availability 矩阵。任何候选都受能力1至120000毫秒公共上限，输入多命令不逐笔刷新。

| 能力 | 旧工具/完整阶段基线 | 候选总预算毫秒 | 工具短限额候选 |
| --- | --- | ---: | --- |
| connect | 工具5秒，原锁/发现不在同一预算 | 30000 | 5000；可能比总预算先结束，须显式裁定 |
| disconnect | 工具30秒 | 30000 | 30000 |
| packages | 工具30秒 | 30000 | 30000 |
| app.start | 工具30秒 | 30000 | 30000 |
| app.stop | 工具30秒 | 30000 | 30000 |
| app.uninstall | 旧 device_artifacts 工具120秒 | 120000 | 120000，排队/握手仍消耗总预算 |
| input | 旧锁等待和全部子命令共同30秒 | 30000 | 所有子命令同 D_L；不重新给每笔30秒 |

候选总预算的目的是给裁定一份可直接生成清单的数字，不是性能或真机结论。若总预算采用其它合法值，必须在清单、schema说明、旧别名有效预算和验收期望中同源更新，不按平台名硬编码宿主默认。

主代理另拥有 workspace Cargo/lock/架构依赖白名单、可信部署与 server/src/main.rs 装配切换。初批成功后仅撤除旧 Android discover/connect/disconnect/packages/start/stop 对应实现与配置消费，以及已被七能力实际覆盖的 Android uninstall/input装配；Harmony仍有 DeviceTools/DeviceArtifactActions 消费，须拆其旧装配并保留，不删除整份共享模块。具体证据入口为 infrastructure/src/devices.rs、device_artifacts/mod.rs、device_input/mod.rs 及 server/src/main.rs；旧 Android install/screenshot、splits.install和 performance 保留后续批次。

实施顺序为纯DTO/清单→协议4入口/空工具确定失败→发现与七能力假ADB真实进程→通用HTTP/MCP/旧名/取消热卸载→真实目标部署→原宿主对应装配撤除。先验短帧/命名空间再切装配，避免再出现清单双前缀且单元测试绕过真实 Request 的假通过。空宿主验证只有在实际撤除对应直接装配后才计迁出证据。

## 下一段 artifact/install 的具体前置

下一段仍只读候选：app.install、screenshot、app.install_apks，不混入本批七能力。前置为本批provider/短名/锁/原D与daemon政策冻结，具备插件私有目录/工具lease清理资格，并以真实能力任务验证 owner.cleanup_failed 准入。不得提前声明产物贡献再用空实现占位。

app.install/app.install_apks 的真实封套输入为 `{"device_id":"serial","input":{"artifact_id":"UUID"}}`，须清单 ArtifactAccess.input_pointers 声明 `/input/artifact_id`；不能用顶层 input_fields 选择虚假的artifact。宿主选择器先拒绝坏字段、再复制；插件按SDK field为该pointer且同ID唯一关联，校size/sha/64MiB后私有copy，再把路径交工具。必须先冻结本插件Session准备的匹配field、错误资源收口与输出发布接缝，不能假定android-packages当前顶层artifact_id准备器可原样复用。

screenshot 需 public capture_to_file_with_lease、原 D_L、有界stdout文件与stderr、私有固定screenshot.png及宿主真实ArtifactOutput声明；旧绑定采用命名产物投影，不能返回插件路径伪装Artifact。PNG资格和文件大小政策需单列回归，读取/发布前复查普通文件与归属，不把工具零退出当产物资格。

app.install_apks 还依赖管理员bundletool/Java来源、APKS核心资格、设备规格探测、原设备写锁下完整提取+安装预算、选中APK资格及真实安装成功证据。公共设备能力上限120000毫秒不变，若真实流程需要更长是新的公共预算裁定，不能套普通Operation.execution绕开。具体新写集候选为插件 operations/{install,screenshot,install_apks}.rs、session/artifacts.rs及对应清单/旧投影/独立tests；其余配置、核心和宿主写权另分。

设备端安装/卸载/连接有不可逆或持久副作用，取消不等于回滚；私有copy与直接PID/目录清理只能证明自身资源边界。AndroidPerformance与PluginPerformance的protected启动选择、会话owner/generation、每采样锁/预算及卸载排空依旧未迁出，不在artifact/install段暗选性能热卸载方案。Harmony、常驻会话、iOS与真机继续独立阶段。
