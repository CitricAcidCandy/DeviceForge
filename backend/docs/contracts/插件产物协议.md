# 插件产物协议（版本 2/3）

## 能力声明
部署者在插件清单中选择 protocol_version=2 或 3，并声明 artifacts。协议 1 继续支持原有请求和成功结果，不能声明产物能力。HTTP / MCP 调用方不能修改清单声明或指定服务器路径。

```json
"artifacts": {"input_fields":["artifact_id","source_ids"],"outputs":true}
```

input_fields 为最多 8 个唯一顶层字段名，字段名只允许 ASCII 字母、数字和下划线，最多 80 字节。任务输入中的对应值可以是 UUID 字符串或 UUID 字符串数组；缺失字段跳过。总输入最多 8 个产物、64 MiB，先复制并核对 SHA-256 和大小。

新增可选 input_pointers 采用 RFC 6901 JSON Pointer，例如设备标准封套使用 `"input_pointers":["/input/artifact_id"]`。每条最多 256 UTF-8 字节、8 段，支持 ~0/~1 转义与规范数组索引，没有通配符或 URI 片段语义。两类选择器合计最多 8 个；重复指针及旧字段与等价 /field 重复拒绝。空列表序列化省略，旧顶层字段行为不变；旧宿主会拒绝无法识别的新清单，不会静默忽略选择。

缺失对象键和超界数组索引跳过，超过宿主整数范围的规范数字也视为超界；操作模式可要求业务参数必填。非容器中间值、非法数组索引和存在的非法终值明确失败；终值仍只允许字符串或全字符串数组。所有路径、值及引用数量先纯校验，再进行目录/存储 IO。相同 ID 出现在不同选择器下按各引用计数并保留标签。完整边界与本轮验证见 [嵌套输入实施](../implementation/插件嵌套输入产物实施.md)。

## 请求上下文
Request 保留 protocol_version、request_id、operation、input，新增 artifacts：

```json
{
  "inputs":[{"field":"artifact_id","artifact_id":"UUID","filename":"source.apk","size":123,"sha256":"摘要","path":"宿主提供的临时副本路径"}],
  "output_directory":"宿主提供的独占输出目录"
}
```

每个输入都关联原字段和原产物 ID；input_pointers 对应的 field 为原指针，例如 /input/artifact_id，其余上下文字段不变。业务 input 中仍是 ID，宿主副本 path 只出现在进程上下文。output_directory 在未声明输出时为 null。插件只使用这些路径执行本次操作，不应把路径当成可持久化标识。工作目录及临时环境目录也指向本次调用目录。

## 输出与宿主结果
插件把文件写到 output_directory，再通过标准输出返回响应：

```json
{"protocol_version":2,"request_id":"原请求 ID","result":{"message":"完成"},"outputs":[{"filename":"result.zip"}]}
```

outputs 默认空数组，最多 8 项；只声明单一文件名，不传文件路径或服务地址。文件总量最多 64 MiB，允许 APK / APKS / AAB / HAP / ZIP / PNG / JSON / MSGPACK；JSON/MessagePack 单文件最多 16 MiB、64 层和 100000 节点。拒绝链接、非普通文件、路径与重复名称，内容检查沿用产物服务。PNG 当前仍仅检查头部。

宿主先预校验所有声明输出，再逐个发布。协议 2 的任务成功结果固定为：

```json
{"result":{"message":"完成"},"artifacts":[{"id":"新 UUID","filename":"result.zip","media_type":"application/zip","size":123,"sha256":"摘要","created_at":0}]}
```

result:null 合法，artifacts 为空时仍保留结果结构。模型 PluginArtifactResult 从领域类型生成到 OpenAPI。客户端下载使用既有产物接口，后续操作继续传新产物 ID。

响应必须匹配协议版本和 request_id，result 与非空 error 只能提供一个。失败响应不能同时声明 outputs。通用准备 / 发布各阶段最多 120 秒，协议 2 进程最多 60 秒；协议 3 沿合作取消协议。设备能力从准入起共用既有 30 秒总期限，包含副本准备、等待、执行和发布，不能靠阶段期限重新计时；清理沿原窗口。请求最多 512 KiB，标准输出 / 错误各最多 1 MiB。

## 一致性与信任边界
多输出发布没有事务回滚：存储错误或取消发生在发布过程中，已经发布的产物可能保留。所有文件预校验可以避免后续明显无效文件导致的部分提交，但不能消除存储故障和并发修改。

清单能力限制宿主提供的访问，不构成操作系统沙箱。本地/同事局域网默认免鉴权，在线插件按可信代码运行于服务账户权限；目前没有网络隔离、磁盘硬配额或完整派生进程树回收。插件不得启动后台进程，不应依赖服务凭据。宿主进程环境不会向插件传入 APK_API_TOKEN。

## 实现与验收
SDK 位于 crates/plugin-sdk；宿主编排位于 infrastructure/src/plugins.rs，产物准备 / 发布位于 infrastructure/src/plugin_artifacts。公开示例 plugins/artifact-copy 只依赖 SDK。

真实子进程测试覆盖输入副本、摘要篡改、输出授权、路径和格式错误、协议版本 / 请求 ID / 空错误 / 空值、数量 / 体积和临时目录清理；runtime-smoke.mjs 覆盖 HTTP / MCP 插件调用、新产物下载与字节摘要。通用进程插件运行中管理见 [运行中插件生命周期](../guides/运行中插件生命周期.md)，离散设备调用复用本协议，见 [设备提供者第一阶段实施](../implementation/设备提供者第一阶段实施.md)。常驻会话和平台迁出仍待实施；多用户权限不在当前开放部署范围。
