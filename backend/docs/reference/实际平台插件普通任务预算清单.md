# 实际平台插件普通任务预算清单

本文是 Android 设备、Harmony 设备与 Android 包工具三个独立插件迁出的预算交接清单。普通操作的公开声明遵守已冻结的[普通操作总期限第一批契约](../contracts/普通操作总期限第一批契约.md)；下表逐工具数值、内部执行包装和具体迁出顺序均为候选，尚未由主代理冻结，不据此修改清单或实现。

当前取证来自宿主已有适配器，不表示三个实际插件已经落地或验收。LONG-A 的 SDK、领域和基础设施预算接入已交主代理统一门禁，本文件不预报其测试结果，也不宣称平台迁出、常驻、iOS、真实包性能或真机完成。

## 已冻结规则与候选的分界

- 普通贡献的可选 `execution` 为 `{api_version:1,total_timeout_ms}`，声明范围为 1 至 3600000 毫秒。应用注册固化未声明普通操作的 60000 毫秒默认值；ProcessPlugin 只映射显式 `Declared`，不猜平台或业务类别。
- 同一次任务从准入起共用总截止点，包含排队、输入准备、执行和输出发布。传入 `Some(D)` 时，宿主底层不能以旧 60 秒或 120 秒窗口截短，也不能每阶段重新申请完整总预算。
- 发现、设备能力和性能 sample 按清单中的实际 operation 关联判断，禁止重复普通 `execution` 声明。旧名称绑定到特殊目标后沿用目标准入及预算，不因旧名称看起来像普通操作就重新声明预算。
- 清理窗口独立且有界，不能扩充业务预算；超时和取消不等于外部资源释放。清理未确认保持原 `cleanup_failed` 门禁。

以下候选值只用于下一批配置裁定。分段上限之和不等于已证明的旧端到端期限：旧链存在未单独计时的解析、监测、阻塞排队及文件操作，新总期限还包含宿主排队和输入/输出校验。必须用实际阶段门闩及真实包证据确认可接受性，不能以算术加总宣称等价或性能承诺。

## Android 包工具插件：七项普通操作

候选插件落点为 `plugins/android-packages`，对应业务不持设备锁。表中名称是旧操作及拟迁出后缀，不冻结新插件 ID 或清单文件结构。所有秒数均为现有源码计时或候选配置，不能由业务调用者覆盖。

| 旧操作 / 候选后缀 | 现有计时与调用链 | 候选普通总预算（毫秒） | 内部工具短限额及迁出要求 |
| --- | --- | ---: | --- |
| `android.package.manifest` / `manifest` | 输入 materialize 最多 120 秒；APK 用 apkanalyzer，AAB 用 bundletool dump manifest，工具最多 120 秒；随后解析 XML | 240000 | 保留每次工具 120 秒上限；APK/AAB 分支共享一次调用的内部截止点，不把解析或宿主排队排除在新总预算之外 |
| `android.package.signature` / `signature` | APK materialize 最多 120 秒；apksigner verify 最多 120 秒；随后解析签名报告 | 240000 | 保留工具 120 秒；非零退出及零退出失败诊断都不能形成 verified；报告中副本路径按旧语义替换 |
| `android.package.extract_apk` / `extract_apk` | APKS materialize、阻塞校验/精确条目提取、宿主产物发布分别有 120 秒等待窗口 | 360000 | 无外部工具；容器校验、CRC 和逐块复制共用内部控制，阻塞等待不能新开阶段总预算；产物发布留宿主 |
| `android.package.extract_splits` / `extract_splits` | 现有整个 work 最多 120 秒，包含 materialize、APKS 校验、规格写入、bundletool、监测、打包和发布；工具另有 120 秒上限 | 120000 | 保留工具短限额但受内部剩余预算约束；不能把原整体 120 秒误读成各阶段都可再用 120 秒 |
| `android.package.build_apks` / `build_apks` | 现有整体 work 最多 120 秒，包含输入、副本、部署签名校验、bundletool build、监测、产物校验与发布 | 120000 | 工具最多 120 秒且受内部总点约束；固定 argv、签名文件及失败诊断脱敏迁入插件，业务请求不选择程序或密码 |
| `android.package.decode` / `decode` | APK materialize、apktool、阻塞打包、产物发布分别有 120 秒窗口；目录监测贯穿工具阶段 | 480000 | apktool 保留 120 秒短限额；监测、打包和工具共享取消树及目录 lease，工具结束不能直接认定全部工作已排空 |
| `android.package.scan_sdks` / `scan_sdks` | ZIP materialize 最多 120 秒；规则验证后阻塞扫描最多 120 秒 | 240000 | 无外部工具；逐条目扫描共享内部总点与取消，保留规则/证据上限，不因较长总预算扩大输入规模 |

准确迁移来源：`crates/infrastructure/src/package_tools/{mod,manifest,signature}.rs`、`splits/{mod,packing}.rs`、`bundles/{mod,validation}.rs`、`reverse/{mod,packing,scanning}.rs`。公共容器/解析边界见[Android 包公共库提取方案](../implementation/Android包公共库提取方案.md)。

旧 `package_tools::ToolCommand::output` 固定 120 秒是工具阶段上限，不是新普通任务总期限。迁出后不直接复制宿主工具包装；改用公开 `tool-process`，由插件内部编排传入截止点。`reverse` 的 10000 项与 `splits` 的 1000 项等业务 profile 差异、CRC、64 MiB 等原有限额必须分别保留，不能通过统一预算顺带放宽。

## Android/Harmony 特殊操作：不重复普通声明

两个设备插件的现有职责均应关联发现或设备能力，不能为了取得较长期限把它们改成绕过设备准入的普通操作。发现总预算沿用现行宿主规则；API 2/3 能力省略预算默认 30000 毫秒，显式能力预算上限 120000 毫秒。下表能力数值仍是迁出候选，120000 毫秒尤其不能证明排队后工具还能独占 120 秒。

| 旧操作 | 归属与范围 | 旧工具/编排短限额 | 迁出候选及缺口 |
| --- | --- | --- | --- |
| `android.devices` | Android discover | ADB devices 10 秒 | 发现总预算沿宿主 30 秒；保留原始特殊状态，三个发现入口复用目录发布；无普通 `execution` |
| `harmony.devices` | Harmony discover | HDC list targets 10 秒 | 同上；保留 Harmony 平台及原始状态语义，不在插件夹具内伪造旧数组映射 |
| `android.connect` | Android provider write | 5 秒 | 能力总预算候选 30000；保留端口和明确 connected/already connected 校验，provider 屏障必须阻止设备读写 |
| `android.disconnect` | Android provider write | 30 秒 | 能力总预算候选 30000；不将调用进程退出解释为连接事务回滚 |
| `android.app.start`、`android.app.stop` | Android device write | 各 30 秒 | 能力总预算候选各 30000；保留失败文本判定，按 provider 与稳定 localID 共享跨代锁 |
| `android.packages` | Android device read | 30 秒 | 能力总预算候选 30000；保留 `{output}` 旧结果，不静默改为新包数组 |
| `harmony.packages` | Harmony device read | 30 秒 | 能力总预算候选 30000；只声明已实现的 HDC 包列表能力 |
| `android.app.install` | Android device write | 输入复制 120 秒，ADB install 120 秒分段 | 能力总预算候选 120000；输入复制改由宿主授权副本负责，不能把两段加为设备能力 240 秒或重复普通声明 |
| `harmony.app.install` | Harmony device write | 输入复制 120 秒，HDC install 120 秒分段 | 能力总预算候选 120000；保持 HAP 校验、明确成功判断及输出路径替换；与旧分段行为的缩短边界须验收 |
| `android.app.uninstall`、`harmony.app.uninstall` | 各自 device write | 工具各 120 秒 | 能力总预算候选各 120000；保留平台具体成功判定，不允许按本地ID跨提供者写设备 |
| `android.screenshot` | Android device read | 工具文件输出 30 秒，宿主发布另有 120 秒 | 能力总预算候选 30000；截图文件返回 outputs，真实 Artifact 由宿主发布；新端到端 30 秒与旧分段差异必须显式验收 |
| `android.input` | Android device write | 锁等待及多条输入命令累计 30 秒 | 能力总预算候选 30000；宿主统一设备锁，插件内部多命令不重计时；坐标、ASCII 文本和诊断脱敏保持 |
| `android.app.install_apks` | Android device write | 现有整体 work 120 秒，包含锁、复制、校验与 bundletool；工具另有 120 秒上限 | 能力总预算候选 120000；不能继续保留一套绕宿主准入的私有设备锁；输入准备、工具和宿主执行/发布链共用宿主总点 |

Android 性能 sample 另有多条 ADB 命令累计 10 秒的内部上限，不属于普通预算声明。宿主八项性能会话操作与动态采样 source/owner、暂停恢复、卸载排空另批闭合；本清单不把离散 sample 当成会话生命周期已经完成，也不扩大 Harmony 到尚无实现的输入、截图或性能能力。

准确迁移来源：`crates/infrastructure/src/devices.rs`、`device_artifacts/mod.rs`、`device_input/mod.rs`、`splits/mod.rs`、`performance/mod.rs`。旧名称只通过通用绑定转换输入/结果，同一 Job 共享目标 owner、generation、锁和预算，禁止嵌套提交。

## 内部上下文与资源排空缺口

宿主 `ExecutionContext.deadline` 是宿主进程内的单调时钟绝对点。当前 SDK Request 不携带它，公开运行库交给 handler 的是 Request 和取消令牌。因此独立插件不能声称拿到了同一个宿主绝对点，也不能自行增加请求字段或把宿主内部类型变成插件生产依赖。

迁出候选是在每次请求内部建立私有控制上下文，含本次取消树和一个进程内截止点。各工具、容器复制、监测及解析批次共用它，工具短限额取该内部总点与本阶段短限额的较早者，下一次 I/O 前复核；不得每次工具调用重新获得完整声明预算。这个本地点从插件收到请求才开始，不能扣除宿主已消耗的排队/副本时间，实际端到端上界仍由宿主统一总点和合作取消保证。本地控制接口及其采用批次待主代理裁定，不在本文件冻结新公共协议。

| 使用者 | 必须持有和排空的资源 | 不能作为释放证据的事件 |
| --- | --- | --- |
| 外部工具 | 本次直接进程、两路输出读取、输入写入与所用目录 lease；tool-process 原有最多 2 秒清理边界保持 | 仅超时、仅取消令牌、直接进程已 kill 或执行 Future 被丢弃 |
| 同步容器/解析工作 | 有界阻塞许可与输入/输出 lease 必须移入实际闭包，按成员/块复核控制；闭包结束后才释放许可 | 外层等待 Future 结束或请求方断开，不能据此称闭包已停止 |
| 输出监测/打包 | 子取消令牌、目录 lease、受跟踪的监测任务及打包工作；退出后汇合，不留 detached 工作 | 工具已输出 response 或工具进程退出，不能代替监测/打包排空 |
| 协议 3 handler | 汇合本次自有工作后再报告 `cleanup=complete`；任何未确认路径保留 failed/未确认语义 | 输出业务成功、单独写 cleaned 事件标记或忽略 EOF/退出码 |
| ADB/HDC daemon 与连接 | 区分部署者共享 daemon、借用连接及插件自有连接；只清理本次拥有资源 | 关闭一次任务进程不证明常驻连接结束；不得杀共享 daemon 或无关进程 |
| 宿主产物 | SDK inputs 是授权副本；有限 outputs 文件名经宿主校验后发布，逐产物沿同一 D | 插件自报 Artifact ID/哈希不是宿主发布证据；多输出不具有整体事务回滚保证 |

协议 1/2 只证明兼容传输和直接进程边界；有外部资源需要释放的实际插件应优先评估协议 3。协议选择、私有阻塞池容量和真实清理矩阵仍待冻结。不得把进程独立执行称为系统隔离，或把离散调用清理称为常驻会话已经实现。

## 三个实际插件的候选迁出次序

公共前置是已冻结的普通/设备总期限、统一发现与旧绑定门禁，以及包公共库的接口/限额/资源所有权裁定。尚未冻结的部分不能靠插件实现自行填默认值。以下是验收切换的候选次序，互不重叠的开发写集可以并行，但每个旧装配点只能在所属目标实测后撤除。

1. **Android 包工具插件 `plugins/android-packages`**：先接 manifest/signature 与纯容器提取，再接 extract_splits/build_apks/decode/scan_sdks；用无设备锁的七项普通任务验证声明、上下文、outputs 和长链取消。对应撤除 AndroidPackageTools、AndroidBundles、AndroidReverse 及 AndroidSplits 的离线提取装配，不能连设备安装职责一起删除。
2. **Harmony 设备插件 `plugins/harmony-device`**：接 API 3 发现、包列表、HAP 安装及卸载，分别验证原始状态、单 Job 发布、提供者/设备准入和清理。通过后切换 Harmony 对应旧绑定与 HDC 业务装配，不增加尚未实现的平台能力。
3. **Android 设备插件 `plugins/android-device`**：先发现与连接/应用/列表，再输入、APK 安装/卸载、截图，最后接依赖包公共库与 bundletool 的 APKS 安装；逐项验证 provider 屏障、设备锁和嵌套输入产物。性能采样及会话 source/owner 排空单独收口后，才能撤除 AndroidPerformance 与 protected 静态采样路径。

三个插件的生产依赖只允许公开 `plugin-sdk`、`plugin-runtime`、`tool-process` 和经裁定的公共包库及必要基础组件。禁止引用宿主 domain/application/infrastructure/server，也不复制宿主 Job、ArtifactStore、注册目录或私有设备锁实现。平台 argv、工具路径及部署签名配置归所属插件；通用宿主只保留任务、授权副本/发布、日志、目录、绑定和生命周期，不能增加平台分支或隐式内置回退。

## 进入实际迁出的最小证据

- 清单声明：七项普通贡献按裁定预算注册，未声明默认行为可见；特殊操作重复普通声明安装失败。旧名称和原目标目录展示同一有效预算，业务请求没有覆盖入口。
- 阶段期限：受控门闩分别消耗宿主排队、输入、副本、工具及发布预算，下一阶段到期零启动；多条工具和多个输出不重计时。内部保留短限额的操作须证明按预期提前终止，不能只证明声明元数据存在。
- 真实进程：模拟工具验证固定 argv、cwd/env、两路输出限额、预取消零启动、运行取消/到期、EOF、退出 PID 和目录 lease；协议 3 的 complete/failed/ignore 各有明确证据。模拟工具不能替代真实包和真机。
- 真实包：覆盖 APK/APKS/AAB/HAP 对应实际能力，验证 CRC、重复成员、链接/路径越界、解包规模、签名失败与输出文件内容；保留 reverse/splits 各自 profile，不把所有扩展名当等价包。
- 生命周期：旧绑定与直接任务同 Job、同 owner/generation 和共享锁；卸载/排队/执行/终态竞争不得产生晚发布，未确认清理后不能执行新任务。实际插件重载不接管旧代任务。
- 空宿主：无插件、无 ADB/HDC/Java/Apktool/签名配置仍启动；安装和加载不自动运行包脚本或检查工具业务能力，实际调用缺配置给出确定失败，不静默回退。
- 发布：源码静态检查、编译、模拟工具、真实包、debug/release/npx 和真机分别记录。当前文档只完成预算取证与候选交接，不运行任何门禁，也不写成平台迁出已完成。

本文件冻结的是可评审文档版本，不是候选预算或新内部上下文契约。待主代理裁定最多三类事项：七项普通/各设备能力的实际清单值、插件内部短限额与私有控制包装、协议及资源排空实施批次。裁定后仍须补真实证据，不能仅依据本表合计秒数发布兼容结论。
