# Android 性能会话接口

## 创建与控制

所有操作通过 POST /api/v2/jobs 或 MCP tools/call 使用共享任务层；HTTP v2 返回带 log_id 的封套，v1 保留兼容入口。HTTP 示例：

```json
{
  "operation": "android.performance.start",
  "input": {
    "target": { "device_id": "emulator-5554", "package": "com.example.app" },
    "interval_ms": 1000,
    "duration_secs": 60
  }
}
```

任务成功结果为 PerformanceSession，包含 id、request、state、revision、samples、started_at、updated_at、error 及可选 source。source 固定记录插件 id、generation、operation；设备型来源另含同提供者 DeviceRef。旧历史缺少 source 仍可读取，不从当前插件反填；重载只影响新会话。后台采样不占用通用任务工作线程；开始任务的终态与会话终态独立，开始成功后使用会话控制结束采样。

| 操作 android.performance.* | 输入 | 返回 |
| --- | --- | --- |
| start | target、interval_ms、duration_secs | 新会话 |
| inspect | session_id | 会话状态 |
| pause / resume / stop | session_id | 更新后的会话 |
| samples | session_id、after、limit | 会话、readings、next_after |
| list | after_id（可空）、limit | sessions、next_after_id |
| capabilities | 空对象 | 指标与限制 |

MCP 工具使用相同完整操作名，arguments 直接传 input。未知字段拒绝，会话编号须为 UUID。间隔为 1000–60000 毫秒，总时长为 1–3600 秒；分页 limit 为 1–100，samples.after 初次传 0，后续传 next_after。会话列表按 UUID 排序，after_id 初次为空，后续传 next_after_id；空页结束。

状态包括 running、paused、stopped、completed、failed、interrupted。暂停取消当前采样并拒绝旧版本结果，恢复建立新的 CPU 基线；暂停时间计入总时长，到期 completed。停止 / 已停止查询幂等，终态不能继续。服务器重启和正常服务关闭将活动会话标为 interrupted；没有恢复设备进程的承诺。

## 指标与口径

| 字段 | 口径 |
| --- | --- |
| sequence | 从 1 起的会话样本序号 |
| captured_at | 宿主采样完成时间，Unix 毫秒 |
| pid / logical_cpus | 目标主进程编号与采样核数 |
| cpu_share_percent | 进程 CPU 增量 / 全机 CPU 增量 × 100 |
| cpu_core_percent | 全机占比 × 逻辑核数，单核归一化，可超过 100 |
| pss_kib | 目标主进程 PSS，KiB |
| rss_kib | 目标主进程 RSS，KiB；设备未提供时为 null |

CPU 使用 /proc 累计计数相邻差值；guest 不重复计入系统总量。首个样本、暂停恢复、PID / 启动时间 / 核数变化、计数回退或差值无效时，CPU 两字段返回 null。主进程退出、权限拒绝、工具错误或采样超时将会话转 failed，保留已采样数据。

采样按顺序执行多项设备命令，指标不是原子快照。主进程不包含同包其他进程；PSS 与 RSS 不等于堆内存。设备 /proc 权限、不同 dumpsys 输出格式与 CPU 热插拔需真机验收。

capabilities 返回当前采样源 source、CPU / PSS / RSS 指标、scope=main_process、max_samples=3600 和 sample_timeout_ms=10000。Android 独立插件已声明 fps=true 与 device_observation=true；帧窗口有效时样本包含可选 fps / frame_window。设备观测带版本、设备归属、观测时间、单位、来源与访问权限，样本可选 device_observation 与 battery_net_power_mw。后者为整机净电池侧功率，单位 mW，正充电、负放电；未知极性缺省，不代表单游戏或设备负载耗电。温度分别标明真实 CPU、GPU、电池或机身传感器类别，缺测省略，旧历史不反填。详情见[性能采样插件协议](性能采样插件协议.md)与[Android游戏指标Rust采集实施](Android游戏指标Rust采集实施.md)。真实游戏指标准确性、GPU 利用率、网络与 root 调用栈另行实施或验收，不宣称性能模块全部完成。

## 扩展与资源边界

PerformanceStore 可以替换存储；宿主会话服务通过操作贡献接入，不增加业务专用路由。生产通过 APK_PERFORMANCE_PLUGIN 显式选择默认插件，每次实时请求查询当前注册；不保留固定平台探针。未配置或尚未加载来源时允许服务启动，start/capabilities 返回 not_found，历史接口仍可读；排空返回 conflict，已知清理风险返回 cleanup_failed，不回退 ADB。来源卸载使活动会话收口 interrupted；每次采样仍为独立进程，常驻插件协议尚未实现。

服务器当前最多 4 个会话，包括暂停会话；配置开发端口允许 1–32。单样本期限取准入加 10 秒、会话期限与能力预算的最早值，覆盖等待、执行、解码及提交；取消清理复用唯一 2 秒窗口。暂停先持久化，再取消样本；未排空拒绝恢复，已知风险返回 cleanup_failed。慢采样跳过错过的周期，不追赶补采。每会话最多 3600 项，数据库分页有上限；历史总磁盘配额、删除和导出仍待实现。默认免鉴权，令牌可选，不支持多实例共享性能数据库。

## 验证

cargo test -p apk-infrastructure performance 覆盖计数 / 内存解析、真实模拟进程、权限错误、非零退出、取消、SQLite 事务、晚到样本、基线重置及 205 项重启恢复。

cargo test -p apk-application --test performance 覆盖生命周期、容量释放、模式验证、暂停期间无新增、到期、服务关闭、采样器 panic 和暂停后的晚到成功数据。新增 --test performance_lifecycle 通过公开来源装卸、真实开始 Job 和条件变量阻塞数据库，覆盖代际历史、卸载、原期限及真实排空、丢弃启动等待、粘性风险与终态写入失败后重试。

node scripts/runtime-smoke.mjs 验证无默认来源时实时请求精确失败及历史可读；--performance-plugin 验证兼容来源的 CPU / 内存 / 合成 FPS、MCP 暂停、HTTP 继续 / 停止、分页、卸载与重载历史。根 scripts/android-device-smoke.mjs --performance 验证设备型来源及假 ADB 的固定工具调用。真实服务、模拟工具、正式包与真机分别记录，不将夹具数值等同设备指标准确性。
