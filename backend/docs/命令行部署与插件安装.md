# 命令行部署与插件安装

## 分发与启动

项目根目录的 `@deviceforge/cli` 包负责启动预编译 Rust 服务、代理和静态资源，不实现设备业务。`npm run pack:cli` 默认构建 release，执行包入口、版本和 SHA-256 门禁后，将 tgz 放入根目录 artifacts。使用者需 Node.js 22.18 或更高版本及 npm，无需 Rust 工具链。

目前尚未发布 npm registry，部署使用本地包。在项目根目录配置 `APK_API_TOKEN` 后执行：

```powershell
npx --yes --package .\artifacts\deviceforge-cli-0.1.0.tgz deviceforge start --ip 0.0.0.0 --port 7030 --mcp-port 7032
```

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `--ip` | `0.0.0.0` | 对外监听地址，接受 IPv4/IPv6 字面量 |
| `--port` | `7030` | 前端静态资源、HTTP API 和同源 MCP 代理 |
| `--mcp-port` | `7032` | 独立 MCP 监听，仅提供 `/mcp` |
| `--data-dir` | 用户目录 `.deviceforge` | SQLite、产物和默认插件目录 |

两个公开端口不能相同。Rust 在随机回环端口监听，两个公开入口共用同一 Rust 注册表与任务存储。默认免鉴权，包括本地和同事局域网；不会生成调用者无法取得的随机令牌。APK_API_TOKEN 可选，配置后客户端显式提供 Bearer。CLI 不打印令牌、不写入 HTML、不替客户端添加 Bearer。

Host 按实际监听地址和本机网卡限制，MCP Origin 按地址与端口生成白名单。自定义域名、反向代理、TLS 与多用户身份管理需后续独立设计，不通过删除来源检查解决部署问题。

## 数据与生命周期

`DEVICEFORGE_DATA_DIR` 可配置默认数据位置，命令行 `--data-dir` 优先。插件默认位于数据目录的 plugins，`APK_PLUGIN_DIR` 可单独配置；相对值按 CLI 当前工作目录解析，安装、列举和启动使用同一绝对位置。持久数据不存入 npm 缓存。工具路径继续使用 `APK_ADB`、`APK_HDC` 等后端部署配置。

启动失败、端口冲突、后端异常退出、Ctrl+C 或 SIGTERM 都会关闭本次公开监听并收敛本次进程。正常取消先向本次回环后端发送停止请求，配置非空令牌时携带鉴权，最多等待 5 秒以收敛任务/会话和刷新日志；超时才使用进程树强制退出兜底。默认免令牌部署也可调用服务停止接口让 npx 正常退出。强制退出后的遗留任务由下一次 Rust 启动收敛；设备操作不会因此自动回滚。其他平台实现存在但尚未验收。

默认日志目录为数据目录/logs，启动输出明确日志位置。`DEVICEFORGE_LOG_DIR` 相对路径同样按 CLI 工作目录统一解析；等级、队列、保留和 HTTP 限流配置见 [日志与关联契约](日志与关联契约.md)。HTTP 推荐 v2，二进制和 MCP 关联按各自公开契约读取。

## 服务器插件安装

```powershell
npx --yes --package .\artifacts\deviceforge-cli-0.1.0.tgz deviceforge plugin install .\my-plugin --data-dir .\runtime-data
npx --yes --package .\artifacts\deviceforge-cli-0.1.0.tgz deviceforge plugin install .\my-plugin-1.0.0.tgz --data-dir .\runtime-data
npx --yes --package .\artifacts\deviceforge-cli-0.1.0.tgz deviceforge plugin list --data-dir .\runtime-data
```

安装也接受 npm 包名及可选版本，拒绝 URL、Git 来源与 shell 指令；禁用 npm 生命周期脚本，完整保留平铺或嵌套依赖。需要 postinstall 编译的插件应由发布者预编译。目录源必须已经具备运行依赖。

包根 package.json 增加公开便携描述：

```json
{
  "name": "example-deviceforge-plugin",
  "version": "1.0.0",
  "deviceforge": {
    "kind": "server",
    "manifest": "plugin.json",
    "entrypoints": {
      "win32-x64": { "runtime": "native", "path": "bin/plugin.exe" },
      "any": { "runtime": "node", "path": "entry.mjs" }
    }
  }
}
```

plugin.json 使用公开 SDK 的 id/version/protocol_version/args/operations 及可选 artifacts/performance/devices，省略 executable。安装器根据当前平台选择包内普通文件，生成绝对入口；Node 插件使用当前 Node 程序。插件版本必须与 npm 包版本一致。编写协议与贡献时遵守 [插件开发](插件开发.md)；内置 Rust 插件的便携 release tgz 由根目录 `npm run pack:plugins` 生成，见 [原生插件分发](原生插件分发.md)，尚未公开发布 npm。

安装步骤为受限复制、生成暂存清单、同包 Rust `validate-plugin` 校验、生成正式绝对入口、原子发布。复制最多 256 MiB、20000 文件、32 层且拒绝链接。暂存在插件目录同卷的兄弟目录 `.目录名-install`，服务不会扫描半成品；同 ID 加锁并拒绝覆盖既有安装。失败或取消只清理本次暂存和锁，崩溃遗留锁需部署者检查。

`validate-plugin` 共用 application 的操作注册门禁，验证协议、入口、能力、命名空间与本地输入模式，不执行插件、不启动 HTTP、不连接设备。插件按可信代码运行，无来源审批或强制隔离。npm 获取依赖阶段没有磁盘硬配额。

## 运行中加载与卸载

服务运行中可执行同一 npx 安装命令。安装原子发布后不会自动执行插件；调用 POST `/api/v2/plugins/{id}/load`，或 MCP `deviceforge.load_plugin`，输入只为插件 ID，配置令牌时客户端提供 Bearer。GET `/api/v2/plugins` / MCP `deviceforge.list_plugins` 是当前运行目录，与 CLI 的本地部署清单不同。

POST `/api/v2/plugins/{id}/unload` / MCP `deviceforge.unload_plugin` 撤销新任务、取消在途任务并等待清理，部署文件、历史任务和产物保留。重新加载同 ID 产生新代际；排空期间拒绝重载，超时保留 draining 可再次卸载。客户端取消等待后管理工作继续收敛，须查询当前状态。被启动性能探针引用的插件标记 protected，拒绝运行中卸载。

具体模型、限额与日志见 [运行中插件生命周期](运行中插件生命周期.md)。CLI 尚无 load/unload/remove 子命令，同 ID 包原地更新未提供。在线 HTTP 已支持两类包上传、目录和部署删除，浏览器生产宿主支持动态加载/停用；在线目录只列在线安装元数据，见 [在线插件接口](在线插件接口.md)。设备提供者和常驻会话仍待实现。

## 验证与限制

根目录 `npm test` 覆盖参数、网络、路径/来源、实际 Rust 安装门禁、HTTP/MCP、鉴权、错误 Host、取消与端口冲突；`npm run smoke:cli` 使用真实 npm pack/npx，在服务启动后安装带依赖插件，验证安装脚本禁用、HTTP/MCP 加载/卸载/重载、新代际、历史任务、本机局域网地址与独立 MCP。相对独立插件目录也必须覆盖安装、列举和服务发现。

当前运行包为 Windows x64。使用本机局域网 IP 的验收只能证明本机网卡监听和代理可用；另一台机器、防火墙、其他平台、npm registry 公开发布及真机须分别记录。debug 流程不能代替 release 包验收；前端页面仍为基础骨架。

当前设备版本已重建并完成真实 npx 验收：同一 tgz 的显式令牌与默认免令牌两阶段、五个原生插件与公开 Node 设备示例实际安装、HTTP/MCP 发现/调用及旧引用精确错误、完整任务/事件历史保留和正常退出通过。独立真实浏览器另验在线两类包及公开设备上下文；设备均为 synthetic_demo，平台迁出与常驻连接仍未完成。
