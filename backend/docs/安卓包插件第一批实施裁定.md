# 安卓包插件第一批实施裁定

日期：2026-10-10。模式 architecture-first / Hybrid。目标是实现独立安卓包插件并经公开协议验收，随后移除宿主的七项包业务装配。本文件是实施输入，不是平台迁出完成证据。

## 清单、配置与业务契约

采用插件 ID android-packages、协议4、每任务一个进程；仅依赖 SDK、plugin-runtime、tool-process、android-package-core 及基础第三方库，不引用四层宿主。七项后缀、输入 schema、业务 result 和固定 outputs 采用部署与七操作契约草案第七操作、业务投影两节；不声明设备或性能贡献。旧名称通过通用操作绑定进入同一任务，没有内置回退或嵌套提交。

外部操作ID为plugin.android-packages.<后缀>，清单Contribution.name和进程Request.operation只使用短后缀。宿主注册加命名空间、调用时剥离命名空间，插件不得再次加前缀。manifest.example.json供既有原生打包器读取，便携manifest.json沿同一七贡献；原帧测试使用真实宿主的短操作格式，不以重复生产错误的手写请求证明协议接通。

明确冻结总预算：manifest/signature/scan_sdks 为240000毫秒，extract_apk 为360000，build_apks/extract_splits 为120000，decode 为480000。每次工具另设120秒短限额，实际点取公开本地D与该短限额的较早者；解析、复制、监测和发布继续使用本次D，不重计时。上述是部署政策，不宣称旧端到端等价或真实包性能已经验证。

采用旁置 android-packages.config.json，默认位于 current_exe 父目录；缺失构造空工具/无签名配置。唯一覆盖参数为 --config 后接绝对文件路径。配置在有效Start后读取，最多64KiB，严格版本1及未知字段拒绝。采用草案的 tools/java、四种工具、signing 四项和 scratch_root 形状；工具仅允许可执行程序或固定Java JAR前缀，Java固定 -Xmx256m -jar。路径/字符串限4096字节，拒控制符；别名限200字节。JAR、签名文件和配置拒绝链接/重解析点及特殊文件，实际依赖某工具或签名时再查存在性；业务输入不覆盖配置，工具诊断与签名路径不公开。

默认不自动寻找或下载工具，不继承宿主 APK_* 配置，不给 main 增加平台配置注入。无工具配置仍可执行不需要外部工具的提取/扫描，依赖缺失确定失败。发行第一批目标为实际Windows x64；其它目标不得由该二进制冒称支持。

## 输入、工作与清理所有权

宿主输入仅按field=artifact_id及相同ID唯一关联，核普通文件、size与sha256，限64MiB；先复制成插件独占私有输入，后续工具只接私有目录。宿主输出目录只用于最终有界复制，插件输出仅固定filename，由宿主生成产物实体。

每个插件进程最多一个同步工作闭包，许可和私有目录租约移入实际闭包，取消通知后仍等待它真实结束。宿主并发准入仍控制最多四个普通任务；本批不宣称跨多个宿主实例存在共享限额。工具通过公共capture_with_lease持有同一私有目录至直接PID退出；错误或丢弃产生的未确认状态粘性保留。

build_apks监测文件增长；decode和extract_splits监测输出树，不把缺少最终必需文件当作正在生成阶段的错误。任一取消、到期或监测失败通知工具并等待工具与监测收口，同一次两秒收口不扩大业务D。最终完整核心校验、打包和输出复制全部在工具已退出后执行。直接PID、worker、监测、目录删除分别取证，不以成功值推断资源已释放。

私有目录只由本任务创建；确认工具、worker和监测全部退出后，才在受限阻塞闭包中删除已验证归属的目录。删除错误/超时、未确认工具或后台持有者保留cleanup=failed，不返回complete；宿主继续draining/cleanup_failed。插件卸载不删除部署者签名、工具或共享daemon。

## 生产文件职责与并行写集

Galileo 独占新增 plugins/android-packages 的 Cargo.toml、src/lib.rs、src/main.rs、src/operations/、manifest与aliases示例、package.json及README。业务模块负责七项纯输入资格、固定argv、公共核心调用和旧值形状，不拥有进程或工作池机制。不要把七项放进单一万能文件。

主代理独占同插件的 src/error.rs、src/config.rs及config/、src/session.rs及session/，负责部署配置、有界输入/工作、工具/监测/目录租约及最终清理；另独占workspace/lock、宿主装配和架构接入。独立协议测试写权等浏览器驱动冻结后交Kuhn，不能改生产适配断言。Lagrange只读核对契约与实现。

公共接缝使用crate内部Error/Result、config::Tool枚举和session::Session。Session准备接收Request/InvocationContext；业务取得私有input元数据/path、root路径，通过work执行公共核心，通过tool/monitored运行固定工具，通过write_private写规格，通过publish复制固定产物，最后finish返回Execution。准确Rust签名由主代理在下一交接消息明确，不猜宿主内部类型。

## 宿主七业务装配撤除裁定（2026-10-10 03:51）

模式为architecture-first / Hybrid，影响应用执行器边界、server启动装配和既有真实服务夹具，不变更HTTP/MCP/SDK业务契约。先让七旧入口经显式绑定调用真实独立插件，验证既有DTO/产物；通过后删除main中的包分析、构建、反编译及离线分包装配。目标是宿主不再提供这七内置贡献，空插件时旧名称和新贡献均缺席，加载与卸载由现有owner/代际/清理控制。

选择单独的InstallApksOperations保留android.app.install_apks；不在main按操作字符串过滤多业务执行器。后者会继续持有离线分包执行器及隐藏注册职责，不适合作为迁出边界。原SplitOperations只作旧库兼容/测试，不用于宿主装配；安装仍依赖既有公开领域SplitPackages及AndroidSplits，后续随设备插件迁出。这一步不宣称全部平台装配已经撤除。

## 验收与迁出顺序
