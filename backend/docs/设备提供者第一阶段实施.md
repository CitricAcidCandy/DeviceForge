# 设备提供者第一阶段实施

## 架构门禁与实施路线

模式为 architecture-first，采用契约先行与行为回归结合的 Hybrid。目标是让独立安装的第三方插件通过设备声明接入统一目录、能力调用和现有热装卸，不修改平台路由。此阶段是完整设备插件迁移的第一步；Android/Harmony 迁出、常驻传输与 iOS 接入继续按迁移清单推进。

影响范围为公开 SDK、领域模型、操作注册/任务准入、进程插件映射、HTTP/MCP、前端客户端/宿主、文档与集成测试。保持协议 1/2/3、默认免鉴权及现有业务兼容，具体产品界面等待设计稿。

两条可选路线是先建立离散能力贡献，或一次性引入常驻 RPC。选择前者：已验证的任务传输、插件所有权、取消和代际可以直接复用。常驻发现/连接/流媒体仍需要心跳、背压与外部资源清理，不能将每次启动一个进程当作常驻会话。拒绝在 DeviceTools 或路由增加新平台分支。

| --- | --- | --- | --- |
| plugin-sdk/devices | 可选设备声明、发现结果与标准能力输入 | 宿主引用、任务注册、ADB/HDC | 无 |

| server/device_routes、mcp、openapi | 薄设备接口、公开生成类型与日志关联 | 发现解析、能力选择、工具执行 | HTTP/MCP |

注册与提交已有多种职责，新增设备逻辑拆入独立模块，不堆入 server/main、application/lib 或 ProcessPlugin。领域实体和公开插件消息经命名映射转换，插件 SDK 不引用宿主内部 crate；前端 HTTP DTO 仅由 OpenAPI 生成。

## 公开契约

Manifest 新增可省略 devices：api_version=1、展示 platform、discover_operation 相对贡献名、最多 32 个 capabilities。每项能力包含 id、正整数 version、operation 相对名、scope（provider/device）和 access（read/write）。声明必须引用自身实际贡献，发现操作接受空对象；能力操作接受标准对象 `{device_id:null|string,input:object}`。同一操作不能同时用作发现或多个能力，以免互斥/范围不明确。

发现返回最多 128 台 PluginDevice：id、state（online/offline/unauthorized/unknown）、可选 model 与能力可用状态。可用状态必须属于该提供者声明的能力/版本；缺失能力不能默认为支持或可用。重复本地 ID、未知状态、未知能力和超量结果明确失败，不能写入目录。描述文字和字段长度有界，公开 API 不返回工具路径。

宿主 ProviderInfo 带 id（插件 ID）、generation（加载代际）、version 和 definition。DeviceRef 包含 provider_id、generation 和 local_id；不同提供者的同名序列号互不覆盖。DeviceDirectory 带 provider、observed_at、discovery_job_id 与 devices；只保存当前加载代际的明确观测结果，不进行隐式背景发现。卸载后查询不再暴露旧目录，重载或旧发现结果不能复活旧代。

HTTP：GET `/api/v2/device-providers`、GET `/api/v2/devices`；POST `/api/v2/device-providers/{id}/refresh` 接收 generation，返回 DeviceDirectory；POST `/api/v2/device-actions` 接收 provider_id/generation、可选 device_id、capability/version 和 input 对象，返回共享 Job。MCP 对应 list_device_providers/list_devices/refresh_devices/invoke_device，与 HTTP 使用同一服务。

动作先验证提供者代际、声明范围、观测设备和能力可用状态，再绑定实际注册快照进入现有任务准入；解析与提交之间发生卸载/重载须拒绝。新平台通过声明与自身命名空间贡献接入，不能根据 platform 推断执行器。设备写操作以提供者和本地设备身份互斥，并覆盖直接 jobs/MCP 操作调用，不能只约束新路由。跨提供者表示同一物理设备的别名协调尚需配置契约，不能宣称已经跨提供者统一互斥。

刷新最多 2 个在途，具有总期限并在取消/丢弃时撤销本次发现任务；同提供者刷新串行或采用明确观测修订拒绝旧结果。发现仍是每任务一个进程。热卸载沿现有所有权取消发现与能力任务、保留历史，资源未确认沿用 draining/cleanup_failed。

写锁的资源键为跨代稳定的 provider_id/local_id，代际只用于运行准入。提供者级屏障区分 provider write 和设备动作：provider write 与所属设备动作冲突，设备动作共享提供者读屏障，设备 write 再持有同设备互斥锁。等待锁可取消，获锁后复查取消，锁一直持有到执行器确认结束。观察目录不保证操作执行时设备仍在线，提供者执行失败必须如实返回。

错误语义固定：未知提供者/精确能力版本/设备为 404 not_found；旧代、未观测、离线或能力不可用为 409 conflict；非法发现结果/重复本地 ID/发现新增未声明能力为 502 dependency_failed；输入语法、作用域和对象结构错误为 400 invalid_input；刷新取消为 409 cancelled。MCP 保留同一领域错误码与日志关联，不能用任意 4xx 作为验收成功。

## 最低证据与后续步骤

先证明声明错误不会发布任何贡献、同名设备隔离、缺失/不可用能力失败、旧代准入与晚到结果拒绝、取消发现不留活动任务；再证明同设备写串行/不同设备并行与直接任务不绕过。HTTP/MCP 用真实第三方模拟包完成在线安装、加载、发现、调用、卸载、重载，不重启宿主。

随后完成两端门禁与 debug 真实服务；发布前重建当前 release/npx，并区分模拟平台、本机局域网、另一台主机、真机和常驻资源。此文件完成架构门禁，实施可继续，无需新增用户批准步骤。
