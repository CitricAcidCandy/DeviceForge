# 剩余包操作薄适配第二批裁定

日期：2026-10-10。模式 architecture-first / Hybrid。整体迁移已有授权，本裁定确定四个本地包操作的实现边界；具体阶段与错误映射沿《剩余包操作薄适配实施接缝》和《剩余包操作独立验收矩阵》，冲突以本文为准。独立插件迁出、跨进程公开期限、安装设备边界与真机仍保留完整目标，不以本批本地实现替代。

## 契约与选择

冻结默认兼容入口，末参均为现有 ExecutionContext，默认委托对应旧方法：

- BundleBuilder::build_with_context(request: BuildApksRequest, cancel, context) -> Result<BuiltApks>。
- PackageReverse::decode_with_context(id: &str, cancel, context) -> Result<DecodedPackage>。
- PackageReverse::scan_sdks_with_context(id: &str, rules: Vec<SdkRule>, cancel, context) -> Result<SdkScan>。
- SplitPackages::extract_with_context(request: ExtractSplitsRequest, cancel, context) -> Result<ExtractedSplits>。

三个 trait 增加默认 false 的 has_unresolved_resources，对应 Executor 实时转发。application 的 execute 委托 default context，新入口按 operation_budget 检查原 D/取消后转换旧输入并调用 context 端口；不改变 DTO、操作 ID、HTTP/MCP 字段或生成类型。install 仍调用旧端口，应用层入口预检不等于安装全阶段已经传递 D。

选择独立共享容量与每适配器 owner 状态，容量最多四个真实阻塞工作；反对给每个新增适配器另建四槽导致总量增长，或把全部 owner 状态一起 clone 导致跨适配器误报。已有首批构造器保留，增加可共享容量构造入口，服务器显式注入同一容量来源。许可和目录 lease 由实际闭包持有至退出。

Some(D) 只转换时钟类型，所有准备、工具、监测、同步核心、打包和发布共享原点，工具不再取 min(D, now+120s)。None 保留各旧入口的完整 work 或阶段限额，具体基线以接缝文档逐入口列出；不能把 Bundle/Split 原完整120秒改成每阶段各120秒。

## 职责与独占写集

| 所有者与单元 | 输入输出与职责 | 副作用和边界 |
| --- | --- | --- |
| Galileo：domain/src/{bundles,reverse,splits}/mod.rs 及 README | 默认兼容四 context 法与观测 | 不导入核心或执行工具，不修改首批 packages |
| Galileo：application/src/{bundles,reverse,splits}/mod.rs、README、新 context_tests.rs | 原 context 接线、输入和旧 DTO 映射 | 不执行同步核心或生成类型，保留旧仅实现者兼容 |
| 主代理：infrastructure 共享包 worker 与工具 until 接缝 | 容量、owner、许可、真实工作结束和工具未确认状态 | 同步副作用只在有界 worker；不冒充 shutdown、派生树或目录删除确认 |
| 主代理：infrastructure/{bundles,reverse,splits} 与构造装配 | 独立核心替换旧校验/扫描/打包、场景错误、原 D、产物发布 | splits 文件只有主代理写，install 不迁入纯包核心；共用错误保留 CleanupFailed |
| Kuhn：新增 infrastructure/tests/package_context_remaining.rs 与 fixtures/package_context_remaining/ | 四操作公开黑盒期限、取消、结果/错误和实际产物 | 不改原28项测试和生产源码，不通过打印字符串伪造 CleanupFailed |
| Lagrange：只读当前冻结契约、源码与证据 | 定点审查依赖、错误和资源所有权 | 不重复写集、不运行构建 |

工具 until 接缝按 cwd/text/file 输出分别追加，原 Duration 签名委托新入口，保留受限环境、独立 argv、错误文案及直接进程清理预算。监测失败先取消工具并等待；CleanupFailed 优先保留，禁止继续 pack/put。Future 丢弃保留未确认，不因后来成功清零；普通被等待的其他工作不能误报。

Split 的明确兼容变化：本批保持 install 的请求、DTO、设备锁与旧调用链；同一适配器实例仍共享 extract/install 资源风险观测，因此 extract 的持久未确认会使随后 install 被现有 Executor 收口识别为 CleanupFailed。这是新增真实风险诊断，不能描述成安装全部行为不变或安装清理已验证。后续迁为设备插件时独立归属，当前不以隐瞒风险换取旧成功结果。

工具与在飞监测停止时只确定一次两秒清理截止点，并发等待两者，不能逐项刷新窗口；到期未确认保留 CleanupFailed、禁止最终打包/发布，实际后台工作仍持许可和 lease。共享容量登记与 close 使用同一同步门禁，取得许可后登记、spawn 前再拒绝已关闭；server 先关闭该容量，随后既有任务退出，再用一次有界排空复核。该新增接缝只覆盖包 worker，不宣称工具派生树、临时删除或产物 staging 全排空。

## 实施与证据顺序

当前三操作完整门禁、前端生成与本批运行输入构建结束前，上表新增 Rust 写集暂不开放；由主代理明确通知后实施，避免修改正在读入的源码。交接后继续独立任务，普通缺陷按验收项汇总，阻断立即回流。

先验证 application 四流确实收到同一个 D、预拒零端口调用、旧仅实现者和 install 兼容；再落实基础设施共享容量、清理错误和四流公共核心替换。最后验证真实模拟工具、校验后下载字节、monitor/Drop、取消和原截止点，并执行新版完整门禁及受影响 HTTP/MCP/browser/runtime/npx。没有确定性 CleanupFailed 公开触发时明确缺口，禁止放宽为任意错误即可通过。
