# 设备适配器插件架构

## 候选方案与实施状态

DeviceForge 的目标是基础运行平台。Android、Harmony、iOS 等设备适配器作为可独立安装、升级和移除的插件；新增平台应通过公开 SDK 注册，无需重新编译宿主或修改 HTTP/MCP 通用路由。

本文是设备适配器插件化的候选职责与影响分析，具体 API、常驻传输与兼容策略尚未定稿；热拔插是整个项目的明确目标。当前运行时代码尚未完成设备提供者插件化：`crates/server/src/main.rs` 直接装配 `DeviceTools`、设备产物操作、Android 输入、分包安装及默认性能探针；`crates/infrastructure/src/devices.rs` 按 Android/Harmony 分支执行工具。现有插件支持操作贡献、产物及可选性能采样，这些能力不能作为设备层完全可插拔的完成证据。

本次决策与文档不会改变现有 `/api/v1` 或插件协议 1/2。下文的新端口、目录和能力语义均为待实施目标；具体序列化字段、版本协商及兼容策略须在实现前定义并生成契约。

## 宿主与插件职责

| 模块 | 负责 | 不负责 | 输入、输出与副作用 |
| --- | --- | --- | --- |
| `plugin-sdk` | 版本化设备提供者声明、设备描述、能力与结构化错误 | 宿主私有类型、数据库、工具执行 | 可序列化契约；无运行副作用 |
| `domain` | 设备身份、能力约束、设备提供者端口 | ADB/HDC/iOS 命令及 HTTP | 设备引用与规则；通过端口调用 |
| `application` | 提供者注册、统一设备目录、能力路由、任务与设备资源互斥 | 平台命令构造、输出解析 | 提供者结果映射到宿主视图；任务与状态变更 |
| `infrastructure` | 插件传输、受控进程、存储、受控产物及日志写入 | 平台业务分支 | 配置与协议帧；进程、文件及数据库操作 |
| 平台适配器插件 | 平台发现、连接、配对、断开、设备操作及平台解析 | 宿主路由、任务数据库、服务鉴权 | 设备协议与工具调用；仅取得明确授予的宿主能力 |
| `server` | HTTP/MCP、鉴权、关联日志、通用插件加载装配 | 导入具体平台适配器或随平台增添路由 | 请求与公开响应；监听、传输及请求审计 |

宿主还保留配置、权限、任务取消、产物管理和插件健康监测等公共服务。安装包分析、Frida、投屏、自动化等适合独立业务插件，可依赖设备能力；一个平台插件无需包揽所有业务。平台特有的包格式和工具链处理应随对应插件迁出宿主，通用产物与会话基础设施留在宿主。

## 设备提供者与能力

设备提供者是一种显式插件贡献。单纯注册 `plugin.<id>.devices` 操作只能暴露工具，不能让宿主自动理解设备归属、连接状态和可用能力；宿主需验证提供者声明并通过公开端口统一调用。

- 每个设备引用包含提供者身份、提供者实例及本地设备标识。不同插件返回相同序列号时不能覆盖彼此；业务调用用宿主设备引用定位提供者，不能根据 `platform` 字符串猜实现。
- 提供者声明支持的宿主系统、协议版本和能力版本；每台设备再报告实际可用能力。平台名称仅用于展示和筛选，不能代替能力协商。
- 通用能力包括发现、连接状态、应用列表、安装、卸载、截图和输入；连接、配对及远程地址等细节由提供者的公开操作模式描述。发现到未授权设备不等于已连接可操作。
- 能力支持状态与当前可用状态分开，授权缺失、断线或工具缺失需返回结构化原因。iOS 插件按实际工具链、宿主系统和设备授权提供能力，不承诺与 Android 功能完全相同。
- 平台特有能力通过版本化命名空间贡献；未支持的能力明确返回“不支持”，禁止用成功空结果模拟功能。
- 单设备独占写操作由宿主统一协调，不能只在 Android 输入模块加锁。同一物理设备经多个提供者暴露时，须显式配置归属或别名，再按统一资源身份互斥。
- 多个插件提供相同能力时显式选择提供者或按配置绑定，拒绝依赖目录顺序、后加载覆盖及静默回退。

设备事件和任务事件分别建模。设备断线、提供者停止、授权变化应更新统一目录；历史任务和产物保留独立身份，不因插件移除消失。

## 传输、生命周期与性能

沿用独立进程插件作为首选发布边界，使用公开的版本化协议；宿主内部 trait 用于端口注入和测试，不等于开发者可安装的插件接口。Rust 动态库 ABI 不作为跨版本插件契约。

现有协议每次调用启动一个进程，适合离散操作。长期设备监测、持续连接、性能采样及投屏需新增常驻会话传输：有界消息、请求关联、背压、取消、心跳、断线收敛和明确的退出清理。平台工具自身的守护进程、端口与设备连接也需声明所有权；不能因插件进程结束就假设连接已经关闭。

“可安装”与“运行中热装卸”分别验收。通用进程插件已有按 ID 显式加载/卸载、代际和任务清理，见 [运行中插件生命周期](运行中插件生命周期.md)；这些机制尚未覆盖设备提供者、常驻连接和设备状态。后续移除提供者时须撤销新任务准入，等待或取消在途调用，关闭自有会话，释放锁并更新目录；崩溃标记提供者不可用。设备写操作失败或连接状态不明时不自动重放，避免重复安装或输入。

发现轮询需要合并并发请求、限定频率和结果容量；缓存带观测时间和失效规则，不把旧目录当实时在线状态。性能测量分别记录协议开销、进程启动、设备工具延迟和宿主处理延迟；常驻协议未实现前，不声称高频采样已具有低开销。

插件安装是管理员部署操作，配置和工具路径由部署者提供。插件只取得必要配置和宿主能力，不继承服务令牌或其他插件的签名凭据；独立进程仍是可信代码边界，当前不是系统沙箱。

## 宿主日志与关联要求

日志框架属于宿主公共能力。请求、任务和插件调用需要关联 `log_id`、`job_id`、插件身份及插件请求 ID；插件通过版本化上下文接收关联信息，不能把日志实现或宿主私有依赖加入公开 SDK。

宿主日志已按 [日志与关联契约](日志与关联契约.md) 实施：v2 业务 JSON 返回日志 ID，v1 保留结构并使用关联头，MCP 使用标准元数据与错误数据，二进制下载保持原字节。任务及插件调用在宿主内关联；现有插件协议 1/2 不添加字段，常驻插件上下文属于后续版本化设计。

宿主日志写入采用有界异步队列和结构化记录，定义容量、溢出策略、丢弃计数、轮转、保留及退出刷新。插件日志需限额并经宿主归集，令牌、签名材料、原始请求体及任意工具输出不可直接记录。任务事件用于业务状态查询，不能代替诊断日志。队列容量、丢弃与实际吞吐需独立验证，不能把非阻塞写入等同于不丢日志。

## 落点与迁移顺序

### 对整体架构的影响与取舍

以热拔插为目标，设备适配器插件化值得采用；宿主仍承担统一资源与行为约束，不能退化成只负责加载任意模块的空壳。设备通信和平台命令由插件实现，任务、鉴权、日志、产物、设备引用与写操作互斥由宿主统一负责。

| 方面 | 收益 | 代价及必须改变的边界 |
| --- | --- | --- |
| 新平台与维护 | Android、Harmony、iOS 可独立发布和修复 | 需要稳定 SDK、兼容范围和各宿主系统的插件构建矩阵；插件化不能消除系统工具或苹果配对限制 |
| 故障边界 | 独立进程崩溃可局限于提供者 | 宿主必须处理超时、心跳、重连与状态失效，进程隔离不能替代系统沙箱 |
| 热拔插 | 运行中增加或撤销平台能力 | 通用动态注册与调用快照已实现；仍须为设备提供者定义实例代际、常驻会话和目录失效，不能只监控插件目录 |
| 并发与性能 | 常驻适配器可复用连接、合并发现和并行 I/O | RPC/序列化和背压增加开销；现有每次调用启动进程不适合高频发现、采样和流媒体，必须独立定义常驻传输 |
| 一致性 | 一个宿主统一任务历史、设备身份与互斥 | 设备从插件消失时仍需保留任务与产物记录；设备断线、插件崩溃和主动卸载要区分 |
| 前端扩展 | 通用设备工作台可复用，平台面板独立增强 | 面板与后端能力分别协商版本；后端提供者可无面板运行，前端不得依赖平台内部实现 |

建议优先采用版本化异步进程协议；Rust 动态库直接热卸载涉及不稳定 ABI 与存活函数/资源引用，不能作为默认机制。卸载先禁止新调用，通知和取消在途任务，等待受限清理，再撤销注册和更新设备状态；重载应生成新的实例代际，拒绝旧实例晚到消息。插件任务取消不意味着外部设备写操作可回滚。

这些影响先进入架构与验收设计，尚未把具体设备提供者接口或常驻协议写入 SDK；当前日志和异步运行基础可以继续使用现有协议完成。

| 顺序 | 目标落点 | 可验收结果 |
| --- | --- | --- |
| 1 | `crates/plugin-sdk`、拟新增 `domain/src/devices/` | 明确提供者贡献、身份、能力、错误及版本兼容；旧协议继续工作 |
| 2 | 拟新增 `application/src/devices/`、基础设施提供者桥接模块 | 注册与目录聚合独立于平台；同名设备、重复贡献和缺失能力可预测失败 |
| 3 | 拟新增 `plugins/android-adapter/`、`plugins/harmony-adapter/` | 平台发现和连接迁出 `devices.rs`；宿主通过通用提供者注册，不导入具体插件 |
| 4 | 平台插件、通用产物/设备能力桥接与相关用例 | 安装、截图、输入、分包安装和性能依赖公开设备引用；通用服务不直接调用 ADB/HDC |
| 5 | 通用插件加载及常驻会话模块、CLI 安装链 | 空插件部署仍能启动；支持独立平台包和会话退出，热装卸另行验收 |
| 6 | 独立 iOS 或第三方适配器插件 | 无宿主代码修改即可接入；平台能力及宿主系统要求按真实证据声明 |

迁移采用契约先行与行为测试结合的方式。先保留现有操作的兼容映射，并标记来源及迁移路径；旧操作映射最终指向提供者，不能长期保留一套内置命令作为隐式备用。新增平台能力迁入独立插件，不继续扩展 `DeviceTools` 的平台分支。

最低验收包括：公开 SDK 兼容、提供者重复注册、设备身份冲突、缺失能力、发现限额、连接失败、取消/超时/崩溃、同设备互斥、退出清理，以及 HTTP/MCP 调用同一提供者。以第三方模拟平台插件验证扩展性；以未安装 ADB/HDC 的空插件部署验证基础平台启动。随后对各平台执行真机验证，模拟插件测试不能证明 iOS 或其他设备已支持。

执行迁移时同步调整 Cargo 架构门禁，禁止 `server` 和通用用例重新引入平台实现；保留插件只依赖公开 SDK/公共库的要求。前端按能力展示及面板扩展的约束独立存放在前端项目。
