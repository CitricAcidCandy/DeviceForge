# 性能采样插件协议

## 能力与部署

任何语言插件可以实现协议 2 的普通操作请求 / 响应，并在管理员清单中声明：

```json
"performance": { "sample_operation": "sample", "fps": true }
```

sample_operation 必须存在于 operations。操作输入模式须接受 device_id / package 对象，宿主按该模式验证目标；模式仅允许文档内引用，不允许 $id 或外部资源。采样插件不能同时声明产物输入 / 输出能力，采样响应 outputs 为空。

通过 APK_PLUGIN_DIR 部署插件，APK_PERFORMANCE_PLUGIN 填写清单 id 选择本次服务的采样源。未配置时仍使用内置 ADB CPU / 内存端口，内置端口 fps=false。指定插件不存在、未声明能力、采样模式无效或插件标识符重复时拒绝启动；请求不能选择可执行程序或插件路径。

一次服务选择一个采样源，切换需要重启，活动会话按现有重启规则转 interrupted。普通贡献 plugin.<id>.<operation> 仍公开，客户端调用该操作得到协议 2 的 result / artifacts 包装；通过 android.performance.* 会话调用时，宿主解包、验证和持久化样本。

## 请求与样本

Request.input 为公开 SDK 的 PerformanceTarget：

```json
{ "device_id": "emulator-5554", "package": "com.example.app" }
```

Response.result 为 PerformanceSample，例如：

```json
{
  "captured_at": 1791468000000,
  "pid": 123,
  "process_start_ticks": 900,
  "process_ticks": 100,
  "system_ticks": 1000,
  "logical_cpus": 2,
  "pss_kib": 2048,
  "rss_kib": 4096,
  "frame_window": { "frames": 60, "duration_ms": 1000, "source": "synthetic_demo" }
}
```

此 JSON 数值仅是结构示例，不能直接发送：captured_at 必须为当前观测完成时间（Unix 毫秒），范围为宿主当前时间前 60 秒到后 5 秒。CPU 计数必须采用统一单位，system_ticks 是全机累计计数，process_ticks 是目标主进程累计计数；process_start_ticks 用来识别进程重启，logical_cpus 是采样时核数。PSS / RSS 为 KiB，RSS 可空。未知样本字段拒绝，PID、核数及系统总计数必须有效。

FrameWindow 可省略，表示本次未得到 FPS 观测；fps=true 表示支持该能力，不保证每次返回数据。未声明 FPS 却返回窗口会失败。duration_ms 为 1–60000 毫秒，frames 为实际观测帧数，source 为 1–80 字节 ASCII 字母 / 数字 / 点 / 下划线 / 连字符。frames 不超过 duration_ms，等价于最高 1000 FPS 的接口边界。零帧表示窗口内实际观测到零帧，缺少观测不能填零。

窗口结束时间采用 captured_at。宿主计算 fps = frames × 1000 / duration_ms，并同时保存原始 frame_window，让调用方理解口径和来源。不同窗口可能重叠，FPS 是各窗口速率，不能把帧数直接累加。插件需明确统计渲染、提交或展示帧，不混用不同来源；宿主不验证设备测量真实性。

## 生命周期与边界

每次采样创建独立插件进程，无宿主常驻插件状态。采用现有请求关联、环境去令牌、独占临时目录与 stdout / stderr 上限；单样本额外限制为 10 秒。后台性能会话仍由 application 管理，沿用暂停 / 继续 / 停止、版本检查、容量和持久化。

插件支持的 FPS 值及帧窗口作为可选字段加入 PerformanceReading；旧会话 JSON 缺少这些字段仍可读取，内置 ADB 采样不增加 FPS 数据。capabilities 动态返回当前 source、fps 和指标列表。

插件是管理员可信代码，没有操作系统沙箱；直接进程取消有约束，完整派生进程树回收尚未实现。需要派生设备工具的插件必须负责取消与清理，不能创建后台常驻进程。本接口不提供热装卸、常驻插件会话、每会话采样源选择或跨插件调用。

## 示例与验证

plugins/performance-demo 只依赖公开 SDK，输出 synthetic_demo 合成数据，用于展示跨进程契约；没有真实 Android FPS 实现。真实 FPS 工具适配与真机验收仍待迁移。

cargo test -p deviceforge-performance-demo-plugin 覆盖清单、模式、真实进程样本、FPS 持久化、时间 / 窗口 / 类型错误、未声明能力、取消和 10 秒超时。

cargo build --workspace 后运行 node scripts/runtime-smoke.mjs 与 node scripts/runtime-smoke.mjs --performance-plugin，分别验证内置端口和插件模式；两种模式均复用 HTTP / MCP 会话操作。
