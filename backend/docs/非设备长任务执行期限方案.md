# 非设备长任务执行期限方案

状态：纯设计建议，声明、数值和兼容策略均待主代理冻结。本次仅新增本文件，不修改源码或已冻结文档，不表示总期限功能已经实现。日期：2026-10-09。

## 范围与已知边界

目标为普通插件 operation 和后续独立包工具任务提供有界长预算，并把准入、排队、准备、执行、结果转换及发布纳入同一单调截止点。设备能力沿用已冻结的 API 2 预算，不覆盖其默认 30 秒/上限 120 秒；性能会话与单样本另见已冻结设计稿 [性能动态提供者生命周期实施方案](性能动态提供者生命周期实施方案.md)，本文件不重新定义长会话。

本方案遵守 [平台适配器迁出实施](平台适配器迁出实施.md) 与 [合作取消插件协议](合作取消插件协议.md)。不在宿主增加平台分支，不调整产物协议，不增加 shell、任意程序路径或客户端预算覆盖。HTTP/MCP 字段、声明具体 Rust 签名和版本编号不在本文件冻结。

## 最小声明建议

建议将预算作为贡献元数据，绑定具体已注册 operation，独立于业务 input_schema。插件端声明只可引用本插件贡献；重复、未知操作、越界命名空间、未知声明版本和未知字段拒绝加载，失败不留下半发布操作。具体采用 Contribution 可选字段还是版本化清单映射，由主代理按第 1 项选择冻结。

声明只表达所需的有限执行时长，不携带墙钟 deadline、shell、线程数或服务器路径。注册时解析为不可变策略，与 Registered/owner generation 同快照发布；执行时不再读取可变清单或加载新代来更新预算。旧操作别名从实际 Plan.target 继承，不允许 Binding 或业务 input 偷增期限，也不再提交第二份 Job。

数值建议：普通任务缺省/null 为 **60000 毫秒总预算**，显式值为整数 **1–3600000 毫秒**；零、负数、小数、字符串和溢出拒绝。部署者可把上限调低但不能超过主代理冻结的全局上限；声明超过有效上限应加载失败，不隐蔽截短，不接受业务调用提权。3600000 是有限上限建议，引用既有协议 3 的一小时窗口作为初始审查边界，不是包工具已证明需要或可运行一小时的证据。

建议新宿主的普通任务准入均建立总截止点，包括未声明预算的旧插件。这保留输入/响应 wire，却改变了旧时间语义：原先排队、120 秒准备和 60 秒传输分段计时的任务，可能在新的 60 秒总预算内失败；协议 3 旧默认 3600 秒也不能自动保留为每普通操作总预算。该变化必须冻结、写迁移说明并验收，不声称完全行为兼容。低层直接 execute/context None 仍可保留旧阶段行为，不作为新宿主任务绕过总期限的入口。

若主代理选择显式新声明才启用总期限，则旧贡献仍存在无总期限排队边界，必须在验收与能力元数据中明确区分，不可宣称所有普通操作已统一有界。推荐默认总期限方案；真正长任务通过声明预算接入，不靠 legacy 路径延长。

已有设备能力、发现预算和性能采样预算优先沿用所属契约；建议首批拒绝在这些特殊贡献上重复声明普通预算，避免两个字段互相覆盖。旧内置非设备操作必须逐项声明合理预算并接上下文，或明确留在未迁移兼容范围；不能按 android.* 名称在通用执行内核硬编码 120 秒。

分类依据实际贡献关联，不因一个插件同时有 devices 就把其所有普通包工具操作套设备预算。在线安装、插件 load/unload 与服务关闭仍有自己的工作池/排空边界，不因普通 operation 声明而延长管理请求。

## 一次准入、一个绝对截止点

建议应用层普通异步提交入口在获得已注册目标快照后、首次等待存储工作池前捕获 `t_admit`。请求 body 上传、网络传输和 HTTP 限流在该起点之前，继续由各自边界管理；客户端持连接时间不等于任务预算。

计算语义为 `D = min(t_admit + 有效操作预算, 已存在的父截止点)`，无父期限时只取前者。HTTP/MCP/同步兼容提交及别名共用同一策略，不让其中一个入口在获执行槽后重新计时。父期限只能收紧，不能以声明更长预算扩大；变成新 Job、换进程或多步骤工具调用都不刷新 D。

| 阶段 | 必须使用 D 的位置 | 到期要求 |
| --- | --- | --- |
| 准入/持久化创建 | 有界验证/存储池等待、双 schema 与别名映射、owner/当前快照复核 | 未进入创建副作用不得创建/执行；创建已开始则由受跟踪工作收敛记录，不放任孤立 Queued |
| 排队 | 通用 workers/容量等待；不得持无限待运行 Future | 队列到期形成确定失败，不调用 Executor，不重新占一个完整预算 |
| 输入准备 | selectors 先拒坏输入；store.get、受控副本/临时目录及复制 | 每次 I/O 前复核；不因有多个输入各给 120 秒 |
| 进程/协议 | argv 启动前、spawn 后首次业务帧、stdin/stdout/stderr、响应/退出 | 过期不发业务帧；使用同一 D，不截短为旧 60 秒也不重新起时 |
| 解码/纯转换 | 有界响应解析、别名结果投影、产物列表校验 | 结果转换完成再次复核；过期值不可进入成功提交 |
| 输出发布 | 校验全部输出及逐项读取/写入、最终宿主包装 | 下一输出仍受同一 D；禁止逐产物新开 120 秒 |
| 终态提交 | 取得一次成功提交资格前复核 D/取消/owner，并归任务跟踪 | 终态 CAS 与取消竞争；晚成功不得覆盖已有取消/失败 |

Tokio Instant 仅在宿主内从已有 `std::time::Instant` 转换，不把宿主单调时钟值序列化给另一个进程。ProcessPlugin 收到 D 后由宿主传输强制执行；插件内部工具若有更短自限仍可能先失败，但不能把内部旧 60 秒隐藏截短称为长预算支持。独立插件须核对自己的逐步骤 tool-process 预算和取消，才能宣称长任务可用；本批不新增 Request 字段。

## 阻塞工作、发布和终态边界

期限到达只表示不再准入新的业务副作用/成功资格，并请求取消已有工作；不表示 `spawn_blocking` 闭包或文件系统调用已物理停止。阻塞复制、解析、压缩、数据库任务的工作许可及临时目录 lease 必须移入工作并持有至真实结束；Future 丢弃不能提前还名额或删除仍被使用的目录。

建议 CPU/文件循环在有界批次间复核 D 和取消；对不可中断调用，仍保持有界工作池及待排空所有权。任务总期限不能证明整个服务响应在 D 精确时刻完成，失败/取消记录及清理排空可以稍后收敛。超时后禁止启动下一阻塞工作，不能把已经启动但未结束的工作忘记在 owner tracker 外。

建议成功提交资格为短时门禁的线性化点：取得资格前 D/取消/owner 必须有效；已进入的存储事务可能稍晚完成，须被任务和 owner 跟踪。取消与成功资格按同一门禁/CAS 先后排序；用户取消已提交的终态不改写，未获资格的晚到结果不得补成功。不能只在纯转换后检查一次，再无限等数据库槽后无检查提交成功。具体实现不持全局注册表锁等待 I/O。

现产物协议不承诺多文件事务发布。第一个产物已原子写入 store、第二个超时可能形成“任务失败但已有部分产物”的边界；截止点应阻止后续发布和最终成功，不宣称回滚全部产物，不删除无关既有产物。是否记录该失败的已发布 ID/如何回收孤立产物另走后续契约，本批不变更 Job/产物 DTO。单产物已开始的不可中断提交也须跟踪，不能把外层 timeout 当作不存在已提交字节。

## 取消树与有界清理

普通插件任务继续归当前 owner generation，并在服务接受门禁内创建/登记 tracked 工作；直接 plugin operation、旧别名、HTTP/MCP 不可使用 owner=None 绕过卸载。服务关闭/owner detach/用户 cancel 请求同一任务取消树；到期同样 cancel 后 await 有界清理，不建立只有外层 timeout 的旁路。

获执行槽后、异步 Running 状态更新之后和 Executor 首次 poll 紧邻调用前都复核 owner.cleanup_failed、token 和 D。cancel/deadline 分支进入清理等待时不得首次 poll 启动未执行的 Future；已启动进程则保留资源守卫直到退出确认或明确标未确认。spawn 用尽剩余时间时也必须阻止首次业务帧，这与仅 spawn 前检查不同。

建议 D 已过时按 Timeout 分类，否则显式用户取消按 Cancelled；同刻以 Timeout 为诊断原因。已由用户 cancel 提交的终态仍由 CAS 保护，不被后来的到期记录覆盖。协议 3 的取消原因应反映这项选择，协议 1/2 不新增控制帧；若实际清理失败，必须另保留 CleanupFailed 风险，不能因最初原因是 timeout 就丢失未确认标记。

清理预算独立于执行 D，仍最多 2 秒；协议 3 沿用合作 1250 毫秒与终止/等待 500 毫秒，公共 tool-process 直接进程清理也遵守既有上限。给执行声明一小时不会把清理等待扩成一小时，不能以进程已杀作为外部设备/派生树已清理证据。

Future 丢弃、CleanupFailed、协议 3 ignore/failed/无有效确认必须保留粘性 unresolved 状态；另一任务成功不得清除。新任务和排队刚获执行槽任务拒绝明确 conflict，卸载保持 Draining/cleanup_failed，同 ID 重载与运行包删除拒绝。普通协议 1/2 取消并确认直接进程退出、协议 3 合作成功可以继续运行，不误标风险。

卸载复用现有串行变更与 tracker.wait 门禁；长执行取消仍应快速进入既有清理窗口，不为声明预算延长卸载的 10 秒等待。若阻塞工作尚在执行，超时返回也须维持待排空 owner、许可和目录归属；不能宣布卸载成功。历史 Job 恢复不续跑旧进程，不用持久化墙钟推算新的“剩余一小时”。

## 最小真实验收矩阵

以下是待执行门禁。测试和服务均由主代理串行统一，本轮仅写设计，不将已有设备预算测试计为普通操作已完成。

| 编号 | 层/场景 | 必须观察的结果 |
| --- | --- | --- |
| LONG-01 | 纯声明 | 旧省略/null、最小/最大值、零/负数/小数/字符串/溢出、未知版本/字段、重复/不存在 operation 精确接受或拒绝 |
| LONG-02 | 加载/安装 | native/Node 便携包保留声明；超部署上限、越命名空间或特殊贡献重复声明 invalid_input，无半发布；不运行包脚本 |
| LONG-03 | 兼容政策 | 旧协议 1/2、协议 3 和低层 None 按冻结的政策断言；区分 wire 兼容与时间语义变化，不接受任意耗时结果 |
| LONG-04 | 准入起点 | 卡住提交存储池，再放行；已耗时间扣除，过期未开执行器；创建已开始时不留下孤立 Queued，阻塞许可不提前还 |
| LONG-05 | workers 排队 | 一个任务占槽，第二个到期/取消；第二个 executor 零调用，容量随后收敛，不依靠手动取消无限等 |
| LONG-06 | 别名/父期限 | 旧别名与实际目标用同一 D/owner；父更短只收紧；没有第二 Job、第二队列或借别名增预算 |
| LONG-07 | 首 poll/spawn | 已取消/到期和 Running 更新期间到期零 execute；spawn 后业务写端 spy/duplex 证明 expired 零业务字节 |
| LONG-08 | 长执行传递 | 假执行器和传输端记录同一绝对点；Some 长预算不被旧 60 秒截短，子阶段不能重新获得预算 |
| LONG-09 | 多输入/输出 | 慢副本、执行、多个发布串联，均扣同一 D；第二项到期不启动下一 I/O；坏输入在 store/temp 前拒绝 |
| LONG-10 | 真实长进程 | 主代理独立安排协议 2/3 声明预算大于 60 秒的真实进程，真实执行越过旧 60 秒后成功；记录 elapsed、PID/响应/退出及声明，不能只用元数据代替 |
| LONG-11 | 真实短期限 | 用短声明卡住 stdin/输出/进程并超时，取消已送达且直接进程退出有证据；外层清理窗口不随长预算膨胀 |
| LONG-12 | 协议 3 | 匹配 cleaned 且等待 stdin EOF 正常；ignore/failed/错 ID/非零/输出超限/Future 丢弃保留风险；成功任务不清除旧风险 |
| LONG-13 | 未确认门禁 | 清理失败后新任务、已有排队任务、同 ID reload 与包删除均拒绝；unload 保持 Draining，不误报成功 |
| LONG-14 | 阻塞丢弃 | 请求/执行 Future 丢弃后实际阻塞工作仍占池槽和目录 lease；闭包退出后释放，不把 timeout 当硬停止 |
| LONG-15 | 提交/部分发布 | D/取消与成功资格竞争，终态仅一个胜者；已有部分产物边界可查，不谎称全事务回滚或删除既有用户产物 |
| LONG-16 | 关闭/恢复 | shutdown 与提交登记竞争无晚 spawn；长任务快速转取消/排空，历史不续跑；旧 Job 不因政策变化改写 |
| LONG-17 | 跨端回归 | HTTP/MCP 及直接插件 Job 同一预算/错误语义，已接受失败查任务；v2 关联、原字节产物和免鉴权默认保持 |
| LONG-18 | 迁出/分发 | 独立包工具真实 argv/多步骤预算及已有设备 120 秒不回退；debug、新 release/npx 分开，平台真工具/真实包另列证据 |

规则和应用竞争可用 Tokio 暂停时间与受控 Barrier，避免普遍等待一小时；进程不随 Tokio 虚拟时钟自动跳时。短期限真实传输测试证明取消/总点传播，LONG-10 才直接证明越过既有 60 秒可成功；若本轮未安排该较长真实场景，必须保留未执行边界，不能将预算展示或短模拟写成长任务实测通过。

所有门禁保留准确命令、构建模式、退出码和报告路径。协议 1/2 退出、协议 3 外部清理、派生树与真实包工具各自证据不得互相替代；生产期限不因 CI 负载临时放宽。

## 最多三项待主代理冻结选择

1. **声明载体、缺省政策与上限**：采用可选贡献字段还是版本化映射，以及旧普通贡献是否统一 60000 毫秒总预算、显式 1–3600000 的建议是否接受。推荐版本化可选声明、缺省总期限、部署可降低上限而超限加载拒绝，明确时间语义迁移；准确字段/版本与 SDK 发布由主代理冻结。
2. **起点与提交边界**：是否从异步入口等待提交存储池前计时，以及创建/成功资格/不可中断提交的线性化。推荐本文 t_admit 和资格规则，既有阻塞工作保留许可/lease/跟踪，多产物部分发布如实记录，不承诺精确时刻硬停止或批量回滚。
3. **取消分类与兼容覆盖批次**：统一到期优先诊断、终态 CAS、CleanupFailed 粘性风险，以及旧内置/独立包工具哪些操作首批纳入。推荐复用取消树和现有 2 秒清理、10 秒卸载等待，先冻结逐操作声明与真实矩阵，不把默认 context 委托当全部副作用已闭合。

冻结的是这份设计稿，不是以上公共规则。实施、完整测试、真实长进程、release/npx 和平台包工具验收均待主代理安排。
