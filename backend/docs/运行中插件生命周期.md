# 运行中服务器插件生命周期

## 架构门禁与范围

模式为 architecture-first，先以契约和行为定义驱动实现。目标是在不重启宿主的情况下，加载已部署的可信进程插件、撤销其操作并清理在途任务。沿用公开插件协议；协议 3 合作清理由独立契约扩展，不制定设备提供者或常驻设备协议。前端通信与热装卸另由前端文档约束。

影响 domain 的部署端口与公开运行视图、application 的注册和生命周期、infrastructure 的目录加载、server 的 HTTP/MCP 装配，以及生成接口、文档、分发和测试。前后端文档仍独立存放。

两条路径比较：直接修改启动器中的执行器列表无法撤销已捕获的调用与任务，且 HTTP/MCP 容易出现不同注册状态；采用应用层按插件持有注册快照、取消树和任务跟踪器，可以让所有入口共用同一生命周期。推荐后一条，不把设备或加载规则堆入通用路由。

## 文件职责

| 单元 | 职责与输入/输出 | 不承担的职责 | 副作用 |
| --- | --- | --- | --- |
| domain/plugins.rs | 部署加载端口、加载贡献、运行状态和 ID 请求类型 | 不定义平台设备 API，不依赖宿主实现 | 无 |
| application/registry.rs | 校验完整贡献、原子发布、代际快照、撤销与排空状态 | 不读取文件，不启动插件 | 受控短时锁、取消树与任务跟踪 |
| application/plugin_lifecycle.rs | 受限且串行的加载/卸载编排；已配置依赖保护 | 不知道文件路径、HTTP 或具体平台 | 调用部署端口、注册、取消和等待 |
| infrastructure/plugin_catalog.rs | 从固定部署根目录按 ID 加载有限清单和进程适配器 | 不决定注册状态，不接受业务路径 | 受限阻塞文件访问 |
| server/plugin_routes.rs 与 MCP | 可选鉴权的管理请求、生成模式、错误与日志关联 | 不处理清单或动态注册规则 | HTTP/MCP 传输 |
| server/main.rs | 注入部署目录、初始插件和受保护依赖 | 不实现加载与卸载规则 | 启动与退出装配 |
| 测试与前端生成类型 | 验证动态发现、取消、失败与代际；同步公开类型 | 不生成完整业务页面 | 独立服务/模拟插件 |

先把注册职责从 Application 的启动与执行流程中抽出，保留同步构造和既有测试接口。注册表只持有短时读写锁，模式编译与部署文件访问在受限工作池；线上请求不能阻塞 Tokio 调度线程。

## 生命周期契约

- 新插件先完整读取和校验全部贡献，再原子发布；冲突或失败不能留下半份操作，不按加载顺序覆盖。
- 每次加载拥有独立代际、取消根和任务跟踪器。提交使用捕获的注册快照，并在任务准入时确认仍为当前代际；旧验证结果不能在重载后提交。
- 卸载先撤销操作并关闭该插件的新任务，再取消排队/运行任务并等待其跟踪器。已完成任务与产物保留；取消终态不允许晚到结果覆盖。
- 排空期间保留 draining 状态，同 ID 不可重载。等待上限 10 秒，超时返回错误并保留状态，可重新请求卸载；不能声称进程已清理。
- 协议 3 增加 cleanup_failed 视图。执行器标记未确认资源后，新提交、排队获锁后和执行器首次 poll 均拒绝继续启动，返回 conflict；排队任务保留失败终态与明确原因。请求卸载时撤销操作并保留 draining，卸载返回 cleanup_failed/409，再次卸载或同 ID 重载不能绕过；清理声明的具体含义见合作取消插件协议。
- 公共工具库回接阶段，协议 1/2 的直接进程回收失败或工具 Future 被丢弃也保留未确认标记，并沿相同 cleanup_failed 准入/卸载门禁处理。正常返回且确认直接进程退出的取消/超时不标记失败，其他并行调用成功不会清除已有标记。直接进程退出仍不证明派生树、设备事务或外部连接清理；这不是协议 1/2 获得了合作清理声明。
- 客户端取消管理请求后，已接收的变更仍由宿主执行收敛；最多 2 个管理工作在途，变更串行，防止取消导致无界后台任务。
- 默认性能来源不再因固定探针而受保护。会话绑定来源当前代际，启动、worker、控制和真实数据库闭包均纳入其排空；卸载撤销新准入，并使 Running/Paused/启动中会话收口 interrupted。新代只供新会话，历史不换源；清理风险继续阻止重载。详见[性能采样插件协议](性能采样插件协议.md)。
- HTTP operations 与 MCP tools/list 读取同一注册快照。分页游标包含目录修订，列表变化后旧游标返回错误，避免跨版本分页漏项。当前无会话 MCP 不宣称支持列表变更推送。

## 公开管理入口

v2 提供 GET `/api/v2/plugins`、POST `/api/v2/plugins/{id}/load` 与 `/unload`，仅接受插件 ID，不接收服务器路径、入口或清单。成功/失败沿用日志关联包装。管理 MCP 工具使用同一应用服务；默认免鉴权，配置 APK_API_TOKEN 后使用共享令牌。

加载只读取固定部署根目录中已发布的插件目录，拒绝路径穿越、链接和超过 64 KiB 的清单。npx 安装仍负责原子部署；安装与加载分别执行，文件夹扫描不自动触发运行。

## 最低验收

先验证原子注册冲突、旧代际准入拒绝、排队/运行任务取消、卸载请求取消后的收敛及受保护依赖；再用真实 HTTP/MCP 服务在启动后部署 echo、加载、执行、卸载、重载并验证宿主进程未重启。真实独立进程取消检查插件退出与临时资源释放，不能由内存执行器替代。

完成后执行两端规定门禁、真实服务 smoke、release 运行包和 npx 验收，更新迁移与 todo。离散设备贡献已复用原生命周期，当前验收见根 todo.md；常驻会话、平台迁出、iOS、全平台热拔插和真机仍须后续实现及验证。
