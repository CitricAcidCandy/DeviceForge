## F01 原始状态与独立版本

- SDK PluginDevice 与领域 ProvidedDevice 增加 `raw_state: Option<String>`，序列化 None 时省略。浏览器 SDK v2 增加 `rawState?: string`，由 app 映射，不重复手写 HTTP DTO。
- 原文非空、非全空白、最多 **100 UTF-8 字节**且不含 Unicode 控制字符。保留原字节含义，不 trim、转小写、截断或猜测平台状态；合法未知原文接受，非法设备使整份观测失败。
- 设备声明 API1/2 的缺失或 null 归 None；非 null 原文拒绝，包括空字符串。API3 的缺失或 null 归 None，有效字符串原样接受；错误类型拒绝。
- API3 继承 API2 的能力预算，可省略/null，默认30000，显式1–120000毫秒；API1 非空预算继续拒绝。发现自身仍统一30000毫秒，不把能力预算套在发现上。
- 归一化状态仍为 online/offline/unauthorized/unknown，动作准入仍只依据归一化状态和已声明能力。raw_state 不放行 recovery、sideload、bootloader 或任意特殊模式动作。
- 设备声明版本、Manifest 顶层版本、任务传输协议1/2/3、浏览器 SDK2、HTTP v2、绑定格式1/2分别校验，不相互推导。旧宿主拒绝 API3，不宣称前向兼容。

## F02 三入口与严格业务输入

显式 refresh、直接 discover Job、显式 discovery 绑定都按真实目标快照识别发现贡献。禁止按名称后缀、平台字符串或旧别名猜测提供者。

三入口的发现业务输入严格为 `{}`。refresh 的 id/generation 是已有传输身份，不送入业务对象。输入必须先经过入口与真实目标校验，再获取发现额度、创建 Job 或清目录；额外字段、非对象、伪 device_id/generation/artifact 参数都以 invalid_input 拒绝，零 Job、零执行且旧合法目录保留。

插件发现贡献加载时要求 input_schema 为 object，模式编译成功且接受 `{}`；不满足则原子拒绝加载，无该 owner 贡献/提供者/别名残留。即使声明模式较宽，统一发现准入仍只接受空对象，不把未知参数转交工具。

每次成功准入只创建一份 Job、执行一次真实目标。Job.operation/input 保留入口原名与原输入；直接入口保留执行器的原结果格式，旧 profile 只投影同次观测。refresh 使用本 Job 的独立内存回执，不再提交包装 Job，不轮询 GET 最新目录猜自己的结果。

## F03 有界准入、锁与同一期限

- 全局同时两项发现额度，三个入口共享，溢出在 Job 创建前返回 Conflict/conflict（HTTP409）。输入/目标无效的请求不占额度。
- 同 provider ID 跨 generation 串行，使用稳定提供者键；获取串行锁前后复核 owner、generation、取消和截止点。旧代未收敛前新代不能越过它。
- 记录准入时单调时钟 D=起点+30000毫秒，覆盖受限存储池、创建、通用工作槽、串行锁、执行、副本/发布处理及目录接受；继承父截止点只能收紧，不重计时、不加业务宽限。
- 发现只占原有一次通用任务执行槽，不新增重复执行池或无界等待队列。整个准入在 active.accepting/tracker 规则内；关闭后零新准入。创建中预留也计容量，并同步持有 application/owner 排空凭据；存储创建和终态补偿不得持 active 锁。关闭立即撤销所有预留的 token/gate，但已经开始且不可撤销的创建仍可能随后形成历史 Job；创建工作负责补偿终态，零开始清目录、零执行，关闭及卸载等待创建/补偿排空后才结束，不把这类历史冒称零 Job。创建成功后重新复核当前性、取消、D和清理状态；合法运行先登记双 tracker，再释放预留，不允许交接计数归零窗口。
- 串行许可、发现额度与资源由被跟踪任务持有至本 attempt 的执行、终态存储处理、Accepted/Cancelled 裁定、阻塞排空及必要有界清理全部收敛，Future 丢弃或历史已终态都不提前释放；清理未确认保留 cleanup_failed。A 等待成功存储时，B 不得开始实际发现或清目录；接受还必须匹配当前 provider/generation/attempt 标记。
- 不新增发现动作屏障。串行锁、通用槽和 Running存储完成后，执行独立同步 begin_execution 门禁：registry write→attempt gate内复核当前性、取消、D与清理状态，通过则写入匹配provider/generation/attempt的开始标记并清旧目录，随后无await地进入执行器首次poll。门禁前的排队、坏输入、创建失败或到期拒绝不清目录。门禁通过后取消/到期仍可能在实际进程启动前发生，此时允许旧目录已清而真实工具零执行；记录“开始门禁已接受、工具未启动”，不能用清目录反推工具执行。该窗口沿取消/失败收敛，不恢复旧观测。旧finally不删除后轮合法目录。

## F04 历史成功观测与当前目录接受

采用方案1：**Job Succeeded 表示该次成功观测；当前目录是否接受由本 attempt 的发布回执决定**。先完成来源校验、完整观测和旧投影以及清理，再尝试存储成功；必须检查 transition 实际返回的 Job，只有实际 Succeeded 才有接受资格。存储失败或返回既有取消/失败时丢弃候选。

持久化与目录没有跨资源事务，允许历史已成功但目录随后因取消、到期、卸载或旧代被拒绝。历史终态与事件不改写；refresh 明确返回本次拒绝，不把后来 GET 或其他 Job 成功冒充自己的接受回执。

每个 attempt 有同步裁定门禁 `Pending / Cancelled(原因) / Accepted(本回执)`。候选在锁外预构造；接受固定取锁顺序 **registry write → attempt gate**，拿到 gate 后检查取消请求、D、当前 owner/generation/贡献和清理状态，Pending→Accepted 与目录插入之间没有 await。无任何 I/O、数据库或 active 锁操作在这些锁内。

取消只取得 attempt gate，Pending→Cancelled 后释放门禁，再触发 token、存储或其它收敛；禁止 gate→registry、持 gate 等待 I/O。用户取消、请求丢弃、父取消、shutdown、到期、owner撤销和内部失败都必须能关同一 Pending 门禁。取得 attempt 引用时先取 active，再释放 active 后裁定；接受路径不反向获取 active。

取消先赢则永不发布；接受先赢后取消不撤回本回执或已接受目录，卸载仍在 registry 锁内撤销目录。父 token 取消是请求信号，与桥接实际取得 gate 生效是两个时刻；接受时检查已取消父 token，不能把异步 watcher 描述成瞬时原子裁定。

Job 已 Succeeded、attempt 仍 Pending 时，用户 cancel **不能因 Job 已终态提前返回并跳过门禁**。attempt 的索引不能在历史终态时提前移除，需保留到发布/拒绝与清理收敛；只限原有在途容量，不新增无限回执缓存。已 Accepted 的回执由本次等待者消费，之后新的目录或卸载不会把回执内容换成其它 Job。

## F05 公开结果和拒绝

沿现有 Error 与 HTTP/MCP 转换，不增加公开回执 DTO 或新的历史终态。HTTP v2 保持 `{log_id,data}` / `{log_id,error:{code,message}}`，MCP 使用相同领域类别与已有日志元数据。

| 场景 | refresh / 准入前表达 | 已受理 direct / alias Job |
| --- | --- | --- |
| 业务输入不合法 | 400 invalid_input；无 Job | 尚未受理，不创建任务 |
| 提供者/精确目标不存在 | 404 not_found | 尚未受理，不创建任务 |
| 旧代、贡献撤销、两额度已满或停止准入 | 409 conflict；无 Job | 尚未受理，不创建任务 |
| 已准入后主动取消先赢 | 409 cancelled，或请求已断开无响应 | 沿现有取消终态；晚成功不覆盖 |
| 总期限先赢 | 504 timeout | 沿现有 Failed/timeout 表达，不新增 Timeout 终态 |
| 消息、版本、完整观测或旧投影错误 | 502 dependency_failed | Failed；不发布目录 |
| 资源清理未确认 | 409 cleanup_failed | 沿现有清理失败及 owner draining 标记，不发布目录 |
| 存储失败 | 500 storage_failed | 已有终态不改写；未形成成功不得发布 |
| 历史已 Succeeded，接受前取消/到期/卸载或旧代获胜 | 分别409 cancelled / 504 timeout / 409 conflict | 历史 Succeeded 保留，目录拒绝；不能把历史当作当前接受证明 |

执行阶段依然服从既有取消/期限优先级；接受阶段在同一门禁中先检查已有取消，再检查到期及 owner/generation。记录拒绝原因供内部回执与受控验收，生产日志只记录有限 ID/阶段/错误类别，不包含原始请求或任意插件输出。

refresh 成功交付只来自本次 Accepted 回执，即使后来 B 已发布，它也不能拿 B 代替 A。前端有效作用域与修订匹配时才返回并写入 A；被替代、卸载、取消或修订变化时沿现有 stale/cancelled 错误结束，不回滚服务端接受。不提供脱离作用域的历史回执通道；本地取消不伪造服务器日志 ID。

## F06 重启与历史

历史 Job、原文/旧数组与事件按现持久契约保留。当前目录不由历史 Succeeded 自动恢复为可动作观测，不自动发现、不把旧代重绑新代；重启后新发现取得新的 Job 与当前 generation。队列/运行历史沿现有恢复策略失败，不假装续跑旧进程。

目录 discovery_job_id 相等可关联当前观测；目录缺失不能证明过去从未接受。当前公开 API 不新增“曾接受”字段，也不持久化发布回执缓存；无法证明的历史发布经历明确不推断。验证分别观察历史、GET 当前目录与精确动作准入。

## F07 绑定格式2与有限旧数组

绑定格式1继续原样拒绝 android.devices/harmony.devices，即使通过普通 echo 间接绑定也不放行。格式2沿用64KiB、最多256条、未知字段拒绝和当前投影规则，额外增加：

- `target: {kind:"device_discovery",plugin_id}`：只解析该 owner 的 discover_operation，禁止 operation/capability 目标绕过发现边界；input 只允许 identity，业务对象仍严格 `{}`。
- `result: {kind:"device_discovery",platform}`：专用有限旧数组投影，只搭配 discovery 目标；不增加脚本、循环、递归表达式或平台命令。普通 identity 结果可用于其它显式发现别名，保留真实目标格式；新 profile 不依赖业务 JSON 外形推断宿主包装。
- android.devices/harmony.devices 必须使用 discovery 目标与专用数组 profile，platform 分别为 android/harmony。其它有限旧数组别名也要求显式 platform 经已有平台字符串规则校验且与提供者声明完全相同，不能按加载顺序猜目标。
- 使用专用数组 profile 的目标必须 API3，本次每设备都含有效 raw_state。缺失/null 整次失败、无目录；空数组是合法成功观测。其它 API3 refresh/direct 仍允许 None，不给所有插件提高强制门槛。
- 旧结果精确为 `[{id,platform,state,model}]`：id=同次 local_id，state=原文，model 缺省归 null，platform=校验后的显式配置。新目录保留完整提供者身份及同一 discovery_job_id；不给旧实体私加字段，不用 unknown/device 替换特殊原文。
- 目标未加载时旧名不可发现且提交 not_found，无内置回退。准备、注册、卸载的真实目标/别名/提供者仍共用 owner/generation 和一次原子注册更新；坏声明/模式/profile/平台一致性在发布前拒绝，无原贡献残留。

发现解码以 ExecutorResultFormat 为准：Json 只接受裸数组；PublishedArtifacts 只接受严格宿主 result/artifacts 包装，result 为数组。协议1伪包装继续拒绝，协议2/3真实包装才有资格。观察、旧投影与目录必须来自同次执行，旧结果不得重跑工具或嵌套提交。
