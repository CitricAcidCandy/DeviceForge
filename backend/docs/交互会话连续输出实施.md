# 交互会话连续输出实施

日期：2026年10月13日。此接缝支持已批准投屏直播业务，不安排性能测试或扩展与直播无关的会话底座。

## 架构门禁

模式为 architecture-first，采用 Hybrid：先冻结声明和游标语义，再验证真实字节与取消规则。选择公开声明的尾部缓存；拒绝扩大累计内存上限来模拟持续直播。旧完整历史默认保持，普通任务协议与第五版帧不变。

| 单元 | 职责 | 不负责 | 输入、输出与副作用 |
| --- | --- | --- | --- |
| plugin-sdk/session_access | 清单输出保留策略 | 进程、平台规则 | 纯序列化与枚举校验 |
| domain/interactive/definition | 版本化会话定义和策略 | 缓存、网络 | 纯声明到领域定义 |
| application/interactive/output_cache | 双端队列、字节与块数边界、过期游标 | 进程或媒体解码 | 原块到输出页；有限内存 |
| infrastructure/plugins/interactive | 声明映射和连续传输准入 | 平台协议、播放 | 有限管道队列与原期限；进程监督 |
| plugin-runtime/session | 显式连续输出模式 | 宿主缓存策略 | 有限通道、单块、取消和固定期限 |
| frontend/shared/api | 校验新策略和安全整数序号 | 投屏业务与重连决策 | HTTP 原契约到生成类型 |

## 合同

清单 `sessions.output_retention` 省略时为 `complete`，旧序列化仍省略默认；显式 `bounded_tail` 允许持续输出。所有会话贡献映射该策略，宿主不按插件名称推断能力。

完整模式仍保存最多16 MiB和65536块，超限停止并等待清理。尾部模式在同样窗口内逐块淘汰最早输出，保留真实递增序号；每块仍最多8192字节，超前游标为输入错误，早于保留窗口的游标为冲突。不能从已淘汰帧中间隐式恢复，媒体客户端须明确停止旧会话并重新打开。

运行库 `SessionOptions.continuous_output` 默认为 false；开启仅撤销累计输出限制，通道容量、单块、checked序号、原绝对期限和取消仍生效。宿主只对声明的尾部模式允许持续原字节传输，stderr仍保持诊断上限；输出总数仍校验整数溢出。单个会话最多一小时，不重新计时。

输入累计限额、EOF顺序、所有权、清理确认、记录容量和终态删除规则不变。本批不是持久化会话或跨服务重启恢复；真实投屏插件及浏览器解码分别验收。
