# 性能采样迁出最小实施裁定

状态：2026-10-10 主代理已冻结最小合同、公开类型及实施写集，进入分段实现；尚无本批构建、服务或真机通过证据。APKS 十一贡献版本的元数据已独立冻结，959 项完整测试与构建通过，其服务验收使用冻结元数据和既有二进制，不转计本批性能改动。

## 目标与最小路径

将当前 Android CPU、PSS、RSS 的实际采样迁入已有独立 `android-device` 插件。宿主保留八个 `android.performance.*` 会话操作、调度、CPU 差分与历史存储；通过当前贡献注册、设备准入和统一执行内核调用采样贡献。默认宿主不再装配 Android 工具探针，性能源允许在线加载、卸载和重新加载。

本裁定收敛 [性能动态提供者生命周期实施方案](性能动态提供者生命周期实施方案.md) 的首批路径：设备型采样源仅绑定同插件提供者，采用协议 4；旧协议 2 合成探针仍可用。跨提供者映射、协议 3 性能资格、常驻采集、真实 FPS、GPU、网络、电池以及派生进程树另行实施，不能据此缩减完整迁移目标或宣称性能模块全部完成。

依据包括 [性能采样插件协议](性能采样插件协议.md)、[性能会话接口](性能会话接口.md)、[平台适配器迁出实施](平台适配器迁出实施.md) 与当前源码。前两份接口文档目前描述启动时永久探针；本裁定完整实现后须同步改写，不能当作已经运行的合同。

## 当前缺口与必须改变的边界

| 当前事实 | 最小改变 |
| --- | --- |
| `crates/server/src/main.rs` 默认 `AndroidPerformance`，环境变量选择长期 `PluginPerformance`，选中性能插件进入 protected 集合 | 只装配通用性能服务及显式默认源 ID；生命周期验收后撤除平台探针与该 protected 项 |
| `PerformanceAccess` 只有 `sample_operation`、`fps`；基础设施只接受协议 2，并禁止整个性能插件声明产物读写 | 新增性能声明版本与同提供者能力绑定；新版本按采样贡献禁止产物，而非禁止插件其它贡献 |
| `PluginPerformance` 长持 `Arc<ProcessPlugin>`，直接执行并另计 10 秒 | 后台采样复用 Application 内核；旧 probe 仅保留兼容测试用途，不进入生产装配 |
| 会话没有来源归属；启动与 worker 未进入插件 owner tracker；暂停收口忽略两秒清理结果 | 固定来源代际，跟踪启动、worker、样本与提交，保留粘性未确认门禁 |
| 追加样本仅由存储 Running/revision CAS 决定 | 在当前注册门禁取得一次提交资格，再由会话提交序列与存储 CAS 收敛 |

`android-device` 已有 APK、APKS 输入与截图输出声明。因此不能只添加 performance 清单字段，也不能把现有 SDK 称为已经支持设备型采样。

## 公开声明、贡献与兼容

为 `PerformanceAccess` 增加 `api_version`（省略默认 1）与可选 `device_capability`，后者为严格对象 `{id,version}`。维持 `deny_unknown_fields`；旧清单原字节仍可解码，新清单要求支持该版本的新宿主，不能交给旧解码器并声称双向兼容。

```json
"performance": {
  "api_version": 2,
  "sample_operation": "performance.sample",
  "fps": false,
  "device_capability": { "id": "performance.sample", "version": 1 }
}
```

| 声明 | 接受资格与输入 |
| --- | --- |
| API 1，省略或显式 `api_version:1` | 仅协议 2；无 `device_capability`；输入仍为 `{device_id,package}`；沿用整个插件禁止产物声明的原规则。无设备引用，不宣称设备准入或互斥覆盖 |
| API 2 | 仅协议 4、设备 API 3；必须引用本插件唯一、精确的 device/read 能力 ID 与版本，其 operation 等于 `sample_operation`；固定输入封套 `{device_id,input:{package}}` |
| 未知版本、API 1 带设备绑定、API 2 缺绑定、跨插件或冲突绑定 | 装载/注册失败，贡献、来源及设备目录不得半发布 |

`android-device` 新增短贡献 `performance.sample` 与 `performance.sample@1` 能力，scope=device、access=read、`execution_timeout_ms=10000`。不重复声明普通 contribution.execution。两个 manifest 保持字节一致；完成后预计 12 个贡献、11 个能力、每设备 9 个能力，须按实际最终清单核对。

输入的顶层和 `input` 均拒绝未知字段；`package` 使用原 Android 包名规则。八个旧会话操作保持原输入、分页、间隔和时长边界，不增加 sample 别名或把 start 映射成单次采样。新贡献可由公开设备动作、直接 Job 与 MCP 调用；它们只返回原始样本的既有 result/artifacts 包装，不建立会话或追加性能历史。

API 2 可以与本插件其它贡献的产物声明共存，但需要两道真实门禁：注册校验固定采样模式及选择器不可能选择采样输入；`ProcessPlugin::invoke` 按精确采样贡献使用空有效产物权限，而非直接传全局 manifest.artifacts。复用既有私有调用目录与协议包装，采样上下文必须为 `inputs=[]`、`output_directory=null`，不要求产物存储，不授予截图输出目录。成功或失败响应出现非空 outputs 均在发布前明确拒绝；直接 Job/MCP 也经过此门禁。

## 来源选择、会话归属与历史

`APK_PERFORMANCE_PLUGIN` 保留为部署者显式配置的默认来源插件 ID；每次 start/capabilities 解析该 ID 的当前注册声明，不长期持有进程适配器，不按加载顺序、平台名称或首个在线设备推断来源，不自动回退内置 ADB。

冻结合同明确改变旧启动行为：未配置来源或配置来源暂未加载时允许宿主启动，历史 inspect/list/samples/stop 继续可用；live start/capabilities 以领域 `Error::NotFound("性能采样源不可用")` 失败，其显示为“资源不存在：性能采样源不可用”。同 ID 来源加载后，新调用可用；来源 draining 为 Conflict，已知未确认资源为 CleanupFailed。清单本身非法仍在装载时拒绝，不因空启动而放过非法声明。capabilities 保持原字段与 `source="plugin.<id>"` 表示形式，不承诺某个目标设备在线。

这里的 not_found/conflict/cleanup_failed 是领域错误分类，不新增 Job 错误 DTO。当前 `Job.error` 为字符串，前端保留真实失败文本，不解析中文制造结构化错误码；只有已有 HTTP 错误封套按其真实 code/status/log_id 消费。capabilities.source 是展示标签，不是完整当前代设备引用。

领域新增来源定义与不可变会话来源引用。`Executor::performance_source()` 默认 None，由 ProcessPlugin 映射公开声明；注册层原子发布/撤销来源与贡献。会话的可选 `source` 保存 `{plugin_id,generation,operation,device?}`；operation 为实际完整贡献 ID，设备型引用使用既有 `DeviceRef{provider_id,generation,local_id}`。能力 ID、版本和声明快照保留在运行绑定中，不用插件 version 代替 generation。

设备型源把旧 target.device_id 解释为该显式来源提供者的 local_id，不扩大旧 ASCII 输入资格；来源 owner 与 provider owner 必须同一插件、同一代。开始时和每次采样准入复核当前设备在线、精确能力版本与当前代。旧协议 2 来源只保存源归属，device 缺省，不能伪造设备身份。

start 保留原输入，因此不携带客户端期望的 source/device generation。浏览器目录预检后发生同 ID 重载，start 可绑定执行时的新代；返回的会话 source 才是权威。前端可与选中引用对照并呈现真实归属，不能宣称请求具有代际 CAS 保证，也不添加未知字段。本批仅保证创建后的归属不可变；若要求创建时绑定客户端指定代，须另冻结请求合同。

`PerformanceSession.source` 默认 None 并在 None 时省略；SQLite 现有会话 JSON 体可兼容旧记录，不强制新表列，不为旧记录反填当前源。恢复继续把旧 Running/Paused 标为 Interrupted；来源是否在线不影响历史读取。相同 ID 重载只供新会话使用，旧会话不得 resume 到新代；旧终态与历史来源保持原值。

## 可执行类型与领域端口签名

下面的名称和字段为首批冻结值，不把“来源语义”留到实现时另造 DTO。SDK 与领域分别定义自己的绑定类型，通过基础设施映射，不让 domain/application 依赖 SDK。

```rust
// plugin-sdk：保持严格 serde 解码；api_version 缺省为 1，序列化 API 1 时省略。
pub struct PerformanceDeviceCapability {
    pub id: String,
    pub version: u32,
}
pub struct PerformanceAccess {
    pub api_version: u32,
    pub sample_operation: String,
    pub fps: bool,
    pub device_capability: Option<PerformanceDeviceCapability>,
}

// domain::performance：operation 已映射为完整注册 ID。
pub struct PerformanceDeviceCapability {
    pub id: String,
    pub version: u32,
}
pub struct PerformanceSourceDefinition {
    pub api_version: u32,
    pub operation: String,
    pub fps: bool,
    pub device_capability: Option<PerformanceDeviceCapability>,
}
pub struct PerformanceSourceRef {
    pub plugin_id: String,
    pub generation: String,
    pub operation: String,
    pub device: Option<crate::devices::DeviceRef>,
}

// domain::Executor 的新增默认方法；原执行上下文签名不变。
fn performance_source(&self) -> Option<performance::PerformanceSourceDefinition> {
    None
}

```

以上可选 SDK 字段采用 default/skip_serializing_if；PerformanceAccess 的 api_version 用独立默认值 1，并在序列化值为 1 时省略，以保留旧 API 1 声明外形。fps 维持原 default，不因新增版本改变原字段含义。来源定义/引用和绑定派生 Clone、Debug，引用再派生 Serialize/Deserialize/JsonSchema 并拒绝未知字段；source.device 默认 None 且序列化时省略 None，DeviceRef 直接复用已有领域类型。SDK manifest 省略 api_version 解码为 API 1，新设备清单显式写 2；公开浏览器 HostContext 的 apiVersion 与此无关。

在既有 PerformanceSession 结构体内增加下面字段，除此之外的现有字段保持：

```rust
#[serde(default, skip_serializing_if = "Option::is_none")]
pub source: Option<PerformanceSourceRef>,
```

PerformanceStore 的 `create(session: PerformanceSession) -> Result<()>`、`append(id: &str, revision: u64, raw: RawPerformance) -> Result<bool>` 和其余现有签名保持不变；存储 CAS 与来源提交资格是不同门禁。原通用 PerformanceProbe 端口可保留测试替身，不新增平台方法；生产服务不接受永久 ProcessPlugin probe。通用样本解码使用领域 RawPerformance，声明 FPS 与墙钟窗口由通用应用规则校验，不增加 SDK 到 Application 的依赖。

新设备会话的公开字段形状如下；API 1 的 device 省略，旧记录的整个 source 省略。字段加入 OpenAPI 生成与前端类型，不能只改 SQLite 实体而让公开 schema 缺失。生成验收同时核对 PerformanceSession、PerformancePage.session 与 PerformanceSessions.sessions 三处；可选字段是否具有 null 联合以实际生成 schema 为准，前端不手写替代 DTO，不用当前目录反填缺省来源。

```json
"source": {
  "plugin_id": "android-device",
  "generation": "当前加载代际",
  "operation": "plugin.android-device.performance.sample",
  "device": {
    "provider_id": "android-device",
    "generation": "同一加载代际",
    "local_id": "emulator-5554"
  }
}
```

应用内部来源访问句柄、绑定快照与提交资格不对插件/HTTP 公开。它们必须携带注册快照、owner、原始单调期限和清理状态，具体私有 Rust 方法由主代理按现内核收敛；不得借此新增公开请求字段、跨 owner 依赖或另一套设备准入。

## 准入、统一期限与设备屏障

应用层向性能服务提供一次绑定的轻量 `Weak<Application>` 访问句柄，负责当前来源查询与内部采样执行；禁止 `Application → PerformanceService → Arc<Application>` 强引用环。创建服务后、对外提供请求前完成绑定，重复绑定或宿主不可用明确失败。领域不携带 Application、tracker、设备锁或 SDK 类型。

开始任务使用原任务取消与截止点，来源门禁中原子登记启动工作及 owner 跟踪资格，再进行落库和 worker 装配。装配成功后使用独立会话取消树，连接 owner 撤销和服务退出；不能让已结束 start Job 的令牌管理后续会话。启动 Future 丢弃、取消、到期或 panic 都必须有受跟踪的收口，不能留下只有数据库记录或无 owner 的后台 worker。

首批保留默认 4 个会话、可配置 1–32、Paused 占名额、存储 4 槽、每会话最多 3600 项；另设后台采样有界槽，名额等于已配置 max_sessions。每会话最多一个在途样本，错过周期直接跳过，不补采；后台 worker 不占普通 Job worker，不提交嵌套 Job。直接采样 Job 仍走普通 Job 容量与执行内核。

会话单调截止点在来源准入并创建会话时固定，与 started_at 同次记录；创建/装配、运行和暂停均消耗 duration_secs，不能在 worker 启动或恢复时重计。每个 tick 从进入内部采样准入开始固定：

`D = min(tick 准入时刻 + 10 秒，会话截止点，实际能力预算截止点)`。

同一 D 覆盖采样槽等待、provider 屏障等待、当前代/在线/模式复核、输入准备、协议握手、配置、五次工具调用、解码及提交资格等待。通过 `execute_with_context` 与协议 4 本地截止点传播，不再套独立续期的 10 秒探针。首 poll 前已取消/到期时 executor 调用数为零；观察到截止点已过优先 Timeout，否则取消为 Cancelled，不靠 select 偶然顺序决定同刻结果。会话到期仍按原规则 Completed，正常退出/来源撤销为 Interrupted，终态由同一提交序列和 revision CAS 决定。

当前设备锁仅在 device/write 时取得 `(provider_id,local_id)` 设备 Mutex；device/read 使用 provider 读屏障，会与 provider/write 互斥，但**不与同设备 device/write 互斥**。本批真实 CPU/内存采样声明 read 并复用该现有边界，不增加全设备读写锁，不宣称安装与采样互斥。纯读取与安装同时发生可能导致进程消失或 PID 重用，须由既有取样一致性校验失败，不能把失败转成有效零样本。

会话空闲、Paused、历史与控制操作不持设备屏障。样本守卫覆盖实际执行/清理确认；发现未确认资源先设置源风险门禁再释放物理守卫，排队采样与普通任务必须复核风险后才可执行。设备动态离线使本次准入失败；provider/source 同代撤销则触发会话 Interrupted，不选择其它设备或新代。

## 暂停、卸载、清理与提交排序

| 事件 | 首批固定行为 |
| --- | --- |
| pause | 持久化原 Paused/revision，取消在途样本，清除 CPU 基线；控制响应不表示资源已排空 |
| resume | 原来源及设备代际仍当前、期限未过且上次样本真实排空才恢复；仍在收口返回 conflict，已知未确认资源返回 cleanup_failed；恢复首样本无旧 CPU 差分 |
| stop | 保留 Stopped 与旧终态幂等规则，撤销新采样并收口；晚结果不得覆盖终态 |
| owner detach | 同一注册写锁撤销来源/贡献/目录，置 draining、关闭 tracker、取消 owner；Running/Paused/启动中会话均受影响，非终态转 Interrupted |
| owner finish | 启动、worker、在途样本、控制提交与已获资格的存储闭包真实排空后，才可删除 owner；复用现管理等待上限 10 秒 |
| 重载 | draining 或 cleanup_failed 时拒绝同 ID 重载；确认排空后的新加载获得新 generation，只供新会话使用 |

首次观察取消/到期后使用既有最多两秒独立清理窗口，取消后不继续业务、不重开窗口。现代码忽略两秒等待结果的行为必须撤除。协议 4 继续采用公共合作取消、响应关联、零退出与明确 cleaned 确认；协议 2 仅保持原直接进程确认，不能升级描述为派生树、设备事务或共享 daemon 已释放。

在途执行/文件工作未排空、panic 后无法确认资源或协议 cleanup failed 时，owner 保留粘性风险；风险与 executor.has_unresolved_resources 合并用于 PluginInfo.cleanup_failed、finish、采样、普通提交/排队执行及 resume 门禁。必要时为 Owner 增加应用层未确认标记，不能只写 session.error 或让单个 worker 局部失败后继续采样。已提交的控制/终态不被清理错误覆盖；风险从插件管理状态及固定会话错误观察，不在本批增加控制回执 DTO。

慢 SQLite 闭包仍执行、卸载十秒等待耗尽或仅任务仍在收口，保留 draining 与 tracker，不凭这些事实直接推断外部资源清理失败。阻塞池许可必须随实际闭包存活；丢弃外层 await 不表示数据库停写或名额已释放。卸载成功返回前必须真正排空，不扩大等待预算。

成功样本进入会话有界提交序列，与 pause/resume/stop/完成/中断排序。序列中再次核对 Running、revision、来源/设备当前代及 D；利用注册层 `with_current(registered, claim)` 在短读锁内取得一次提交资格，claim 只做内存登记，不执行 I/O、await 或阻塞存储。资格和实际 append 闭包归 owner 排空。

提交资格是撤销与成功提交的先后点：detach 后不能获新资格；撤销前已获资格的写入可在卸载等待中收敛。存储 Running/revision CAS 继续拒绝控制/终态之后的晚样本；新代不得接管旧样本。全局注册锁不跨数据库等待。截止点后不发新资格、不启动下一 I/O；已经运行的阻塞提交允许晚结束并被跟踪，不能承诺硬停止或把该规则写成撤销瞬间禁止一切既准入提交。

## 真实 Android 采样与数值规则

采样复用插件部署者配置的 ADB、Restricted 环境、公开 InvocationContext、工具租约、两流各 1 MiB 上限及已有 Session 收口，不读取宿主 APK_ADB，不要求 Java/JAR，不接收程序路径或自由 shell。固定顺序执行以下独立 argv；所有命令共用原 D，不按命令重计十秒：

1. `-s <serial> shell -T pidof -s <package>`。
2. `-s <serial> shell -T cat /proc/<pid>/stat`，取得进程启动计数。
3. `-s <serial> shell -T dumpsys meminfo -s <pid>`。
4. 再读同一 `/proc/<pid>/stat`，确认进程未被相同 PID 替换并取得累计 ticks。
5. `-s <serial> shell -T cat /proc/stat`，取得系统累计计数与逻辑核数。

保留旧失败子串 `permission denied`、`permission denial`、`no such file`、`error:`、`exception`、`not found`、`device offline`、`unauthorized`；非零退出、输出超限、取消/到期或无法确认清理均失败。业务错误使用固定中文，不回传工具路径、任意诊断或完整目标。不能因旧 Electron 使用常驻 shell、top、grep 或 IPC，就把这些旧形态作为新的采样合同。

解析迁入插件纯规则模块，保留以下真实边界：唯一非零 u32 PID；stat 按最后 `) ` 定位含括号的进程名，核对 PID、累计 utime+stime 和 starttime；system 最多十个计数字段、累计前八项且不重复计算 guest，核编号唯一且数量 1–4096；meminfo 必须匹配目标 PID、TOTAL PSS 必有、RSS 可缺省，多种汇总出现时数值一致。整数累计须检查溢出，解析失败不产生样本。

采完后取得 captured_at，返回既有 PerformanceSample 字段；本插件 `fps=false`、frame_window 缺省。通用宿主解包已声明的结果封套，再按领域 RawPerformance 与声明校验计数、FPS 资格和 captured_at 前 60 秒/后 5 秒范围；不在 Application 导入公开 SDK 或重新猜 result 外形。CPU 差分仍由宿主存储计算，仅同 PID、同 start_ticks、同核数相邻样本有效，首样本与恢复基线不填 CPU 百分比。

旧 perfmon 仅提供浮点 fps，没有可靠实际帧数及观测窗口；不得用 interval 或 fps 反推 FrameWindow，也不得给缺失观测填零。本批保持 CPU/PSS/RSS 实际迁出，真实 FPS 作为明确剩余业务。

## 已冻结的最小决定

1. 接受 API 1=协议 2 兼容、API 2=协议 4/设备 API 3 同提供者 device/read；API 2 与其它贡献产物共存，但采样无输入/输出授权。
2. 保留显式默认源环境变量，接受无源/暂未加载源允许启动、live 真实失败及不回退 Android 的行为变化。
3. 接受可选不可变会话 source、旧 JSON 不反填、原设备 read 锁范围、原始单样本/会话截止点与一次提交资格排序。
4. 接受 owner 跟踪与风险合并、暂停未排空拒 resume、原两秒清理与十秒卸载等待；生命周期完成并验收后才撤永久探针/protected。

上述四项最小决定及公开类型已由主代理冻结；应用内部方法按现有执行内核分段落地，不改变本文的输入、归属、期限和提交排序。本文不构成本批实现或门禁通过结论，实际结果按对应源码与报告登记。
