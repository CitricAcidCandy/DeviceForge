# 服务器插件生命周期、期限与清理

安装、加载、执行、卸载、部署删除是不同动作。完整功能以 `release.json` 统一管理，新安装满足必填 requirements 后默认启用，缺输入则 `configuration_required` 并停用；更新保留原启用意图。发布 `enabled` 持久化，宿主重启按该意图恢复，但恢复受阻和清理未确认时不能强行加载。浏览器实例的真实激活状态仍需客户端另行确认。

统一安装写操作进入 `installation.install/update/enabled/uninstall/cleanup` 任务，HTTP/MCP 共用用例；接受返回不等于完成。更新、启停、卸载携带真实 `expected_revision`（原始发布清单 SHA-256），冲突先刷新，不能自动覆盖。关闭面板或取消等待不回滚服务端管理工作。

## 加载与卸载

统一发布所属组件由统一启停用例装卸，旧组件级 load/unload/包删除入口不能绕过所属关系。旧独立部署仍兼容 `APK_PLUGIN_DIR` 与插件 ID 子目录的 `manifest.json`；可用 HTTP `POST /api/v2/plugins/{id}/load` 或 MCP `deviceforge.load_plugin`，只传插件 ID。宿主验证清单和输入模式，再原子发布贡献；前端、HTTP 和 MCP 从当前注册目录发现操作。

卸载可用 `POST /api/v2/plugins/{id}/unload` 或 MCP `deviceforge.unload_plugin`。先撤销新调用，再取消并等待排队和执行中的任务/会话收敛。历史任务与产物保留，同 ID 重载获得新代际，旧引用不能静默绑定新实例。受保护插件拒绝卸载。

若资源清理未确认，保留 `draining` 和 `cleanup_failed`，拒绝同 ID 重载与部署删除。客户端取消等待不会自动撤销已开始的管理工作，应查询当前目录。不要用删除包文件、替换 ID 或直接杀进程掩盖未确认状态。

## 任务执行和期限

每个任务启动一个独立进程；不要启动脱离本次生命周期的后台子进程。请求、标准输出/错误、队列、工作池及结构数据都有界。普通操作可声明 `execution:{"api_version":1,"total_timeout_ms":60000}`，范围为 1–3600000 毫秒；省略时使用宿主固定默认预算。设备能力按自己的公开契约确定预算，不重复声明普通操作预算。

总截止点覆盖排队、设备锁、输入副本准备、工具执行和发布；各阶段传递原截止点，不能收到请求后重启完整计时。清理窗口独立于业务期限，不以延长业务预算方式隐藏清理。

协议 1/2 兼容直接子进程终止，只适合没有需要确认释放的外部资源的短任务。需要外部资源的任务使用协议 3/4；协议 4 还将固定截止点交给处理器。协议 3/4 的宿主合作清理窗口为 1250 毫秒，插件应及早响应取消，取消后释放实际资源并等待相关工作退出。

## 资源所有权

对连接、临时文件、设备上启动的进程、转发、监听器与派生工具分别登记归属。只清理自己创建且身份匹配的资源；同名路径或历史 PID 不足以证明归属。停止请求成功、直接子进程退出、传输 EOF 或 Future 被丢弃都不等于外部资源已释放。

只有响应版本/请求 ID 匹配、进程零退出和明确 `cleanup=complete` 全部成立，宿主才确认合作清理。清理失败返回 `failed`，缺少确认保留未确认风险；晚到结果不得覆盖已有终态。业务处理器必须真实等待清理完成后返回，不后台继续清理再提前报告完成。

## 交互会话

协议 5 的进程承载一份会话，持续输入和输出有总量、单块、序号与期限限制。空字节数组仍是数据，只有 EOF 关闭输入。取消或输出失败撤销新 I/O 后继续等待处理器真实 `Execution`，会话终态仍明确报告清理结果；不能把断连当作成功清理。会话贡献与普通操作同样纳入插件代际、卸载与新调用门禁。
