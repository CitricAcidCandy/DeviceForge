# 插件开发

## 服务器扩展
插件通过独立进程和 JSON 协议接入，可使用 Rust、Python、Go 等语言。宿主只引用公开协议 SDK；插件不直接访问宿主类型、数据库或 HTTP 路由。独立进程是故障边界，不是操作系统沙箱。

设备提供者通过可选 Manifest.devices 显式贡献发现与版本化能力，公开离散设备第一阶段已实现并完成本机集成；契约见 [设备提供者第一阶段实施](../implementation/设备提供者第一阶段实施.md)。平台工具迁出、常驻会话与真机仍按 [设备适配器插件架构](../implementation/设备适配器插件架构.md) 推进，注册一个枚举操作不能替代完整提供者声明。

部署目录由 `APK_PLUGIN_DIR` 指定，各插件 ID 子目录包含不超过 64 KiB 的 `manifest.json`，目录名必须与清单 ID 一致，目录及清单不得为链接。清单参数为 `id/version/protocol_version/executable/args/operations`，支持协议 1、2 和 3；入口必须为存在的绝对文件路径。贡献操作使用 `name/title/input_schema`，输入模式必须为对象。公开 ID 为 `plugin.<插件ID>.<操作名>`，必须兼容 MCP 名称，不超过 128 字符；`deviceforge.*` 为宿主保留空间。

注册时编译输入验证器，执行前校验输入。禁止外部模式引用与 `$id`。重复操作、无效模式或不兼容协议拒绝启动，防止启动后才发现贡献不可调用。

## 执行协议
每次操作启动一个插件进程。协议 1/2 标准输入发送一份请求 JSON 后关闭；协议 3 第一行发送请求后保持输入流，以取消控制帧通知资源清理。请求包含 `protocol_version/request_id/operation/input`。协议 1/2 标准输出仅包含一份响应 JSON：同版本、同请求 ID，且只提供 `result` 或非空字符串 `error` 之一。显式 `result:null` 是有效结果，字段缺失才表示无结果。日志使用标准错误。

协议 1/2 默认超时 60 秒，标准输出和标准错误各限制 1 MiB。插件环境只保留部署运行所需的路径和系统目录，不继承服务访问令牌。取消和超时终止直接子进程。Windows 后台派生进程树尚未提供完整作业对象约束，插件不得自行创建后台进程。

协议 3 总期限 1 小时，取消后提供 1250 ms 合作清理窗口，再进行直接进程终止兜底；响应为 CooperativeResponse，只有同版本/请求 ID、零退出与 cleanup=complete 全部成立才确认清理。无确认或清理失败保留本次 unresolved/cleanup_failed 诊断，不得永久封锁全插件；draining 只反映真实在途排空，排空后可重载，旧诊断继续保留。后台恢复与独立新调用分离，现行硬约束见[资源故障隔离与后台回收裁定](../implementation/资源故障隔离与后台回收裁定.md)。公开异步运行库与详细协议见 [合作取消插件协议](../contracts/合作取消插件协议.md)，示例为 plugins/cooperative-demo；不能用此示例宣称 Frida 或常驻设备会话迁移完成。

## 最小示例
设备声明 API 1 继续兼容，API 2 的每项能力可声明 execution_timeout_ms，省略或 null 默认 30000 毫秒，显式值为 1–120000 毫秒。宿主在准入时确定截止点，排队、锁、产物准备、进程和发布共享预算；此时传输的 60 秒/1 小时默认值不再截短或重计时。发现固定 30 秒，刷新子任务继承原截止点。业务请求不能覆盖预算，清理窗口独立。普通非设备插件保留原阶段期限。

参考 `plugins/echo/README.md`。执行 `cargo build -p deviceforge-echo-plugin`，将示例清单复制至部署目录并填写实际绝对路径。启动时自动加载；运行中部署后调用 `POST /api/v2/plugins/echo/load`，`operations` 和 MCP `tools/list` 均应出现 `plugin.echo.echo`。通过 `POST /api/v2/jobs` 或 MCP 同名工具提交输入；查询任务最终结果。

## 生命周期与拓展路线
通用进程插件支持启动时加载及运行中显式加载/卸载/重载，插件执行仍按请求创建进程。npx 安装器支持便携目录、tgz 及 npm 包依赖布局，安装负责原子部署，加载通过 HTTP/MCP 单独执行；默认免鉴权，非空令牌可选，详见 [运行中插件生命周期](运行中插件生命周期.md) 与 [命令行部署与插件安装](命令行部署与插件安装.md)。卸载停止新调用、取消并等待排队/运行任务；历史任务和产物保留，重载生成新代际。性能来源支持同 ID 热装卸，活动会话随原 owner 收口，旧历史不替换来源。

宿主贡献依赖协商、常驻插件会话、事件贡献和跨插件调用尚待实现。产物读写能力已通过协议版本 2/3 接入，当前新增 input_pointers 以支持设备封套中的嵌套 ID，详见 [插件产物协议](../contracts/插件产物协议.md) 与 [本轮实施](../implementation/插件嵌套输入产物实施.md)；能力声明不是操作系统沙箱。计划分别采用版本化端口扩展，禁止插件自行拼装宿主路由。浏览器扩展契约单独见前端目录的插件开发文档。

协议版本 2 的产物复制示例见 plugins/artifact-copy/README.md。协议版本 1 继续支持；版本 2 的任务结果固定包装为 result + artifacts，使用新协议的客户端需读取该结构。

性能采样 API 1 使用协议 2，API 2 使用协议 4 并绑定同插件设备 API 3 的精确 device/read 能力。部署者使用 APK_PERFORMANCE_PLUGIN 显式选择默认来源；缺省或暂未加载不阻止宿主启动，实时采样明确失败且不回退平台工具。公开类型与流程见[性能采样插件协议](../contracts/性能采样插件协议.md)。它复用宿主会话，但每次采样仍启动独立进程，常驻插件协议尚未实现。

标准 MessagePack 编解码与分页查询插件见 plugins/msgpack/README.md 和 MessagePack插件接口.md。生产依赖只使用公开 SDK 与公共编解码库，宿主内部类型仅用于集成测试。旧 DLL 私有格式兼容尚未证明。
