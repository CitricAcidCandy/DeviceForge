# 插件脚本与录像产物接缝

日期：2026年10月12日。主代理负责本通用接缝；测试角色只修改独立Frida驱动，前端与SDK研发继续所属私有模块。

## 实际问题与边界

Frida真实前端首轮`artifacts/frida-consumption-service-debug-3973e971-10a2-4acd-8d51-36dda9e5dbce/report.json`在已完成动态六贡献发现后，上传`frida-server.bin`实际返回400/invalid_input。宿主正常exit0，失败原件保留。当前通用上传仅接受归档、图片、JSON、MessagePack与DEX，输入副本白名单也缺少bin/js；Frida输出的log/js/jsonl与投屏的mp4同样没有通用媒体映射。

这是业务接缝缺失。不得把输入改名为ZIP/JSON绕过格式门禁，也不能用插件协议层成功冒充完整HTTP业务完成。既有Frida/投屏门面、业务规则与公开DTO保持，通用宿主不增加Frida或scrcpy命令分支。

## 最小通用资格裁定

| 后缀 | 媒体类型 | 最低资格与上限 |
| --- | --- | --- |
| bin | application/octet-stream | 非空原字节，最多64 MiB；内容不是可执行资格证明，业务插件继续检查实际工具执行结果。 |
| js | text/javascript | 非空合法UTF-8、拒绝空字节，最多64 MiB；不证明JavaScript语法或实际运行。 |
| log | text/plain | 最多64 MiB，可为空，保留原工具字节；不强制假设工具日志编码，也不作为服务器日志内容自动写入。 |
| jsonl | application/x-ndjson | 合法UTF-8及逐行JSON最低资格，允许空通知文件；总量最多64 MiB，单行沿公共编解码16 MiB限额。 |
| mp4 | video/mp4 | 与现有录像插件保持最低12字节ftyp及首段声明大小资格，最多128 MiB；不宣称完整容器、H264解码或播放成功。 |

部署总量上限仍可更低，格式限额不能被部署设置提高。上传与插件输出使用同一内容检查；验证进入已有受限阻塞工作池，文本流式检查处理跨块UTF-8，不能无限读取或把工作移入异步调度线程。授权输入副本仅增bin/js，继续原SHA-256、总量、路径、取消、截止点与临时资源释放规则。

公开上传/下载与元数据结构不变；前端生成类型仍由主代理同步。最低内容资格、插件业务校验、真实工具、实际设备与完整内容验证分别记录，不能互相替代。
