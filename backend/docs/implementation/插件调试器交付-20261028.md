# 插件调试器首期后端增量

日期：2026-10-28。范围为后端调试器独占目录；不是生产通过证明。公共装配、生成类型、完整安装和投屏内部不由本批修改。

## 本批行为

- 会话因目标换代进入 `target_changed` 后，可以在原闲置期限内显式重新选择当前目标。重新激活仍受活动会话容量限制；已关闭、过期或断线的会话不会重新打开。重新激活会移除旧历史淘汰索引。
- 显式选择其他目标撤销旧命令。旧代回执保留原终态，不写入新目标，不自动重放。
- 浏览器重载只有已派发的本次重载能跨越卸载／加载心跳间隙。成功回执必须声明同插件的新代次；其他旧代命令撤销。是否跟随由调用者显式选择，并等待真实目录登记该新代次。
- 服务器 operation 试调用直接捕获注册表内的真实贡献和提供者代次，使用原输入校验、设备准入、存储工作池与 Job。不会根据名称前缀猜归属，也不会检查后再重新查找可能已换代的贡献。
- 报告等待真实浏览器回执，或读取真实服务器贡献目录；可选持久日志必须经注入端口查询。只把递归脱敏后的有界证据写入原 `ArtifactStore`。
- 所有等待有界。结果未确认时不自动重试；停止等待不等于原 Job 或原生命周期后台工作停止。

## 工具输入合同

### `deviceforge.debug_events`

旧输入保持兼容：

```json
{"session_id":"会话UUID","after":0,"limit":200}
```

也可明确 `source:"lifecycle"`。它仍为内存事件、升序序号和原 `next_after`，不表示持久业务日志。

持久日志输入：

```json
{
  "source":"logs",
  "plugin_id":"example",
  "generation":"当前代次",
  "log_id":"可选UUID",
  "job_id":"可选UUID",
  "session_id":"可选UUID",
  "q":"可选关键词",
  "order":"desc",
  "cursor":"上一页返回的不透明游标",
  "limit":100
}
```

`plugin_id` 必填；其余关联与代次均可省略。排序默认 `desc`，页大小为 1 至 100，关键词最多 128 字节，游标最多 2048 字节。省略代次表示查询该插件跨代日志，不能擅自补当前代次。

返回 `{source:"logs",entries,next_cursor,limited,coverage}`。全部筛选、排序和分页必须由持久日志端口执行；不能先取旧百条再排序，也不能在前端筛出“完整结果”。覆盖范围、缺失关联、保留期限与扫描截断必须保留。

未注入端口返回 `debugger_diagnostics_unavailable`；等待最多 2.5 秒，到期返回 `debugger_diagnostics_timeout`。原公共日志 API 仍只有日志 ID／关键词和排序；2026-10-28 用户追加授权后，本批新增独立持久日志分页模块，不修改原 `search_logs` 查询逻辑。

### `deviceforge.debug_invoke`

外围为 `{session_id,parameters}`。服务器 service 保留原参数，要求 `kind:"service"`、`id`、精确 `version`、`input`、`confirmed:true` 与 `allow_unknown_side_effects:true`。

服务器 operation 参数：

```json
{"kind":"operation","id":"plugin.example.echo","input":{},"confirmed":true,"allow_unknown_side_effects":true}
```

operation 不接受 service 的 `version` 字段。目标和代次取自所选会话，真实注册归属必须一致。成功只返回原 Job 身份与状态，不复制原输入或任意插件输出；通过原任务入口查询和取消。

### `deviceforge.debug_reload`

```json
{"session_id":"会话UUID","parameters":{"confirmed":true,"follow":false,"timeout_ms":30000}}
```

`follow` 默认 false，期限为 100 至 30000 毫秒，默认 30000 毫秒。浏览器会把 `follow` 和宿主期限留在宿主侧，只向原本地重载实现传 `{confirmed:true}`。跟随等待共用原截止点，不重启预算。读取仍为 5 秒，其他动作仍为 10 秒；重载使用独立 `reload_timeout`，排队不重启预算。

前端同步要求：gateway 对 reload 的 `remaining_ms` 上限改为 30000；bridge 不再把该命令截断为 10000。浏览器执行等待须绑定原调用方与宿主生命周期，不能被正常卸载导致的旧选择作用域撤销打断。完整 feature 重载仍由原共同安装目录及 `retryBrowser` 用例处理，不拆成独立组件安装。本批不修改前端或共同安装实现。

服务器通过 `DebuggerPorts.reload_expected` 转发原 `Arc<PluginService>`、插件 ID 和捕获的旧代次。适配器必须在原服务的同一次串行管理工作内校验代次、保留托管／保护／依赖规则、调用原排空卸载并加载。未注入返回 `debugger_reload_unavailable`，不分开执行存在竞态的公开 unload/load。等待到期返回 `timed_out_unconfirmed`，随后应重新查询目标。

### `deviceforge.debug_report`

```json
{"session_id":"会话UUID","parameters":{"export":"json","logs":{"q":"失败","limit":100,"order":"desc"}}}
```

`export` 可为 `none`、`json` 或 `markdown`，默认 `none`。`logs` 可省略；允许 `log_id/job_id/q/order/cursor/limit`，插件与代次固定取自本次所选目标。未请求日志会明确返回未包含说明，不伪造空日志成功。

返回 `{report,artifact}`，不导出时 `artifact:null`。导出含 `format`、原产物 `metadata` 和 `/api/v2/artifacts/{id}/content` 下载地址。JSON 写 `.json`；本轮公共产物适配器已补充 `.md`／`.markdown` 与 `text/markdown`，报告直接下载为 `.md`，复用普通文本的有界存储与附件下载。对应专项及真实联调结果由主代理最终登记。

浏览器报告未成功确认、会话已关闭或目标已改变时拒绝导出。报告生成总等待最多 15 秒，结构沿用 1 MiB 调试结果预算，格式化产物最多 2 MiB；超时可能已有产物提交，不自动重试。

`debug_report` 工具可能写入产物，MCP 注解固定 `read_only:false`。这是一项保守注解；默认读取并不写文件。注解不是按参数动态变化的权限机制。

报告保留原覆盖范围和缺口；会话事件可能包含之前选择的代次，单独标记，不把整段会话历史说成当前代证据。递归脱敏匹配已知凭据、签名材料、令牌、密码、私钥等字段名，替换为 `[已脱敏]`，保留数组和范围信息。不保证识别自由文本、自定义字段名及任意业务值中的所有秘密。

## 主代理接线需求

代码已保留原五参数 `tools::invoke`；它使用空端口，旧调用可继续编译。完整接线应在 `server/debugger/mod.rs` 重新导出并使用 `invoke_with_ports`、`DebuggerPorts`、日志端口相关类型和 `ReloadExpected`。HTTP 与 MCP 必须传入相同服务实例。

```rust
// 仅示意参数关系，生命周期方法须由原服务所属文件实现。
DebuggerPorts {
    diagnostics: Some(&diagnostics),
    artifacts: Some(artifacts.as_ref()),
    reload_expected: Some(&reload_expected),
}
```

日志端口为 `DebuggerDiagnostics: Send + Sync`，已提供 `tools::PersistentDiagnostics(pub LogMetrics)` 真实适配器：

```rust
fn query(&self, query: DiagnosticQuery)
    -> BoxFuture<'_, Result<DiagnosticPage, ApiError>>;
```

`DiagnosticQuery` 的公开字段与 `source:"logs"` 参数一致，但不含 `source`。`DiagnosticPage` 为 `entries:Vec<Value>`、`next_cursor:Option<String>`、`limited:bool`、`coverage:Value`。默认倒序枚举由端口负责；游标须绑定查询和排序，在真实日志范围内分页。同步文件工作只允许放在已有日志服务的受限工作池，查询 Future 被丢弃后后台工作也必须遵守原绝对期限。

产物来源为 `ApiState.artifacts`；`Application` 没有 `artifacts()`。日志来源为 `RuntimeServices.logging`；HTTP/MCP 每次调用可临时创建 `PersistentDiagnostics(logging.clone())`，克隆共享原目录、两工作槽及新增有界游标缓存，无需另一份全局状态。生成合同仍由主代理统一更新。

生命周期回调类型为：

```rust
dyn Fn(Arc<PluginService>, String, String)
    -> BoxFuture<'static, apk_domain::Result<PluginInfo>> + Send + Sync
```

主代理需在原 `application/src/plugin_lifecycle.rs` 增加 `reload_expected(id,generation)` 或等价的原子用例，回调只转发该用例。当前调试器不会绕过托管发布边界，也不会新建执行器或安装体系。原服务方法及公共接线不在本批独占写集中。

主代理后续已报告实现原服务 `reload_expected` 与 HTTP/MCP 集成文件；该结果由主代理验证，本批不替其宣称验收通过。

## 持久日志分页的追加实现

新增 `observability/src/query/debugger.rs` 及其子模块；原 `query.rs` 仅登记子模块并给原 `LogReader` 增加共享游标缓存，原 `search_logs`、过滤、扫描和返回结构保持原样。`lib.rs` 只追加公开类型导出。

- `LogMetrics.search_debugger_logs(DebuggerLogQuery)` 使用原两槽信号量，不排队另占额度；阻塞池前建立两秒绝对截止点，等待上限 2.5 秒，丢弃 Future 不释放仍在扫描的工作槽。没有在异步调度线程读日志文件。
- 第一次查询最多枚举 1024 个目录成员、选择 64 份宿主 JSONL，每文件最多末尾 8 MiB，总读取预算 64 MiB。首次固定文件身份、长度和窗口，不把后来追加记录插入本次分页。
- 使用 Windows 卷号／文件索引或 Unix 设备／inode 验证真实文件身份，另校验创建时间、首尾锚点与缩短／改写；游标记录最后返回条目的实际时间、文件和字节偏移。全局按实际时间排序，相同时间由文件和偏移稳定消歧，不要求日志写入时间严格单调。
- 每页在固定持久窗口内先同时匹配 `plugin_id/generation/log_id/job_id/session_id/q`，再按实际时间排序及键集分页。只保存本页和一条向后探测记录，不缓存整份文件或完整日志集合。默认倒序，最多百条；不是在首次百条结果上继续分页。
- 游标为随机 UUID，只保存在宿主内存中，绑定全部筛选与排序、首次文件窗口及边界偏移；缓存最多 128 项、每个游标有效期五分钟。宿主重启或过期明确返回 `debugger_cursor_expired`；改变筛选或排序明确拒绝。
- 轮转删除、同名替换、截短或锚点变化返回 `coverage.gap=true`，不再发后续游标。绝对期限导致未完成扫描时返回 `incomplete_scan=true` 且不继续分页；目录／文件／字节窗口限制写入 `scan_limited`。页数尚未取完由 `has_more` 区分。
- `missing_association_records` 统计扫描中缺失必要关联的记录，不猜测其插件／代次归属；`invalid_records` 包含坏行、超限行、未完成行及无效时间。响应只返回原安全日志字段加插件、代次与会话身份，不返回文件路径、输入载荷或任意原始附加字段。

`retained_logs_only=true` 明确保留期限外、其他宿主和缺失关联历史不在已证明范围内。分页完成也不等于业务全量审计，更不表示生产通过。游标仅供同一宿主的五分钟内查询，不是跨重启的持久日志位置协议。

公共 `mod.rs/openapi.rs`、HTTP/MCP 装配、生成类型、根 `todo.md` 由主代理统一更新。本批不修改用户并行的安装体系、Cargo.lock 或其他业务文件。

## 显式恢复代码包的评估

现有 `InstallationStore.restore_previous(id,expected_revision)` 已具备发布身份／修订校验、受控活动文件恢复、反向事务日志和资源引用保护，可作为显式共用恢复用例的存储基础。它不是业务数据回滚端口。

但当前快照表示“上一版”，并非独立记录的“上一成功激活包”。恢复后反向快照保存恢复前版本，再次调用可能切回。不能直接用“上一成功包”命名并承诺成功激活资格；如确需该语义，应由安装模块所有者追加明确的成功版本证据和相应存储契约。

建议增量文件与入口：

- `application/src/plugin_installations.rs`：显式 `restore_previous_cancelled(id,expected_revision,cancel)`。在原 `PluginService.serialized` 下校验当前修订，撤销当前组件，调用原存储恢复，并通过原依赖、配置与加载流程重新激活。失败保留恢复阶段和真实运行状态，不擦除旧故障。
- `application/src/installation_operations.rs`：新增原 Job 操作 `installation.restore_previous`，输入 `{id,expected_revision,confirmed:true}`。提交后查询、取消与日志继续使用原任务入口。
- `server/src/plugin_installations.rs`：薄 HTTP 入口 `POST /api/v2/plugin-installations/{id}/restore-previous`，202 返回原 Job；MCP 通过同一操作注册消费，不另建 `debug_install`。
- `server/src/lib.rs`、`openapi.rs` 和生成类型由主代理接线。配置、数据库、设备状态、产物内容和插件业务数据均不回滚。

本节仅是基于当前文本的只读评估，未写入上述并行文件，也不计恢复功能已实现。
