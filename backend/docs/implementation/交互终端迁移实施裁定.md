# 交互终端与常驻会话迁移实施裁定

日期：2026-10-10。完整范围继续包括交互终端、Frida、自动化及流媒体常驻会话；本文不将公共工具库的实现计为整体迁移完成。

## 架构门禁

- 模式：`architecture-first`。新增双向流和进程所有权接口，影响公共工具集成、插件传输、领域端口、宿主会话用例及前端消费。
- 目标：保留旧终端的持续 stdout/stderr、运行时输入、日志消费与主动停止；后续 Frida 使用相同生命周期约束，但专用控制和消息仍由 Frida 插件实现。
- 约束：旧工程只读；无平台命令进入通用宿主；输入、输出、会话和期限有界；卸载及服务关闭撤销输入并等待清理。直接进程退出不能证明远端会话或派生进程树已释放。
- 已核实：旧终端不是 PTY，没有 resize；新 application 的 `terminal.rs` 是任务终态提交模块，交互功能使用 `interactive` 命名。当前工具库只有 capture/capture_to_file 及租约版本，领域 ExecutionContext 只有 deadline，现有 JobEvent 无输出载荷。

## 方案选择

| 方案 | 变更与风险 | 决定 |
| --- | --- | --- |
| 公共异步双向管道，独立插件贡献，宿主管理会话 | 先补真实流式执行，再冻结协议和所有权；平台命令、传输与调度有明确边界，可供终端及其他常驻工具复用 | 采用 |
| 用循环短任务或独立全局后台进程模拟终端 | 丢失同一进程输入与输出语义，退出、卸载和代际脱离宿主所有权，后续 Frida 仍需重做生命周期 | 不采用 |

| 单元 | 负责 | 不负责 | 输入与输出 | 副作用 |
| --- | --- | --- | --- | --- |

| tool-process `streaming/input` | 有界输入准入、EOF 顺序、累计字节上限 | 输出与业务命令解析 | 有界字节 → 写入队列 | 异步通道 |
| tool-process `streaming/output` | 分片读取、分路累计上限、背压 | UTF-8 文本解码、日志持久化 | 管道原字节 → 带路标的输出块 | 异步 I/O |
| tool-process `streaming/lifecycle` | 持续驱动、取消/期限收口、退出后关闭输入、保留租约 | 外部资源清理确认 | 管道与进程所有者 → 退出结果 | 进程等待与直接回收 |
| plugin-sdk / plugin-runtime 后续会话协议 | 版本化打开、输入、输出、结束和清理确认帧 | 宿主私有状态、平台命令 | 会话消息 ↔ 公开协议帧 | 运行库异步传输 |
| domain / application `interactive` 后续会话用例 | 当前代准入、容量、游标、控制和 owner 清理接线 | 平台工具、进程 API、HTTP 包装 | 类型化请求 → 公开会话状态和输出 | 通过领域端口调用 |
| infrastructure 后续会话适配器 | 实现领域端口，传输到已注册插件 | 业务平台分支、任务终态存储混用 | 领域会话 ↔ 插件协议 | 插件进程 |
| 平台及终端插件 | 工具配置、独立 argv、平台会话和专用清理 | 宿主注册及私有缓存 | 公开上下文与会话请求 → 平台输出 | 配置的工具与设备 |
| server 后续交互路由 / MCP | 日志关联、请求检查、调用同一用例、生成 OpenAPI | shell 拼接、平台决定、会话所有权规则 | HTTP/MCP ↔ 公开模型 | 网络 |
| frontend 后续 shared/api、features、公开 SDK | 生成类型消费、输入/输出用例、取消、销毁、晚到保护 | 服务器路径、工具命令构造、未冻结 DTO | 公开接口 → 框架无关用例与扩展 | 网络和订阅 |
| tool-process 独立行为测试 | 真进程输出、输入、EOF、背压、限额、取消、丢弃和直接退出 | 将模拟工具计为真机或外部资源验收 | 独立夹具 → 断言及报告 | 测试临时文件与进程 |

## 分阶段落地与验证

现有 capture 职责保持独立；新流式实现分输入、输出和生命周期模块，不把交互状态追加到任务终态模块或 server/main.rs。

采用 Hybrid（契约先行，加真实进程行为测试）：先确定公共 API 和资源边界，再由独立测试驱动证明持续流和直接进程生命周期，最后接插件、宿主和浏览器。必须先证明“退出前可读到输出”“输入可多次发送”“取消或丢弃不遗留直接 PID”。

第一批可立即实现 tool-process 双向流，默认沿用现有总输出上限和绝对截止点；输入逐块与累计有上限，通道容量有界，慢消费者受同一期限与取消约束。输出保留原字节，非零退出公开原退出状态，输入关闭不再接受后续提交。等待终态可以排空未读输出，不能因队列满而永久等待。

后续必须完成插件版本化传输、owner/generation 卸载接线、HTTP/MCP 和前端生成类型用例，再交付终端插件。Frida 服务部署、注入、权限分析、自定义 hooks 与日志退出继续按原迁移清单独立实现。PTY、进程树和真机证据按实际需求与平台另行验收。

## 协作写权

- 后端开发：tool-process 流式生产模块、lib.rs、error.rs 和本库 README。
- 测试助理：本库新增 streaming 行为测试与独立夹具；不修改生产模块，不运行 Cargo。
- 前端开发：前端独立终端消费边界文档；不手写 DTO、不改现有 UI、不执行生成。
- 主代理：本文、契约裁定、Cargo/架构集成、全量门禁和交付记录；所有 Cargo 由主代理串行执行。

本批没有等待用户答复的阻断项。产品 UI 继续等待设计稿；公共流能力的实现不依赖该设计稿。

## 第一批实际交付与证据

公共双向流已经落入 tool-process：输入准入、输出分片、监督及句柄分别实现；不改变原 capture 或 Error 契约。新增 18 组真实进程/配置行为通过，包含持续输出、二进制双路、多次输入、共享 EOF、精确限额、满队列排空、停止消费及输入背压下的取消/原期限、父子 token、已轮询等待丢弃后重新等待、直接 PID 与租约实际释放顺序。

- 架构 18 模块及 6 规则、全工作区格式检查、全目标 Clippy、工作区测试和 debug 构建均退出 0。最终 87 组结果共 1057 passed / 0 failed / 0 ignored，完整末尾 Doc-tests 终态；原工具测试 39 项和新增流测试 18 项都在。1057 项仅证明本批输入，不转计后续会话协议实现。
- 独立测试及全量报告为根 `artifacts/interactive-stream-behavior-initial-20261010.txt`、`interactive-stream-workspace-test-initial-20261010.txt`；相同前缀的 architecture、architecture-tests、fmt、workspace-clippy-initial、workspace-build-initial 报告分别记录对应门禁。
- 693 个冻结后端文件在完整门禁期间 SHA256 零差异，见 `artifacts/interactive-stream-frozen-inputs-verification-20261010.json`；门禁原件摘要另存 `interactive-stream-gate-reports-20261010.json`。证据记录之后仅追加本文和交付记录，不因此重复输入未变的源码门禁。
- 默认与 `--performance-plugin` runtime 两种真实服务均退出 0，见 `interactive-stream-runtime-{default,plugin}-20261010.txt`；合作取消服务三种 complete/ignore/failed 情景通过且正常关闭，见 `interactive-stream-cooperative-service-20261010.txt`。这些回归验证既有服务，不证明新交互 HTTP、插件传输或终端业务已接线。
- 前端只新增独立[消费边界](../../../frontend/docs/contracts/交互终端公开接口消费边界.md)，未改生成类型、用例或产品页面；没有为文档重复执行前端构建。

第一批结论限于本机 Windows 真实直接进程和公共管道；无真机、PTY、派生进程树、远端资源或正式分发结论。下一批接版本化常驻插件传输、领域会话端口、owner/generation 卸载与服务关闭，再接 HTTP/MCP 和前端生成消费，完整终端及 Frida 范围保持待迁移。

## 第二批：公开会话协议与运行库

[协议第五版裁定](../contracts/交互会话协议第五版裁定.md)中的独立 SDK/运行库已实现：SDK 21 项、运行库 23 项通过；完整后端 89 组、1101 项通过，架构/fmt/Clippy/build 及两种 runtime/合作取消服务均退出 0。722 个冻结后端输入在门禁期间零差异，报告统一为根 `artifacts/interactive-session-`。首次输入溢出测试与导入排序失败保留，修复仅涉及观察时序和格式，不放宽生产协议。

新协议专项仍是内存双工管道，既有真实服务回归不表示协议 5 宿主适配已完成。会话贡献声明、领域端口、进程适配与 owner/generation 接线仍待，完整终端、Frida、HTTP/MCP 和前端用例继续迁移。业务期限/取消不得直接交给流式进程硬监督，否则会立即终止插件而丢失合作清理窗口；未来适配需独立强制取消 token 与覆盖清理/终态传输的硬期限。
