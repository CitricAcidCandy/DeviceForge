# 设备原始状态与统一发现实施方案

## 方案状态与边界

本文件为 2026-10-09 下一批 architecture-first / Hybrid 候选方案，供交付总监和主代理审核。所有新增版本、字段、配置变体、内部接口及最终提交语义均未冻结，不得直接按本文实施。当前只新增本文件，不修改 SDK/domain/application/infrastructure/server 源码或其他文档，不执行 Cargo、fmt、构建、服务或真实进程。

操作绑定第一批的冻结规则见 [操作绑定第一批契约](../contracts/操作绑定第一批契约.md)。本批仍禁止 android.devices/harmony.devices 别名和普通目标指向发现贡献；本方案不能解除已实现的拒绝门禁。主代理已报告 23 项纯回归及 application --lib 共 39 项通过，BIND-001/002 定向已复验；BIND-003 真实协议回归另行进行，该结果不表示本候选方案已验证。

目标是在公开发现消息和统一目录保留原始状态，并让显式 refresh、直接发现 Job、未来旧发现别名共用准入、单次发现执行、结果校验及目录发布。平台命令继续归独立插件；空插件宿主、默认免鉴权和可选令牌不变。常驻会话、真机、性能生命周期和平台完整迁出不在本批关闭范围。

## 当前调用路径与明确缺口

以下路径相对 backend，是只读取证，不是本次源码写入授权。

| 当前路径 | 实际行为 |
| --- | --- |
| `crates/plugin-sdk/src/devices.rs`、`crates/domain/src/devices/mod.rs` | 设备声明 API 1/2，状态为 online/offline/unauthorized/unknown；PluginDevice/ProvidedDevice 无 raw_state |
| `crates/infrastructure/src/device_providers/mod.rs`、`plugins.rs` | 实际发现贡献的结果按 SDK 消息校验；协议 2/3 经宿主生成 result/artifacts 包装，协议 1 为裸发现数组 |
| `crates/application/src/devices/refresh.rs` | 两项全局在途额度、同 provider 串行、30 秒截止点、开始时清空目录；提交一个发现 Job，等终态及 active 清理完成后再次校验并发布目录 |
| `crates/application/src/submission.rs`、`alias_plan.rs`、`runner.rs` | 提交真实目标快照，保留入口 operation/input；runner 执行、投影及写终态。直接发现 Job 当前不走 refresh 的目录发布 |
| `crates/application/src/devices/registry.rs`、`registry.rs` | 目录与贡献共享注册锁，发布复核代际、取消和截止点；卸载撤销贡献及目录，GET 过滤当前代 |
| `crates/application/src/lib.rs`、`crates/infrastructure/src/store.rs` | 取消先写取消终态再触发令牌；存储 transition 遇到已终态时返回原任务，不覆盖终态 |
| `crates/infrastructure/src/devices.rs` | 旧 DeviceTools 保留 device/offline/unauthorized/recovery/sideload/bootloader；旧结果为 Device 数组，HDC 已识别目标使用 device 状态 |

关键缺口有三处：原始状态不能无损表达；目录发布只在 refresh 的额外编排中；持久化终态和内存目录不属于一个原子事务。统一入口不能仅把 publish_directory 调用追加到 runner，必须先明确这第三处的可观察语义。

## 原始状态与版本候选

建议保持四种归一化 state 不变，在 SDK PluginDevice 和领域 ProvidedDevice 增加可选 `raw_state: Option<String>`，以设备声明 API 3 启用。它是同一次观测的原始状态文本，不是可执行指令、完整工具输出或任意 metadata 容器；参考上限为 100 UTF-8 字节，非空、非全空白且禁止控制符。具体上限和字段名仍待冻结。

raw_state 仅供保真呈现、历史与兼容转换；准入仍依据归一化 state 和已声明能力的 available，不从 raw_state 推断权限、连通性或所有能力。未知但有界的原始状态应原样保存，不建立宿主平台状态枚举、不 lower-case/trim 后替换原文。归一化含义由插件负责，宿主不添加 Android/Harmony 分支。

| 设备声明版本 / 消息 | 建议行为与兼容边界 |
| --- | --- |
| API 1/2，raw_state 缺失 | 接受，内部 None；序列化省略，保持原消息形态 |
| API 1/2，raw_state 显式 null | 建议新宿主接受并归 None；旧宿主的严格消息解析仍可能拒绝该属性，新插件发旧版本时应省略 |
| API 1/2，raw_state 非空字符串 | 建议拒绝，不能在旧版本偷带新语义；实际发现错误为 dependency_failed |
| API 3，raw_state 缺失或 null | 建议接受为 None，明确表示没有原始状态证据，不补造特殊状态 |
| API 3，有效已知/未知字符串 | 原样贯通 SDK 映射、Job 观测、目录及允许的旧结果转换 |
| API 3，空白/过长/控制符/非字符串 | 拒绝整个发现，不截断或丢弃坏设备后当作成功 |
| 归一化 state 为未识别字符串 | 仍拒绝；未知平台状态应使用 state=unknown 和有界 raw_state |
| 旧宿主遇 API 3 清单 | 明确版本不支持，不宣称向旧宿主前向兼容 |

API 3 继承 API 2 能力预算规则；API 1 仍不接受非空预算声明。这里只提升设备声明的版本，不提升 Manifest 顶层 api_version、任务传输 protocol_version、能力精确 version 或 HTTP /api/v2。部署绑定配置的版本变化另行确定，不能与这些版本混为一谈。

建议用例如下：online/device、offline/offline、unauthorized/unauthorized；recovery/sideload/bootloader 可由 Android 插件归一化为 unknown，raw_state 保留原文。未来平台若在特殊状态确有可执行能力，需另行定义准入能力，不能靠 raw_state 绕过现有 Online 门禁。对于任意 raw_state 与 state 的组合，宿主只按归一化状态准入，不在通用规则中猜测平台一致性。

## 三入口的统一发现准入

建议在提交时依据真实目标快照识别 discover_operation，建立应用内部发现执行计划；不通过 operation 名称后缀、旧别名字符串或平台名推断发现。三入口走同一个应用流程，refresh 只负责指定当前代并等待其 Job 收敛，不再持有独立的发布实现。

| 入口 | 输入与身份 | 单 Job 与响应建议 |
| --- | --- | --- |
| HTTP/MCP 显式 refresh | provider ID + generation，发现业务输入为 `{}` | 提交一份发现 Job，返回其发布回执对应的 DeviceDirectory；不另外造包装 Job |
| 直接 jobs 的发现目标 | 已加载目标 operation + `{}` | 保留现 Job.operation/input；同一 Job 自动经过发现校验和目录发布，不能只成功返回数组却绕过目录门禁 |
| 后续旧 android.devices/harmony.devices 别名 | 明确配置 plugin_id，旧业务输入仍 `{}` | 同一 Job 保留旧入口名和旧数组结果；由真实目标计划执行发现并发布同一观测，不再调用 refresh 产生第二个 Job |

建议保留全局两项发现额度并将其覆盖三个入口，包括排队及取消清理收敛；队列容量沿 Application 现有界限。实施前确认在途额度在创建 Job 前即拒绝，避免直接入口绕过名额，或者已创建任务又挤入无界等待。执行未来仍只占一次通用 workers 名额。

同 provider ID 的发现串行，锁键不含 generation；持锁前后复核当前 owner 和代际，新代不能越过旧代未收敛发现。等待串行锁和通用执行槽扣除准入起的同一 30 秒绝对期限。刷新请求在受限阻塞提交前记录起点，并向原任务传递截止点，不在创建 Job 后重新开始计时。

真正开始本轮发现前清空当前代目录，避免坏发现后继续使用旧观测；尚在等待串行锁时不先清除另一发现刚发布的目录。失败、取消或到期沿既有清空策略，不改为保留旧缓存。新目录必须带 provider/generation、observed_at 和该单 Job 的 discovery_job_id，GET 只暴露当前代已接受的观测。

发现串行锁与 provider 读写屏障是不同职责。现有发现不取得动作屏障，建议此项先保持，三个入口均不得反过来绕过 provider/device 动作锁。若要禁止发现与 connect/disconnect 同时观察，必须单独确认发现屏障模式及全局获锁顺序，再加测试；不能顺手把发现改成 provider write 导致所有设备动作阻塞。

后台工作须在 active.accepting 准入锁保护下进入现有 tracker，并传播 LogContext；不得在 shutdown 关闭 tracker、wait 完成后创建新发现任务。请求/Future 丢弃只触发原任务取消，工作名额、串行锁和临时目录由被跟踪任务持有直到执行/有界清理收敛，清理未确认保留 cleanup_failed。

## 结果处理与终态/发布竞争

推荐提取命名的发现结果处理流程：按执行器声明的结果格式解码、验证同次完整观测、生成目录候选、进行入口结果转换，最后进入终态与发布收敛。不把解析、注册锁、持久化和旧格式拼在 HTTP 路由或一个万能 helper 内。

Json 执行器只接受裸发现数组；PublishedArtifacts 执行器只接受严格 result/artifacts 两字段的宿主包装，result 为发现数组。来源依据本轮新增的 ExecutorResultFormat 端口，不依赖业务 JSON 外形；协议 1 伪造宿主包装仍拒绝。产物额度、已发布元数据和清理沿既有规则，本项不自行新增发现产物类型或信任声明。

任何入口在任务成功终态前都要完成完整发现校验及所需旧结果转换。重复 local ID、非声明能力、API/raw_state 不匹配、格式错误、过量设备或能力，都使本 Job 失败且不发布目录。只允许从同一次实际发现生成旧数组和目录；不得再次执行工具，也不把 Job 已成功当作可跳过目录规则的证明。

当前任务持久化和目录注册使用不同资源，没有跨二者的原子事务。建议先采用与现有不可变终态兼容的方案，并明确其边界；若主代理要求更强一致性，必须冻结额外收敛机制后才能实现。

| 候选方案 | 实施与可观察边界 | 建议 |
| --- | --- | --- |
| 先确认成功观测终态，再尝试接受当前目录 | 先完成解析/转换及清理，调用现 transition，检查它实际返回的终态；只有实际 Succeeded 才复核当前 owner/cancel/deadline 并发布。允许历史成功观测因随后卸载/到期而未成为当前目录，refresh 据发布回执返回明确失败 | 建议优先，改动较小；必须先确认“Job 成功表示成功观测，当前目录以发布回执为准”可接受，不隐瞒两结果差异 |
| 成功终态必须与当前目录接受一致 | 引入有界内部最终提交状态或暂存目录，取消、失败、存储成功和目录激活共享明确的决定点；目录接受前不可供动作准入使用 | 若拒绝上一语义则必须选择此项；需另行设计存储失败/截止点/卸载及进程重启恢复，不把前后两次检查误称原子提交 |

两方案都不能持注册 RwLock 或 active 同步锁跨越数据库 await，不能延长 30 秒业务期限来完成发布，不能在发布后把取消终态改回成功。第二方案的接口、锁顺序、决定点和补偿规则尚未完成门禁，本文不把它写成已具备实现条件；主代理需在开始实现前择一冻结。

第一方案建议收敛顺序如下：

1. 串行发现已结束、进程清理确认后，完整校验观测、版本、raw_state 和旧投影；记录真实完成观测时的 observed_at，保留目录候选及当前 owner 快照。此时目录仍不可见。
2. 检查取消/到期/当前代及 cleanup_failed，再由现有任务生命周期尝试持久化结果。必须检查 transition 实际返回的 Job，不能仅相信请求写入的 Succeeded；若返回既有 Cancelled/Failed，丢弃候选并保留终态。
3. 对实际 Succeeded 的本 Job，在注册写锁内同时核对 provider/代际、目标当前性、owner 仍 Loaded 且无 cleanup_failed、取消令牌和截止点，再一次性接受目录。卸载使用同一注册锁，因此卸载先赢则不能发布，发布先赢则卸载撤销它。
4. 发布成功产生只属于本 Job 的内部回执；refresh 根据该回执返回目录，不再从“当前目录最新值”猜测自己的结果。直接 Job 和旧别名维持各自结果结构，新的 GET 仍代表当前代目录，后来刷新或卸载可以改变它。
5. 持久化后因到期、取消或代际变化拒绝发布时，目录保持空或后来合法的新观测；历史 Succeeded 不改写，refresh 返回 Timeout/Cancelled/Conflict。该情况须在真实回归报告单独记录，不能把历史成功解释为目录已发布或对外整体成功。

这套有条件接受流程不需要先发布再回滚目录，也不增加跨任务无界结果缓存。refresh 的结果回执可以由被跟踪的本任务持有并交给唯一等待者；等待者丢弃时任务继续清理收敛。任何等待结构必须有与 active/队列一致的容量及释放时机，不能建立无限增长的 discovery_job_id 会话表。

| 竞争情况 | 必须冻结并验证的结果 |
| --- | --- |
| 取消已写终态，runner 后到成功 | transition 返回原 Cancelled，目录候选永不激活，不改旧事件 |
| 取消/到期在进程启动前或首次 poll 前获胜 | 零工具业务执行，无目录，清理路径不首次 poll 未开始执行器 |
| 取消/到期在结果返回、解析或旧转换期间获胜 | 丢弃晚成功，沿当前终态及独立有界清理收敛 |
| 第一方案中持久化已 Succeeded，发布前取消/到期 | 历史成功可保留、当前目录拒绝；refresh 明确失败，不能悄悄重计时 |
| 发布与卸载同时发生 | 注册锁决定先后；卸载后 GET 无旧代，旧结果不能复活 owner 或目录 |
| 新代加载，旧代发现随后返回 | 旧代拒绝；任何清空或补偿只作用匹配 provider+generation+job，不删除新代目录 |
| 本轮失败，下一轮已有合法发布 | 不允许旧任务的 finally 无条件 clear(provider) 抹掉新结果 |
| 关闭服务与发现准入同时发生 | active.accepting 决定是否能创建 tracked 工作；关闭后无新 Job/发现后台工作 |

用户主动取消与到期同刻的判断沿已经冻结的总期限规则，不在本项重定义。SDK raw_state 为显示数据，也不得影响 Cancelled/Timeout/CleanupFailed 的判定。

## 旧名称与旧数组兼容候选

建议部署绑定格式增加独立发现目标，例如候选 `device_discovery {plugin_id}`，只能解析为该 owner 的 discover_operation；普通 operation 和 capability 目标继续禁止占据旧发现名称。建议配置格式 2 才允许该加法，格式 1 的 BIND-002 拒绝规则原样保留；文件仍使用部署配置，无业务请求选择提供者或新增绑定管理路由。

旧发现只接受旧 `{}` 输入，配置在目标加载时解析到真实 owner/代际，加载仍仅验证属于该 plugin_id 的绑定；别名/目标/owner 一次原子发布撤销。目标未安装或未加载时旧名称不可发现、提交 not_found，不回退 DeviceTools；多个提供者暴露同一本地 ID 时由配置选定目标，不用平台名称猜测。

建议使用专门的有限数组兼容规则，而不是给现有 object 投影加入循环、脚本或递归表达式。候选旧结果为 `[{id,platform,state,model}]`：id 是同次观测 local ID，platform 是经过注册校验的显式配置字符串且须与提供者声明一致，state 取原文 raw_state，model 按旧实体保留 null。提供者/代际只在新目录中，不擅自给旧 Device 加字段。

SDK/domain 的 raw_state 可选是为了公开发现向后兼容；要求旧结果无损的别名则应要求目标 API 3，而且本次每个设备都有有效 raw_state。缺失/null 时建议整次旧发现任务失败且不发布其目录，不能猜成 device、用 unknown 替换 recovery，或静默少返回设备；空数组仍是合法成功观测。新 refresh/直接发现允许 raw_state=None，故这一要求只属于旧兼容 profile，不提高所有提供者的强制门槛。

known device/offline/unauthorized 与 recovery/sideload/bootloader 全部原文输出；未来未知有效原始状态也保留。旧客户端可能不理解新文本，应由客户端显示或版本化处理，宿主不能为了旧枚举把真实状态改成在线。是否允许显式降级 profile 必须独立冻结，本建议默认不降级，不声称 API 1/2 发现可无损替换旧数组。

Job.operation/input 保留旧名与原对象，历史数组及事件在卸载后不改写；新目录保留同 Job 的 discovery_job_id。设备声明版本、绑定格式、旧结果兼容 profile 三者的检查必须显式，不能只检测 raw_state 属性存在就启用新契约。

## 文件职责、建议实施顺序与非职责

以下为候选写集，须由主代理分配后实施；当前所有源码仍冻结。API/model 的加法、注册层、任务生命周期和生成文件各由一个所有者统一集成，避免插件角色同时修改公共端口。

| 单元与候选路径（相对 backend） | 输入/输出和职责 | 副作用 / 明确不负责 |
| --- | --- | --- |
| `crates/plugin-sdk/src/devices.rs` | API 3、PluginDevice.raw_state 的严格序列化及版本兼容用例 | 无副作用；不判断平台状态、不发布目录 |
| `crates/domain/src/devices/{mod,rules}.rs` 及所属测试/README | ProvidedDevice.raw_state、版本/长度纯规则，保留现状态/身份/能力限制 | 无 I/O；不编译业务假样例、不引入 Tokio 或解析 ADB 文本 |
| `crates/infrastructure/src/device_providers/{mod,tests}.rs`、`plugins.rs` | SDK 到领域映射、版本校验、真实结果来源与协议包装 | 仅沿现进程执行/产物副作用；不缓存目录、不创建发现 Job |
