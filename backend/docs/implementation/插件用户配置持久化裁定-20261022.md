# 插件用户配置持久化裁定

模式：architecture-first。用户要求初始插件可留随包目录，所有插件配置统一持久化到用户目录。此次只改变配置归属，不迁移任务、日志、工具和插件程序。

采用独立用户根：默认用户目录 `.deviceforge`，显式部署和隔离测试可通过 `DEVICEFORGE_USER_DIR` 指定。`APK_DATA_DIR`、CLI `--data-dir` 继续控制业务数据；插件安装根继续独立。配置落点为 `plugin-configurations/server/<id>/` 和 `plugin-configurations/browser/<id>/`。

不采用把全部业务数据搬入用户目录的方案：那会改变现有预览、工具和产物部署。浏览器配置改由服务器 API 持久化，localStorage 仅为无远端记录时的兼容导入源，不再承担保存成功的依据。

| 单元 | 职责及输入输出 | 不负责 | 副作用 |
| --- | --- | --- | --- |
| server 配置根解析 | 环境与用户目录转换为配置绝对路径 | 插件安装、业务数据搬迁 | 读取环境 |
| infrastructure/plugin_configurations | 服务器配置修订、旧状态复制、首次声明配置落盘 | HTTP、浏览器运行 | 受限文件工作、锁及原子发布 |
| domain/application/browser_configurations | 浏览器记录、CAS 端口及用例 | 文件路径、插件激活 | 经端口调用存储 |
| infrastructure/browser_configurations | 浏览器原值记录持久化与有界 CAS | 前端模式校验与遮蔽 | 文件工作、锁及原子发布 |
| server 浏览器配置路由 | ID、请求与日志包装适配 | 存储细节、插件代码执行 | HTTP |
| frontend 配置模型/适配器 | 激活前读取、保存、应用及旧 localStorage 导入 | 用户目录路径选择 | HTTP、旧记录只读、订阅 |
| 启动器与预览入口 | 转发用户根，业务根保持独立 | 配置规则 | 启动进程 |

先拆分新增的路径解析、迁移与浏览器存储模块，再接入既有装配。旧服务器配置只在用户目录无对应状态时复制，保留修订、应用修订、原值和源文件；目标已有配置时优先目标，不覆盖。声明默认值与旧旁置配置在首次读取或调用时物化到用户目录。无配置声明且无旧数据的插件不创建无意义配置。

浏览器 API：GET/PATCH `/api/v2/browser-plugin-configurations/{id}`。读取返回 `{record:null|record}`；写入接收 `{expected_revision:null|string,record}`，比较旧修订后原子写入。记录保留 `version/values/revision/applied/sensitivePaths`，仅允许合法插件 ID、有界 JSON 和普通文件。原值用于可信浏览器插件实际运行，展示继续使用模式遮蔽；原值和服务器路径不进入日志。有配置声明的浏览器插件首次读取或激活时，即使只使用默认值也创建用户记录，避免随包默认值升级改写原有使用值；无配置声明时不额外请求。

局域网浏览器通过服务端保存，因此配置归属于运行服务器的系统用户；客户端电脑不会分别创建一套插件配置。多个宿主实例如需独立配置，应显式设置各自的 `DEVICEFORGE_USER_DIR`，不能同时占用同一配置根。Windows 的 `.DeviceForge` 与现有 `.deviceforge` 通常指向同一目录；沿用已有小写名称，避免在区分大小写的平台产生两套用户配置。

验证采用 Hybrid：先证明目录解析、迁移保值、CAS 与重启，再验证浏览器异步激活、旧记录导入和保存失败无本地降级，最后运行所属端门禁与实际分发验收。真实手机、媒体长时和性能不属于此次范围。各角色按独占写集并行，生成器、Cargo、构建和服务统一由主代理调度。
