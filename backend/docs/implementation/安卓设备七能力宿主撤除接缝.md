# 安卓设备七能力宿主撤除接缝

日期：2026-10-10。版本：v1，接缝设计稿。本文件依据已冻结的《安卓设备插件第一批实施裁定》及当前生产装配，只提出下一批最小写集与验收资格；新增执行器名称、构造签名和拆分方式仍待主代理正式裁定。本文件不授权修改源码，不把插件源码交接或纯测试落盘计作宿主已经撤除。

本次只撤 Android 首批七能力加发现的八个内置入口。Harmony、Android APK安装、截图、APKS安装及性能会话保持原装配。通用HTTP/MCP、设备目录、代际、锁、任务、在线安装与绑定层不增加Android分支，不按插件有无静默回退。

## 当前真实装配与八入口归属

当前名称以源码为准：`DeviceTools` 位于 infrastructure，不是 application设备目录服务；用户描述的 DeviceArtifactOperations 对应实际 `device_artifacts::DeviceArtifactActions`；DeviceInputOperations 对应 application的 `device_input::InputOperations`，底层为 infrastructure的 `AndroidInput`。不得按近似名称创建重复领域端口。

| 旧公开操作 | 当前声明和执行者 | main装配 | 撤除后的唯一目标 |
| --- | --- | --- | --- |
| android.devices | infrastructure/src/devices.rs：DeviceTools.operations/execute/list；parse_adb为旧解析 | server/src/main.rs:35，DeviceTools含adb与hdc | android-device的discover短贡献；旧名由格式2专用发现绑定提供 |
| android.connect | DeviceTools.operations/execute | 同上 | provider/write的connect能力，版本1 |
| android.disconnect | DeviceTools.operations/execute | 同上 | provider/write的disconnect能力，版本1 |
| android.packages | DeviceTools.operations/execute | 同上 | device/read的packages能力，版本1 |
| android.app.start | DeviceTools.operations/execute | 同上 | device/write的app.start能力，版本1 |
| android.app.stop | DeviceTools.operations/execute | 同上 | device/write的app.stop能力，版本1 |
| android.app.uninstall | infrastructure/src/device_artifacts/mod.rs：DeviceArtifactActions.operations/execute | server/src/main.rs:72 | device/write的app.uninstall能力，版本1 |

`APK_ADB`不能整体删除：撤去DeviceTools和AndroidInput两处后，main仍由DeviceArtifactActions残余装配、AndroidSplits安装侧车及AndroidPerformance缺省采样三处消费。`APK_HDC`仍供Harmony设备与产物操作；`APK_JAVA`、`APK_BUNDLETOOL_JAR`及`APK_PERFORMANCE_PLUGIN`保持。插件只读自己的可信配置，不从宿主旧环境继承这些业务覆盖。

保留项不是已迁出的公开设备能力，不能因新提供者online便声称旧安装/截图/APKS/性能也进入provider屏障。它们目前仍可能与插件设备动作在同一真机上竞争；宿主新锁不覆盖其它ADB用户或共享daemon。这个缺口需要后续artifact/install与性能提供者批次解决，本次不通过隐式锁或新平台分支扩大范围。

## 推荐的最小专用执行器

推荐先收窄宿主生产装配、复用保留行为，再分批移除剩余旧平台代码。两个专用名称均为候选，不是新增公共契约已经冻结。

1. `devices::HarmonyDeviceTools { hdc: String }`：只声明并执行 harmony.devices、harmony.packages，不携带adb字段，不构造Android argv。实现只提取现有HDC发现和packages行为，复用parse_hdc与现有字段资格。不能用一个泛平台字符串方法重新暴露android分支。旧DeviceTools可暂留兼容测试/库调用，但main不再装配，旧Android服务入口不可从其绕回。
2. `device_artifacts::RemainingDeviceArtifactActions`：私有包住既有DeviceArtifactActions，构造材料仍为adb、hdc、ArtifactStore。静态白名单恰好为 android.app.install、android.screenshot、harmony.app.install、harmony.app.uninstall。operations只发布白名单；execute和execute_with_context先查白名单，非成员返回NotFound且零工具/零产物副作用，再委托现有实现。不能只过滤operations而继续接受android.app.uninstall。

残余产物侧车不是新的通用“排除操作”配置，不让请求或环境选择黑名单。固定四项准入保证升级时新增旧贡献不会自动发布。execute_with_context原样转发原ExecutionContext；has_unresolved_resources转发底层观测，不能把底层未确认清理改成false。结果格式沿底层Json，不伪造宿主产物包装声明；没有新的DeviceProviderDefinition。

当前DeviceArtifactActions本身没有覆盖context传播或未确认资源观测，默认Executor仅委托旧execute/返回false。侧车转发不能补成“原D覆盖全部阶段”或“资源清理已证明”；安装/截图旧分阶段期限、目录及直接工具租约缺口继续记后续批次，不借本次撤除改写其实现或夸大资格。

`InputOperations(AndroidInput)`在main整段停止装配即可，不新建空输入执行器。application/domain端口和旧适配器可以保留供旧端口测试及后续迁出核对，但它们不是宿主服务贡献。新插件执行器已通过通用catalog/PluginService接入，main不导入独立插件crate，不按android-device ID直接new平台对象。

目前新专用模块可由所属父模块导出，infrastructure/src/lib.rs已有pub mod devices/device_artifacts，不必为模块名重复增加顶层端口。application/src/device_input/mod.rs、domain/device_input、application/src/devices、server HTTP/MCP无需本批源码改动。Cargo依赖、公开SDK和生成类型也不需要为这次装配收窄新增协议；若实施发现新的真实缺口，按最小文件即时回流，不能先改它们凑通。

实施顺序：先冻结专用执行器及精确白名单回归；再替换main三段；随后用同一新宿主二进制/实际部署目录验证无插件、加载、卸载与保留操作。只有实际main切换后，才执行撤除资格审查；旧DeviceTools或完整DeviceArtifactActions的独立测试不代替新装配。

旧绑定继续采用通用 `APK_OPERATION_BINDINGS` 有界读取，输入为格式2配置，合并部署者现有其它bindings且拒重复ID；不手工加入main的平台路由。android-device的aliases.example.json已给八旧名：android.devices必须target.kind=device_discovery/result.kind=device_discovery/platform=android；七动作target.kind=device_capability，version=1，input为字符串device_envelope，result为Value wrapped=true。发现走现有统一目录发布，不把旧名绑定普通echo，也不直接调用插件后自造旧数组。

初始没有显式绑定时，不能承诺旧名自动存在；加载插件提供真实完整plugin.android-device.*贡献与能力。旧名只有有效绑定及目标注册后由通用注册层发布。目标缺失、卸载或load失败时不得回退到内置Android八入口。默认免鉴权、可选APK_API_TOKEN、日志关联以及HTTP/MCP结果形状保持，不为迁出额外加审批或鉴权要求。

## 当前交接与下一批依赖

本设计只写本文件，读取的是当前main及三个真实执行器，没有运行Cargo、格式化、测试、构建或服务。本插件13生产文件、INPUT-001修复与四纯测试文件已交主代理逐SHA核对；主代理正在格式化与编译/定点验收，结果未在本设计中预记通过。安装/截图/APKS与性能provider后续契约不因首批迁出自动冻结。
