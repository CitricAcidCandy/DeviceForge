# 资源故障隔离与后台回收裁定

## 状态与用户决定

2026-10-26 固化为长期硬约束：根 `AGENTS.md` 与两端 `AGENTS.md` 均须执行本裁定。适用普通任务、设备发现、性能采集、交互会话、插件启停/重载、配置应用与统一安装，不因插件未声明 recovery 而恢复“历史失败锁死全插件”的旧策略。源码、模拟、浏览器、部署与真机分别验收；本文规则不代表这些门禁已通过。

产品为个人及可信同事局域网工具，不增加多租户、来源审批或强制沙箱。现有可选令牌、输入与产物正确性、精确资源归属和有界容量继续保留，不将必要的运行稳定性管理解释为 Web 安全平台。

2026-10-23 用户明确要求面向本机 npx 自用，不再因旧资源清理失败反复拦住新操作；旧资源在后台回收，新调用分配新资源。模式为 architecture-first。该轮已有宿主历史告警与普通准入解耦的源码改动及定点回归，插件、前端与成套部署仍未完成集成验收，不以局部回归表示交付完成。2026-10-26 本轮只核对文档与静态遗漏，不重新声明所有实现均已满足。

2026-10-23 集成前记录的服务属于窄修版本：结束会话不再因历史 Failed/Unconfirmed 返回409，工作台记录与资源债务分离；这是历史快照，不是 2026-10-26 的现场服务查询。部署身份和新验证另行记录，不能把旧服务测试称为完成本裁定。

## 取代的旧策略

旧策略把一次调用未确认清理升级为整个插件不可用，又要求历史清理成功才能释放会话记录。隔离粒度过大，使不同设备、不同调用及工作台退出一起受阻。

本轮选择“旧调用隔离、后台有界回收、新调用使用独立资源”，不选择继续增加前台核对按钮，也不通过一处清零布尔值冒充实际释放。既有文档中默认因任意未确认标记阻断全部新调用的描述，后续实现应按本裁定逐步取代，未实现部分仍如实报告。

## 职责与落点

| 单元 | 职责与输入输出 | 不承担 | 副作用 |
| --- | --- | --- | --- |
| application 调用/会话生命周期 | 结束前台占用、保存旧债务、准入新调用 | 删除远端目录、按平台执行命令 | 有界监督及状态发布 |
| registry 资源准入 | 按插件、设备、资源身份与调用代际判断真实冲突 | 用一个 cleanup_failed 封锁整个插件 | 资源凭据登记与撤销 |
| infrastructure 进程监督 | 持有旧进程句柄，按截止点终止并真实回收 | 全局结束 ADB/HDC 或其他工具 | 精确进程回收 |
| 独立插件资源实现 | 新调用分配唯一目录/端口/令牌，旧台账后台续办 | 擅自认领外来资源 | 台账与设备资源操作 |
| HTTP/MCP 与前端 | 立即退出旧工作台，展示非阻断恢复状态；必要时显式接管 | 将后台失败伪装成已清理 | 请求与交互反馈 |

## 默认行为

1. 用户结束会话即退出本地画面与输入占用；旧调用继续由宿主监督，不丢弃回收句柄，不重放设备输入。
2. 旧调用的进程、文件和转发记录进入有界后台队列；宽限期后可强制结束本运行确实持有的子进程，按真实退出结果记录，不要求用户重复点击恢复。
3. 新调用使用新的调用代际、唯一目录、动态端口与资源令牌。旧失败不是新调用的全局拒绝条件，晚到旧结果不能修改新调用。
4. 可以另行分配的资源直接分配。只有确实需要同一独占资源而无法并存时，才对该资源执行接管或返回明确冲突，不扩大到整个插件或其他设备。
5. 发现/查询等独立操作不因另一条投屏残留一起封锁。清理风险仍可观察，但不能单凭风险布尔值返回409。
6. 显式强制接管只处理本运行可归属的旧会话与资源，不按进程名批量杀其他应用，不清除外来转发；这不是鉴权策略，而是避免结束错误对象。
7. 后台工作、台账及输出保持有界。队列满、真实设备编码器容量不足或磁盘失败须报告具体资源问题，不以“Web安全”解释，也不宣称用户操作有误。
8. `cleanup_failed`、`unresolved`、`recovering` 和历史 blocked/busy 报告均不能单独成为普通新业务的拒绝条件；恢复任务之间可合并或串行，不能冻结整个插件或要求用户先重启。后台回收失败或耗尽重试后仍保留诊断，新独立调用继续按真实资源准入。
9. 本次清理确实失败仍返回本次失败；新调用成功不抹掉旧失败，旧调用晚到失败不改变新调用成功。HTTP/MCP/公开 SDK/前端按钮/默认启用/安装存储必须贯通同一规则。
10. 退出后的外部债务与活动占用分账。确认直接进程退出且调用持有者结束后释放该调用不再需要的工具读锁，旧债务不占活动额度；尚无退出确认的真实持有者仍保留精确锁和容量，不按进程名或清空台账绕过。
11. 恢复确认仅覆盖开始时固定的 owner/代际/风险修订与债务快照，不能释放新调用的租约、清除之后产生的风险，或跨设备认领资源。后台任务继承固定截止点，重试/退避/队列均有上限，服务退出有明确收口路径。
12. 对声明恢复能力且确有旧债务的插件，普通任务、性能或会话失败路径均应核对有界后台续办覆盖，不能只给某类交互会话接线；不支持恢复时保留真实诊断和本次已有的进程清理，不强迫用户先恢复。逐调用进程清理与插件级旧债务续办分别验收，二者都不是独立新调用的前置门禁。

## 状态语义与文档优先级

历史清理诊断、前台会话记录、本次调用结果、实际活动资源、文件事务状态是不同维度。历史 `cleanup_failed` 不能伪装成实际活动锁，`draining` 也必须能说明正在排空什么；管理请求到期返回真实错误而非无限等待。文件事务不一致仅限制对应发布的文件变更，不冻结无关业务。

纯组件装卸失败阶段的可重试清单由 `InstalledRelease::has_retryable_component_warning` 与前端公开 helper 保持一致；文件事务恢复和未知原因继续按实际状态核对。详见[实施导航](历史清理告警与新任务解耦.md)。前端等待、禁用和诊断要求见[前端契约](../../../frontend/docs/contracts/插件清理告警与重试约束.md)。

旧指南、早期方案或验收矩阵中“未确认即拒绝全部新任务/重载”“先完成恢复再打开”的描述为已废弃策略，不得作为新实现依据；历史日志、失败报告和当时的测试结论仍原样保留。根约束及本裁定优先，发现文档冲突应修正文案和用例，而非恢复旧门禁。

投屏插件内部由用户指定的另一代理处理，本轮只固化共同规则和接续要求，不修改其实现或代替其报告验收。

## 实施顺序与证据

采用契约与失败行为先行的混合验证：先用同插件A调用清理失败、B调用独立成功建立先红回归，再修改准入与资源所有权。不能只删宿主判断而让适配器和插件内部仍按同一全局标记拒绝。

- 同插件、不同设备与不同资源的新调用不被旧失败阻断。
- 同一真实独占资源接管、仍存活旧进程、晚到旧清理、重复释放均有明确结果。
- 后台回收无响应时到期强制收口，不能丢句柄或无限重试；外来进程和工具服务保持不动。
- 真实HTTP/MCP、生产页面、两轮关闭复开、本机npx分发分别验收。
- 当前恢复第一版的模拟测试及短时真机通过不代替本策略的实施与验收。

以下为后续资源相关修改必须满足的回归清单，不是已通过记录：

- [ ] 普通任务、排队、发现、性能及长会话分别验证 A 清理失败后 B 真正执行成功；无 recovery 声明也不永久封锁。
- [ ] A 晚到失败不污染 B 成功，B 成功不清 A 诊断；旧代回调不改变新代或释放新租约。
- [ ] 恢复中及重试耗尽后仍能提交独立新业务；无响应回收有界，退出服务不遗弃本次持有的进程句柄。
- [ ] 旧退出债务不占活动额度或工具读锁；未知退出和实际独占冲突仍被正确限制，并给出受影响对象和可结束/重试路径。
- [ ] 前台释放与资源确认分开；已结束记录不因旧清理失败一直占工作台，历史结果不被删除或篡改。
- [ ] 配置、统一安装的领域/应用/存储/前端一致放行纯组件告警；真正文件事务问题仅阻止对应变更。
- [ ] 实际 HTTP、MCP、生产前端与本机 npx 候选使用相同冻结输入；部署后重核运行身份，不借用旧包/旧测试证明当前实现。
