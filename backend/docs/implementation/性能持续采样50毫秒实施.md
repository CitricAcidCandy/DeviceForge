- `crates/domain/src/performance/mod.rs`：`PerformanceStart.interval_ms` 的模式最小值、领域校验与错误文案由 1000 改为 50 毫秒，上限仍为 60000 毫秒。
- `crates/domain/src/performance/tests.rs`：新增就近纯规则测试，覆盖 50 / 49 / 0 / 60000 / 60001、模式上下限和 0 / 1 / 3600 / 3601 秒时长边界。
- `crates/application/tests/performance.rs`：既有公开操作模式测试增加五个间隔边界；新增真实时钟与 SQLite 的 50 毫秒会话测试，分别使用快探针和耗时超过周期的慢探针，断言一秒内 3–20 项已落库样本、最大同时采样数为 1、相邻执行时间不重叠、到期后无活动采样。
- 同步[性能会话接口](../contracts/性能会话接口.md)。共享生成文件、worker、其他会话及资源恢复实现不在本批写集；根进度由主代理集成记录。

## 调度与不变量

CodeGraph 核对 `crates/application/src/performance/worker.rs` 的 `run`、`tick` 与 `execute_sample` 后确认：现有 worker 使用固定周期 `tokio::time::interval`，配置 `MissedTickBehavior::Skip`，并非完成后延时。

首个 tick 立即就绪；worker 串行等待 `tick` 返回，包含采样与落库，再检查会话状态并等待下一 tick。慢采样结束时如果一个 tick 已过期，可以立即开始下一次采样；该过期 tick 被消费后跳过其余错过的周期，保持后续周期网格，不逐个补发积压。暂停恢复仍立即重置 tick。间隔下限变更不修改这一调度策略，也不为 50 毫秒引入并发、积压队列或每样本额外任务。

时长继续为 1–3600 秒，暂停仍计入总时长；每会话上限仍为 3600 样本。单样本仍取准入加 10 秒、会话期限与来源能力预算中的最早绝对截止点，清理沿用唯一 2 秒窗口。会话容量、采样工作池和存储工作池均保持原实现。50 毫秒只表示允许的请求周期，真实频率受采样、存储及工作池等待限制，不构成真机 20Hz 或开销达标承诺。
