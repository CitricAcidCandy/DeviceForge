# 安卓设备插件安装与截图接缝草案

日期：2026-10-10。状态：独立候选，未冻结公共契约、未授权生产实现。本文件接续已冻结的《安卓设备插件第一批契约草案》，只整理随后 app.install、screenshot、app.install_apks 三流，不改七离散能力或 daemon 策略，不以文档计设备迁出完成。

本次安装侧车 `application/splits/InstallApksOperations` 只保留旧 android.app.install_apks 注册与入口预检，仍调用 SplitPackages.install；这不是协议4设备插件，不新增安装 context 端口，也不证明安装工作已沿原 D 运行。侧车保留期间 AndroidSplits 与其部署依赖仍在宿主，不能因七项纯包工具撤除而删除。

| --- | --- | --- |
| APK安装 | infrastructure/src/device_artifacts/mod.rs:install：materialize .apk → adb -s serial install 私有路径 → Success确认，诊断私有路径换原filename | capability/短operation=app.install，device/write，version=1；业务 `{artifact_id,output}`，无输出产物；旧android.app.install。 |
| 截图 | 同模块:screenshot：adb -s serial exec-out screencap -p → 有界文件 → ArtifactStore.put | capability/短operation=screenshot，device/read候选，version=1；固定screenshot.png声明，旧android.screenshot投影真实Artifact。 |
| APKS安装 | infrastructure/src/splits/mod.rs:install_with_timeout：materialize .apks → validate_source → bundletool install-apks --apks=私有路径 --device-id=serial --adb=管理员解析的程序 | capability/短operation=app.install_apks，device/write，version=1；业务 `{artifact_id,device_id,installed:true}`，旧android.app.install_apks。 |

**纠正上一草案末段的候选依赖：** 当前 APKS 安装不是宿主先探测 DeviceSpec、离线 extract 再逐个 install。第一候选应保留真实 bundletool install-apks 及既有结果，APKS 输入资格由公开核心校验。Java工具内部如何选包/启动ADB须另取证；不能把“依赖 DeviceSpec/显式提取”写成现有宿主行为。若改为显式提取多APK再安装，是另一方案，须先冻结设备探测、选包、安装事务和成功语义，不能趁迁出扩大行为。

三流沿 API3/协议4，清单及Request短名、外部ID plugin.android-device.<短名>。设备贡献不填普通 Contribution.execution，七项首批和三项追加清单合并时无重复名字、能力ID或版本。安装不是普通包插件业务，不能绕设备屏障/锁经普通operation提交。

## 嵌套产物与严格 DTO

安装真实插件 Request.input 候选如下，封套和内部对象均拒未知字段，device_id非空且为当前稳定local ID，artifact_id规范UUID：

```json
{
  "device_id": "192.0.2.1:5555",
  "input": {"artifact_id": "3b9e35ac-f5b1-422f-a9eb-5024e7f8f7be"}
}
```

截图 Request.input 为 `{"device_id":"serial","input":{}}`。provider_id/generation保留在宿主动作/归属层，不重复传进业务对象；调用者不选文件、adb、Java或任意参数。旧名称 input.device_id 由通用device_envelope映射，不另做平台专用HTTP路由。

候选统一 ArtifactAccess 如下。两个安装共享唯一pointer；截图没有该字段时宿主不读取输入store，但SDK outputs权限仍由声明控制。

```json
{
  "input_fields": [],
  "input_pointers": ["/input/artifact_id"],
  "outputs": true
}
```

宿主现有 selectors 先验证全部选择器和实际值，坏类型/中间非对象在读store或建temp前拒绝；SDK ArtifactInput.field保持原pointer `/input/artifact_id`。插件只按field+相同ID匹配唯一行，不能任取inputs[0]或回落顶层artifact_id；同ID多行但field不同也不能借未授权行。缺行、重复匹配、size/sha256错误、链接/重解析点、特殊文件和大小超限全部在工具启动前拒绝。

插件侧须限64MiB并在同D_L下核普通文件/元数据/完整SHA256，先复制至自己的稳定私有输入。宿主授权路径只用于此复制，后续工具只用私有路径；目录lease不能延长宿主目录本身。app.install只接受.apk，app.install_apks只接受.apks，扩展名与实际结构资格分开；ZIP/APKS核心并不证明Android安装兼容或签名真实。

android-packages当前Session准备的是顶层field=artifact_id，不能直接拿来匹配设备封套。候选新接缝为设备Session的输入选择规格、唯一元数据匹配、私有copy和有界worker；准确Rust签名由主代理另冻结。需要阻塞核心校验时使用原D_L与只读取消回调，permit/lease移入实际闭包并持到真实结束；外层Future丢弃不等于闭包停止。

| 旧ID | 输入映射 | 结果映射候选 | 不得伪造的来源 |
| --- | --- | --- | --- |

| android.screenshot | device_envelope | Artifact filename=screenshot.png | 仅从宿主实际发布列表唯一匹配取得Artifact，不能返回插件私有路径或业务JSON实体冒充。 |

协议4业务返回公开runtime Output/ArtifactOutput，由宿主真实PublishedArtifacts通道处理；旧别名不能凭result外形猜包装。成功安装/截图、文件移交和资源清理是分别的资格；清理未确认禁止返回成功或输出，prepare创建私有目录后发生清理失败也必须cleanup=failed，不能一律Execution::complete。

插件内部坏包/配置/工具错误仍受当前Response.error字符串边界约束，不靠文案还原宿主Invalid/Storage/TooLarge。提交schema继续invalid_input，目标/代际/设备状态继续已有not_found/conflict，超时/取消/清理失败继续公开通道；实际HTTP/MCP精确类别须验收，不能接受任意4xx/5xx。

## 同一期限、工具与目录资源

三流在宿主统一设备准入下获取provider read，两个install再取provider ID+stable local ID写锁；screenshot候选read也受provider write屏障。直接jobs和旧别名必须按真实贡献固定scope/access；取消/卸载/旧代及cleanup_failed拒绝新提交与获锁后的待执行任务。不同插件进程里的Mutex不能替代宿主稳定键互斥。

候选能力总预算 app.install=120000、screenshot=30000、app.install_apks=120000毫秒，全部待裁定。已存在能力上限120000不变，超上限需求先公共版本设计，不给设备Contribution.execution另声明长普通预算。宿主从准入起固定D，本地握手获得D_L；输入复制、核心、排队、工具、文件监测和输出发布全用同D_L，不逐阶段重授。工具短限额是否另取min(D_L,工具启动+短限额)，继续第一批预算待裁定政策。

旧基线须分开记录：APK安装工具120秒，输入物化还有旧阶段期限；截图工具30秒后，旧发布另限120秒；APKS旧install_with_timeout整段120秒。安装侧车当前普通注册还可能受应用默认有效预算约束；这些常量不是已证明端到端可用时间，迁出候选数字不能宣称与旧每阶段相加等价。

APK安装固定 `adb -s serial install <私有copy>`，不加调用者自由flags。APKS固定管理员Java前缀与 `bundletool install-apks --apks=<私有copy> --device-id=<serial> --adb=<管理员确定的可执行路径>`；其中--adb部署解析不能来自请求或SDK filename。Java固定-Xmx256m -jar政策可复用已裁定包插件，但准确配置入口仍须设备插件自己的裁定，不复制宿主APK_*读取。

APKS核心沿Archive/validate_apks资格，完整验证放有界worker且保持稳定输入；不额外复制ZIP算法。APKS资格不执行设备命令，不替代安装成功判定。旧失败诊断与真正设备安装结果须分别复验，禁止以伪造的Success或installed=true响应证明真机成功。

截图固定 `adb -s serial exec-out screencap -p`，使用capture_to_file_with_lease写私有固定文件，stdout文件上限候选64MiB、stderr默认1MiB；超限失败不声明产物。关闭写端、确认工具结束后，再做文件资格并复制至SDK output_directory；工作路径不由调用者提供，file/open/复制都复核D_L与普通文件/非重解析点。旧代码没有完整PNG解码资格，若增加8字节PNG签名或完整块CRC/图像解码，须明确新增规则与依赖；仅签名不等于完整PNG验证，不假称沿用旧行为。

所有直接子工具、worker、监测和目录删除各有真实结束跟踪；闭包/工具持permit与lease至结束。任何CleanupFailed、仍在飞工作或目录删除未确认粘性保留，不把后来正常结果清零。删除只在确认本次资源结束后清自己的目录，不扫描删除部署目录、用户产物或历史scratch。

**APKS额外清理缺口：** bundletool Java可能派生ADB客户端，标准ADB还连接共享daemon。tool-process直接PID租约仅确认Java直接进程，不递归证明派生客户端/daemon退出；杀Java也不能证明设备端安装中止。若要求本次启动的派生资源全排空，须先冻结可取证的工具部署/派生进程策略；不能靠隐含进程树能力、kill-server或cleanup字符串补洞。若范围仅声明直接客户端和私有工作目录，则须列可持续外部行为和目录占用风险，不能删除仍可能被子进程使用的输入。

宿主现有合作窗口与公共工具最多2秒清理不是可串行累加的预算。设备Session应以一次固定清理点收口并留帧返回时间；宿主可能在1250毫秒合作期限后强制终止插件，因此工具租约在插件进程内的后台wait不跨强杀存在。遇不确定性返回failed/draining并保留资源，不把延长业务D或杀插件当确认；具体取消流程先以真实子PID和目录占用回归验证，再裁定发布资格。

## 三个实施前置与候选文件所有权

1. **上游设备配置与资源政策冻结。** 第一批provider、能力名字/可用矩阵、ADB路径来源/daemon所有权/预算有正式裁定；设备Session公开本地D、单槽worker、tool/file输出lease、私有copy、finish准确接缝。不能在本段暗选server启动或性能热卸载。
2. **产物与工具资格冻结。** 嵌套pointer匹配规格、APK/APKS限额/结构、截图PNG最低资格与真实旧投影；bundletool/Java/ADB管理员来源和Java派生客户端处理有明确可验承诺，缺口阻断需要该承诺的能力发布。
3. **真实验收与撤除顺序冻结。** 新三流先独立协议/假工具+真实包，再HTTP/MCP/热装卸与实际设备；有证据后主代理撤除宿主对应Android安装/截图和APKS侧车装配。fake工具成功只计契约，不计Android设备安装或截图真实性。
