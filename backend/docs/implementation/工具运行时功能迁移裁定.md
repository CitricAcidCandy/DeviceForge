# 工具运行时功能迁移裁定

日期：2026-10-12，UTC。模式：架构优先；本批只迁移工具供应的运行时功能查询和准备，不扩展通用宿主或产品界面。

后续来源缓存批次遵守[工具来源缓存回退裁定](工具来源缓存回退裁定.md)，五项清单操作新增外层来源及摘要元数据并允许有效版本携带来源错误；本文原先“不新增缓存”及空版本降级描述保留为第一批边界，不覆盖后续契约。准备子项仍保持原四字段，取消、到期、本地损坏和缓存硬错误不转为来源错误。各批实际通过范围见[六项业务迁移实施](六项业务迁移实施.md)。

## 目标与旧业务依据

旧 `src/main/tool_updater/service.ts`、`runtime_feature.ts` 按清单中的 `type=runtime` 和 `featureKey` 查找模块，同一功能可以匹配多个模块。新业务以部署者清单为唯一映射，不把开发时的 `case-assistant → codex-sdk` 回退写成生产映射，不动态载入 Node 模块，不接受服务器程序、来源或安装路径。

公开贡献：

- `plugin.tool-supply.runtime_feature.status`：查询功能的完整清单匹配与本地安装资格。
- `plugin.tool-supply.runtime_feature.prepare`：使用同一清单快照按清单顺序准备全部匹配模块。

输入均为 `{feature_key: string}`，拒绝额外字段。功能标识沿用现有清单规则：非空、UTF-8 编码不超过 128 字节；不套用模块 ID 的 64 字节、字符模式或 Windows 保留名规则。

## 公开结果

`status` 返回：

```text
{feature_key, manifest_version: string|null, source_error: string|null,
 found: boolean, ready: boolean, modules: ToolModule[]}
```

`ToolModule` 沿用清单/计划结果的字段和动作。只有匹配模块均为 `current` 且入口存在，整体才 `ready=true`；已有更高版本不能等价替代清单指定版本。版本、SHA-256、类型、功能归属、入口及归档根均须符合现有安装资格。这里验证的是托管安装状态和入口，不宣称重新哈希全部安装文件或实际 SDK 可执行。

- 未知功能：来源正常，`found=false`、`ready=false`、空模块列表。
- 来源读取/清单验证失败：结果成功返回，版本为空，`source_error` 为既有脱敏错误，`found=false`、`ready=false`、空模块列表；取消和到期仍失败，不转为普通来源错误。
- 本地安装状态损坏、未确认清理或其他本地错误继续失败，不伪装成未安装。

`prepare` 成功返回：

```text
{feature_key, manifest_version: string, ready: true,
 modules: ToolInstallation[]}
```

`ToolInstallation` 沿用 `{module_id, version, sha256, changed}`。返回至少一个且唯一的模块，顺序与清单一致；不返回绝对路径或凭据。该结果证明本次准备成功，不承诺之后其他调用不能移除或升级这些模块。

## 事务、取消与来源边界

只读取一次清单，全部匹配从该快照选取。不能循环调用原 `Install` 入口，否则会反复读取清单并漂移。抽取共享单模块快照安装函数，旧单模块安装仍先取得模块锁再读取清单，保持与移除的在途互斥。

准备按清单顺序安装，使用原绝对截止点、取消信号和每模块锁，不重置预算、不自动降级。未知功能、来源或任一模块失败使 Job 失败；前面已提交的模块保留，当前模块按原事务恢复，后续不执行。取消、失败及清理未确认不能吞掉；后续 `status` 可观察部分结果。不是跨模块全有或全无事务。

清单来源缓存回退是独立兼容缺口，本批不新增缓存，也不宣称与旧工具更新器完全等价。真实发布来源、SDK 执行、模型和跨平台继续独立验收。

### 查询与在途安装的清理资格

查询前保留全局稳定本地状态预检，未知功能和来源错误不得掩盖损坏状态或真实遗留事务。预检枚举已托管模块与事务归属，读取每个模块状态前取得对应模块锁；锁竞争是普通 `Busy` 业务失败，不能返回 `Cleanup/Failed`。取得锁后仍存在对应事务才表明清理未确认；不持有跨模块锁集合，也不把清单网络读取放入全局锁。合法准备中的暂存条目或目标替换窗口不能作为未确认资源证据。

验收同时覆盖准备首块下载门闩期间的查询、取消后重新查询、未知功能和来源错误下的稳定损坏，以及真实遗留事务。业务失败和合作清理资格分别断言，避免查询失败将本可继续使用的插件错误地留在draining状态。

## 职责与落点

| 单元 | 负责 | 不负责 | 输入/输出与副作用 |
| --- | --- | --- | --- |
| `src/input.rs`、插件清单 | 两操作严格输入和执行预算声明 | 业务选择、下载 | 输入解析，无业务副作用 |
| `src/feature.rs` | 单快照选择、状态聚合和顺序准备 | 解压细节、宿主装配 | 读取来源/安装状态，调用共享安装 |
| `src/operations.rs`、必要独立安装模块 | 既有四操作、共享快照安装 | 硬编码功能映射 | 复用锁、下载、校验、事务与清理 |
| `src/feature_tests.rs` | 多模块、失败无损、快照、取消和资格回归 | 放宽生产期限 | 临时文件、ZIP、本地 HTTP |
| 前端 `features/tool-supply` | 严格结果解码、任务恢复/取消、公开类型 | UI、SDK 执行、服务器路径 | 公开 Job 端口与日志关联 |
| 独立服务驱动 | 真实 HTTP/MCP 与安装状态核对 | 生产实现、真实 SDK 验收 | 合成来源、真实宿主/插件 |

推荐共享快照安装，拒绝反复调用旧入口的捷径；不新增宿主分支。文件过大时仅拆出安装职责，不进行无关结构整理。前后端和独立驱动文件写权由主代理另行分配；生成类型仍只由主代理运行生成器。

## 开发与验收

采用契约先行加行为测试：先固定未知/来源失败、多模块和部分提交语义，再实现共享安装，最后进行真实服务与分发。最低证据包括输入字节边界、仅匹配 runtime、全部准备及重复准备无下载、缺入口/错归属/错摘要资格、来源只读一次、第二模块失败后首模块保留且第三模块未执行、原预算取消/到期及未确认清理、前端错结果/错票据/不重复提交及日志关联。

后端和前端遵守所属 AGENTS 的完整门禁；原批次交互夹具和性能 smoke 的失败保留，不能借记旧通过或用本批局部通过覆盖。新生产冻结后重建当前二进制，服务、原包与 npx 按实际修改范围重新验证。
