# 普通期限共享传输兼容裁定

本裁定补充普通总期限批次的共享端口行为，不改变原冻结清单字段、公开 JobStore/Executor 签名或预算。设备发现和能力继续使用各自既有预算，性能专用采样独立。

普通期限第一批契约规定：共享截止点已经经过时诊断 Timeout，否则显式取消诊断 Cancelled。ProcessPlugin、受限副作用检查及合作传输复用该规则；它们收到 ExecutionContext.deadline 后不按平台名称或当前贡献名称另选取消优先级。因此设备适配器通过同一公开传输端口直接调用时，也遵守已过 D 优先 Timeout。context None 保留未到期取消兼容；这是一项可见错误分类迁移，不将它描述为旧分类完全不变。

原 device_deadline_fixtures 用例在 token 已取消且 D 已经过时期待 Cancelled。本批真实执行返回 Timeout，233316门禁报告及失败夹具原件保留。用例改为分别严格断言：未到期为 Cancelled、已经到期为 Timeout；两协议均保留产物读取零次、进程零启动和资源无未确认风险的断言，没有修改生产去迎合用例。

CleanupFailed 是资源风险，不能由到期或取消覆盖。已观测风险在等待存储槽前短时记录，失败事务重试保留；已有终态资格及实际终态保持，不因为后来风险改写历史。owner 的未确认状态仍单独保留，不能由 Job 成功、取消或进程退出清除。

发现目录的 Pending/Cancelled/Accepted 门禁仍沿统一发现契约；当前目录接受与 Job 历史终态分别裁定。共享传输错误分类不绕过目录取消请求、当前 generation、来源及清理校验。

本文件是实施兼容裁定，尚须新版完整门禁及真实 HTTP/MCP/浏览器/release/npx分别验收；旧分发或单项通过不代表本批完成。
