# DEX 产物资格接缝

日期：2026年10月12日。直接分析插件已通过26项，但现有上传后缀白名单不接受DEX，插件库通过不能证明HTTP业务可使用。本批补齐上传、授权元数据及原字节下载之间的通用文件接缝。

## 职责与契约

- 既有产物存储接受不区分大小写的`.dex`，媒体类型为`application/vnd.android.dex`；仍仅使用产物ID，不向浏览器开放服务器路径。
- 单文件上限为64MiB与部署上限的较小值，流式写入提前拒绝超限；上传许可、受限验证工作池、原子发布和失败清理保持原行为。
- 最低资格只读取44字节前导并核对文件实际长度：至少112字节，标准035/037/038/039/040标识、112字节头、little-endian、头内file_size等于实际长度。
- 完整主索引、映射、字符串、类定义、SHA1、Adler32与SDK证据仍由独立DEX插件负责。最低资格通过不宣称文件完整有效，也不允许把DEX当ZIP预览。
- HTTP/MCP、领域端口、公开SDK及生成DTO没有新增业务分支或新结构。上传与插件产物资格共用现有内容检查入口。
- 真实服务首轮发现通用插件输入副本白名单遗漏`.dex`，上传成功后仍在任务准入失败。现已在`plugin_artifacts`补该后缀，继续复用授权选择、总量限制、SHA256核验与私有副本清理；首轮失败原件保留，完整调用链修后另验。

## 验证要求

定点覆盖分块上传、大小写后缀、元数据与原字节下载、头内长度及编码拒绝、错误不发布、较低部署上限、提高部署上限仍提前限制64MiB。实际HTTP上传后调用插件inspect/scan_sdks、原Job共享查询、日志和卸载另行验证；库回归不替代这条服务链路。
