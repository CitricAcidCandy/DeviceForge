# 包工具退出与目录租约裁定

日期：2026-10-10。模式 architecture-first / Hybrid，沿已批准包工具取消、丢弃及真实资源所有权目标修复总监 P1。本批不改变公开业务 DTO、SDK 协议、期限或派生树范围。

## 结论与影响

现有 Tracker 只保留未确认标记，工具 Future 丢弃会直接丢弃 Child；kill_on_drop 不是退出确认，临时目录的最后 Arc 也可能提前释放。选择公共工具库持有直接 Child 与调用者租约直到 wait 成功；不使用等待固定两秒后删除目录或仅保存布尔标记的方案。

新增公共 capture_with_lease / capture_to_file_with_lease 加法入口，接受调用者 Arc<T: Send + Sync + 'static>。原 capture、capture_to_file 和 ExecutionOptions 的 Copy 及字段兼容不变。正常完成和有界错误清理确认后释放租约；CleanupFailed 或 Future Drop 把 Child 与租约交给后台真实 wait 所有者，业务错误仍立即按原两秒窗口返回，不更新业务 D。后台等待失败或运行时被关闭时保留租约至进程退出，不能冒充已清理；调用者仍负责并发和 sticky 风险诊断。

## 文件职责

| 单元 | 输入输出与职责 | 副作用与边界 |
| --- | --- | --- |
| tool-process/ownership.rs | 直接 Child、可选资源 Arc；确认后释放，未确认转后台持有 | 不导入宿主或平台，不解析输出；只确认直接进程，异常保留租约 |
| tool-process/execution.rs、lib.rs | 新加法入口与共同执行实现 | 保留原 argv、环境、限额、D及错误；旧无租约入口兼容 |
| infrastructure/process.rs | 部署工具与 Temporary 映射至公共租约入口 | 错误分类、stdout/text 和受限环境沿旧约定 |
| package_tools/tool.rs 及七操作工具调用 | 每实例风险与本次实际 Temporary 交接 | sticky 风险不由后续成功清零，不将目录删除当进程退出证据 |
| 独立测试 | 真实 PID 退出先于资源 Drop，正常/取消/丢弃 | 不通过输出字符串伪造清理，无法确定性触发的 CleanupFailed 明示缺口 |

后台所有者不获得第二个业务或两秒同步收口窗口；仅持有既有工具等待真实退出。其存在不表示派生树、文件删除和 staging 全部排空。原工作池四槽和 server 包 worker drain 范围不扩大。

先补所有权组件和真实工具租约回归，再复核七操作接线，执行当前完整门禁及受影响服务/退出回归。此前运行通过不能借记新增租约版本。
