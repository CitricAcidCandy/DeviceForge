# 历史清理告警与新任务解耦

日期：2026-10-23，Asia/Shanghai。用户最新明确本地个人项目，以可持续使用为先，不以历史清理诊断永久锁住整个插件。

2026-10-26 文档收口：本文为实施导航，长期规则以[资源故障隔离与后台回收裁定](资源故障隔离与后台回收裁定.md)及两端 AGENTS 为准；相关前端约束见[插件清理告警与重试约束](../../../frontend/docs/contracts/插件清理告警与重试约束.md)。本次固化文档不代表部署或最终验收已完成。

## 决定

历史 `cleanup_failed` 是诊断，不是新任务准入条件。一次真实清理失败仍应失败并记录，后续独立进程、任务、设备发现与性能会话可以继续；另一笔晚到失败不能覆盖本次已取得的成功结果。新成功也不清零历史失败。

通用宿主按调用归属裁定成功、取消、超时和清理，不再在提交、排队、完成、设备、性能来源、交互打开等位置反复检查同一插件历史布尔值。前台打开会话不先等待全插件恢复，恢复保持独立入口与后台续办。恢复任务之间可以短暂互斥；只有真实冲突的资源约束对应调用，不能仅据 recovering 布尔值冻结新业务。

## 职责

| 单元 | 负责 | 不负责 |
| --- | --- | --- |
| application 执行与完成 | 本次调用有界清理、结果归属、任务终态与旧代际撤销 | 用其他调用的历史告警否决当前成功 |
| registry、设备与性能来源 | 当前注册代际、在线能力、真实活动登记及并发 | 永久冻结出现过清理失败的插件 |
| 进程插件与交互 provider | 每次独立调用、进程退出、当前清理回执与历史告警 | 把共享历史状态当本次失败 |
| 插件资源租约 | 真正在用的工具租约、退出后的释放、外部债务诊断 | 让退出的旧调用永久占用活动额度与工具读锁 |
| 安装生命周期与文件存储 | CAS 修订、真正文件事务恢复、启停更新 | 把旧组件装卸告警当文件损坏永久拒绝 |
| 前端 | 可见错误、日志与手动重试、操作中串行与显示限额 | 用旧清理标记灰掉后续功能 |

真实在途进程、活动文件锁、同设备独占资源、恢复任务之间的互斥、代际撤销、取消截止点、容量上限继续保留。它们是运行稳定性约束，不是增加鉴权、网络来源审批或多用户安全模型；后台恢复不阻断普通独立调用。

安装记录中 component_cleanup、activation_cleanup、enable_cleanup、activation_reload、startup_activation、unload_rollback、configuration_rollback、disable_rollback 可以正常重试；activation_rollback、commit_rollback、transaction_* 及未知原因仍需要核对真实文件状态。前后端与存储使用同一规则，避免上层已放行而下层继续拒绝。

## 范围与排除

此规则适用宿主、普通任务插件、公开交互入口和性能采集。Android/Harmony/Frida/自动化等每次调用内的真实清理结果仍保留；AI 原生线程上一轮结果未知不自动重放，独立新线程可用。

用户最新指定投屏插件由另一个代理处理。本轮不修改 `backend/plugins/mirroring` 的业务、持久台账、控制权和恢复实现，也不执行投屏设备验收；共享宿主改变会惠及该插件，但不算其内部问题已修好。

## 验证要求

至少覆盖：失败后下一独立调用成功、并行与排队成功不被另一失败污染、告警仍可查询、真正本次清理失败仍失败、旧代际仍拒绝、活动资源仍互斥、退出进程不占工具租约，以及 50 ms 性能会话请求实际接受。真实服务和三星新 run 另行记录，不以测试夹具替代。

此前文档中“任意未确认标记永久拒绝整个插件”的描述是旧策略，不作为本次交付标准。保留失败原件，实际门禁与运行版本写入验收记录和根 todo。
