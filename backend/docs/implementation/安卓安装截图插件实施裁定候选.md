# 安卓安装截图插件实施裁定候选

日期：2026-10-10。版本：v2，公开源码核对完成，主代理已冻结实施裁定并开放生产。本文接续android-device首批八短贡献/七能力及宿主残余侧车，目标追加APK安装与PNG截图两能力，随后撤除宿主对应两条装配；APKS安装、Harmony、性能及常驻会话保持独立。冻结责任、接口与失败规则见[安卓安装截图插件实施裁定](安卓安装截图插件实施裁定.md)，本候选保留取舍依据，不充当实现或测试通过证据。

选择在同一android-device提供者追加两能力，以复用真实provider/generation、stable local_id和宿主设备锁。若另开android-artifacts提供者，相同ADB serial会落在不同providerID锁键，不能自动与首批input/uninstall互斥；因此本候选不采用独立第二provider规避现有所有权。没有新的设备SDK版本、Request字段或平台HTTP路由需求。

## 两贡献、严格输入和结果

| 项目 | APK安装候选 | 截图候选 |
| --- | --- | --- |
| 短贡献与能力ID | app.install，version=1 | screenshot，version=1 |
| 外部完整ID | plugin.android-device.app.install | plugin.android-device.screenshot |
| scope/access | device/write | device/write；与现有动作串行以得到明确执行次序 |
| 真实Request.input | `{device_id:<原文serial>,input:{artifact_id:<规范UUID>}}` | `{device_id:<原文serial>,input:{}}` |
| 普通预算 | 不声明Contribution.execution | 不声明Contribution.execution |
| 能力总预算候选 | 120000毫秒 | 30000毫秒 |
| 工具短点候选 | None，直接原D_L | None，直接原D_L |
| 固定argv | `-s serial install <插件私有input.apk>` | `-s serial exec-out screencap -p` |
| runtime Output.value | `{artifact_id,output}`，保留旧字段；输出私有路径替换原filename | null，产物实体仅由宿主真实发布生成 |
| runtime Output.artifacts | 空 | 唯一`ArtifactOutput { filename: "screenshot.png" }` |
| 旧名称投影 | android.app.install：device_envelope，Value wrapped=true | android.screenshot：device_envelope，Artifact filename=screenshot.png |

两层输入都是strict object；serial继续宿主宽原文资格，artifact_id必须36字符标准连字符UUID，类型/未知字段在读配置、建目录、读产物或启动工具前纯拒绝。不接受路径、tool、flags、预算或server端点。实际Request只接受短名，不兼容错误完整名。

追加后清单共十贡献、九能力，discover仍不算能力。两个manifest逐字节同源；两新能力只在online设备availability中声明，连同已有五device能力共七项，非online均false且固定有限reason。connect/disconnect仍provider/write、不放入每台设备列表。旧特殊原状态继续unknown并原文保留，不因为添加安装/截图放行recovery/sideload/bootloader。

截图若选read，只持provider read屏障，没有device写Mutex，会与input、安装、卸载并发。经主代理意向核对，实施输入选择write作为明确串行政策；schema、清单、矩阵、直接Job与旧别名都必须同源。dispatched/Success/PNG资格不证明真机UI、包安装完成后可运行或截图内容符合期待。

## 嵌套产物与授权目录

候选ArtifactAccess为`{input_fields:[],input_pointers:["/input/artifact_id"],outputs:true}`。声明属于整个插件；七旧动作及discover没有此字段时，宿主选择器不读输入store，协议4合法Some空ArtifactContext仍被接受。当前lib只拒非空inputs，不能把它原样沿用到新安装；应按已解析Input明确安装需要一行、其它操作不得携带输入行。不能回到把Option::Some本身当错误的旧边界。

安装必须在Request.artifacts.inputs中唯一匹配`field == "/input/artifact_id"`且artifact_id与业务输入完全一致；禁止任取第一行、顶层field=artifact_id回退或从同ID其它field取得路径。首批只接受这一行，额外/重复/缺行均提前拒绝。SDK ArtifactInput字段实际为field、artifact_id、filename、size、sha256、path；ArtifactOutput只有filename，**没有path字段**。插件不能把私有路径或自造Artifact实体写成输出声明。

安装输入限64MiB、filename以.apk结尾；匹配元数据后验证普通文件与路径祖先无链接/重解析点/特殊文件，流式校真实size和完整SHA256，并写插件独占目录的固定input.apk。计数同时受声明size与64MiB约束；超限、提前EOF、hash不一致、路径变更/换文件失败都零工具。后续ADB只读已验证的私有copy，宿主临时授权path只用于准备。稳定内容是调用者约束，不把同一File误称不可变快照。

旧上传APK检查的是ZIP元数据路径/条目/声明体积资格，旧安装又检查扩展、size/hash；它不做完整签名验证或保证可安装。本批不能偷偷提高为必须经过完整AndroidManifest解析、CRC遍历或签名验证再称“兼容迁出”。推荐保持旧输入资格与私有copy校验；若主代理要加公开核心结构校验，必须显式裁定profile、错误与附加预算，实际阻塞工作另入有界池并持lease至结束，不复制ZIP算法。

截图先从ArtifactContext取唯一output_directory授权，不从业务输入或插件配置猜宿主路径；路径与每段祖先检查为普通目录且无链接/重解析点。原文件写在插件独占目录screenshot.png，不让ADB直接写宿主输出目录。工具真实退出并关闭写端后，复查文件归属/size/最低PNG资格，再沿同D_L复制至授权目录固定screenshot.png，失败不声明产物。

最低PNG资格推荐准确保留现宿主规则：至少45字节；前8字节PNG签名；随后4字节长度13与IHDR；宽、高都非零。不是只看8字节，也不是完整块CRC或图像解码。可用有限头读取纯规则在本插件落盘，无新图像库；宿主实际发布仍执行自己的资格。输出文件最多64MiB，stderr最多1MiB；两者超限禁止成功声明。完整PNG解码及真机图像内容继续独立验收。

## 公开执行上下文和清理收口

宿主从准入开始固定D，包含排队、provider/device锁、插件握手、配置、输入准备、工具、结果及宿主发布；插件只用InvocationContext本地D_L。每个下一I/O、工具首poll、复制分块与成功交付前复核到期/取消，None不是本协议4新授权预算。不按工具或阶段重新给120/30秒；到期与取消同刻继续公开Timeout优先，未确认清理优先于普通成功/错误。

当前android-device Control只有capture(args,short_limit)、check及finish(Result<Value>)，租约是Arc<()>；这能管理首批直接客户端，不能携带新增私有目录/文件所有权。下一批必须按职责加法，候选本地接口与名称仍待主代理冻结：

| 候选接缝 | 最小职责 |
| --- | --- |
| control.rs及control/file.rs | `capture_to_file`经公开capture_to_file_with_lease，原D_L、Restricted环境、64MiB stdout与1MiB stderr；工具lease绑定本次目录资源，不复制spawn/kill逻辑 |
| session.rs及session/directory.rs | 仅两新产物流创建独占目录，跟踪实际持有者、删除结果和粘性未确认；七旧动作不为新能力多建目录 |
| session/input.rs | 同pointer/ID唯一输入、元数据/链接资格、流式私有copy+hash，同D_L；不调用宿主ArtifactStore |
| session/output.rs | 有限PNG头资格、最终授权目录copy、固定filename与Output构造，不伪造宿主实体 |
| session/finish.rs或短小session.rs收口 | 真实工具/文件/复制结束后清自有目录；Error::CleanupFailed及目录删除未确认返回cleanup=failed，prepare失败也同收口 |
| operations.rs/lib.rs | 纯parse后按Input选择旧无资源Control或新Session；内部结果支持runtime Output，旧七值通过Output::from保持，外部execute(Request,InvocationContext)->Execution不变 |

工具/复制和实际文件句柄到真实结束才释放目录lease；外层Future丢弃不能先删仍在使用的input.apk或screenshot.png。不能先把TempDir丢给Drop重试，然后宣称cleanup=complete；也不能把ToolGuard::confirmed只代表直接PID确认扩成目录删除确认。SDK授权输出根仍归宿主，本插件只复制它自己的固定目标文件，不删除根或其它文件。

源码核对后修订文件执行选择：Tokio文件I/O可能由后台阻塞工作执行，丢弃读写Future不能证明文件句柄已结束，故输入/输出分块复制、有限头规则和自有目录建删走每调用单槽、显式追踪的受限阻塞工作；闭包持有目录租约至真实返回。截图仍通过公开文件捕获接口，另由独占文件任务持有实际Tokio File，在捕获结束后排空文件I/O并关闭句柄，再释放租约；不复制公共进程所有者。具体丢弃、排空和删除确认见实施裁定。

配置选择严格format1的可选绝对scratch_root，缺省系统临时根；存在的每段祖先必须为普通目录且无链接/重解析点，请求不能指定。既有七动作和发现不因新字段创建工作目录。不能把android-packages私有Session或宿主Temporary直接链接进独立插件，不能改变部署者所有的共享ADB server责任。
