# 统一发布安装集成验收

## 契约与实现

统一发布契约见 `../contracts/统一插件安装v1.md`。完整安装写入走 `installation.*` 任务，HTTP/MCP 共用同一用例。宿主从 `DEVICEFORGE_MARKETPLACE_CONFIG` 或 `DEVICEFORGE_MARKETPLACE_SOURCES` 读取允许的市场目录；未指定时使用本机7040。配置文件兼容 CLI 的来源格式，大小、来源数量和 URL 均有界，安装资源不得跳转到其他来源。

安装进度复用既有任务事件，阶段为 preparing、downloading、verifying、deploying、activating、complete，下载事件附已完成字节、总字节及资源摘要。不会把服务器绝对路径写入公开进度。写入节流250毫秒；提交之后的进度存储故障不能触发发布回退。取消与超时使用原始任务截止点，排队变更获取生命周期门禁后再次检查取消。

资源清理入口为 `POST /api/v2/plugin-installations/cleanup`，返回任务。默认 `dry_run=true`；实际执行由生命周期锁内的运行组件集合与持久发布引用共同保护，客户端不能自行声明资源空闲。

## 调用配置池与工具校验池的交付审查

调用侧 `invocation_path`、`resources_path` 使用2个执行名额与8个等待名额，普通配置编辑继续保留原有立即拒绝策略。配置读取的等待由调用方 `execution_deadline::run` 消耗原取消令牌与绝对截止点；托管工具校验在池内沿同一取消令牌与绝对截止点等待。没有资源描述的普通调用直接返回，不占校验池。已启动阻塞工作的执行许可和仓库读租约由真实闭包持有，不因外层 Future 丢弃提前释放；未确认外部资源的保守租约语义保持原状。

本代理实际完成4个Rust文件的定向格式检查、5个相关脚本的 `node --check` 与定向差异检查，均通过。新增用例覆盖有界等待、取消、到期、Future丢弃、许可及读租约保留；本节不将这些用例记为运行通过，Cargo与release证据由主代理统一收口。阻塞测试使用5秒通道等待上限，并在观察到闭包结束后核对许可恢复；等待中的Future由测试容器显式丢弃，当前实现未见遗留等待者。另有测试健壮性边界：配置队列满时的错误断言及释放执行名额后的成功等待没有独立超时兜底，若未来实现退化为无限排队或许可泄漏，测试本身可能挂起；工具校验入口的等待仍受自身原deadline限制。

只读逐项核对18份源码发布声明，工具、必需标记与用户输入声明均与官方构包规则一致。Android设备的ADB必需，Java与bundletool可选；Android包工具的Java、apkanalyzer、apksigner、bundletool、apktool均可选，空工具配置仍有不依赖外部工具的精确APK提取与已解码ZIP扫描。当前工具库存明确省略这些可选工具及input-trace，不能据此宣称清单、签名、构建或解码扩展能力已取得工具执行证据。

可选工具接入仍有实质缺口：Android设备的bundletool及Android包工具的各对象入口由带 `kind` 标签的枚举解析；现有绑定仅注入 `jar` 或 `executable`，空默认配置中没有对应 `kind`，发布模板也未补齐。当前省略可选工具的包不触发该路径；将来包含这些工具时，不能仅凭安装成功宣称自动配置可用。须先以不覆盖用户值的方式补齐有效配置形状，并增加实际配置解析证据。本轮只读审查未修改此生产路径。

安装事务的活动写集固定为组件目录中的manifest、market、resources、installation四类文件；用户根中的 `plugin-configurations/server` 与 `browser` 不在发布切换和删除写集。已有用户状态优先读取，工具入口只生成有效快照，不覆盖保存值及修订。安装用例、资源准备与配置绑定按公开声明和组件归属工作，未发现按官方插件ID决定宿主安装行为的分支；官方发布暂存模板中存在按官方ID补默认值的发行规则，不能外推为宿主特例。更新、启停和删除在生命周期门禁内检查旧组件 `cleanup_failed`，发现后保留旧修订并持久化 `recovery_blocked`；对应新增回归的运行结果仍由主代理记录。
