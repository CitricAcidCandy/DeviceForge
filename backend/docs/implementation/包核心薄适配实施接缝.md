# 包核心薄适配实施接缝

## 状态与范围

本文是供下一批裁定的实施方案，文档冻结不等于接缝已实现。当前 `deviceforge-android-package-core` 提供同步、无宿主依赖的包结构与 Android 文本解析能力；旧 infrastructure 仍直接承担工具调用、产物副本、解析、打包与发布。本文只确定如何真实替换重复解析，不改变已冻结公共核心签名，不新增设备连接或平台调度分支。

实施依据为《包工具公共库第一批实施裁定》《平台适配器迁出实施》以及现有 `package_tools`、`bundles`、`reverse`、`splits`、`artifacts/validation`、`artifact_files`、`execution_deadline` 和公共核心源码。既有普通操作总期限与资源清理规则继续适用；以下新增接缝、工作池接入和部署配置方案仍须主代理裁定。

第一步允许同进程薄适配保留原领域端口和返回 DTO；第二步才把七项纯包操作迁至独立 Android 包插件；最后撤掉宿主直接装配与旧业务实现。`splits::install` 包含 ADB 与设备写锁，不属于七项纯包操作，不能随整个模块搬入包核心或包插件。PNG、JSON、MessagePack 验证也不属于 Android 解析迁出。

## 逐 API 替换

下表路径均相对 `backend/crates/infrastructure/src/`。公共核心路径相对 `deviceforge_android_package_core`，调用前必须完成原入口参数校验与资源准入。

| 旧接缝 | 公共核心 API | 必须留下的薄适配职责 |
| --- | --- | --- |
| `artifacts/validation.rs::archive`、`validate_archive` | `archive::Archive::open(File, ArchiveProfile::Structure, &Control)`；`Archive::directory()` | 普通文件打开、宿主错误转换、旧入口全目录重名拒绝。核心保留重复成员供观测，不能直接把旧拒绝行为变成接受。 |
| `artifacts/validation.rs::entries` | `Directory::entries()` | 保留原目录顺序、分页游标校验、`ArchivePage` 与宿主 `ArchiveEntry` 字段映射；不按名称重排后分页。 |
| `package_tools/manifest.rs::parse` | `android::parse_manifest(&str, &Control) -> ManifestData` | 补回 `artifact_id`、`format`、`module`，逐字段构造 `PackageManifest`；保留版本号原字符串、可空字段、权限集合及原 XML。删除旧 XML 解析循环。 |
| `package_tools/signature.rs::parse` | `android::parse_signature(&str, &Control) -> SignatureData` | 补回 `artifact_id`，映射 signer、scheme、report；临时路径替换与工具报告脱敏仍由适配器负责。删除旧报告解析循环。 |
| `package_tools/mod.rs::extract_apk` 的 ZIP 读取与复制 | `Archive::open` → `select_exact(&mut self, name, &Control)` → `SelectedEntry::copy_to(self, &mut File, limit, &Control)` | 保留选中名称校验、旧全目录去重、`create_new` 输出、副本 lease、64 MiB 上限和宿主真实产物发布；完整复制成功前不得构造业务成功结果。 |
| `bundles/validation.rs::check` | `Archive::open` → `android::validate_apks(&mut Archive, BuildMode, &Control) -> ApksSummary` | 保留输入/工具输出场景区分、普通文件预检、域 `BuildMode` 映射和 `apk_count` 返回；Universal 从 summary 取得 `universal_entry`。删除旧逐条解压/CRC/资格循环。 |
| `reverse/packing.rs::check`、`pack` | `archive::tree::scan(root, TreeProfile::Reverse, &Control)`；`tree::pack(&TreeSnapshot, &mut File, &Control) -> PackedTree` | 监测期允许未完成树，完成后才要求有效必要成员；旧 `files`、`unpacked_size` 取自 `PackedTree`，输出名仍为 `decoded.zip`。删除旧遍历、限长写器和 ZIP 打包循环。 |
| `reverse/scanning.rs::scan` | `Archive::open` → `android::validate_decoded(&Directory)` → `android::scan_sdks(&Directory, &[SdkRule], &Control)` | ZIP 全目录去重、规则 DTO 映射、补回 `artifact_id`。现有 `scanning::validate` 在读产物前执行；核心规则验证非公开，不能为了迁出而取消该入口预检。 |
| `splits/packing.rs::check`、`pack` | `tree::scan(root, TreeProfile::Splits, &Control)` → `tree::pack` | 保留监测期即拒绝非 `.apk` 的检查：读取扫描目录的普通文件成员后检查名称。最终空目录、坏 APK 与非 APK 错误分开映射；`apk_entries` 来自完成后的打包结果。删除旧 ZIP 打包循环。 |

`Archive::open` 接收拥有的 `std::fs::File`；`select_exact` 独占借用 Archive，返回值消费式复制至调用方借用的 File。输出必须是调用方新建的空普通文件，不能打开现有用户文件后让库截断。库不删除目录、不发布产物、不创建新的生命周期 owner。

核心 `Archive` 持有同一 File 不表示输入字节不可变。适配器须使用宿主校验后的私有副本，并保证该副本在归档读取生命周期内不被工具或其他写者改写；`Directory`、`TreeSnapshot` 也不能被宣传为不可变字节快照。工具完成、停止写入后才允许最终扫描与打包，扫描期间的文件变化按原冲突语义处理。

`Structure` 的结构检查不等于所有成员 CRC 已验证。选中复制必须读至结束并验证长度/CRC；APKS 验证必须对外层成员逐条读完。Splits 最终检查每个 APK 的结构资格，不等于证明其内部所有成员 CRC、签名或可安装。不得从 `Archive::open` 成功推出这些额外保证。

## 七项纯包操作的输入、输出与工具归属

表内为现有领域方法/业务语义，不定义新的 HTTP 字段或别名。输入产物必须经宿主副本或公开 SDK 产物输入协议获得；不能把调用者任意文件路径当产物。

| 操作 | 输入与原校验 | 工具及核心阶段 | 保持的业务结果与输出 |
| --- | --- | --- | --- |
| `PackageAnalyzer::manifest` | `artifact_id`，可选 `module`；输入 `.apk`/`.aab`。APK 拒绝 module；AAB 缺省 `base`。module 字母开头，仅 ASCII 字母/数字/下划线，最多 80 字节。 | APK：apkanalyzer `manifest print`；AAB：bundletool `dump manifest`；随后核心 XML 解析。 | `PackageManifest` 保留 `artifact_id/format/module` 和全部解析字段。无新输出产物。 |
| `PackageAnalyzer::signature` | `artifact_id`，仅 `.apk`。 | apksigner `verify --verbose --print-certs`；先替换临时输入路径，再核心报告解析。 | `PackageSignature` 保留 `artifact_id/verified/signers/schemes/report`。无新输出产物，报告不泄露临时部署路径。 |
| `PackageAnalyzer::extract_apk` | `artifact_id` 指向 `.apks`；精确 entry 最多 500 字节、路径安全，后缀 `.apk` 不区分大小写；并非任选第一个 APK。 | 无外部工具；核心结构、全目录重名门禁、精确成员复制与 CRC。 | `ExtractedApk { source_artifact_id, entry, artifact }`；真实宿主产物文件名 `extracted.apk`。 |
| `SplitPackages::extract` | `ExtractSplitsRequest { artifact_id, device_spec }`；输入 `.apks`。ABI 1..16、locale 1..100，唯一、ASCII 字母/数字/下划线/连字符且每项最多 80 字节；density/sdk 1..10000；拒未知字段。 | 核心按 Default 验证 APKS；管理员生成 camelCase spec 文件；bundletool `extract-apks`；监测、Splits 最终打包。 | `ExtractedSplits { source_artifact_id, device_spec, artifact, apk_entries }`；发布 `selected-apks.zip`，内部临时 ZIP 名不替代该公开文件名。 |
| `BundleBuilder::build` | `BuildApksRequest { artifact_id, mode }`；输入 `.aab`；Default/Universal 仍按既有枚举。 | bundletool `build-apks`，固定 `--max-threads=2`、部署签名参数；核心验证输出 APKS。 | `BuiltApks { source_artifact_id, mode, artifact, apk_count, universal_entry }`；发布 `built.apks`。Default 可多 APK；Universal 必须唯一 `universal.apk`。 |
| `PackageReverse::decode` | `artifact_id`，仅 `.apk`。 | apktool `decode`；decoded、framework 都在本次私有 scratch；Reverse 监测、扫描、最终打包。 | `DecodedPackage { source_artifact_id, artifact, files, unpacked_size }`；发布 `decoded.zip`。 |
| `PackageReverse::scan_sdks` | `artifact_id` 指向 `.zip`；1..100 项有界唯一 rules，保持原入口预检。 | 无外部工具；核心结构、必要文件门禁与 smali 路径扫描。 | `SdkScan` 保留 `artifact_id/findings`；每个 finding 保留 rule、package/class 判定与最多 10 条排序证据。无新输出产物。 |

反编译树条目上限为含目录 10000，Splits 树为含目录 1000，不能共用一个宽松 profile。树深度 128、文件总量与完成 ZIP 各 64 MiB 的约束分别保留；APKS 压缩体积 64 MiB、展开总量 256 MiB 不与普通结构声明 2 GiB 混为一个限额。

独立插件仅用公开 SDK 返回 outputs 声明与业务 value，输出 filename 保持上述名称。宿主 Artifact 实体必须由严格宿主结果包装中的真实列表唯一匹配得到；插件业务 JSON 自带 `artifact` 对象不构成已发布证据。旧操作绑定的纯投影沿已冻结绑定规则配置，不自行设计私有 wrapper 或绕过产物准入。

## 错误兼容与安全修正

错误转换需要携带调用场景，不能实现一个无上下文的 `From<core::Error>` 后用于所有包操作。核心识别包与树规则；宿主薄层决定这是调用者输入无效、工具产出不合格、存储失败还是资源排空未确认。固定中文文案不能包含签名材料、部署路径或未经脱敏的工具 stderr。

| 核心错误或前置失败 | 宿主接缝规则 |
| --- | --- |
| `Cancelled` / `Timeout` | 原类透传；统一原截止点已过且令牌同时取消时，结果按 Timeout 分类。已有 CleanupFailed 不得被改写为 Timeout。 |
| `InvalidArgument` | 业务入口规则失败映 `Invalid`；内部适配器传错 profile/参数不能冒充用户坏包。先保留原入口参数预检，再调用核心。 |
| `InvalidManifest` | 工具文本解析映 `Dependency("工具返回的 AndroidManifest XML 无效")`。输入后缀、module 等旧入口错误仍是 `Invalid`。 |
| `InvalidSignature` | 映 `Dependency("签名工具未返回完整、明确的验证结果")`。非零退出、工具不可用由工具层处理，不伪造签名失败模型。 |
| `EntryMissing` / `EntryDuplicate`、输入 ZIP 的 `InvalidArchive` | 保持选中条目缺失/重复及输入容器无效的旧 `Invalid` 分支；全目录去重必须先执行，不能只拒绝所选条目的重复。 |
| 通用结构 `LimitExceeded` | 原上传/通用 ZIP 门禁的条目 10000 与声明展开 2 GiB 超限仍为 `Invalid`，保持“压缩包条目超过 10000”“压缩包声明解压体积超过 2 GiB”等固定文案。 |
| 复制、树、文本或 APKS 工作限额 `LimitExceeded` | 保持既有 `TooLarge` 分支。按限额种类和阶段区分，不能把通用 ZIP 的旧 `Invalid` 一并改为 `TooLarge`。 |
| `SourceChanged` | 反编译打包映 `Conflict("反编译输出在打包期间变化")`；Splits 打包映对应“分包提取输出在打包期间变化”。私有输入被改写不得继续发布成功。 |
| 真正文件 I/O 的 `Io { stage, source }` | 原文件打开、读写、sync 等映 `Storage`，保留来源区分；解压格式/长度/CRC 不合格按包校验错误处理，不能统称磁盘故障。 |
| 外部工具 Spawn/ProcessIo/NonZeroExit/输出超限 | 保持现有 `process` 公共库适配规则；捕获非零 trim stderr、文件输出非零带退出码、stderr 超限 Dependency 等不在核心重写。 |
| 工具或 worker 清理未确认 | 宿主 `CleanupFailed` 独立保留。核心没有这个错误，也无资格证明宿主、插件或子工具全部退出。 |

最终业务资格另有场景差异，必须显式适配，不能只按核心错误字符串统一转换：

| 场景 | 保留的宿主错误与发生阶段 |
| --- | --- |
| Reverse 工具最终输出缺/空 `apktool.yml` 或 `AndroidManifest.xml` | 最终打包前 `Dependency("反编译未生成有效的 <必要文件名>")`；监测期缺失不失败。核心必要成员校验返回 `InvalidArchive`，薄层按工具输出场景映射。 |
| SDK 扫描输入缺/空必要成员 | 输入不合格仍为 `Invalid`，不能复用 Reverse 工具输出的 Dependency 分类。 |
| Splits 最终没有 APK | `Dependency("工具没有生成匹配的 APK")`；不能仅以核心“空或非 APK”的合并错误文案决定分类。薄层先按扫描目录区分空与非空。 |
| Splits 任意阶段出现非 `.apk` 普通文件 | `Invalid("提取目录只允许 APK 文件")`；保留旧大小写规则与监测期早拒行为。 |
| Splits 最终 APK 结构不合格 | `Invalid`；仅在最终阶段检查完整资格，不能将尚在写入的 APK 以坏包提前结束。 |
| bundletool 未生成 APKS | 保留前置普通文件检查和 `Dependency("构建工具没有生成 APKS 文件")`。已存在却为链接/特殊文件仍为 `Invalid("构建输出必须为普通文件")`。 |
| APKS 重名、长度/CRC、缺非空 toc、无 APK、Universal 不唯一 | 保持各旧 `Invalid` 分支；字节/展开量上限仍为 `TooLarge`。 |

错误类别与既有明确文案是适配回归基线；新增核心更严格的结构拒绝按所在输入/输出场景转换为有界固定错误，不能扩大为“新旧所有坏包文案完全等价”。XML 命名空间实体校验、规范化 URI 与 expanded 属性判重属于已修正的安全规则；旧实现接受的未定义实体和等价命名空间重复属性应拒绝，不为兼容旧缺陷降级。

## 原截止点、同步控制与工具短限额

统一截止点记为 D，由宿主 application 注册与准入阶段确定；从排队、输入准备、工具执行、同步解析/复制/打包到发布使用同一个绝对点。薄适配不得重新以 `now + total_timeout` 建立总期限。

| 接缝 | 转换与约束 |
| --- | --- |
| `ExecutionContext.deadline: Option<std::time::Instant>` → 宿主异步阶段 | `Some(D)` 仅做 `tokio::time::Instant::from_std(D)`；传给 `execution_deadline`、`materialize_until` 和支持绝对点的 process 入口。 |
| 异步截止点 → 核心 `Control` | 用同一 Tokio Instant 的 `into_std()`，或保存最初 std D；`Control::new(Some(D), &只读取消回调)`。回调只读 `CancellationToken::is_cancelled`，不 I/O、不阻塞、不延长预算。 |
| 核心 `Control::new(None, ...)` | None 不补预算。保留旧阶段期限的责任在调用方；若原阶段有 120 秒期限，必须在其阶段开始确定一次并传给本阶段所有 worker 检查。 |
| 工具原短限额 | 有 D 时允许工具点为 `min(D, 本工具开始点 + 原短限额)`，工具早超时仍结束整项操作；不能把工具短限额当新总预算。D 不截短为插件默认 60 秒，也不因阶段切换延后。 |
| 下一次 I/O、启动 worker 或发布前 | 先检查 D/取消，取得工作池许可后再次检查。到期或已取消时不启动新业务工作；结束前再检查，禁止晚成功和下一产物续预算。 |

`process::run_until`、`run_plugin_until` 已有绝对点接缝。`run_to_file`、`run_isolated`、`isolated_text` 仍有旧 Duration 签名；需另批增加 until 薄入口并保留旧签名委托，才能把 bundletool/apktool 的 cwd、受限环境与文件输出规则连到原 D。不得通过反复计算 Duration 让队列等待被排除在预算之外。

当前 `PackageAnalyzer`、`BundleBuilder`、`PackageReverse`、`SplitPackages` 旧领域端口只接取消令牌，并未接 `ExecutionContext`；现有 `Executor::execute_with_context` 不会自动把 D 传入这些端口。第一批纯 parser 替换可以不改公开端口，但不能因此声称旧七操作已具有全阶段总期限。若要同进程保留旧端口又落实 D，须由主代理冻结默认兼容 context 入口与 application 调用接线，再实施。

跨进程公开 Request 尚无原 D 或剩余预算传递字段。宿主可以在原 D 到期后取消/清理插件进程；插件本地工具短限额只能作为内部上界，不能证明其每笔 I/O 使用宿主同一 D。跨进程强语义需要公开 SDK 上下文及匹配 runtime 的另批加法裁定；不能偷偷用业务 input、私有环境变量或 JSON 字段传期限，也不能跨进程直接传 std/Tokio Instant 数值。本文不改变该未接通边界。

## 受限 worker、目录 lease 与排空

同步核心在受限阻塞 worker 内使用；核心本身不引入 Tokio、工作池、JobStore 或目录清理。现有部分包模块直接 `spawn_blocking`，不能宣称已经复用 application 的存储工作池：`application/src/blocking.rs` 的许可为私有，`FileArtifacts` 的上传验证池也不是包操作工作池。

下一批需明确可注入的有界 worker 接缝与排空归属，建议采用以下完整顺序；池名、槽数和端口签名仍待裁定：

1. 在原准入与服务关闭门禁内登记资源工作；等待许可同时监听取消与 D，拒绝 shutdown 后新增未追踪任务。
2. 取得 `OwnedSemaphorePermit` 后重查 owner/取消/D；把 permit、取消子令牌、原 D、输入副本及 `Arc<Temporary>` 一起移入阻塞闭包。闭包内构造借用这些对象的 `Control`，不要借用请求栈中会提前释放的控制对象。
3. 每个工作持有所需输入、输出及临时目录 lease 到真实线程退出；外层请求被取消或 Future 丢弃时只发取消，并由仍受追踪的所有者等待退出。运行中的 `spawn_blocking` 不能靠 abort 证明停止。
4. 阻塞核心响应检查后正常退出才释放许可。反复取消请求不能让仍在后台运行的闭包释放槽位，再创建不限量工作。
5. 外部工具、目录监测与最终 worker 使用同一取消树。监测失败先取消工具，待确认退出后再最终扫描；不得让工具还写文件时打包或删除 scratch。
6. 有界清理等待与业务 D 分开：D 到期后不能继续新的业务 I/O，但仍须执行既有清理流程。线程、子工具或资源删除无法确认时保留资源归属与 CleanupFailed 阻断，不能把目录暂时不存在或正常 exit marker 当作全部排空证据。

`Temporary::drop` 的直接删除与 Windows 异步重试是尽力清理，不等于 tracker 完成或 cleanup 确认。`artifact_files` 的私有副本和 `plugin_artifacts` 的输出验证/发布必须保留现有目录守卫；`ArtifactStore::put` 自身阶段限额也不自动等于原 D。外层 timeout 丢掉 put Future 时，内部验证可能继续，仍要保存其 staging 所有权、工作许可与排空证据，不能在此宣称已回滚或已停止。

多个输出先逐项用原 D 复核并沿严格宿主发布路径提交；已有发布成功与后续失败的边界依既有产物协议处理，不在薄适配中虚构跨产物事务。独立插件不可直接写宿主产物库；核心同步返回也不是 Job 可终态成功的充分条件。

## 工具部署配置接缝

目前 `server/src/main.rs` 直接装配 `AndroidPackageTools`、`AndroidBundles`、`AndroidReverse`、`AndroidSplits`。工具来源是管理员环境配置，业务 input 不可选择 executable、shell、JAR、工作目录、签名文件或密码路径；当前 `ToolCommand::java_jar` 的固定前缀为 `-Xmx256m -jar`。保留 argv 逐项传递，不改成拼接 shell 命令。

| 现部署来源 | 当前行为与迁出要求 |
| --- | --- |
| `APK_JAVA` | 缺省 `java`；独立插件应从受支持的管理员部署配置取得，不能假定 restricted 环境自动继承。 |
| `APK_APKSIGNER_JAR` / `APK_APKSIGNER` | JAR 优先，否则 executable 缺省 `apksigner`；解析后的路径与固定前缀属于工具层，不属于包核心。 |
| `APK_APKANALYZER` | executable 缺省 `apkanalyzer`；缺工具在调用相关能力时返回确定的工具错误，不令空宿主启动检查 Android 工具链。 |
| `APK_BUNDLETOOL_JAR` / `APK_APKTOOL_JAR` | 可选；相关操作保留未配置时的 Dependency 边界，不能让其他不依赖工具的包操作一并不可用。 |
| `APK_BUNDLE_KEYSTORE`、`APK_BUNDLE_KEY_ALIAS`、`APK_BUNDLE_STORE_PASSWORD_FILE`、`APK_BUNDLE_KEY_PASSWORD_FILE` | 必须整组提供。保留绝对现有文件与 alias 有界/无控制符校验；密码经工具文件参数提供，不读进业务输入、日志或结果。 |

部署来源尚未裁定时，不能把这些宿主私有环境变量当成已受支持的插件配置协议。后续必须明确由插件受支持部署配置或管理员可控路径获得工具，并验证 relative cwd、可读签名材料和子工具资源归属；不把工具配置塞入纯核心 API。旧宿主环境变量迁到何处、缺省 executable 的解析及签名材料如何发布是独立部署裁定，不在本文强行冻结。

## 最小验收矩阵与冻结边界

本文仅经过文件级静态核对，没有执行任何命令、构建、格式化、测试或服务。以下是后续实施必须提供的真实证据，不是已经完成的验收：

| 类别 | 必须证明 |
| --- | --- |
| 旧模型兼容 | 三分析操作逐字段结果、版本号前导零、AAB base/module、可空字段、权限排序、签名 scheme/signer/report；七项产物名与真实 host Artifact 来源。 |
| 包与 XML 拒绝 | 路径/链接/重复成员/CRC/长度/ZIP64/体积；未定义命名空间实体、编码等价 URI、expanded 重复属性；阶段断言不把 open 早拒误称 copy 校验。 |
| 树与输出资格 | Reverse 10000、Splits 1000，监测允许缺必需成员但拒危险项；Splits 监测拒非 APK、最终空/坏 APK 精确错误；Universal 唯一与所有外层 CRC。 |
| 原 D | 预取消/预过期零产物读、零工具 spawn；等待许可计入预算；跨准备/工具/解析/复制/多个发布不刷新 D；首 poll 与下一 I/O 前复核。 |
| 取消与丢弃 | 取消 Future 后阻塞 worker 仍持 permit/目录 lease；第二请求不能绕过槽位；晚结果不发布；Drop 发取消且有可观察追踪；成功清理与 CleanupFailed 分证。 |
| 真实工具与资源 | 管理员部署的工具 argv/cwd/env、真实进程退出、临时目录稳定与取消排空、错误脱敏；marker 和正常 exit 不单独证明外部资源全部清理。 |
| 空宿主与三入口 | 不配置 Android 工具/不安装平台插件时宿主可启动；真实插件通过 HTTP/MCP/CLI 加载与旧绑定调用，无平台硬编码；未安装能力返回精确错误。 |

下一项可独立实施候选是 A-context：PackageAnalyzer 默认兼容入口、application 三流接线及 Recorder 定点回归，与主代理 infra 写集互斥。前置依赖是准确入口签名、现有 `ExecutionContext` 与预算预检函数、未解决资源状态的转发规则和所属文件授权。它不依赖 Java/JAR/真机，也不依赖跨进程 SDK 加法；交付时必须明确仅完成 context 转交，底层预算/worker 由 infra 另角色接通。
