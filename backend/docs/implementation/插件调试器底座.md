# 插件调试器底座

## 范围与装配责任

应用核心落在 `crates/application/src/debugger/`，只负责实例、会话、浏览器命令传输和生命周期事件。HTTP/MCP 适配器由主代理装配，必须共用同一 `Arc<DebuggerService>`；不另造业务执行器，不接管设备或投屏。

公开传输类型均派生 `Serialize`、`Deserialize`、`JsonSchema`，协议字段使用 snake_case，顶层 DTO 拒绝未知字段。动态 JSON 只用于有限工具的结构化参数和回执，事件不记录参数、结果正文或凭据。

服务器目标必须由适配器在 open/select 前读取真实 `PluginService::list` 并核对精确代际。核心只验证 `target_kind=server`、`instance_id=None`、非空 `plugin_id/generation`，不伪造服务器目录，不提供服务器 executor。核心的 `targets()` 只返回已登记浏览器目录，服务器目录由适配器聚合；核心接受结构不代表已确认服务器目标存在。

## 冻结接口

下列方法均为 `&self`；`Result<T>` 是公开的 `debugger::Result<T>`，错误为 `DebuggerError { code: ErrorCode, message: String }`。

| 方法 | 输入 | 输出 |
| --- | --- | --- |
| `new` / `default` | 无 | `DebuggerService` |
| `with_config` | `DebuggerConfig` | `Result<DebuggerService>` |
| `with_clock` | 配置、`Arc<dyn DebuggerClock>` | `Result<DebuggerService>` |
| `register_instance` | `BridgeRegistration` | `Result<BrowserInstance>` |
| `instances` | 无 | `Result<Vec<BrowserInstance>>` |
| `heartbeat` | `BridgeHeartbeat` | `Result<BridgeStatus>` |
| `targets` | 无 | `Result<Vec<DebugTarget>>` |
| `open_session` | `SessionRequest` | `Result<DebugSession>` |
| `session` / `touch_session` / `close_session` | `&str` 会话标识 | `Result<DebugSession>` |
| `select_target` | `&str` 会话标识、`DebugTarget` | `Result<DebugSession>` |
| `disconnect` | `&str` 实例标识 | `Result<()>` |
| `enqueue` | `DebugCommandRequest` | `Result<DebugCommandReceipt>` |
| `execute`，异步 | `DebugCommandRequest` | `Result<DebugCommandResult>` |
| `command_result` | `&str` 命令标识 | `Result<DebugCommandResult>` |

| `events` | `EventQuery` | `Result<EventPage>` |

没有字符串任意工具入口，也没有 `set_server_targets`。最初讨论的旧工具名称和即时 poll 方案已由下述冻结行为替代。

## 实例与显式目标

- 每次登记由服务生成新 UUID `instance_id`，刷新页面不能沿用旧登记。目录包含最多 64 个 `{plugin_id, generation, version?}`，禁止同一实例出现重复插件标识。
- 浏览器目录登记必须给出非空 generation。只有实例而没有已登记插件时，不能打开任意插件会话。
- 浏览器 open/select 必须显式指定当前 `instance_id + plugin_id + generation`；可选 version 若提供也必须匹配。会话保存已解析的当前目录快照，不自动选第一个实例或最新代。
- heartbeat 可不带 plugins，只续实例；`plugins: []` 明确撤销全部插件。更新目录后，已消失、换代或版本变化的目标会话进入 `target_changed`，相关命令立即结束宿主等待，不影响其他会话和实例。
- 实例闲置 TTL 默认 60 秒，heartbeat 和实际 poll 续实例。会话闲置 TTL 独立为 30 分钟，只有 touch、成功入队和 select 续会话；目录心跳、poll、普通读取和回执不续会话。
- close 幂等保留有限终态；最后会话关闭后，可通过 heartbeat/poll 查询到空 `active_sessions`。实例 disconnect 释放其队列、结束会话并唤醒等待；已经断开的实例 poll 返回 `not_found`，由桥接方重新登记，不把旧身份复活。

## 命令与等待语义

- 统一请求是 `{session_id, tool, parameters}`。工具白名单固定为 `inspect/ui_tree/ui_query/ui_diff/ui_assert/ui_action/invoke/reload/report`。
- `ui_action/invoke/reload` 默认总预算 10 秒，其余 5 秒。预算从入队开始，排队和领取不重启期限。core 的 server 命令返回 `unsupported_target`，由适配器复用真实用例。
- 每浏览器最多 4 个已预留或已领取的在途槽位，加 32 个排队槽位；未 poll 前也最多接纳 36 条。空槽位预留不等于已交付，只有 poll 后才能回执；完成/取消/超时释放槽位，最早排队命令晋升。
- 命令标识由服务生成 UUID，poll 领取即从待领队列移除。响应丢失不自动重放，调用方也不得把相同动作自动重试理解为安全续跑。
- 回执必须匹配命令所属实例、插件及精确代际，并且已经被领取。重复回执、旧代、不属于本实例、未领取及到期回执均拒绝；迟到结果不能覆盖终态。
- 超时只返回 `timed_out_unconfirmed`，关闭、断开、换目标或调用 Future 被丢弃则为 `cancelled_unconfirmed`；二者都不表示浏览器动作已停止或资源已清理。丢弃 execute 的接收端在下一次访问时先撤销，之后不会领取该命令。
- execute 通过单次结果通道等待，有固定绝对期限。同步状态锁使用 try_lock，竞争时立即返回 capacity，不形成无限等锁；超时收尾遇短暂竞争仍返回未确认结果，下一次访问继续按原期限收口。

## 有界长轮询

- poll 没有活动会话或已有可领取命令时立即返回。否则本次 Future 内最多等待 2 秒，且会按本实例会话 TTL 和命令剩余预算提前检查。
- 先创建 `notified()` 并 enable，再锁内检查状态，避免检查和 await 之间丢唤醒。所有 await 都在锁外，入队、回执、关闭、换代、断开和到期状态变更通过 `notify_waiters` 广播。
- 同一实例最多同时挂起 4 个 poll，立即获取有限信号量名额，不排无限等待队列；不同 poll 竞争同一命令时只会交付一次。通知可能跨实例唤醒，但每次都会重查本实例，且不延长原两秒期限。
- 不创建常驻任务、定时扫描器、后台进程或额外 executor。TTL 在访问时惰性扫描；没有任何访问时不会自动释放记录，但容量上限始终有效。测试时钟影响规则判断，默认时钟和 Tokio 定时器都支持暂停时间测试。

## 容量与内容限额

默认最多 32 个实例、128 个活动会话，终态会话历史 256 个，终态命令历史 256 个且累计结果编码不超过 16 MiB；按最旧终态淘汰，不淘汰活动记录来伪造容量。配置只允许缩小默认上限和期限，期限最小 1 毫秒。

请求限 64 KiB、4096 个 JSON 结构节点、深度 12；回执限 1 MiB、32768 个结构节点、深度 32。回执 `nodes/children` 数组中的对象总数最多 500；具体 UI 树语义和采集范围仍由浏览器 dispatcher 保证，核心不将任意业务数组当作完整 UI 协议验证。大小采用流式编码计数，在达到上限时停止，不为拒绝超大数据额外复制整份 JSON。

`source/code` 等正常覆盖信息或结构化错误字段允许使用。参数和回执只拒绝已知凭据字段；字段检查不是可靠的内容脱敏器，不能保证任意普通字符串没有秘密，采集端必须只发送允许公开的数据。禁止任意 JS 执行依靠有限工具及 dispatcher 无 eval，而非通用字段黑名单；核心不执行 JSON 文本。

## 事件环与分页

- 仅保存实例/会话/命令生命周期标识和状态，不放任意日志正文、输入或输出。
- 默认保留最多 10000 条且 JSON 编码累计不超过 16 MiB，任一限额触发则丢弃旧事件；单事件超过配置预算时也显式计数丢弃。
- 每页为 1 到 200 条。`EventQuery.session_id` 可选；提供时先检查会话仍在活动或有限历史中，再在环内按会话过滤，之后分页。
- `next_after` 是最后返回序号，无匹配则推进到当前最新序号。返回 `oldest_available/latest_sequence/gap/dropped_events/retained_bytes`，不隐藏丢弃；gap 是全局环的保守缺口指示，不推断被丢弃事件必然属于所选会话。
