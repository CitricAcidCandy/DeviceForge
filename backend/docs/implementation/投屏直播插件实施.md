# 投屏直播插件实施

日期：2026年10月13日。写集为 `plugins/mirroring/` 和本文；公共 SDK、宿主与前端生成由主代理负责。性能测试按用户决定延后至全部业务完成。

## 架构门禁

模式为 `architecture-first`，采用 Hybrid：先固定公开媒体与控制合同，再做插件纯解析回归和独立真实进程/套接字验证。目标是持续直播、音频、输入、断开重连及有据可查的资源退出；具体页面与视觉暂不开发。

现有插件只有工具查询和 MP4 录像。旧工程的 `script/adb/ADB.ts` 投屏调用桌面 scrcpy，且显式禁用音频；旧工具实际 `--version` 为 3.3.1。不能把桌面窗口或录像当作浏览器直播。选择插件直接启动已配置的 scrcpy-server，并消费其视频、音频与控制三路 TCP；不通过重复短录像模拟直播，不给宿主添加 ADB 或平台分支。

| 单元 | 负责 | 不负责 | 输入、输出与副作用 |
| --- | --- | --- | --- |
| `config` | 保留格式 1，增加可选固定直播服务文件及版本；有界读取 | 请求选工具路径 | 部署文件到固定入口；异步读文件 |
| `live/model` | 打开输入、限额和严格控制规则 | 进程、网络 | JSON 到纯规则结果 |
| `live/wire` | DFML 封装、媒体元数据和 scrcpy 包解析 | 解码、播放、宿主缓存 | 原字节到有界帧 |
| `live/control` | 严格逐行输入及 scrcpy 控制编码 | 输入回放、全局剪贴板同步 | 输入 JSON 到控制套接字 |
| `live/device` | 独占目录、文件、转发和固定服务器 argv | 共享 ADB daemon、其他设备资源 | 固定命令到本次资源句柄 |
| `live/lifecycle` | 原截止点、取消、资源确认及有限重连 | 假装远端失败已回收 | 实际等待结论到 Execution |
| `main` | 首帧选择原协议 4 或会话 5 | 业务分支进入宿主 | 标准输入到公开运行库 |

录像职责保持独立，直播新增 `live/` 子模块；不扩大原录制文件。普通贡献及旧配置继续兼容。

## 公开合同

会话贡献 `plugin.mirroring.open`，协议 5，总期限 3600000 毫秒；组声明 `output_retention:"bounded_tail"`，运行库 `continuous_output:true`，保留有限队列、单块上限和原截止点。输入为 `device_id`，可选 `max_size=1280`（64–4096）、`max_fps=30`（1–60）、`video_bit_rate=2000000`（128000–16000000）、`audio=true`、`control=true`、`reconnect_attempts=2`（0–5）。拒绝未知字段、程序路径及自由 shell。

stdout 为连续 DFML 帧，24 字节大端头：魔数 `DFML`、版本 u8=1、类型 u8、标志 u16、微秒 PTS u64、载荷长度 u32、重连 epoch u32。类型为 1 视频配置 JSON、2 视频原包、3 音频配置 JSON、4 音频原包、5 状态 JSON；标志 bit0 为关键帧、bit1 为编码配置，其余为零。单载荷不超过 4 MiB，完整帧串行发送并允许跨 8192 字节会话块。epoch 从 1 开始，每次已确认清理后的设备重连递增。

视频配置为 `{"codec":"h264","format":"annexb","width":N,"height":N}`；SPS/PPS 保持独立视频配置标志包，媒体保留原时间戳与关键帧。音频配置为 `{"codec":"pcm_s16le","sample_rate":48000,"channels":2}`，载荷为交错 PCM。状态为 `{"state":"connecting|streaming|reconnecting|audio_unavailable","attempt":N}`。不把媒体或任意工具诊断写入日志。

控制输入为 UTF-8 JSON 行，单行最多 4096 字节、拒绝未知字段，必填 `epoch` 且须匹配当前帧代次：touch（action=down/up/move、pointer_id 默认 0 且最多 9、x/y、width/height、pressure 默认 1）；key（action=down/up、keycode 最多 320、repeat 默认 0 且最多 1000、meta_state 默认 0 且最多 2147483647）；text（UTF-8 最多 300 字节）；clipboard（UTF-8 最多 2048 字节、paste 默认 false）；rotate；reset_video。两类文本拒绝 NUL。空输入块不表示 EOF，EOF 仅关闭控制写入且视频继续。重连拒绝回放旧控制；客户端恢复沿宿主游标，过期游标明确失败后重新打开，不能从截断媒体块继续解码。

## 工具与所有权

直播配置为可选 `live:{scrcpy_server:绝对路径,server_version:"3.3.4"}`，scrcpy/adb 仍由格式 1 的部署者配置。服务版本只接受 3.3.1 或 3.3.4，推荐 3.3.4；启动、就绪和清理使用本次固定的同一可信版本身份。上游 3.3.1 的 Streamer、DesktopConnection、AudioConfig、AudioCodec 与 ControlMessageReader 已实际读取，且这些协议文件在 3.3.4 未变：三套接字按视频、音频、控制建立；视频 12 字节 codec/width/height，音频 4 字节 codec，之后媒体为 12 字节 PTS/标志/长度头。原始音频固定 48000 Hz、双声道、16 位。

插件每次建立独占远端目录、服务文件、pid 文件和 SCID；通过 `forward --no-rebind tcp:0 localabstract:scrcpy_SCID` 获得本地端口。服务器禁用 device meta、dummy byte 和全局 cleanup，只使用本次固定参数。取消先关闭本地套接字，再根据本次 pid 与 cmdline 身份终止远端服务器、确认退出并移除本次目录及精确转发；不执行 kill-server、pkill 或全局工具杀进程。未确认远端、直接进程或转发时保留 Failed，并禁止重连。

本批代码与测试写回不代表已编译、真机或浏览器解码成功。定点库测试、独立假 ADB/socket 服务、宿主热卸载、真实 ADB/scrcpy-server、音视频播放、正式包与跨平台分别验收。

## 当前实际交接

普通任务与会话双入口、三路 TCP、严格媒体包头、控制代次、有界输入、独占远端目录/服务/PID/端口登记、清理脚本及最多五次重连已经写回。库中静态计有 12 项回归（含旧录制），覆盖首帧边界、控制精确字节与过期拒绝、帧字段/长度/数值精度、转发响应丢失的归属查询、私有清理和重连规则。

首轮主代理编译发现 `checked` 闭包返回 `&str` 与公开 `String` 错误不一致；私有闭包已窄修。最后环境切回沙箱后再次出现创建进程前拒绝，因此修后 Cargo、Clippy 和最终格式未取得结果，不写成验证通过。最后 `wire/device` 窄修需恢复后定点格式化。独立测试助理继续夹具与驱动写集，编译、宿主构建和运行由主代理串行协调。

公开 EOF 后保留控制写半部直到媒体结束，避免 TCP FIN 导致设备服务器结束视频；逻辑上不再接受后续控制。媒体/TCP 断流仅在所有旧资源确认退出后重连；真实 ADB 或设备完全离线导致身份/退出无法核对时保留 Failed，当前没有无限离线恢复结论。

## 修后定点与冻结证据

子代理执行器经一次只读核验可运行，主代理临时协调后端代理串行执行共享 Cargo；没有并发构建或生成类型。修后库 13/13、协议运行库 24/24、输出缓存 3/3、应用交互 15/15 均退出 0；宿主 `cargo check`、投屏全目标 Clippy 和宿主/插件 debug 构建均退出 0。最初库 10/12 的失败发现内部标记枚举空变体接收未知字段，改为严格空结构变体后通过；Clippy 首次仅因 `is_multiple_of` 写法失败，原报告保留。

总监独立复核后进一步收紧资源确认：`server_attempted` 在尝试启动前登记；服务器已尝试而 PID 缺失时有限等待后失败且保留目录，不依赖删除目录排除延迟启动。转发删除前按设备与 SCID 核对端口归属，删除后再次查询确认本次映射消失；归属未知不删除别人的端口。该修复新增一项回归，最终 13 项报告为根 `artifacts/mirroring-live-library-final-20261013.txt`，运行库、缓存、交互、宿主 check、Clippy 和 debug 构建分别保存 `mirroring-live-*` 独立报告及退出码。

debug 输入位于 `artifacts/mirroring-live-debug-frozen-ea223604-2dc0-4af6-a72c-04988fdadf96`：宿主、投屏二进制、清单和两份部署模板共五个副本均与原文件 SHA-256 一致，`frozen-inputs.json` 另记十六个插件文件快照。该快照在构建终态后采集，不表示已逐哈希冻结全部宿主源码。独立新夹具编译与三项自检退出 0；它只证明夹具可执行及自检，直播实服由测试助理另验。

当前证据限于库/公共用例、编译和冻结副本；真实 scrcpy-server/ADB、Android 音视频、浏览器播放、完整断线恢复、Release、正式分发和跨平台继续独立待验，性能测试按排程延后。

## 2026-10-15 真实三星直播修复

当前预览三星 SM_G991U、scrcpy 3.3.1 的首次开流在 `connecting` 阶段因远端 PID 未出现而触发 `cleanup_failed`。核对独占目录、进程和转发后，使用宿主优雅退出接口重启预览后端重建准入；仅有启动应用任务不会自动开启直播。

真机逐项复现确认：ADB forward 本地连接可早于远端 Unix 套接字就绪；设备默认 H264 硬件编码器在 10 秒原生录制中零帧，部署侧选择 `c2.android.avc.encoder` 后产生非空 MP4；`audio=false` 时传 `audio_codec=raw`、`--nice-name` 和 `power_on=false` 分别可在该机触发 scrcpy-server 发出配置后退出，设备诊断含 `stack corruption detected`。现仅在启用音频时传 `audio_codec=raw`，移除后两项；本次 PID 的命令行以 scrcpy 主类、3.3.1、随机 SCID 和 forward 参数精确匹配，就绪还要求本次 Unix 套接字。身份不明仍拒绝清理。`power_on` 使用 scrcpy 默认行为，屏幕关闭时可能被点亮。

当前预览配置加入经真机验证的软件编码器。服务会话 `1f3995d4-14ee-4474-8eb1-72fa40016c6f` 持续输出 3715 个块，抽样输出含 DFML 视频包头与 Annex B 字节；取消后 `cleanup=complete`、`process_exited=true`、插件 `cleanup_failed=false`，本次转发和独占目录均消失。后端架构、6 个架构用例、格式、全工作区 Clippy、插件 19/19 定点用例及插件 debug 构建通过。工作区测试编译时因当前预览 `apk-server.exe` 正在运行，无法替换该文件而退出 1；未据此宣称完整工作区门禁通过。前端 WebCodecs 真实画布、启用音频和控制、正式分发仍需单独验收。

此前的 debug 冻结目录为 `artifacts/mirroring-live-debug-frozen-bcd0487a-d92f-4199-9816-f7ed140ba112`，五个运行副本逐个与来源 SHA-256 核对，另记录十六个插件文件快照。该批 16 项证据和目录曾替代上一轮 13 项及旧目录作为实服验收输入；旧报告保留。该冻结批次当时尚无真实 ADB/scrcpy-server、Android 音视频、浏览器播放、Release、正式分发或跨平台通过证据；10 月 15 日真机增量以本节新记录为准。
