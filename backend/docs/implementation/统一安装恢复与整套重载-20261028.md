## 成功证据与恢复范围

原 `previous-<id>.json` 是事务操作前版，可能从未激活成功，也可能在反向恢复后改变方向。新增独立 `installations/successful/<id>.json`，每个发布最多保存两份成功快照。只有整套宿主贡献完成激活后才登记 `scope: "host_activation"`；旧安装没有明确记录时拒绝恢复，不用启用状态或普通前版推断成功。

恢复选择最近一份不同于当前修订的成功记录，核验当前修订、目标修订、组件归属、不可变文件清单和共享工具，再通过原文件事务切换整套代码与活动视图。它保留操作前当前启停意图，缺依赖或配置时保留启用意图并返回 `dependencies_required` 或 `configuration_required`。配置、数据库、设备状态和其他业务数据均不回滚。

成功记录引用进入原资源回收保护，重启后仍可查询。成功范围仅为宿主激活，不表示浏览器实际执行、真实设备或生产业务验证。

## 冻结应用接口

以下方法均属于 `InstallationService`：

```rust
pub async fn previous_successful(
    &self, id: &str, expected_revision: &str,
) -> Result<SuccessfulRelease>;

pub async fn reload(
    self: &Arc<Self>, id: String, expected_revision: String,
    cancel: CancellationToken, context: ExecutionContext,
) -> Result<InstalledRelease>;

pub async fn reload_component_expected(
    self: &Arc<Self>, id: String, generation: String,
    cancel: CancellationToken, context: ExecutionContext,
) -> Result<PluginInfo>;

pub async fn restore_previous_successful(
    self: &Arc<Self>, id: String, expected_revision: String,
    cancel: CancellationToken, context: ExecutionContext,
) -> Result<InstalledRelease>;

pub async fn release_action(
    self: &Arc<Self>, id: String, expected_revision: String,
    restore: bool, cancel: CancellationToken, context: ExecutionContext,
    progress: Arc<dyn ProgressReporter>,
) -> Result<InstalledRelease>;
```

最后一个方法供原 Job 统一执行；调试器应直接调用相同用例并传递原上下文，不能从外层拆开托管服务器组件。执行前必须由入口取得本次显式确认。重载不把已停用发布自动启用。活动任务冲突沿用原卸载拒绝规则，失败后补偿操作前已加载服务器组。

调试器选中托管服务器组件时使用 `reload_component_expected`。门禁外仅按组件定位候选所属发布；原 `release_action` 共用的私有实现取得同一 `serialized` 门禁后重新核验当前发布修订、服务器组件归属、`Loaded` 状态及精确代次。核验失败不撤销任何组件。整套成功后在释放门禁前取得选中组件的新代回执，避免锁外读到另一调用的代次。HTTP/MCP 原发布级请求类型保持不变。

两项操作共用原 `PluginService.serialized` 门禁。总截止点是 `min(传入原截止点, 进入用例时刻 + 30秒)`；排队等待到期可退出，开始事务后必须排空至稳定状态。工作阶段预留同一预算末尾五秒用于补偿。补偿不重新开启预算。逐组件撤销及注册处于同一管理事务，不宣称跨组件注册表单次原子可见；浏览器仍须原共同加载层消费目录并返回确认。

## 请求、任务和 HTTP 装配

领域请求类型位于 `apk_domain::plugin_installations`：

```rust
pub struct InstallationAction {
    pub expected_revision: String,
    pub confirmed: bool,
}
pub struct InstallationActionRequest {
    pub id: String,
    pub expected_revision: String,
    pub confirmed: bool,
}
pub struct SuccessfulRelease {
    pub release: InstalledRelease,
    pub activated_at: u64,
    pub scope: SuccessfulReleaseScope,
}
pub enum SuccessfulReleaseScope { HostActivation }
```

`InstallationAction` 和 `InstallationActionRequest` 拒绝未知字段，`confirmed` 必填且必须为 `true`。原操作注册已新增 `installation.reload`、`installation.restore_successful`，均声明 `total_timeout_ms: 30000`，复用原 Job 及其结果和进度；因此随原任务操作目录自动对 MCP 暴露，无需另建变更工具。

`server/src/plugin_installations.rs` 已提供以下边界函数，主代理在 `server/lib` 和 OpenAPI 装配：

| 建议路由 | handler | 请求与响应 |
| --- | --- | --- |
| `POST /api/v2/plugin-installations/{id}/reload` | `reload` | `Json<InstallationAction>`，202 原 Job |
| `POST /api/v2/plugin-installations/{id}/restore-successful` | `restore_successful` | `Json<InstallationAction>`，202 原 Job |
| `GET /api/v2/plugin-installations/{id}/previous-successful` | `previous_successful` | `Query<InstallationRevision>`，`Json<SuccessfulRelease>` |

两个 POST handler 的准确签名为 `pub(crate) async fn 名称(State<ApiState>, Path<String>, Result<Json<InstallationAction>, JsonRejection>) -> Result<impl IntoResponse, ApiError>`。GET handler 为 `pub(crate) async fn previous_successful(State<ApiState>, Path<String>, Query<InstallationRevision>) -> Result<Json<SuccessfulRelease>, ApiError>`。现有 v2 响应包络由原公共层提供。

成功版本预览没有增加独立 MCP 只读工具；MCP 的变更使用原操作任务。离线包仍通过原 HTTP 产物上传取得产物 ID，再作为原 `InstallSource` 输入安装任务；本轮未新增 MCP 文件传输，不能宣称纯 MCP 可提交调用者本地路径导入。

## 公共生命周期接线缺口

交接时 `actions.rs` 需要主代理在其独占的 `plugin_lifecycle.rs` 提供两个内部方法，不能以现有无期限入口或外层丢弃 Future 代替：

```rust
pub(crate) async fn load_serialized_until(
    &self, id: &str, context: ExecutionContext,
) -> Result<PluginInfo>;

    &self, id: &str, context: ExecutionContext,
```

依赖检查、阻塞工作准入和注册发布前核验必须继承传入同一截止点，返回前排空已经开始的阻塞工作。整套用例持有原串行门禁，两个内部方法不得重复取得门禁。本侧未修改该公共文件，也未以重开预算方式回退。

底层磁盘事务开始后仍须排空提交或反向恢复；30 秒为同一准入和执行预算，不宣称操作系统阻塞磁盘能提供硬实时返回保证。缺少以上接线时应用模块不能编译，不能把本轮标记为功能验收完成。

## 离线同版本构建修复

真实联调发现原版本身份校验同时阻止了本地同版本重导入。现按 `fetch::Origin` 保留来源到 `Prepared.offline`：准备及计划只对当前同发布归属的离线 release/component 接受新摘要，原事务提交在同一文件锁内先核对调用方 `expected_revision`，再允许新构建切换。没有当前安装、CAS 缺失或过期、另一发布的组件均不借此取得覆盖资格。

本地代码构建身份另存于 `installations/build-identities/<release_id>/<revision>/...`；原 `installations/identities` 的首次版本摘要不覆盖。Market 来源继续完整校验原版本摘要，同版本新构建仍拒绝。共享工具始终按原标识、版本、平台锁定摘要，不进入本地代码构建例外。成功版本快照、旧代码保留和回收引用逻辑不变，恢复仍只切代码而不回滚业务数据。

直接回归模块为 `plugin_installations::tests::local_rebuild::`：离线同版本 CAS 构建保留成功版恢复；缺失或过期 CAS、工具换摘要及删除后新安装拒绝；真实回环 HTTP Market 清单同版本换摘要拒绝。测试先于生产补丁落盘；首次失败回归因共享 Cargo 锁未运行，不能记为已观察红灯。
