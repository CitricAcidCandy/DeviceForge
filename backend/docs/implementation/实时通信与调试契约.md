# 宿主实时通信与调试契约

本次同时接入调试桥、任务通知和 MCP 调试参数及结果确认。宿主拥有公共传输，调试和任务仍各自持有业务状态；不创建第二套任务存储，不让任务模块依赖调试插件。接口延续协议版本 1，新增能力独立发现。投屏业务及其状态数据源仍由投屏插件原维护者负责。

## 传输与生命周期

后端固定使用 `socketioxide 0.18.9`，浏览器固定使用 `socket.io-client 4.8.4`，只启用 WebSocket。能力入口为 `GET /api/v2/realtime/capabilities`；连接路径为 `/api/v2/realtime/socket.io`，命名空间为 `/debugger` 和 `/tasks`。同一前端运行实例复用一个 Manager，业务模块只持有命名空间订阅。旧 HTTP 调试接口保留；只有能力接口明确返回 404、405 或 501 才选择旧桥，临时网络错误不创建竞争传输。

| 资源 | 默认上限及调度 |
| --- | --- |
| 物理连接 | 32；升级后归独立配额，不长期占普通 HTTP 许可 |
| Ping／Pong | 25 秒／10 秒，正常传输日志使用 DEBUG |
| 连接及登记 | 5 秒 |
| 同页恢复 | 从服务端确认断线起 60 秒，不延长原会话或命令期限 |
| 客户端重连 | 500～5000 毫秒、20% 抖动，每轮最多 60 秒 |
| 调试执行 | 同一实例最多 4 条在途命令 |
| 库缓冲 | 每连接最多 8 包 |
| 应用待发送正文 | 每物理连接累计最多 8 MiB，调试与任务分队列轮流发送 |
| 单消息 | 最多 1 MiB＋16 KiB，业务正文另受原限制 |
| 任务合并 | 100 毫秒，发送最新修订，不发送任务结果正文 |

这些值限制待发送数据和宿主等待，不等于实际进程内存用量。性能收益需另行测量。本轮不预报 CPU、内存或延迟的改善比例。

两类业务使用独立订阅和故障域。卸载调试面板只撤销其观察，不终止宿主 MCP 桥；撤销任务消费者不关闭仍被调试消费者使用的公共连接。最后一个消费者退出才回收 Manager、命名空间和所属定时器。加载失败或调试动作失败应局限在本模块，工作台及普通 HTTP 用例继续可用。

普通锁竞争先短暂让步，随后等待独立的锁释放通知；只读请求也会唤醒竞争方，不靠业务修订或空闲轮询。应用退出会等待已登记的实时收尾任务：物理关闭和模块排空分别最多 5 秒，宿主收尾总等待最多 12 秒，超时保留未确认诊断。未完成命名空间登记的连接通过升级请求的实际资源释放确认归还配额。

默认免鉴权，`APK_API_TOKEN` 可选。配置后在命名空间握手的 auth 中传递，不进入 URL、日志或插件公开接口。`/tasks` 支持普通局域网访问，`/debugger` 复用既有真实连接及 Origin 的本机检查，不增加多租户或来源审批流程。

## 调试桥公开事件

实时适配器只调用现有 `DebuggerService`，不复制实例、会话或命令状态。所有事件回执使用 `{log_id,data}` 或 `{log_id,error:{code,message}}`，日志编号与命令编号分别维护。

| 事件 | 方向 | 内容 |
| --- | --- | --- |
| `bridge:open` | 客户端发起并等待回执 | 插件目录、可选原实例及恢复密钥、最多 4 个在途命令编号；返回当前归属和命令状态摘要 |
| `bridge:directory` | 客户端发起并等待回执 | 当前实例及变化后的插件目录；目录不变时不发送 |
| `bridge:ready` | 客户端发起并等待回执 | 当前实例及 0～4 个空槽；服务端仍须遵守真实在途上限 |
| `bridge:batch` | 服务端推送 | 沿用原会话、目标、命令参数及剩余期限，按消息字节预算组批 |
| `bridge:ack` | 客户端发起并等待回执 | 按原命令 ID 补交一次执行结果，晚回执不能改写终态 |
| `bridge:close` | 客户端发起并等待回执 | 显式撤销本实例，不等待新命令 |

交付即从待交付队列移出，后续断线不重新派发。恢复核对原实例、插件代次、归属及在途 ID；已经交付的动作不会再次执行。若执行结果已产生，只在原期限内补交；若宿主已记终态，丢弃本地待确认副本。恢复摘要不重复携带完整结果，完整保留结果通过原 `debug_command` 查询。页面刷新及服务重启建立新身份，旧连接的迟到清理不能撤销新代。

## 任务通知及快照竞争

`NotifyingJobStore` 对原 `JobStore` 作薄包装。`create/transition/progress/recover` 写入成功后更新内存 watch 修订；失败和读取不发布。没有新增数据库、任务扫描或后台任务列表轮询。

`tasks:changed` 仅发送 `{revision:十进制字符串,reset:布尔值}`。新订阅及恢复通过 `reset=true` 请求读取快照。前端先订阅再读取，读取期间收到变化则标记待刷新并合并补读；健康且已同步时停止周期 HTTP 刷新。断线保留已有内容，按消费者原有节奏通过 HTTP 降级；恢复后重读成功才停止降级定时器。通知不充当任务结果，任务状态以现有存储和 HTTP 查询为准。

公开 SDK 增加可选 `taskHistory.subscribeChanges(listener)`，返回可撤销订阅；通知只含 `state/revision/reset`，不暴露 Socket 或令牌。旧宿主及旧插件仍可省略此方法。

## MCP 参数与检查点

UI 契约修订为 `2026-11-03.1`。Rust 同一份 UI 类型供 MCP 模式及 OpenAPI 消费；前端通过 `frontend/scripts/generate-api.ts` 串行生成边界类型，禁止手改生成文件。`debug_ui_tree/query/diff/assert/action` 公开完整嵌套模式。格式错误在进入命令队列之前拒绝，返回字段路径、预期结构和固定修正示例，不回显调用者敏感输入。

`deviceforge.debug_guide` 是只读工具，支持 `quickstart/ui/automation`。正文及例子通过 MCP 返回，开发者无需宿主源码。工具描述同时给出关键层级：顶层是 `session_id/parameters`；动作放 `parameters.action`，节点引用放 `action.target`，挂载根放 `parameters.root_id`，检查点 `parameters.expect` 与 `action` 并列。

以下示例中的 ID、节点代次、修订及根必须来自实际读取；`confirmed` 和未知副作用授权继续独立判断。

```json
{
  "session_id": "当前会话标识",
  "parameters": {
    "root_id": "当前挂载根",
    "action": {
      "type": "fill",
      "target": { "id": "实际节点标识", "generation": 1, "revision": 1 },
      "value": "示例输入",
      "confirmed": true,
      "allowUnknownSideEffects": true
    },
    "expect": {
      "kind": "ui",
      "assertion": {
        "condition": "value_equals",
        "query": { "role": "textbox", "name": "设备地址" },
        "expected": "示例输入"
      },
      "timeout_ms": 3000
    }
  }
}
```

检查点默认最多等 3 秒，可明确设置至 10 秒，始终消耗原调用剩余预算。等待只读状态，不重新派发动作。控件回读只比较本次普通 `fill/select` 的期望与实际状态，不公开原值；界面检查沿用断言，并提供普通非敏感控件的 `value_equals/selected_equals`。业务检查必须使用已登记数据源，例如 `expect:{kind:"data",source_id:"实际状态源",checks:[{pointer:"/connected",equals:true}]}`；JSON Pointer 只用于等值读取，不执行表达式。

动作原 `status` 保留，新增可选 `verification`：`scope` 为 `control/ui/business`，`status` 为 `passed/failed/unavailable/timed_out`，`reason` 说明范围或缺口。`dispatched` 只证明事件派发；控件或界面匹配不能证明投屏成功。没有公开投屏状态时报告具体缺口及结果未知，不自动追加日志遍历、视觉审核、设备探测或重复点击。

`debug_automation_run` 沿用最多 32 步、总预算 30 秒，第一步前验证整份计划。目标绑定使用 `bind.target_from_step` 指向先前唯一且完整的 `ui_query`，同时省略 `parameters.action.target`；固定目标与绑定互斥。绑定业务修订使用同来源先前 `data_read`。每步检查点只为对应动作作证，独立断言不能把未验证动作或整段操作标记为业务成功。四步示例由 `debug_guide(topic="automation")` 直接提供。

## 本轮验证边界

采用定向单元测试和必要的严格类型检查，覆盖内存服务状态、虚拟时钟、假传输和 JSDOM 控件。实际执行结果统一记录根目录 `todo.md`；不以模式注册、类型生成或编译通过代替行为测试。真实 WebSocket、浏览器、设备及性能测量均独立记证，本轮未自动部署、启停用户服务或提交代码。
