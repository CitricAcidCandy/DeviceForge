# 插件执行上下文第四版裁定

日期：2026-10-10。模式 architecture-first / Hybrid。本裁定是实施输入，尚不表示新协议已经通过动态验收。

## 目标与选择

独立平台插件需要公开的本地绝对期限、取消与资源收口。影响公开SDK、独立异步运行库、宿主通用传输、便携包版本校验和独立测试；HTTP、业务DTO、原Job预算及前端生成类型不变。协议1/2/3保持原字节格式与处理器签名。协议4由清单protocol_version显式选择，未知版本拒绝，不向旧Request偷偷添加字段。

选择Ready/Start握手，不采用接收请求后重新授予剩余预算，也不序列化std::Instant内部值。插件解析初始Request后先固定本地单调点C0，再发送Ready；宿主收到匹配Ready后，按原D计算剩余R，发送Start；插件的本地截止点为C0+R。传输和准备消耗该期限，允许保守提前到期，不宣称不同进程精确同点或远程时钟同步。宿主仍使用原D决定取消、输出发布与最终成功资格。

## 公开帧与运行接口

- 初始Request仍使用现有字段，protocol_version=4，512KiB换行帧；业务处理器在有效Start前零调用。
- ReadyFrame：protocol_version=4、request_id、command="ready"。StartFrame：protocol_version=4、request_id、command="start"、remaining_timeout_ns。两个小帧各4096字节以内，deny_unknown_fields；字段为严格整数，剩余允许0，上限3600000000000纳秒。0表示已到期，不恢复默认值。
- 单次请求只接受一份Start；错误版本、ID、命令、缺字段或额外字段拒绝。重复Start不得续期，后续输入只解析取消控制。控制帧和CooperativeResponse沿已有公开形状，嵌套protocol_version为4；资源清理complete/failed规则和响应1MiB上限不变。
- SDK新增context模块，仅定义严格纯帧模型与版本常量，不依赖Tokio，不改旧Rust结构体字面量。运行库新增serve_once_with_context / serve_io_with_context，旧serve_once / serve_io不变。
- 新处理器签名为FnOnce(Request, InvocationContext)->Future<Output=Execution>。InvocationContext可Clone，公开deadline()->std::time::Instant、cancellation()->CancellationToken、check()->Result<(),ContextError>；ContextError为Timeout/Cancelled，check先判断本地到期再判断取消。deadline保持同一C0+R，不在每次调用重置。
- 有效Start到达时本地期限已经过：零业务调用，返回精确错误"插件执行期限已到期"、无输出、cleanup=complete。运行中本地到期通知token并等待处理器真实收口，拒绝其晚到成功；不以丢弃Future假称complete。主机取消、EOF或坏控制同样通知token并收口，未确认由宿主沿既有风险门禁处理。

两秒工具清理、宿主1250毫秒合作窗口及后续500毫秒直接进程收口不扩大。后台租约保留、直接PID退出、插件cleanup确认分别记录；不证明派生树、共享daemon、物理目录全部删除或真机事务回滚。协议4实际平台插件、动态性能来源和常驻连接继续另批实现，不把握手库通过计为平台迁出。

## 2026-10-13 启动握手取消收口修正裁定

模式architecture-first / Hybrid。OEM原件重放的第一采样成功，第二采样启动后立即stop导致cleanup_failed；真实日志高度符合Ready/Start取消窗口，但没有保存第二握手字节，不将其具体落点当已捕获事实。源码明确将等待Ready时取消视作握手失败，运行库Start前不接受取消；本批修复通用协议4，不改Android电池、业务stop语义或驱动卸载断言。

选择完整初始Request之后、Start之前的合作取消路径，不以等待驱动或杀直接进程替代资源确认。取消或到期发生时开启单一次既有1250ms清理窗口，继续有界读取并完整校验匹配Ready，再发送现有协议4 Cancel；不发送Start、不重授执行预算。运行库收到严格匹配Cancel后零业务调用，返回无产物、cleanup=complete的合作响应。宿主继续要求匹配响应与零退出；Ready错误、超限、无回应、初始Request未完整发送、Start部分发送均保持保守cleanup_failed。协议1/2/3形状和处理器签名不变，原D、C0公式、1250ms和后续500ms进程收口预算不扩大。
