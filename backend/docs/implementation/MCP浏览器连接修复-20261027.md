# MCP 浏览器连接修复（2026-10-27）

## 问题与边界

用户通过根 `启动后端.bat` 启动预览后，在设置中读取 MCP 目录失败。该批处理调用 `scripts/backend-console.mjs`，Rust 宿主的 `/mcp` 与 HTTP API 共用一个进程、一个 7031 端口，不需要再启动 MCP 子进程。独立 npx CLI 的 7030/7032 代理部署是另一入口，不能套用到此批处理。

现场预览的 `/mcp` 预检返回 204，但 `Access-Control-Allow-Headers` 没有 `mcp-protocol-version`、`mcp-method` 等前端实际请求头；浏览器因此不能继续发送请求。独立发送带 `Origin: http://127.0.0.1:5173` 的 MCP `tools/list` 又返回 403 `mcp_transport_rejected`：默认配置启用空来源清单强校验，拒绝所有带来源的请求。SDK 默认 Host 限制还会影响局域网地址。这是传输配置缺陷，不是缺少第二个 MCP 进程。

本次不改前端布局或设计，不操作设备、投屏内部和用户服务；只修复现有浏览器接入，保留协议字段、取消、消息大小上限及可选令牌。默认遵循个人/可信局域网约定；部署者显式设置 `APK_MCP_HOSTS` / `APK_MCP_ORIGINS` 时仍按清单核对。

## 实现职责

按架构门禁的 `direct-fix` 处理，落点明确且不改变领域或用例职责，不新增服务层或代理进程。

| 单元 | 本次职责 | 不承担的职责 |
| --- | --- | --- |
| `crates/server/src/cors.rs` | 允许浏览器发送 MCP 协议、方法、工具名、会话及断点续读头，暴露会话/协议响应头 | 不解释业务与执行工具 |
| `crates/server/src/mcp.rs` | 默认与可信局域网 HTTP 开放行为一致，移除默认全来源拒绝和仅回环 Host 限制 | 不移除部署者显式配置或可选令牌 |
| 根 `scripts/backend-console/console.mjs` 与入口帮助 | 打印同进程 `/mcp` 地址 | 不额外启动 MCP 或自动替换现有部署程序 |
| `crates/server/tests/mcp.rs` | 真实路由预检、本机/LAN 目录读取与显式限制回归 | 不操作设备 |
| 根 `scripts/tests/backend-console-lifecycle.mjs` | 私有端口启动同一宿主后验证 HTTP 与 MCP 均可用，核对窗口提示与退出 | 不访问 7031 预览数据或停止用户服务 |
