## 架构门禁

模式 architecture-first，采用契约先行与行为回归。部署场景是本地和同事局域网，默认免鉴权，在线插件按可信代码运行，不要求多用户权限或强制隔离。环境变量 APK_API_TOKEN 可选，配置后继续执行现有令牌检查。

目标是浏览器上传服务器或浏览器插件包，在不重启宿主的情况下完成安装、加载、卸载与部署删除。具体页面和 UI 框架等待设计稿；当前先交付端口、客户端与可执行用例。性能、Frida 等业务迁移继续单独记录，在线安装不能证明这些业务完成。

两条路径比较：在 CLI 代理中增加独立在线安装会把公共接口、日志和注册规则分散到两个服务；推荐 Rust 提供统一包部署端口，HTTP/MCP 管理及前端客户端消费同一公开契约，CLI 继续使用公开便携包格式。不得把解包、校验、目录发布与运行加载集中到一个路由。

## 包与生命周期契约

- 安装包沿用 npm 便携声明：package.json 中 deviceforge.kind 区分 server/browser，manifest 指向版本化清单，entrypoints 描述运行入口。上传路径只接受包内容，不接受服务器任意目的路径或执行命令。
- 服务器包继续采用公开插件协议 1/2/3；native/node 入口从已发布包内生成，不在便携清单写机器路径。在线上传包自带运行依赖；现有 CLI 的 npm 依赖安装能力单独保持。
- 浏览器包采用 ES 模块入口及相对静态资源；具体 UI 库由插件自行打包，宿主扩展协议不绑定 UI 框架。安装清单与运行模块分别校验 ID、版本和 API 版本。
- 每次浏览器启用生成 run_id，并从 `/api/v2/browser-plugins/{id}/runs/{run_id}/assets/{path}` 加载入口和相对依赖。运行代次放在路径中，避免仅对入口加查询参数时相对模块仍复用旧缓存；普通 assets 路径保留作静态读取。
- 上传、验证、安装、运行加载、运行卸载、部署删除是独立状态。失败不发布半包，安装成功不隐式执行代码；显式启用后才加载。卸载先撤销贡献，再取消并等待清理；清理未确认时不能删除仍被占用的服务器部署。
- 普通安装继续拒绝同 ID 覆盖；独立 PUT 更新先完整暂存、验证新包，核对路径 ID 和可选期望版本，再经插件管理串行门禁替换已卸载部署。部署锁内先备份旧目录，再同卷重命名发布；发布失败立即恢复旧目录，回滚也失败则保留旧副本并报错。该锁保证本宿主目录与资源读取不观察到中间状态，不表示突然断电时的文件系统事务。更新不自动启用。浏览器每次启用生成独立代次与模块 URL，旧请求、订阅和挂载结果不能复活。
- 默认无令牌可使用管理和业务接口；配置令牌后保留鉴权兼容。浏览器模块/静态资源作为已发布代码提供，不能混入令牌、签名材料或运行数据。
- 运行启停状态当前不持久化。停止服务器插件保留部署文件，下一次服务器启动仍按部署目录加载；安装成功仅保证当前运行进程不自动执行入口。浏览器启停属于各浏览器运行实例。
- 保留流式上传、有界并发、输出限制、总期限和目录边界，作为稳定运行与错误收敛要求；不增加插件权限审批、来源白名单或强制隔离。各端文档必须明确可信运行事实。

## 验证与实施顺序

先证明默认免鉴权以及配置令牌后的 HTTP/MCP 兼容；再证明上传包校验、安装失败回滚、同 ID 冲突和删除保护。浏览器验证新增组件/模块/命令、服务器调用与逻辑扩展，卸载后入口、请求、订阅、DOM 和服务贡献全部撤销。最后执行两端门禁、真实服务、当前 release 与 npx。

当前实现已完成上述在线安装与开放扩展基础范围。后端最终架构/规则、fmt、Clippy、168 项 Rust 测试与构建通过；debug/release 在线服务验证 ZIP/TGZ、失败无残留、同 ID 冲突、运行删除保护、HTTP/MCP 任务和静态资源原字节。默认免鉴权与可选令牌兼容已回归。

独立真实浏览器直接导入生产 `frontend/dist/assets/plugin-host.js`，经前端公开用例上传两类包，验证 ESM 相对依赖在重载后换代、DOM/默认渲染恢复、模块/命令/服务/动态状态、任务钩子 4→5 与停用恢复 4，以及真实服务器响应日志 ID。debug/release 报告位于根目录 artifacts/browser-plugin-smoke-*.json；这不代表具体产品页面或视觉验收。

当前 Windows x64 release 与真实 npx 已通过默认免令牌和显式令牌双阶段、五个原生插件及正常停止/监听释放。设备提供者、常驻会话、另一台局域网客户端、其他系统和真机仍需独立实现或验收，不将通用插件闭环扩写为全部迁移完成。
