# 性能动态提供者生命周期实施方案

状态：独立设计建议，公共契约、版本、端口和错误映射均待主代理冻结。本次仅交付本文件，不表示动态性能源已经实现或验收。日期：2026-10-09。

## 目标与范围

在宿主保留性能会话调度、CPU 差分、SQLite 历史、暂停/恢复与分页；将平台采样归独立插件，并允许当前代采样贡献热加载和安全卸载。设备型样本必须经过通用设备准入与共享锁，不能以长期持有探针或禁止卸载代替生命周期管理。

本批建议只覆盖一次请求、一次样本、一个插件进程。持续 FPS 采集、常驻连接、派生进程树、真机回滚、历史删除/导出与磁盘总配额继续独立设计和验收。不增加宿主 Android/Harmony 分支，不新增产品界面，不冻结 HTTP/MCP 字段。

上位边界见 [平台适配器迁出实施](平台适配器迁出实施.md)、[运行中插件生命周期](../guides/运行中插件生命周期.md) 与 [合作取消插件协议](../contracts/合作取消插件协议.md)。前端性能消费由所属角色另行设计，不能从本方案推导已有生成类型。

## 最小身份与版本建议

以下只是需要表达的语义，不是 DTO、JSON 属性或已存在的 Rust 类型名。

| 身份 | 建议含义 | 不允许的推导 |
| --- | --- | --- |
| 采样源归属 | 插件 ID、加载 generation、实际采样贡献及其声明快照；插件 version 可作为历史展示信息 | 用插件 version 代替 generation，或按来源字符串临时找最新插件 |
| 设备引用 | 设备型源固定 `DeviceRef` 的 provider ID、generation、stable local ID，并固定实际能力版本 | 从裸 `device_id`、平台名称、加载顺序或当前首个在线设备猜归属 |
| 会话修订 | 原有 revision，隔离 pause/resume/stop 与样本竞争 | 将 revision 当 owner generation，或跨修订复用 CPU 差分基线 |
| 会话存续 | 独立会话 UUID、运行期取消树、当前样本与排空状态 | 复用已结束的 start Job 取消令牌来管理长会话 |

建议首批设备型源由同插件声明实际设备采样能力，复用精确 capability/version 与固定封套，不另造一套读写声明。来源 owner 与设备 provider owner 可以不同，但必须由明确配置或公开选择关联；跨 owner 时同时复核和跟踪两者，不能合并 generation，也不能只跟踪来源。

协议 2 合成探针没有 devices 声明，不能因迁移而要求其凭空发现设备。建议保留“独立源兼容模式”：仍绑定当前源 owner/generation、预算、限额及卸载排空，但没有设备引用和设备互斥保证。既有 `{device_id,package}` 保持原输入语义；若兼容插件实际访问硬件，必须补明确设备关联后才能作为设备型源发布，不因带有 device_id 就声称共享锁已覆盖。

设备型来源的版本化声明应与协议帧版本分别审查：采样贡献引用、目标模式、输入映射和能力关联须显式可校验。旧声明省略新版本保持旧协议 2 兼容；未知版本、冲突映射和越界命名空间拒绝。`deny_unknown_fields` 下不能把新字段直接塞给旧解码器并称兼容。确切声明版本号、字段和便携包保留方式待主代理冻结。

会话创建后归属不可自动更换。相同 ID 重载得到新 generation，旧会话不得 resume 到新源/新设备；用户需要显式创建新会话。宿主重启后旧会话仍 Interrupted，即使数值 generation 恰好相同也不恢复旧执行。

## 公共端口和注册职责建议

建议在领域端口表达采样源声明，由 Executor 提供默认无贡献的可选元数据；保留 `PerformanceProbe` 作为兼容端口和测试替身。动态插件采样不再通过长期基础设施 probe 绕过 Application。端口名称、签名和旧 probe 的适用范围均待冻结。

| 层 | 最小职责 | 边界 |
| --- | --- | --- |
| plugin-sdk | 版本化性能声明、公开目标/样本；协议 3 性能资格的加法规则 | 不携带宿主 Arc、tracker、锁或私有数据库类型 |
| domain | 来源定义、会话归属语义、样本规则和存储端口 | 不解析进程帧，不引用 Application/基础设施；旧目标的 Android 包名限制不能冒充通用目标规则 |
| application 注册层 | 校验声明引用与双 schema，原子发布/撤销采样源和对应 owner；设备型源校验能力关联 | 不根据平台猜映射；错误声明不留下半发布贡献 |
| application 性能服务 | 创建/控制会话、跟踪依赖、短样本调度、提交序列和历史查询 | 不调用平台命令，不再次提交嵌套 Job，不长期占通用 Job worker |
| application 执行内核 | 当前快照、准入、取消树、共享设备锁、截止点和清理风险复核 | 普通直接 sample Job 与后台样本共用此边界，直接 Job 不创建性能会话或追加历史 |
| infrastructure | ProcessPlugin 的声明映射、协议传输、样本解码和 SQLite 事务 | 样本解码适配器可以保留；不得自持源并直接执行来替代应用准入 |
| server | 配置及通用端口装配，HTTP/MCP 使用已有任务层 | 不加入平台采样分支；来源选择和响应字段由后续契约/生成门禁确定 |

应用层建议注入轻量执行/注册句柄，避免 `Application → PerformanceService → Arc<Application>` 强引用环。来源操作及旧会话操作仍走同一注册门禁；旧操作绑定不可直接映射成一次 sample 来伪装长会话。

声明验证保留本地 schema 编译和真实输入校验，不用固定 device_id/package 样例证明任意业务 schema 可调用。设备型映射只允许冻结后的有限形式，固定封套/范围最低结构校验与能力规则共用。输出继续拒绝产物，不能经其它贡献或嵌套选择器绕过性能禁产物门禁。

## 会话创建、每次采样与发布

1. start 校验参数、显式来源选择及当前设备引用，取得独立会话名额。在应用接受工作门禁与同一注册快照下绑定全部 owner，并登记会话/启动工作；禁止 `shutdown/tracker.close` 完成后再 spawn。
2. 持久化创建和 worker 装配在受跟踪工作中完成。调用 Future 丢弃不打断半装配；启动取消或 owner 在装配期间撤销时，收敛记录和名额，不留下 Running 无 worker 的会话。继承 `LogContext`，只记录归属/修订/错误码，不记录任意插件输出。
3. start Job 完成后，会话拥有独立存续令牌；任一归属 owner、设备依赖 owner 或服务关闭都能取消它。一个 worker 可登记到多个依赖跟踪计数，但不得因此启动两份采样循环；Paused 会话也保留这项卸载依赖。
4. tick 只启动一个样本；保留跳过错过周期的定时器，不堆积补采队列。样本取得有界执行名额与绝对截止点，再校验源/设备代际、当前目录、能力可用、会话 revision 和 cleanup_failed。
5. 设备型样本使用实际能力声明确定 scope/access，取得既有 provider 屏障及必要设备写锁；获锁后及执行 Future 首次轮询紧邻调用前再次复核取消、到期、代际和清理风险。无效样本不得先 spawn 再取消。
6. ProcessPlugin 使用同一 `ExecutionContext`；响应解码仍验证计数、时间窗口、FPS 声明和无产物。任意 JSON 内有 result 不构成可解包证据，只有执行端口声明的宿主包装格式才能解包。
7. 成功样本进入会话独立、有界的提交序列，再复核 Running/revision、来源/设备归属及截止点。SQLite `append` 保留事务 CAS；未获提交资格的晚到样本直接丢弃，不能把旧代结果改标为新代。

提交与撤销需明确线性化。建议短时准入门禁发放“一次提交资格”作为先后点，资格和实际阻塞写入均归 owner 排空；撤销后不再发放资格。撤销前已获资格的写入可在卸载等待期间收敛，卸载成功返回前必须结束。pause/stop 与 append 在会话提交序列内排序并由存储 revision 兜底，终态后的旧样本不得写入。不得以写入前一次 owner 检查后跨 await/阻塞排队，宣称已解决竞争；若要求撤销瞬间连先获资格的提交也废弃，须额外冻结存储失效协议。

不持全局注册表锁等待数据库或异步 I/O；阻塞池许可必须移入闭包，取消外层等待不释放仍执行的写入名额。提交排空超时不能声称 SQLite 闭包已停止。

## 共享锁与单样本预算

所有设备范围样本持 provider read 屏障，device write 再持 `(provider ID, stable local ID)` Mutex；provider write 持 write 屏障，必须阻止所属设备的 read/write。锁键不含 generation；弱引用池复用现有原子创建/升级规则。

当前设备 Mutex 只实现设备写写互斥，device read 不取得该 Mutex，因此不能宣称同设备 read/write 已全互斥。需要独占观测窗口或会修改 FPS 状态的能力应声明 write；纯只读样本仍受 provider write 屏障。不得由客户端传入 read 标志，也不得以“采样”名称自动降成 read。

会话空闲、Paused、历史查询和控制操作不持设备锁；pause/stop/unload 不得一边占采样锁一边等待采样清理。守卫覆盖实际进程退出/清理结果；超过清理窗口仍未确认时，进入粘性失败门禁后才允许释放物理守卫，随后排队任务不得再执行。

建议保留单样本 10 秒上限，会话时长仍含暂停时间；同一单调绝对点覆盖执行槽等待、设备锁等待、输入准备、进程、解码和提交资格等待。样本截止点取“准入时刻 + 10 秒”、会话截止点、实际能力预算及继承父期限的最小值；能力声明不能把本批采样延长为 30 秒或长安装期限。准入从样本 tick 进入执行内核时开始，不从获锁后重计时。恢复不延长会话总时长。

到期后不得启动下一 I/O 或接受新提交资格；已准入的阻塞提交可能晚结束，需跟踪排空，不能虚称硬停止。会话到期/取消先请求样本取消，再给既有最多 2 秒独立清理窗口。建议统一截止点已过时分类 Timeout，否则用户取消分类 Cancelled；同刻选择及会话终态映射待冻结并用确定性测试固定。墙钟 captured_at 校验不代替单调 deadline。

## 暂停、恢复、卸载与历史

| 事件 | 建议收敛 | 不允许的行为 |
| --- | --- | --- |
| pause | 持久化 Paused 并增 revision，取消当前样本；保留 owner 依赖及会话期限 | 返回 Paused 就宣称设备资源已释放 |
| resume | 仅原来源/设备 generation 仍当前、全部清理已确认且期限未过时恢复；前一样本未排空时拒绝，恢复重建 CPU 基线 | 旧 Future 仍运行时启动下一样本，或自动选择新代 |
| stop | 保留当前持久化 Stopped/终态幂等兼容，撤销新样本并排空现有工作 | 控制返回即当作卸载成功，或清理失败覆盖已提交终态 |
| 会话到期 | 无错误且清理确认后 Completed；到期与用户 stop 由先成功的终态 CAS 决定 | 丢弃未确认 Future 后写“正常完成” |
| 来源或设备 provider 卸载 | 同一撤销门禁取消相关 Running/Paused 会话，非终态建议 Interrupted；等待启动工作、worker、在途样本及提交结束 | 仅撤销来源入口而让后台 probe 继续执行 |
| 样本失败/清理失败 | 未终态会话建议 Failed；会话已终态则保留其状态，另保留清理风险及诊断 | 忽略清理失败然后恢复下一 tick |
| 同 ID 重载 | 仅已排空且无未确认资源的旧 owner 可以完成删除；新会话绑定新 generation | 在 Draining/cleanup_failed 时重载同 ID |
| 服务关闭/重启 | 先关闭全部准入，再取消/等待；重启 recover 为 Interrupted，保留原记录和样本 | tracker 已 wait 完成后补 spawn，或从历史探针自动续跑 |

动态卸载复用 `PluginService` 的串行变更/包删除门禁，不新增只属于性能的管理通道。detach 需同步撤销采样源并触发依赖取消，不能先成功卸载再异步找会话。保留现有卸载 10 秒外界等待；等待超时维持 Draining，不删除 owner、不释放同 ID 重载资格，不宣称已经排空。未确认资源另返回 CleanupFailed 并保留 cleanup_failed；不是每次慢存储等待都能直接证明外部资源未释放。

清理风险至少阻止来源新任务、排队刚获锁的样本和 resume。若跨 owner 样本实际持有设备资源，未确认风险还必须阻止该设备/provider 上可冲突操作，不能因设备提供者自己的 Executor 仍健康就绕过；具体共享风险标记端口待冻结。普通协议 2 取消且直接进程清理已确认，或协议 3 合作清理成功，不得误标失败；其它并发成功不得清除已有未确认标记。

只有上述会话归属、跟踪、排空及失败门禁完整验收后，才撤除性能用途的 protected 集合及其启动装配。`APK_PERFORMANCE_PLUGIN` 可保留为显式默认来源选择的部署兼容入口，但不能重新建立永久 probe；配置指向尚未加载来源时是启动报错还是仅 start 不可用，待主代理冻结。没有来源/平台工具的宿主应能启动且读取历史，不自动回退 Android。

历史保存源/设备归属的不可变值，不保存 Arc、令牌或可执行探针。旧 SQLite 记录缺少新归属时保留缺省，不能按当前插件反填；迁移须兼容既有分页、样本序号与 CPU/FPS 口径。卸载不删除会话、样本、旧 Job 结果，历史查询不需要活跃来源。

八个旧操作分组处理：`start/resume` 必须有可执行的原代来源；`pause/stop` 控制既有会话；`inspect/samples/list` 读历史；`capabilities` 查询当前可用来源而不承诺历史源仍在线。旧单源 capabilities 的 wire、无源行为和通用名称如何呈现需另冻结；本方案不新增 HTTP 路径/字段，也不把全部旧操作直接绑定成插件 sample。

## 协议 2 兼容与协议 3 加法

协议 2 保留已有 PerformanceAccess、PerformanceTarget、PerformanceSample、FPS 可缺省语义和空输出约束；原生 performance-demo 的 synthetic 来源继续验证旧协议。样本解码保持 captured_at 为宿主当前墙钟前 60 秒至后 5 秒、计数有效、声明 fps 才允许 frame_window，CPU 只比较同 PID/启动计数/核数的相邻样本。

协议 3 当前 performance 声明在 ProcessPlugin 门禁中被拒绝。本批建议显式开放资格，并让同一公开样本位于现有响应业务 result 中；宿主适配器取得已验证的结果包装后再解码样本，不重复猜测响应结构。插件取消控制、匹配响应、零退出和 cleaned 确认沿用现协议 3；不新增性能 session 帧或宣称常驻。

清理沿用合作 1250 毫秒、终止/等待 500 毫秒及宿主外层最多 2 秒，不扩大生产期限。收到取消响应但仍等 stdin EOF 的插件必须正常收敛；错 ID、failed、无响应、输出超限、非零退出和 Future 丢弃保留原清理判定。协议 2 已确认直接进程退出仍不证明派生树、远端设备事务或共享 daemon 被释放；声明资源需求的采样源须选择能确认的协议，不把旧协议成功退出包装为合作清理证据。

## 待主代理冻结的选择

1. **来源契约与兼容**：设备型来源的声明版本/输入关联，跨 owner 支持边界，独立协议 2 兼容模式，以及旧环境变量/操作/能力响应的无源行为。推荐显式选择、保留旧 wire，不静默回退。
2. **执行与提交边界**：内部端口、每样本 10 秒绝对预算是否含提交资格、一次提交资格线性化与阻塞写入排空、超时/取消同刻选择。推荐复用通用内核，采用本文提交资格先后规则，不承诺已运行闭包硬停止。
3. **清理与历史呈现**：跨 owner 设备风险标记、暂停/停止的状态确认与排空回执、源卸载的会话终态/归属持久化、协议 3 性能资格。推荐保持旧控制 wire、另保留风险证据，验收后再去 protected；具体公开字段另走生成门禁。

本文件冻结的是设计稿版本。以上选择未形成公共冻结契约，动态性能实现、release/npx 与真机验收均未由本次完成。
