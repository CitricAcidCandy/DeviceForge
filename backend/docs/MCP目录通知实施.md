# MCP 动态工具目录通知

## 契约与职责

MCP 协议 `2026-07-28` 通过 `subscriptions/listen` 的 POST SSE 流订阅 `toolsListChanged`。沿用现有 `rmcp 3.5.1`、无会话传输、可选令牌和 Origin/Host 校验；普通发现与工具调用仍返回 JSON。服务器声明 `tools.listChanged`，只接受已请求且实际支持的工具目录通知。

- 用例注册表是目录修订的唯一来源。成功发布操作、别名或会话，以及首次撤销贡献时，在同一个短时写锁内更新修订并发布最新值。
- 冲突、失败发布、重复撤销和排空完成不产生额外目录变化。设备观测、任务状态不属于工具目录变化。
- 用例层只公开目录修订的异步订阅，不引用 MCP、HTTP 或服务器模块；服务器负责把失效信号转换成标准 `notifications/tools/list_changed`。
- 每次订阅先发送一次目录失效通知，要求客户端重新读取目录，以覆盖发现与订阅建立之间的变化。之后使用容量为一个最新值的 watch 通道，允许合并连续修订；通知数量不等于注册次数。
- 通知本身不包含工具或插件数据。客户端重新执行 `tools/list`，沿用修订游标、每页 100 条、缓存时间零和旧游标失效规则。

## 资源与关联

一个服务实例最多接受 32 个活动目录订阅。每个订阅独占一个许可，慢客户端不会阻塞注册表发布，也不会累积无限事件。发送最长等待 5 秒；请求断开、取消、服务器退出或发送失败均结束订阅并释放许可，不新建游离后台任务。

MCP 日志适配器必须转发订阅过滤及监听方法，关联订阅请求、目录失效发送和终止日志。HTTP 流响应沿用 `x-deviceforge-log-id`；目录通知附加标准扩展元数据 `deviceforge/log_id`。SDK 自行生成的订阅确认与正常结束帧保留 SDK 标准结构，不承诺它们包含宿主自定义元数据。

旧协议客户端继续显式读取目录，不将现代订阅实现宣称为旧会话 GET SSE 支持，也不增加独立平台或业务分支。

## 验证范围

定点验证覆盖成功发布/撤销、失败与重复操作不通知、连续修改合并、普通操作与会话贡献共享修订、标准 POST SSE 的确认/失效/重新发现、可选鉴权、关闭和重新订阅、订阅容量与慢发送边界。既有 MCP JSON、共享任务及日志关联需要回归；阶段完整门禁、当前 release/npx 和真实 MCP 客户端互操作独立验收。
