# Rust 原生插件分发

## 目标与文件职责

内置插件使用公开 SDK 独立编译，通过通用 npx 安装器部署。插件操作与输入模式在各插件的 manifest.json 中维护；不存在正式清单时兼容原 manifest.example.json，正式清单损坏则直接失败。Cargo 提供版本、许可证和二进制目标，打包时派生便携 plugin.json 与 npm 描述，避免另写一份操作契约。

| 文件 | 职责 | 边界与副作用 |
| --- | --- | --- |
| 根 scripts/native-plugin-plan.mjs | 校对 Cargo/清单版本，派生平台包与入口 | 纯函数；宿主注册规则仍由 Rust 校验器负责 |
| 根 scripts/native-plugin-source.mjs | 读取当前公开清单与配置模板 | 受限 JSON 和普通文件门禁；不采集实际部署配置 |
| 根 scripts/native-plugin-assets.mjs | 读取静态成员声明并校验复制身份 | 受控文件映射、大小和目标冲突门禁；不扫描未声明目录 |
| 根 scripts/native-plugin-package.mjs | 发现插件、原生 release 构建、Rust 门禁、npm 打包 | 编译及文件操作；业务执行由插件承担 |
| 根 scripts/pack-native-plugins.mjs | 命令入口与中文摘要 | 只选择插件 ID 并调用打包流程 |
| 根 scripts/cli-smoke-native.mjs | tgz 安装后的行为验收 | 经 HTTP/MCP 检查公开任务和产物 |

## 构建与安装

构建者在项目根目录执行：

```powershell
npm run pack:plugins
# 可只打包指定插件 ID。
npm run pack:plugins -- msgpack echo
```

脚本从 Cargo 工作区发现 backend/plugins 下的独立插件，要求一个二进制目标且清单版本与 Cargo 一致。Rust host 必须匹配当前 Node 平台和架构；显式使用该 host 构建 release，再从 Cargo JSON 构建结果取得真实程序路径，不猜测默认 target 目录。当前实际构建与验证平台为 Windows x64。

包名带平台后缀，npm 的 os/cpu 与 deviceforge.entrypoints 同时标明平台。Windows x64 产物如下：

| 插件 ID | 文件 | 用途 |
| --- | --- | --- |
| echo | deviceforge-plugin-echo-win32-x64-0.1.0.tgz | 协议 1 回显示例 |
| artifact_copy | deviceforge-plugin-artifact-copy-win32-x64-0.1.0.tgz | 协议 2 受控产物复制示例 |
| msgpack | deviceforge-plugin-msgpack-win32-x64-0.1.0.tgz | 标准 MessagePack 转换和查询 |
| performance_demo | deviceforge-plugin-performance-demo-win32-x64-0.1.0.tgz | 合成性能/FPS 协议示例 |
| cooperative_demo | deviceforge-plugin-cooperative-demo-win32-x64-0.1.0.tgz | 协议 3 合作取消与资源清理示例 |

文件输出到根 artifacts。构建者需 Rust、Node.js/npm；部署者使用预编译 tgz，只需 Node.js/npm。先生成或取得 CLI 运行包，再执行：

```powershell
npx --yes --package .\artifacts\deviceforge-cli-0.1.0.tgz deviceforge plugin install .\artifacts\deviceforge-plugin-msgpack-win32-x64-0.1.0.tgz
npx --yes --package .\artifacts\deviceforge-cli-0.1.0.tgz deviceforge plugin list
# 默认免鉴权；服务启动会加载已部署插件，运行中安装则显式加载。
npx --yes --package .\artifacts\deviceforge-cli-0.1.0.tgz deviceforge start
```

本地 tgz 包不等于已公开发布 npm。插件 ID、版本和协议独立于平台包名；一个 ID 在同一部署目录只允许一个安装，不能用切换 npm 包名绕过覆盖限制。CLI 参数和数据位置见 [命令行部署与插件安装](命令行部署与插件安装.md)。

## 分发门禁

打包先去除手工部署示例中的 executable，再通过安装器的公开便携描述生成暂存绝对入口，并调用同次 release 构建的 validate-plugin。门禁验证协议、能力、输入模式与入口，不执行插件。npm pack 禁用生命周期脚本，包含二进制、便携清单、README、npm 必需元数据，以及源码目录内除 manifest.example.json 以外的公开 *.example.json。配置模板放在包内 bin，部署者按插件说明复制为实际配置并填写本机路径后显式加载；不自动启用，也不采集实际 *.config.json 或凭据。暂存目录由本次构建创建，检查清理边界后删除，tgz 保留。

根 `npm test` 的分发规则测试覆盖版本漂移、入口歧义、未知/重复选择、包名冲突、Rust/Node 平台不一致及正式清单/公开模板。2026-10-10 当前18项通过，release运行包门禁通过。此前 `npm run smoke:cli` 的五个release原生包与Node依赖插件通过真实npx，覆盖回显、产物复制和摘要、MessagePack、合成采样及合作清理；两鉴权模式均正常停止并释放端口。该历史结果不转计以下新八包矩阵。

需要旁置运行文件的插件可在源码根提供 `package-assets.json`，结构为 `{"api_version":1,"files":[{"source":"worker/dist/index.js","target":"bin/worker/dist/index.js"}]}`。每项必须指向源码根内非链接普通文件，目标位于包内 bin，复用安装器相对路径规则；最多64项、单文件8 MiB、累计32 MiB。拒绝大小写重复、文件/目录前缀冲突及入口或模板覆盖，构包期间复制摘要须匹配预先读取的成员身份。未声明的运行目录、依赖树及实际配置不会自动打包。当前 AI SDK 声明五个固定 worker JS 与两份包元数据，Node/官方 SDK/CLI仍须按插件说明由部署者准备。2026-10-12 新静态成员6项加既有来源/计划6项共12项定点通过；2026-10-13 已生成 Windows x64 AI SDK TGZ，并用本地 CLI TGZ 经真实 npx 在隔离目录安装/列举 6 项操作。该证据不等于真实模型、完整服务 release、跨平台或 registry 发布。

## 当前边界

当前仅交付 Windows x64 独立包，没有跨平台合并包、npm 公开发布或同 ID 包原地升级。默认免鉴权，非空令牌可选；通用进程插件通过 HTTP/MCP 加载/卸载/重载，详见 [运行中插件生命周期](运行中插件生命周期.md)。在线部署删除已提供，在线目录与 CLI 旧部署目录的区别见 [在线插件接口](在线插件接口.md)。离散设备提供者及默认性能来源支持热装卸；来源会话按原代际排空，常驻设备会话仍待实现。当前性能版本正式包/npx需独立验收，不能转计历史包结果。插件按可信代码运行，便携包和独立进程不构成系统沙箱。performance_demo 只提供合成协议数据，不能证明真实设备性能/FPS；MessagePack 的旧 DLL 私有格式仍待样本和兼容验证。
