# Rust 原生插件分发

## 目标与文件职责

内置插件使用公开 SDK 独立编译，通过通用 npx 安装器部署。插件操作与输入模式只在各插件的 manifest.example.json 中维护；Cargo 提供版本、许可证和二进制目标，打包时派生便携 plugin.json 与 npm 描述，避免另写一份操作契约。

| 文件 | 职责 | 边界与副作用 |
| --- | --- | --- |
| 根 scripts/native-plugin-plan.mjs | 校对 Cargo/清单版本，派生平台包与入口 | 纯函数；宿主注册规则仍由 Rust 校验器负责 |
| 根 scripts/native-plugin-package.mjs | 发现插件、原生 release 构建、Rust 门禁、npm 打包 | 编译及文件操作；业务执行由插件承担 |
| 根 scripts/pack-native-plugins.mjs | 命令入口与中文摘要 | 只选择插件 ID 并调用打包流程 |
| 根 scripts/cli-smoke-native.mjs | tgz 安装后的行为验收 | 经 HTTP/MCP 检查公开任务和产物 |

## 构建与安装

构建者在项目根目录执行：

```powershell
npm run pack:plugins
# 可只打包指定插件 ID。
npm run pack:plugins -- msgpack echo
```

脚本从 Cargo 工作区发现 backend/plugins 下的独立插件，要求一个二进制目标且清单版本与 Cargo 一致。Rust host 必须匹配当前 Node 平台和架构；显式使用该 host 构建 release，再从 Cargo JSON 构建结果取得真实程序路径，不猜测默认 target 目录。当前实际构建与验证平台为 Windows x64。

包名带平台后缀，npm 的 os/cpu 与 deviceforge.entrypoints 同时标明平台。Windows x64 产物如下：

| 插件 ID | 文件 | 用途 |
| --- | --- | --- |
| echo | deviceforge-plugin-echo-win32-x64-0.1.0.tgz | 协议 1 回显示例 |
| artifact_copy | deviceforge-plugin-artifact-copy-win32-x64-0.1.0.tgz | 协议 2 受控产物复制示例 |
| msgpack | deviceforge-plugin-msgpack-win32-x64-0.1.0.tgz | 标准 MessagePack 转换和查询 |
| performance_demo | deviceforge-plugin-performance-demo-win32-x64-0.1.0.tgz | 合成性能/FPS 协议示例 |

文件输出到根 artifacts。构建者需 Rust、Node.js/npm；部署者使用预编译 tgz，只需 Node.js/npm。先生成或取得 CLI 运行包，再执行：

```powershell
npx --yes --package .\artifacts\deviceforge-cli-0.1.0.tgz deviceforge plugin install .\artifacts\deviceforge-plugin-msgpack-win32-x64-0.1.0.tgz
npx --yes --package .\artifacts\deviceforge-cli-0.1.0.tgz deviceforge plugin list
# 配置 APK_API_TOKEN 后重启，加载刚安装的插件。
npx --yes --package .\artifacts\deviceforge-cli-0.1.0.tgz deviceforge start
```

本地 tgz 包不等于已公开发布 npm。插件 ID、版本和协议独立于平台包名；一个 ID 在同一部署目录只允许一个安装，不能用切换 npm 包名绕过覆盖限制。CLI 参数和数据位置见 [命令行部署与插件安装](命令行部署与插件安装.md)。

## 分发门禁

打包先去除手工部署示例中的 executable，再通过安装器的公开便携描述生成暂存绝对入口，并调用同次 release 构建的 validate-plugin。门禁验证协议、能力、输入模式与入口，不执行插件。npm pack 禁用生命周期脚本，只包含二进制、便携清单、README 和 npm 必需元数据；暂存目录由本次构建创建，检查清理边界后删除，tgz 保留。

根 `npm test` 的分发规则测试覆盖版本漂移、入口歧义、未知/重复选择、包名冲突和 Rust/Node 平台不一致。`npm run smoke:cli` 通过真实 npx 安装一个带依赖 Node 插件及四个 release 原生包，再启动同一服务验证回显、产物复制和摘要、HTTP MessagePack 编码、独立 MCP 解码/筛选，以及明确标注 synthetic_demo 的合成性能采样。

新增 Rust 插件应属于 Cargo 工作区，具有一个原生入口、中文 README 和公开 manifest.example.json，依赖遵守后端 AGENTS.md 的 SDK 边界。新增或变更插件必须扩展行为验收，不能只检查 tgz 文件存在。

## 当前边界

当前仅交付本机构建平台的独立包，没有跨平台合并包、来源签名、npm 公开发布、同 ID 包升级或部署文件删除。已部署通用进程插件可通过鉴权 HTTP/MCP 加载/卸载/重载，详见 [运行中插件生命周期](运行中插件生命周期.md)；长期性能探针引用的插件受保护，设备提供者和常驻会话仍未支持。服务器插件为管理员可信代码，便携包和独立进程均不构成系统沙箱。performance_demo 只提供合成协议数据，不能证明真实设备性能/FPS；MessagePack 的旧 DLL 私有格式仍待样本和兼容验证。
