# 原 JPEG 截图与产物交付

本模块只实现公开 `screenshot@1` 的设备范围写操作，原总预算为30000毫秒。输入严格为 `{device_id:"HDC001",input:{}}`，不接受业务扩展字段、输入产物或调用者指定路径；宿主必须先授予输出目录。输出是 `value:null` 与唯一 `ArtifactOutput{filename:"screenshot.jpeg"}`，由宿主构造协议4 `{result:null,artifacts:[宿主产物实体]}`，本模块不分配产物标识或编写宿主路由。

## 模块职责

- `scripts.rs` 保存五个固定远端模板和独立 HDC argv；本次标识仅接受32位小写十六进制，设备参数复用现有 ASCII 资格。
- `rules.rs` 校验完整唯一终端回执、所有权、规范状态、平台探测、官方 JPEG 成功诊断及十进制大小。
- `receive.rs` 从有界接收文件确认帧尾，按正文范围检查失败诊断和严格流式 Base64；保持原字节，不把回执或日志交给图片验证器。
- `jpeg.rs` 只映射公开 `deviceforge_data_codec::jpeg::Validator` 错误；不复制 JPEG 解析，不解码像素或重编码图片。
- `publish.rs` 管私有目录、授权输出预登记、`create_new` 复制、真实关闭和失败清理。
- `screenshot.rs` 编排资格探测、截图、大小、读取、公共 JPEG 验证、授权复制及远端和本地收尾。

## 固定远端资格与阶段

远端根固定为 `/data/local/tmp/deviceforge-screenshot-<token>`。设备必须先通过 `printf 'DeviceForge' | base64 -w 0`，返回精确编码 `RGV2aWNlRm9yZ2U=` 和本次完整探测回执。未通过则不创建截图目录；不能根据部署者的 HDC 路径推断设备编码器资格。

截图模板使用 `umask 077`、独占 `mkdir`、本次 `owner` 文件和前台 `snapshot_display -f`。不使用 `mkdir -p`，碰撞时不删除已有目录。成功同时要求本次 `DF_OWNER_READY`、固定路径的唯一官方 JPEG 成功诊断、非零宽高和完整 `DF_CAPTURED:0`。大小与读取模板继续校验相同所有权；终端回执分别为 `DF_IMAGE_SIZE` 和 `DF_READ_DONE`。

所有预计远端动作在命令派发前登记为待确认。完成回执只确认对应前台工具已经返回；直接 HDC 退出、零退出码、目录当前不存在或一次删除都不能替代远端回执。错标识、重复、缺失、非终端帧及非规范状态拒绝发布。

## 本地接收与数据边界

| 资源 | 固定边界 |
| --- | --- |
| 原 JPEG | 67,108,864字节，64 MiB |
| Base64 正文 | 89,478,488字节 |
| 编码接收帧 | 89,478,616字节，包含最多128字节帧尾余量 |
| 其他 stdout 与每次 stderr | 各1,048,576字节 |
| 公共流分片及通道 | 8192字节，容量8 |
| 私有文件写入通道 | 唯一通道，容量8 |
| 解码输出及复制缓冲 | 约64 KiB |
| 公共 JPEG 结构段 | 最多65,536段 |

接收复用公开 `spawn_stream_with_lease`，保持 Restricted 环境与原绝对截止点。协调任务完整消费 stdout、stderr 后才调用 `wait()`；成功退出的 stderr 仍参与失败诊断。唯一受限阻塞写线程独占真实文件、工作槽与租约，写前检查累计限额、取消和期限，实际刷新、关闭并返回后才确认。

正文只接受规范 Base64 字母表、padding 和尾部位，允许正文末尾至多一个 LF 或 CRLF，拒绝内部换行、空白、截断、日志、padding 后内容和与设备大小不一致。显式 stdout 失败诊断在已确认读取完成后优先处理；合法编码字母中的 `error`、`failure` 等子串不会被当作 HDC 诊断。解析、资格及复制均在受限工作槽执行并重复检查原期限与取消。

公共 JPEG 验证器负责增量结构资格与完整结束，`Limit` 映射为 `数据超过插件限额`，`Invalid` 和 `Unsupported` 映射为具体中文输入错误。结构验证不构成像素解码或图片视觉验收，也不构成远端独立摘要比对；宿主按最终发布字节计算和核验产物摘要。

## 输出所有权与清理

授权 `screenshot.jpeg` 在受限工作排队前预登记，初始为未创建。成功 `create_new` 后立即登记本调用所有权，随后进行分块复制。遇到 EEXIST 不接管或删除已有文件；复制输出只有在真实刷新、关闭及工作线程实际终态成立后才登记为已关闭。

正常业务、远端删除、本地私有目录删除和最终取消检查共用原总预算。同步 `finish_output` 只在无额外租约、无粘性未确认、远端及私有目录已清理时标记移交；此前写入的文件不表示已交付产物。

失败、取消、到期或等待被丢弃时首次固定两秒清理点。直接 HDC、文件句柄、固定远端清理与本地删除全部共享此点，不按资源或重试续预算。失败输出仅删除本调用已经创建、尚未移交且真实关闭的文件；NotFound 可确认，既存碰撞文件及已移交输出保留。

只有已确认截图工具返回且读取未派发，或读取工具已确认返回，才运行固定远端删除模板。所有权不匹配、未知文件、删除失败、失败诊断或缺少 `DF_CLEARED` 均不算清理完成。待确认探测、截图、大小或读取阶段不以额外 `rm` 掩盖可能晚到的创建者或读取者。

工作线程或等待者被丢弃后，后台仍持租约到实际退出，粘性未确认不会因晚到成功清除。处理器未确认返回 `插件资源清理未确认` 与 `CleanupOutcome::Failed`。公开协议4运行库在取消、EOF或期限胜出时优先返回其上下文错误，同时原样保留处理器的清理结果；因此错误文本为取消或期限不表示资源已清理。宿主任务取消优先级、历史和卸载 `draining` 保持既有合同，不新增任务状态。

## 验证范围

`tests.rs` 与其 `tests/receive.rs`、`tests/publication.rs` 覆盖纯输入、固定模板、回执、资格、编码、公共 JPEG 映射，以及授权预登记、EEXIST、实际关闭、失败删除、移交保留、NotFound 和工作等待丢弃后的租约与粘性失败。文件所有权测试通过公开协议4运行入口取得上下文，不新增公共测试构造器。

库测试落盘不等于执行通过。独立原帧、真实宿主模拟 HDC、分发、真实 HDC、设备编码器资格、真机截图及视觉验收分别记录；本模块不代替常驻会话、设备层完整迁出或平台支持验收。完整实施依据为 `backend/docs/Harmony截图插件实施裁定.md`。
