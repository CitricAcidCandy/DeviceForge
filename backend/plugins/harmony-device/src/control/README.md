# 调用资源控制

`Control` 把协议4的原截止点和取消信号传入公开工具库；HDC 只接收固定独立参数与受限环境。调用结束、取消和到期必须等待直接进程清理，不能用 Future 丢弃表示完成。

`resources.rs` 保管单工作槽、目录租约、截图远端阶段、授权输出所有权、首次固定的两秒清理点和等待守卫。等待被丢弃会发取消并设置粘性未确认；弱引用不额外延长目录租约。模块不解析 HDC 文本、不删除目录、不管理共享 daemon。

`worker.rs` 使用同一个工作槽与租约执行受限阻塞工作，安装文件操作和应用详情 JSON 解析共用原截止点、取消与实际返回确认；等待被丢弃、工作线程异常或清理未确认时保留粘性失败。调用者提供纯业务闭包，控制模块不包含平台 JSON 或应用规则。

`file.rs` 将公开 `spawn_stream_with_lease` 的两流完整消费后再等待工具终态；stdout 经容量8的唯一通道交给持单槽、租约和真实文件句柄的阻塞写线程，stderr 独立保留至业务诊断。公共流分片8192字节、容量8，插件在通道提交前和实际写入前分别检查累计限额。写线程真实刷新、关闭并返回后才确认，等待被丢弃不会中止后台监督或线程。截图调用的 stdout 为89,478,616字节，stderr 为1,048,576字节。

`cleanup.rs` 提供仅供固定资源收尾使用的工具与工作入口。业务取消后使用新的清理标识，所有直接进程、文件句柄、远端模板与本地删除共享既有首次固定的两秒点；入口不续预算，不重新运行普通业务。

`finish_output` 接受公共产物输出，只在租约归一、无粘性未确认、远端及私有目录已清理时交付。授权文件必须由本调用创建并真实关闭才能标记移交；错误而仍持有自己创建的未交付文件时返回清理失败。原 JSON 入口 `finish` 保留上下文检查并薄委派，截图在同步移交前完成最终取消及期限检查。
