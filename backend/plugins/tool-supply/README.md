# 工具供应业务插件

独立 Rust 进程通过公开协议 4 提供工具清单、更新计划、安装和显式移除。插件只依赖公开 SDK 与运行库，不引用宿主内部模块。标准输出只写协议帧。

## 部署边界

将构建得到的插件可执行文件和 `tool-supply.config.json` 放在同一部署目录。配置示例见 `tool-supply.config.example.json`。必须恰好配置 `manifest_url` 或 `local_manifest`；本地清单的相对路径以部署目录为基准。`custom` 模式下，`install_root` 必须是专用的绝对目录，模块固定安装到 `<install_root>/<module_id>`；`managed` 模式使用文末的公开共享仓库。普通操作不能传路径、下载地址、程序或参数。

默认下载上限 512 MiB，解压总量上限 1 GiB，成员数量上限 10000。部署者可降低或提高到插件硬上限（下载 2 GiB、解压 4 GiB、成员 100000）。配置最多 64 KiB，清单最多 1 MiB，模块最多 128 个。

默认只允许无地址内凭据的 HTTPS。HTTP 必须由部署者显式启用 `allow_http`，用于受控内网或本地验证。下载不跟随重定向，也不继承环境代理；没有自动重试或新的阶段超时。配置和清单只应由部署者维护，SHA-256 用于校验来自该可信清单的归档。

远程 `manifest_url` 默认启用 `manifest_cache_enabled`。成功获取并完整验证的清单写入安装根下专属 `.manifest-cache`，缓存封装上限为清单上限的两倍（2 MiB），不设置 TTL，也不重置调用期限。封装保存版本 1、规范化来源 URL 的 SHA-256、完整验证清单规范 JSON 的 SHA-256 和清单内容；规范 JSON 使用 Rust 结构字段顺序与数组顺序序列化，版本号不能代替内容摘要。每次回退重新验证封装身份、摘要、清单资格和当前部署限额。缓存只回退清单，不提供归档离线安装。

来源获取的连接、DNS、TLS、非成功 HTTP 状态、响应中断、正文超限和清单解析/资格错误可以回退一个同来源缓存快照。请求配置、URL策略、客户端初始化、本地清单错误不读取远程缓存。缓存不存在只是未命中；缓存损坏、身份不符、链接或非普通文件、权限/元数据/读取错误、锁忙，以及缓存写入、刷新、同步、原子提交或清理错误均硬失败。取消和到期在来源、缓存和提交阶段均硬失败，不另开回退窗口。查询操作可在无缓存时保留原来源错误降级，计划、安装和准备仍失败。

五个清单外层结果包含 `manifest_source`、`manifest_sha256` 和 `source_error`；`catalog`、`plan`、`install`、`runtime_feature.status`、`runtime_feature.prepare` 均带完整元数据，单模块 `install` 另带 `manifest_version`。准备结果的 `modules` 子项仍保持原四字段，不嵌套来源元数据，共享内容复用也保持该契约。当前来源为 `live` 时来源错误为空，缓存回退为 `cache` 且同时保留脱敏来源错误；无快照查询降级时三项元数据为空而来源错误存在。前端应按这组三态校验，不把缓存成功误判为无版本。

缓存锁只存在 `.manifest-cache` 内，网络请求不持锁，缓存读写不取得模块锁。旧 `install` 仍先取得模块锁再读取清单；其他清单操作先完成来源/缓存短锁，再按原业务取得模块锁，避免锁顺序反转。

`manifest.json` 描述七个操作及预算；部署打包时应按宿主插件包规范补齐实际可执行文件定位。操作均位于 `plugin.tool-supply.` 命名空间，不在宿主增加业务分支。

## 操作输入与结果

| 操作 | 输入 | 结果 |
| --- | --- | --- |
| `catalog` | `{}` | 清单版本、来源错误、各模块的可用版本/已安装版本/差异动作 |
| `plan` | `{"module_ids":["adb"]}`，省略或空列表代表全部 | 清单版本、需下载总字节数、模块计划 |
| `install` | `{"module_id":"adb"}` | 模块版本、是否改变；改变时含 SHA-256 |
| `import` | `{"archive_artifact_id":"上传产物的UUID","module_id":"adb","manifest":完整工具清单对象}` | `module_id`、`version`、`sha256`、`changed` |
| `remove` | `{"module_id":"adb"}` | 是否移除；移除时含原版本 |
| `runtime_feature.status` | `{"feature_key":"case-assistant"}` | 清单版本、来源错误、匹配runtime模块以及整体found/ready |
| `runtime_feature.prepare` | `{"feature_key":"case-assistant"}` | 单清单快照中的模块安装结果，成功时ready为true |

所有输入拒绝额外字段。ID 使用小写字母开头的最多 64 位字母、数字、下划线或连字符；Windows 保留设备名也拒绝。`plan` 的 ID 不得重复。只通过显式 `remove` 移除，不随清单删除自动删除本地模块。

`feature_key` 单独沿用清单功能标识规则：非空、有效UTF-8、最多128字节，不套用模块ID字符或Windows设备名限制。功能只由部署者清单的`type=runtime`与`featureKey`映射，可匹配多个模块；同键tool不参与准备，未知功能不使用硬编码回退。

功能查询保留全局稳定本地状态预检，各模块状态在对应锁内读取。合法在途安装/移除导致`Busy`业务失败，不标记清理失败；取得锁后仍有事务才报告未确认清理。稳定损坏和真实遗留在未知功能、来源失败时也不能隐藏。来源错误成功返回空匹配和脱敏`source_error`，取消/到期仍失败。只有全部模块`current`且入口存在才就绪，更高本地版本不能替代清单版本。

功能准备只加载一次清单，按清单顺序调用共享单模块安装事务，保持原绝对预算。前面已提交的模块在后续失败/取消时保留，当前模块沿原回滚/清理规则，后续模块不执行；这不是跨模块全有或全无事务。重复准备已符合资格的模块不下载。结果不返回服务器路径，也不证明SDK已执行或来源缓存兼容完成。完整裁定见`../../docs/工具运行时功能迁移裁定.md`。

差异动作包括 `install`、`update`、`repair`、`current`、`local_newer`、`local_only`。相同数字版本和摘要且入口存在时不下载；相同版本但摘要不同或入口缺失时修复；拒绝自动降级。版本采用最多八段点分非负整数，`1.2` 与 `1.2.0` 数值相等，不接受预发布标签。来源不可用时 `catalog` 保留本地状态并给出 `source_error`，`plan/install` 则失败；取消和原期限到期不会降为离线成功。

清单格式见 `tool-catalog.example.json`。示例 URL、摘要和大小是占位数据，不能作为可安装发布包。保留旧 `tool_updater` 的 `name/type/version/url/sha256/size/required/entryFile/featureKey` 元数据；`runtime` 必须包含入口和功能标识。可用 `archiveRoot` 选择 ZIP 内包装目录，入口相对于该目录。

本地导入先上传 ZIP 为受控产物，再调用 `plugin.tool-supply.import`，同时提供现有格式的完整工具清单及其中一个模块 ID。操作声明 `/archive_artifact_id` 输入指针，只接受宿主准备的唯一匹配 ZIP 副本；请求不能指定服务器源路径或安装目的路径。清单的 URL 仍须符合部署 HTTPS/可选 HTTP 策略，但导入不读取部署清单、不发网络请求、不建立远端缓存，也不执行入口程序。清单、产物描述及真实归档的长度与 SHA-256 必须一致；摘要、入口、包装根、版本与降级规则沿用原安装事务。相同版本已安装仍核对上传内容，资格相同则返回 `changed=false`。结果只包含上表四字段，不声称存在远端 `manifest_source`。

`custom` 模式的本地导入与在线安装均写入部署配置的绝对 `install_root`，该目录与插件进程和 npx 缓存生命周期独立；该旧模式的内容没有公共仓库引用保护。需要宿主共享时应显式选择 `managed`。插件只读取 SDK 的公开描述，不从宿主私有记录推断路径，也不会自动搬迁原安装。已有显式配置继续生效。

旧 `extractRoot` 字段仅兼容读取，不再决定服务器目标目录；它与新 `archiveRoot` 含义不同。部署迁移时需要为 ZIP 包装目录明确配置 `archiveRoot`，并核对消费者使用的固定模块目录。`minAppVersion` 作为清单元数据读取，当前插件不把旧 Electron 应用版本当新宿主兼容性证据。

安装状态同时记录实际 `archive_root`。同一 ZIP 即使版本、下载摘要和入口名称不变，只要切换包装根，也必须重新修复安装内容；不能返回 current 或 changed=false。旧状态缺少该字段仍允许读取，但进入 repair，成功重新安装后保存完整资格。该行为由同归档 A/B 根切换及旧状态恢复回归验证。

## 事务和取消行为

每个模块从清单读取开始就持有跨进程文件锁，移除或第二个安装不会等待并越过在途安装。锁文件永久保留，但排他锁由文件句柄实际持有，进程退出后释放。

下载写入 `<install_root>/.transactions/<module_id>/archive.zip`，同时计算 SHA-256，长度和摘要都匹配才解压。中央目录的声明数量和体积在 ZIP 库建立成员表之前检查。解压拒绝分卷/ZIP64、符号链接、特殊文件、绝对路径、`..`、反斜杠、设备名、状态文件覆盖及重复/大小写冲突；按实际读取字节累计限额。原期限和取消令牌贯穿每个网络块与解压块，阻塞解压工作始终被等待到实际结束，取消后才清理 staging。

新模块的版本、摘要、入口、功能标识和安装时间先写进 staging 内的 `.tool-supply-state.json`，然后把旧目录重命名为 backup，再把 staging 根重命名到固定目标。每次重命名发生在同一文件系统内；两个重命名之间有短暂不可见窗口，不承诺多目录原子快照。提交前失败或取消会恢复真实 backup，且回滚不使用已经撤销的业务预算。

提交完成后移除 backup 和事务目录属于资源收尾。此阶段失败返回 `cleanup=failed`，已提交的新版本可能仍在目标目录；不能把此类失败当成旧版本必然仍在。进程硬终止留下的事务不会自动删除或覆盖，再次安装/移除被拒绝。部署者应在确保没有运行中的该模块安装后检查 `.transactions/<module_id>/backup` 与目标状态，恢复或清理遗留事务；插件不会替部署者猜测确认。

既有目录必须包含合法的插件状态才允许更新或移除，不接管无状态目录、不将损坏状态当空状态。显式移除不存在模块返回 `removed=false`；不会触碰相邻模块或非模块文件。

| `main.rs` / `lib.rs` / `input.rs` | 协议入口、输入边界、公开清理结论 |
| `config.rs` / `manifest.rs` | 部署配置、清单和纯版本规则 |

| `unpack.rs` | ZIP 元数据预检和受控解压 |
| `storage.rs` / `transaction.rs` | 模块锁、版本状态和替换/回滚 |
| `operations.rs` | catalog/plan/install/remove 业务编排 |
| `local_import.rs` | 严格本地导入输入、受控产物关联及逐块复制校验；复用安装规则与事务收尾 |
| `feature.rs` | 单快照匹配、状态聚合和顺序准备；复用安装事务 |

测试源包括真实本地 HTTP/ZIP 安装、摘要错误、无效/越界 ZIP、扩容限额、入口缺失、HTTP 失败、版本计划、离线 catalog、在途移除拒绝、取消/到期清理、真实目录重命名失败回滚、遗留 backup 保留、runtime 包装目录，以及真实插件协议 4 进程与请求路径覆盖拒绝。

本地导入回归另覆盖来源不可用时的离线安装、跨调用持久状态、同版本重复/修复、拒绝降级、真实字节与声明摘要/长度不一致、坏清单、坏 ZIP、穿越/入口缺失、输入副本授权、模块锁和取消；失败时原版本与状态保持完整。真实协议 4 进程用不存在的部署清单和不可用下载地址验证导入与重复导入。

编译和运行命令由工作区统一门禁执行：`cargo test -p deviceforge-tool-supply-plugin`。测试文件的存在不代表已经运行；外部发布源、真实工具使用和生产部署仍需要各自的动态证据。

## 共享工具仓库模式

工具配置新增 `repository_mode`：新托管配置默认 `managed`，通过公开 SDK 的仓库描述使用宿主用户根的 `tools`。不填写该字段的旧配置继续使用 `custom` 与原 `install_root`，不会自动搬迁或覆盖旧目录；独立运行请参照配置示例显式使用 `custom`。托管模式缺少宿主描述时明确失败，不回退到其他路径。

配置版本 2 允许 `managed` 模式省略 `install_root` 或将其设为 `null`，真实路径始终来自 SDK 的仓库描述。`custom` 模式（含未声明模式的旧配置）必须提供有效绝对目录，拒绝空值、相对路径、父目录段及控制字符；已有合法绝对路径继续生效。

托管内容完整保留归档根，按工具标识、版本、平台和原始归档摘要不可变发布；`.repository/clients/<插件标识>` 只保存本插件的选择、缓存与事务状态，不把状态写入共享内容。导入仍核对实际上传归档摘要；在线安装可以复用已经完整校验的同一资源。配置里的 `install_root` 在托管模式不参与路径选择。

移除会在公共仓库写锁下复核所有引用，活动发布、上一版、其他插件选择或任务/会话读租约都会阻止删除。写锁被调用占用时明确返回忙；不等待或绕过租约。失败事务保守保留引用及恢复线索，不用业务取消信号阻断回滚。切换仓库模式不会撤销旧选择引用，旧模式的选择需在原模式下显式移除；无法确定的引用只会保留内容。
