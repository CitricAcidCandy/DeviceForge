# 设备产物动作与性能采样的资源收口

`session.rs`分发 APK、APKS 安装和 PNG 截图。`input.rs`按唯一嵌套pointer/ID校验产物并生成固定私有副本，内部选择 `input.apk` 或 `input.apks`；`output.rs`执行现有最低PNG资格，复制到宿主授权的固定目标后只声明文件名；宿主生成最终产物实体。

`install_apks.rs` 单独编排部署工具资格、私有副本、公共 `ArchiveProfile::Structure` 和 Default APKS 校验、固定 Java argv 与旧成功规则，输出精确三字段结果。公共校验在受限 worker 内运行，沿原截止点和只读取消回调，不增加文件工作槽、设备锁或阶段预算；它不声明新的输出产物。

`performance.rs`在创建私有目录前分流单次采样，使用既有 `capture_scoped` 顺序执行pidof、进程stat、meminfo、相同stat与系统stat；第四笔核对start_ticks后才允许第五笔。输出与解析复用下述单槽worker，内存和系统逐行检查原截止点及取消；采完后取时间戳并编码既有原始样本，FrameWindow缺省，不计算CPU差分或启动常驻进程。性能请求必须空inputs、null输出授权，输入校验先于配置；该分支不创建目录、私有文件或新产物。

`worker.rs`每调用最多一个活动阻塞闭包，闭包持工作许可与调用租约至实际返回，分块或逐行使用原截止点和只读取消回调。产物分支另保留所属目录租约；`files.rs`只提供普通路径/句柄资格与独占文件创建。`directory.rs`记录真实私有目录与删除结果；目录租约没有自动删除Drop，失败目录保留便于检查。

取消、到期和Future丢弃不表示文件工作已终止。正常返回仍须真实排空、租约归还和目录删除成功才声明清理完成；未确认为粘性失败。仅删除本次自有目录及失败时明确独占创建的固定输出文件，不删除授权输出根或配置scratch_root。

资源生命周期回归测试直接覆盖阻塞worker、单槽、Future丢弃、panic、固定清理点到期、输出撤除和目录保留；主代理统一执行编译与测试后再记录通过证据。

APKS 的直接进程确认只覆盖本次 Java。bundletool 派生 ADB、共享 server 和部分设备安装的回滚不属于当前目录租约或清理保证；cwd 和三项临时环境的假工具观测也不证明真实 JVM 的所有内部临时文件行为。
