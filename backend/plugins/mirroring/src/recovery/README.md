# 投屏资源台账与恢复

## 职责

本模块属于独立投屏插件，不依赖宿主内部实现。协议4的 `runtime.recover` 输出公开 SDK 的有限恢复报告；新直播准入仅核对本次设备标识及本地登记目录，不再执行旧资源审计。设备副作用只使用部署者配置的 ADB。

2026-10-23 本批落实已批准的资源隔离裁定：旧台账、旧控制状态及外来 scrcpy 不作为独立新会话的全局拒绝条件。旧债务仍持久保留，恢复失败仍返回真实诊断，不通过清空状态冒充释放。宿主 application 负责后台自动调度，最多三次，调度点为0/250/1000毫秒；插件不另建后台循环或重放业务调用。

| 文件 | 负责 | 不负责 |
| --- | --- | --- |
| `store.rs`、`atomic.rs` | 有界文件池、永久锁、有限读取、原子落盘 | 设备命令和恢复决策 |
| `admission.rs` | 本次设备标识和登记目录资格 | 扫描旧台账、控制文件或调用 ADB |
| `ledger.rs` | 资源意图、阶段、身份和工具监督租约 | 对资源已经消失作推断 |
| `process.rs` | 本机进程出生身份和旧直接子进程审计 | 按裸 PID 结束进程 |
| `remote.rs` | 可信参数脚本、远端出生身份、精确转发表解析 | 任意路径或命令请求 |
| `runner.rs` | 固定总期限的 ADB 执行、分阶段清理和只读旧版审计 | 更新宿主风险标记 |
| `identity.rs` | 对缺台账旧控制摘要核对在线传输与硬件标识 | 创建连接、推测设备归属、清理远端资源 |
| `sweep.rs` | 全台账逐资源核对、跳过活跃资源、确认后撤销旧记录 | 新会话准入、重放直播或设备输入 |

## 存储与租约

根目录是当前插件 EXE 旁的 `.mirroring-resources`。每个资源记录是 `<32位十六进制token>.json`，最多48份，每份最多32 KiB。记录包含设备、独占远端目录、SCID、端口、固定服务版本、本机 PID 与出生身份、四类阶段及远端 PID/启动时刻/设备启动标识。

`process.lock` 从入口读取首帧前开始持共享租约。普通任务、直播与恢复统一使用共享租约，恢复不再切换为全插件排他租约，不冻结活跃会话或新调用。直接工具监督也保留共享租约和对应资源租约，不能因处理器退出或等待 Future 被丢弃提前释放。

每记录同名 `.lease` 是资源存活租约；恢复逐条尝试取得独占租约，持有者仍活跃时跳过，不能发送该资源的清理命令。旧持有人已退出但租约仍被工具监督持有时，保留忙碌债务。取得租约后重读台账，避免使用正常退出前的旧阶段快照。`<设备摘要>.gate` 只串行化短时台账登记，不跨恢复命令持有；`catalog.lock` 串行化有界目录登记。所有锁文件永久保留，不能删除重建以绕过现有持有者。调用方必须保持部署目录稳定；跨部署复制资源台账不是受支持的恢复方式。

活动台账额度只统计 JSON，不再将历史 `.lease` 算入旧的8192条目限制。只有空的32位小写十六进制 `.lease`、64位摘要 `.gate`、`process.lock` 和 `catalog.lock` 可作为已知锁文件跳过；未知文件、暂存记录、损坏锁、目录和符号链接均明确阻断，不能静默忽略。扫描只保留最多48条活动路径，每128条让出阻塞线程并检查同一个三秒总预算，开始与结束也检查预算；到期不发布部分成功。不删除历史锁，也不通过取消活动记录上限换取放行。

上述严格扫描用于恢复结论，不再作为新记录创建的前置审计。新登记独立检查容量：旧 JSON 与同名 pending 合并计一份债务，未知或损坏条目也占容量但不要求内容审计成功，已知空锁不占容量；达到48份才以明确的资源容量错误拒绝新分配。登记同样使用三秒总预算及分批检查，保留所有原件，不删除异常记录来腾额度。

文件写入经同目录暂存、`sync_all`、原子替换发布。Windows 使用带写入穿透的 `MoveFileExW`，Unix 刷新父目录。台账写入失败时不继续创建下一阶段资源。文件池最多四项执行，等待池许可最多三秒；操作系统文件调用不可强制中断，工作持锁至真正完成。

## 直播和恢复顺序

1. 新 `open` / `open_webrtc` 在资源创建、控制注册之前，仅核对本次设备标识、取消期限及登记目录。不读取旧控制状态，不执行 ADB、设备枚举或 legacy 审计；随后沿用已有独立 token 目录与动态端口创建流程。
2. 创建任何设备资源之前发布台账，随后在目录创建、服务上传、转发、服务启动前后分别持久化阶段。动态端口回执丢失时依靠唯一设备与 SCID 重新查表，不猜测端口。
3. 远端目录放置不可覆盖的 token 标识；启动前记录 PID、进程启动时刻及设备启动标识。就绪后将身份回执写回本机台账。
4. 正常退出先等待本机直接进程，再核对并终止明确属于本记录的远端服务、删除精确目录和转发。阶段确认后更新台账，全部确认才撤记录。
5. `runtime.recover` 全量读取资源记录和旧控制状态，逐资源取得租约，跳过活跃独立资源。`device_id` 只辅助定位缺台账旧状态，绝不缩小全插件覆盖。指定 A 设备仍会核对 B 设备残留。
6. 崩溃记录须取得资源租约，并证明旧本机进程及其直接子进程不再存活。远端发送信号前核对出生时刻、设备启动标识、进程类名、固定版本、SCID、隧道参数和服务文件环境归属。可归属旧 server 先 TERM，最多等待十轮、每轮50毫秒；仍为同一进程时重新检查完整归属后 KILL，再作同样有界的真实退出确认。读取失败不作退出证明，也不形成无限重试。端口复用和不唯一映射明确拒绝。
7. 控制恢复先取得完整状态快照，再做旧资源审计；最终持控制协调锁和相关存活锁，只有当前状态与快照完全相同时才发布新修订。活跃会话跳过，状态变化则保留诊断；旧结果不能清除新会话、参与者或新代次。不能删除锁文件或只重置状态。
8. 已确认释放的旧资源记录独立撤销，不因新会话活跃或另一条控制债务扣留。最后复扫台账，包括恢复期间新登记的记录；只有扫描成功、无旧债务、非空检查全部确认才返回恢复成功，活跃独立资源不计旧债务。旧资源仍未确认时如实返回 busy/blocked，但不改变独立新调用的准入。

恢复按持久化阶段续办：`forward_stage=Released` 后不再查询或删除旧端口，允许外来会话正常复用；尚未确认释放的转发仍须拒绝外来归属。目录释放回执已经证明服务退出及上传文件删除，`directory_stage=Released` 后只补齐可能被中断的阶段写入，不重复远端删除。设备阶段全部释放即可撤销该 token 的记录，剩余控制债务由独立控制文件保存和审计，不据此清除新会话状态。

## 旧版本与录制

后台恢复无台账旧 `blocked` 时，必须能从请求设备标识或现存台账定位设备，严格只读检查旧目录、服务进程、套接字和转发。发现无归属残留时不执行删除，提示无法证明安全恢复。不能定位设备时保留该旧债务，不据此拒绝独立新调用。

旧 DFML 可能从未创建控制状态文件，不能用空台账、空控制目录或宿主重启后的风险布尔证明没有残留。`runtime.recover` 未指定目标且无资源台账时，无论 `_host_cleanup_unconfirmed` 是否为真，均在共享进程租约内执行 `adb devices`，逐个严格只读审计在线设备。设备列表只接受完整标识行、最多8192字节和128个唯一在线标识；离线、未授权、未知状态、损坏或失败的枚举均不能报告恢复成功。宿主注入字段仅接受布尔值；宿主负责覆盖客户端值，本插件不将假值当作不存在旧资源的证明。

若无设备可审且宿主风险为真，保留后台债务并提示连接、选择故障设备；风险为假时仅报告当前无已登记资源或在线设备。后续新 `open` / `open_webrtc` 不再等待这类审计，新资源必须经本次唯一目录、SCID 和动态端口登记。审计发现外部 scrcpy 只保留旧债务诊断，不删除、发送信号或重放输入。设备控制仍沿用原有所有权协调；真实共享输入资源不可确认时保持不可控状态，不将该局部冲突扩大为视频独立资源的全局拒绝。

显式 `device_id` 在没有其他待证明的旧控制摘要时不触发设备枚举；无其他设备登记时只审计指定设备，不因另一台设备在线就向其发送 shell。其他已有资源台账和控制状态仍必须全部核对，不能靠指定 A 设备忽略 B 的已登记风险。

旧版控制文件只保存设备标识的摘要。USB 标识切换为无线地址后，不能把摘要不匹配解释成设备不存在。发现无法定位且确实需要资源证明的旧控制状态时，在同一共享租约与固定截止点内枚举在线传输；先核对直接标识，再用只读 `shell getprop ro.serialno` 读取硬件标识并严格匹配摘要。硬件标识必须是单行、非空、最多200字节的合法设备标识，不接受客户端提交别名。匹配后只通过现有严格只读资源审计确认旧目录、进程、套接字和转发，再固定存活锁、持协调锁并比较状态快照后更新旧状态；硬件标识相同本身不构成资源释放证明。离线、标识不符、属性读取失败或仍有外来投屏均保留旧债务，不创建/断开 ADB 连接，不清理外来资源。

### 假工具接线

- 新增 `RecoveryRunner::devices()`，直接执行全局参数 `["devices"]`，没有 `-s`，不使用空设备哨兵。
- `command(device, args)` 保留原参数 `["-s", device, ...args]`；全局枚举不经过此方法。
- 枚举成功文本为 `List of devices attached\n<serial>\tdevice\n\n`，空列表为 `List of devices attached\n\n`；也接受正常 CRLF。
- 随后的只读参数为 `["-s", serial, "forward", "--list"]` 和 `["-s", serial, "shell", LEGACY_AUDIT]`。`remote::LEGACY_AUDIT` 未变，成功只接受 `DFML_AUDITED\n` 或 CRLF。

普通 `record` 委托外部 scrcpy 管理资源，创建前登记 `externally_managed` 债务，不伪造独占目录、SCID 或服务版本。零退出后仍执行只读资源审计再撤债务；崩溃债务只能通过严格审计，不按版本或进程名杀其他投屏。

## 安全限制与验收边界

- 不执行 `kill-server`、`pkill`、全局转发删除，不向设备重放输入。
- 全部恢复命令共用原调用截止点，且最多30秒；直接进程的退出监督仍由公共工具库负责。超时、直接进程未确认或任何资源身份冲突均保留阻断。
- ADB 转发的查表和删除不是条件原子操作。删除前重复核对归属，已观察到的外来端口绝不删除；外部工具在两命令之间主动改绑的竞争仍不能由 ADB 公共协议完全消除。
- 远端身份检查和发送信号之间也没有内核级进程句柄。重复出生身份检查可拒绝已发生的 PID 复用，但不宣称消除了所有设备内核级竞争。
- 当前完整崩溃后本机直接子进程审计实现面向 Windows。其他平台无法确认时保守阻断，不静默降级成功。
- Android 的 `ps`、`awk`、`/proc` 读取不支持或权限不足时必须保留阻断，不能把不可见当作不存在。
- 单元回归、假 ADB、真实浏览器协商与画面、真机和长时稳定分别验收。编译与空台账报告不证明浏览器投屏已经修好。
