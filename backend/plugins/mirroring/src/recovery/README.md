# 投屏资源台账与恢复

## 职责

本模块属于独立投屏插件，不依赖宿主内部实现。输入是协议4的 `runtime.recover` 请求或新直播的设备标识，输出是公开 SDK 的有限恢复报告。设备副作用只使用部署者配置的 ADB。

| 文件 | 负责 | 不负责 |
| --- | --- | --- |
| `store.rs`、`atomic.rs` | 有界文件池、永久锁、有限读取、原子落盘 | 设备命令和恢复决策 |
| `ledger.rs` | 资源意图、阶段、身份和工具监督租约 | 对资源已经消失作推断 |
| `process.rs` | 本机进程出生身份和旧直接子进程审计 | 按裸 PID 结束进程 |
| `remote.rs` | 可信参数脚本、远端出生身份、精确转发表解析 | 任意路径或命令请求 |
| `runner.rs` | 固定总期限的 ADB 执行、分阶段清理和只读旧版审计 | 更新宿主风险标记 |
| `sweep.rs` | 全台账核对、目标新会话核对、确认后撤销记录 | 重放直播或设备输入 |

## 存储与租约

根目录是当前插件 EXE 旁的 `.mirroring-resources`。每个资源记录是 `<32位十六进制token>.json`，最多48份，每份最多32 KiB。记录包含设备、独占远端目录、SCID、端口、固定服务版本、本机 PID 与出生身份、四类阶段及远端 PID/启动时刻/设备启动标识。

`process.lock` 从入口读取首帧前开始持共享租约。普通任务和直播的直接工具监督也保留共享租约，不能因处理器退出或等待 Future 被丢弃提前释放。特殊恢复取得排他租约，持有至协议处理结束；无法取得时返回忙碌，不发送设备清理命令。

每记录同名 `.lease` 是资源存活租约；`<设备摘要>.gate` 串行化同设备核对和台账创建；`catalog.lock` 串行化有界目录登记。所有锁文件永久保留，不能删除重建以绕过现有持有者。调用方必须保持部署目录稳定；跨部署复制资源台账不是受支持的恢复方式。

活动台账额度只统计 JSON，不再将历史 `.lease` 算入旧的8192条目限制。只有空的32位小写十六进制 `.lease`、64位摘要 `.gate`、`process.lock` 和 `catalog.lock` 可作为已知锁文件跳过；未知文件、暂存记录、损坏锁、目录和符号链接均明确阻断，不能静默忽略。扫描只保留最多48条活动路径，每128条让出阻塞线程并检查同一个三秒总预算，开始与结束也检查预算；到期不发布部分成功。不删除历史锁，也不通过取消活动记录上限换取放行。

文件写入经同目录暂存、`sync_all`、原子替换发布。Windows 使用带写入穿透的 `MoveFileExW`，Unix 刷新父目录。台账写入失败时不继续创建下一阶段资源。文件池最多四项执行，等待池许可最多三秒；操作系统文件调用不可强制中断，工作持锁至真正完成。

## 直播和恢复顺序

1. 新 `open` / `open_webrtc` 在资源创建、控制注册之前，先核对目标设备旧台账及持久控制状态。
2. 创建任何设备资源之前发布台账，随后在目录创建、服务上传、转发、服务启动前后分别持久化阶段。动态端口回执丢失时依靠唯一设备与 SCID 重新查表，不猜测端口。
3. 远端目录放置不可覆盖的 token 标识；启动前记录 PID、进程启动时刻及设备启动标识。就绪后将身份回执写回本机台账。
4. 正常退出先等待本机直接进程，再核对并终止明确属于本记录的远端服务、删除精确目录和转发。阶段确认后更新台账，全部确认才撤记录。
5. `runtime.recover` 全量读取资源记录和旧控制状态。`device_id` 只辅助定位缺台账旧状态，绝不缩小全插件覆盖。指定 A 设备仍会核对 B 设备残留。
6. 崩溃记录须取得资源租约，并证明旧本机进程及其直接子进程不再存活。远端发送信号前核对出生时刻、设备启动标识、进程类名、固定版本、SCID、隧道参数和服务文件环境归属。端口复用和不唯一映射明确拒绝。
7. 手机资源核对完成后才持有控制协调锁，固定所有相关存活锁，原子发布解除 `blocked` 的新修订。核对前后都检查活跃持有人，不能删除锁文件或只重置状态。
8. 最后复扫台账，只有扫描成功、无剩余、非空检查全部确认才返回全插件恢复成功。业务参数错误仍是普通失败；自动核对发现残留、损坏台账或旧阻断则报告清理失败，宿主可据此进入统一恢复入口。

恢复按持久化阶段续办：`forward_stage=Released` 后不再查询或删除旧端口，允许外来会话正常复用；尚未确认释放的转发仍须拒绝外来归属。目录释放回执已经证明服务退出及上传文件删除，`directory_stage=Released` 后只补齐可能被中断的阶段写入，不重复远端删除。即使全部设备阶段已释放，记录仍保留至剩余控制状态审计成功，不跳过控制审计。

## 旧版本与录制

无台账旧 `blocked` 必须能从请求设备标识或现存台账定位设备，严格只读检查旧目录、服务进程、套接字和转发。发现无归属残留时不执行删除，提示无法证明安全恢复。不能定位设备时保留阻断。

旧 DFML 可能从未创建控制状态文件，不能用空台账、空控制目录或宿主重启后的风险布尔证明没有残留。`runtime.recover` 未指定目标且无资源台账时，无论 `_host_cleanup_unconfirmed` 是否为真，均在现有排他进程租约内执行 `adb devices`，逐个严格只读审计在线设备。设备列表只接受完整标识行、最多8192字节和128个唯一在线标识；离线、未授权、未知状态、损坏或失败的枚举均阻断。宿主注入字段仅接受布尔值；宿主负责覆盖客户端值，本插件不将假值当作不存在旧资源的证明。

若无设备可审且宿主风险为真，保留阻断并提示连接、选择故障设备；风险为假时仅报告当前无已登记资源或在线设备。后续新 `open` / `open_webrtc` 在没有可信台账或活跃控制持有人时仍须严格审计同一目标，覆盖“先空目录恢复、后连接旧设备”的路径。可信活跃资源租约及本机出生身份成立时不触发这类宽泛旧版审计，避免干扰已有观看端。审计发现外部 scrcpy 只报告冲突，不删除、发送信号或重放输入。

显式 `device_id` 不触发设备枚举；无其他设备登记时只审计指定设备，不因另一台设备在线就向其发送 shell。其他已有资源台账和控制状态仍必须全部核对，不能靠指定 A 设备忽略 B 的已登记风险。

### 假工具接线

- 新增 `RecoveryRunner::devices()`，直接执行全局参数 `["devices"]`，没有 `-s`，不使用空设备哨兵。
- `command(device, args)` 保留原参数 `["-s", device, ...args]`；全局枚举不经过此方法。
- 枚举成功文本为 `List of devices attached\n<serial>\tdevice\n\n`，空列表为 `List of devices attached\n\n`；也接受正常 CRLF。
- 随后的只读参数为 `["-s", serial, "forward", "--list"]` 和 `["-s", serial, "shell", LEGACY_AUDIT]`。`remote::LEGACY_AUDIT` 未变，成功只接受 `DFML_AUDITED\n` 或 CRLF。

普通 `record` 委托外部 scrcpy 管理资源，创建前登记 `externally_managed` 债务，不伪造独占目录、SCID 或服务版本。零退出后仍执行只读资源审计再撤债务；崩溃债务只能通过严格审计，不按版本或进程名杀其他投屏。

## 安全限制与验收边界

- 不执行 `kill-server`、`pkill`、全局转发删除，不向设备重放输入。
- 全部恢复命令共用原调用截止点，且最多30秒；直接进程的退出监督仍由公共工具库负责。超时、直接进程未确认或任何资源身份冲突均保留阻断。
- ADB 转发的查表和删除不是条件原子操作。删除前重复核对归属，已观察到的外来端口绝不删除；外部工具在两命令之间主动改绑的竞争仍不能由 ADB 公共协议完全消除。
- 远端身份检查和发送信号之间也没有内核级进程句柄。重复出生身份检查可拒绝已发生的 PID 复用，但不宣称消除了所有设备内核级竞争。
- 当前完整崩溃后本机直接子进程审计实现面向 Windows。其他平台无法确认时保守阻断，不静默降级成功。
- Android 的 `ps`、`awk`、`/proc` 读取不支持或权限不足时必须保留阻断，不能把不可见当作不存在。
- 单元回归、假 ADB、真实浏览器协商与画面、真机和长时稳定分别验收。编译与空台账报告不证明浏览器投屏已经修好。

## 本轮确定性回归

新增测试按 `tests/enumeration.rs`、`tests/stages.rs`、`tests/catalog.rs` 分组：覆盖宿主风险丢失、无 ownership 的旧 DFML、空设备列表、离线及授权失败、首次打开资格、活跃会话不干扰、目标设备隔离、已释放端口复用、剩余控制审计、8193个历史锁、48条活动额度、未知或损坏文件及注入扫描预算到期。测试只使用临时文件锁和注入命令，不连接真实设备。

本轮按主代理要求暂不执行 Cargo；新增用例和既有调整后的用例仍待集中编译与运行，不计为已通过。仅执行定向 rustfmt 和文件级静态检查；完整门禁、假工具集成和部署由主代理统一完成。根 `todo.md` 由主代理合并更新，本 worker 不越过独占写集。
