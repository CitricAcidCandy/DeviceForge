# 投屏设备控制权协调

本模块协调同一部署下多个独立投屏插件进程。输入是设备标识、客户端标识、服务端确认的控制授权与主控身份；输出是当前客户端的控制状态。文件锁、状态文件和存活探测属于本模块，设备输入、WebRTC、客户端地址判定及真实设备清理属于调用者。

## 存储和边界

- 根目录固定为当前插件可执行文件目录中的 `.mirroring-control`，不读取逐会话变化的临时目录环境变量。
- 设备标识与客户端标识采用 SHA-256 文件名，不直接拼入路径。每设备一份协调锁和有限 JSON 状态，每客户端一份操作系统存活锁。
- 存活锁由文件句柄持有至 `Ownership` 及相关 `Guard` 全部销毁。禁止按 PID 或墙上时钟推断存活、删除锁文件或绕过操作系统锁抢占。
- 每设备最多 64 名参与者、32 个控制申请，JSON 最多 64 KiB，修订序号不超过 JavaScript 安全整数上限。锁文件内容为空，文件名不重复利用为其他客户端身份。
- `revision` 表示全部控制状态变化，`control_revision` 仅随持有人、移交状态或故障状态变化递增。普通申请和拒绝不会撤销持有人在途输入；设备输入与剪贴板回包须使用 `control_revision` 作为归属代次。
- 文件操作和 `try_lock` 进入每进程最多 4 个工作的阻塞池；池等待及协调锁等待为 3 秒，文件工作等待为 3.1 秒。操作系统文件调用无法强行中断，超时后的阻塞工作保留工作许可及锁到实际完成；调用者必须将超时视为控制失败并终止本会话。
- 状态写入在协调锁保护下经有限临时文件、`sync_all` 和重命名发布。异常 JSON、非法归属和超限状态均失败关闭。

## 调用约定

1. `Ownership::new(device_id, client_id).await` 创建本会话的存活锁。客户端标识应为服务端认可的单会话标识。
2. `register(allowed, master).await` 记录由服务端确定的权限。首个被允许控制的参与者取得空闲控制权；只读主控仍然只能观看。
3. `lock().await` 读取并核对参与者存活，返回独占的 `Guard`。调用者在同一把锁内检查 `is_owner()`、发送受控设备输入、提交移交或丢弃回包，不能先解锁再发送输入。
4. `command(Command)` 执行申请、答复、主控抢回或主动释放；修改后显式 `save().await`。`view()` 产生 `version:1`、`type:control_state`、`epoch:1` 的客户端视图。
5. `needs_handoff()` 为真时，旧持有人停止接受输入并释放全部已按键及触摸。只有释放成功后才能 `finish_handoff()` 并保存；该步骤完成前没有任何客户端拥有可写控制权。
6. 外部设备资源清理完成后调用 `unregister(clean).await`。`clean=true` 可完成已经同意的移交或释放，`clean=false` 使当前持有人保留故障阻断。

普通参与者使用 `Command::Request`，由当前持有人通过 `Respond { client_id, accept }` 决定。主控使用 `Reclaim` 可替换尚未完成的移交目标，但仍须等待旧持有人完成输入释放。申请者退出会删除申请，已批准目标退出会使本次移交退化为释放。

## 失联与恢复

失去持有人的操作系统存活锁只证明插件进程不再持锁，不能证明手机上的 scrcpy 已停止。核对失联后保留原 `owner_id` 并标记 `blocked=true`，普通申请不能取得控制权。

主控在失联状态提交 `Reclaim` 只记录恢复申请，不直接授予控制权。仅恢复申请者的 `needs_recovery()` 返回真，运行时据此提示旧设备控制资源未确认释放。当前版本没有解除 `blocked` 的生产入口，不支持插件崩溃后的设备资源恢复；设备控制保持不可用，须由部署者核对并清理后恢复控制。单纯重连设备或重新打开投屏不会自动解除持久化阻断。正常主动释放和在线接管不进入这一故障恢复流程。

`finish_recovery()` 仅在测试编译中存在，用于验证状态机要求主控身份、旧持有人失联和明确恢复确认；它不代表生产版本已经实现外部设备清理，也不能作为运行时恢复能力的验收证据。后续接入生产恢复时，必须先在同一 `Guard` 内取得旧设备控制端清理成功的真实证据，再恢复这一确认入口。

协调器不持有设备端进程句柄，不提供虚假的设备清理实现，也不把聚焦、最近点击或最后操作时间当成复制因果证明。单持有人规则只建立远程控制归属；手机本地触控或后台应用自行改写剪贴板没有浏览器客户端因果标识。

## 验证

模块测试覆盖普通申请与同意/拒绝、移交前输入禁用、主控强制目标替换、释放、失联阻断、仅测试的恢复确认门槛、只读主控拒绝、申请/参与者/序号上限、真实操作系统文件锁、状态持久化、异常与超限 JSON。测试不代替跨进程服务联调、真实手机复制及接管资源清理验收。
