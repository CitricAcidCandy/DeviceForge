# 设备独占资源清理

`cleanup.rs` 只负责 mirroring 插件本次登记的流式 ADB、远端目录/服务器与独占转发，不改变公开协议和宿主清理失败保护。输入为设备资源登记与命令执行器，输出仍为清理是否完整确认的布尔值；副作用限于取消/等待本次直接进程及带设备参数的 ADB 命令。

本模块仅预防新调用中的可确认瞬态失败，不读取、重置或绕过持久协调状态；旧 `blocked`、残留所有者与未确认状态不会因此自动恢复。

先取消并等待本地流式 ADB，然后只建立一次两秒远端绝对截止点。远端最多执行两轮；每条命令和两轮共用该截止点，不续期。到期后不再启动新命令。工具库仍有自身直接进程回收预算，所以两秒不等于整个清理调用的严格墙钟上限，也没有增加宿主窗口。

只重试尚未确认阶段的暂时性工具错误：进程启动/管道错误、ADB 通用退出码 1，以及清理脚本退出码 73–76。取消、超时、未知退出码不触发重试；直接进程 `CleanupFailed` 保留原始原因，即使原因是 `Timeout` 也不恢复。已有 `unresolved`、非法/超限输出、PID 拒绝（71/72/77）、归属冲突与删除成功后仍未消失均保持粘性。硬失败只封锁对应远端阶段，其他已登记资源仍可安全收口，最终结果仍失败。

目录/进程脚本只有收到精确 `DFML_CLEAN` 标记才解除登记，后轮不重复。启动过服务器却缺少 PID 仍拒绝；目录缺失不能证明远端进程已消失。脚本重放若已丢失 PID 也不能按成功处理。信号只发给命令行身份匹配的 PID，不进行全局杀进程或清理其他会话。

每次删除转发前都重新查表，精确核对设备、scid 与登记端口。创建响应丢失时可从完整合法清单恢复唯一端口，一经确认便固定该端口。`remove` 的暂时性错误允许在同一截止点内重新查表，且继续核对原端口；仅本次独占映射确实消失才能解除登记。若仍存在，下轮先查表再决定是否删除；端口被其他设备或 scid 复用立即失败，禁止继续删除。ADB `list` 与 `remove` 不是原子操作，检查和删除之间仍可能发生外部并发修改，本模块不承诺消除该竞争窗口。

`tests.rs` 注入假命令执行器和单调时钟，覆盖两轮共享截止点、暂时/持续失败、成功阶段不重复、到期不启动、移除后的复核与重试前查表，以及粘性拒绝。测试不启动 ADB，不代表真机、宿主或工具进程回收验收。
