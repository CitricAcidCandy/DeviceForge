# 原生伪终端

公开 `spawn_pty_with_lease` 接受固定 `ToolCommand`、原 `StreamOptions`、`PtySize`、取消信号与资源租约。Windows使用ConPTY，进程出生暂停并先归属本次Job再恢复执行；不经过shell拼接程序参数。其他平台明确拒绝，不能以普通管道静默替代。

`PtyInput`按同一顺序提交原字节、尺寸与EOF，容量、单块和累计字节沿用流式限额。输出为stdout原字节，PTY合并原生stdout/stderr；ANSI和终端查询由网页终端模拟器解释。输入EOF终止该PTY会话，键盘Ctrl+D是普通输入字节。尺寸范围列20至500、行5至200。

Windows使用Tokio重叠命名管道，避免同步读写堵住调度线程；启动和ClosePseudoConsole置于有界启动池/阻塞工作中。关闭PTY同时持续排空输出，正常终态须确认直接进程、Job零活动进程、输出EOF以及PTY关闭工作完成。取消、超时、消费者关闭或Drop进入本调用的树清理；清理两秒未确认返回CleanupFailed并保留租约，不宣称完整释放。不会全局结束同名工具。

Restricted模式与宿主插件、普通工具启动共同调用公共`restricted_environment()`，仅继承程序查找、系统、临时目录、用户目录、应用数据及PowerShell模块定位所需白名单环境，再显式设置TERM和COLORTERM；不继承宿主令牌。上游宿主须使用相同规则保留PATHEXT、COMSPEC和应用数据路径，下游不能恢复已经被上游剥离的环境。终端字节不写诊断日志。用户输入仍可运行可信shell命令，该能力不是安全沙箱。

启动监督器独立接收原生启动结果，外层Future取消或丢弃会触发相同取消信号，不能使已分配PTY脱离归属。启动期间取消或到期时，调用方在cleanup_timeout内继续等待监督器交接；若已取得PtyProcess，则取消并等待完整清理，确认之后才返回原取消或期限原因。等待预算耗尽返回CleanupFailed，已取得的进程所有者或尚未交接的监督器继续后台回收，不能提前用普通Cancelled表示已释放。直接丢弃Future仍由取消守卫及独立监督器负责回收。

启动失败仍确认PTY关闭和管道排空；归属Job前失败的暂停根进程由精确句柄终止。主收口预算沿用cleanup_timeout，超时后回收器最多再工作两秒。运行时关闭或回收仍无法确认时，沿用公共ownership模块的资源租约粘性合同，将租约保留至宿主退出，不能报Complete；这只用于不确定失败分支，正常取消和退出须释放租约。PTY回归通过单线程确定调度及真实PID覆盖监督器未运行、真实树已运行但未交接时的取消和绝对期限，均在启动调用返回的当下检查进程已退出、租约回到1。
