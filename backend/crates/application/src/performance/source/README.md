# 性能来源访问与内部采样

`../source.rs` 用一次绑定的弱引用访问宿主，按显式默认插件标识查询当前注册代际。来源声明、操作与 owner 同步撤销；启动和提交资格只在短注册锁内登记 tracker 令牌。缺省或尚未加载来源允许宿主启动，实时调用返回来源不可用，历史不依赖当前来源。

排空期间来源返回 `conflict`，已知清理风险优先返回 `cleanup_failed`，不将两者伪装成来源不存在。采样与恢复使用严格资格；暂停和停止的控制资格允许收口已有清理风险，仍拒绝撤销代际、取消和到期，不跨 I/O 持有注册锁。

`sampling.rs` 复用设备目录准入、原提供者读屏障、执行上下文和共同取消清理内核，不提交嵌套 Job。原截止点贯穿等待、执行与解码；物理屏障在执行清理确认或风险登记后释放。结果按执行器声明的格式解包，校验领域计数、FPS 声明及观测时间，不导入插件 SDK。

`tests.rs` 覆盖无源与晚加载、弱引用与重复绑定、owner 排空资格、旧代拒绝、零调用预检查和原期限传播。设备型会话、存储序列与真实插件服务仍由所属集成回归验证，不能以这些局部测试认定整个迁移完成。
