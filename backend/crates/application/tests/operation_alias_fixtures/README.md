# 操作绑定独立集成夹具

入口为 `tests/operation_aliases.rs`，本模块包含 17 项测试。主代理冻结生产接口后，在后端目录统一运行 `cargo test -p apk-application --test operation_aliases`；本批编写阶段不执行 Cargo、服务器或真实进程。`node --check crates/application/tests/operation_alias_fixtures/provider.cjs` 仅检查夹具语法，不表示 Rust 已编译或真实行为已验收。

## 文件职责

- `config.rs`：从 JSON 构造公开部署 Config；旧模式、目标封套和管理员 Node 入口相互分开。
- `provider.cjs`：自包含协议 1/2/3 Node 进程；记录本次请求、协作取消和直接进程退出，以释放文件控制实际完成。
- `support.rs`：真实 ProcessPlugin、SQLite、PluginService/DeviceService 装配、独立临时证据及直接 PID 只读观察。
- `mapping.rs`：单份 Job、旧 operation/input/id 与事件保留、真实目标封套、显式包装和对象投影。
- `locks.rs`：旧/新同设备写串行、不同设备写对照、同设备读并行、提供者写同时阻止旧设备读与新设备写。
- `lifecycle.rs`：别名与原贡献的原子修订/撤销、合作清理、重载代际和历史保留，以及未确认清理拒绝新任务与排队任务。
- `registration.rs`：显式目标缺失不回退、不阻断无关插件；精确版本/实际贡献缺失及普通操作绕过能力或发现均加载失败且无半份贡献；协议 1 真实伪包装不能注册产物投影。
- `budget_port.rs`、`budgets.rs`：纯 Executor 记录传下来的原绝对截止点；真实 Node 的跨六十一秒门闩独立验证，不能把端口记录写成传输证据。

## 时钟与证据

纯任务验证 API 1/2 省略时三十秒、API 2 显式一百二十秒跨六十秒、工作槽与提供者屏障扣除原预算，以及排队过期后目标零调用。端口只使用 identity 结果，不伪称拥有宿主已发布产物格式。所有截止点使用 `tokio::time::Instant::from_std` 比较，业务时钟只由测试显式推进。

Tokio 1.53.2 的 `Sleep` 使用毫秒粒度，注册截止点时向上取整；夹具初始化后手动暂停可能保留相对于定时器起点的亚毫秒余数。四项纯预算测试先断言已精确到达原数学截止点，再仅推进一毫秒定时器刻度以观察终态，并断言观察时钟值。传入 `ExecutionContext` 的绝对截止点、排队/屏障扣时和过期目标零调用断言保持不变；这一观察唤醒不重计时、不扩大生产预算或墙钟观察上限，也不改变真实 Node 跨六十一秒用例。

真实协议 2/3 别名进程先写 ready，再推进宿主时钟六十一秒，最后通过本次释放文件让 Node 返回和自然退出。等待真实 Node/SQLite I/O 时持续 `yield_now`，并断言暂停时钟未自行前进；恢复时钟后检查实际退出。观察失败的独立墙钟上限不参与生产预算或清理宽限，未修改三十秒/一百二十秒声明、两秒合作清理和十秒卸载期限。

协议 3 确认取消控制、cleaned、response_written、stdin_eof、零退出与本次 PID 消失分别成立；失败清理可使直接进程消失，但仍必须保留 cleanup_failed、draining 和拒绝重载，不能以进程退出宣称外部资源已释放。协议 1/2 只要求响应与零退出，不把初始 stdin EOF 当作合作取消。所有标记和释放文件仅位于本次临时目录；失败或仍有本次直接 PID 时保留证据，绝不发送终止信号或清理其他目录。

这些测试不覆盖 HTTP/MCP/浏览器，也不重复主代理的旧注册快照和同轮取消成功回归。真实 API 验收由主代理独立脚本负责；发现别名本批明确拒绝，不存在旧发现成功用例。结果 value/object 由真实协议 2/3 空产物包装验证；产物发布与文件名选择的正向真实覆盖仍由已有产物测试和后续独立用例承担，不将协议 1 伪包装拒绝扩大为完整产物验收。
