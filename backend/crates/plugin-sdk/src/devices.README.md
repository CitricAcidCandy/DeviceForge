# 设备提供者公开契约

Manifest.devices 是可选贡献，旧清单不需要新增字段。api_version 当前为 1；发现操作与能力操作均引用同一插件的相对贡献名，宿主负责命名空间映射、校验和能力路由。

发现输入为空对象，输出 PluginDevice 数组；设备 ID 属于提供者本地命名空间，宿主再添加提供者和加载代际。平台字符串仅供展示，不能用于选择平台实现。能力区分 provider/device 范围与 read/write；标准动作输入是 device_id 和 input 对象。

本契约复用现有每任务独立进程与协议 1/2/3，不表示常驻连接、设备监测或流媒体已经实现。数量、声明引用、发现结果、取消与热装卸由宿主验证；完整实施边界见后端 docs/设备提供者第一阶段实施.md。

发现操作接收空对象；能力操作使用标准封套 `{device_id:null|string,input:object}`。业务 input 可以包含必填字段及其他 JSON Schema 约束，设备 ID 可限定 pattern/enum；注册不要求空业务参数或固定假设备 ID 合法，真正提交时验证实际输入。能力范围和读写属性由清单决定，业务输入不能覆盖。

协议 2/3 的现有产物输入声明只选择顶层字段，尚不能选择设备封套内的 `input.artifact_id`。需要产物输入的设备能力在平台迁出前另行设计加法契约，不通过私有宿主源码或服务器任意路径绕过；输出产物沿用原有声明和有界发布。此限制不影响无产物输入的离散能力和发现。
