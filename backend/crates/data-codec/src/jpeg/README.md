# JPEG 增量结构校验

`jpeg.rs` 保存固定大小状态，逐字节推进 SOI、段长度、扫描区转义、重启标记和 EOI；`segments.rs` 只处理 SOF/SOS 字段规则，不操作文件、线程、HTTP 或平台工具。

公开入口为 `Validator::new()`、`push(&[u8])` 和 `finish(self)`。返回尺寸 `Info`，错误区分资源超限、无效结构与不支持编码；失败后的验证器不能恢复。输入必须精确结束于 EOI，拒绝截断和尾随数据。

支持 8 位 SOF0 基线与 SOF2 渐进结构、1 至 4 个组件。检查非零尺寸、组件标识、采样因子、量化表编号、SOS 组件选择、谱范围和近似字段、初始扫描覆盖、DRI 与循环重启顺序。256 字节固定表记录各组件频段的前次近似，拒绝初次扫描重叠、未初始化细化和不连续细化；重启前后必须存在本间隔的扫描字节。这些规则不解析熵编码中的 MCU 或像素。

输入最多 64 MiB，SOI 之后最多 65,536 个标记，包含 EOI 与重启标记；填充字节和 FF00 转义不计为标记。段负载只保存前 18 字节，APP、COM、DQT、DHT 其余内容按声明长度跳过，不解析量化表、霍夫曼表或熵编码。因此结构资格通过不证明可完整解码、像素正确、视觉质量或真实设备截图成功。

`cargo test -p deviceforge-data-codec --test jpeg` 覆盖分块、截断、尾随、字段错误、扫描覆盖、渐进编码、重启顺序、粘性失败及精确字节/标记限额。测试中的最小结构帧只证明上述资格，不是像素解码样本。
