# 设备绝对期限集成夹具

入口为 `../device_deadlines.rs`，通过公开 `Executor::execute_with_context` 调用真实 `ProcessPlugin`，不装配服务器或应用工作池。依赖 PATH 中可用的 Node；缺失时明确失败，不跳过。夹具只模拟 `synthetic_demo` 离散设备，不连接真机或派生子进程。

## 文件职责

- `declarations.rs`：公开 SDK 的可选整数解析、API 1/2 兼容、默认 30000 毫秒与 1–120000 毫秒边界。
- `transport.rs`：协议 2/3 真实运行的预过期、预取消、运行期限、取消、Future 丢弃和拒绝合作。
- `stages.rs`：真实副本流与发布前门闩，证明准备、传输、发布共用调用方绝对截止点。
- `long_budget.rs`：暂停 Tokio 时钟，在真实协议 2 进程就绪后推进 61 秒，再释放文件门闩得到成功响应。
- `success.rs`：成功调用对照、产物哈希与下载原字节。
- `store.rs`：包装真实 `FileArtifacts`；门闩只改变首块副本流和发布前等待，不改变生产存储。
- `support.rs`：声明、独占临时目录、阶段观察和证据保留；`liveness.rs` 只探测本次直接 PID。
- `provider.cjs`：独立真实 Node 进程，记录启动、就绪、取消、清理、响应写完、stdin EOF、自然退出。

## 期限和证据

共 19 项 Rust 测试，多数运行测试在一个测试内分别覆盖协议 2/3。短期业务预算采用 3、4、6 秒；成功/主动取消/丢弃测试使用 15 秒期限，先收到真实就绪标记再操作。副本与传输/发布合并测试先通过门闩消耗准备预算，距离原截止点约 2 秒时释放；后续阶段不能重新获得完整预算。测试外层在原截止点后最多观察 3 秒，只限制失败收敛，不修改生产期限或清理宽限。

跨 61 秒测试使用开发依赖 Tokio `test-util`。测试设置 120 秒上下文，通过 `tokio::time::Instant` 构造并转为领域 `std::time::Instant`；暂停后不以真实墙钟计算业务期限。真实文件检查配合持续轮询调用和 `yield_now`，防止等待 I/O 时暂停时钟自动推进。推进 61 秒后确认调用仍挂起、PID 仍存在且尚无响应，再写释放文件，得到匹配响应、输出产物与零退出。真实墙钟只限制夹具就绪/完成的观察循环。

协议 3 中断要求匹配取消原因、`cleaned`、响应、stdin EOF、零退出同时成立；单独 `cleaned` 标记不表示实际 PID 已退出。协议 2 只证明直接进程终止和本次副本清理，不声明外部资源或进程树清理。拒绝合作精确要求 `cleanup_failed`，即使直接进程已终止也保留未确认资源。源产物须保留，发布阻塞/取消不得提交新产物。

每次运行使用独占临时目录。正常成功只清理本次目录；断言失败或记录的 PID 仍存在时保留目录并输出位置，不强杀进程。夹具自身 30 秒真实墙钟保险用于异常遗留，不能算作宿主期限或清理通过证据。超时前尚未启动进程的副本测试只能从存储调用与未启动标记确认行为，未通过公共接口定位宿主内部临时目录，不宣称完成全局临时目录审计。

## 验证边界

主代理统一执行：`cargo test -p apk-infrastructure --test device_deadlines`，并统一负责格式、Clippy 与全工程门禁。本测试源码交付时仅静态检查，实际编译及运行结果以主代理记录为准。

应用工作池、实际排队与设备锁等待、HTTP/MCP、在线包安装、热装卸和常驻设备由其它验收负责。本夹具覆盖真实 Node 直接进程及真实文件储存，不能证明平台真机、进程树、外部资源持久化或所有主机环境下的尾延迟。
