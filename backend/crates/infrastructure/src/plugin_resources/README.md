# 工具租约恢复债务

本模块只负责宿主工具仓库读锁、直接进程退出凭据与调用债务，不核对设备资源，不解释插件恢复报告，不清除清理风险标记。

## 身份与接线

- `acquire(path, cancel, deadline, &unresolved)` 将一次调用登记到同一 `Arc<AtomicBool>` 对象身份下。标记的布尔值不是身份；新建相同布尔值不能解锁旧组。
- `recovery_ready(&Arc<AtomicBool>) -> bool` 只在该组没有活动调用，且全部保留调用已确认真实直接进程退出时返回真；空组返回真。
- `confirm_recovery(&Arc<AtomicBool>) -> apk_domain::Result<()>` 在同一个台账临界区再次检查退出及活动状态，成功后只取出该组保留读锁。失败保留全部债务，不操作其他组。
- 主调用者必须先冻结所有 owner 准入、排空业务，取得覆盖全量外部资源的报告、匹配协议响应、清理 Complete 与真实零退出，再调用 confirm。提交前后还须核对 owner、代际、恢复编号及风险修订；本模块不代替这些检查。
- 主调用者只在 confirm 成功后清理 `unresolved`。单纯改布尔值或只看到业务 tracker 为空不会释放工具锁。

## 退出凭据

合作进程的 `Owner::wait` 只在系统 wait 成功时记录退出；已知退出在返回前同步释放 Owner 与清理守卫，恢复调用本身不会遗留异步活跃登记。未完成等待才由 Drop 移交后台，后台 reap 成功继续更新同一调用。等待失败、丢失运行时或后台被丢弃都不伪造退出。

会话监督在真实退出结论已知时记录凭据，另把专用 `ProcessLease` 交给公共工具进程所有者。公共库仅在未启动或确认真实 wait/reap 后正常释放该对象；回收失败时保守保留。因此外层会话监督丢失后，晚到的后台成功仍能补上凭据。这个对象不能交给任意普通业务 Future 当作退出探针。

`ToolLease::retain` 不再永久遗忘读锁。最后一个调用持有者结束后，锁转入台账，只有显式全量确认才释放。直接进程已退出不代表外部资源已释放；没有声明恢复能力的旧插件继续保留原保守语义。

## 有界与可见性

每个 owner 最多 64 个调用登记，单宿主最多 256 组、4096 个登记；达到上限时启动前明确返回冲突，不驱逐旧风险或释放旧锁。每个调用只保留一个仓库读锁，不复制输出和输入。保留、未知退出与额度耗尽均产生结构化警告，包含活动数量、待确认退出数量、保留锁数量及无存活 owner 的组数，不记录原始插件输出或敏感配置。

台账只持有 owner 的 Weak、调用元数据及必要读锁，不持有 ToolLease/owner 的强引用；没有 Arc 环。正常调用结束就删除登记，恢复成功就删除组。无法确认的孤立债务不因 owner 消失或时间流逝自动解锁，最多占用上述固定额度，并保留至宿主结束；这是有意的失败关闭，不是无限增长的垃圾缓存。台账互斥发生异常后整体保持未确认，不静默恢复。

## 验证边界

`recovery_tests.rs` 覆盖旧进程仍持有、同组释放、其他活动读锁、身份区别、单清风险标记无效和协议4恢复返回后同步排空。合作所有者另覆盖后台 reap 前后。测试交主代理统一 Cargo 执行；这些用例不代表真机、浏览器投屏或完整恢复产品流程已验收。
