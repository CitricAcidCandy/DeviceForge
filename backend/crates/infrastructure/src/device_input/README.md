# Android 输入适配器

AndroidInput 只运行管理员配置的 ADB。点击、滑动和按键使用固定命令、数值参数；文本按设备端 shell 的单引号规则引用，用户内容不成为设备命令。ADB 会重新拼接 shell 参数，不能只依赖服务器端 argv 的分离。

空格转换为 AOSP input text 的 %s 表示。字面量 %s 在百分号后拆为相邻调用，避免误转空格；输入超过一个分片或要求回车时按顺序执行。整个动作共用 30 秒期限，各进程沿用有界输出、取消和退出清理。字符上限使分片数量有界，极端重复 %s 会产生最多 513 个文本调用，仍受总期限约束。

使用非交互 shell -T。退出成功且没有诊断输出才返回 dispatched；标准输出 / 标准错误出现诊断、非零退出、超时或取消都失败。设备诊断可能包含文本，适配器不将原诊断写入任务错误。

多个分片不是设备事务，失败 / 取消可能已输入部分文本；重试不能保证幂等。不会在取消后继续发送回车，也不会自动重试输入。任务执行成功不证明焦点正确或应用接收了输入。

fixtures 是跨平台独立 Rust 模拟工具，其参数解析仅模拟宿主生成的引用形式；不能代替真实 Android shell / 键盘布局与焦点验收。

验证：cargo test -p apk-infrastructure device_input，覆盖实际进程参数、引号 / 特殊字符 / 字面量 %s、空格、长按、诊断、非零退出、边界、超时与运行中取消。node scripts/runtime-smoke.mjs 覆盖真实服务 HTTP / MCP 任务。
同一设备的 android.input 动作整体串行执行，等待锁也计入 30 秒期限并支持取消；不同设备可以并行。锁表只保留活跃调用的弱引用，设备编号不会无限常驻。此锁只协调该适配器，其他业务工具与外部设备操控仍可能改变焦点。
