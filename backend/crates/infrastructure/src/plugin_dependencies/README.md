# 插件依赖基础设施

本模块只实现领域依赖端口，不管理插件部署事务、启用状态、前端交互或资源执行适配。

- `targets`：解析独立组件及发布归属，核对部署身份与旁置声明。
- `configurations`：将用户主动保存的 `source=managed` 配置绑定作为可选发现候选；忽略默认值，无配置仍继续自动发现。
- `discovery`、`environment`：依次发现显式配置、本机环境、用户目录及共享工具，校验全部入口与真实版本；不下载。
- `download`、`archive`：市场优先、网络及资源不可用才兜底；HTTPS 重定向有界，摘要、解包、入口及版本错误直接失败。
- `preparation`：每次任务独占准备引用，覆盖探测、发布至最终绑定提交；真实进程持有租约或暂存目录至退出确认。
- `workflow`：配套依赖拓扑排序，复用已找到的主工具，仅下载缺项；视图按整个依赖闭包计算可准备性。
- `state`、`files`：跨存储句柄文件锁与修订比较，不可变快照先写、单一索引最后原子切换；失败不覆盖旧索引。
- `local_index`：登记通过检测的外部入口及内容身份，供其他插件复用；不获得外部文件的删除权。
- `failures`：独立记录最近失败诊断，查询呈现失败项但不污染有效绑定；后续检测成功清除对应诊断。

文件工作池最多两个实际阻塞闭包，最多六十四个等待者、单次最多等待两秒。短时并发状态读取有限排队，不立即冲突；等待队列满或超时仍返回可重试错误。工作闭包继续持有实际许可直到退出，不把外层等待取消解释为底层文件操作已完成。

每个组件快照按组件配置绑定及部署根 `.deviceforge-runtime.json` 的 `dependency` 引用选择工具，再纳入 `requires` 闭包；配置 `bindings` 仍按组件过滤。没有配置绑定的脚本运行时及配套工具同样进入 `tools`、可选 `managed_tools` 和 `component_managed_keys`。运行时必须引用公开依赖的必需工具及已声明入口，元数据参与部署身份核对，独立组件与完整发布使用相同解析路径。不伪造配置绑定；运行适配器按稳定工具标识、入口名查找，实际版本与仓库包修订保持分离。

没有依赖的新目标不写绑定索引，不获取仓库写锁。外部工具不移动、不覆盖、不删除；忘记目标只移除自身索引、核对归属的当前快照与引用。旧不可变快照保留为历史文件，不继续作为当前绑定。

新下载先在同一仓库写锁内登记准备引用。后续失败释放本次独占引用，下载内容保留为无引用缓存，可以由显式清理移除；旧绑定继续有效。Future 被直接丢弃或进程中断可能留下保守准备引用，不会自动清除未知活动资源。引用释放失败会记录告警，不能将其解释为清理成功。

测试已接入本模块 `tests`、`state_tests`、`work_queue_tests` 和 `download::tests`；全部使用临时目录，不修改进程环境或 Windows 注册表。版本探测通过当前测试程序的独立测试入口；本机 HTTP 夹具显式关闭代理，不改变全局代理配置。

由主代理串行执行：`cargo test -p apk-infrastructure --lib plugin_dependencies`，再执行 `cargo test -p deviceforge-tool-repository --lib`。本次基础设施角色未运行 Cargo、格式化器或服务；编译、运行及跨层集成结果须以主代理最新输出为准。

主代理集成补充：local_index 将验证过的外部入口、实际版本和内容摘要登记在用户根，安装者卸载后仍可供新插件复用；新消费者重新核对内容身份，不移动或删除外部文件。用户显式失效覆盖不被其他候选伪装为就绪，也不自动下载无效覆盖路径。忽略与默认值相同的保存值，普通用户无需先配置。

完整发布保存依赖市场基址，解析同源相对摘要；离线包内存在的依赖归档先校验并进入既有安装缓存，只有实际缺项时才解包准备。缓存摘要损坏直接失败，不能换源掩盖。新版 SDK 的 runtime 引用随资源快照一起取得租约，普通任务、合作任务和独立会话使用同一快照的解释器，重新检测不会把活动进程切换到新入口。
