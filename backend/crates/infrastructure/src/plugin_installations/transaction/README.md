# 成功代码包证据

`successful.rs` 在原安装存储的两个有界阻塞工作槽和事务锁内读写 `installations/successful/<发布标识>.json`，每个发布最多保留两份已登记的宿主激活成功快照。登记只由完成整套激活的应用用例调用；历史 `previous-*.json` 仍是原事务反向恢复证据，两者不混用。

恢复使用当前修订和目标成功修订双重核验，校验整套组件归属、不可变代码清单及共享工具，再复用原事务日志切换活动文件和安装记录。配置和业务目录不在文件快照范围内。提交前沿传入绝对截止点检查目录、文件和每块摘要读取；提交开始后沿原事务排空提交或反向恢复，不能丢弃阻塞任务后让文件晚到覆盖。

回收器把成功快照与当前版本、普通前版、未决事务一并转为保留引用，避免成功代码和工具先被回收。记录损坏时明确拒绝查询、恢复或回收，不从状态字段推测某版成功。相关直接测试位于 `../tests/successful.rs`。
