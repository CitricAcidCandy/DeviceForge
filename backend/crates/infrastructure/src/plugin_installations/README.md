# 用户目录统一安装适配器

mod 负责装配、可信市场目录、有限工作池和目录排他锁；fetch 负责流式获取与摘要缓存；prepare 负责便携组件映射、工具选择和计划；content 负责组件普通文件清单；paths 负责安装路径边界与原子写入；transaction 负责活动视图、CAS 提交和中断恢复；storage 负责持久查询、启停记录和不可变浏览器资源；repository 只将宿主当前、上版和未决事务转为公共仓库的独立引用；cleanup 负责门禁内的显式引用计算与资源回收。

所有安装写入均位于构造器传入的用户根。配置目录不在安装写集内，程序升级和删除保留旧版本、共享工具及配置。可验证的事务恢复失败时持久化恢复受阻状态并保留启用意图，等待启动重试；日志本身无效或阻断状态无法落盘仍使初始化明确失败。暂存目录租约覆盖已取消但尚未退出的文件工作。显式回收保护当前、上版、准备和运行引用，缓存与历史程序没有自动回收策略。

工具内容统一由公开 `deviceforge-tool-repository` 管理，宿主不再自行绕过仓库锁发布或删除共享目录。提交在同一排他锁下登记新旧引用、发布并复核复用内容，稳定后收敛自身引用；供应插件的独立引用也能保护工具。资源快照附带 SDK 公开仓库描述，配置保存值不写入工具目录。

运行进程在启动前通过 `plugin_resources` 的最多两个阻塞工作者完整校验入口并取得共享租约。普通调用、合作调用和会话监督把租约交给实际进程所有者，等待 Future 丢弃后仍等待回收；合作或会话外部清理没有确认时保守保留仓库读锁至宿主退出。没有工具绑定的供应插件不取得读锁，避免自行写仓库时死锁。旧资源描述缺少仓库字段时继续兼容，不能将其计为共享租约保护。

测试覆盖真实离线 ZIP、摘要拒绝、版本身份不可变、CAS、旧程序与配置保留、字节资源、日志恢复、市场目录边界、阻断状态、共享引用、取消和实际进程租约。定点命令为 `cargo test -p apk-infrastructure --lib plugin_installations` 与 `cargo test -p apk-infrastructure --lib plugin_resources`；完整工作区和服务验收由主流程统一运行。
