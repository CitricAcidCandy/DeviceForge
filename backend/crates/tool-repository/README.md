# 公共共享工具仓库

`deviceforge-tool-repository` 只依赖文件系统、serde、SHA-256、文件锁及原子临时文件。宿主基础设施与独立插件可以共同依赖；不依赖 domain、application、infrastructure、HTTP、Tokio 或任何具体插件。

根路径由调用者显式传入 `Repository::open`，库不读取环境或推断主目录。内容固定在 `root/<id>/<version>/<platform>/<sha256>`，`.repository/` 保存锁、身份账本、引用和暂存。调用方必须先核对下载归档原始摘要；仓库负责展开内容的清单、完整性、普通路径边界及不可变版本。身份账本在删除内容后仍保留。

`Repository::read` 返回跨进程共享租约，覆盖调用或准备阶段。持有者必须把租约交给真正的进程/会话资源所有者，不能只放在可能被丢弃的外层 Future 中。`Repository::write` 非阻塞取得排他锁；任何任务租约存在时返回 Busy。写锁下可以发布、替换显式引用集、查询引用者和删除。全仓库锁采用保守策略，任何工具任务运行时均暂缓写入，避免执行中被替换或删除。

`WriteGuard::set_references(owner, keys)` 原子替换独立所有者的引用快照。宿主负责活动、上版及未决事务的并集；工具供应方负责当前选择；准备阶段可先登记引用，即使工具尚未发布。发布前登记，稳定提交后再收敛；崩溃残留引用只会保留工具。库不读取宿主内部记录，不替调用方猜测引用。任何无效引用记录都会阻止删除。

所有共享目录移除只走 `WriteGuard::remove`。它重新核对全部所有者引用、路径边界与内容；仍被活动版本、上版或任务持有时拒绝。配置、自定义旧工具根与宿主网络凭据不属于本库写集。归档解包和供给清单处理仍由现有安装器/插件承担。

`Repository::client_directory` 为公开调用方创建独立选择状态目录；`ReadLease::verify_entry` 同时核对完整内容、入口普通文件及四层身份。同步遍历与校验须由调用方放入受限阻塞工作者，并透传原截止点和取消检查，公共库不启动异步工作。

验证用例覆盖多类持久引用、多个仓库句柄的任务租约、损坏内容、版本身份保留、损坏引用、取消、外部暂存拒绝、相同摘要的展开内容冲突及带构建信息的版本。定点命令为 `cargo test -p deviceforge-tool-repository --lib`；宿主与工具供应的真实接缝测试分别位于 infrastructure 的安装/资源租约测试与 tool-supply 的 managed_tests。
