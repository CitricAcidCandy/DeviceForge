# 官方发布第二批构建输入

本交接记录主代理协调的共享 Cargo 构建。官方清单为 `official.mjs` 中的18个插件；工作区另有 `spreadsheet`，不应自动混入本批。

第一批`official-batch-01`和第二批`official-batch-02`的原始身份均保留。第二批在源码冻结后使用release、单任务Cargo构建，并完成十八份TGZ、十八完整ZIP与独立流式分发核验。许可证补充使用独立工具归档与库存，没有覆盖第一批工具字节。

## 共享构建命令

在 `backend` 执行，下列18个 crate 的唯一默认二进制入口与 crate 同名：

```powershell
$officialDirectories = @('ai-assistant', 'ai-sdk', 'android-device', 'android-packages', 'artifact-copy', 'automation', 'cooperative-demo', 'dex-analysis', 'echo', 'frida', 'harmony-device', 'marketplace', 'mirroring', 'msgpack', 'performance-demo', 'settings', 'terminal', 'tool-supply')
$releaseArgs = @('build', '--locked', '--release', '--target', 'x86_64-pc-windows-msvc', '--bins', '-j', '1', '-p', 'apk-server')
foreach ($pluginDirectory in $officialDirectories) { $releaseArgs += @('-p', "deviceforge-$pluginDirectory-plugin") }
cargo @releaseArgs
```

`apk-server` 用于提供真实 `validate-plugin`。入口预期为 `backend/target/x86_64-pc-windows-msvc/release/deviceforge-<id>-plugin.exe`，但最终以 Cargo compiler-artifact 的 executable 为准，不拿陈旧目录推断当前构建成功。

现有原生打包器自己会执行同范围 Cargo 构建、校验器和 npm pack，因此如需要直接生成本批组件 TGZ，可在根目录执行：

```powershell
npm run pack:plugins -- ai-assistant ai-sdk android-device android-packages artifact_copy automation cooperative_demo dex-analysis echo frida harmony-device marketplace mirroring msgpack performance_demo settings terminal tool-supply
```

打包器没有跳过编译参数，已显式加入 `-j 1`；仍须由主代理统一排程，不在其他角色 Cargo 构建期间启动。可复用 `packNativePlugins({ destination, selected })` 选择新的独占输出目录。selected 使用清单ID，上述三项下划线不能写为目录名。组件 TGZ 不等于依赖齐全的最终 ZIP。推荐使用 `build-official-releases.mjs` 连续执行本轮构建、冻结、输入生成、最终构包和目录复验；见同目录 README。

## tool-supply职责与目录边界

本角色只有分发/CLI写权，没有`backend/plugins/tool-supply`、SDK或宿主写权。工具供应与统一工具仓库由主代理及后端角色维护；本角色不重复接手，不直接改安装账本或清理共享资源。

托管工具复用统一仓库的版本、平台和摘要身份；统一发布组件、工具和配置归服务器`DEVICEFORGE_USER_DIR`或默认用户根。`--data-dir`、旧插件目录及`APK_ADB/APK_HDC`是业务数据或兼容入口；旧自定义供应仍使用显式`install_root`，不应把该设置当作统一发布资源根。已托管的可选APK工具按资源声明补齐有效配置中的`kind`，已有用户值优先，自定义路径仍需手填正确的工具类型。
