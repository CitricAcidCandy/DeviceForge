# 第三方设备提供者真实服务验收

入口为根目录 `node scripts/device-provider-smoke.mjs`；发布模式追加 `--release`。分别读取 `backend/target/debug/apk-server` 或 `backend/target/release/apk-server`，Windows 使用 `.exe`。脚本不运行 Cargo/npm、不准备 runtime；必须等集成负责人确认最新构建后再执行，不能以旧程序证明新设备契约。

报告写入 `artifacts/device-provider-smoke-{profile}.json`，包括阶段、精确错误码、检查项、共享任务 ID、真实夹具进程与清理标记、响应日志关联及失败位置。写好脚本或语法检查通过仅是静态证据；报告的 `passed` 和本轮命令退出码共同表示真实验收结果。

成功发现检查的 `providers` 摘要记录真实 HTTP 声明的 `devices_api_version`、能力 ID/版本、`execution_timeout_ms` 和 `execution_timeout_omitted`；同一声明已与 MCP 完整比较。省略预算时报告值为 `null` 且省略标志为 `true`，不将默认值推导写成实测预算。新增摘要需以重新运行后的报告为证，既有报告不会自动补齐。

## 文件职责

- `client.mjs`：默认不带 Authorization 的公开 HTTP/MCP 调用、日志 ID、分页和共享任务终态。
- `fixtures.mjs`：小型自包含 TGZ、便携清单、设备/能力声明，以及受控门闩、标记和进程退出观测。
- `node-provider.mjs`：归档中的协议 3 独立 Node 入口，不依赖宿主内部代码。发现操作接受空对象，能力接受 `{device_id,input}`；响应后等待宿主输入 EOF。
- `discovery.mjs`：提供者列表、明确刷新、同名设备身份，以及刷新失败撤销陈旧目录和成功刷新重建。
- `actions.mjs`：两种范围和访问类型、固定准入错误、共享任务及真实执行互斥。
- `lifecycle.mjs`：取消发现/能力、卸载撤销、旧代拒绝、重载及历史保留。

## 覆盖与证据

每次在空临时目录启动默认免令牌真实 Rust 服务，显式用 `DEVICEFORGE_NODE=process.execPath`。两个在线 TGZ 的插件 ID 不同，本地设备 ID 相同；展示平台字符串相同，不能据此选择执行器。安装、加载和刷新分别执行，不接受业务请求选择服务器路径。

覆盖 HTTP/MCP 的提供者和目录列表、刷新与共享发现任务、动作与共享能力任务。设备能力含读/写、明确不可用和缺少可用观测；提供者能力也含读/写。校验版本精确匹配、离线/未知设备、未观测目录、未知能力、过期代际、非法输入，以及重复 localID、非法状态和非声明能力发现。坏设备声明必须安装失败且无部署/暂存或贡献残留。128 台设备、32 项声明及其他数量边界由后端单元测试负责，本脚本不声称覆盖全部数量上限。

刷新开始时撤销该代目录；失败或取消后，HTTP/MCP 均不得继续暴露陈旧观测。每种坏发现分别从已有有效目录执行 HTTP/MCP 失败检查，每次失败后再成功刷新并更新快照，以验证目录重建并为后续能力动作提供明确观测。取消发现也先核对目录不可见，再执行成功刷新。

互斥通过真实进程门闩与追加事件顺序判断：同设备写串行且直接 `jobs` 不绕过；不同设备写可并行；同设备读可并行；提供者写屏障同时阻止所属设备读和写，直接 `jobs` 仍受约束；不同提供者可并行。这里的同名模拟设备不是同一物理设备的别名，不证明跨提供者物理身份互斥。

能力任务经 MCP 显式取消；发现共享任务经 HTTP 取消，刷新返回精确 `409 cancelled`。卸载能力任务与在途发现时，要求管理返回时已收到取消、已写清理标记且进程退出。再核对目录/操作撤销、旧代不可提交、重载新代目录不得复活，以及成功/取消历史仍可查询。服务全过程不重启，结束后正常关闭并验证日志落盘。

错误断言固定为：未知提供者/能力/精确版本/设备 `404 not_found`；旧代、离线、不可用或未观测 `409 conflict`；错误发现、重复 ID 或非声明能力 `502 dependency_failed`；语法、缺字段、非对象输入或非法版本 `400 invalid_input`；刷新取消 `409 cancelled`；坏设备声明安装 `400 invalid_input`。MCP 业务失败必须使用对应工具结构和相同领域 code，不接受任意 4xx 兜底。

## 清理与边界

夹具资源只有自有计时器、输入流和本次临时标记。协议 3 声明 `cleanup:complete` 与进程退出证明这些模拟资源已清理，不证明真实设备恢复、外部连接清理或常驻传输。管理员路径只放入本次包配置，不放入业务 HTTP/MCP 输入。

失败也先关闭自有宿主，仅在必要时终止本脚本直接持有的 ChildProcess。绝不按可复用 PID 强杀；若夹具仍可见则失败并保留临时目录。递归删除前检查绝对目标位于系统临时目录内，只删除本次目录。不修改源后端、前端、runtime、旧 smoke 或用户其他文件。
