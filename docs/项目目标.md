## 用户后续明确决定

以下是对会话后续指令的整理；与原始目标共同构成接续范围。

- 新项目位于当前工作区：`G:\Rust\DeviceForge`，名称为 DeviceForge（设备工坊）。旧 `E:\React_Js\Electron\ApkTool` 只读取证，不写入重写实现。
- `backend/AGENTS.md` 与 `frontend/AGENTS.md` 必须各自独立，前后端分别遵守所属开发要求；前后端业务文档不能混放。
- 热拔插是整体项目目标。基础平台负责通用运行、插件注册、任务、设备目录、产物及日志；Android、Harmony、未来 iOS 等具体平台能力通过适配器插件接入。新增平台不在通用宿主增加命令分支。
- Rust 服务使用异步框架，提高并发能力；当前选定 Tokio 多线程运行时与 Axum。性能需要测量，不能仅凭框架选择宣称达标。
- 前端可以在线提交服务器插件和前端插件并热装卸。前端插件开放动态渲染、组件、模块、功能、逻辑、命令、服务及服务器对接；公开 SDK 与宿主私有实现保持边界。
- 部署预期为本机或同事局域网。用户最新选择默认免鉴权、可信插件运行；令牌可选，不要求多用户权限、来源审核或强制不可信插件沙箱。这一决定覆盖此前讨论过的普通用户不可信插件隔离方案。资源限额、取消与清理仍属于稳定性要求。
- 具体产品界面、视觉方案和新增 UI 框架等待用户设计稿。本阶段做基础工程、通信、模块用例及插件框架，不能用占位页面表示业务界面完成。
- 四角色为交付总监、前端开发、后端开发、测试助理。开发交接冻结批次后继续独立下一项；普通缺陷按验收项汇总，阻断即时回流。主代理明确文件写权、集成和验收排程，不能让开发无依赖地等整批测试。
- 用户可能同时修改文件：不擅自恢复、覆盖或删除无关改动，不自动 Git 提交。注释、文档使用中文和 UTF-8；大型写入分批。
- 用户询问进度时仅核对并汇报，不因此启动开发、构建或测试；本轮已明确要求继续，四角色按独占写集恢复开发。
- 最新优先级为“先迁移内容，再做优化”：先按迁移清单交付核心业务和公开接口，保留必要的正确性、编译、取消与清理验证；性能调优、非阻断结构整理、资源增强及重复扩展验收延后。已冻结批次进入验收队列后，开发继续独立下一项，不等待整批分发或性能验证。
- 前端采用严格 TypeScript，检查范围须覆盖维护的源码、工具和测试；浏览器运行的 JavaScript 由构建生成。用户再次质疑初始 Svelte 选型及维护 `.mjs`，当前前端工具与测试已迁严格 TS；主代理承认 Svelte 选型论证不足并推荐 React + 严格 TS。React 切换尚未执行，不把提问或推荐写为用户已批准框架切换。
