# 插件开发清单与生成工具

本模块面向独立插件工程，只读取一份 `manifest.json` 和显式构建产物，不执行构建脚本、不启动服务、不操作设备。旧安装协议继续使用生成后的便携包与完整发布格式，不修改现有安装器。

- `manifest.mjs` 校验并归一化开发清单、身份继承、运行字段及统一依赖。
- `market.mjs` 校验市场字段，从功能和组件生成完整展示资料。
- `components.mjs` 收集显式产物、生成便携清单与浏览器身份入口。
- `pack.mjs` 编排新目录暂存、依赖、组件 TGZ、真实摘要与完整离线发布。
- `prepared.mjs` 保存已封口字节的准备回执，核对原目录和最终成员后提交；不重新构建或覆盖目标。
- `finalize.mjs` 对最终重命名提供有界等待；`native-move.mjs` 仅在 Windows 明确共享冲突时调用固定辅助脚本，不改变执行策略。失败只接收固定协议的有界HResult，不把任意stderr或路径显示给调用者，也不因取得诊断而自动重派。
- `commands.mjs` 解析开发命令，装配打包、只读计划与显式发布。

归档、资源验证与发布复用随 CLI 一同交付的公共发布工具；根 npm 包显式包含这些模块及其 semver 依赖，不要求开发者获取宿主源码。市场资源摘要仅在在线清单生成后进入 catalog，不能写回自身归档。已存在输出不覆盖；源工程保持原样。普通打包失败清理本次独占暂存；显式准备流程保留回执和暂存，供原批次查询与接续。

需要让打包进程先退出时，使用 `plugin pack manifest.json --out 新目录 --prepare-only true`，再以返回的实际回执路径执行 `plugin finalize 回执.json`。前者只返回 `prepared`，不能用于安装或发布；后者逐成员核对大小、SHA-256、发布清单和最终 ZIP。目标已存在且源仍在时拒绝覆盖；源已消失时仅观察目标完整字节，符合原回执才返回 `completed`。结果未知保留现场，不自动重新打包。

直接验证使用 `node --test cli/tests/plugin-authoring.test.mjs`。此命令只供本仓库维护者使用，对外流程及字段分别由 MCP 的 manifest、packaging 和 examples 主题提供。
