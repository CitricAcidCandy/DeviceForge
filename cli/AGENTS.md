# 启动器与分发开发要求

## 职责与依赖

- 当前目录负责参数、网络监听、运行包加载、进程生命周期和服务器插件安装，设备业务交给 Rust 后端。
- `bin` 只解析命令并装配；`options` 负责参数；`network` 负责地址与 Host/Origin；`start` 负责启动和收敛；`web-server` 负责固定代理与静态资源。
- `install` 编排安装；`plugin-package` 处理便携清单；`plugin-files` 执行受限复制；`runtime` 和 `paths` 校验分发文件。不得将这些职责集中到单一入口。
- 不复制宿主插件注册规则，安装使用同包 Rust 校验器和公开插件协议，不引用前端或后端内部源码。

## 路径、网络与资源

- Node.js 参数使用独立 argv，不把包名、路径或用户参数拼入 shell。相对部署路径按 CLI 工作目录统一解析，再向子进程传绝对路径。
- 默认监听局域网，保留 `--ip`、`--port`、`--mcp-port`；两个公开端口必须不同，Rust 内部端口仅监听回环。
- 按用户最新决定默认免鉴权，APK_API_TOKEN 可选；不因局域网启动缺少令牌而拒绝启动，不自动生成调用方无法取得的随机访问令牌。配置令牌时保留现有兼容行为。
- 令牌不进入日志、HTML、插件或安装子进程，不自动替浏览器注入鉴权；Host 与 MCP Origin 按实际监听配置验证。
- 安装禁用 npm 生命周期脚本，受限复制并校验清单，暂存与发布同卷；拒绝覆盖相同 ID，不扫描半成品。
- 取消、启动失败、端口冲突和后端提前退出必须关闭本次监听及进程，不终止无关进程。仅清理本次创建且已检查边界的临时目录。
- 保持流式代理，不把上传下载整体缓存在启动器内存；运行包验证平台、版本与摘要。

## 检查与交付

- 注释与文档使用中文及 UTF-8，大型写入分批进行；不自动提交、恢复或删除用户无关修改。
- 在项目根目录执行 `npm test`；改动分发或启动边界还需 `npm run prepare:runtime`、`npm run smoke:cli` 和 `npm pack --pack-destination artifacts`。
- 修改两端源码时另行遵守各端独立 AGENTS.md；更新根目录 todo.md，记录实际构建模式与验证边界。
- 本地 tgz、npm 公开发布、本机局域网地址、另一台机器、跨平台与真机分别记录，禁止将单平台模拟验收扩写成全部完成。
