# 前端文件骨架与开发约束

## 基础骨架
```text
frontend/
  src/app/               启动、路由装配、全局样式
  src/features/          操作、任务、设备、服务器插件与在线包基础用例
  src/shared/api/        生成接口类型与 v2 HTTP 客户端
  src/shared/ui/         纯展示组件与可访问性基础交互
  src/plugin-sdk/        公开扩展契约
  src/plugins/           贡献注册表、包加载与运行生命周期
  tests/                 客户端、用例、插件行为及架构测试
  scripts/               接口生成等开发工具
  public/                部署静态资源
  docs/                  仅前端文档
```

## 依赖方向
app 装配 features/plugins；features 使用 shared 与 plugin-sdk；plugins 依赖公开 SDK；shared 不引用 app/features；插件只依赖公开接口，不访问宿主私有模块。功能按业务用例划分，避免还原旧 renderer 目录和跨页面单例。

设备工作台按提供者贡献及能力驱动，平台特有流程通过面板扩展；规则见 [设备能力与插件面板](设备能力与插件面板.md)。通用界面不复制设备工具命令，不按平台枚举决定功能是否可用。第一阶段设备上下文及目录/选择/离散动作已实现，能力 UI 尚未实施。features/devices 只依赖公开网关与 SDK；app 映射生成 HTTP 字段并编排本地管理后的目录撤销与重查。

## 开发规则
- 只在接口适配器处理 HTTP、令牌、重试和错误映射；组件使用明确的状态与用例函数。
- HTTP 类型从后端模式生成，不复制后端实体定义。插件契约独立版本化，适配器承担 DTO 映射。
- 本阶段提供真实通信、基础用例和开放热装卸；完整业务页面等待设计稿。
- 所有文档和代码注释使用中文；接口字段保留协议定义。
- 开启严格类型、索引检查与准确可选字段；不得用 any 绕过接口边界。
- 每个异步任务明确取消、销毁及失败行为；插件卸载必须释放订阅和 DOM。
- 不读取本机绝对路径，不使用 Electron 桥接，不将访问令牌保存在 localStorage 或 URL。
- 组件采用语义 HTML、键盘操作及可访问标签；长列表后续使用分页或虚拟化，并以实际数据测量性能。
- 本地/同事局域网默认免鉴权，在线包按可信代码运行；不增加来源审批或强制隔离，生命周期管理遵守公开 SDK。
- 门禁：生成接口类型后执行 npm run check、npm test、npm run build。业务 UI 正式加入时补浏览器交互测试。

## 当前限制
外壳只展示开发进度，不提供设备交互。客户端、宿主上下文、动态加载器、开放贡献与第一阶段设备用例已实现，生产入口 `/assets/plugin-host.js` 导出 createFrontendRuntime/createNamedSlotAdapter。runtime.devices 已接入可选 HostContext.devices，apiVersion 保持 2；`main.ts` 已通过 bootstrap 装配产品 runtime，并接入页面根节点和可选主题目标。具体设备 UI、主题设置入口、常驻设备会话、后台推送、平台工具迁出与真机仍待独立实施或验收。主代理前阶段 debug/release 浏览器证据覆盖实际在线上传、运行与清理，不扩大为本轮设备证据。

设备刷新在途清本代旧观测/选择，修订和取消保护替代请求及旧代；实例与挂载子生命周期撤销设备请求和订阅。远端变化显式刷新，本实例服务器管理后先撤销目标缓存再重查。本轮 check 退出 0（49 源码、0 错误/0 警告），test 退出 0（73/73），最终 build 与设备浏览器验收由主代理负责。

## 自动架构门禁
完整执行要求见本端 AGENTS.md。`npm run check:architecture` 已接入 `npm run check`，使用 TypeScript 和 Svelte 解析器检查 import、重导出、类型引用及字面量动态导入。路径别名按 tsconfig 解析，拒绝跨工程源码、反向依赖、功能之间直接耦合及循环导入；UI 不引用 API，SDK 不引用宿主。网络直接调用只能放 shared/api，手写源码禁止 any；generated.ts 的生成类型独立保留。

前端维护脚本、测试与 Vite 配置同样纳入严格类型检查。架构门禁拒绝生产源码和 scripts/tests 中重新引入的 JavaScript 维护文件；浏览器验收模块由 TypeScript 构建为独立 JavaScript 产物，公开宿主继续作为外部依赖。JSDOM 测试只证明节点行为，真实浏览器驱动另验构建产物。

规则及失败用例包含在 npm test。门禁检查静态导入和直接调用，不能证明网络函数别名、运行时模块加载、插件信任、视觉效果或资源释放正确；这些仍需审查与行为验收。新增动态加载方案须先更新契约和相应门禁。
