# 前端目录与组件约束

本约束适用于 React 前端维护源码；架构门禁由 TypeScript AST 解析值导入、类型导入、重导出和动态导入，解析真实目标路径后检查，路径别名不能绕过。

## 公共组件

公共目录是 `src/components`，范围不限于官方基础组件。

| 目录 | 职责 | 允许的内部依赖 |
| --- | --- | --- |
| components/ui | 官方基础组件与可访问性组合 | ui、lib、shared 纯工具 |
| components/common | 无业务状态的通用展示 | common、ui、lib、shared 纯工具 |
| components/integrations/<库或能力> | 实际使用的第三方通用封装 | integrations、common、ui、lib、shared 纯工具 |
| components/lib | 组件纯工具 | lib、shared 纯工具 |

所有 components 均禁止读取 shared/api、features、app、plugins、plugin-sdk。shared 纯工具限定 shared/lib 和 shared/utils，不能反向读取其他共享业务适配或自行联网。common 不依赖具体 integrations，ui 不依赖 common/integrations；第三方包可以作为通用封装依赖，业务查询、设备状态与任务派发留所属功能或 app。只在实际使用时创建集成目录，不建空目录或虚构封装。

## 功能模块

`src/features/<功能>` 的根目录保留薄 index 公开门面和中文 README，其他源码按实际职责放入所需层，不强制建立四个空目录。

| 层 | 职责 | 同模块允许的内部依赖 |
| --- | --- | --- |
| domain | 纯规则与模型 | domain |
| application | 用例和状态 | application、domain、infrastructure |
| infrastructure | 适配器与解码 | infrastructure、domain |
| ui | 该功能专用展示 | 本模块各层与 components |

不同功能不直接互相导入，跨功能协作由 app 装配公开端口。app 对 features 的值或类型导入都必须经过 `features/<功能>/index.ts`；功能内部不反向依赖 app。只有 ui 层可依赖 components，其他功能层不能引入展示组件。现有公开 shared/SDK 消费继续按原层边界检查，本批目录迁移不额外创造强制剥离任务。

## 执行与例外

`npm run check:architecture` 检查源码位置、依赖方向、循环、网络边界与 README；`tests/architecture.test.ts` 包含第三方封装允许用例，以及组件反向依赖、类型与别名入口绕过、功能根部源码的拒绝用例。测试可读取内部源码，但不会放宽生产导入限制。

发现普通结构或约束异常时，开发者直接修正文件职责、导入或门禁并补对应行为证据，不新增用户审批步骤。无法完成的外部条件如实报告；禁止用文档豁免依赖错误或把目录重排计为业务、视觉或真机验收。
