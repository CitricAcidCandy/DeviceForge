# 任务历史与事件公开接口裁定草案

日期：2026-10-10。任务 TASK-HISTORY-CONTRACT，模式 architecture-first / Hybrid。本文整理已有只读方案，**待主代理裁定，不是已实施的公开接口或验收报告**。冻结本文只冻结评审输入，不代表 SDK 字段已获最终裁定。产品界面继续等待设计稿。

## 目标与现有边界

向第三方浏览器插件开放已有任务历史查询及状态事件查询，沿用 SDK API2 的可选加法。当前 `runtime.tasks` 已有 `list(query, signal)`、`get(id, signal)`、`events(id, query, signal)`；公开 `HostContext` 已有 `getJob`，尚无历史列表或事件查询入口。后端与生成类型已有这些 HTTP 能力，本批建议不增加服务器路由或重复 DTO。

当前服务端任务列表只接受 `limit`，默认 50，范围 1..200，按持久化记录的 rowid 降序返回最近记录；没有列表游标、平台筛选或完整历史遍历保证。事件只接受 `after`，默认 0，每次最多 200 条，按全局 `sequence` 升序返回目标任务的记录。不同任务共享序号空间，同一任务的序号允许有间隙。事件是状态记录，不是任务日志、百分比进度、SSE 或 WebSocket；本批不增加自动轮询或重连器。

实现依据：[任务基础用例](../src/features/tasks/index.ts)、[现有公开映射](../src/app/public-api.ts)、[HTTP 端点](../src/shared/api/endpoints.ts)、[HTTP 校验](../src/shared/api/validation.ts)。生命周期分层沿用[插件产物传输第一批裁定](插件产物传输第一批裁定.md)，具体职责继续遵守[前端运行架构](前端运行架构.md)。

## 推荐公开形状

推荐 `HostContext.taskHistory?: TaskHistoryAccess`。旧 API2、自建宿主上下文和既有插件可省略；缺省时不补伪实现。所有方法显式传入 `AbortSignal`，即使查询选项为空也传 `{}`。下面仅定义建议中的独立 SDK 模型，不是服务器 DTO，也不表示当前 SDK 已导出这些名称。

```ts
export interface HistoricalJob extends Job {
  readonly input: JsonValue;
  readonly createdAt: number;
}
export interface JobEvent {
  readonly sequence: number;
  readonly jobId: string;
  readonly status: Job['status'];
  readonly timestamp: number;
}
export interface TaskHistoryQuery { readonly limit?: number }
export interface TaskEventQuery { readonly after?: number }
export interface TaskHistoryAccess {
  readonly list: (query: TaskHistoryQuery, signal: AbortSignal)
    => Promise<HostResult<readonly HistoricalJob[]>>;
  readonly get: (id: string, signal: AbortSignal)
    => Promise<HostResult<HistoricalJob>>;
  readonly events: (id: string, query: TaskEventQuery, signal: AbortSignal)
    => Promise<HostResult<readonly JobEvent[]>>;
}
```

`HistoricalJob` 继承现有 SDK `Job` 的 id、operation、status、result、error，只新增持久化 input 与 createdAt；原 `Job`、`getJob`、提交和取消签名不变。宿主显式映射 `created_at -> createdAt`、`job_id -> jobId`，timestamp 保留字段名并明确单位为 Unix 毫秒。列表和事件返回 `HostResult` 的 data/logId，不暴露服务器包装、凭据或路径。

历史读取不关联当前操作目录来补写 execution，不以当前 provider/generation、设备 rawState 或预算填充历史。服务器插件已卸载或同 ID 换代后，旧任务仍以持久化记录为准；查询成功不代表原操作现在可重新提交。已有 result 中的协议包装与产物引用原样作为 JSON 消费，不在本批重解释或新增产物查询功能。

## 参数与响应校验建议

| 项目 | 推荐规则 | 错误关联 |
| --- | --- | --- |
| limit | 省略时交给服务端默认；显式值须为安全整数 1..200 | 发请求前拒绝非法参数，不伪造响应日志 |
| after | 省略时交给服务端默认；显式值须为非负安全整数 | 不补游标、不递增一位来猜下一条序号 |
| id / jobId | 非空白公开标识；校验不改原文，不强制 UUID 格式 | get 的响应 id 与请求 id 精确相同；events 每项 jobId 与请求 id 精确相同 |
| sequence | 正安全整数；每次响应严格递增，且每项大于本次有效 after | 重复、倒序、不安全值或错误任务关联均拒绝整次响应 |
| timestamp / createdAt | 有限、非负安全整数，单位 Unix 毫秒；允许 0 | 不裁剪、取整或猜测秒单位；不要求事件时间单调 |
| input / result / status / error | input、result 沿 SDK JsonValue；status 沿现有五种状态；error 沿现有 Job 映射 | 非法历史数据拒绝映射，不用空对象或当前目录修补 |

安全整数范围以 `Number.isSafeInteger` 为准，拒绝 HTTP 数值超出 JavaScript 精确表示范围的情况；不通过转换为字符串或修改生成类型绕过。事件可以返回空数组，也可以因跨任务序号产生间隙；不能据此宣称事件丢失。客户端可显式用最后一条 sequence 作为下次 after，查询取消或映射失败时不得推进自己的游标。

本批校验在新增宿主映射中收口，不为 SDK 加法扩大既有共享校验器或旧 app 调用行为。旧 `isJobEvent` 仅检查有限数值，因此建议适配层额外验证安全整数、排序与关联，而不是把既有 app 端口写成已具备这些保证。

## 取消、代际与日志

宿主网关组合 caller 与 runtime 生命周期；插件代理再组合实例和挂载子作用域生命周期。请求开始前先检查资格与信号，预取消、runtime 关闭或插件作用域退出均为零新传输。查询属于发起的作用域代次：同 ID 插件重载取得新代理，旧引用不能随新代恢复。

推荐网关显式管理取消等待：即使注入端口忽略 signal 或永不返回，取消仍使宿主等待及时以 `HostError(kind='cancelled')` 拒绝，不能只在 await 之后检查信号。各成功、失败、取消分支移除监听器，对晚到 resolve/reject 均保留已安装的处理器，避免旧结果交付或未处理拒绝。结果接受前复核当前资格；取消先被观察则拒绝，结果已经完成交付后不追溯撤回。实现不得引入当前任务列表的隐式全局缓存或把不同任务的并发查询互相撤销。

作用域退出只撤销插件的查询资格与等待，不删除历史、不隐式取消服务器 Job。浏览器 Abort 不等于 `cancelJob`；服务器插件卸载也不等于历史记录失效。若插件自行维护选中任务、游标或定时器，须在自身生命周期登记清理，并在更新消费状态前复核其选择代次。SDK 不创建轮询、计时器、订阅或连接，因此本批没有可误称为事件重连的宿主资源。

HTTP、网络及协议错误沿现有 `publicCall` 映射为 HostError，保留 code、status、retryAfter 与真实响应 logId；映射失败也必须保留该次响应 logId。建议本地非法查询使用 `kind='protocol'`、`code='invalid_history_query'`；非法历史/事件映射分别使用 `invalid_history`、`invalid_job_events`。这些名称待裁定，不新增服务器错误码。

取消发生时尚无响应，则 logId 为 null；已有响应再拒绝映射或晚到交付时保留已取得的日志，不把 Job ID、事件 sequence 或客户端随机值当日志 ID。迟到响应不能回写已结束的 caller 结果，仅可被安全消费并丢弃。重启后查询到的持久化事件不是当前提供者观测的发布回执，也不保证恢复浏览器退出前的局部选择状态。

## 最小验证与裁定点

采用 Hybrid：先确定可选契约与纯映射，再以可控门闩覆盖作用域；集成后由主代理统一执行类型、测试、构建与真实生产浏览器验收。最小回归应覆盖：旧 API2 缺省；历史 input/createdAt 原值和旧 Job 形状；序号间隙允许而不安全数值/重复/倒序/错误 jobId 拒绝；HTTP 及协议映射日志；预取消零调用；忽略信号的端口取消等待与晚 reject；子作用域退出、同 ID 重载旧引用失效；服务器插件撤销后历史仍可读且不补当前元数据。真实浏览器须通过在线插件实际 public context 查询服务端记录；纯适配测试不能证明持久化、热卸载或真实服务通过。

待主代理裁定仅三组边界：

1. 接受 `taskHistory`、HistoricalJob、JobEvent 与上述三个方法的命名及只读返回形状；原 Job/getJob 保持兼容。
2. 接受安全整数、精确 jobId 关联、事件严格升序及整次拒绝规则；上述本地错误码仅用于 SDK，logId 保持实际响应来源。
3. 接受无隐式缓存/轮询、取消等待及时拒绝、已交付结果不撤回的生命周期语义，以及三新文件先行、四处装配后置的写集顺序。

本草案未实施 SDK、HTTP 或产品界面；未运行生成、类型检查、测试、构建或服务。产物加法和协议升级的既有报告独立保留，不作为任务历史公开能力的运行证据。
