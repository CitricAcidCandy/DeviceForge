# 产物配额与保留期消费边界

本文规定前端、浏览器插件和宿主插件如何消费产物存储的容量、并发、删除和保留期结果。本文只描述公开 HTTP/API 消费语义，不实现产物列表、配额管理、保留期清理或具体产品界面。

## 现状与证据边界

当前服务已公开以下产物端点：

- `POST /api/v2/artifacts`：流式上传；成功返回产物元数据。
- `GET /api/v2/artifacts/{id}`：读取元数据。
- `GET /api/v2/artifacts/{id}/content`：读取原始字节。
- `GET /api/v2/artifacts/{id}/entries`：分页预览 ZIP 中央目录。
- `DELETE /api/v2/artifacts/{id}`：删除一个已发布产物，成功响应携带被删除产物的元数据。

当前后端的 `FileArtifacts` 有单个产物和格式验证上限、上传/读取并发限制以及受控目录删除；没有总磁盘配额计数器、配额查询端点或保留期清理任务。因此：

- `payload_too_large` 目前只表示本次上传超过单产物、格式或结构上限，不能被前端解释为总配额用尽。
- 当前没有已冻结的 `quota_exceeded` 专用响应，也没有保留期清理状态响应。前端不能通过本地累加文件大小、错误消息或 HTTP 413 自行推导总配额。
- `cleanup_failed` 是现有插件外部资源清理语义，不能自动改名或套用为保留期清理失败。
- 总配额、保留期限和清理失败的专用错误码需由后端先冻结 OpenAPI 后，前端再运行生成器并补适配测试。未冻结前，未知错误按原始公开错误消费。

## 错误保真

`src/services/api/client.ts` 已将 v2 错误的 `error.code`、HTTP `status`、`log_id` 和 `retry-after` 原样放入 `ApiError`。消费方必须同时保留 `kind`、`code` 和 `status`，不能只根据中文 `message` 或把所有 409/413 归为同一业务状态。

| 返回结果 | 当前公开含义 | 前端消费动作 |
| --- | --- | --- |
| `http` + `payload_too_large` + 413 | 本次上传超过单产物、格式或结构上限 | 停止本次上传；修正输入后由调用方显式重试。不提示“清理空间后一定成功”，也不自动重放相同字节。 |
| `http` + `conflict` + 409 | 并发上传/下载/ZIP 预览已满，或删除时仍有读取者 | 保留真实 `logId`；结束当前等待并让调用方决定稍后重试。不得把它改成成功删除或自动循环重试。 |
| `http` + `not_found` + 404 | ID 不存在，或已被删除/保留期清理 | 将该 ID 视为陈旧引用，清掉本地选中项和相关元数据/目录页；显式重新查询来源。不得自动换用其他 ID。 |
| `http` + `storage_failed` + 500 | 服务端存储或校验异常 | 保留错误类别和 `logId`，停止写操作重放；是否重试由调用方按人工确认和新的查询结果决定。 |
| `cancelled` | 调用方取消等待、切换选择或销毁宿主，不代表服务器事务已回滚 | 立即结束本地等待并丢弃晚到结果；随后重新查询以确认服务器最终状态。 |
| 未来 `quota_exceeded` | 后端冻结后的总磁盘配额准入拒绝 | 视为写入未获准；停止自动重试，先显式查询容量/清理状态，确认有空间后由调用方重新发起。前端不得自行删除任意产物来“腾空间”。 |
| 未来保留期清理错误 | 后端冻结后的保留期清理状态 | 原样保留后端 `code/status/logId`；清理未确认时不宣称空间已经释放，也不把仍可读取的旧元数据视为永久有效。 |

`quota_exceeded` 和保留期清理专用码在后端正式加入前只是预留语义，不是当前可发送的客户端错误。客户端收到未知 code 时仍按 `ApiError.kind === 'http'`、实际状态和原始日志处理，并不得猜测它属于容量、保留期或权限问题。

## 取消与重新查询

### 上传

上传是流式写入。调用方取消可能发生在请求尚未到达、服务端仍在暂存，或服务端已经提交而响应尚未返回的任一阶段；因此取消后不能断言“没有产物”，也不能断言“临时文件已删除”。

取消上传后按以下顺序消费：

1. 结束当前 `AbortSignal` 等待，不读取晚到成功或晚到错误来覆盖当前取消状态。
2. 不使用未知 ID 盲目调用删除，也不立即用相同字节自动重传，避免产生重复产物。
3. 通过拥有该上传的任务/操作查询或未来的产物目录查询确认最终状态。当前服务没有产物列表和配额查询端点，前端只能保留“结果未知”并等待宿主提供查询入口。
4. 只有显式查询确认未发布或调用方明确决定重试后，才重新上传；重试仍需重新走输入校验和容量准入。

### 元数据、目录与下载

元数据、ZIP 目录和下载请求都必须传入独立 `AbortSignal`。选择切换、刷新、`clear` 或 `dispose` 会撤销本地等待；晚到成功不得复活旧选择。取消不会改变服务器上的产物。

若取消后需要继续显示，调用方必须用新的 signal 重新查询当前 ID。新查询收到 `not_found` 时清除陈旧观测；收到 `conflict` 时保留冲突日志并等待下一次显式操作；不得从旧快照推断产物仍然存在。

### 删除

删除成功后，响应中的元数据只能作为本次操作回执使用；该 ID 从成功时刻起不得继续作为可读取资源。当前共享 API 尚未提供删除适配器，本条供未来宿主/功能接入时遵守。

删除等待被取消时，不能判断删除是否提交。调用方必须重新查询元数据或拥有该产物的来源：

- 查询成功表示删除尚未生效，继续使用新的元数据快照；
- 查询得到 `not_found` 表示已删除或已被保留期清理，移除本地引用；
- 查询得到 `conflict` 或 `storage_failed` 表示状态未确认，不重复删除、不宣称成功，保留日志并等待人工或后续显式查询。

重复删除已不存在的 ID 按 `not_found` 消费，不做幂等成功转换。这样可以区分“这次删除确认提交”和“目标早已不存在”，避免错误释放配额或重复更新任务结果。

## 配额与保留期的待冻结接缝

后端实现总配额和保留期清理时，必须在 OpenAPI 与错误响应中同时明确：

- 配额计算是否包含上传暂存、已发布产物和跨进程共享目录；拒绝发生在写入前还是提交时；失败是否保证暂存回收。
- `quota_exceeded` 的稳定 code、HTTP status、可选 `retry-after` 和日志 ID；客户端不得用文件大小估算替代服务端准入结果。
- 保留期扫描的时间基准、删除顺序、并发读取/下载时的冲突结果，以及清理失败是否需要人工介入。
- 清理完成后再次查询的可见性；在途下载得到的字节是否允许完成，后续元数据请求何时转为 `not_found`。
- 跨进程服务重启后的计数恢复、重复清理和异常退出回收。没有这些证据时，前端只能报告“状态未确认”。

配额查询或清理控制一旦落地，应新增独立 shared/api 端点和生成类型；不要把容量字段塞进 `ArtifactDto`，也不要由浏览器插件直接读取服务端路径或目录。

## 插件边界

服务器插件、设备提供者和浏览器面板都只能通过宿主公开的产物引用和 `HostResult` 消费结果。插件不能：

- 读取 `APK_DATA_DIR`、服务端文件路径或锁文件来判断配额；
- 将 `payload_too_large`、`conflict`、`not_found` 改写成自定义成功值；
- 在取消后继续使用未确认的临时路径或假定清理完成；
- 为了容量自动删除其他插件或用户的产物；
- 以旧快照、任务 ID 或文件名代替产物 ID 重新定位资源。

插件卸载或宿主销毁只撤销本地调用和订阅，不改变服务器产物生命周期。任何删除或保留期动作都必须由公开服务返回可审计的 code、status 和日志 ID。
