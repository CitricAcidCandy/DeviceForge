# 投屏直播消费契约

## 范围与层次

本轮模式为 architecture-first：真实服务器插件负责设备连接、scrcpy-server 三路套接字、资源清理与设备重连；前端复用公开交互会话端点，负责有界分帧、无页面解码/播放、控制输入与消费生命周期。HTTP 生成类型、SDK 和 app 装配由主代理统一管理；本模块不复制 HTTP DTO、不实现产品页面、不引入 UI 框架。

## 打开与会话消费

通过 `createHttpMirroringStreaming(client, options)` 先 `refreshDefinitions(signal)`，确认目录中的 `plugin.mirroring.open` 后执行 `open(input, signal)`。输入是以下业务字段，不能传本机工具路径或录制时长。

| 字段 | 边界 |
| --- | --- |
| `device_id` | 与录像一致的 1 至 200 字符 ASCII 设备标识 |
| `max_size` | 可选整数 64 至 4096 |
| `max_fps` | 可选整数 1 至 60 |
| `video_bit_rate` | 可选整数 128000 至 16000000 |
| `audio`、`control` | 可选布尔值，实际默认由后端决定 |
| `reconnect_attempts` | 可选整数 0 至 5 |

公开会话输出块仍由 `SessionGateway.output` 返回。前端只保留当前帧的重组缓冲（最大 4MiB 载荷加 24 字节包头）、配置、游标与计数，不积累视频历史。每次只允许一个 `readOutput/pollOutput`；先取消并等待旧调用退出，再恢复游标。

输出字节采用专用平坦数组校验，保留 8192 字节、整数范围、稠密自有数据属性及无额外属性的要求，不对每个字节构造通用 JSON 递归结构。媒体页复制后冻结会话、块及字节数组，来源修改不能影响消费。普通音视频包按原顺序交付 sink，计数与游标在页末统一通知；状态、配置和连接代次变化仍及时发布，普通媒体包不逐包触发界面快照通知。该处理不跳过 H264 差分帧或重连依赖检查。

`readPackets({limit?}, signal)` 返回 `{session,cursor,packets,mediaPackets}`，其中 packets 是累计完成包数，mediaPackets 仅包含本次完成包。它与 `readOutput/pollOutput` 共享唯一消费游标，不读取重复页，不储存历史；不能先消费计数页，再要求媒体方法返回同一页。每批最多 100 个 8192 字节输出块，已缓存半包最多 4MiB，完成媒体原字节不超过 4MiB 加 819200 字节，完成包最多 32768 个。媒体字节在交付可选宿主 sink 前建立独立副本，宿主 callback 修改收到的字节不会污染调用方批次。

同一实例的 `resume(id, signal)` 保留已确认游标和未完整媒体包，网络失败不会重开会话。换会话只从零读取，不提供任意媒体中间游标。服务器尾部保留导致游标过期时，传播公开错误，要求显式重开，不静默跳至中间 H264 帧。帧交付开始后的取消/解码失败会撤销本消费继续恢复资格，避免重放已交付帧。新 open 撤销本地旧消费，但不会自动终止服务器旧会话；宿主须显式 cancel 旧会话，避免留下设备资源。

## DFML 版本 1

stdout 是连续原字节，包可跨多个 8192 字节输出块。前端拒绝 stderr 媒体页、错身份、错插件代次、输出缺块和乱序；不把二进制内容转为文本。

| 包头偏移 | 内容 |
| --- | --- |
| 0 至 3 | ASCII `DFML` |
| 4 | 版本 1 |
| 5 | 类型：1 视频配置、2 视频、3 音频配置、4 音频、5 状态 |
| 6 至 7 | 大端 flags：视频 0 差分/1 关键帧/2 SPS/PPS；其他类型为 0 |
| 8 至 15 | 大端 u64 PTS，单位微秒，前端要求安全整数 |
| 16 至 19 | 大端 u32 载荷长度，1 至 4MiB |
| 20 至 23 | 大端 u32 连接 epoch，从 1 开始，重连后递增 |

视频配置 JSON 为 `{codec:'h264',format:'annexb',width,height}`。随后视频 flags=2 携带 Annex B SPS/PPS，前端从 SPS 派生真实 `avc1.*` 浏览器配置。普通视频包为原始 H264，flags=1 是关键帧。配置切换或解码队列超限会撤销依赖链，等待新关键帧；关键帧前补本代 SPS/PPS，避免差分帧越代复用。

音频配置 JSON 为 `{codec:'pcm_s16le',sample_rate:48000,channels:2}`。音频是双声道交错 PCM16 小端原字节，长度须按 4 字节对齐。浏览器 sink 将样本归一化为左右声道，播放队列有界；共享 AudioContext 由实际宿主启动和拥有，模块只释放自己创建的音源，不自动绕过浏览器的用户交互要求。

状态 JSON 为 `{state,attempt}`，state 是 `connecting/streaming/reconnecting/audio_unavailable`，attempt 为 0 至 5。新 epoch 必须从状态或视频配置开始；旧 epoch 包明确拒绝。新代清空视频/SPS/PPS/音频配置，不能消费旧代依赖。

## 控制与防重放

`sendControl(command, signal)` 接收业务命令，门面加入当前已观察到的 `epoch`，编码为 UTF-8 JSON 加换行，单行最多 4096 字节。只能在已观察本代 Streaming 后发送，Connecting/Reconnecting 收敛入口；不允许调用方伪造 epoch。

| 命令 | 字段与边界 |
| --- | --- |
| touch | action=`down/up/move`；pointer_id 可选 0 至 9；width/height 为 1 至 65535；x/y 在尺寸内；pressure 可选 0 至 1 |
| key | action=`down/up`；keycode 0 至 320；repeat 可选 0 至 1000；meta_state 可选 0 至 2147483647 |
| text | 有效 Unicode、无 NUL，UTF-8 最多 300 字节 |
| clipboard | 有效 Unicode、无 NUL，UTF-8 最多 2048 字节，paste 可选布尔值 |
| rotate、reset_video | 仅 type 与门面生成的 epoch |

设备剪贴板读取使用 `get_clipboard`（`copy_key` 为 `none/copy/cut`）。WebRTC 使用可靠有序的 `deviceforge.control` 通道承载控制所有权和剪贴板分片。兼容模式会排空但丢弃设备回传，不能通过共享输出游标读取剪贴板正文。

### WebRTC 独占控制与原生复制

同一设备同时仅一名控制者。可控制的分享链接允许申请接管，当前控制者同意或拒绝；服务器认定的主控可以主动抢回，控制者可以释放。只读分享继续观看，不能发送触摸、键盘、粘贴或控制申请。创建者身份本身不决定正文归属；接管成功的分享接收者在设备内点击原生复制菜单时，只由该接收者的客户端写入电脑剪贴板。

服务端通过 DataChannel 发布 `{version:1,type:'control_state',epoch:1,revision,control_revision,client_id,owner_id,is_master,can_control,has_control,transitioning,blocked,requests}`。`revision` 与 `control_revision` 为正安全整数：前者用于状态与申请队列更新，后者仅用于控制交接、阻断和恢复。普通申请或拒绝不撤销当前控制修订，避免吞掉当前控制者的按键释放。客户端与所有者身份为规范 UUID（`owner_id` 可为 `null`）；状态布尔字段必填。`requests` 最多 64 个且客户端身份不可重复，每项为 `{client_id,is_master}`。前端映射为 `MirroringOwnership` 的 camelCase 字段，未知或失权状态关闭页面设备输入，视频继续播放。主控判定来自服务器可信连接上下文，客户端不提交主控身份。

局域网开发部署默认由浏览器直连当前前端页面主机名的 `7031` 后端端口，也可通过 `VITE_API_BASE_URL` 显式指定服务器地址。设备控制相关连接不可经开发服务器的共享代理隐藏来源 IP，否则服务器会将所有同事看作同一代理来源。生产反向代理必须提供后端支持的可信来源上下文；未建立该约定时使用直连，不从浏览器字段声明主控。

`requestControl(signal)`、`respondControl(clientId,accept,signal)`、`reclaimControl(signal)`、`releaseControl(signal)` 分别发送带换行的 UTF-8 JSON `{version:1,epoch:1,type:'control_request'|'control_respond'|'control_reclaim'|'control_release',request_id}`，每次 `request_id` 为新的 UUID，响应申请额外携带 `client_id` 与布尔 `accept`。这些请求无需当前持有控制权，仍须已启用控制功能、会话运行且可靠通道就绪；最终资格由后端裁定。普通 `sendControl` 在所有权未确认或本方不是控制者时明确拒绝，发送时在 envelope 顶层加入当前 `control_revision`，服务端据此丢弃旧控制修订的排队操作。仅用于自身视频重置的 `reset_video` 保留无修订兼容旁路。

所有权操作等待同一通道的 `{version:1,epoch:1,type:'control_result',request_id,ok,error?}`，只完成对应请求；`ok:false` 以业务拒绝呈现，不中断视频。错误文字最多 1024 字符与 4096 UTF-8 字节，禁止 NUL；成功回执不携带错误。最多同时等待 64 项，5 秒未收到回执明确超时，调用方取消或连接关闭撤销等待，迟到回执丢弃。按钮等待真实回执，不把浏览器本地发送排队当作服务器批准。状态与请求回执分别消费，拒绝导致所有权不变时仍能反馈操作失败。

剪贴板分片新增可选 `control_revision`。所有权已知后，只有本方 `has_control` 且分片修订等于最新控制修订才组装；所有权撤销或控制修订变化清空未完整正文，旧修订正文直接丢弃。收齐后快照增加可选 `controlRevision`，页面只在当前控制修订仍有效时写入本机。该路径包含设备原生菜单复制，不要求先登记网页复制请求。控制变化清空待发粘贴、按键和复制队列，不把旧操作发送给接管后的设备会话；仅申请队列刷新不会清理当前输入。

旧服务器没有所有权消息时保留旧剪贴板格式的定点兼容：按钮或 `Ctrl+C/X` 注册有界请求，正文只消费本人请求；模型与媒体页在缺少所有权时保持普通设备输入关闭。scrcpy 原生剪贴板监听不提供远程操作者标识，独占控制期间的设备剪贴板按当前控制者归属，不通过最后点击者或窗口焦点猜测。局域网 HTTP 下浏览器可能拒绝自动写入，届时当前控制者可点击「复制到电脑」或手动选中文字复制。

服务端必须比较当前 epoch，拒绝上一连接残留命令，重连后不回放控制。前端也不因网络失败、恢复媒体或收据丢失重发控制；输入收据失败将入口标为不确定。收据 accepted 只表示后端接受队列，真实控制执行以设备或原生套接字证据判断。EOF 只关闭控制输入，媒体继续；显式 cancel 的 Stopping 响应不证明进程和转发已清理，需等 Finished completion。

### 媒体页键盘控制

开始投屏前启用「开启设备控制」，控制通道就绪后点击画面获取键盘焦点。WebRTC 视频与兼容画布共用页面内键盘适配，经现有顺序控制队列发送 `key` 命令；字母、数字、方向键、空格、回车、退格及修饰键映射为 Android 按键，Esc 对应返回。按住键持续发送有界 repeat，松开键发送 up。

键盘监听只在投屏画面生效，点击文本框或其他位置后恢复浏览器交互。画面失焦、窗口失焦或页面进入后台时释放本地记录的按键；会话或连接代次变化时清空记录，禁止将旧键释放发送到新会话。浏览器保留快捷键和输入法组合事件不拦截，输入法文本继续使用现有「设备输入文本」入口。

## 生命周期与验证

调用显式带 AbortSignal。关闭、选择新会话和取消会及时结束忽略信号的网络等待，消费晚拒绝；旧代结果不能更新快照。sink 也收到同一信号，可信回调应停止副作用。VideoFrame 在回调完成后关闭，旧代输出同样关闭。浏览器 sink 的资源由消费方拥有，dispose 释放解码器、音源与本地订阅；不自动删除服务器会话或关闭共享音频上下文。

`release(signal)` 使用 `POST /api/v2/sessions/{id}/release`，服务端撤销活动会话输入并监督清理，仅在确认清理完成后自动删除记录；HTTP 202 只表示已接受请求。MCP 对应 `deviceforge.release_session`。清理失败或未确认保留记录，不能据此显示释放成功。

前端释放查询最多等待15秒；取消等待不撤销已经发起的释放，重复释放合并为一次提交。确认清理完成或发现记录已不存在后撤销本地选择；记录不存在仅表示无需继续持有该本地身份，不补造清理完成结果。超时保留身份与日志，需重新查询。打开等待被取消或消费实例关闭后，迟到的已接受会话会补发释放请求。

产品投屏页手动释放、离开活动路由和运行实例关闭共用释放流程，停止读取、控制排队、解码器和本页音频上下文。正常关页沿既有 `pagehide` 执行清理，释放请求设置 `keepalive`；浏览器崩溃或断网可能阻止请求送达，不能承诺这些情况下立即释放。

## 公开插件服务

`runtime.mirroringStreaming` 是宿主公开基础用例。浏览器插件通过 SDK 现有版本化扩展服务调用 `context.extensions.callService('host.mirroring.stream', '1', request, signal)`，不导入 features 内部，不接触令牌或服务器路径。

| action | 请求字段 | 返回 |
| --- | --- | --- |
| definitions | 仅 action | 公开会话目录 |
| open | action、input（直播业务输入） | Opening 会话 |
| resume | action、id | 原会话记录，保留同实例游标 |
| output、poll | action、可选 limit | 消费计数与会话状态；poll 持续消费至 Finished |
| packets | action、可选 limit | 本次完成媒体包，视频/音频 bytes 为原字节数字数组 |
| control | action、input（控制业务字段） | 接受收据，epoch 由门面加入 |
| eof、cancel | 仅 action | EOF 收据或停止中的会话 |
| snapshot | 仅 action | 纯 JSON 配置、状态、计数、日志与错误 |

请求 JSON 最大 16KiB，普通响应最大 1MiB，媒体批次 JSON 最大 32MiB。所有动作严格限制字段，不接受 sink、函数、客户端路径或伪造 epoch。输入和输出使用已有 SDK JsonValue/HostResult，不新增与宿主功能耦合的 SDK DTO。服务合并插件调用与宿主生命周期信号，插件卸载后在途等待撤销，旧上下文不能继续调用。

宿主仅可在 `createFrontendRuntime` 构造时通过可选 `mirroringSink` 注入固定媒体消费者，插件不能替换它。默认宿主不创建可见播放器；插件可以选择 packets 动作获取新媒体原字节，再用自己打包的浏览器解码器和组件播放。宿主处理器关闭失败仍会继续清理其他 runtime 资源并汇总错误，不因为一个回收失败留下注册表或订阅。

本轮最终定点证据：`node --test tests/mirroring-streaming-runtime.test.ts tests/mirroring-streaming-consumption.test.ts tests/mirroring-streaming-framing.test.ts tests/mirroring-http-consumption.test.ts tests/mirroring-consumption.test.ts` 33 项通过，包含 HTTP 边界、分帧断点、4MiB 跨页原字节批次、截断/乱序/错误配置、半包网络恢复、旧代取消、控制 epoch、不重放、EOF、PCM/H264 规则、状态兼容及实际插件上下文公开媒体消费；`npx tsc --noEmit` 退出 0，最终装配版架构检查通过 190 源码。生成器、全前端门禁和当前源码分发由主代理集成后记录。真实服务器/native forward 夹具、真实浏览器 H264/音频、scrcpy-server、真机和具体页面需分别取得证据，不能由本定点测试转计。

用户已要求性能测试延后到全部业务开发完成后，本轮只做必要功能检查，不执行负载测试或性能调优验收。
