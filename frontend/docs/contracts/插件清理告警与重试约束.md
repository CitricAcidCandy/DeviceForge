# 插件清理告警与重试约束

生效日期：2026-10-26，Asia/Shanghai。本文将用户 2026-10-23 的要求固化为前端长期约束，不代表实现、部署或验收已全部完成。后端规则见[资源故障隔离与后台回收裁定](../../../backend/docs/implementation/资源故障隔离与后台回收裁定.md)。

## 产品边界

面向个人及可信同事局域网，默认免鉴权，令牌可选，插件按可信代码运行。不为历史清理故障引入来源审批、强制隔离、多用户安全流程或反复人工确认。保留产物完整性、真实设备身份、取消期限和避免误操作的基本正确性检查。

## 状态与入口

| 状态 | 必须呈现 | 不得推导 |
| --- | --- | --- |
| 历史 cleanup_failed/unresolved | 旧调用、代际、错误、实际日志 ID 和已知任务 ID；可查看但不阻断的告警 | 整个插件失效，或用户必须先点恢复 |
| recovering、旧 blocked/busy 报告 | 后台核对状态与具体资源说明 | 普通新任务、设备发现或采集按钮全部不可用 |
| 本次提交结果未知 | 停止自动重放，保留已知归属，允许查询并显式选择重试 | 服务器必然没执行，或永久禁止后续尝试 |
| 真实在途、独占冲突、容量不足 | 具体占用对象、受影响操作与可结束/取消/重查的路径 | 所有设备或无关功能都必须等待 |
| 终态、撤销或旧代结果 | 原终态与历史，拒绝把旧响应写进新实例 | 用新代恢复旧上下文，或用新成功清掉旧错误 |

前台结束会话、停止本地绘制/输入、后台释放旧资源和新调用准入是不同职责。关闭工作台不代表资源已清理，新工作台也不等待全插件历史清理完成。普通任务、服务端插件与浏览器插件、默认启用、市场及所有页面按钮必须一致，不能仅在模型层放开。

## 有界等待与可诊断性

- 加载器、激活、面板/组件/模块挂载、配置回调、停用、资源释放及串行队列，都必须可取消或按固定期限结束宿主等待；清理超时不能让后续新操作无限排队。
- 旧代完成/失败不能恢复已撤销的 DOM、订阅、命令、服务、配置指针或资源入口。宿主不承诺强制停止忽略信号的可信 JavaScript；只收敛自身等待并隔离晚到结果，不能据此声称副作用终止。
- 新操作成功不得被别的旧调用失败改判；旧告警必须有可达的查看路径，不能只存在于无人消费的内部缓存。重复消息可合并，当前任务反馈与历史诊断分开。
- 截图继续保留串行、数量/字节限额、摘要检查及对象 URL 回收；本次失败停自动截图但不永久封死显式重试，纯指标采集不受无关截图失败影响。

## 统一安装记录

以下组件操作失败可以正常重试：`component_cleanup`、`activation_cleanup`、`enable_cleanup`、`activation_reload`、`startup_activation`、`unload_rollback`、`configuration_rollback`、`disable_rollback`。客户端保留真实 status、failure.phase/reason，并使用公开恢复规则，不在卡片、详情与用例中复制不一致的判断。

`activation_rollback`、`commit_rollback`、`transaction_*` 及未知/缺失原因涉及文件状态待核对，不能当成纯历史组件告警一律忽略；限制也只落在对应发布/文件变更，不应冻结其他插件。后端领域、应用和文件存储须使用同一规则。

## 必须验证

- [ ] A 清理失败后 B 独立操作实际执行成功；A 历史仍能查看。
- [ ] A 的晚到失败不污染 B 的运行、排队、成功或新代；B 成功不清除 A 的错误。
- [ ] 加载、激活、挂载与清理的永不返回回调分别测试；取消/超时后独立新调用能完成，不只检查 Promise 被拒绝。
- [ ] 默认启用、市场卡片/详情、实际页面按钮与用例都不因旧告警或 recovering 禁用；真实资源冲突仍有明确反馈。
- [ ] 提交未知不自动重放；显式重试保留真实日志和任务归属。
- [ ] 纯组件告警可重试，真实文件事务未恢复仍限制对应变更，前后端口径一致。
- [ ] 生产浏览器与当前运行宿主取得新证据；源码测试、构建、设备和视觉结论分别记录。
