# 性能采集前端读取修复

日期：2026-10-23，Asia/Shanghai。

## 现场与根因

- 用户反馈 SM_G991U 在「性能与调用栈」开始采集后页面没有数据。
- 当前宿主设备目录确认该机引用为 `192.168.208.237:8100`，没有把其他在线设备或历史模拟器结果作为本机证据。
- 只读查询已存在的会话 `68ae2650-37f5-4ce1-92e9-0e182126a5a5`，目标包为 `com.ChillyRoom.DungeonShooter`，时长 10 秒，状态 completed，实际保存 3 点。CPU、PSS、RSS 有实际观测，首点 CPU 尚无差分基线，三点 FPS 均缺测。
- 原页面的创建回调从旧快照取 ID，但 `performance.start()` 只返回创建结果、不改变选择，因此无法接入新会话；页面同时缺少后续样本读取循环。

## 修复职责

| 文件 | 职责 | 不负责 |
| --- | --- | --- |
| `src/pages/performance/index.tsx` | 显式传递创建返回的 ID，分开创建与读取错误；同 ID 重读保留已有样本 | 不运行平台工具，不改变采集契约 |
| `src/pages/performance/hooks/usePerformancePolling.ts` | 对选中会话串行增量读取，每页最多 100 点；空首轮继续读取，终态补齐尾页；切换和卸载取消 | 不创建、恢复或停止服务器采集，不进行设备操作 |
| `tests/performance-page-lifecycle.test.ts` | 用真实页面、真实性能模型和模拟 HTTP 验证接线与取消 | 不证明 Canvas 绘制、视觉质量或真实设备实时更新 |

错误读取按 2、4、8、10 秒退避，上限 10 秒；沿用模型中的错误与真实日志 ID。控制结果需要显式核对时，不用自动读取绕过 `needsReconcile`。

创建成功后立即退出创建弹窗并保存该 ID，后续读取错误在页面消费，避免把读取失败当成创建失败再次启动采集。同一会话再次读取使用 inspect，不清空已读样本，也不依赖已经停止的轮询重启。
