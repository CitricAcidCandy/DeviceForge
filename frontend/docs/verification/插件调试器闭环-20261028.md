# 插件调试器受控本机闭环（2026-10-28）

本记录由测试助理维护。当前状态为驱动和专项单元测试已就绪，真实 Rust 宿主与 Edge 闭环等待主代理明确冻结本轮新增模块的同一底座。没有把旧冻结宿主、构建成功或模拟传输计为真实联调通过。

## 独占写集与入口

- `scripts/debugger-browser.ts`：冻结核对、原 HTTP 安装、HTTP/MCP 同状态查询、独占宿主与 Edge 编排、截图路径及进程端口回收记录。
- `scripts/debugger-browser-harness.ts`：公开宿主工厂装配、显式启动桥、可复现功能断言、官方面板明确选择、卸载与销毁。
- `scripts/debugger-fixture.ts`、`scripts/debugger-fixture-contract.ts`：独立包生成、冻结输入校验和有界 JSON／回执解码。
- `scripts/debugger-fixture-provider.ts`、`scripts/debugger-fixture-consumer.ts`：只消费公开 SDK 类型的独立插件。转译后擦除 SDK 源码路径，不包含宿主私有导入。
- `tests/debugger-acceptance.test.ts`：驱动直接相关的单元测试。

不修改实现、生成类型、Vite 配置、公共根文档或投屏插件。根 `todo.md` 由主代理汇总本记录。

## 最小联调依赖

1. 主代理构建并冻结包含本轮后端调试工具、持久日志和报告端口的宿主可执行文件。测试助理不运行 Cargo，不启动第二份同命令宿主。
2. 主代理在前端构建入口登记 `scripts/debugger-browser-harness.ts`，输出名为 `debugger-browser-harness`，产物为 `assets/debugger-browser-harness.js`。需一并提供其全部依赖块、样式和公共 React 入口；不使用旧宿主或旧验收包替代。
3. 主代理运行官方插件构建器，提供 `examples/browser-debugger` 的 `package.json`、`plugin.json`、`dist/index.js` 及入口实际引用的产物。测试驱动只打包这些冻结文件，不实现替代面板、不安装依赖、不发市场发布。
4. 官方 `focus` 仅带入候选；面板保留目标卡片中的插件 ID、实例和“选择并检查此插件”按钮。验收会在候选带入后先断言零会话，再显式点击当前实例目标。卸载需通过有效清理信号关闭本插件创建的会话；若继续使用已经撤销的挂载信号，关闭请求可能无法派发。
5. 本机 Node 22.18 以上及现有 Edge。沿用 `scripts/plugin-defaults-browser/browser.ts`，无需浏览器 MCP。所有服务绑定 `127.0.0.1` 自动分配独占端口；保护 7031、5173、5186。

独立工厂显式调用 `host.debugger` 的 `start`；不会假定工厂自动启动桥。装配 `installPublicUi` 与既有共享 React import map，官方插件使用宿主实例。受控宿主从空服务器／浏览器部署目录启动，并核对设备及提供者目录为空。

2026-10-28 10:35 源码观测：HTTP 调试入口仍调用默认端口适配；持久报告需要同一 HTTP/MCP 用例接入日志和产物存储。此为冻结前依赖，驱动不会绕过公开服务伪造产物。并行实现可能继续变化，最终以冻结字节与真实结果为准。
