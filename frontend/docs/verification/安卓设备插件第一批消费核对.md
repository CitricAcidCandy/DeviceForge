# 安卓设备插件第一批消费核对

日期：2026-10-10。本文只核对冻结 `android-device` 与现有前端消费接口，不修改生产实现或公开契约。本角色没有执行项目命令、构建、测试、服务或真实设备调用；运行结论由主代理另记。

依据：[后端实施裁定](../../../backend/docs/implementation/安卓设备插件第一批实施裁定.md)、[插件说明](../../../backend/plugins/android-device/README.md)、[实际清单](../../../backend/plugins/android-device/manifest.json)与[aliases](../../../backend/plugins/android-device/aliases.example.json)。前端相关边界沿用[旧操作绑定迁出接入](../implementation/旧操作绑定迁出接入.md)、[统一发现发布回执消费边界](../contracts/统一发现发布回执消费边界.md)及[设备提供者第一阶段实施](../implementation/设备提供者第一阶段实施.md)。

静态结论：八贡献、七能力、API3 原始状态与预算均可沿现有四条设备 HTTP 端口、公开 `HostContext.devices` 和通用任务入口消费；没有发现必须增加宿主私有导入、浏览器工具路径或按 `platform === 'android'` 分支的接口缺口。APK/APKS 安装、截图、性能、常驻会话与真机不属于本批七能力，不能补造目录入口。

## 八贡献、七能力与显式旧绑定

三个版本分别是浏览器 SDK `context.apiVersion === 2`、提供者声明 `provider.definition.apiVersion === 3`、服务器插件 `protocol_version === 4`，不能把 API3 写成浏览器 SDK3。插件收到的真实 Request.operation 是短名；宿主对外贡献 ID 为 `plugin.android-device.<短名>`，只映射一次。前端读取目录返回的贡献与能力，不自行拼接协议请求。

| 短贡献 | 能力版本／范围／访问 | 声明总预算 | 标准业务 input | 显式部署后才可能存在的旧 alias |
| --- | --- | --- | --- | --- |
| discover | 独立发现，不是能力 | 发现固定 30000ms | `{}` | android.devices |
| connect | connect@1／provider／write | 30000ms | `{address}` | android.connect |
| disconnect | disconnect@1／provider／write | 30000ms | `{address}` | android.disconnect |
| packages | packages@1／device／read | 30000ms | `{}` | android.packages |
| app.start | app.start@1／device／write | 30000ms | `{package}` | android.app.start |
| app.stop | app.stop@1／device／write | 30000ms | `{package}` | android.app.stop |
| app.uninstall | app.uninstall@1／device／write | 120000ms | `{package}` | android.app.uninstall |
| input | input@1／device／write | 30000ms | `{action}` | android.input |

七项 `definition.capabilities[*].operation` 映射到当前完整贡献，预算从 `execution_timeout_ms` 显式映射为可选 `executionTimeoutMs`。本批清单没有普通 `execution` 声明；普通操作总预算与设备预算不能互相补写，浏览器不能用 input 或请求选项覆盖期限。

aliases 格式2中，android.devices 的 target 为 device_discovery，input 为 identity，result 为 device_discovery/platform=android；七动作 target 为 device_capability，精确 capability/version=1，input 为 device_envelope，result 为 value/wrapped=true。provider 旧业务输入只含 address；device 旧业务输入为 device_id 加对应业务字段。alias 必须显式部署并且实际出现在 `context.listOperations(signal)` 的当前目录；不因示例文件存在就认为已经加载。目标卸载后不回退内置实现。

新插件优先通过 `devices.invoke` 发起能力；旧消费者若确需 alias，只能按当前操作目录的真实 ID 与 input_schema 通过 `context.submit` 提交。直接完整贡献的 input_schema 要求标准设备封套；旧 alias 的业务输入与封套不是同一个形状。前端不自行重做 alias 映射，不从旧 serial 自动绑定任意新提供者代次。

## 现有公开消费链路

| 公开 SDK | 现有 HTTP | 明确职责 |
| --- | --- | --- |
| refreshProviders(signal) | GET /api/v2/device-providers | 当前提供者、generation 与能力定义 |
| refreshDirectories(signal) | GET /api/v2/devices；前端先重新读取 providers | 读取已发布目录，不替代执行发现 |
| refreshProvider(id,generation,signal) | POST /api/v2/device-providers/{id}/refresh，body 为 `{generation}` | 发起统一发现，消费本次 attempt 回执 |
| invoke(action,signal) | POST /api/v2/device-actions | 精确提供者代次、能力与业务对象，返回原 Job |
| select／snapshot／subscribe | 本地公开状态 | 完整 DeviceRef、选择、目录通知；不创建服务推送 |

HTTP snake_case 由 [device-gateway.ts](../../src/app/device-gateway.ts) 索引生成 DTO 并映射，公开模型见 [devices.ts](../../src/plugin-sdk/devices.ts)。标准 SDK 动作为 `{providerId,generation,deviceId,capability,version,input}`，对应 HTTP `{provider_id,generation,device_id,capability,version,input}`。宿主据声明定位短贡献，将业务传入插件的严格封套 `{device_id,input}`；provider 必须显式 `device_id:null`，device 必须是目录引用的原文 localId。插件每层拒绝未知字段。调用方只提供一次业务 input，不在 input 里再次嵌套 device_id/input。

动作定义、scope 与 access 由提供者声明决定。平台名称只用于说明或筛选，不能决定路由、自由 shell 命令或工具参数。插件从 activate/mount 收到的公开 context 调用；不导入 app/features/shared 私有模块，不读令牌、部署配置或本机路径。

## 公开调用示例

下面辅助函数只接收插件的公开 context、当前目录中明确选定的提供者/引用和 caller signal。`providerId` 来自宿主目录选择，不在通用代码中硬编码 Android 分支。旧 API2 可以没有 devices，此时明确报告能力未提供。

```js
function deviceAccess(context) {
  if (!context.devices) throw new Error('宿主未提供设备扩展');
  return context.devices;
}

export async function discoverDevices(context, providerId, caller) {
  const devices = deviceAccess(context);
  const signal = AbortSignal.any([context.signal, caller]);
  const providers = await devices.refreshProviders(signal);
  const provider = providers.data.find((entry) => entry.id === providerId);
  if (!provider) throw new Error('当前目录中没有选定的提供者');
  const discovery = await devices.refreshProvider(provider.id, provider.generation, signal);
  return { providers, discovery };
}

export async function connectProvider(context, provider, address, caller) {
  const devices = deviceAccess(context);
  const capability = provider.definition.capabilities.find((entry) =>
    entry.id === 'connect' && entry.version === 1 && entry.scope === 'provider');
  if (!capability) throw new Error('选定提供者没有声明 connect@1');
  return devices.invoke({
    providerId: provider.id, generation: provider.generation, deviceId: null,
    capability: capability.id, version: capability.version, input: { address },
  }, AbortSignal.any([context.signal, caller]));
}

export async function listPackages(context, reference, caller) {
  const devices = deviceAccess(context);
  const signal = AbortSignal.any([context.signal, caller]);
  devices.select(reference);
  return devices.invoke({
    providerId: reference.providerId, generation: reference.generation,
    deviceId: reference.localId, capability: 'packages', version: 1, input: {},
  }, signal);
}
```

`discoverDevices` 返回两个实际 HostResult，不用一个请求的日志替代另一个请求；目录使用 discovery.data，保留 observedAt 与 discoveryJobId。设备引用取其 devices[*].reference，完整保留 providerId/generation/localId；不把 localId trim、转 ASCII 或重新拼接。选中设备不保证动作可用，最终还由 `invoke` 校验当前代目录、online 与 availability。

其他能力沿同一 `invoke` 对象，只改变精确 capability 与业务 input：disconnect 使用 `{address}`；app.start/app.stop/app.uninstall 使用 `{package}`；input 使用例如 `{action:{kind:'tap',x:100,y:200}}`。坐标为整数 0..32767；swipe 还需 x1/y1/x2/y2 和 1..10000 的 duration_ms；keyevent 使用 1..65535 的 key_code 与可选 long_press；text 仅接受 1..1024 个可打印 ASCII 字符及可选 enter。示例不是自由命令入口；input 的具体结构以当前声明的 input_schema 与插件校验为准。

address 为 ASCII host:port，可用 IPv4/DNS 或方括号 IPv6，端口1..65535；不要把 address 当成工具配置或服务器 endpoint 覆盖。start/stop/uninstall 的 package 为最多200字节的点分 ASCII 包名；start/stop 相比旧宽泛 identifier 收紧，旧输入需按当前 schema 修正，不能由前端偷偷归一成另一包名。

`invoke` 返回 HostResult<Job>；HTTP 成功、拿到 Job 或拿到任务 ID都不表示设备业务成功。保留原 Job status/result/error；若尚未终态，调用方之后显式使用 `context.getJob(id,signal)`，本文不新增轮询。终态成功后需要更新设备观测时，再显式调用 `discoverDevices`；connect/disconnect 本身不承诺立即改写目录或自动重绑选择。存在可选 taskHistory 时，历史查询继续使用其持久化记录，不从新目录补 provider、预算或 rawState。

非 input 动作的插件业务值为 `{output}`，packages 保留合法 `package:com.failed.example` 等输出，不按 failed/error 任意子串宣布失败。input 业务值为 `{device_id,action,dispatched:true}`，只表示命令完成，不证明设备界面已变化。Job.result 仍保留当前协议的公开 result/artifacts 包装，不把插件业务值当作整个 Job，更不把发现 Job 成功当成 GET 目录接受。

## 宽 serial、rawState 与能力准入

插件 serial 与宿主 local_id 资格一致：原文非全空白、最多200个 UTF-8 字节、没有 Unicode 控制字符且不以连字符开头。发现从 ADB 分列 token 读取，动作保留传入原文；前端不能再加 ASCII identifier 正则，也不能用 JavaScript 字符数代替 UTF-8 字节限制。现有 [device-validation.ts](../../src/services/api/device-validation.ts) 不把 local_id 收紧为 ASCII，[设备规则](../../src/features/devices/utils/rules.ts)按完整引用匹配，HTTP 映射保留原文。

| 插件原始状态 | 规范 state | 五项 device 能力 |
| --- | --- | --- |
| device | online | available=true |
| offline | offline | available=false，保留 reason |
| unauthorized | unauthorized | available=false，保留 reason |
| recovery／sideload／bootloader／其它合法原文 | unknown | available=false，原文仍保留 |

七能力中的 connect/disconnect 是 provider 能力，不要求选择某台设备，也不放入每台设备的 availability。不能因为 rawState 为某个熟悉的特殊状态就越过 state/available/version 允许 device 动作；未来特殊能力必须由提供者公开声明。

raw_state 在 HTTP 映射为可选 rawState，只用于说明与透传。API3 接受非全空白、无 Unicode 控制字符、最多100个 UTF-8 字节的原文，前端校验但不 trim，拒绝无法成为 Rust UTF-8 String 的孤立代理项；API1/2 的 None/缺省与 API3 的 None 均省略 SDK 字段。后续目录是整份替换，None 不能沿用旧 rawState。坏 serial/raw/model、重复标识或超过128设备使整次发现失败，前端不发布部分设备列表；model 只作可选说明，不作为执行资格。

## 精确错误与日志归属

区分请求发出前的本地资格、实际 HTTP 错误、已经返回的 Job 终态。不要统一包装为“连接失败／超时”，也不要将 Job.error 字符串臆造为带 code 的新 DTO。

| 所在层与触发 | 当前公开行为 | 消费要求 |
| --- | --- | --- |
| 本地动作形状或 provider/device scope 不符 | HostError protocol／invalid_input，status=400，logId=null | 修正精确输入；没有服务器日志 |
| 本地找不到提供者、能力版本或当前目录中的设备 | protocol／not_found，status=404，logId=null | 显式刷新目录，不补入口或能力 |
| 本地旧 generation、没有本代观测、非online、能力不可用 | protocol／conflict，status=409，logId=null | 撤销当前动作资格；不自动替换 generation |
| 实际 HTTP Invalid／NotFound／Conflict | http／invalid_input(400)、not_found(404)、conflict(409) | 保留实际 code/status/logId，与本地 protocol 区分 |
| 实际 HTTP Cancelled／Timeout／Dependency | http／cancelled(409)、timeout(504)、dependency_failed(502) | 沿服务器真实分类；不靠等待时长或错误文字重分类 |
| 实际 HTTP CleanupFailed／TooLarge | http／cleanup_failed(409)、payload_too_large(413) | 保留清理资格与限额；不假装成功或立刻重用旧引用 |
| 提供者发现响应关联错误或 HTTP 形状错误 | protocol／invalid_device_directory，或共享 client 的 invalid_response | 保留该次真实 logId；不部分接受坏目录 |
| caller、宿主、插件或挂载撤销与晚结果 | cancelled 类；可为 cancelled、plugin_unloaded、stale_result、stale_device_result | 只撤销消费资格；交付前已有响应时保留已取得 logId，预关闭零调用时不造日志 |
| 成功 HTTP 返回失败 Job | 原 Job.status/error/result；不一定抛 HostError | 检查任务终态，保留原 error，不补造结构化 error.code |

HTTP 分类依据现有通用 [server 错误映射](../../../backend/crates/server/src/lib.rs)，本地资格依据 [devices/rules.ts](../../src/features/devices/utils/rules.ts)。清理未确认也可能被准入规则以 conflict 拒绝；前端保留实际收到的分类，不把所有409改写为 cleanup_failed。具体插件失败可能作为失败 Job 留在历史，表中的 HTTP 状态只适用于错误确实沿该 Error→ApiError 路径返回时。

connect 的工具短点最多5000ms，总能力期限30000ms。短点先到而总期限未到，冻结裁定接受已有字符串失败路径的 `dependency_failed`；浏览器不得按“约5秒”或插件文字把它升级为宿主 Timeout/HTTP504。只有公开实际响应为 timeout 或任务本身明确总期限失败时沿真实结果处理。能力预算只是元数据，客户端不能自行选择短点或总期限。

不展示或索取服务令牌、工具路径、插件日志文件路径。失败排查使用本次 HostResult/HostError 的 logId；任务 ID、discoveryJobId、浏览器代次标记都不代替日志 ID。input 中的文本和底层诊断不会被前端当成插件错误原文回显。

## 目录撤销、旧代和显式 refresh

现有 [devices/index.ts](../../src/features/devices/index.ts)、[state.ts](../../src/features/devices/models/state.ts)与[作用域代理](../../src/plugins/device-access.ts)已经提供下列通用行为，无需在 Android 消费层另写平台分支：

1. refreshProviders 读取当前代次；同 providerId 换 generation 会移除旧目录/选择并撤销旧代在途发现与动作。DeviceRef 的三字段是整体身份，同 localId 不会合并不同提供者，旧引用不自动重绑新代。
2. 主动 refreshProvider 开始先清本代本地观测和选择，防止把旧缓存继续视为有效设备；后端排队阶段不因此清服务端目录，真正执行前才清本代观测。两者职责不能混写。
3. 同提供者发现 A 被 B 替代或本地目录 revision 改变后，A 的晚回执不得覆盖 B；失败/取消的旧 A 也不能清除 B 的成功目录。显式 refresh 消费自己 attempt 的回执，不再 GET 猜哪次发现属于自己。
4. refreshDirectories 读取服务端已经发布的聚合目录。它与 refreshProviders 都不是 ADB 重发现；只有显式 refreshProvider、目录真实 discovery contribution 或已部署的发现 alias 才触发统一发现任务。Job 成功观测可能没有成为 GET 当前目录，不从成功历史补缓存。
5. 本浏览器 app 的服务器管理收敛由 [catalog-refresh.ts](../../src/app/catalog-refresh.ts)装配：撤销操作目录和目标提供者缓存后重查。插件 SDK没有服务器安装/管理端口；插件只消费公开设备与任务，管理部署由宿主 app 的 pluginPackages/serverPlugins 完成。
6. 同事另一实例发生卸载/重载，当前前端不靠后台推送立即获知；下一次显式 refreshProviders/refreshDirectories 及服务端准入会给出真实状态。若旧缓存尚在，服务器仍可用 conflict/not_found 拒绝旧代；不把本地尚未同步解释成服务许可。
7. 插件卸载、挂载退出或 runtime.dispose 撤销对应作用域。devices 的四个异步入口合并 caller 与生命周期，select/snapshot/subscribe 也检查关闭资格；订阅由作用域登记释放，退出一个挂载不关闭兄弟。调用必须使用当前 mount 的 context，不借旧 activate 引用绕过子作用域退出。

查询等待 Abort 不等于取消已经受理的设备 Job，也不保证服务器管理或设备效果回滚；确需取消任务时使用已公开 `context.cancelJob(id,signal)` 并再显式查询状态。历史可选 taskHistory 不依赖当前贡献或提供者加载，不补当前预算/rawState/generation。共享部署资源的所有权沿后端裁定处理，前端不新增共享 daemon 控制、退出按钮或私有清理接口；具体产品 UI 仍等待设计稿。

## 可沿用的验收与未验证范围

后续主代理可按现有通用设备/在线包浏览器链路核对：当前目录缺插件时不补入口；八贡献和七能力精确版本；provider null/device 原文封套；同名 localId 跨提供者区分；未知 rawState 保留但五项 device 能力不可用；None 替换；旧代409与本地无日志区分；发现 A/B/失败撤销；管理后目录失效；子作用域/整代退出；服务器卸载后历史独立。宽 serial、raw 字节与控制字符、严格业务 schema 和短限额 dependency_failed 可由独立假工具/服务用例覆盖，但不能计为真实 ADB或真机。

本文没有创建这些测试，也没有运行既有测试或浏览器。只有静态接口消费核对和文档示例，不能宣称 Android迁出本批验收、共享部署资源清理、APK/APKS安装、截图、性能、常驻会话、产品界面或真实设备已经完成。源文件、生成DTO、生产dist和已冻结根驱动全部保持原写权；本文唯一职责是供前端插件按当前公开契约接入与排查。
