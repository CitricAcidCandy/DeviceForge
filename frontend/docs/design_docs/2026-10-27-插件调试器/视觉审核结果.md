## 问题清单：按严重度与影响排序

本次未发现足以判定 P0/P1 的明确静态视觉证据。以下均为 P2，即应在视觉收口前修正的中等问题；不把未画出的动态行为直接判为实现故障。

### V-01 / P2：小字号弱文字与警告色的对比度余量不足

- 图片与区域：01 的筛选占位文字、只读快照说明和底栏；02 的第三个目标及选择说明；03 的筛选条、失败详情说明和底栏；04 的最后观测卡和重连说明；05 的筛选框、只读说明及底栏；06 的底部入口说明。01、03、04、05 的能力或异常提示也需一并核对。
- 静态复现：先读深色标题，再读上述浅底上的小字号灰字及橙字。字形本身没有缺笔或重叠，但对比明显偏弱，940 窄窗没有额外的可读性余量。
- 规格佐证：按《设计规格与交付.md》声明的颜色计算，`#979FB1` 对白底约为 2.65:1，对 `#F7F8FC` 约为 2.50:1；`#6C7688` 对 `#F7F8FC` 约为 4.32:1；警告字 `#B4690E` 对 `#FDF6ED` 约为 3.94:1。对稿中 12–14 字号的有效信息，建议按普通文本至少 4.5:1 处理。此处是规格令牌的理论计算，不是 PNG 逐像素取色，也不是完整无障碍认证。
- 影响：最后观测时间、历史失败原因和只读边界不应退化为近似禁用文字；低对比同时放大了小字号密度的负担。
- 修法：保留白卡、发丝线和主色，不另起视觉体系；将需要阅读的辅助信息提升为更深的文字令牌，警告文字加深至目标对比度。弱色仅留给不承担关键信息的装饰或真正禁用态；重要状态说明尽量采用 13–14 字号。不要仅靠加粗或换色相解决对比度不足。

### V-02 / P2：断线态只见旧快照摘要，没有完整旧快照的查看入口

- 图片与区域：04，内容区约 `x=384–1384，y=316–672`；与 01 的树及节点详情对照。
- 静态复现：从 01 的 DeviceList 树和节点属性切到 04 的断线画面。原树及详情被断线说明整块替换；白色卡片只保留时间、代次、挂载状态和节点数量。画面可见“重新连接”“查看历史日志”，未见“查看最后快照”或返回旧树的入口。
- 影响：规格要求保留带过期标签的最后快照供排查，但当前画面只证明摘要可见，不能继续检查旧节点 ID、能力与属性。用户容易把重连当作继续检查快照的前置条件。
- 修法：保留现有断线警告，在其下提供“查看最后快照（只读 / 已过期）”展开区，或允许切回带整区过期标识的旧树与详情。最后观测时间和代次必须跟随快照显示，保持刷新不可用、其他目标可选；不要添加编辑、插入或自动重放入口。
- 证据限度：只能确认稿面未呈现完整快照及其入口，不能据此断言运行时已丢失缓存或日志。

### V-03 / P2：时间线筛选条看起来像说明文字，不像独立控件

- 图片与区域：03，约 `x=384–1384，y=316–358` 的筛选条，尤其是左侧“级别：全部”“包含旧代：开启”“搜索日志 ID 或事件”。
- 静态复现：在不读取规格的情况下查找级别下拉、旧代开关与搜索输入。三者目前以同色小字和分隔点串排；未见明确的下拉指示、开关形态或搜索输入边界，与右侧紫色“继续跟随”的操作外观不一致。
- 影响：能读懂当前取值，却难以判断哪些文字可以点击、从哪里输入，以及“包含旧代”如何关闭；高密度排查面板会因此增加试点成本。
- 修法：保留同一行组织，将级别画成紧凑下拉，将包含旧代画成有文字状态的开关或切换按钮，将搜索画成有可辨识边界的输入框。将“已暂停跟随”状态靠近“继续跟随”入口，避免只依赖远处底栏。控件间距按既有 4 像素基准处理，不靠继续缩小字号塞入。
- 证据限度：这是静态可发现性问题，没有点击控件，不判断其实际是否响应。

### V-04 / P2：缩放入口与右下角缩放区的视觉对应不明确

- 图片与区域：01–04 底栏右侧的“缩放”，约 `x=1318–1344，y=700–715`；05 的“缩放”，约 `x=800–824，y=660–676`。桌面面板右下角为约 `(1400,728)`，窄窗为约 `(924,688)`。
- 静态复现：对照规格“右下角为缩放区域”寻找拖拽抓手。实际只见内缩的文字，未见角部抓手或其他方向提示；05 的文字距真正右边缘更远，且比桌面呈现更强的紫色操作外观。
- 影响：用户不容易判断应拖文字、拖角落，还是点击打开尺寸设置；桌面与窄窗对同一能力的表达不一致。
- 修法：在实际右下角画出明确、统一的缩放抓手，预留不与刷新操作冲突的命中区；若“缩放”本身是点击按钮，需给出按钮态及点击后状态，不能同时让人猜测拖拽语义。补充键盘调整入口或其设计状态，但不要将尚未验证的键盘行为写成已完成。
- 相关正向结论：01–05 的“收起”和“关闭”均在标题栏可见，没有被身份栏、内容区或视口边缘遮挡；本问题不等于关闭入口缺失。

### V-05 / P2：仍可看日志的目标被画成近似禁用项

- 图片与区域：02，目标列表第三项“第三方主题”，约 `x=394–734，y=566–618`。
- 静态复现：对比第二项“Android 设备服务”的深色名称和说明，再看第三项的整项灰字。第三项同时写着“仅可查看公开日志”，但没有“仅日志”的正常可用徽标、明确动作或清晰的可选容器。
- 影响：不提供树不等于不可调试；当前弱化外观容易让用户误以为该目标不可选择，从而错过公开日志。此处也不能依赖悬停后才解释可用性。
- 修法：名称维持正常可读的主文字，辅以“仅日志”“未提供 UI 树”能力说明；选择后明确进入时间线或提供“查看公开日志”。灰色禁用样式仅用于真正不可选且有原因的项。若目标没有提供代次等身份字段，明确标为未提供，不挪用当前选中目标的身份。
- 证据限度：未展示第三项目标选中态，不能判断真实选择行为，也没有证据说明它确实被程序禁用。
