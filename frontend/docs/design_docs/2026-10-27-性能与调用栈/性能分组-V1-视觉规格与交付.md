# 性能与调用栈 · V1 数据分组

日期：2026-10-27。状态：历史稿，用户认为三个指标仍在一起，未接受本方案。当前修订为 [V2独立面板](性能分组-V2-视觉规格与交付.md)，V1不作为实施依据。延续本轮用户指定的 Penpot 与 Product Design 流程，不使用生图模型，不修改产品代码、服务或设备。

## 目标与现状

用户反馈“每个类型数据都放在一起分不清”。所附 2021×1229 截图显示画面、时间轴、帧率、CPU、内存与调用栈共用白底大容器，轨道间仅留少量空隙；名称与右侧当前值相距很远，画面关闭和无栈样本也占完整轨道高度。

现有 `SampleBoard` 已按真实时间戳关联采样点，本轮设计保留此契约与原有业务能力。调用栈只能展示所选采样点归属的数据；设备画面按既有近邻关联语义呈现，不宣称逐帧精确关联。图中读数与调用链仅用于设计，不能作为运行性能、真机采集或符号化能力证据。

## 设计决定

1. 每种指标使用自己的标题带与绘图区。标题集中显示名称、当前值、单位、统计或缺测状态，图中网格仅属于该组。
2. 一条共享时间轴对应所有组。选中采样点后，帧率、CPU、内存及调用栈同步选择；指标标题带保留分隔，不以颜色独自承担分类识别。
3. 帧率使用既有紫色，CPU 沿用蓝色，内存以绿色区分；内存把 PSS、RSS 放在同组，RSS 缺测明确显示“未采集”，不画为零、不补线。
4. 画面关闭时仅占 34px 一行。开启或已有归档画面时才展开原画面内容；该展开态未在本次两图中逐像素设计。
5. 调用栈位于独立章节，空态仅占 74px；有栈样本时展开火焰图与选中帧详情。火焰条宽严格按样本权重，避免示例比例误导。
6. 支持按组折叠，让长会话和后续新增指标继续纵向扩展。归档示例中折叠指标，把空间让给调用栈；不新增业务 API 或采集能力。

## 实施与验证边界

本次只交付设计，不修改 `src/pages/performance` 或采集业务。用户确认本稿后再按同一分组结构实施；届时只执行直接相关的单元测试，不自动运行全量、生产构建或浏览器验收。

当前尚未实施组折叠、标题带、跨组选择提示或紧凑空态。两图的视觉通过不证明点击、键盘、采集或查询通过；画面展开、窄屏、采集中、失败状态与长名称仅列实施约束，不冒认为已有逐像素稿或验证结果。归档调用链名称与权重为明确标注的设计样例。
