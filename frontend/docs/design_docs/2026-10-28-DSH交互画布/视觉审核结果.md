# DSH 左对话右画布：独立视觉审核结果

审核日期：2026-10-28（Asia/Shanghai）。角色：独立视觉审核。

**两张图均有问题，本轮静态视觉审核不通过。** 左对话、右画布的分屏方向成立，失败态也没有用全屏遮罩覆盖左侧；主要问题是实际预览中的配色、文字与主按钮呈现，以及调宽抓手不可辨认。不能依据设计说明中的颜色值、节点数量或几何检查判定图片通过。

## 全部发现

以下坐标为所见 1424 × 805 预览中的近似位置，用于定位，不是节点结构验收。P1 表示影响本稿视觉通过，P2 表示应一并修正的清晰度或交接问题。

### 1. P1：两图大面积深绿色底，偏离说明中的白卡与浅灰层次

- 状态与区域：两图全局，包括顶栏、左右卡片、输入框、原生嵌入区及失败反馈卡。
- 图片证据：两张实际预览均呈近乎统一的深绿色底和白色轮廓，没有呈现说明中的浅灰窗口、白色卡片与浅暖错误底色。深色正文、灰色辅助文字、紫色与棕色状态文字在该底色上都较难阅读。正常态同步信息、示例声明，失败态同步待确认及错误解释尤其受影响。
- 影响：主要信息虽能定位，但不能认定中文和状态已清楚可读；同色嵌套区域也削弱了宿主容器、原生边界和示例文档的层级。
- 修改建议：先使实际可编辑设计及其预览正确呈现既定白卡、浅灰和错误浅暖底色，再核对正文、辅助文字和状态标签。不得只以说明或节点中已经写入颜色作为修复证据。
- 判断边界：这里记录的是 `view_image` 所见预览，不推断颜色、透明度、截图或导出异常的具体原因，也不推断真实 DSH 的配色。未量测对比度，不作完整无障碍合规结论。

### 2. P1：发送与重试缺少清楚的按钮形态

- 状态与区域：两图左侧输入框右下方“发送”（约 x447 / y711）；失败图反馈卡下部“重试加载”（约 x771 / y519）。
- 图片证据：“发送”和“重试加载”主要表现为白色文字，没有可辨认的紫色实心按钮底及明确控制边界；相邻“在浏览器打开”则有可辨认的轮廓按钮边界。
- 影响：输入区域没有被错误遮挡，但主要动作看起来更像孤立文字。无法据此确认“左侧仍可发送”及“右侧可独立重试”具有足够清楚的视觉可用性，不能仅因文字存在就判通过。
- 修改建议：恢复两处主要按钮的可见底色、完整点击区域及文字对比，使其与输入提示、错误解释和辅助文字明确区分。这里要求的是设计可辨识性，不宣称实际点击已经验证。

### 3. P2：调宽分隔条及抓手在两图中不可辨认

- 状态与区域：两图左右卡片之间，约 x536–552 / y68–789。
- 图片证据：可见两张卡片间的空隙，但看不到清楚的调宽轨道或居中的抓手。左侧说明提到拖动分隔条，并不能代替控件自身可发现。
- 影响：静态左右分屏清楚，但用户难以从图中发现右栏可以调宽。
- 修改建议：在现有 16 像素分隔区内使轨道、抓手与底色形成适度对比，不增加另一套布局或编辑模式。实际拖动、键盘调宽及最小宽度仍留待运行验证。

### 4. P2：说明中的公共接口待确认项已过时

- 文档位置：`设计说明.md` 的“验证与未确认项”仍把“DSH 公共分屏扩展接口”列为尚未确认。
- 依据：用户本次明确说明主代理已确认实际 DSH 0.2.1-rc.2 右栏公共接口存在。
- 修改建议：由主代理在其所有权内更新该条，区分“接口存在已确认”与“实际 Ardot 嵌入及交互尚未验收”，不重复发起接口调查。本审核不代改原说明。

## 证据与未验证边界

- 这是一轮两张既有静态设计预览的图片审核，不是运行中产品流程审核；问题仅来自本次所见图片和明确列出的文档差异。
- 左侧实际输入、发送，右侧实际加载、重试、浏览器打开、关闭与恢复、拖动调宽、焦点和键盘行为均未执行，不能写成通过。左右分区及文案只能说明设计意图。
- MCP 已连接、已同步、设备数和选中状态均为画面示例。真实连接、同步事件、保存、持久化和故障隔离没有在本轮得到运行证据。
- DSH 公共右栏接口存在不等于 Ardot 已成功嵌入。没有核验原生编辑器真实工具布局、嵌入约束或可编辑交互；也没有据静态 PNG 核验远端节点可编辑性及本地源文件往返一致性。
- 仅覆盖所给 1424 × 805 两态。窄屏、长文件名、缩放、焦点、可访问名称和实际对比度未验证，不据此扩大为产品缺陷，也不要求本轮追加截图或测试。
- 本轮没有启动后台或常驻进程，没有进程回收项；没有调用 MCP。
