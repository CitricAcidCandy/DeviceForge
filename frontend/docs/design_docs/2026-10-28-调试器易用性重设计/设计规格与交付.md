## 设计目标与入口

本轮解决“调试器看不懂、信息太多”的问题。保留全局悬浮球和非全屏浮层，把首页改为看懂 Agent 调试过程：当前插件、整段计划是否结束、最终步骤结果、接下来可做的操作。手动检查是次级入口；不再把六个技术页签全部放到首屏。

调试器启用后，复用现有 `developer.tools` 全局贡献，仅显示悬浮球；默认不选择插件、不打开观察会话、不采集页面。点击球后在浮层内部明确选择被调试插件。切换业务页面不丢失或重复挂载入口；禁用、卸载释放调试器自身入口、订阅和会话，不停止业务插件。这个全局槽位和初始收起状态已经存在，本轮不发明新宿主槽位。

新云端可编辑文件：<https://ardot.tencent.com/file/741320030627157>，页面 `0:1`。旧 R2 文件保持不变。示例统一使用“应用别名”，字段、名称、时间、结果均为设计示例，不是运行或设备证据，也不代表该插件当前实际登记了同名数据源。

## 关键交互与状态

1. 首次打开未选目标：按“选择插件 → 让Agent调用调试工具 → 在这里查看结果”引导，只有明确点击“选择并查看调试过程”才建立目标观察；不默认绑定“应用别名”。目录有多个窗口时必须继续显示并选择对应窗口，不自动取第一个。
2. 暂无记录：显示“等待第一条调试调用”和手动拾取入口，不放聊天输入框或“连接Agent”按钮。无记录不等于 Agent 离线，历史不完整不等于从未调用。
3. 整计划进行中：只显示整段“计划执行中／等待结果”，不画正在第几步、百分比或流式勾选。已知计划参数可以列出预定步骤；取不到参数时显示中性执行卡，不能从命令状态猜出步骤。最终回执到达后才更新逐步结果。
4. 最终结果：读取、保存并回读、页面断言分别表述。点击派发只显示“已派发”，不能标记业务成功；页面断言明确通过才标“页面检查通过”。数据回读不自动等同通用相等断言或完整业务成功。
5. 结果未确认：保留已知派发事实，主按钮“查询原命令结果”，次按钮“查看实际状态”。查询只读原回执，不自动重放修改，不把取消等待、超时或关闭视为插件动作已经停止。
6. 数据冲突：保留用户全部编辑内容，不自动覆盖新修订。通过“读取最新值并比较”获取最新值后，下一步显式比较并决定如何重新编辑和保存；本轮未单独绘制比较弹层，不将其列为已完成交互图。
7. 断线：历史步骤加“当时”、结果加最后观测时间与过期提示，保持只读；更换目标和保存已有报告仍可用。重新连接先核对身份和代次，只恢复观察，不重放历史动作。
8. 手动检查菜单包含“检查界面”“查看数据”“调用公开能力”。拾取时临时收起浮层、提示按 Esc 取消，完成后返回选中节点的简短检查卡。节点树、原始属性、参数和日志全文作为次层技术详情；本轮未新增逐节点复杂编辑器。

数据页按照 schema 的字符串、数值、布尔和枚举生成业务表单；复杂结构进入“高级JSON”。字段值不能从脱敏占位符恢复隐藏秘密。只列主动登记数据源；空目录解释“插件尚未公开数据源”，不声称没有私有状态。服务器数据继续通过其已有公开服务，不显示伪造的服务器内部数据编辑能力。

保存只确认实际保存与回读。若生效策略是下次调用或重载，显示“已保存，待下次调用／重载生效”；不能直接显示“当前已应用”。只读源明确显示只读并移除保存动作。普通使用流程不堆能力开关、危险模式或确认复选框；真实变更的必要确认沿原能力规则执行。

收起只隐藏浮层；关闭释放调试器面板自己的观察会话，保留全局入口。关闭不停止外部 Agent、业务插件或原 Job。浮层拖动、缩放继续沿用已有交互并将位置夹取到视口；按钮区域不触发拖动。普通查看态 Esc 收起并返回球焦点；弹层、拾取或尺寸模式内 Esc 优先取消当前模式。

## 旧功能迁移映射：简化入口，不删能力

| 原功能 | 新入口与展开位置 | 保留的行为与边界 |
| --- | --- | --- |
| 目标、实例、代次与连接 | 固定目标栏；完整身份在“技术详情 → 目标身份” | 显式选窗口与插件，展示精确代次；复制标识，不自动选择第一个目标 |
| 公开目录 | “技术详情 → 公开能力”，可从试调用页返回该目录 | 列出当前目标实际公开的服务、命令、组件及操作说明；无目录不能虚构能力 |
| UI树、节点属性、高亮、差异、断言 | “手动检查 → 检查界面”，默认简短选中卡，展开“节点树与原始属性” | 保留查询、分页、完整性提示、三态断言、前后快照差异；不读取React私有状态 |
| 手动service／command／invoke试调用 | “手动检查 → 调用公开能力”进入次级表单；从公开能力目录可直接选择一项 | 选择公开入口、填写schema业务字段，复杂参数进入高级JSON；原禁用条件、设备限制、必要确认不取消；返回原Job、日志ID和真实结果，不另建任务事实 |
| 插件数据读写 | “手动检查 → 查看数据” | 保留目录、schema、只读/可写、生效策略、原子修订冲突与未确认结果；表单不回填脱敏秘密 |
| 事件、时间线、业务日志、旧代错误 | “技术详情 → 日志与事件”次级列表，可从失败步骤定位相同日志ID | 保留筛选、搜索、跟随、旧代标识、复制与有界缺口；旧清理告警不阻止独立新调用，当前成功不擦除旧失败 |
| 报告查看、保存、下载 | 已有结果底栏“保存报告”；“技术详情 → 报告与证据”查看已保存产物 | 复用原公开报告和产物下载，保留完整性及省略说明；不是新的无限历史库 |
| 插件重载与更新后的重新连接 | “技术详情 → 插件操作 → 重载当前插件”独立动作 | 按实际公开能力显示；确认本次目标和影响，重载后核对新代并使旧节点、旧修订失效；不重放旧业务动作 |
| 收起、关闭、拖放与尺寸调整 | 固定标题栏与角部手柄；键盘尺寸入口进入“技术详情 → 面板设置” | 沿用原拖放和键盘可访问能力；关闭只回收调试器资源，不停止业务 |

“技术详情”是一个可返回的次层抽屉/详情视图，以分组折叠组织，不恢复横向技术页签。打开“调用公开能力”等次页后始终保留目标栏和“返回调试过程”。上述展开态和完整试调用表单没有在本轮九幅中逐一绘制；实施前仍需针对实际调整补相应细节稿，不能在落地时直接删除原能力或编造已实现的新表单。

## 接线依赖与能力边界

本轮仅交付设计，不实现新的运行观察协议。

当前公开合同已有整段 `debug_automation_run` 与最终步骤回执；`events` 只保留实例、会话、命令生命周期元数据，没有计划参数和逐步结果正文。`debug_command` 要求原会话归属，不能让调试器自己的会话直接读取另一 Agent 会话回执。已有保存报告不是完整的当前目标活动目录；有界内存记录也不保证重启恢复。

因此首页查看外部 Agent 跨会话记录仍有明确小依赖：按已明确选中的实例、插件、代次，提供只读的公开命令活动与保留回执视图。它应复用现有命令事实、期限和容量，保留缺口与淘汰标识，不新增执行器、实时步骤事件、自动重放或无限持久历史。没有可信调用来源标记时显示“外部工具调用”，不能把每条记录硬标成 Agent。

依赖未完成时，03空态及手动检查可按现有能力工作；04、05等跨会话记录画板作为待接线设计，不能用假数据模拟真实运行后宣称能力已实现。运行状态有记录缺口、当前目标换代或报告不完整时，都应保留不确定性。

既有自动计划最多32步，浏览器内部总预算28秒；本轮不增加任意自然语言计划生成、任意脚本、条件分支、自动回滚、React私有状态编辑或服务器数据登记。面板“下一动作”来自固定状态对应的按钮，不生成未经证实的建议。

## 源文件与本地交付性质

云端链接中的画板使用真实文本、容器、控件及矢量图层，可在 Ardot 中继续编辑。PNG 是该文件的真实画板预览，不是 HTML 模拟图。

本地节点备份保留读取到的真实节点身份、文字、字体、颜色、尺寸与父子层级。它用于审计和恢复参考，**不是 Ardot 的直接导入格式，也不保证可以重开**。`Ardot-最终真实节点备份.jsonl` 包含九画板、371个节点、196个真实文本节点，无压缩占位子树，共152379字节。`Ardot-制作中节点快照.jsonl` 是修改状态前的中间备份，不是最终稿；不将它当成最终源。

首轮九图保留在 `首轮预览/`，目录根的九幅PNG为四项意见合并修订后的最终批次。第二批仍一次包含全部九画板，没有拆分成反复微调截图。01新增球下常驻“调试”文字，02底栏补“尚未选择插件，调试器不会读取页面”，03空记录卡片从432收紧到340高，04增加低强调“等待最终回执”。悬浮入口的实现还须提供“打开调试器”的可访问名称，文字不能取代可访问语义。

当前 MCP 只提供图像、文档和HTML导出，没有原生整文件下载接口；主代理检查原生界面入口时遇到未登录页面，没有使用凭据或继续登录。本轮没有取得原生可重开的 `.ardot` 文件，不把JSON、轮廓SVG或截图改扩展名冒充原生源。原生本地源下载仍是交付缺口；云端编辑层和本地备份并不消除这个缺口。

## 用户确认后的步骤命名约定

用户询问“读取当前配置／修改名称前缀／检查应用名称”等动作名称的来源。画板中的文字为示例；实施增加可选步骤 `label`，由Agent提供业务名称，未提供时由调试器按工具给出中文默认名。名称仅作展示，最多80个Unicode字符、不得为空白或包含控制字符；不替代稳定 `id`，不用于绑定，不参与执行状态或成功判断。状态文字始终由原命令回执和显式检查证据生成，Agent将动作命名为“检查通过”也不能使状态变成通过。
