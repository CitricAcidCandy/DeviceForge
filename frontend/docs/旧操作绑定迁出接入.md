# 旧操作绑定迁出的前端接入计划

## 决策与当前范围

模式为 architecture-first / Hybrid。依据后端 [平台适配器迁出实施](../../backend/docs/平台适配器迁出实施.md)、本端 [前端运行架构](前端运行架构.md) 与 [平台适配器迁出边界](平台适配器迁出边界.md)，下一批沿现有操作目录、设备能力和单次任务入口接入动态平台插件；旧名称绑定、输入/结果兼容及执行准入由后端负责。

2026-10-09 主代理已报告预算增量 check、78 项测试及 build 通过；该证据属于设备声明 API 1/2 与能力预算，不证明旧操作绑定或平台迁出已完成。原设计批只新增接入计划，未修改源码或执行运行门禁；随后主代理局部解冻 operations 目录失效，实施记录见文末。具体 UI 等待设计稿，main.ts 仍未装配产品 runtime。

选择消费服务端动态目录和公开能力，不在浏览器维护旧名称到平台命令的映射表。前端自行猜提供者或失败后转交另一入口会破坏同一次任务准入、重复设备写操作；该路径不采用。现阶段不需要新增 HTTP 路由或 SDK 方法，绑定管理配置、旧结果兼容细节和性能会话契约仍由后端后续冻结。

## 已核对的真实入口

| 入口与代码依据 | 当前职责与契约 | 接入限制 |
| --- | --- | --- |
| shared/api/endpoints.ts、features/operations/index.ts | GET /api/v2/operations 查询当前操作；Operation 只有 id、title、input_schema | 没有 owner、generation、alias 或绑定状态字段，不从名称解析这些信息 |
| features/tasks/index.ts、app/host-context.ts | runtime.tasks.submit 接受 operation/input；HostContext.submit(id, input, signal) 返回 HostResult<Job> | 请求没有设备引用或代际字段；任务提交前运行现有 beforeTaskSubmit 钩子 |
| shared/api/device-endpoints.ts、app/device-gateway.ts | GET 提供者/目录、POST 提供者 refresh 与 device-actions；HTTP 类型索引生成 paths | camelCase SDK 显式映射 HTTP snake_case，不手写设备或绑定 DTO |
| plugin-sdk/devices.ts、features/devices | DeviceRef 为 providerId/generation/localId；DeviceAction 为 providerId/generation/deviceId/capability/version/input | 精确能力版本、范围、观测和可用状态由公开模型驱动；提供者能力的 deviceId 为 null |
| app/runtime.ts、catalog-refresh.ts | 服务器 load/unload 收敛时撤销目标设备缓存，再重查操作及设备目录 | 仅本实例管理联动；目录查询不是发现，也没有远端推送 |
| app/public-api.ts、shared/api/client.ts | 传递 v2 日志关联和受控错误；Job.result 作为 JSON 原结构映射 | 不在适配器按旧操作名称拆平结果或伪造日志 ID |

浏览器插件通过可选 HostContext.devices 的 refreshProviders/refreshDirectories/refreshProvider/invoke、select/snapshot/subscribe 使用设备；旧宿主可以省略 devices。生产公开宿主 /assets/plugin-host.js 导出运行工厂，不自动启动业务。runtime.serverPlugins/pluginPackages/artifacts 是 app 管理与产物入口，并非插件 SDK 已开放的管理 API。

设备声明版本位于 provider.definition.apiVersion，能力列表位于 provider.definition.capabilities；capability.version 是能力版本，provider.version 是包版本，三者不能互换。可选 executionTimeoutMs 是只读声明元数据，API 2 才允许非空 1–120000 毫秒，缺省/null 保持 SDK 省略、由宿主默认 30000 毫秒。动作、旧任务及业务 input 不新增覆盖预算的语义。

## 旧行为与迁出后的消费规则

现有 server/main.rs 仍装配具体平台执行器；application/registry.rs 的 Registered 保存 owner，而旧内置贡献 owner=None。application/devices/rules.rs 遇到无 owner 时不进行设备贡献准入。后端迁出门禁将通用绑定落到 application/operation_aliases，由当前贡献快照共享代际、锁、队列、取消与期限；本次读取的代码尚未提供该绑定接入完成证据。

| 当前旧操作样本与代码依据 | 旧输入或结果 | 迁出后的前端规则 |
| --- | --- | --- |
| infrastructure/devices.rs：android.devices、harmony.devices | 空对象；返回旧 Device，包含 id/platform/state/model | 新设备入口用聚合目录和完整引用；旧枚举作为兼容任务消费，状态转换由后端冻结 |
| 同文件：android.connect/disconnect、android.app.start/stop、android.packages、harmony.packages | address、package 或裸 device_id，具体要求以 input_schema 为准 | 按当前目录提交旧名称一次；不把平台或裸 ID 当作提供者来源 |
| infrastructure/device_artifacts/mod.rs：两平台 app.install/uninstall、android.screenshot | device_id 加 artifact_id/package；旧截图 result 是产物信息 | 安装输入保持产物 ID；截图结果兼容由后端确定，不替换历史任务格式 |
| application/device_input/mod.rs、splits/mod.rs：android.input、android.app.install_apks | 各自当前生成输入模式；包含设备相关业务参数 | 仅在实际公开贡献或绑定存在时消费，不臆造新平台能力 ID |
| application/performance/operations.rs：android.performance.* | 当前性能任务与会话操作 | 动态采样绑定及会话热卸载需独立契约，不以普通设备动作代替 |

新代码调用设备能力时优先用 devices.invoke，保留完整 providerId/generation 和精确能力 ID/version。capability.operation 是服务端公开的贡献名，不作为浏览器自行创建别名或推导业务输入模式的规则。平台名称只用于展示/筛选，Harmony 入口仅消费其实际声明的能力。

旧调用继续查询 operations 并通过 submit 提交原 operation/input。迁出目标是绑定存在时发布对应旧名称、撤销时从目录移除；目录存在仅为一次查询观测，实际提交仍可能因并发卸载被拒绝。浏览器不得追加私有 owner/generation 字段到旧请求，也不得把裸 device_id 自动补成“第一个同名设备”。多个提供者暴露同一本地 ID 时，来源由后端显式绑定配置解决，歧义拒绝的具体错误需后端冻结。

旧提交没有客户端代际字段，其本次绑定由服务端原子注册快照决定；排队或已准入任务不能自动切到重载后的新贡献。绑定输入转换和结果兼容必须发生在同一个任务内，前端不再提交第二个 Job 补做平台调用。取消或冲突后只刷新并报告，由使用者显式决定新提交，不自动重放。

旧 parse_adb 支持 recovery/sideload/bootloader，当前公开设备 state 为 online/offline/unauthorized/unknown，尚无无损映射承诺。前端不将旧特殊状态强转 online，亦不新增未冻结状态枚举。历史 Job.operation/result 保留原值；协议 2/3 带产物结果保留 { result, artifacts }，旧截图平面结果与新包装的适配规则待后端逐项确认。设备 input.artifact_id 沿服务器插件 artifacts.input_pointers 声明解析，输入不能传服务器路径。

## 状态撤销与错误映射

现有 devices 在提供者消失/代变后撤销相关目录、选择和请求；刷新开始清该代旧观测，失败保持空，替代请求和旧代晚到不能回写。插件实例及面板/组件/模块子作用域合并请求信号并释放订阅，后续接入保持这些约束。

设计审查时 operations 使用 createLatestResource：刷新在途及失败时保留之前的 result；HostContext.subscribeOperations 只在结果列表引用变化时通知。当时 catalog-refresh 撤销设备缓存，但未撤销操作快照，本地卸载后的目录重查失败可能使旧名称留在快照和订阅者手中。因此安排功能内部操作快照失效，在管理收敛回调先撤销不再可靠的旧列表；现有 Operation 没有 owner，不能按私有来源字段过滤，先整体失效再重查。SDK 沿现有空 Operation[] 通知撤销，不新增绑定 DTO 或状态字段。当前局部实现见文末，保留本段原缺口来源。

重查分别记录 pending/error，失败不能将历史列表恢复成当前可调用目录；新查询成功后发布新列表。已有 serverPlugins 在管理成功、失败或取消后用独立生命周期重查，不假定管理回滚。远端或其他实例变更仍由显式刷新获知；本地失效不等于客户端实时获知所有贡献变化，提交准入最终由服务器决定。

| 当前真实类别 | 前端消费与下一批回归 |
| --- | --- |
| HTTP 400 / invalid_input | 保留服务 code/message/status/logId；旧输入转换由服务端负责，不在客户端删字段后自动重试 |
| HTTP 404 / not_found | 当前不存在的操作、提供者或精确能力版本不能执行；更新观测，不切换其他来源补做 |
| HTTP 409 / conflict | 可能是旧代、贡献撤销、设备不可用、清理未确认或队列满；按返回值处理，不能一律解释为“请重装” |
| HTTP 409 / cleanup_failed、cancelled | 按服务实际映射透传；管理状态保留 draining/cleanup_failed，取消或任务终态不证明资源已释放 |
| HTTP 504 / timeout、502 / dependency_failed、500 / storage_failed | 保留当前响应类别与真实 logId；不延长浏览器预算、不自动重放写操作 |
| 本地设备校验 / HostError.kind=protocol | invalid_input、not_found、conflict 沿现有 status；logId 为 null，不能伪造服务日志 ID |
| 客户端等待取消 / kind=cancelled，或旧结果撤销 | 结束等待并拒绝回写；不等同 cancelJob，也不证明服务器没有接收任务 |
| 网络失败 / network_error，响应无效 / invalid_response | 维持 network/protocol 区分，沿适配器可取得的 logId；不把传输原始异常或本机路径公开 |
| 已接受任务的 failed/cancelled | getJob 查询是成功 HTTP 响应，任务失败读取 Job.status/error；当前 error 是字符串，不解析成未公开的平台错误对象 |

错误类别依据 server/src/lib.rs 的 ApiError、shared/api/client.ts、app/public-api.ts 和 features/devices/rules.ts。别名歧义、旧状态丢失、旧结果不兼容的精确错误尚未冻结，本文不为其新增错误码。请求 logId 与任务 ID 分开；轮询返回的 logId 是该次请求关联，不能替代未公开的任务执行错误详情。

## 实施顺序与验收

采用 Hybrid：先基于已冻结接口补行为场景，再实现操作目录撤销；绑定语义用后端契约与真实集成验证，不用前端假传输证明服务端锁或进程清理。当前可直接评审本文并准备现有接口的回归场景；源码解冻后实施目录失效，不必等待新的 HTTP 端点。旧名称逐项兼容、绑定配置、特殊状态和性能会话的接入则等待后端明确契约与证据。

1. 后端交接旧名称、原 input_schema、目标贡献、来源配置、结果形状与错误映射清单，区分设备能力、包工具及性能会话。确认缺绑定/歧义时拒绝、原子撤销、单次 Job 与共同准入，不以默认内置工具回退。
2. 前端按本文职责补最小行为测试与操作失效，保留 devices、tasks 和 SDK 的现有签名；新的公开字段仅在冻结并生成后消费。管理重查失败仍撤销不可靠操作和目标设备选择，后续刷新可恢复新观测。
3. 主代理统一生成（仅模式变化时）、check、test、build，并串行执行受影响的真实服务/生产宿主验收。随后独立重建当前 release/runtime/npx 与平台包，记录本轮报告、退出码和覆盖范围，不能复用上一阶段预算或工具库报告充作迁出完成证据。

| 场景 | 前端最低行为证据 | 需要后端/真实集成补齐的证据 |
| --- | --- | --- |
| 动态加载、卸载、空部署 | 目录按新列表增减，能力按 ID/版本使用；无声明能力不产生入口，空列表可正常消费 | 不装平台包也能启动且不检查工具；装载发布、卸载撤销实际贡献及旧名称，无内置回退 |
| 本地管理成功、失败或取消 | 操作失效通知订阅者；重查失败不复活旧列表；目标设备目录/选择立即撤销，新刷新可恢复 | 查询反映真实管理状态，draining/cleanup_failed 不被客户端清除；取消等待不假定变更回滚 |
| 同名设备与精确版本 | 两 provider 的同名 localId 以完整引用区分；版本不匹配、范围错误、离线/未授权/不可用按现有规则拒绝 | 裸 ID 仅由显式绑定决定来源；歧义拒绝与错误形状按冻结清单验证 |
| 旧名称与单次提交 | 使用当前 schema 和原 input；一次触发只发一个 POST /jobs，失败不回退 devices.invoke；beforeTaskSubmit 仍按原规则执行 | 别名与新能力共享 owner/generation、设备锁/provider 屏障、队列、预算与取消；无嵌套 Job |
| 选择切换、替代刷新、重载 | 发现/动作旧等待不能回写，新选择保留；已接受 Job 仍可按 ID 独立查询历史，不因目录撤销被删除 | 卸载时旧快照和已准入任务受当前代取消树约束；重载不将旧任务切到新执行器 |
| 产物与旧结果 | artifact_id 透明传递；平面旧结果及新 result/artifacts 包装分别保留，不按当前包版本重写历史 | 旧截图、安装及其他结果转换逐项冻结；真实下载校验大小/摘要，无服务器路径泄露 |
| 错误与日志 | HTTP 包装、status/code/logId 原样适配；本地拒绝不伪造 logId，失败任务不当作 HTTP 失败；不自动重放 | 实际缺绑定、代变、取消、超时、清理失败及执行失败对应冻结语义与真实日志关联 |
| 插件实例与挂载子作用域 | 退出/卸载取消请求并释放设备和操作订阅；旧上下文不可使用，晚到不恢复 DOM 或状态 | 实际平台资源收敛独立验证；浏览器清理不证明 daemon、外部事务或真机已回滚 |
| 预算与性能边界 | API 1/2 与可选预算既有回归继续通过，请求不出现预算覆盖字段；不猜性能 capability | 长安装整体截止点、性能会话 owner/generation 及热卸载排空另验收，不以普通 Job 取消替代 |

前端测试只证明客户端、公开上下文和状态行为；真实平台安装、工具异常、共享 daemon、性能会话及真机由所属后端/验收角色提供独立证据。SDK 订阅和目录刷新不是远端推送，能力发现也不是常驻设备热拔插已完成。

## 审核结论与剩余依赖

当前设备网关和动作请求能够支持动态提供者，下一批无需发明绑定 HTTP DTO、浏览器 shell、本机路径接口或预算覆盖入口。优先缺口是操作目录本地失效及旧/新入口兼容回归；绑定来源、特殊状态、旧结果和性能会话的精确语义归后端冻结。若后端保持既有 HTTP 形状，前端无需扩大 SDK；确有公开加法时再由主代理生成、评审并交接。

原设计批记录接入计划和源码核对，未实施操作失效或旧绑定。后续局部操作失效增量见下节，旧绑定仍由后端负责。具体 UI、平台迁出、常驻连接、远端推送、真机与本轮 release/npx 均不因本文完成而计为验收通过。

## operations 局部解冻实施记录（2026-10-09，待统一门禁）

本轮为 plan-and-build / Hybrid：先新增 operation-migration 回归源码，再增量实施功能内失效及 app 回调装配。没有修改共享 createLatestResource、devices、shared/api、SDK 或 generated，也没有运行 npm、Cargo、构建或服务；前述 78 项测试结果不能作为本增量通过证据。

| 本轮文件 | 职责与行为 |
| --- | --- |
| src/features/operations/state.ts（新增） | 管理操作专属刷新代次、快照、失效及订阅；invalidate 发布 logId=null 的空目录，失败保留撤销后的空目录；订阅重入或旧响应不能恢复旧快照 |
| src/features/operations/index.ts | 保留 list/refresh/snapshot/subscribe/dispose，新增 app 用 invalidate；独立 list 与刷新绑定目录观测及生命周期，失效/销毁取消旧等待并拒绝晚到结果 |
| src/features/operations/README.md | 说明状态职责、空目录通知、取消和未验收边界 |
| src/app/catalog-refresh.ts、runtime.ts | 只注入失效回调，管理收敛后先失效操作目录与目标设备缓存，再重查现有目录 |
| tests/operation-migration.test.ts（新增） | 10 项行为回归源码：旧刷新/独立 list、失败/取消/恢复、销毁、管理成功/失败/取消、在线包停用、SDK 通知顺序及订阅重入 |

失效发生在现有服务器管理收敛回调，不承诺在管理 HTTP 等待开始时就撤销。成功、失败和取消都会触发原有独立生命周期重查；重查失败继续保留空目录和实际错误，不自动重放变更。普通显式刷新仍可保留此前未失效的观测，但在本地管理已撤销后，旧列表不再作为失败回退。远端变化需显式刷新，服务端仍承担实际提交准入。

原有 SDK subscribeOperations 和 host.operations.changed 通过新的空列表引用收到撤销；没有新增 SDK 方法。失效没有服务响应，logId=null；重查错误和新成功结果各自保留真实查询日志 ID。停止订阅或运行实例销毁后不再通知，提供者/任务取消语义沿原实现。

当前只完成源码与行为回归编写，静态空白/编码检查与文件哈希在冻结交接消息中记录。剩余门禁为主代理统一 check、test、build 及受影响的生产宿主浏览器验收；旧绑定、平台锁、真机和本轮分发证据不由这些受控传输测试证明。
