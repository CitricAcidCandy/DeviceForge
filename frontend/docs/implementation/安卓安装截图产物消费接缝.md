# 安卓安装截图产物消费接缝

日期：2026-10-10。本文是前端对[安卓安装截图插件实施裁定](../../../backend/docs/implementation/安卓安装截图插件实施裁定.md)的静态消费核对及独立浏览器驱动交接，不修改生成接口或生产代码，也不把冻结能力写成已完成浏览器验收。

## 结论

现有前端公开设备与产物接缝已经能够消费 `android-device` 追加的 `app.install@1` 和 `screenshot@1`。不需要增加 HTTP 字段、SDK 版本、平台专用路由、宿主私有导入或 Android 分支。

前端从当前目录读取提供者声明和设备能力，再通过 `HostContext.devices.invoke` 发起动作；浏览器通过公开 `artifacts.upload` 取得产物 ID，嵌套产物授权由宿主执行层根据 `/input/artifact_id` 选择。浏览器不读取宿主路径或猜测临时目录。截图结果以公开 `Job.result` 内的 `result/artifacts` 包装消费，不能把插件私有路径或插件内部文件对象暴露给前端。

## 公开调用映射

| 后端冻结合同 | 前端现有消费 |
| --- | --- |
| `plugin.android-device.app.install`，`app.install@1`，`device/write` | 通过当前 `DeviceProviderInfo.definition.capabilities` 发现精确 `id/version/scope/access`，调用 `devices.invoke({providerId, generation, deviceId, capability: "app.install", version: 1, input: {artifact_id}})` |
| `plugin.android-device.screenshot`，`screenshot@1`，`device/write` | 同一 `devices.invoke`，`input: {}`；不得按平台名称拼接路由或使用 shell 参数 |
| 安装总预算 `120000ms` | 读取能力的 `executionTimeoutMs` 只作显示和准入元数据；浏览器不覆盖、拆分或重新计算期限 |
| 截图总预算 `30000ms` | 同上；不得把工具短限额转换成前端超时或自行重试 |
| 安装业务输入 `{device_id: serial, input: {artifact_id}}` | 公开 SDK 的 `deviceId` 使用目录引用中的 `localId`，`input` 仅传 `{artifact_id}`；不重复嵌套设备封套 |
| 截图业务输入 `{device_id: serial, input: {}}` | `deviceId` 使用完整 `DeviceRef` 对应的 `localId`，`input` 为空对象 |
| 安装输出 `{artifact_id, output}` | 读取任务 `Job.result` 包装内的 `result`，保留原字段和空产物数组；不按文件名或错误文本猜测成功 |
| 截图输出 `ArtifactOutput { filename: "screenshot.png" }` | 读取 `Job.result` 包装内宿主发布的 `artifacts`；实体下载继续走现有 `HostContext.artifacts.download(id, signal)`，不读取路径 |

旧 alias（如 `android.app.install`、`android.screenshot`）只有在操作目录真实出现时才可消费。前端不因 manifest、旧名称或平台字符串存在而补造入口；卸载后也不得回退到宿主内置实现。

## 产物授权边界

安装动作需要一个且仅一个与业务 `artifact_id` 完全相同的 `ArtifactInput`，字段为 `/input/artifact_id`。前端不得把顶层 `artifact_id` 当作兼容回退，也不得从同一产物的其他字段、文件名或本地路径推断授权。重复、缺失或多余输入属于后端准入错误，前端保留真实错误并停止提交。

截图没有业务输入产物。前端不提供输出目录、不把下载目录或浏览器缓存路径写入请求；服务器插件负责在自己的临时目录生成 `screenshot.png` 并声明文件名，宿主完成公开产物发布。服务器插件 SDK 的 `ArtifactOutput` 只有 `filename`，没有 `path`；这项服务端协议规则不应扩张成浏览器对整个 `Job.result` 的通用字段拒绝规则。

前端现有 `ArtifactAccess` 只传原始 `Blob` 和公开产物 ID，保持 JSON、NUL 和非法 UTF-8 字节；它不承担 APK 内容资格、SHA-256、链接/重解析点或 PNG 头校验。上述检查属于后端插件和宿主发布边界，不能在浏览器侧复制一份并据此宣称安装或截图成功。

## 状态、代次与错误消费

动作前必须从当前 `DeviceSnapshot` 取得完整 `providerId/generation/localId`，并由既有设备规则检查提供者代次、观测目录、设备 `online` 状态和能力可用性。代次变化、提供者移除、刷新或插件卸载会撤销旧引用；晚到的 Job 回执带有已取得的 `logId`，但不得写回新代目录或继续更新已撤销面板。

前端应沿现有 `HostError` 分类处理：

- 本地输入、能力版本或作用域不符：`protocol/invalid_input` 或 `protocol/not_found`，状态可能为 400/404，`logId=null`，不产生 HTTP 重试。
- 旧 generation、无本代目录、设备离线或能力不可用：`protocol/conflict`，状态 409，`logId=null`，先显式刷新，不自动替换设备引用。
- 真实服务拒绝：保留 HTTP 错误的 `code/status/logId`，包括 `dependency_failed`、`timeout`、`cleanup_failed` 和 `payload_too_large`；不要把所有 409 改名为清理失败。
- caller、宿主、插件或挂载撤销：使用 `cancelled`、`plugin_unloaded`、`stale_device_result` 等现有本地分类；若响应已抵达，继续保留其日志 ID，预取消和本地资格拒绝不得伪造日志 ID。
- 成功 HTTP 但任务失败：读取原始 `Job.status/error/result`，成功后的产物在 `Job.result` 内；任务 ID、发现 Job ID 和浏览器代次标记都不能代替服务日志 ID。

取消只结束前端等待和结果交付资格，不证明设备动作已回滚、ADB 子进程已终止或服务器任务已取消。需要取消服务器任务时使用已有 `cancelJob`，并随后显式读取任务状态；不要因为 `AbortSignal` 触发就把安装、卸载或截图效果判为已撤销。

## 现有代码接缝核对

- `frontend/src/plugin-sdk/devices.ts` 已公开 `refreshProviders`、`refreshDirectories`、`refreshProvider`、`invoke`、选择、快照和订阅，能力预算映射为 `executionTimeoutMs`。
- `frontend/src/app/device-gateway.ts` 已将生成的 snake_case 设备 DTO 显式映射为 SDK camelCase，并将动作统一发送到 `/api/v2/device-actions`。
- `frontend/src/features/devices/rules.ts` 已按完整 `DeviceRef`、能力版本、scope、online 和 availability 做准入；没有平台硬编码分支。
- `frontend/src/plugins/device-access.ts` 与 `frontend/src/plugins/scope.ts` 已合并 caller/宿主/插件代次信号，撤销后拒绝晚到结果。
- `frontend/src/plugin-sdk/artifacts.ts`、`frontend/src/app/artifact-gateway.ts` 和 `frontend/src/plugins/artifact-access.ts` 已提供可选原字节上传/下载及代次收口；不暴露宿主路径。

因此本批前端实际缺口是消费层验收。后端已冻结截图 `access`、嵌套 `ArtifactContext` 解析规则、Job 输出声明和错误/清理终态；独立浏览器驱动按正式清单与真实目录消费这些约束。没有产品界面和设计稿时，不新增占位页面。

## 浏览器历史驱动输入核对

`node scripts/browser-task-history-smoke.mjs` 与 `--release` 是独立真实浏览器验收，不是前端生产实现。驱动只接受无参或 `--release`，自建临时数据/插件目录、回环端口、Rust 宿主、透明 HTTP 代理和独立 headless Edge/Chrome profile；不执行 Cargo、npm 或生成器，不连接已有用户服务。

当前环境静态输入满足驱动前置：Node `v24.14.0` 提供全局 `fetch`、`WebSocket`、`AbortSignal.any`；Edge、`frontend/dist/assets/plugin-host.js`、debug/release `apk-server` 均存在。release 二进制仍需由主代理在当前版本冻结后重建，不能以文件存在代替版本对应证据。

每轮报告必须覆盖：十项任务历史/事件场景、七个真实回执取消门闩、真实日志 ID 与代理请求匹配、在线 server/browser 包、浏览器和 Rust 进程正常 OS 退出、代理无错误、输入清单前后字节无变化。驱动通过只证明任务历史公开接口及插件代次/取消消费；不证明 Android 安装、PNG 内容、真机 UI、长期期限、npx、LAN 或可信插件副作用已清理。

主代理首次实际 debug 运行报告 `artifacts/browser-task-history-debug-uHrfow/report.json` 在 TH-B01 因验收 harness 未注入 `RuntimeOptions.esmImporter` 失败；第二次 `artifacts/browser-task-history-debug-ig5PYT/report.json` 在同项因面板 ID 缺插件命名空间失败。现已注入原生 `import(url)` 并在导入前后复核 signal，面板定义、挂载、卸载和目标映射改为同一完整 ID。增强后的 debug `artifacts/browser-task-history-debug-GjOOf3/report.json` 与 release `artifacts/browser-task-history-release-jAxt1c/report.json` 均通过十项场景和七个门闩，二十五项输入字节稳定、Rust/Edge 正常退出与端口重绑均已核对。原失败记录保留，详见[任务历史浏览器验收记录](../verification/任务历史浏览器验收记录.md)；这些证据不转计安装截图驱动。

## 安装截图浏览器驱动交接

已落盘独立入口 `scripts/android-artifacts-browser-smoke.mjs` 和所属七个模块及 README。驱动消费生产 `plugin-host.js`、在线 API2 浏览器探针、真实 native 插件部署副本和现有 device-tool 进程夹具。它不改生产源码、前端生成类型或已通过任务历史驱动。

参数为 `node scripts/android-artifacts-browser-smoke.mjs [--release] --tool-binary <已编译device-tool绝对路径> [--source-directory <冻结插件元数据绝对目录>]`。安装的固定 Stored ZIP 为 269 字节，PNG 为实际 fixture 的 68 字节，SHA256 为 `02bdccb1bea6c2eb32cc2301ab98b3bd77f40de47e9ee934438ec7b044da4e86`；该 APK 仅供假工具检查，不宣称真机可安装。

九项场景包含十贡献/九能力、公开上传安装、PNG 原字节与 SHA256、SDK/HTTP/MCP 同历史/完整事件、真实输入与任务错误、预取消、面板/浏览器/runtime 旧引用零传输、提供者卸载/新代和资源/端口收口。静态 Node 语法、实际 `readPluginModule`、固定字节及临时复制部署物化检查均已通过；静态部署只复制 Node 工具输入，没有执行它。主代理随后完成 debug `artifacts/android-artifacts-browser-debug-XrHsHN/report.json` 和 release `artifacts/android-artifacts-browser-release-OOnWRO/report.json`，B01—B09 均通过；本角色独立核对两轮 38 项输入稳定、部署副本摘要、九次 MCP 日志、Rust/Edge 正常退出、端口重绑、私有副本/scratch 与临时目录清理，详见[安卓安装截图浏览器验收记录](../verification/安卓安装截图浏览器验收记录.md)。

首次实际 debug 报告 `artifacts/android-artifacts-browser-debug-jBK39O/report.json` 已通过 B01 在线目录、B02 安装及 B03 截图逐字节检查，B04 的真实 `/mcp` 回执为 403。原因是独立宿主未授权验收桥写入的本次上游 Origin；现已为该子进程设置精确 `APK_MCP_HOSTS`、`APK_MCP_ORIGINS`，生产来源校验仍启用。此回环代理范围及未验证的产品来源授权见驱动 README；原失败报告保留。

第二次 debug 报告 `artifacts/android-artifacts-browser-debug-3hkp4A/report.json` 的 MCP 已取得 200 和匹配日志，B04 在 HTTP/MCP 历史比较处失败。HTTP 直接序列化 `Job` 结构，MCP 先转换为 JSON 值，两者对象键顺序不同；验收比较现已改为递归对象键排序，仍严格比较键集合、值、数组顺序和完整事件，不修改生产序列化或结果字段。原失败报告保留，两轮成功报告均采用修复后的比较。

工具没有可靠在途门闩，因此浏览器驱动只证明预取消、已撤销引用和消费资格；安装运行中的工具取消、文件排空与异常清理以独立后端协议/服务证据核对。本文与驱动都不把取消等待扩大为设备副作用停止。
