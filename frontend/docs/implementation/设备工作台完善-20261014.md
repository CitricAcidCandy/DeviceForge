# 设备工作台与暖色界面完善

日期：2026-10-14，Asia/Shanghai。模式：architecture-first。

## 目标与边界

沿用用户指定 `../design/2026-10-14/night-workshop-v1.png` 的导航、目录、详情、当前设备与任务区域布局；背景继续使用已有电子设备工坊图片。用户明确不参考原图颜色，因此采用浅奶油环境底、暖米白工作面、深橄榄文字及鼠尾草绿色操作。

本轮影响展示层、设备公开用例消费、验收与文档。不新增后端业务或重复 DTO，不修改 SDK；不连接或唤醒真机。参考图与最终截图仅由视觉子代理审核。

## 选择与职责

选择保留唯一 runtime、现有服务通信和插件挂载的增量完善方案。另建页面请求与平台专用命令会复制契约、绕过完整设备引用及代际保护，不采用。设备主区拆为目录和详情私有组件，右侧摘要保留在现有外壳。

| 单元 | 职责、输入输出 | 不负责 | 副作用 |
| --- | --- | --- | --- |
| app/styles.css | 统一主题变量、外壳尺寸与响应式 | 设备网络与准入 | 无 |
| app/product/shell.tsx | 真实当前设备摘要、全局导航、服务状态 | 设备发现与能力输入规则 | 已有订阅、选择回调 |
| pages/devices/index.tsx 与私有组件 | 设备目录、筛选、详情、连接与能力入口 | 平台命令、接口解析与 SDK 定义 | 调用公开设备、任务用例 |
| pages/devices 私有规则与等待逻辑 | 完整引用比较、能力准入、动作终态及晚到结果保护 | 全局可变状态 | 显式取消、任务轮询 |
| device-workspace 测试及浏览器驱动 | 验证真实组件消费接口和关键失败路径 | 真机与性能验收 | 隔离浏览器与受控服务 |
| 所属端文档与根 todo | 当前版本、验证范围和未验证事项 | 历史成绩外推 | 文档记录 |

## 实施与最低证据

先契约核对，再实现公开提供者发现与能力行为，最后集成暖色主题，采用契约与行为验证结合。明确区分 `refreshDirectories` 的观测读取和逐提供者 `refreshProvider` 的实际发现；操作按公开能力版本、作用域、可用状态与权限开放。取消等待不代表服务器任务回滚。

必须执行生成类型、架构/严格类型、全量测试和生产构建，并补设备页浏览器交互、桌面/390px 窄屏视觉审核及当前 Rust 服务接口验证。真实 Root、真机、正式分发及性能专项仍按原延期边界单独验收。

## 用户追加：插件默认启用

用户追加要求现有插件默认启用。新增跨页面 plugin-defaults 工厂消费公开安装目录和运行状态，服务装配负责注入，main 负责每次新服务实例显式启动，插件页负责结果与失败重试。构造无网络，正常包失败彼此隔离，当前实例手动停用后不周期恢复。浏览器动态模块由 app/installed-package-importer.ts 唯一适配器加载，只接受当前服务公开运行代次资源；架构检查仅对该适配器的非字面量模块导入作精确例外，网络和 any 检查继续生效。

本地预览从当前 debug 业务程序注册13个服务器插件，清单均经真实 Rust 校验。示例插件另置隐藏未用目录，不纳入业务范围。注册和默认启用不执行设备发现、模型请求或业务任务，未配置工具路径的能力保留真实错误。
