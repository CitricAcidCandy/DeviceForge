# 插件数据与Agent自动调试

日期：2026-10-28。本文记录当前实现合同；易用性九态新稿已获用户确认并进入实现，运行服务与发行产物是否已更新须按交付记录核对，不能据源码宣称在线已生效。

## 交付方案

沿用官方普通调试器插件、公开宿主服务和原本机MCP桥，新增数据登记与有界步骤执行。Agent按明确插件、浏览器实例和代次执行，不自动选择第一个标签页。旧插件不强制接入数据SDK；服务器数据继续使用插件已有公开服务和原Job，新数据工具暂只支持浏览器目标。

| 工具 | 输入 | 结果与用途 |
| --- | --- | --- |
| `deviceforge.debug_data_catalog` | `{session_id,parameters:{}}` | 当前代已登记数据源、schema、读写能力、持久化与生效方式；不触发读取 |
| `deviceforge.debug_data_read` | `{session_id,parameters:{source_id,query?}}` | 数据值与不透明修订；缺省查询由源解释 |
| `deviceforge.debug_data_write` | `{session_id,parameters:{source_id,expected_revision,value,confirmed:true}}` | 完整替换业务投影，实际写入后回读；不支持任意对象路径 |
| `deviceforge.debug_automation_run` | `{session_id,parameters:{confirmed,steps,stop_on_failure?}}` | 逐步证据、耗时、失败或未确认状态、未执行步骤 |
| `deviceforge.debug_command` | `{session_id,command_id}` | 查询原桥命令回执，不再次派发；必须属于该会话 |
| `deviceforge.debug_activity` | `{session_id,limit?,before?,command_id?}` | 只读观察会话明确目标的留存调用；列表仅元数据，指定命令后读取单条脱敏最终回执，不借用原会话身份 |

所有调用也可通过 `host.debugger@1` 的 `{action:'call',name,input}` 消费，保持原HostResult与日志ID。桥回执的 `state=succeeded` 只表示收到执行器结果，还须检查 `response.status` 和各步骤状态。超时后的未知结果不自动重放，`debug_command` 只能查已保留的回执，不能恢复未送达的浏览器证据。

## 插件主动登记

可选 `context.debug.registerDataSource` 接收 `id/label/schema/persistence/applyPolicy/read/write?`。读函数返回 `{revision,value}`；写函数接收 `{expectedRevision,value}`，比较实际修订与修改必须位于插件同一事务或同一不让出执行权的临界段。宿主预读只能提前发现冲突，不能代替最终原子比较。

宿主将插件修订映射为当前登记实例的不透明标识，调用者应原样使用；同名数据源重新登记后不能复用旧修订。最多登记六十四个源，单值不超过二百五十六KiB；读取、写入和取消等待均有界，旧代晚到结果不能作为新代成功。

数据源应公开无敏感信息的业务投影。已知凭据键、密码Schema与writeOnly值脱敏；对外schema省略敏感属性并保留不完整标记及省略路径。含敏感字段的完整替换明确拒绝，不隐式拼回旧秘密。`next_invocation`和`reload`只确认数据保存与回读，不证明当前运行状态已应用。

独立示例中 `demo.settings` 演示内存数据、最终修订比较、非法输入拒绝与缺少可选SDK时正常激活。它只修改示例数据，不改变回显面板布局。

## 自动调试步骤

每步为 `{id,label?,tool,parameters,bind?}`，标识唯一。Agent可提供 `label` 业务名称，最多80个Unicode字符，不允许空白名称或控制字符；旧计划省略时使用工具中文兜底。名称仅显示，绑定仍引用稳定 `id`，名称与状态完全独立，命名“检查通过”不能代替显式断言通过。最终结果及未执行步骤保留提供的名称。

工具允许 `inspect/data_catalog/data_read/data_write/ui_tree/ui_query/ui_assert/ui_action/invoke`。整份计划预检后才开始执行，禁止嵌套、重载和等待人工拾取。最多三十二步，内部总预算二十八秒、单步十秒，桥命令总预算三十秒；步骤不重启总期限。

`bind.target_from_step` 只引用更早、完整且唯一的界面查询，投影节点标识、代次和修订，沿用同一挂载根。`bind.revision_from_step` 只引用更早同源读取的修订。两者不支持表达式、任意对象路径、前向引用或覆盖显式固定参数。

```json
{
  "session_id": "由打开会话取得",
  "parameters": {
    "confirmed": true,
    "steps": [
      {"id":"读取","label":"读取当前配置","tool":"data_read","parameters":{"source_id":"demo.settings"}},
      {"id":"保存","label":"修改显示名称","tool":"data_write","bind":{"revision_from_step":"读取"},"parameters":{"source_id":"demo.settings","value":{"name":"新名称","count":2},"confirmed":true}},
      {"id":"回读","label":"读取修改后的配置","tool":"data_read","parameters":{"source_id":"demo.settings"}}
    ]
  }
}
```

计划级确认不补写动作自身确认，也不覆盖禁用、只读、校验或原设备限制。已知设备DOM动作仍不自动派发。遇失败默认停止，设置 `stop_on_failure:false` 仅允许继续可确认失败后的步骤；取消和结果未知始终停止。

## 结果与证据

报告包含每步状态、当前代次、耗时、脱敏结果和省略原因；每步证据最多十六KiB，总证据最多七百六十八KiB。大结果不长期缓存，绑定仅保留小型节点引用与源修订。业务 `value` 正常保留，凭据键与已知秘密文本继续脱敏。

界面点击或填值返回 `dispatched`，仍保留业务结果未知。`ui_assert` 的显式通过才计入对应界面检查点；当前 `verified` 不为数据写入或公开入口调用宣称完整业务通过。数据相等断言、条件分支、自动回滚、来源断点和服务器数据登记不是本批已实现能力。

## 界面与验证边界

用户已确认[调试器易用性重设计](../design_docs/2026-10-28-调试器易用性重设计/设计规格与交付.md)：启用即全局悬浮球，窗口内部选目标，首页调试过程优先。界面检查、数据及公开试调用进入手动入口，原始标识、树、日志和重载按需展开；不再新增一排技术页签。

活动查询按观察会话的种类、实例、插件和代次精确隔离，可只读查询仍留存的其他会话调用，不续期、重新派发或放松原 `debug_command` 归属。列表最多50条，`before`为稳定序号；列表不带原业务参数、原命令会话标识或结果正文，单命令详情返回已有校验的回执。`gap`与`retained_only`明确有界历史，不保证重启恢复。来源未有可信标记时显示“外部工具调用”，不硬标为Agent。

进行中只展示整段计划与“等待最终回执”，不提供实时步骤流或百分比。没有内置Agent聊天、自然语言生成计划、第二执行器或自动重放。静态图审、局部构建与单元不代替在线插件/真实浏览器及设备验收。

实际定向单元、产物身份与剩余缺口在根待办和交接中记录。用户确认新界面后，已通过原停止入口停止后端，将本轮协议编译到标准程序，并生成配套静态前端和官方调试器包；最终保持停止，交由原入口启动。没有浏览器、真机、性能或全仓验收，构建与单元不表示实际启动和在线交互已经验收。
