# 统一插件安装前端接线

## 当前实现

- `features/plugin-installations` 负责领域安装状态、任务等待、服务器启停与浏览器生命周期；HTTP 适配直接索引生成契约。
- 安装顺序为计划、安装 Job、目录重读、启用 Job、目录重读、浏览器启动。更新和卸载先清理旧浏览器组件并等待服务器停用；旧修订通过 CAS 拒绝。
- `runtime.pluginInstallations` 继承现有 ApiClient 与令牌提供器。浏览器入口使用后端返回的不可变 `entry_url`，校验同源及发布修订路径；同版本不同修订先撤销旧加载器。
- 完整离线 ZIP 根目录需要 `release.json`。本地预览切片读取 ZIP 目录及 256 KiB 以内清单，核对声明资源路径和目录大小；全包 SHA-256 使用 File stream 计算。File 原字节直接上传 `/api/v2/plugin-installations/artifacts`（4 GiB 独立存储），不进入普通产物的 64 MiB 上传端点。服务器继续流式核对资源摘要与归档。当前本地预览支持标准 ZIP，不支持分卷及 ZIP64，并明确报错。
- 市场 `release_format: 1` 通过服务器拉取清单。已安装目录按完整功能聚合，屏蔽其底层服务器、浏览器组件的重复安装项。旧格式组件包继续兼容。

## 集成接缝

以下文件有用户并行界面修改，当前角色未获得页面布局和共享公共模块写权，需要主代理协调最小接线。

1. `pages/marketplace/index.tsx` 的安装判定需要同时查看 `market.installations`；完整功能卸载调用 `market.removeInstallation(id, revision)`，启停调用 `market.setInstallationEnabled(id, revision, enabled)`，不能转交旧 `pluginPackages.remove`。
2. 功能卡片根据 `entry.details.release_revision` 与 `release_enabled` 显示启停按钮；保留用户当前样式和布局。配置入口根据安装记录的组件列表选择目标，传真实组件 ID 给既有配置对话框，不以功能 ID 代替组件 ID。
3. `plugins/manager.ts` 需要可选的按插件构建 HostContext 端口。只有对应浏览器组件的业务提交带固定发布头，不修改共享 HostContext 或共享 ApiClient 的全局状态。
4. `services/api/types.ts` 的 RequestSpec 与 `client.ts` 增加可选请求头后，可通过包装现有 client.call 的 endpoint.request 注入 `x-deviceforge-plugin-release`。值为 JSON 字符串 `{ "id": release_id, "revision": sha256 }`；保持当前 tokenProvider 与任务提交钩子。
5. 产品启动时调用 `runtime.pluginInstallations.restore(signal)` 恢复已启用且配置完整的浏览器组件；旧默认启用逻辑必须排除统一安装已拥有的底层组件，以免绕过发布启停意图。
6. 客户端运行状态从 `runtime.pluginInstallations.clientSnapshot/subscribeClient` 订阅。浏览器失败后调用 `retryBrowser(id, revision, signal)` 只重试本实例，不重放安装或服务器启用任务。启动恢复会继续后续功能并汇总失败。
