# 统一插件安装前端接线

## 当前实现

- `features/plugin-installations` 负责领域安装状态、任务等待、服务器启停与浏览器生命周期；HTTP 适配直接索引生成契约。
- 安装顺序为计划、安装 Job、目录重读；缺少业务配置时正常保留已安装需配置状态，配置保存后的显式启用提交服务器重新评估。更新只清理旧浏览器，宿主更新保留服务器原启停选择；仅原来启用且实际仍已启用的发布才激活新浏览器。卸载清理旧浏览器并等待服务器停用；旧修订通过 CAS 拒绝。`recovery_blocked` 不能启用、更新或恢复，HTTP 边界拒绝未知状态并保留日志标识。
- `runtime.pluginInstallations` 继承现有 ApiClient 与令牌提供器。浏览器入口使用后端返回的不可变 `entry_url`，校验同源及发布修订路径；同版本不同修订先撤销旧加载器。
- 完整离线 ZIP 根目录需要 `release.json`。本地预览切片读取 ZIP 目录及 256 KiB 以内清单，核对声明资源路径和目录大小；全包 SHA-256 使用 File stream 计算。File 原字节直接上传 `/api/v2/plugin-installations/artifacts`（4 GiB 独立存储），不进入普通产物的 64 MiB 上传端点。服务器继续流式核对资源摘要与归档。当前本地预览支持标准 ZIP，不支持分卷及 ZIP64，并明确报错。
- 市场使用发布器实际输出的 `release_format_version: 1` 标记完整发布，同时兼容早期 `release_format: 1`。通过服务器拉取清单，已安装目录按完整功能聚合，使用外显名称和描述，屏蔽其底层服务器、浏览器组件的重复安装项。旧格式组件包继续兼容。
- 配置对话框从安装组件列表选择真实 `kind/id`，交给既有配置工厂。统一启停、卸载、恢复受阻限制和单客户端浏览器重试均已接入；卸载后重读底层包和运行目录，避免旧缓存再次显示已移除组件。
- 安装任务增量读取事件，展示阶段、资源、完成字节、可选总字节及任务和日志标识；任务页也保留阶段字节详情。取消等待忽略晚到结果，不撤销或重放服务器任务。
- 真实下载进度的资源标识包含 SHA-256，允许以数字开头；前端校验对齐后端通用标识规则，拒绝路径分隔符和非法字节。
- 已安装页提供托管资源入口，先检查引用、展示服务器报告，再显式执行清理。运行、事务和恢复仍引用的资源由服务器保留；该接口不负责恢复受阻事务。

## 发布修订与启动恢复

1. `services/api/request-headers.ts` 包装现有 ApiClient，注入 `x-deviceforge-plugin-release`，值为 `{ "id": release_id, "revision": sha256 }` 的 JSON 字符串。保留令牌提供器与业务输入，不增加另一套客户端状态。
2. `app/release-requests.ts` 从现有安装快照匹配产品任务、会话创建、设备动作及提供者刷新；任务在提交钩子完成后匹配最终操作。没有归属的请求保持原路径，不额外查询安装目录。
3. `plugins/manager.ts` 通过可选 `hostForPlugin` 构造插件 HostContext，`app/release-host.ts` 固定插件加载时的发布身份。目录更新后旧浏览器仍携带旧修订；服务器拒绝时保留错误日志。共享任务钩子、取消和设备模型继续复用。
4. 产品启动先恢复统一安装，只启动目录中已启用且配置完整的浏览器组件。旧默认启用排除统一安装拥有的 `kind/id`；统一目录不可读时不绕过安装意图启动底层包。
5. 浏览器失败单独记录在客户端运行快照，通过 `retryBrowser` 只恢复当前实例；启动恢复继续后续功能并汇总失败。生产启动测试已使用市场入口和统一消息展示，旧插件页测试入口已更新。

后续会话读取、输入与关闭仍由既有会话身份和代次契约处理；HostContext 当前公开 API 没有会话入口。这部分不能表述为所有历史会话请求都携带固定发布头。

只读契约核对确认：后端 `SessionDefinition::validate` 强制会话标识使用所属插件的 `plugin.<plugin_id>.` 命名空间，因此当前会话创建的前缀匹配覆盖有效公开会话，不需要另增生成类型。生成 `PluginInfo` 已带可选 `sessions` 列表，但当前实现不依赖该列表。设备目录和提供者列表使用 GET，无需执行修订；单提供者刷新与设备动作使用 POST，已接入发布头解析。真实产品浏览器本轮仅通过 SDK 任务证明发布头，设备动作及会话仍只有前端行为测试与契约核对，不能扩写为设备或会话实机验收。

## 用户操作步骤

### 连接服务与市场

1. 在“设置”的“服务连接”中填写实际“服务地址”和需要时的“可选令牌”，点击“测试并应用”。切换服务会结束当前工作会话；源码预览常用端口为 7031，CLI 默认端口为 7030，应以正在运行的目标服务为准。
2. 在“市场发现”中填写“市场地址”，点击“保存并刷新”。此处覆盖只保存在当前浏览器，不改服务器配置。
3. 打开“资源市场”中的“发现资源”，使用“搜索市场”或“刷新”查找发布。完整功能插件以发布名称和描述展示，ID 和版本用于核对身份。

### 在线安装与配置

1. 在卡片点击“安装”打开详情，核对名称、描述、来源、版本、SHA-256 和兼容性，再点击详情中的“安装”提交。完整发布由服务器安装匹配平台的组件和工具，浏览器只加载浏览器组件。
2. 等待安装任务完成，保留失败时的任务 ID 和日志 ID。随后切换“已安装”，以卡片实际显示的“需要配置”“已启用”或“已停用”为准；任务提交成功不表示插件已能运行。
3. 点击“配置”。多个组件先选择“服务器组件 · <id>”或“浏览器组件 · <id>”，单个组件直接进入表单。字段来自插件声明；显示“此插件无需配置。”表示该组件未声明可编辑字段。
4. 按表单策略点击“保存配置”或“保存并重载”；已保存但待重载时可点击“应用已保存配置”。“重新读取”读取当前值，“恢复默认”恢复插件声明的默认值。配置不兼容时按错误修正或恢复默认，并可复制日志 ID 排查。
5. 原状态为“需要配置”时，补齐并保存后关闭对话框，点击卡片“启用”，由服务器重新评估。后续可用“停用”和“启用”管理运行状态。

服务器已启用而当前浏览器激活失败时，卡片提供“重试本客户端”，只恢复此浏览器实例。显示“恢复受阻”时应按服务器恢复日志处理，再刷新目录；重复安装不能代替事务恢复。卸载使用卡片“卸载”和弹窗“确认卸载”，完整发布卸载后保留用户配置。

### 完整离线包首次导入

1. 从发布者取得发布器生成的完整离线 ZIP。ZIP 根目录必须包含 `release.json` 及其声明的全部资源；当前上限为 4 GiB，不支持 ZIP64 或分卷。发布器入口见 [完整发布打包说明](../../../scripts/plugin-releases/README.md)。
2. 在“资源市场”点击“本地导入”，保持“插件便携包（ZIP / TGZ）”，点击“选择插件便携包”选择该 ZIP，再点击“检查导入内容”。
3. 核对预览中的发布名称、ID、版本、组件和工具数量、文件大小、全包 SHA-256，然后点击“确认导入”。服务器仍会独立校验资源摘要、归档和入口。
4. 等待成功后点击“完成”，在“已安装”检查实际状态，并按上述步骤配置和启用。点击“取消当前等待”只结束客户端等待，服务器提交可能已生效，应先刷新任务与安装目录再决定后续操作。

当前界面的“本地导入”只提交安装，不提供对已有完整发布的离线更新；此场景使用下节 CLI 的 `plugin update`，以保留配置和启停选择。旧单组件 ZIP/TGZ 继续走兼容安装，不等同于包含所有依赖工具的完整发布。

完整发布在市场卡片和详情中显示“下载发布清单”，下载的是 `release.json` 清单资源，不会自动组合完整离线 ZIP；旧独立资源仍显示“下载”。需要离线搬运时应取得发布器打包的完整离线包。“上传发布”用于向市场发布资源，首次安装无需经过此入口。

### 在线更新

1. 市场发现或已安装卡片读取到更高语义版本时，会显示“可更新”及“更新”入口。点击卡片“更新”打开详情，核对目标版本后再点击详情“更新”。同版本和更低版本不提供此入口。
2. 更新保留用户配置及原来的启停选择，完成后重新检查卡片状态。新版本要求补充配置时，先完成配置再显式启用。
3. 若返回 409 修订冲突，应刷新安装目录核对当前版本与状态，不能继续用旧修订覆盖。恢复受阻的安装需先处理服务器恢复问题。

### CLI 安装、更新与资源清理

CLI 连接已经运行的 DeviceForge 宿主，不会再启动第二个后端。`--api-url` 默认读取 `DEVICEFORGE_API_URL`，未设置时为 `http://127.0.0.1:7030`；请把它改成目标宿主的实际地址。安装位置是服务器用户根目录，客户端的 `--data-dir` 不决定远端安装位置。

```powershell
deviceforge plugin install <release.json完整URL> --api-url http://127.0.0.1:7030 --release-id <发布ID> --release-version <版本> --manifest-sha256 <清单原字节SHA-256>
deviceforge plugin install <完整离线ZIP> --api-url http://127.0.0.1:7030
deviceforge plugin list --api-url http://127.0.0.1:7030
```

线上 `release.json` URL 必须同时填写 `--release-id`、`--release-version` 和 `--manifest-sha256`；摘要是清单原字节的 SHA-256。离线 ZIP 不混用这三个市场身份参数，普通文件上限为 4 GiB。命令会等待服务器任务完成，只有任务为 `succeeded` 才返回成功；失败或取消应根据任务和日志 ID 排查。按 Ctrl+C 只结束本地等待，服务器任务仍可在任务页查看。

```powershell
deviceforge plugin update <发布ID> <release.json完整URL> --expected-revision <旧安装修订SHA-256> --api-url http://127.0.0.1:7030 --release-id <发布ID> --release-version <新版本> --manifest-sha256 <新清单原字节SHA-256>
deviceforge plugin update <发布ID> <完整离线ZIP> --expected-revision <旧安装修订SHA-256> --api-url http://127.0.0.1:7030
```

这里的 `--expected-revision` 是旧安装修订，`--manifest-sha256` 是新清单摘要，二者不能互换。配置、启停和卸载仍在当前市场“已安装”页面执行；CLI 没有对应的完整发布配置、启停或卸载子命令。资源清理先预览，再显式确认：

