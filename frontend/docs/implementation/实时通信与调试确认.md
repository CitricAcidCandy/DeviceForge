# 实时通信与调试确认

本文记录宿主公共实时连接、调试桥、任务历史订阅及动作检查点的前端契约。实现说明与验证证据分开记录；真实通信和服务端验证由本轮主代理最终汇总。

## 职责与连接归属

| 单元 | 职责 | 状态归属 |
| --- | --- | --- |
| 宿主实时通信层 | 能力探测、按需加载客户端库、共享连接、命名空间租约、有界等待与释放 | 连接状态和传输预算 |
| 调试桥 | 浏览器实例登记、会话选择、目录变化、命令领取与回执核对 | 当前页面的实例、在途命令和待确认回执 |
| 任务消费 | 接收变化提示，再通过原任务接口读取快照 | 原任务存储和各业务展示模型 |
| 本地调试执行器 | 执行动作并读取明确检查点 | 选定插件代次、挂载根和公开数据源 |

每个前端宿主运行实例创建一份实时客户端，通过同一个 Socket.IO Manager 复用底层 WebSocket。`/debugger` 与 `/tasks` 是独立命名空间，消费者各自持有租约。它们不会互相执行启停、建立第二套任务存储或将业务状态放进公共传输层。不同页面或不同宿主运行实例各有自身生命周期。

调试功能失败不应阻塞工作台初始化、任务消费和普通 HTTP 业务。停用一个业务插件只释放它的订阅；仍有消费者时公共连接继续存在。最后一个消费者退出后，宿主撤销所属连接、等待和定时器。调试面板的显示与收起不接管宿主 MCP 桥的独立生命周期。

## 协议选择与兼容

实时能力通过 `GET /api/v2/realtime/capabilities` 读取。当前客户端要求协议版本 `1`、路径 `/api/v2/realtime/socket.io`，以及 `/debugger`、`/tasks` 两个命名空间。能力响应只说明协议可用；实际连接就绪仍由命名空间状态通知确认。

前端使用 `socket.io-client 4.8.4`，仅启用 WebSocket，不启用 Socket.IO 的 HTTP 轮询传输。客户端库在首次消费时动态加载，能力探测与加载都有期限。

| 情形 | 调试桥行为 | 任务消费行为 |
| --- | --- | --- |
| 宿主声明支持且实时连接就绪 | 使用 WebSocket 登记、推送及回执 | 订阅变化，读取快照后停止周期刷新 |
| 能力接口明确返回 `404`、`405` 或 `501` | 兼容原 HTTP 调试桥 | 保留原 HTTP 查询与刷新节奏 |
| 未注入宿主实时客户端的独立旧装配 | 使用原 HTTP 调试桥 | 按原装配消费任务接口 |
| 网络失败、实时协议不匹配或库加载失败 | 报告当前连接不可用，不据此启动竞争的 HTTP 调试桥 | 保留已有任务内容，使用 HTTP 降级读取 |
| 已选 WebSocket 后临时断线 | 在有界窗口内恢复并核对原命令 | 按原节奏降级，恢复后补查快照 |

正常连接且任务快照已同步时，空闲期间不需要周期性 HTTP 调试心跳或任务列表请求。首次能力探测、初始快照、变化后的读取和断线降级仍会使用 HTTP。WebSocket 自身的 Ping/Pong 保活继续存在，不能将“没有周期性 HTTP”理解为“没有任何心跳包”。

旧 HTTP 桥的轻量目录心跳及命令领取逻辑保留，仅服务兼容路径。新桥的插件目录在登记和目录变化时上报；没有变化时不重复上传完整目录。

## 有界资源与断线恢复

以下为当前默认协议和前端调度约束，不是 CPU、内存占用或延迟的实测承诺。

| 项目 | 约束 |
| --- | --- |
| 服务端 Ping 间隔／Pong 超时 | 25 秒／10 秒 |
| 能力探测、库加载、连接及调试登记 | 单次最多等待 5 秒 |
| 重连退避 | 0.5～5 秒、20% 抖动；客户端 Manager 最多尝试 12 次，单轮恢复窗口最多 60 秒 |
| 前端待确认请求 | 两命名空间共享最多 8 条、累计正文最多 8 MiB |
| 单条传输消息 | 最多 1 MiB＋16 KiB；业务正文继续服从原业务限制 |
| 调试命令并发 | 最多 4 项；待补交回执也占用可用槽位 |
| 本页命令去重记录 | 最多 4096 项，不通过清空记录自动重放旧动作 |
| 请求回执等待 | 默认 5 秒；原调用取消或更短期限可提前结束等待 |
| 任务变化通知 | 服务端按 100 毫秒窗口合并提示，不传输完整任务正文 |

前端发送不启用库自动重试或离线发送缓冲。容量超限在发送前拒绝；已经发送后发生超时，只能说明回执尚未确认，不能推断动作没有发生。两个命名空间的观察者异常在所属回调内收敛。

同页面恢复时保留实例恢复凭据、已见命令编号、在途执行及待确认回执。重连核对原命令终态，必要时只补交原编号的结果；已交付动作不因重连再执行，原期限不重新起算。过期实例或宿主重启需要新身份，旧实例的待确认状态不能搬入新实例。页面刷新也会建立新页面身份。

取消和关闭只能结束宿主等待并阻止晚到结果写入新代，不能证明可信 JavaScript 回调的实际副作用已经停止。结果未知时读取原命令状态，不通过重复点击补证。

默认免鉴权、令牌可选的部署规则保持。令牌只由宿主提供器交给连接认证，不放进 URL、业务通知或插件接口；任务命名空间支持普通局域网消费，调试命名空间沿用本机连接检查。

## 公开任务历史订阅

`HostContext.taskHistory` 继续提供 `list`、`get`、`events`。新增可选的 `subscribeChanges(listener)` 返回释放函数，插件只消费这个公开能力，不读取 Socket、Manager、恢复凭据或令牌。

通知形状如下；其中修订是宿主提供的不透明字符串：

```ts
interface TaskHistoryChange {
  readonly state: 'ready' | 'changed' | 'unavailable';
  readonly revision: string | null;
  readonly reset: boolean;
}
```

| 字段或状态 | 消费语义 |
| --- | --- |
| `ready` | 订阅通道可用，应读取当前快照；不表示本地任务内容已经同步 |
| `changed` | 任务历史可能变化，合并安排一次只读刷新 |
| `unavailable` | 保留已有内容，按原刷新节奏通过 HTTP 补查 |
| `revision` | 用于辨识变化提示；可以为空，不解析为时间、不跨服务重启排序 |
| `reset: true` | 需要重新读取快照，不能仅凭本地修订推断没有遗漏 |

通知不携带任务列表、进度正文、结果或逐条事件，也不保证每次存储变化对应一条独立通知。任务存储成功后产生变化修订，多个变化允许合并；原 HTTP 查询及事件序列仍是读取具体记录的入口。

消费者按以下顺序处理：

1. 先登记订阅，再读取初始快照。订阅回调可能在登记期间同步触发，初始化过程也必须接受状态变化。
2. 一次只保留一个在途快照读取。读取期间收到变化只标记待刷新，不反复撤销已有读取；完成后仍有变化则继续补查。
3. 只有通道可用且快照同步成功后，才停止降级定时器。连接恢复本身不能替代补查。
4. `subscribeChanges` 缺失、登记抛错、收到 `unavailable` 或快照读取失败时，保持原 HTTP 降级行为。
5. 卸载时释放本消费者订阅、读取与定时器。释放一个消费者不能关闭其他消费者仍在使用的公共连接。

官方任务展示与兼容入口复用宿主注入的订阅，不自行创建 Socket.IO 客户端。前端公共刷新模型负责快照竞争和降级调度；新插件可按相同语义通过公开 SDK 实现自身展示。

### 插件作用域中的订阅保留与回收

宿主注入订阅之后，插件作用域适配也必须保留这个可选方法。只转发 `list/get/events` 会使官方任务插件误判宿主没有推送能力，持续走 HTTP 刷新。当前 `scopedTaskHistoryAccess` 仅在上游提供时透传 `subscribeChanges`，保留上游方法调用归属，并使用本作用域的 `current()`、取消信号和 `track` 管理订阅。

登记和通知都检查当前作用域，已释放的订阅不再通知，旧作用域保留的函数引用不能登记新消费者。消费者同步抛错在自身回调中收敛；手动释放、作用域关闭或父信号取消只撤销所属订阅，兄弟消费者继续工作。

清理归属在调用上游订阅前登记。若上游同步首条通知导致作用域关闭，返回句柄时也立即释放，并将异步释放纳入作用域排空；不能因为句柄尚未赋值而漏掉回收。订阅登记失败仍允许后续独立读取或重新登记，不留下失效监听。

## 动作参数与结果检查点

MCP 的 `deviceforge.debug_ui_tree/query/diff/assert/action` 使用当前调试会话。顶层是 `session_id` 和 `parameters`，挂载根放在 `parameters.root_id`，动作放在 `parameters.action`，检查点 `expect` 与 `action` 同级。

示例中的会话、根、节点引用和数据源都必须替换为本次公开查询返回的实际值。一次确认格式后复用，不反复读取整份目录。节点引用包含 `id`、`generation`、`revision`，不要只传节点编号；多个挂载根必须明确选择根。查询应同时限定角色与名称，并取得唯一、完整结果，避免名称相同的容器和控件混淆。

普通非敏感输入的填写及界面回读示例：

```json
{
  "session_id": "当前会话标识",
  "parameters": {
    "root_id": "当前挂载根标识",
    "action": {
      "type": "fill",
      "target": { "id": "当前输入节点标识", "generation": 1, "revision": 1 },
      "value": "示例名称",
      "confirmed": true
    },
    "expect": {
      "kind": "ui",
      "assertion": {
        "condition": "value_equals",
        "query": { "role": "textbox", "name": "名称" },
        "expected": "示例名称"
      },
      "timeout_ms": 3000
    }
  }
}
```

`confirmed` 继续位于动作内。副作用未知时，还需调用者独立明确授权 `action.allowUnknownSideEffects`；不能把这个字段当成所有动作的默认补丁。真实设备、禁用、隐藏、校验失败及表单提交等原保护继续生效。

普通控件的 `fill/select` 即使没有 `expect`，也会在派发后比较本次期望与原生控件状态，回执可包含 `scope: "control"` 的检查结论。`value_equals` 的 `expected` 为字符串；`selected_equals` 为无重复项的字符串数组，按集合比较。控件断言要求查询唯一且完整；纯历史快照不能代替当前控件回读。

密码、凭据、文件、隐藏、可编辑或不透明控件不提供普通值比较。检查只返回匹配结论，不把当前控件值或调用者输入加入树、日志和回执。

业务检查使用已登记数据源的明确字段。以下示例仅适用于目标已经公开具有 `running` 字段的状态源，不代表投屏插件已提供此能力：

```json
{
  "session_id": "当前会话标识",
  "parameters": {
    "root_id": "当前挂载根标识",
    "action": {
      "type": "click",
      "target": { "id": "当前按钮节点标识", "generation": 1, "revision": 1 },
      "confirmed": true
    },
    "expect": {
      "kind": "data",
      "source_id": "从当前数据目录取得的状态源标识",
      "query": { "view": "public" },
      "checks": [{ "pointer": "/running", "equals": true }],
      "timeout_ms": 3000
    }
  }
}
```

`query` 是可选项，只传该数据源公开接受的查询；不支持这个查询时应省略。`checks` 必须有 1～16 项，`pointer` 是以 `/` 开头、最多 1024 字符的 JSON Pointer，支持 `~0`、`~1` 转义及数组索引，只检查明确字段；空指针不能比较整个公开投影。等值比较不依赖对象键顺序，数组仍按顺序比较。不执行脚本，不访问未登记内部对象，不比较敏感或已脱敏字段。

`expect.timeout_ms` 默认 3000、范围 0～10000 毫秒，并消耗原命令剩余预算。它只等待公开只读证据，不重新派发动作；原调用、插件代次或会话撤销时也结束检查。非法 `expect` 在动作派发前拒绝，预算结束后的晚到读取不会将结果改成通过。

| 回执字段 | 可以确认的事实 |
| --- | --- |
| `status: "dispatched"` | 合成事件或接口调用已经派发 |
| `verification.scope: "control"` | 本次期望与普通原生控件回读的比较 |
| `verification.scope: "ui"` | 本动作声明的当前挂载根界面检查点 |
| `verification.scope: "business"` | 本动作声明的已登记业务投影字段等值检查 |
| `verification.status: "passed"` | 对应范围的检查点满足期望 |
| `verification.status: "failed"` | 取得了与本次期望不符的控件证据 |
| `verification.status: "unavailable"` | 缺少端口、来源或字段，或目标敏感、不唯一、不完整，无法确认 |
| `verification.status: "timed_out"` | 原调用或检查预算结束，未能确认期望 |

动作回执保留原 `status` 和 `businessOutcome: "unknown"`，新增的 `verification` 只说明对应检查范围。界面或控件通过不证明完整业务成功；业务字段通过也只覆盖调用者声明的字段。没有投屏状态等公开回读能力时，报告具体缺口和结果未知，不追加日志遍历、视觉审核、设备探测或重复点击来替代证据。

## 批处理与证据关联

`deviceforge.debug_guide` 的 `quickstart/ui/automation` 主题用于取得短指南与参数示例。`deviceforge.debug_automation_run` 复用同一本地执行端口，一次提交最多 32 步，所有步骤共享原 30 秒总预算，先校验整份计划，再执行第一步。

每步使用 `id`、`tool`、`parameters`，可选 `label` 和 `bind`。步骤中的 `tool` 使用 `ui_query`、`ui_action` 等短名，不带 MCP 工具前缀。计划确认不能替代每个变更动作的确认及未知副作用授权；当前契约中的 `ui_action` 步骤即使是只读 `wait`，仍要求计划 `confirmed: true`。

需要从前一步绑定节点时，在同一计划内使用下列结构。前置查询必须返回唯一、完整节点；已有明确挂载根时继续复用：

```json
{
  "confirmed": true,
  "steps": [
    {
      "id": "find-name",
      "tool": "ui_query",
      "parameters": {
        "root_id": "当前挂载根标识",
        "query": { "role": "textbox", "name": "名称", "limit": 2 }
      }
    },
    {
      "id": "fill-name",
      "tool": "ui_action",
      "parameters": {
        "action": { "type": "fill", "value": "示例名称", "confirmed": true },
        "expect": {
          "kind": "ui",
          "assertion": {
            "condition": "value_equals",
            "query": { "role": "textbox", "name": "名称" },
            "expected": "示例名称"
          }
        }
      },
      "bind": { "target_from_step": "find-name" }
    }
  ]
}
```

上例是 `automation_run` 的 `parameters`，外层仍需当前 `session_id`。节点绑定继承查询根，不能再提供固定 `action.target`，也不能指定不同根。数据修订绑定只能引用同一来源的前置 `data_read`，与固定 `expected_revision` 互斥。后半段参数错误时，整份计划在派发第一步之前拒绝。

批处理结果将验证保留在对应动作步骤，即使大结果被裁剪，也保留该步骤的验证摘要。末尾独立 `ui_assert` 不能替前面未验证的动作作证；只读查询或等待也不能让整个计划变成业务成功。验证不可用或超时会停止后续步骤，不自动重放；明确失败是否停止继续服从原 `stop_on_failure` 策略。整个计划的 `business_outcome` 保持 `unknown`，`verified` 仅汇总对应动作检查点的覆盖情况。
