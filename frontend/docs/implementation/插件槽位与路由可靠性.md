## 槽位释放与排队

- 原问题是槽位释放已在串行队列内，却等待再次排入同一队列的 `lease.dispose()`，造成自身等待。
- 队列改为按槽位 ID 隔离，同名槽位的登记、获取、释放继续串行；一个槽位慢清理不阻塞另一个槽位。
- 每个租约保存内部释放入口，队列内直接调用内部入口；对外 `dispose()` 才排队。释放移除插件根及取消监听，不重入队列。
- 槽位释放闭包绑定本次 `SlotRuntime`，不按名字查找新实例；重复调用返回同一释放结果，失败结果也不改成假成功。
- 旧租约只修改所属槽位实例。释放槽位先禁止默认渲染重建，再释放租约及默认渲染器。
- 关闭立即禁止新获取、移除已有插件根，并等待已排队工作及各槽位内部释放收口；保留清理失败汇总。

## 统一派生接口

入口保持为 SDK 的 `src/plugin-sdk/slots.ts`，供注册表与管理器直接消费；本批不修改 SDK index。

```ts
slotKey(value: string): string
pluginSlotKey(pluginId: string): string
pageSlotId(pluginId: string, page: string): string
```

- `pluginSlotKey` 对符合 `^[a-z][a-z0-9._-]{0,99}$` 的合法插件 ID 原样返回，包含完整 100 字符；不得用页面片段的 64 字符上限截断身份。
- 非法展示名输入继续走原 `slotKey` 兼容规则。该兼容行为不是插件 ID 合法性校验，注册表仍需检查真实声明。
- `slotKey` 继续负责页面片段：去首尾空白、转小写、替换非法字符、必要时补前缀并限制至 64 字符。该规则不保证不同原始页面名不会碰撞。
- `pageSlotId(pluginId, page)` 等价于 `page.${pluginSlotKey(pluginId)}.${slotKey(page)}`。
- 产品层 `pluginRoute(pluginId, page)` 使用同一插件身份规则；`routeHash` / `parseProductRoute` 往返后，`routeSlotId` 与模块的 `pageSlotId` 保持一致。
- 注册表可直接用 `pageSlotId(pluginId, contribution.route)` 校验归一化页面槽位冲突；不要只比原始 route，也不要对不同插件的同名页面作全局禁止。

主代理需同步宿主清单 `src/app/product/slots.ts`（无 x）的 `isKnownSlot` 页面白名单：插件 ID 上限为 100，页面片段上限仍为 64；该文件不属于本批独占写集。

## 路由与接管状态

- App 通过稳定订阅消费默认插件启用快照。`idle` / `running` 阶段不把暂未出现的插件直达地址改成设备页；`completed` 后仍缺失才回设备。
- 启动完成且页面存在时保留地址；后来卸载、禁用并撤销模块目录后，当前路由回设备。
- 已访问宿主页的缓存行为不变；不增加新界面或修改 Tailwind 样式。
- fallback 只在替换贡献真正挂载成功后让位。登记失败、挂载等待或失败时保留宿主内容，失败同时显示原有告警。
- 替换贡献的身份包含 `pluginId + generation + kind + id`，并校对槽位 ID、槽位宿主和扩展入口对象；同 ID 热重载不复用旧代成功状态。
- 追加贡献的 effect 键同样包含 `pluginId + generation + id`。旧代完成或失败不能通过已撤销的 effect 改写新代状态。
