## 范围与职责

本批继续全 Web UI 插件化补全，基线为 `8003be3`。采用 architecture-first：不改运行内核、服务总线或 Job，不把 Cordis 迁移混入发行改造。业务安装包和开发依赖包分别交付，不能把 SDK 或业务辅助库 TGZ 当成已安装的业务功能。

构建与打包分开：公开构建工具负责浏览器 ESM、Tailwind、CSS 与 Worker；原单清单 CLI 负责身份包装、组件 TGZ 与完整发布。没有新增安装器、联网发布流程或运行服务。

| 单元 | 输入与输出 | 明确边界 |
| --- | --- | --- |
| `workspace-release-inputs.ts` | 开发清单、源码与真实 TGZ，输出来源和包内模块 | 只做读取、身份和路径校验；不加载业务 |
| `workspace-release-packages.ts` | 工程显式本地依赖，输出已发行公共 ESM 和声明 | 按依赖顺序准备；同名不同来源不静默替换 |
| 独立 `plugin-tools` 包 | 工程、公开依赖、主题文本，输出浏览器模块和资源 | 不读取宿主源码或工程 Vite 配置，不负责安装和身份 |
| `workspace-plugin-entry.ts` | 原插件工厂，输出样式生命周期薄包装 | 身份仍由 CLI 注入；激活失败和停用释放样式 |
| `browser-bundle-references.ts` | JavaScript、CSS 文本，输出静态引用 | 纯解析，不访问文件或执行脚本 |
| `browser-bundle-closure.ts` | 构建目录与引用，输出资源摘要和未确认项 | 不把静态通过当成浏览器、样式或设备验收 |
| `build-workspace-plugins.ts` | 动态发现的工程，输出独立发布及最终字节报告 | 不改源清单、数据、端口和运行宿主，不启停用户服务 |
| `workspace-release-resume.ts` | 整批来源基线、已构建工程与最终归档，输出可复用判定 | 不自动接纳变化，不重建已成功包，不把旁路 TGZ 当成最终 ZIP |
| 既有 `plugin pack` | 单清单和实际构建文件，输出组件与完整发布 | 不编译、不自动安装、不访问市场 |

## 官方浏览器发行流程

运行前须取得已经构建的公开 SDK、HTTP 类型、清单规则和插件工具本地 TGZ，以及工程声明的第三方依赖。当前均未发布到 registry，不能只给一个包名让开发者猜下载地址。

在前端工程执行：

```powershell
npm run pack:workspace-plugins
if ($LASTEXITCODE -ne 0) { throw "官方浏览器插件发行失败" }
```

入口按 `plugins/*/manifest.json` 动态发现来源，没有第二份业务清单。输出写入 `frontend/artifacts/` 的独占新目录，不覆盖此前交付。普通新增浏览器插件沿相同公开工程结构进入发行，不修改宿主业务代码或本脚本的业务枚举。

1. 冻结各工程的单清单、开发依赖及本包资源身份。
2. 真实解开 SDK 等公共 TGZ；业务辅助库、设备模型和设置模型按显式依赖先发行，再从归档消费。
3. 将本次源码复制到隔离工程，由公开工具编译；不使用宿主的源码别名或开发条件。
4. 附加样式归属入口。原 `index.js` 与工具报告不改写；源清单只在隔离工程程序化派生，CLI 再从同一身份生成最终包装。
5. 检查模块、延迟块、Worker、CSS、字体和图片的静态闭包。页面共享 React 可以保留裸导入，Worker 不继承页面 importmap。
6. 只把实际运行资源交给原打包器，不将包含本机绝对路径的开发归属报告带进安装组件。
7. 再核对源身份和最终 ZIP 字节，生成 `build-report.json`。失败保留本次诊断，不继续签发完成报告，也不清空用户目录。

`development-packages/` 中是独立开发库及主题输入；`releases/` 中才是各官方浏览器组件和完整发布。它们用途不同，不能相互替代。`builds/` 为本次隔离工程和闭包证据，不是另一套运行宿主。

### 显式接续与 Windows 目录提交

首次运行在构建前以独占写入保存 `source-baseline.json`。失败后可对同一个输出目录执行：

```powershell
npm run pack:workspace-plugins -- artifacts/本次失败目录 --resume
if ($LASTEXITCODE -ne 0) { throw "发行接续未完成，查看保留的诊断" }
```

接续先核对全部来源集合、源码和清单，包括尚未开始构建的工程；公共依赖、工具 TGZ 及主题也须与旧批次字节相同。已构建且相同的工程不重新编译，已成功的发布不重新打包。复用发布时读取最终 ZIP 的真实 `release.json` 和组件 blob，核对身份、大小、摘要及 dist，而不只比较旁路文件。半成品只有在来源相符、实际构建闭包完整且暂存清单未被未知修改时才完成封口。

旧批次没有初始来源基线时默认拒绝接续。仅在明确接受其历史证据缺口时追加 `--adopt-current-inputs`，记录 `origin: explicit_legacy_adoption` 与真实建立时间；它不能证明尚未构建工程在更早运行时未变化，不能补造初始快照。此后继续按该已落盘基线拒绝跨运行变化。最终报告保存同一来源说明。

Windows 最终目录提交仅在 `EPERM/EBUSY` 时有限重试 rename：总等待最多 10 秒、最多 8 次，每次核对独占暂存身份、同父目录及目标不存在。取消、来源被替换、目标冲突或其他错误立即结束，不重新执行构建或打包，不覆盖目标，也不通过杀用户服务规避占用。现有正常路径流关闭单元通过，但现场占用来源尚未确认。

本批另补显式准备协议：`deviceforge plugin pack manifest.json --out 新目录 --prepare-only true`只返回`prepared`和实际准备回执。让该进程退出后，`deviceforge plugin finalize 回执.json`先核对同一真实父目录、暂存dev/ino、全部成员快照、发布清单及最终ZIP，再执行一次有界提交；源已消失且目标完全一致时只观察并报告原提交完成。失败、取消或未知结果保留回执和目录，不自动重打包。官方发行器复用该流程，不另设打包或安装协议。

只有显式准备的最终提交在Windows明确EPERM/EBUSY后才调用固定PowerShell 7辅助脚本；不修改执行策略、不执行拼接文本。脚本用`Directory.Move`避免移入并发出现的已有目标，不合并或覆盖。无论目录提交采用哪条路径，最终仍须核对完整成员字节；原生等待未知不按EPERM再次派发。准备3项、原生提交2项、原有提交兼容5项定向单元通过，发行strict通过；源码CLI帮助和文档已同步，既有CLI TGZ未重建。

TAR 与 ZIP 读取收尾在请求销毁解压流后，显式等待本次文件输入 `close`，固定五秒上限；超时报告未确认，不只看 `destroyed` 标记。等待器无论成功或失败都撤销自有监听和计时器，原调用方监听保持不变。两项延迟文件关闭单元先复现旧缺口，另三项 helper 单元验证边界；这修复了真实资源归属问题，但不证明其是现场偶发 `EPERM` 的唯一来源。

## 公开主题与资源

独立工具接受公开主题文本，不导入宿主私有 CSS。发行器仅派生现有 `@theme inline` 命名令牌和显式 `.dark` 变体，生成 `deviceforge-ui-theme.json`；不复制宿主业务选择器。

生成的 `styles.js` 无导入时 DOM 副作用。样式通过实际 Document 的引用计数获取，释放句柄登记到插件生命周期；全局 Tailwind 层也覆盖 Radix 门户。卸载只撤销所属样式，不删其他插件资源。

未知计算式导入、无法确认的 Worker 根或外部 CSS 资源不能被静态检查伪装为闭包通过。业务运行期从用户输入取得 URL 属于另外的公开调用行为，不在静态资源完成证据中。
