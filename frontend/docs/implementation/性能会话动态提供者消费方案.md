# 性能会话动态提供者消费方案

## 状态与依据

本文后文保留前端消费方案初稿；2026-10-13 当前源码已完成本节记录的消费与公开服务接线，不新增 HTTP 路由、DTO、操作名或 SDK 方法。本文不表示性能会话热卸载、平台迁出、常驻连接、真机或产品 UI 已完成；后端动态来源与真实设备证据分别验收。

### 当前接线与公开服务（2026-10-13）

`createHttpPerformance` 复用 `shared/jobs` 提交与查询网关，运行时实例以 `runtime.performance` 持有并随 `runtime.dispose()` 释放等待与订阅。app 注册公开 `host.performance` 服务版本 `1`，可信浏览器插件通过已有 `context.extensions.callService('host.performance', '1', request, signal)` 调用，不引用宿主私有模块。

| action | 请求字段 | 返回的 `HostResult.data` |
| --- | --- | --- |
| start | `{action:'start',input:{target:{device_id,package},interval_ms,duration_secs}}` | 直接会话对象 |
| inspect/pause/resume/stop | `{action,input:{session_id}}` | 直接会话对象 |
| samples | `{action:'samples',input:{session_id,after,limit}}` | 会话、样本页与 next_after |
| list | `{action:'list',input:{after_id?,limit}}` | 历史列表与 next_after_id；省略 after_id 发送 null |
| capabilities | `{action:'capabilities'}` | 已校验能力消费视图 |

请求最多 16 KiB、返回最多 4 MiB，拒绝未知字段、循环/非有限数值及非普通 JSON 对象。现有性能规则继续校验会话 ID、创建参数、分页游标与对应业务结果，普通 sample 的 result/artifacts 封套不能被当作会话成功结果。`capabilities` 保留 `metrics/fps/scope`，将服务器 `source/max_samples/sample_timeout_ms` 映射为已有消费视图 `sourceLabel/maxSamples/sampleTimeoutMs`；来源标签不充当设备引用或当前可用性证明。

服务 `logId` 保留最后真实提交或查询响应关联；失败任务保留 `PerformanceJobFailure` 的 Job、原错误文本、提交日志与最终查询日志，等待失败保留已知 Job 与 cause。HTTP 错误沿既有公开错误映射，不把任务编号当日志编号。插件代次撤销和 runtime 关闭只取消客户端等待、订阅及挂载上下文，不自动 stop、不取消已提交服务器 Job、不把客户端取消解释为服务器回滚。

定点回归位于 `tests/performance-http-consumption.test.ts` 与 `tests/performance-runtime.test.ts`，覆盖八操作 wire、真实最终日志、非法动作/字段/JSON、失败任务、取消、卸载代次和 runtime 关闭。严格检查、全量门禁、真实服务与分发由主代理集成；客户端行为证据不替代来源排空、SQLite 持久化、真机指标或产品 UI 验收。

依据为当前源码与 [平台适配器迁出实施](../../../backend/docs/implementation/平台适配器迁出实施.md)、[性能会话接口](../../../backend/docs/contracts/性能会话接口.md)、[性能采样插件协议](../../../backend/docs/contracts/性能采样插件协议.md)。设备原始状态的待冻结设计仍独立维护，本文不修改前一批已冻结文件。

## 当前可确认的消费基础

- 后端通过共享任务执行器贡献 `android.performance.start/inspect/pause/resume/stop/samples/list/capabilities`，没有性能专用会话 HTTP 路由。前端默认 v2 客户端仍走现有 jobs；后端接口文档中的 v1 示例不能据此成为新增路由或回退策略。
- `PerformanceTarget` 当前只有 `device_id/package`；`PerformanceSession` 返回 `id/request/state/revision/samples/started_at/updated_at/error`。设备完整引用、采样源 owner/generation 未进入此会话公开模型。
- 当前服务持有启动时装配的单一 `PerformanceProbe`。配置的性能插件被列入 `PluginService.protected`，运行中卸载会拒绝；未配置仍有内置 ADB 回退。两者是待迁出的现状，不能称为动态提供者已经接入。
- 前端尚无独立性能 feature 或类型化性能 SDK。公开 `HostContext` 的操作目录、`submit/getJob/cancelJob` 可传标准 JSON；`Job.result` 仍为 `JsonValue`。生成文件虽含 `PerformanceSession/PerformancePage/PerformanceSessions`，现有任务适配器没有因此自动校验性能结果。
- `HostContext.devices` 为 SDK v2 可选扩展，设备引用为 `providerId/generation/localId`。它与操作目录已有独立失效、取消和订阅机制，但没有性能会话状态推送或性能专属消费者状态。
- 当前会话状态为 `running/paused/stopped/completed/failed/interrupted`；暂停和控制通过服务端 revision 拒绝旧采样，历史保留在宿主存储。启动 Job 成功只表示会话创建成功，不表示后台采样结束。

公开 SDK 仅有操作、任务、设备与贡献访问入口。app 的服务器插件和在线包管理用例不能写成插件已获得全套管理 API；本方案也不向插件暴露服务令牌、采样工具、本机路径或浏览器 shell。

## 会话绑定与代次边界（待冻结）

迁出门禁要求会话绑定当次设备引用和采样源 owner/generation，每次采样走宿主共享设备准入。前端建议保存服务器实际返回的绑定，不从裸设备 ID、平台名、目录顺序或当前全局选择反推。

| 标识 | 消费职责 | 禁止混用 |
| --- | --- | --- |
| 会话 ID 与 revision | 会话身份、控制后状态与旧采样版本判断 | 不是 Job ID、日志 ID，也不是浏览器请求序号 |
| 设备 `providerId/generation/localId` | 区分同名设备和设备提供者代次 | 不能只凭 `localId` 合并设备或迁移会话 |
| 采样源 owner/generation | 绑定服务器贡献的当代入口，卸载后拒绝旧引用 | 采样源不必与设备提供者相同，不能默认共用一套代次 |
| 浏览器插件 ID 与运行代次 | 约束消费者请求、订阅及挂载资源所有权 | 不代替服务器提供者代次或性能采样源代次 |
| 本地查询代次与选择代次 | 防止旧请求覆盖当前消费者快照 | 不作为服务器准入令牌或公开请求参数 |

设备 generation 当前是不可解析的字符串，浏览器插件运行代次是本地数值；均不推导先后关系。采样源代次的公开形状尚未冻结，不自造字符串、数字或 UUID 字段。

建议新建会话时使用当次有效设备观测并锁定绑定；切换当前选中设备只改变后续创建输入，不改已有会话目标。提供者失效立即撤销依赖旧观测的新建或恢复入口，但不删除对应历史记录，也不在重查时把旧会话重绑至新代。同一设备 ID 在两个提供者中存在时必须明确选择，不能自动猜测。

当前 start 输入拒绝未知字段，因此不得提前向它添加 DeviceRef 或 owner/generation。旧裸 `device_id` 如何通过显式旧操作绑定解析、歧义如何拒绝、旧历史缺少绑定时如何表达，交由后端契约冻结；前端不填造“当前代次”让旧数据看似具备新准入保证。

## 卸载与历史消费（待冻结）

建议将“可新建/可恢复”“会话观测”“插件清理状态”分开维护。采样源或设备提供者停止、卸载开始及目录失效时，先撤销不可靠入口，取消依赖当前观测的等待；服务器负责取消并等待受影响的 running 和 paused 会话排空。paused 不等于资源已释放。

| 场景 | 前端建议行为 | 服务端待确认边界 |
| --- | --- | --- |
| 卸载正在处理 | 不再创建或恢复相关会话；重新查询管理与会话状态 | 哪些绑定受影响、入口撤销时点及排空确认 |
| 管理等待失败或取消 | 保留本地撤销，显式重查；不假定卸载回滚，也不重放写请求 | 最终管理状态与会话状态是否已改变 |
| 资源仍为 draining/cleanup_failed | 保留可追踪信息，不发布可用新代或“完全停止” | 原有生命周期字段适用范围及恢复条件 |
| 提供者重载成功 | 刷新新目录，新会话可以使用新代 | 旧会话不得调用新代；不自动恢复或迁移 |
| 历史查询成功 | 按会话 ID 保留状态与分页样本 | 查询入口留宿主，不能随采样贡献卸载消失 |

会话终态与插件资源清理成功不是同一事实。卸载后到底返回现有哪一种终态、如何表达来源撤销或清理未确认，必须由服务端冻结；前端不新增会话状态，也不从 `stopped/interrupted` 猜测外部设备事务已释放。

历史 inspect/list/samples 建议保持宿主入口，不要求旧采样源仍已安装。旧会话缺少绑定时保留原 request 和样本，按历史记录读取，不借新目录补全权限或能力。分页游标限定在对应会话或历史列表，不跨会话复用。总磁盘配额、删除、导出及多实例共享数据库仍不是当前能力。

## 暂停、恢复与晚到结果（待冻结）

当前控制输入只有 `session_id`，没有公开的 expectedRevision 或浏览器可选择的执行预算。建议前端在同一会话内串行控制，不重复提交 pause/resume/stop；跨浏览器的竞争仍以服务器返回的状态为准。本地串行和 AbortSignal 不能替代服务器原子准入或锁。

建议消费者执行以下规则：

1. start 和控制均先获得 Job，再通过现有任务入口确认终态；queued/running 不作为新会话或控制成功发布。成功后按操作约定校验 result，失败保留 Job.error 与对应请求的日志 ID。
2. 会话选择、设备观测撤销、控制开始及消费者关闭分别更新本地请求代次，取消旧轮询。即使下游忽略取消，旧代响应不能覆盖当前会话、入口可用性或游标。
3. 已确认较新会话 revision 后，较旧响应不得回退活动状态；同 revision 的并发查询也不能以旧样本计数覆盖新快照。优先串行刷新与样本分页，不只按客户端时钟或 updated_at 猜测响应新旧。
4. pause 成功后不发布旧轮次的活动采样结果；resume 成功后采用返回的新 revision。已持久化的旧 revision 历史样本仍可读，不能把“拒绝旧采样写入”误解为删除暂停前样本。
5. 暂停时间按当前契约计入总时长，paused 可能直接到期 completed；恢复不能延长时长。首样本和恢复后的 CPU 缺测保持 null，缺少 FPS 窗口保持缺测；零帧观测与缺测分别处理。
6. 设备或采样源换代后，不自动恢复旧会话。若旧会话处于终态或无法确认原绑定仍有效，保持恢复入口撤销并重新查询；不能把新代目录视为旧绑定已恢复。

HTTP 等待取消、Job 取消与后台性能会话 stop 是三条不同路径。start 已创建会话后，关闭页面、卸载浏览器插件或取消成功的启动 Job 都不能被前端当作服务器会话已停止。控制等待取消后显式查询收敛，不自动重放 start、resume 或 stop。

建议浏览器插件/模块退出的默认行为只释放本消费者的请求、轮询、订阅及挂载资源。是否对其创建的会话额外发送 stop，属于待冻结的会话归属和产品策略；当前没有浏览器所有者字段，不按“最后一个面板退出”擅自停会话。服务器提供者卸载的排空责任独立存在，本实例前端无法强制同事浏览器关闭消费者。

当前 interval/duration、单样本 10 秒与清理窗口 2 秒分别描述采样调度和现有实现，不能组成新的浏览器 timeout 覆盖入口。迁出后的设备准入、采样截止点及合作清理预算由后端冻结，不把设备能力 executionTimeoutMs 元数据直接当会话寿命或清理成功保证。

## 公开 SDK 的最小扩展建议

建议在公开模型冻结后，沿 SDK v2 增加可选性能访问扩展；名称、方法签名、模型字段均待主代理确定。老 HostContext、仅通用任务入口的插件及没有性能提供者的宿主必须仍可工作。可选扩展存在只表示宿主支持消费协议，不等于某个采样源当前可用。

候选职责是能力发现、创建与控制、会话/样本/历史查询，以及消费者 snapshot/subscribe/dispose。设备选择复用公开设备引用，不读 features 私有状态；调用采样源遵循宿主能力目录或已冻结旧操作绑定，不按平台拼接命令、猜测 `plugin.<id>.*` 或直接调用裸 sample 冒充宿主会话。

- SDK 独立模型只表达公开消费含义；HTTP 适配器使用生成类型，app 显式映射。当前已有生成性能组件可作为现状依据，未来绑定字段未生成前不手写重复 DTO、不用断言将 JsonValue 当完整会话。
- 通用操作入口保持可用。未来类型化适配器须校验操作对应的成功结果、会话状态、revision 和分页形状；未知版本或无法识别的结果报协议不兼容，保留原始结果供通用任务消费，不伪造空成功。
- 宿主会话操作返回会话或分页对象；普通采样插件调用返回协议的 result/artifacts 包装。不能套一条固定拆包规则处理两类结果，也不绕过宿主样本验证与持久化。
- 所有异步入口合并调用方、浏览器插件运行代次和模块挂载子信号；关闭后调用应拒绝、订阅应释放。旧 HostContext 不因提供者或浏览器插件重载重新获得有效性。
- 网络或协议错误沿用 HostError 的 kind/code/status/logId；Job 失败仍由 Job.error 表达。来源撤销、设备旧代等语义需要后端明确错误映射，不能解析字符串虚构结构化错误或为本地撤销造服务器日志 ID。

## 兼容组合与文件职责建议

HTTP v2、浏览器 SDK apiVersion 2、设备声明 API 1/2、采样插件协议 2/未来协议 3，以及包版本和运行 generation 分别演进。不能因为设备 API 2 支持能力预算，就宣称性能会话支持热卸载或合作清理。

旧服务器的裸 target 与启动时单一 source 只按旧保证消费；不将其转换为动态绑定保证。旧历史无 owner/generation 时仍可查询，新的创建或恢复不能因此绕过当前准入。若下一批开始输入或旧操作绑定行为不兼容，应先冻结兼容分支或版本升级，再启用前端入口；不能用未知字段“试探”写请求。

| 候选文件归属 | 允许的职责 | 不承接的职责 |
| --- | --- | --- |
| frontend/src/features/performance/（后续新增） | 消费用例、独立状态、查询/控制代次、分页与撤销 | 平台采样、跨 feature 内部导入、产品页面 |
| frontend/src/services/api/ | 索引生成契约、任务结果校验和错误适配 | 手写重复 HTTP DTO、擅增性能路由 |
| frontend/src/plugin-sdk/ | 独立可选公共消费模型与取消/订阅契约 | 设备工具路径、令牌、宿主私有类型 |
| frontend/src/app/ | 公开适配与装配、本地管理收敛后的失效回调 | 在 runtime 内堆会话规则或服务器资源清理 |
| frontend/src/plugins/ | 插件与挂载作用域资源释放 | 推断服务端会话归属、替服务器排空采样 |
| backend 与主代理 | 会话绑定、共享准入、采样撤销/排空、历史入口与生成同步 | 以浏览器取消代替服务端清理确认 |

以上只是下一批职责建议，不授权本轮新增源码。操作和设备已有独立失效机制，性能状态应在本功能内维护；app 通过公开回调协调，不为性能改共享 createLatestResource，也不让 features 互读内部状态。远端变化仍需显式查询，没有新增推送承诺。具体 UI 等待设计稿。

## 最小行为验证矩阵（实施后执行）

| 场景 | 前端必须证明的行为 | 证据边界 |
| --- | --- | --- |
| 两个提供者具有同名设备，采样源另属第三个插件 | 设备完整引用不混淆，采样源绑定不冒充设备 owner | 假目录只能证明映射；服务端另验准入与歧义拒绝 |
| 旧服务器或历史记录缺少绑定 | 历史可读，标识能力缺省不补造当前代次 | 不能由兼容解析证明动态卸载已支持 |
| 切换设备或会话后旧查询才返回 | 当前选择、会话快照与分页游标不被回写 | 忽略 AbortSignal 的假传输用于证明晚到保护 |
| pause 后旧样本/inspect 晚到，随后 resume | 活动状态不回退，历史样本保留，恢复采用新 revision | 服务端另验旧采样不会提交与基线重置 |
| paused 期间到期 | 查询收敛至 completed，不因 resume 重置时长 | 不用浏览器定时器自行宣布服务器终态 |
| running 和 paused 会话的采样源卸载 | 新建/恢复入口撤销，旧响应不复活绑定 | 真实服务另验两类会话都取消并排空 |
| 设备提供者卸载而采样源仍存在 | 旧设备观测失效，不因 source 可用继续使用旧引用 | 服务端另验每次采样共享设备准入 |
| 卸载等待失败、取消或 cleanup_failed | 重新查询，保持撤销，不假定回滚或完全清理 | 真进程/外部资源确认不能由假客户端测试替代 |
| 任一提供者重载为新代 | 新创建可使用新绑定，旧会话不迁移或复活 | 真实服务另验旧会话无法调用新代 |
| source 已卸载后 inspect/list/samples | 历史状态和分页仍可查询，旧绑定不被新目录改写 | 需要真实宿主入口与存储验证 |
| 同一会话连续控制及两浏览器并发控制 | 本实例串行，服务器返回胜出；冲突后重查不自动重放 | 不伪称已有公开 CAS 或跨客户端串行保证 |
| start/控制 HTTP 等待取消 | 不把取消当服务端回滚，查询已提交 Job 或会话收敛 | 真实 HTTP 另验取消与落库竞争 |
| 浏览器插件卸载、模块退出后旧调用返回 | 子信号取消、订阅释放、旧上下文拒绝及旧响应不可写 | 默认不自动 stop；服务器会话与 DOM 生命周期分开验 |
| 缺测、零帧、恢复首样本和分页重试 | 保留 null/缺省与零的差异；按会话 sequence 去重，失败不前移游标 | 不在浏览器重算 CPU 或简单累加重叠 FPS 窗口 |
| 未安装 source、缺能力、坏结果或未知消费版本 | 不回退内置工具、不把错误变空成功；保留对应日志 ID | 本地协议错误可沿响应日志，纯本地拒绝保持无服务器日志 |
| 旧 HostContext、SDK v2 与协议 2 组合 | 可选扩展缺省可运行，标准任务入口兼容，包装不误拆 | 协议 3 清理加法须另验，不从版本号推断 |

本矩阵是后续测试要求，未创建测试或执行验收。前端行为测试只证明消费状态、映射与资源释放；服务器锁、排空、进程树、设备事务、历史持久化及真机指标分别由对应层提供证据。既有普通设备/浏览器插件、release/npx 或工具库结果不能作为性能会话动态提供者通过的证据。

## 冻结前未决选择与审核风险

1. 新会话的设备完整引用与采样源 owner/generation 是否公开、放在何处、如何表达旧历史缺省；两类提供者独立时各自绑定和失效范围如何定义。
2. 动态采样源如何发现、选择和与旧操作绑定兼容；启动时单源配置及内置回退何时撤销。未冻结前不设计新的 source 列表 HTTP 路由或选择参数。
3. 卸载对 running/paused 会话的准确终态、错误表达和清理未确认可观测信息；清理未确认与历史可读必须能同时表达，不能靠一种终态隐藏未释放资源。
4. 保留哪些宿主历史/控制入口，以及旧绑定失效时 stop 的幂等和 resume 的拒绝语义；不能将所有性能操作随 source 一起撤销导致历史不可读。
5. SDK 可选扩展的最小方法、公开模型、未知版本处理，以及浏览器退出是否需要显式会话停止策略；没有消费者所有权契约前不推导会话 owner。
6. 每采样共享准入、期限和协议 2 兼容到协议 3 合作清理的关系；超时/取消不能在浏览器侧被解释成锁已释放或设备事务已回滚。
