# 非设备长任务消费方案

## 交接状态与消费范围

本文为前端独立设计的冻结交接版本，内容是待公开契约冻结后的消费建议，不冻结后端字段、执行预算或进度协议。本轮只新增本文件，不改变现有源码、生成类型及已冻结文档，不实现产品 UI。无需等待 BIND 全量门禁；已同步的 BIND 集成结果不作为本方案实施证据。

面向使用产物 ID 和公开业务参数的包分析、构建、反编译、签名等非设备 operation 长任务。设备动作预算、性能后台会话和常驻连接另行设计，不能把它们的生命周期套入普通 Job。平台工具和服务器文件路径仍归部署与插件，浏览器不调用 shell，也不接收本机路径作为业务输入。

依据为当前 tasks、shared/api、plugin-sdk 源码，以及 [平台适配器迁出实施](../../../backend/docs/implementation/平台适配器迁出实施.md)、[合作取消插件协议](../../../backend/docs/contracts/合作取消插件协议.md)、[服务器插件生命周期消费](服务器插件生命周期消费.md)、[日志ID与接口消费](../contracts/日志ID与接口消费.md)。

## 现有事实与声明元数据

| 当前入口或模型 | 已有保证 | 前端不能据此推断 |
| --- | --- | --- |
| Operation / SDK Operation | id、title、input_schema | owner/generation、预计时长、可覆盖预算、进度协议 |
| Job | queued/running/succeeded/failed/cancelled、result、error | error 已结构化，取消已回滚外部事务 |
| app tasks | submit/list/get/cancel/events/select、选择晚到保护、销毁取消等待 | 已实现后台轮询、事件自动重连或产品页面 |
| GET /api/v2/jobs/{id}/events | after 可选，返回 job_id/sequence/status/timestamp 数组 | SSE、WebSocket、wait_ms、百分比或业务阶段 |
| 公开 HostContext | listOperations、submit/getJob/cancelJob、操作订阅及生命周期信号 | 事件读取、完整 HTTP Job 元数据、管理及产物 API 已公开到 SDK |

HTTP Job 类型还保留 input/created_at；当前独立 SDK Job 没有这两项，也没有任务 owner/generation。app 能查询完整历史不等于插件获得同样的公开模型。SDK 的 result 为 JsonValue，平台插件消费须按已知公开结果约定校验，不能断言为私有 DTO。

建议将长任务声明视为只读元数据：后端若公开预算、取消支持或阶段信息，前端只显示或供逻辑选择使用，不向 submit、业务 input 或 URL 塞预算覆盖参数。字段归属、名称和默认值未冻结前保持“未声明”，不从 operation 名称、平台、输入模式描述或包版本猜预算。

设备能力 executionTimeoutMs 的默认 30 秒和上限 120 秒不能成为通用非设备任务规则。现有文档中协议 1/2 的 60 秒与协议 3 的 1 小时描述插件执行传输边界，不保证队列、准备、发布及清理合计的完整 Job 总期限，也不保证预计完成时间。浏览器请求超时更不能决定服务器业务截止点。

## 提交、取消与查询的建议行为

1. 提交前使用当前有效操作目录；失效或卸载后撤销新提交入口。实际准入仍由服务器决定，本地目录检查不能代替服务器绑定与锁。长任务不增加按平台硬编码的输入转换或工具分支。
2. submit 返回 Job 后以 Job ID 跟踪状态，queued/running 只是已接受。成功、失败、取消均通过 get 与事件确认，不以请求耗时、产物是否暂时可见或某次空事件页宣布结束。
3. 提交与取消是写操作，不自动重试。提交等待取消或断网后，已接收任务可能继续；有 Job ID 则查询，无 ID 时不能因历史中存在同名 operation 就自动认领任务。没有公开幂等键时，不承诺安全重放或恰好一次提交。
4. 用户明确取消时调用 cancel，返回后继续查询收敛；AbortSignal 只终止客户端等待，不等于服务器 Job 已取消。重复取消的精确响应沿现有服务契约，不把网络失败解释为取消成功。
5. queued/running 等待可取消；插件或模块退出默认释放消费者请求、计时器、订阅，不自动取消用户服务器任务。取消服务器 Job 是显式业务动作，不以最后一个面板关闭推断。
6. 每次请求保留对应 logId，网络、协议和 HTTP 错误沿现有 HostError/ApiError；Job.error 仍是字符串。任务 ID、事件 sequence 和浏览器代次均不冒充日志 ID，也不解析错误文本虚构稳定错误码。

普通插件协议 2/3 的 result/artifacts 与旧绑定结果应按各自公开约定消费；不能统一强拆 result.result，也不把传输 cleanup 包装直接当 Job 业务结果。取消终态不得被晚到成功覆盖，取消或清理未确认时不宣称产物已成功发布、临时副本已删除或设备事务已回滚。

## 事件重连与进度消费建议

当前事件消费是增量 GET，不是持久连接。所谓重连应实现为读取同一 Job 的下一批事件，不增加未冻结的流式路由或传输参数。

- 每个 Job 独立保存已接收的 after，初次为 0。验证 job_id 与当前请求一致，sequence 是非负安全整数，按 sequence 去重并有序处理；完整批次成功接收后才推进游标。网络失败、协议错误或取消不推进游标。
- 当前存储 sequence 来自全局自增，某个 Job 的序号可以有间隙；不能按每任务连续计数推断事件丢失。游标仍严格属于本 Job，不跨任务复用。现有 query 只有 after，不擅加 limit、wait_ms 或断线令牌。
- 读取和事件请求串行或按消费者代次收敛。断线后保留已确认游标，恢复时从该处继续，重复响应不会重复应用。消费者重建时可从 after=0 重读并去重，不要求新增浏览器持久化契约。
- 暂时空数组只代表本次没有更新，不能当任务完成或连接失效。按有界间隔继续只读查询；网络错误或限流采用有上限的退避并尊重现有 Retry-After，稳定输入/协议错误停止自动尝试。退出立即清理定时器和在途等待，不无限并发重连。
- get 返回最终 result/error，事件用于状态迁移与历史顺序。读取到终态事件后再查 Job 获得完整结果；此前较旧 queued/running 响应不能回退已确认终态。查询断网不把任务改为 failed，保持任务状态与连接状态分离。

当前没有标准 percent、阶段、完成量或业务日志流。可消费 queued/running/终态及事件时间，不能按运行耗时、预算比例、事件条数、stdout 文本或产物大小合成“已完成百分比”。工具输出及宿主日志 ID 也不等于进度事件。

后续若后端声明结构化进度，前端再按版本校验其口径与可选性；旧事件仍按状态记录。未知扩展不能覆盖 Job 终态、触发业务重放或把缺测填成零。进度消费不提供浏览器自行续期、拆分任务或跳过宿主期限的能力。

## 历史、卸载换代与晚到保护

历史查询与当前可提交目录分开。服务器插件卸载后，旧 Job 的 operation/input/result 和产物记录按宿主历史读取；不按新版本 schema 重解释旧输入，不改写旧操作名或重新执行以“恢复结果”。具体产物消费仍走宿主已有入口，SDK 尚无上传下载适配时不得借私有 app 模块绕过。

建议本地管理收敛、目录失效和消费者切换均撤销依赖旧观测的新提交及声明元数据缓存。控制器分别跟踪操作目录观测、当前 Job ID、查询代次和浏览器插件/挂载生命周期；同名 operation 重载不是同一运行实例。服务器任务的 owner/generation 当前不公开到 Job，不解析 operation 字符串填造归属，也不增加提交 generation 参数。

目录撤销后仍允许宿主独立查询指定旧 Job 的历史。旧结果若写回自己的历史记录是合法读取；若覆盖新任务、当前选择、重载后的插件状态或重新激活提交入口则必须拒绝。这两类晚到行为不能共用“旧代一律丢弃”或“任务 ID 相同就总接受”的简化规则。

服务器负责撤销旧代入口、取消排队/运行任务及拒绝终态晚到提交；前端只证明消费状态保护。卸载错误、等待取消或 draining/cleanup_failed 后显式重查，不假定旧代仍可执行，也不把取消 Job 等同于已释放全部外部资源。重载成功后新提交使用新目录；不自动认领或重放旧 Job。

浏览器插件卸载与模块退出取消本消费者的请求/轮询/订阅，旧 HostContext 不因再次加载而复活。host 仍可查询旧历史；其他同事实例与远端管理变更通过显式刷新获知，本方案没有新增推送承诺。

## 后续文件职责与最小验证

| 所属层 | 后续消费职责 | 保持边界 |
| --- | --- | --- |
| features/tasks | 任务跟踪、事件游标、重连状态、取消后的查询与晚到保护 | 不导入 operations/devices 内部，不执行平台工具 |
| features/operations | 冻结后元数据映射和目录失效 | 不拥有任务历史，也不从平台名推断预算 |
| shared/api | 生成契约索引、响应校验、日志与取消传播 | 不手写 DTO、不新增猜测路由或业务重试 |
| plugin-sdk 与 app | 契约冻结后的可选公开消费适配与装配 | 不把 app.events 私有入口称为已公开 SDK |
| plugins | 运行代次与模块挂载子作用域资源释放 | 不替服务器确认 Job 清理或强制取消同事任务 |

上述是下一批职责建议，本轮不改文件，也不改共享 createLatestResource。后续先补行为回归，再按主代理授权实施；具体 UI 等设计稿。

| 最小场景 | 消费层断言 | 仍需对应层证据 |
| --- | --- | --- |
| 旧 operation 无声明、新元数据缺省或未知版本 | 保持可提交兼容，不填设备预算，不增加输入字段 | 声明合法性和有效截止点由后端另验 |
| submit 已落库后断网/等待取消 | 不自动重放，有 ID 继续查询，无 ID 不猜测认领 | 真实 HTTP 另验落库竞争，不能伪称已有幂等键 |
| 用户取消与成功竞争 | 按返回终态收敛，旧响应不能复活任务 | 服务端终态原子性、合作清理由对应层证明 |
| 事件重连、重复页、全局 sequence 间隙 | 去重正确，错误不前移游标，无跨 Job 复用 | 宿主持久化和历史事件可读性另验 |
| 空事件页、终态事件先于 Job 查询、查询断网 | 不误判完成，不回退终态，不把网络错误写入 Job.error | 不假装已有百分比进度或流式连接 |
| 操作卸载/重载与旧查询晚到 | 撤销新入口，旧历史可读，不能覆盖新任务或新代状态 | 真实服务另验旧代撤销、排空和 cleanup_failed |
| 浏览器插件卸载或模块退出 | 信号合并、定时器/订阅释放，旧引用拒绝 | 不把消费者清理当服务器任务已停止 |
| 平台旧绑定、协议 2/3 结果及产物 | 按公开结果约定校验，日志不混淆，旧历史不重解释 | 原始产物与平台结果兼容由集成层另验 |

本矩阵未执行。客户端假传输只能证明状态和游标规则，不证明服务器锁、派生进程清理、真实平台工具或真机事务；既有 BIND、release/npx 和浏览器结果不扩大为非设备长任务元数据/进度已实现。

## 三项关键未决

1. **operation 长任务声明**：公开元数据归属、版本、有效总预算与取消含义如何表达；前端只读，不借用设备预算或开放浏览器覆盖。
2. **结构化进度与事件演进**：是否扩展现有事件，如何版本化口径及兼容状态记录；当前仅消费 after 状态数组，不预定 DTO 或流式协议。
3. **公开消费与任务归属**：SDK 是否可选增加事件/元数据消费、Job 是否公开 owner/generation，以及提交结果未知时如何可靠关联；契约冻结前保持通用任务入口，不发明幂等键或重连标识。

交接只冻结本设计文件，不冻结以上后端选择。完成单文档 UTF-8、空白差异检查和 SHA-256 后释放写范围；不执行生成、构建、测试、服务，不修改根记录或其他已有文件。
