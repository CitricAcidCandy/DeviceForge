# 本地导入插件、工具与配置

资源市场右上角的“本地导入”连接当前 DeviceForge 服务，独立于“上传发布”。文件从浏览器选择后上传到服务所在机器，落点由该服务的持久数据目录与工具安装配置决定，不需要市场条目，也不接受浏览器输入任意服务器路径。根启动配置另用命令行 `config import` 管理，在服务器运行 `deviceforge config path` 查看路径；该路径属于服务器用户，不是访问页面的浏览器用户目录。

## 插件与工具

插件选择符合便携包规范的 ZIP、TGZ 或 tar.gz，预览显示运行位置、ID、版本与原文件摘要。浏览器只检查已构建入口与包身份，服务器继续执行完整清单与归档校验；不为本地导入增写 market.json。确认后调用原插件包安装接口，安装完成不会自动启用或执行。

工具选择 ZIP 与现有工具供应清单 JSON，点击“读取工具清单”后选择一个模块，再检查导入内容。清单保留 manifestVersion、modules 与已有字段/别名，每个模块仍需来源 URL、版本、大小、SHA-256 与相应入口元数据；URL 仅用于规范校验，本地导入不联网下载。清单最多 1 MiB、128 个模块，服务器继续执行部署配置的归档与解压限额。

界面核对所选 ZIP 的原始大小、SHA-256；确认时通过原产物上传取得公开 UUID，再次核对产物大小和摘要，最后提交 `plugin.tool-supply.import`。本地结果只消费 module_id、version、sha256、changed，不借用远端来源标记。已有同内容按幂等结果显示，导入不执行工具；平台兼容与设备运行仍需独立验证。

## 配置文件封装

只接受明确目标的 UTF-8 JSON，最多 1 MiB。不展开配置值，预览只显示目标、配置区或字段名及当前修订。

设置配置区采用以下格式；配置区通过现有 settings.import 按 CAS 事务合并，同名配置区会更新，其他配置区保留。

```json
{
  "format_version": 1,
  "kind": "settings",
  "scope": "user",
  "owner_id": "local",
  "sections": {
    "editor": { "theme": "dark" }
  }
}
```

`scope` 为 user 或 workspace，owner_id 与配置区名遵守现有设置身份规范。一个文件包含 1–64 个配置区。原始 sections JSON 缺少归属，不会被猜测导入。

已安装服务器插件的运行配置采用以下格式，合并语义与插件配置页一致。导入先确认目标已安装且声明配置能力，拒绝只读字段变更，服务器执行模式、敏感字段与修订校验。

```json
{
  "format_version": 1,
  "kind": "server_plugin_configuration",
  "plugin_id": "example",
  "values": { "count": 2 }
}
```

确认始终使用预览取得的修订；期间有人修改会返回冲突，须重新检查，不在提交时读取最新版静默覆盖。保存不自动调用 apply；需要重载时在插件配置中显式应用。

## 失败与取消

失败不自动重试安装或覆盖配置，错误保留可复制日志 ID。取消仅停止当前等待，服务器提交可能已经生效，应刷新目录或配置后核对真实状态；工具产物上传成功后取消不会删除已上传产物。关闭对话框或离开页面会撤销当前等待，旧结果不回写新对话框。

本轮行为回归为 `tests/local-import.test.ts` 与市场对话框测试；真实服务、分发重启、截图和设备运行由集成验收另记，不能用类型或构建通过替代。
