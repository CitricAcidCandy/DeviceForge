# 市场文件夹上传

上传入口位于市场页面的独立对话框，保留三步：选择内容、编辑描述、确认发布。先选择插件、工具、配置、分发包或内部资源，再选择单文件、文件夹或已有 ZIP/TGZ。资源服务单独启动，上传过程不会启动资源服务。

## 内容准备

- 文件夹选择与目录拖入保留相对路径，生成 ZIP；浏览器没有目录接口时使用已有 ZIP/TGZ。
- 插件目录根须直接包含 `package.json`、其 `deviceforge.manifest` 声明的运行清单、已构建入口和运行依赖。TypeScript/React 或原生程序须先构建；上传不会执行安装或构建脚本。
- npm TGZ 保留 `package/` 根。ZIP 插件包须使用直接包根，不能额外包一层目录。
- 图片、视频、音频等单文件直接上传原字节。大媒体可以通过资源地址和 Range 引用。
- `.git`、`.svn`、`.DS_Store` 和 `Thumbs.db` 排除项在确认页展示；不会自动排除插件运行所需依赖。

`upload-preparation/` 分别负责路径与限额、ZIP 目录校验、ZIP/TGZ 编解码、包身份和元数据、Worker 通信及目录读取。可见界面只协调选择、草稿和发布状态，不执行包内代码。

## 元数据与摘要

读取包根的 `market.json` 自动填写表单，插件 ID、版本、种类与 `package.json` 和运行清单交叉验证。插件运行位置、工具能力、配置对象及分发入口使用普通表单，高级 JSON 保留扩展字段。

第二步完成后在独立 Worker 内写回最终 `market.json` 并重新归档。归档内不写入自身的 `resource_id`，避免摘要自引用；最终文件 SHA-256 在确认页展示。上传响应摘要与本地最终摘要相等后，才发布指向该资源的市场条目。

第三步展示最终文件树、排除项、展开大小、平台架构、调用能力、权限、重启要求和类型专属描述。返回上一步修改后重新准备归档。

## 限制与取消

- 文件夹：256 MiB、4096 项。
- 插件：归档上传 64 MiB、展开 256 MiB、单文件 64 MiB。
- 单文件资源：2 GiB；散列分块读取，不整体复制媒体。
- 拒绝越界路径、大小写或 Unicode 规范化后的重复路径、文件目录冲突、链接和特殊 TAR 成员；ZIP 检查目录、成员长度及 CRC。
- 不支持加密、分卷与 ZIP64；这些格式应先转换为标准 ZIP/TGZ。

关闭、卸载界面或取消当前操作会终止 Worker 或网络等待。旧请求晚到结果不能覆盖新对话框；已经写入资源服务的资源不会因取消等待被冒充为未上传。

## 验证入口

纯归档及限额测试：`node --test tests/upload-preparation.test.ts tests/upload-worker.test.ts`。市场交互测试：`node --test tests/marketplace-ui.test.ts`。完整前端门禁和实际浏览器验证以本轮交付记录为准，单元测试不代表真实设备或性能专项通过。
