# 网页完整功能插件发布接入

## 范围与职责

本轮采用 plan-and-build，沿主代理已确定的完整发布引擎契约接入市场上传入口。默认流程为“完整功能插件”；“独立组件或其他资源”切换到原有兼容上传，不改变旧资源打包和发布规则。

## 用户流程

1. 在市场点击原有“上传发布”，默认显示“完整功能插件”；独立资源发布可显式切换到兼容入口。
2. 选择发布器生成的完整 ZIP，点击“检查完整 ZIP”。只有检查成功才显示发布预览和发布按钮，选择新文件立即清空旧预览、错误和结果。
3. 预览清单中的中文名称、描述、发布 ID、版本、组件与工具、平台变体、安装者所需输入、清单摘要、资源摘要及总资源字节。ID、版本、名称和描述只读；需要修改这些身份信息时重新打包 ZIP。
4. 填写可独立调整的市场简介、分类、适用项目、作者、许可证、关键词及 MCP/Agent 支持。发布前使用既有元数据校验；清单身份和完整发布标记由适配器保留，并由引擎再次校验。
5. 点击“确认上传并发布”，UI 真实调用主代理引擎，显示资源与字节进度。依赖先上传，随后在线发布清单，最后只提交一个完整功能插件市场条目。
6. 只有引擎返回成功才显示已发布、复用数量、来源和最终在线清单摘要，并通知市场刷新。通知回调允许同步或异步；目录提交成功即开放“完成”，不等待刷新通知才允许关闭。通知失败只提示手动刷新，不将已完成的发布改写为上传失败，也不恢复发布按钮。兼容资源流程采用相同边界。

## 取消、错误与状态归属

检查和发布期间禁止关闭弹窗、切换模式、改文件或改市场资料，用户通过“取消当前操作”显式撤销当前等待。关闭或卸载组件也撤销当前请求；每次操作均使用独立 AbortController，进度、成功和错误只在请求身份仍为当前且未取消时写入。

卸载时先撤销当前请求身份再取消，使旧 `finally` 不再向卸载实例写忙碌状态。已提交目录后的刷新通知仍归属于原请求：关闭、重开或切换流程后，迟到刷新失败不污染新弹窗。普通上传、目录冲突等失败只消费公共客户端已有的错误与日志 ID，不在组件中定义新的 HTTP 错误类型。

取消发布或发布失败时，不显示成功、不调用成功通知。界面保留真实错误及可用日志 ID，并提示“已上传资源可在重试时复用；市场目录提交可能已完成，请先刷新目录确认”。取消等待和请求失败不能证明服务器已回滚。选择新文件、重新检查、修改市场草稿和重新打开会清除过期操作反馈；旧请求即使忽略取消后迟到，也不能覆盖新预览或发出成功通知。

当前 ZIP 检查仍由引擎按既有边界处理归档与资源，UI 不允许把普通独立组件包当作检查已通过的完整发布，也不把安装流程或旧资源上传成功转计为完整发布成功。
