## 可用性与输入

- 投屏侧栏保留紧凑排查入口，切到应用栏仍可用。正常时仅显示低权重“连接排查”；异常时显示简短状态、“核对并恢复”和“查看详情”，不以大块诊断卡片占据投屏参数区域。
- 设备编号、完整报告、技术检查、读取状态和日志 ID 默认折叠；点击详情后才挂载，切换设备自动收起。折叠按钮使用 `aria-expanded` / `aria-controls`，错误仍接入现有全局消息与日志复制入口。
- 未选择设备时使用插件级 key，主动 GET 状态；按钮为“核对全部投屏资源”，POST 的 input 是空对象。无需先成功发现设备、选择设备或打开投屏。
- 已选择设备时传当前 localId；分享页传链接里的设备 ID。两者 POST 的 input 均为 `{device_id}`，不提交提供者旧代际。
- 切设备、清空选择、切分享目标和离开活动页面均取消旧等待；晚到结果不得回写当前目标。
- 手动恢复先 GET 最新插件 generation，然后至多 POST 一次；代际冲突只回读，不自动重发。
- 恢复不依赖 operations 或 session-definitions 可用。成功后只尝试刷新会话目录，不调用 open；用户仍从正常按钮打开投屏。

## 自动核对与错误边界

- 自动资源核对由宿主新会话准入和插件负责；前端打开准备最多 GET 一次，不额外自动 POST。已有查询或恢复在途时，撤销旧请求的本地等待后立即返回，不叠加 GET，也不走取消按钮的自动回读分支。
- 辅助 GET 失败、recovering 快照及历史 blocked/busy 报告都不成为普通打开的额外封锁条件；真实新会话准入由宿主裁定。被打开准备撤销的旧 GET/POST 即使忽略信号并晚到，也不回写状态、不重发核对。
- 页面出现新的投屏失败或 ownership.blocked 时读取恢复状态；失败晚于在途 GET 时，收尾后最多补读一次，不循环恢复。
- POST 失败或取消等待后最多 GET 一次真实状态。已开始的服务器恢复不因浏览器取消而推断回滚；不自动重放投屏、触摸、键盘、剪贴板或录制。
- 404 显示升级宿主提示，插件 supported 为 false 时显示升级插件提示。原始请求错误及日志 ID 保留，回读错误不能覆盖原始 POST 错误。
- 日志 ID 在面板中可选择，错误同步接入现有全局反馈及其复制入口。

## 报告约束与展示

业务类型直接索引主代理生成的 GET 响应和 POST 请求，不手写重复 DTO，不改 generated.ts。

解码强制 coverage 为 plugin，inspected / remaining 为非负安全整数。recovered 还必须 remaining 为零、checks 非空且全部 confirmed；检查明细最多 64 项。报告消息、资源名、检查消息均非空且不超过 500 个 Unicode 码点，计数方式与 SDK 的 chars().count() 对齐，不误用 UTF-16 长度。缺字段、错误状态、非有限计数、损坏明细等均作为协议错误拒绝，并保留日志 ID。

展开详情后显示整个插件覆盖、已检查数及未确认数，不把传入的设备 ID 描述为仅检查这台设备。GET 最近报告未携带请求目标，不把它标作当前设备的本次恢复；仅本页 POST 返回时显示本次报告，后续 GET 回到“插件最近核对报告”。

新样式全部采用 Tailwind 工具类；报告区域有可滚动高度上限，未新增或修改 CSS。

## 2026-10-23 前端释放与打开准备有界补齐

本节接续上述窄修，不改页面、性能功能、application 或生成类型，后端资源隔离由主代理独立集成与验证。

- 兼容投屏和 WebRTC 收到释放响应的 running/stopping 即清空本地会话与打开/释放等待，停止媒体与输入，不再等待 Finished 或发起终态 GET。返回原状态，不能据此认定服务端资源已清理。
- Finished 且清理未确认仍退出本地会话，原清理结论保留于 errors.release 与日志；真实释放错误不伪装成功，保留原错误对象及日志 ID，允许显式重试。404 仅撤销本地身份。
- 释放请求等待仍有 15 秒上限，WebRTC 的注入网关忽略信号时也及时结束等待。调用方取消不取消独立释放提交；重复释放共用本代任务，旧任务收尾不得清除新任务。
- 旧输出、旧协商及旧控制等待不能写入新代；自然终态将诊断与退出状态一次发布，订阅回调内立即重开也不会被旧轮询诊断覆盖。
- prepareOpen 不再因 recovering 或旧报告拒绝新打开。新打开撤销旧核对的本地等待时不追加 GET/POST；普通手动取消已提交 POST 后的一次只读回查规则保持不变。
- 主代理移除开始投屏按钮的两项恢复状态门禁后，本角色补真实 DeviceScreen 行为回归：后台 recovering=true 与手动恢复 POST 在途都能点击开始，并实际通过原工厂和 HTTP 客户端提交一次 session open。只替换 JSDOM 不具备的媒体展示端，不替换 open；活动会话仍禁止重复打开，缺少直播会话能力仍禁用按钮，缺少 WebRTC 能力的分享页仍不提交 open。
