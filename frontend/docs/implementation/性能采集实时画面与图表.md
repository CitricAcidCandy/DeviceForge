# 性能采集实时画面与图表

日期：2026-10-23，Asia/Shanghai。

## 实施与边界

本轮只修改前端，复用公开性能会话、设备 `screenshot@1`、任务查询/取消和产物下载。没有新增后端接口、设备命令或采集协议，也没有把归档录制伪装成实时画面。

| 单元 | 职责与副作用 | 不负责 |
| --- | --- | --- |
| `pages/performance/index.tsx` | 页面编排、显式画面开关、选择采样点、跟随最新与查看原图 | 不运行平台命令，不自行编解码任务协议 |
| `pages/performance/services/live-frames.ts` | 按完整设备引用核对截图能力，等待真实任务，校验产物并下载；撤销时请求取消已知任务 | 不回退其他设备，不自动重交结果未知的写操作 |
| `pages/performance/models/live-frames.ts` | 串行节流、数量/字节限额、对象 URL 所有权与服务器时间近邻规则 | 不创建服务器采集，不删除任务产物 |
| `pages/performance/hooks/useLiveFrames.ts` | 将会话、设备代次、暂停/终态与页面作用域绑定 | 不改变性能会话状态，不用指标读取的 pending 状态频繁中断截图 |
| `SampleBoard/chart-domain.ts` | 按真实有效值计算量程，保留缺测、零值和低/高帧率 | 不将刷新率或占位值当观测 |
| `components/MultiTrackChart` | 正尺寸 Canvas 初始化、数据提交、尺寸恢复与释放 | 不访问业务接口 |
| `shared/jobs/artifacts.ts` | 统一大小与 SHA-256 校验；无 Web Crypto 的局域网 HTTP 使用既有纯 JS 哈希库 | 不跳过摘要或信任任意截图字节 |

## 验收操作

1. 保持目标应用在设备前台，在性能页开始持续采样；纯指标验收不勾选「采样画面」。
2. 要检查画面链路时显式勾选「采样画面」。每次截图完成后至少再等 3 秒；每个页面内会话最多保留 20 张或 32 MiB，单张超过 8 MiB 即拒绝并暂停画面读取。指标采集不会因为画面限额或错误而停止。
3. 点击缩略图或时间轴后，选择保持在该历史点；点击「跟随最新」恢复跟随。该点有图时可「查看当前画面」，横屏原图以完整比例查看，不把缩略图裁切当成采集内容。
4. 暂停、终止、切换设备或撤销来源会停止新截图并取消旧等待。已经取得任务 ID 的在途截图另向服务器请求取消，并以独立 5 秒预算确认终态；查询失败也保留取消责任。提交结果未知或取消未确认只停止自动截图，即使换源或销毁页面也通过全局消息保留错误及已有任务 ID；用户可以显式重试，不需要历史清理记录归零。没有自动重交，不能据本地取消声称设备资源已经清理。
5. 持续采样间隔允许 50–60000 ms，默认仍为 1000 ms；输入及返回会话校验同步放开。低间隔不是实际 20 Hz 承诺：后端固定周期串行读取并跳过错过的周期，采样和落库耗时均影响实际频率。页面指标按秒增量刷新，截图仍按独立低频链路读取，不随 50 ms 重复请求。

## 时间与资源

- 截图是设备当前屏幕，不保证仍显示目标应用。以服务器产物 `created_at` 与指标 `captured_at` 寻找 5 秒内最近点，并保留偏差及整笔请求耗时；无近邻指标则暂不显示在该点。
- 截图发布、下载和采样有不同延迟，近邻关联不是设备时钟级同步，也不表示图中卡顿与该指标存在因果关系。多个截图落到一个指标点时显示偏差更小的一张。
- 画面对象 URL 由当前会话持有，切换会话或销毁页面后撤销。浏览器刷新不会恢复本地关联。服务器截图产物保留在原任务结果，供另行查看或清理，不自动删除用户验收证据。
- 字节限额限制页面保留量；达到上限时最后一笔已发布的截图可能不进入页面，仍保留其任务结果。连续截图本身有设备及传输开销，不能把开启画面时的读数当成无观测开销的精度结论。

实际门禁、浏览器与真机证据另记验收文档，不由本文设计覆盖直接推定通过。

50 ms 需要运行宿主同步更新。旧宿主若仍公开 minimum=1000，不能仅刷新前端就视为服务端已支持。
