# 任务历史与事件插件接入示例

日期：2026-10-10。本文消费已冻结的 SDK API2 任务历史加法，只介绍插件逻辑，不新增公开字段或产品界面。实现契约见[任务历史与事件公开接口第一批裁定](../contracts/任务历史与事件公开接口第一批裁定.md)，SDK 入口见 [HostContext](../../src/plugin-sdk/index.ts)、[任务历史模型](../../src/plugin-sdk/task-history.ts)和[产物模型](../../src/plugin-sdk/artifacts.ts)。本文示例未执行；类型、测试、构建、真实浏览器与正式分发结论由主代理另记。

## 公开入口与记录含义

插件从 activate 或 mount 回调收到的 context 使用可选 taskHistory 和 artifacts；挂载内使用该回调自己的子上下文，不借激活时保存的根上下文绕过挂载退出。旧 API2 宿主可以省略这些字段，插件检测后决定功能是否可用，不读取 runtime.tasks、私有功能模块、令牌或服务器路径。

| 入口 | 返回 data | 消费规则 |
| --- | --- | --- |
| taskHistory.list({limit?}, signal) | readonly HistoricalJob[] | 显式 limit 为安全整数 1..200；传 {} 使用服务器默认 50，返回最近记录，不保证能遍历所有历史 |
| taskHistory.get(id, signal) | HistoricalJob | 响应 id 精确匹配请求 id；在原 Job 上仅增加持久化 input、createdAt |
| taskHistory.events(id, {after?}, signal) | readonly JobEvent[] | after 为非负安全整数，省略默认 0；一次最多 200 条状态记录 |
| artifacts.upload(filename, blob, signal) | Artifact | 原字节上传，SDK 元数据为 camelCase；取消不保证已接纳上传回滚 |
| artifacts.download(id, signal) | Blob | 保留包括 JSON、NUL、非法 UTF-8 在内的原字节，不按业务 JSON 封套拆包 |

异步入口均返回 HostResult，即 {data,logId}。HistoricalJob 保留原 id/operation/status/result/error；createdAt 与事件 timestamp 为非负安全整数 Unix 毫秒，允许 0。JobEvent 使用 sequence/jobId/status/timestamp；sequence 为正安全整数，整页严格升序且全部大于 after，允许间隙与时间不单调。SDK 会拒绝错任务关联、重复、倒序和不安全数值，不能把这些响应当部分成功继续推进游标。

服务器插件卸载、操作目录撤销或同 ID 换代不妨碍读取已有持久化历史；历史不补当前 execution、provider/generation、rawState 或能力预算。Job.result 的协议业务包装与产物引用仍是原 JSON，不能把事件 timestamp 或任务记录当设备目录接受回执。原 context.getJob 的 Job 形状不变；需要 input/createdAt 时使用本扩展。

## 示例一：显式选择与下一页查询

下面是原生 ESM 插件自有辅助函数，不是 SDK 新方法。select 每次显式选择都会取消此前选择的等待，并清空本地观测；next 仅由调用方显式调用一次，不创建轮询、定时器、订阅或连接。recent 查询独立于当前选择，不取消其在途请求。

```js
export function createHistoryReader(context) {
  const history = context.taskHistory;
  if (!history) throw new Error('宿主未提供任务历史扩展');
  const lifetime = new AbortController();
  let revision = 0;
  let selection = null;
  let accepted = null;
  let queryingEvents = false;

  function close() {
    lifetime.abort();
    selection?.controller.abort();
    revision += 1;
    selection = null;
    accepted = null;
  }
  const dispose = context.onDispose(close);
  function combined(caller, selected) {
    const signals = [context.signal, lifetime.signal, caller];
    if (selected) signals.push(selected.controller.signal);
    const signal = AbortSignal.any(signals);
    signal.throwIfAborted();
    return signal;
  }
  function current(selected, signal) {
    signal.throwIfAborted();
    if (selection !== selected || selected.revision !== revision) {
      throw new Error('任务历史选择已经变更');
    }
  }

  return Object.freeze({
    dispose,
    snapshot: () => accepted,
    async recent(caller) {
      const signal = combined(caller, null);
      const result = await history.list({ limit: 20 }, signal);
      signal.throwIfAborted();
      return result;
    },
    async select(id, caller) {
      selection?.controller.abort();
      const selected = { id, revision: ++revision, controller: new AbortController() };
      selection = selected;
      accepted = null;
      const signal = combined(caller, selected);
      const job = await history.get(id, signal);
      current(selected, signal);
      accepted = Object.freeze({ job, events: null, after: 0 });
      return accepted;
    },
    async next(caller) {
      const selected = selection;
      const previous = accepted;
      if (!selected || !previous) throw new Error('请先成功选择一个历史任务');
      if (queryingEvents) throw new Error('本实例正在查询一页任务事件');
      const signal = combined(caller, selected);
      queryingEvents = true;
      try {
        const events = await history.events(selected.id, { after: previous.after }, signal);
        current(selected, signal);
        const last = events.data[events.data.length - 1];
        accepted = Object.freeze({ job: previous.job, events, after: last?.sequence ?? previous.after });
        return accepted;
      } finally {
        queryingEvents = false;
      }
    },
  });
}
```

在插件收到 context 后创建 reader，调用 reader.recent(signal) 获取最近记录，再用实际返回的 id 调用 reader.select(id, signal)、reader.next(signal)。snapshot 是插件自己的最近已接受结果，包含原 HostResult，保留各请求 logId；events 只表示最近一次成功取得的页，不是全部任务事件或实时当前状态。需要更新任务状态时显式重新 select，它会重新取记录并从 after=0 开始。

next 仅在完整成功且选择仍有效时更新 after；空页保留原 after，错误/取消保留上一份已接受观测。选择变更先清空旧观测，晚返回不能恢复旧选择。reader 的同步赋值与资格复核处于同一续执行段；同 ID 的新插件代次须创建新 reader，不复用已关闭实例。dispose 登记到 context.onDispose，可提前调用；查询退出不调用服务器 cancelJob，也不删除历史。

## 示例二：将已接受历史快照作为自有产物传输

此函数接收上一示例成功取得的 snapshot；不从当前操作目录补值，也不把历史快照格式加入服务器 DTO。JSON 内容是插件自己创建的产物正文，服务器仍只接收原 Blob 字节；日志保留在上传/下载各自的 HostResult。固定文件名不依赖任务 id 作为路径。

```js
export async function transferHistorySnapshot(context, snapshot, callerSignal) {
  const artifacts = context.artifacts;
  if (!artifacts) throw new Error('宿主未提供产物传输扩展');
  if (!snapshot) throw new Error('没有可传输的已接受历史快照');
  const signal = AbortSignal.any([context.signal, callerSignal]);
  signal.throwIfAborted();
  const content = new Blob([JSON.stringify({
    job: snapshot.job.data,
    events: snapshot.events?.data ?? [],
    after: snapshot.after,
  })], { type: 'application/json' });
  const uploaded = await artifacts.upload('task-history.json', content, signal);
  signal.throwIfAborted();
  const downloaded = await artifacts.download(uploaded.data.id, signal);
  signal.throwIfAborted();
  return Object.freeze({ uploaded, downloaded });
}
```

调用方将 reader.snapshot() 传入 transferHistorySnapshot，并传自己的有限调用信号。返回的 uploaded.data 为 Artifact，使用 mediaType/createdAt 等 SDK camelCase 字段；downloaded.data 为 Blob。这里只传输一份选定的已接受快照，不宣称收集了所有历史或事件。若上传后选择改变，原快照仍是历史数据；消费方想让导出也随选择撤销时，另创建该次导出控制器，在新选择或退出时 abort，并通过 context.onDispose 登记。不要让历史数据去回写当前设备或当前选择。

任意下载产物都可能不是 JSON；此函数不调用 Blob.text 或 JSON.parse，不解包看起来像 {log_id,data} 的正文。若插件创建 Blob URL，必须用 context.onDispose 登记 URL.revokeObjectURL；本文不创建 URL、下载按钮或 DOM。上传取消、下载取消与上下文退出只约束调用资格和等待，不保证服务器撤销已保存产物，不增加删除产物或查询元数据接口。

## 错误、日志与撤销边界

每个 SDK 调用成功读取 HostResult.data，同时保留本次 logId；不要用任务 id、事件 sequence、产物 id 或客户端运行标记代替日志。HTTP 错误的 kind/code/status/retryAfter/logId 沿现有 HostError 传递，网络失败和未取得响应的取消可以没有日志。本地非法历史查询为 protocol/invalid_history_query；历史与事件响应映射错误分别为 invalid_history、invalid_job_events，并保留已经取得的响应日志。示例辅助函数的能力缺省、选择变更等错误是插件自有 Error；throwIfAborted 可产生原生取消异常，不伪装成服务器错误。

宿主 runtime、插件实例、挂载子作用域或 caller 撤销时，taskHistory 等待及时拒绝，包括注入端口忽略信号或永不返回的情况；晚 resolve/reject 被安全消费，不能写回旧代。结果交付之前再检查资格，已经交付的历史记录不因后来取消追溯撤回。旧插件或旧挂载上下文不能随同 ID 重载恢复资格；新代重新创建消费辅助函数。停止等待不证明可信插件自己的副作用已停止或外部资源完成清理。

这里没有隐式 cancelJob。取消查询不等于取消服务器任务、删除历史、卸载服务器插件或回滚管理动作。服务器插件停用后，可从仍存活的另一插件上下文或宿主重新读取持久化历史；已停用浏览器插件保存的旧上下文仍失效。远端目录变化依靠显式查询，不以历史任务或事件补当前目录。

## 最小接入复核

新插件可在开发验收中依次显式调用 recent、select、next，并保留三次日志；再上传该份 snapshot、下载上传返回的真实产物 id，独立比对字节与日志。选择 A 后切 B，A 的晚结果不得恢复本地状态；取消或错误不推进 after；子挂载退出不得关闭兄弟；卸载重载后使用新上下文，旧引用应拒绝。历史即使指向已经撤销的服务器操作也只按持久化记录读取，不套用当前预算或提供者状态。
