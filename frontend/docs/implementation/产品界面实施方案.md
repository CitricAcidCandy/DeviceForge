# 产品界面实施方案

日期：2026-10-14，Asia/Shanghai。用户已选择电子设备背景 v4，并授权设计各业务界面、把已实现功能接入前端。旧「产品界面先不做」的阶段限制由本次指令解除；整体迁移与性能专项边界不因此改变。

## 架构门禁

模式：architecture-first。目标是交付真实可操作的 React 产品界面，保留现有严格 TypeScript 工厂、任务/日志/产物、设备能力准入及插件运行中装卸，背景为环境层，功能文字与控件真实渲染。

影响层：app 装配与页面、shared/ui 官方展示组件、框架配置、架构扫描、前端测试与文档。后端公开契约和生成类型保持现有事实；若发现真正缺失的公开能力，单独裁定。采用 React + Tailwind 与已选场景，优于继续扩充 Svelte 骨架，因为用户已明确 React 设计方向，业务工厂与 SDK 本身不依赖框架。禁止把所有网络、表单、插件和页面逻辑堆入 App。

| 单元 | 职责 | 输入/输出与副作用 | 不承担 |
| --- | --- | --- | --- |
| app/product-services | 装配既有功能工厂，提供任务钩子与统一生命周期 | runtime、客户端配置进入；输出功能实例；网络只经 shared/api | 页面布局、HTTP DTO 重写 |
| app/product-state | 缓存外部订阅快照、路由与本地偏好、业务结果视图 | 功能快照进入；稳定订阅输出；只保存非敏感显示偏好 | 后端事实、主题持有业务状态 |
| app/product 与各业务页面 | 场景外壳、导航、真实表单及结果展示 | 注入的业务实例、AbortSignal；输出用户操作 | fetch、私有插件导入、跨 features 内部引用 |
| app/product-slots | React 与插件挂载根的所有权隔离 | 具名槽位、独立 DOM 根和释放函数 | 在同一 DOM 子树混用所有权 |
| components | 经过批准的官方组件、纯展示与可访问性 | 展示参数和事件输出；无业务依赖 | API、runtime、features |
| scripts 与 tests | TSX 纳入严格架构扫描、行为/生命周期验证 | 当前源码和真实服务；输出可追踪门禁 | 用静态检查代替浏览器或图审 |

先拆分装配、控制器与页面；所有依赖由 app 向 features/shared/plugins/SDK 单向注入。设备、主题等每次创建新对象的 snapshot 需要在展示适配器缓存，避免 React 外部存储重复渲染。路由和主题变化不销毁整个 runtime；关闭统一撤销等待、释放业务与插件实例，再卸载 React 根。

## 页面范围

以当前接口盘点为准覆盖：设备工作台与应用、文件/产物、包分析、截图/投屏/录像、Android 指标与 Root 栈、Frida、自动化、终端、AI CLI/SDK、DEX/MessagePack/表格、任务日志、服务器/浏览器插件、工具供应、设置与主题。各功能有专用任务表单与结果呈现；动态操作目录保留为专业扩展入口，不拿通用 JSON 表单替代所有产品页面。

2026-10-14用户进一步授权采用常规中后台布局。场景图共用，左侧分组导航与顶部设备上下文稳定；操作区为连续暖纸色工作平面，支持导航折叠、窄屏抽屉和专注模式。具体职责与验收见[中后台工作台布局](中后台工作台布局.md)。设备离线、能力缺失、未装插件、权限不足与服务器断开分别说明；任务失败保留真实日志 ID，取消等待不冒充服务端已停止。性能缺测保持空值及原因，不补零；截图和实时投屏区分来源。

## 开发与验收顺序

采用 Hybrid：先冻结输入/输出边界和页面行为，再为取消、晚到、插件撤销、文件上传/下载与权限准入补回归；逐模块实现后执行生成、完整 check/test/build，最后真实浏览器业务验证与子代理截图审查。门禁需覆盖 `.tsx`；稳定 plugin-host 与两项浏览器 harness 构建入口保留。

四角色写权：主代理兼交付总监，独占公共装配、生成、配置审批与共同记录；前端开发负责页面外壳与官方组件接入；后端开发当前先核对业务契约，随后负责独立业务消费装配；测试助理负责视觉规格及真实浏览器/截图验收。具体写集由主代理逐批下发，不重叠。

官方依赖及逐项组件清单已获用户明确批准并安装；版本及来源见[产品界面依赖与组件来源](../guides/产品界面依赖与组件来源.md)。采用官方生成器导入组件，仅调整引用路径、中文文案及主题变量；不改交互与无障碍逻辑。背景已获用户接受，本轮不重新生图。所有图像审核只由子代理执行，主代理不打开图片，只回收结论。
