# 设备提供者第一阶段前端实施

## 实施门禁

模式为 architecture-first，采用契约先行与行为回归结合的 Hybrid。目标是消费四个生成设备端点，提供可执行目录/选择/动作基础用例，并给 SDK v2 增加可选 HostContext.devices；不新增产品页面、不引入 UI 库，也不实施常驻连接或平台工具。根/backend、generated.ts 与生成命令由其他角色负责。

选择独立 features/devices、纯身份/能力规则和显式宿主映射。另一条路线是将设备状态、HTTP 请求和插件映射直接加入 app/runtime，改动集中但混合职责、难以验证选择与代际竞态，因此不采用。SDK 公开模型独立于 HTTP DTO，后者只能索引主代理已同步的生成 paths，不手写第二套 HTTP 结构。

| 单元 | 职责与输入/输出 | 不负责 | 副作用 |
| --- | --- | --- | --- |
| shared/api 设备 types/endpoints/validation | 索引生成输入输出，校验未知响应与目录身份，定义四路由 | 平台执行、选择状态、手写 DTO | 无 |
| features/devices 规则 | 完整 DeviceRef 比较、提供者代次和能力准入 | HTTP、UI、按平台选择执行器 | 无 |
| features/devices 状态/用例 | 提供者/目录刷新、选择、动作、取消与晚到保护 | SDK 转换、插件私有状态 | 调用客户端、发布订阅 |
| plugin-sdk 设备模型 | 独立 DeviceProviderInfo/DeviceRef/DeviceDirectory/动作与访问契约 | 生成类型、服务令牌、宿主私有模块 | 无 |
| app 设备适配器 | HTTP DTO 显式映射 SDK，日志错误保持，装配 runtime.devices | 业务准入、平台规则 | 根生命周期调用与订阅 |
| plugins 设备访问包装 | 插件实例及挂载子生命周期合并信号，撤销请求/订阅和旧结果 | 设备目录管理、HTTP | 取消、释放订阅 |
| tests/devices 与插件行为测试 | 同名身份、选择/代次竞态、能力/状态/取消/日志错误和卸载取消 | 真实设备、具体产品界面 | 假传输/挂载 |

设备职责从现有 app/runtime、host-context 与 plugin scope 中拆出独立适配/包装模块；app 只装配公开入口，features 不跨其他功能内部导入，SDK 不依赖 app/features/shared/plugins。保持 strict/noUncheckedIndexedAccess/exactOptionalPropertyTypes，不用 any、断言或条件类型空壳绕过生成缺口。

## 契约依赖检查点

2026-10-09：主代理已同步生成类型，生成进程最终退出码为 0；前端已消费以下四个 HTTP 端点，不再等待设备契约：

- GET /api/v2/device-providers → DeviceProviderInfo[]。
- GET /api/v2/devices → DeviceDirectory[]。
- POST /api/v2/device-providers/{id}/refresh，body 为 {generation} → DeviceDirectory。
- POST /api/v2/device-actions，DeviceActionRequest → 共享 Job。

响应继续采用 v2 包装与日志关联，设备引用包含 provider_id/generation/local_id。动作的 provider_id/generation、可选 device_id、capability/version 与对象 input 从生成请求类型推导；SDK 使用独立具名模型并显式映射，不读取工具路径或私有模块。

## 已冻结公开入口与生命周期

runtime.devices 已实际装配；HostContext.devices 为 SDK v2 可选加法扩展，旧宿主可以省略，插件使用前应检查该字段。公开签名保持如下：

```ts
refreshProviders(signal: AbortSignal): Promise<HostResult<readonly DeviceProviderInfo[]>>;
refreshDirectories(signal: AbortSignal): Promise<HostResult<readonly DeviceDirectory[]>>;
refreshProvider(id: string, generation: string, signal: AbortSignal): Promise<HostResult<DeviceDirectory>>;
invoke(action: DeviceAction, signal: AbortSignal): Promise<HostResult<Job>>;
select(reference: DeviceRef | null): void;
snapshot(): DeviceSnapshot;
subscribe(listener: (snapshot: DeviceSnapshot) => void): Dispose;
```

SDK DeviceRef 使用 providerId/generation/localId，不能以显示名或 localId 单独定位。DeviceAction 使用 providerId/generation/deviceId/capability/version/input，其中 deviceId 可为 null，input 为 JSON 对象。SDK 与生成 HTTP snake_case 字段由 app/device-gateway.ts 逐字段映射；插件无需读取生成类型、私有模块或令牌。invoke 返回共享 Job，接受任务不等于设备动作已成功完成。

选择以完整引用绑定当前目录。切换选择、提供者消失或代次变化时撤销旧选择关联的等待与结果；旧目录/发现/动作响应不能覆盖当前选择或复活旧提供者。缺失能力不视为支持或可用，离线/未授权/未知状态与不可用能力应明确失败。最终准入仍由后端按原子注册快照验证，前端检查不替代服务端。

refreshDirectories 先同步提供者，再读取已有目录，不隐式触发发现。refreshProvider 开始时即清除该代旧目录和选择，刷新在途不能继续把旧缓存作为当前观测；失败后保持空。请求记录清理后的修订，自己的成功能够发布，替代请求和旧代晚到响应不能覆盖新目录。单个提供者的修订互不干扰，不同提供者可并行刷新。

app/catalog-refresh.ts 在本实例服务器插件 load/unload 成功、失败或取消后，先撤销目标提供者的目录、选择及相关请求，再独立重查操作和设备目录。runtime.pluginPackages 的服务器 enable/disable 也走此编排；重查失败仍不保留目标旧缓存。若管理失败且提供者仍在服务端，重查可重新观察它，但不会复活旧选择。其他浏览器或远端管理的变化通过显式刷新获知，当前没有后台推送。

实例、面板、组件和模块设备请求都合并调用者、插件/子挂载与宿主生命周期信号；卸载立即撤销信号与订阅，晚到响应拒绝进入新代。HTTP 取消不等同服务端变更回滚，不自动重放写动作。当前发现是显式刷新，尚无后台推送或常驻传输。

所有设备入口在作用域关闭后拒绝使用，snapshot/select/subscribe 也不能绕过；订阅手动释放和卸载均幂等，停止后不发布晚通知。HTTP 错误保留真实服务日志 ID；未产生服务响应的本地准入或生命周期错误 logId 为 null，不构造日志 ID 冒充服务端证据。
