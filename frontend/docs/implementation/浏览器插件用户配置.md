# 浏览器插件用户配置

## 存储与迁移

浏览器插件配置统一使用当前服务器用户目录；前端只调用公开配置接口，不访问宿主文件系统。默认根为 `<home>/.deviceforge`，后端支持 `DEVICEFORGE_USER_DIR` 显式隔离。记录路径是根下 `plugin-configurations/browser/<id>/state.json`；它不随初始插件包、在线部署目录或 `APK_DATA_DIR` 改变。切换服务器即切换该服务器的配置；同一服务器上的浏览器窗口共享记录。

有配置声明时，首次读取或激活执行以下流程：

1. GET 远端记录。有记录即采用远端，不读取旧 localStorage。
2. 仅远端为 null 时按旧服务地址和插件 ID 查 localStorage。旧记录原样保留，迁移完整字段并补充当前声明的敏感路径。
3. 没有旧记录时，以当前声明默认值创建版本、`revision: defaults`、`applied: defaults` 和敏感路径。这样后续包默认值变化不会悄悄改变已经使用的配置。
4. 创建记录使用 `expected_revision: null`。409 后只重读胜方记录，不重放旧数据或默认值。

GET、迁移或普通保存失败均沿公共错误返回，保留状态、错误码和日志 ID；不能降级为本地保存。旧数据损坏时返回安全错误，不附带解析载荷。旧 localStorage 不再写入或删除，供用户追溯。

没有 configuration 声明时，读取、准备与确认应用均不访问配置 API，SDK 上下文也不注入配置访问器。

## 端点与职责

GET/PATCH `/api/v2/browser-plugin-configurations/{id}` 的类型直接索引生成 `paths`，响应先按未知值解码。PATCH 显式携带 `expected_revision` 和完整 `{version,values,revision,applied,sensitivePaths}` 记录，values 必须是 JSON 对象。公开 API 客户端统一处理令牌、日志 ID、错误和取消。

`services/browser.ts` 适配 HTTP 与领域记录；`services/legacy-browser.ts` 只读旧记录；`models/browser.ts` 负责串行编排、声明校验和运行值。`utils/browser-view.ts` 生成页面视图并遮蔽敏感字段、历史路径和声明默认值。可信插件的 SDK 仍读取原值。

## 生命周期与竞争

宿主先异步 prepare，再执行 activate；配置通过版本和 Schema 校验后才提供同步 `configuration.get/subscribe`。next_invocation 保存成功后更新运行值并通知订阅，plugin_reload 保存只改变持久记录。

重载以用户指定的 revision 固定目标；如果另一窗口在卸载、激活前后改了记录，prepare 或最终重读会拒绝。成功激活后 markApplied 先核对 prepare 消费的 revision，再以相同 revision 执行 CAS 写入 applied。确认完成前插件保持 loading，失败则沿原生命周期清理新代。不会把另一窗口的新修订标成已应用。

每插件请求串行，组合调用方、模型和 runtime 的信号。底层传输或自定义回调忽略信号时仍可结束宿主等待，晚到成功和失败均被消费；取消或销毁后不能重新发布运行值或订阅事件。取消不承诺撤回后端已经接纳的写入，下一次读取以实际服务端记录为准。

## 验证入口与边界

本轮实现新增以下定点用例，主代理统一生成 API 后执行：

```text
node --experimental-strip-types --test tests/browser-configuration-api.test.ts tests/browser-configuration-persistence.test.ts tests/browser-configuration-runtime.test.ts tests/plugin-configurations.test.ts
```

用例覆盖未知响应解码、端点编码、默认值首次落盘、包默认值变化、旧记录迁移与保留、远端优先、CAS 竞争、API 失败不降级、无声明零请求、取消及销毁后的晚到结果、加载等待和应用确认失败回滚。完整 check/test/build 仍由主代理在共享工作区串行执行；本功能实现代理没有运行共享测试、构建或真实服务，不将测试源码存在写成验收通过。

此前插件中文名称、描述、配置表单与 PATCH 跨域修复的浏览器报告属于上一阶段，不能代替用户目录持久化、跨重启和分发运行验收。
