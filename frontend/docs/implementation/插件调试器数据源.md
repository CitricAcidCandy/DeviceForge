# 插件调试器数据源

日期：2026-10-28。本文只说明前端数据源登记与本地工具实现，不代表在线宿主、后端桥或正式分发已经更新。

## 职责和入口

`context.debug.registerDataSource` 是可选公开能力。插件主动登记独立业务投影，旧插件可以不接入；宿主不扫描 React 状态、任意对象路径或存储。没有登记时，`data_catalog` 返回空目录，并明确空目录不能证明插件没有内部数据。

SDK 定义：

```ts
interface DebugDataSnapshot {
  readonly revision: string;
  readonly value: JsonValue;
}
interface DebugDataSourceDefinition {
  readonly id: string;
  readonly label: string;
  readonly schema: JsonValue;
  readonly persistence: 'memory' | 'persistent';
  readonly applyPolicy: 'immediate' | 'next_invocation' | 'reload';
  readonly read: (query: JsonValue, signal: AbortSignal) => Promise<DebugDataSnapshot>;
  readonly write?: (
    request: { readonly expectedRevision: string; readonly value: JsonValue },
    signal: AbortSignal,
  ) => Promise<void>;
}
```

读写回调由插件拥有；回调内不得记录凭据和完整调试输入。注册返回释放函数，同名数据源不能并存；撤销旧登记后可以登记新源，旧释放函数不能删除新源。面板、模块等子作用域关闭时只撤销自己的数据源，父级与兄弟继续有效。

## 工具参数和结果

各工具外层使用原调试会话 `{ session_id, parameters }`，下面只列 `parameters`：

| 工具 | 参数 | 结果 |
| --- | --- | --- |
| `data_catalog` | `{}` | `sources` 列出 `id/label/schema/schema_complete/omitted_schema_paths/writable/persistence/apply_policy`；目录查询不执行读取回调 |
| `data_read` | `{ source_id, query? }` | `{ source_id, revision, value, writable, apply_policy }` |
| `data_write` | `{ source_id, expected_revision, value, confirmed: true }` | 保存后回读，返回前述字段及 `runtime_applied` |

`value` 是完整替换值，不是合并补丁。省略 `query` 时传 `null`；写入前后的读取固定使用 `null`，所以可写数据源的 `read(null, signal)` 必须返回完整、可替换的业务投影，而不是分页局部视图。只读源可以自行解释查询条件。

`apply_policy=next_invocation/reload` 的写回结果带 `runtime_applied: 'pending'`，表示保存成功但运行状态尚未由本工具验证。`immediate` 返回 `'declared'`，只说明数据源声明即时生效，不代替界面或真实业务断言。

## 原子修订与未知结果

宿主先读取并比较修订，执行模式校验和只读字段检查，再调用一次写回，并重新读取真实数据。插件可以归一化输入，返回值以回读为准。

工具公开修订是当前登记 UUID 和有限序号组成的不透明标识，不直接暴露插件原始修订。每个数据源最多保留 32 个公开修订映射；同名源撤销重登记时使用新 UUID，即便插件原始修订又从 `r1` 开始，旧公开修订也不能写新源。映射过期必须重新读取，不能猜测或拼接修订。进入插件写回时宿主将当前公开修订还原为插件原始修订，SDK 回调仍比较自己的原始修订。

插件必须在实际写入回调内部原子完成修订比较和提交。宿主预读与回调之间可能有用户或其他调用修改数据，不能把宿主预读当作实际并发保护。插件可用 `HostError('protocol', 'debugger_revision_conflict', '数据已变更')` 报告原子修订冲突；宿主只返回固定诊断，不透出插件异常原文。

一次读或一次完整写入流程共享十秒预算，写入的预读、写回和回读不会各重置十秒。每个源只有一个当前写入等待，不隐式排队。超时、取消、源撤销、插件卸载后结束宿主等待，回调信号同步撤销；可信回调忽略信号时，宿主不能强制停止实际副作用。

已经进入写回后发生异常、取消、超时或回读失败，返回 `debugger_result_unconfirmed`，不自动重放。后续独立读取仍可使用；旧未确认结果不永久禁用整个插件。回读失败不伪装成保存成功，取消等待也不表示保存撤销。

## 模式、脱敏与容量

- 登记时编译完整 JSON 模式，读取结果和待写值使用同一完整模式校验；只读字段不能经整体替换修改。
- 一个插件最多登记 64 个数据源。每个业务值最多 256KiB，深度最多 16 层、结构节点最多 8192，字段名最多 128 字节；目录及工具总回执不超过 1MiB。读取值复制不执行 getter、`toJSON` 或类实例方法，拒绝访问器、循环、空位数组及非有限数字。
- 凭据字段名、Bearer 模式及已知凭据赋值模式脱敏；模式的 `writeOnly` 和 `format: password` 值也屏蔽。普通业务字段 `value` 和工具包络 `value` 保留，不使用旧界面元数据的整字段屏蔽规则。
- 数据字段按凭据精确名称与后缀识别，普通 `token_count/tokenCount` 计数保留；不得用包含 `token` 的宽泛规则屏蔽正常统计。
- 公开目录省略敏感模式属性以及默认值、示例，返回 `schema_complete: false` 和对应 `omitted_schema_paths`；完整模式仅用于本机校验。公开模式不完整时不能据此推断原源缺少字段。
- 含凭据字段或敏感模式声明的数据源不能整体替换，目录相应标为不可写。对现有值含敏感字段的宽松模式源也拒绝写入。插件应另行登记无敏感业务投影，不隐式恢复、合并或回写旧秘密。
- 自由文本中的秘密无法完整识别，登记者仍负责避免暴露不应公开的数据。动作事件只留工具名等元数据，不复制新旧业务值。

## 验证边界

直接单元覆盖目录无副作用、修订冲突、回读归一化、只读和无效模式、敏感字段、源撤销、超时取消、容量、子作用域隔离及本地工具分发。实际命令和结果由本轮主代理汇总。没有据此执行全仓测试、完整构建、浏览器、真实设备或用户服务重启。
