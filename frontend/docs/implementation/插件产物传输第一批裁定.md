# 插件产物传输第一批裁定

日期：2026-10-10。模式 architecture-first / Hybrid。目标是浏览器插件通过公开SDK上传与下载真实产物，当前仅为实施输入，不是运行通过报告。影响SDK、app适配、插件作用域与独立前端测试；服务器路由及生成契约不变，产品界面等待设计稿。

## 选择与兼容

选择HostContext.artifacts可选加法，不让插件依赖shared/api或使用宿主令牌自行fetch。旧API2、已有插件和自建HostContext字面量继续兼容；未提供时不补伪实现。此批只开放原字节上传下载，任务列表/事件、产物查询预览和管理API分别后续实施，不把加法二接口写成完整业务迁移。

SDK新增独立artifacts.ts：Artifact包含只读id、filename、mediaType、size、sha256、createdAt；ArtifactAccess包含upload(filename:string,content:Blob,signal:AbortSignal)->Promise<HostResult<Artifact>>和download(id:string,signal:AbortSignal)->Promise<HostResult<Blob>>。Blob保留包括JSON/NUL/非法UTF8在内原字节，不解析成业务封套；logId沿JSON及关联响应头保留。

app由生成ArtifactDto经命名适配映射到SDK，不复制服务器DTO。runtime继续公开原有artifacts入口并向HostContext注入公开适配；可选新增createHostContext末参，不修改已有参数含义。错误经publicCall映射HostError，协议映射失败也保留本次logId。元数据用SDK规则检查非空标识/文件名、有限非负安全整数、64位十六进制摘要及有限非负时间值，不擅自改服务字段或伪造摘要。

宿主与插件作用域组合caller、runtime、plugin/panel撤销信号，关闭后零新调用；晚到成功不交给已撤销代次。插件层用独立artifact-access.ts代理，通过现有call/current收口，不把文件传输逻辑堆入scope。取消等待不承诺服务器已接纳上传回滚。SDK不创建下载URL；插件若创建Blob URL须通过onDispose登记撤销。

## 职责、写集与验证

| 单元 | 输入输出与职责 | 副作用与边界 |
| --- | --- | --- |
| plugin-sdk/artifacts.ts及index加法 | 独立只读模型、可选公开能力 | 无HTTP或宿主内部依赖 |
| app/artifact-gateway.ts、host-context/runtime加法 | 生成DTO映射、错误/logId、宿主信号与原传输注入 | HTTP由现有client执行，不复制fetch或暴露凭据 |
| plugins/artifact-access.ts、scope加法 | 插件/面板代次的调用资格与晚结果拒绝 | 无具体功能依赖，不创建URL/文件系统路径 |
| tests/plugin-artifacts.test.ts | 真实HTTP适配原字节、错误关联、撤销及兼容缺省 | 不改既有用例或关闭类型检查来通过 |

Kepler独占上述前端文件与所属README/开发者文档最小更新，其他角色不写同文件。生成类型及所有check/test/build/服务由主代理串行执行。Hybrid先验证SDK不依赖私有实现、上传/下载原字节与日志，再覆盖作用域取消/关闭/重载晚到结果；随后完整前端门禁和生产浏览器真实服务。未跑浏览器时只记适配测试通过，不写线上验收完成。
