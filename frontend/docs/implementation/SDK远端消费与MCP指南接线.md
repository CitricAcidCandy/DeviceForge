## 前端消费边界

正常安装已用公开附件替换三个外部源码链接。主入口及`/json`、`/models`、`/slots`均来自本工程正常安装目录；宿主兼容转发与公开包共享同一`HostError`构造器。

`sdk-repository.ts`只定位已安装公开包，不再读取旧环境变量或推断同级仓库。开发发行脚本只收集公开包`files`中的真实运行文件和声明，不执行SDK源码生成器、不写安装目录。重新归档保留成员字节，但压缩容器摘要可以与原下载TGZ不同，发行报告不得混用两者。

公共HTTP契约现在只读核对已安装类型与宿主生成结果。发生差异时，应在SDK仓库更新并发行类型包，再调整宿主固定依赖；宿主生成器不能直接覆盖外部仓库或node_modules中的公共声明。

七份旧专项类型配置曾把`@deviceforge/plugin-sdk`指回宿主薄转发，造成转发再次解析自身。现移除此类别名及跨仓HTTP类型路径，业务别名继承现有生成配置，不再维护陈旧副本。五处测试中的旧SDK加载映射同步移除；跨目录示例夹具仅解析已安装公开包，不改变业务或运行时接口。

## 指南消费边界

新增公开`deviceforge-plugin-guide`库在SDK仓库内编译期嵌入正文，宿主仅映射其常量，不再使用build.rs、环境变量或开发机文档路径。保持八个主题、十六份响应文档，前端SDK正文继续拼接组合说明，知识版本升为5。

新版正文给出SDK、构建工具、HTTP类型、Rust运行库及示例源码、Windows x64 CLI的真实附件地址，以及版本、字节数、SHA-256和配套依赖。Rust示例固定已发行源码修订`e1aa53c52381bcdebf8883e99ab04491b88cb771`；宿主的指南消费固定后续修订`54a2889...`，两个用途不同。原v0.1.0标签及七份附件不移动、不覆盖。

指南源码更新与运行服务更新分别验收。本次未替换运行中的后端程序，在线MCP仍取其编译时正文；要采用知识5，需要沿原标准路径编译后由原启动入口重启，不能只重启旧二进制就宣称更新。
