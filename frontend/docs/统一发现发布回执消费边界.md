# 统一发现发布回执的前端消费边界

## 状态、依据与职责

本文依据用户已选定的方案1：先确认成功观测的 Job 终态，再有条件接受当前目录。主代理正在冻结 attemptgate 内部策略；本文只定义前端消费语义，不定义其内部锁、状态机或公开 DTO，也不声称本轮已经实施或验收。后端候选文档中仍保留的二选一描述属于评审历史，不改变本轮选定方案。

依据为后端 [设备原始状态与统一发现实施方案](../../backend/docs/设备原始状态与统一发现实施方案.md)、[统一发现验收矩阵](../../backend/docs/设备原始状态统一发现验收矩阵.md) 及本端已冻结的 [设备原始状态接入方案](设备原始状态接入方案.md)。本文补充发布与消费边界，不修改原设计、已有源码、生成类型或 SDK；具体产品 UI 继续等待设计稿。

现有 SDK v2 可选 HostContext.devices 提供 refreshProviders、refreshDirectories、refreshProvider、invoke、select、snapshot 和 subscribe。DeviceDirectory 已有 provider、observedAt、discoveryJobId 与 devices；HTTP 字段由 app/device-gateway.ts 显式映射。本文沿用这些已公开概念，不声明额外的发布状态字段、回执端点、查询参数或 SDK 方法。

现有 features/devices 已有本地目录撤销、请求身份、目录修订及提供者代际检查；本实例管理先撤销再重查。它们不能证明本轮服务端发布竞争已实现，也不能用上一阶段测试、release/npx 或浏览器报告替代本轮验收。

## 三种结果必须分别消费

| 对象 | 表示什么 | 不能据此推断什么 |
| --- | --- | --- |
| Job 实际成功终态及历史结果 | 本任务完成了一次通过校验的成功观测；终态按任务契约保留 | 不保证观测曾被当前目录接受，不保证提供者仍加载，也不证明设备此刻可操作 |
| 本次 refresh 所属 Job 的发布回执 | 服务端对本次观测是否接受、以及接受的本份目录作出的结果；回执是内部编排依据 | 不等于响应送达时 GET 最新目录；不能认领另一任务的目录，不能保证接受后未被卸载撤销 |
| GET 当前目录 | 当前代已接受且仍保留的观测快照 | 不证明某个历史 Job 已发布；缺失不等于历史任务失败，也不是自动执行一次新发现 |

“回执”在本文中是语义名称，不是新公开类型。refresh 继续通过冻结的公开响应/错误表达结果；主代理同步生成契约后，前端按实际公开模式消费。不得以 Job Succeeded、设备列表相同或随后 GET 成功拼造自己的回执。

若 Job 已持久化成功，但接受前因取消、到期、卸载或代变被拒绝，历史成功保持原终态，refresh 按服务端真实拒绝返回失败。前端不能将历史改成失败以掩盖差异，也不能为了让 refresh 成功而读取其他任务的目录。历史结果用于回顾本次观测，当前目录才用于当前选择及动作准入。

## refresh 只认领自己的任务

设发现 A 已接受，等待者尚未收到响应；随后发现 B 接受新目录。A 的响应应来自 A 的回执，GET 此时可以是 B。前端不得用 B 的 discoveryJobId、设备或原始状态替换 A 的返回值，也不得补交第二份发现 Job 来“修复”A 的结果。

调用返回值与当前 snapshot 的写入资格分别判断：A 的回执可说明 A 的成功接受，但旧请求、替代请求、目录修订变化或提供者代变，均不能让 A 回写已撤销或更新的本地目录。对已经观察到 B 的消费者，A 只能是该次调用的历史结果；是否仍可向活跃调用方交付，按本文取消与接受原则及未决边界确认，不臆造新的 wire 标志。

本地开始 refresh 时即撤销不可靠旧观测和选择，是前端防误用策略；服务端在等待串行锁与真正执行发现时的清空时点是服务端职责。两者不能被解释为同一个决定点，也不能用前端 snapshot 为空证明服务端已执行、已取消或已完成清理。

## 取消与接受的先后

先后以服务端冻结的接受决定为准，不以浏览器调用 abort 的墙钟时间、HTTP 返回顺序或两次 GET 采样猜测。前端发送取消和停止本地等待，不代表服务端已收到或已经裁定取消。

| 服务端及调用方情形 | 前端应保持的语义 |
| --- | --- |
| 取消先赢，任务尚未形成成功观测终态 | 消费实际取消结果；候选不得成为目录；晚成功不能改旧终态或恢复本地观测 |
| Job 已成功，但取消在目录接受前赢 | 历史成功与 refresh 拒绝并存；不补发布、不改历史，不用后来 GET 冒充回执 |
| 接受先赢，随后调用方取消等待 | 调用方可按既有作用域取消规则结束等待；该取消不追溯撤销服务端已接受目录或改写历史终态。当前目录仍可能随后被新发现或卸载替换/撤销 |
| 接受后，浏览器插件或挂载作用域退出 | 释放请求与订阅，不向失效实例写状态或继续交付晚结果；不把本地退出当作服务器提供者已卸载 |
| 卸载先赢，或旧代在新代加载后返回 | 拒绝旧观测的当前消费，不复活目录、选择或旧 HostContext；旧失败清理不得删除新代观测 |

接受先赢不要求已取消的调用方继续等待，也不把取消解释成事务回滚。可信插件自身副作用、服务器执行与清理是否停止，需要其各自生命周期证据；取消一个 Promise 或释放订阅不证明这些副作用已被强制中断。

## 原始状态随整份观测消费

沿原始状态设计，归一化状态负责通用准入，recovery、sideload、bootloader 及未知原文负责观测说明。字段、版本和限制以最终冻结公开契约为准；本文不把候选设备 API 或原始信息模型写成当前 SDK 已支持。

原始信息必须与同次完整目录的提供者、代际、设备引用和 discoveryJobId 一起替换、失效或清空。不能从历史 Job、后来 B 的目录或上一代缓存为 A 补原文；新观测没有原始信息时，不残留旧值。未知原文不能授权动作、覆盖归一化状态，也不能成为浏览器 shell、工具路径或超时覆盖入口。

成功但未接受的 Job 原始观测仅属于历史结果；它不能恢复当前选择。引用仍以 providerId/generation/localId 区分，不能因平台或设备名相同把历史观测套到新代。

## 本实例撤销与远端变化

本实例执行服务器插件管理时，继续先撤销不可靠的操作目录、目标设备目录和选择，再重查；重查失败或取消不恢复旧缓存。旧 refresh 回执、旧聚合 GET 和旧 finally 不得复活被撤销的目录，也不得清除后来新代的合法观测。app 只装配管理与撤销回调，失效规则保留在所属功能模块。

浏览器插件卸载或挂载退出只负责自身请求、订阅和贡献资源；提供者实际卸载由服务器管理契约决定。服务端卸载在接受之后发生时，可以撤销已经接受的目录，此后 GET 没有旧代；先前 refresh 回执仍描述接受当时的结果，不能据它重建当前目录。

其他同事实例的装卸、发现或远端变化仍通过显式 refreshProviders/refreshDirectories 获知；需要重新发现时才调用 refreshProvider。这里没有远端推送、后台轮询或常驻热拔插承诺。当前本地引用校验不替代服务端最终准入，未观察到远端撤销也不意味着引用仍有效。

## 重启后历史不等于当前观测

历史任务按现有持久化与查询契约读取，当前目录按重启后实际提供者与 GET 结果读取，两者分别呈现。不得从历史 Succeeded、旧 discoveryJobId 或任务结果反序列化出可选择的当前目录；也不得因 GET 为空将历史成功改成失败。

如果重启后尚无已接受目录，前端保持无当前观测，按现有入口重新查询或显式发现。旧代引用不能因 localId 相同自动重绑；动作仍需当前提供者、代际、设备状态和能力验证。服务端是否恢复或重建观测以其最终契约为准，本文不承诺回执持久化、重启自动发现或可重放发布。

## 冻结后最小验证与实施归属

| 待验证场景 | 必须分别观察的结果 |
| --- | --- |
| Job 成功后、接受前拒绝 | 历史实际终态保持成功；refresh 返回真实拒绝；本地及 GET 不因历史成功恢复目录 |
| A 接受后 B 更新，最后交付 A | A 只取得 A 的回执或冻结的明确拒绝；GET 可为 B；本地已观测的 B 不被 A 覆盖 |
| 取消先赢与接受先赢 | 前者候选不发布；后者取消等待不追溯回滚服务端接受。用服务端决定点证据判断，不能仅以浏览器 abort 顺序判断 |
| 本实例卸载、重查失败、新代加载后旧响应 | 目录和选择立即撤销；失败不恢复；旧代成功/失败均不复活旧观测或删除新观测 |
| 远端装卸后显式重查 | 重查更新当前观测和引用；无后台推送假设；旧引用仍由服务端最终拒绝 |
| 重启查询历史与 GET 空目录 | 历史成功可见但不可用于当前选择；重新发现恢复当前目录，不重放历史发布 |
| 原始状态与日志消费 | 同次观测完整替换原文；未知文字不改变准入。真实服务错误沿既有日志 ID 链路保留，本地取消/冲突不伪造服务器日志 ID |

矩阵只提出后续验收条件，没有新增测试或执行任何门禁。前端受控响应测试可证明映射、撤销和晚到保护；服务端接受决定、取消竞争、单 Job/单执行与重启行为须由主代理统一集成验证，不冒充服务器锁或真机证据。

后端与主代理负责冻结内部接受规则、公开错误及响应模式，并生成类型。前端后续仅在明确分配写集后调整 shared/api 校验、app 公开映射和 devices 消费规则；不从插件读取私有任务、注册表或令牌，不增造独立发现缓存。当前唯一交付物为本文，已有冻结 inputs 保持不动。

## 仅三处未决消费边界

1. **失败的公开证据**：历史成功但接受拒绝时，refresh 的精确公开错误映射、日志 ID 及已有任务关联是否足以让消费者辨别该情形。由主代理冻结实际响应；前端不预造回执 DTO、附加字段或依赖未公开的内部原因。
2. **回执交付与本地提交**：已接受 A 在 B、卸载或本地取消之后交付时，活跃调用方得到 A 还是已有取消/失效错误，以及不符合本地修订的 A 如何只作调用结果而不写 snapshot。原则已定为不认领 B、不回滚接受、不复活旧观测；具体消费门禁需结合最终服务端回执与现有作用域取消实现统一确认。
3. **重启后的查询关联**：历史任务与当前 GET 目录是否已有足够公开关联，以及历史查询能否说明接受记录曾存在。没有公开证据时只能分别报告历史观测与当前目录，不推断发布经历；不为此增加回执缓存或自动恢复选择。

以上不重开方案1选择，也不新增产品 UI、远端推送、常驻会话或真机验收范围。本文完成静态文档检查后冻结，后续只读审查不改变其内容；本轮未实施统一发现消费增量。
