# 产品页面接口清单

日期：2026年10月14日，Asia/Shanghai。本文按当前前端公开工厂、后端路由与插件清单核对页面接入范围，供选定工坊背景之后实施产品界面。本文只记录静态事实与已有证据边界，没有新增后端实现、生成类型或测试结论。

## 实施原则

- 产品页以设备、应用、包、会话、产物等真实业务对象组织。通用操作目录及 JSON 调试入口可作为高级工具，不能替代应用管理、性能分析、投屏、自动化或助手页面。
- 业务入口是否可用以本次刷新后的操作、设备能力或会话目录为准。表内列出 ID 只说明源码中存在合同，不保证当前部署已安装、加载或配置该插件。
- 新 HTTP 消费沿 `/api/v2` 与生成类型，组件不直接 `fetch`。异步用例传显式 `AbortSignal`，保留真实错误类别与日志 ID。
- 跨功能组合放在 `app`：注入各 feature 的公开工厂或端口，不从某个 feature 导入另一个 feature 的内部文件。普通任务使用 `createHttpJobGateway(client)`；产物下载适配传 `client.downloadArtifact`，保持原字节。
- 服务器工具路径、Java/ADB/HDC/Frida/CLI 配置、终端程序与模型凭据属于部署。页面仅提交公开 ID、产物 ID 与业务参数，不能添加任意程序、命令、路径或环境编辑器。
- 默认免鉴权；配置了可选 API 令牌时由既有客户端令牌提供器注入。令牌不写入 URL、localStorage、任务输入或日志。

## 当前公开装配与接入缺口

当前 `createFrontendRuntime(options)` 已装配 `operations/tasks/devices/serverPlugins/pluginPackages/webPlugins/themes/artifacts/aiSdk/aiSdkStreaming/performance/mirroringStreaming/mcp`。公开 `HostContext` 已有设备与产物访问、任务历史及扩展服务；可信浏览器插件通过 `host.ai-sdk`、`host.ai-sdk.stream`、`host.performance`、`host.mirroring.stream` 消费对应业务。

其它已有 feature 工厂需由产品装配层显式构造、注入并销毁，不能因为文件存在而把它们当作 runtime 的同名属性。`main.ts` 当前通过 `createFrontendBootstrap` 装配运行实例，已不是早期“没有 runtime”状态；基础启动不代表各业务产品页已接入。生成类型只由主代理统一同步。

| 公共消费 | 真实后端入口 | 页面接入要点 |
| --- | --- | --- |
| `createOperations(client)`、`createTasks(client, beforeSubmit?)` | `GET /api/v2/operations`；`GET/POST /api/v2/jobs`；`GET /jobs/{id}`、`POST /jobs/{id}/cancel`、`GET /jobs/{id}/events` | 目录、任务列表、真实状态、增量事件及日志关联；任务 ID 与日志 ID分开展示。普通任务事件不包含模型 token 或实时视频 |
| `createDevices(gateway)`，runtime 已装配 | `GET /api/v2/device-providers`、`GET /api/v2/devices`；`POST /device-providers/{id}/refresh`、`POST /device-actions` | 完整 `providerId/generation/localId`；刷新目录不隐式发现，主动发现使用 `refreshProvider`；能力版本、scope/access 与 availability 决定按钮准入 |
| `createHttpArtifactBrowser(client)` | `POST /api/v2/artifacts`；`GET/DELETE /artifacts/{id}`；`GET /artifacts/{id}/content`、`GET /artifacts/{id}/entries` | 上传、已知 ID 元数据、ZIP 分页预览、原字节下载、删除；没有公开全产物列表或配额面板查询接口 |

媒体页面必须由页面拥有画布、VideoFrame消费及Blob URL寿命。视频回调同步消费或复制后，原帧由sink关闭；共享 AudioContext 不由业务sink关闭。投屏 `readPackets` 与 `readOutput/pollOutput` 共用输出游标，只能选一个媒体消费者，不能先耗尽字节后再要求播放重放。EOF只结束控制输入；取消返回 Stopping 后仍查询 Finished及cleanup。

性能曲线的缺测显示断点与原因，不能补零或沿用上一帧。原单位按合同展示，SurfaceFlinger FPS 表示所选层展示频率；不称为引擎提交或GPU完成帧率。电压µV、电流µA、温度°C、有符号整机净电池mW保留实际来源与极性；不能取绝对值或归因到目标游戏。

## 建议产品路由与实施顺序

路由名称是产品组织建议，不改变后端端点。首页使用已选背景及真实连接/设备/任务摘要，进入工坊后保持统一导航，业务页面以专用布局实施。

1. 工坊概览与设备页：装配一个runtime，建立可观察服务连接、提供者发现、设备选择和真实空/失败态；设备卡显示完整归属与规范状态，详细ID可收起但可复制。
2. 应用与包、文件产物、截图：共同组合设备、任务和产物公开端口，使用专用包列表/清单/签名/归档预览与结果区；任务关联保留原输入与日志ID。
3. 投屏、录像、性能、Root：各自独立会话与生命周期，切页退出消费者，服务资源显式停止；媒体真实解码和采样缺测单独验收。
4. Frida、自动化、终端、AI、DEX、MessagePack、表格：由app注入现有专用工厂；每页先刷新实际操作或会话目录，缺依赖显示具体状态和工具准备入口；不添加统一JSON表单来表示产品页已交付。
5. 任务中心、插件中心、工具供应、设置与主题：共享真实任务/日志摘要组件、可复制关联ID；两类插件运行与部署分开展示，主题恢复和设置CAS冲突都做显式交互。

每个页面至少验证真实空目录、成功、后台失败、取消等待、显式服务取消、旧设备/旧代结果、依赖未准备、卸载后的入口收敛；只在适用业务增加对应场景。已有工厂测试不替代新可见交互、浏览器媒体、真机或真实模型验收。页面实现完成后，由主代理统一生成类型并执行前端四门禁；后端未改动时不因本文盘点擅自启动Cargo或重跑旧门禁。
