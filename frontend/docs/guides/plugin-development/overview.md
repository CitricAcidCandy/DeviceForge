# 浏览器插件开发总览

推荐流程：只维护一份 manifest.json 开发清单（manifest_version:1），在 components 声明入口、能力与配置，在 market 声明市场资料；完整字段、默认值和示例均由 manifest 主题直接提供。使用带 plugin pack 命令的 DeviceForge CLI 发行包生成运行、市场和发布清单，再 plan/publish 或离线安装，命令查询 packaging 主题。自己的 package.json 只负责依赖和构建，DeviceForge 身份与版本不用重复填写。

本指南对应 DeviceForge 浏览器插件 SDK v2（`apiVersion: 2`），内容随宿主编译发布。它描述当前公开开发契约；运行时是否提供可选能力仍须检查实际上下文与扩展目录。需要完整可打包入口时读取 `examples`，清单、SDK、生命周期、打包与验证分别读取同名主题。

插件在自己的独立工程开发，无需获取宿主源码。通过 `deviceforge.get_plugin_development_guide` 按主题取得 `documents.content` 正文，以公开 HostContext、操作目录、JSON Schema 和宿主提供的公共 ESM 入口接入。

知识范围包括开发流程、公开能力与接口、约束、生命周期、调试和发布要求。`overview` 介绍能力与开发顺序，`manifest` 描述声明约束，`sdk` 提供公开接口，`lifecycle` 说明加载、挂载和清理，`examples` 提供示例，`dependencies` 描述共享依赖，`packaging` 说明发布要求，`validation` 提供调试流程与结果核对。正文直接交付，不包含宿主源码位置或文档物理地址。

## 能力与职责

浏览器插件是可信的原生 ESM 模块，默认导出插件对象。宿主调用 `activate(context)`，按需挂载面板或其他界面贡献，并在停用、失败回滚或关闭时撤销本代贡献、取消等待、释放已登记资源。插件可以自行打包 React 等界面依赖；原生 DOM 同样可用，不要求宿主私有模块或未发布的 npm SDK 包。

| 扩展面 | 插件可以实现的内容 | 必须遵守的边界 |
| --- | --- | --- |
| 面板 `panels` | 在插件页的面板入口打开独立界面 | 不会因声明面板而自动嵌入设备、设置或其他业务页面 |
| 组件 `components` | 在具名插槽追加或替换内容 | 槽位须由宿主实际开放；替换依赖槽位适配器 |
| 模块 `modules` | 声明 `route/title` 与界面挂载函数，生成插件页面与侧栏入口 | 路由按插件命名空间隔离，不能与替换宿主页面混为一谈 |
| 命令、服务 | 提供可调用逻辑、精确版本服务 | 使用插件命名空间，处理调用取消和提供者撤销 |
| `beforeTaskSubmit` | 变换或拒绝公开任务提交 | 只影响宿主实际接入钩子的提交链，不拦截任意网络请求 |
| 主题 `themes` | CSS 变量、可信 CSS、明暗模式 | 登记后须显式选择；卸载撤销并恢复宿主基础样式 |
| 操作与任务 | 发现操作、提交、查询、显式取消任务 | 以实际操作目录和 JSON Schema 为准，接受不等于成功 |
| 设备、产物、历史 | 通过可选 SDK 扩展读取和操作 | 先判断字段存在，按当前能力与代次准入 |

当前产品支持以下界面接入方式；先根据期望显示位置选择贡献，再读取 `sdk` 的完整签名和 `examples` 的挂载示例：

| 目标位置 | 接入方式 | 行为与限制 |
| --- | --- | --- |
| 插件页的独立面板 | `panels` | 用户选择面板后挂载，不自动进入原业务页面 |
| 设备工作台右栏「应用」页签 | `components`，`slot: 'devices.apps'` | `append` 在原内容之后追加；`replace` 接管整个区域 |
| 自己的插件页面与侧栏入口 | `modules` | 如 `/catalog` 派生 `#/plugin/<插件ID>/catalog`，不需要额外声明独立面板 |
| 已开放的宿主业务页面 | `components`，`slot: 'route.<路由>'` | 可追加或替换；`route.settings` 与 `route.marketplace` 只允许追加 |
| 设置页插件分组 | `components`，`slot: 'settings.plugin.section'` | 只允许追加插件设置 |

`workshop.extensions` 是旧工坊入口的兼容插槽，不能据此判断当前产品只有这一个接入位置。组件只能使用宿主实际开放的具名插槽，不能按任意 DOM 选择器注入，也不能直接修改宿主 React 组件。`devices.apps` 已开放整个应用区域，但原列表每行的名称、图标和操作还没有独立插槽或展示解析服务入口；声明一个别名解析服务不会自动改变原列表。只想追加面板时复用 `mount` 注册组件即可；整块替换时需要插件承担该区域的界面和交互。

实际挂载成功后才隐藏被替换的宿主内容；等待、失败或卸载时回落到默认内容。插件模块路由按插件隔离，不同插件可使用相同的 `/catalog`；同一插件归一化后相同的页面键会被拒绝。页面直达在启动尚未就绪时保留。完整产品外壳、导航和顶栏仍没有整体替换接口。

## 前后端配套

已有后端操作可直接经 `context.listOperations/submit/getJob/cancelJob` 组合。需要新增设备协议、本机命令、采集、文件系统或持续运行能力时，应制作配套服务器插件，再由浏览器界面通过公开操作、设备能力或宿主服务消费。不要在浏览器代码导入 Rust 工程、Node 内置模块、宿主私有状态、服务器路径或服务令牌。

当前推荐用 `release.json`（`format_version:2`、`host_api_version:2`）将浏览器组件、配套服务器组件和工具依赖组成一个完整功能发布，市场显示一个功能条目，由宿主统一计划、安装、配置、启停和按修订更新。两类组件的底层包格式及运行协议仍独立；旧单组件安装入口保留兼容，不能拆装统一发布所属组件。

浏览器关闭面板或本地实例停用不会自动取消已接受的服务器任务；要取消任务须显式 `cancelJob` 后重查状态。发布持久启停由统一安装用例处理，不能用页面是否出现推断服务器工作成功。默认部署免鉴权，可选服务令牌由宿主管理，不能放进包、URL 或前端状态中。

发布安装与配置归运行宿主用户根，默认 `<home>/.deviceforge`，宿主可用 `DEVICEFORGE_USER_DIR` 指定；浏览器不选择该目录。根 `config.json`、`plugin-configurations/server`、`plugin-configurations/browser` 与共享 `tools` 分别承担启动配置、两类组件配置和工具内容；npx 缓存不是用户配置根。托管路径和用户高级覆盖由宿主处理，浏览器只读可公开的状态。在线市场和离线完整 ZIP 的安装要求见 `packaging`。

## 开发顺序

1. 根据目标选择浏览器、服务器或配套开发；先确认独立面板、已开放业务插槽、独立路由或逻辑服务，避免把独立面板误当作原页面嵌入。
2. 读取真实操作目录或服务目录，确定输入、版本、取消及日志契约。
3. 使用独立清单和 ESM 入口，声明 SDK 2 与插件命名空间。
4. 所有异步 SDK 调用传入 `AbortSignal`，所有监听、订阅、DOM 和外部资源登记释放。
5. 构建两类独立组件，再打成完整发布并检查实际闭包；在市场管理流程安装、配置、启用后验证挂载和停用。单组件示例仍可走旧兼容入口。
6. 分别记录静态、打包、真实宿主行为、界面和设备验证，不能用构建通过替代运行验收。

SDK 成功结果为 `{ data, logId }`，错误保留 `kind/code/status/logId/retryAfter`。日志 ID、任务 ID、产物 ID 各有用途，不可相互替代。扩展状态属于当前运行注册表的内存状态，命名空间隔离不是持久化或安全沙箱。


新版统一依赖使用 dependencies.json（独立组件）或 v2 清单的 dependencies，先自动发现本机与用户根共享工具，一次安装只下载缺失必需项；启动与重新检测不下载。v1 保留兼容。完整字段、来源约束与管理接口通过本指南工具查询 `dependencies` 主题。
