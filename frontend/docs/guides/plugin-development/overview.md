# 浏览器插件开发总览

本指南对应 DeviceForge 浏览器插件 SDK v2（`apiVersion: 2`），内容随宿主编译发布。它描述当前公开开发契约；运行时是否提供可选能力仍须检查实际上下文与扩展目录。需要完整可打包入口时读取 `examples`，清单、SDK、生命周期、打包与验证分别读取同名主题。

## 能力与职责

浏览器插件是可信的原生 ESM 模块，默认导出插件对象。宿主调用 `activate(context)`，按需挂载面板或其他界面贡献，并在停用、失败回滚或关闭时撤销本代贡献、取消等待、释放已登记资源。插件可以自行打包 React 等界面依赖；原生 DOM 同样可用，不要求宿主私有模块或未发布的 npm SDK 包。

| 扩展面 | 插件可以实现的内容 | 必须遵守的边界 |
| --- | --- | --- |
| 面板 `panels` | 自己的任务、设备和结果界面 | 只操作 `mount` 分配的容器，返回清理函数 |
| 组件 `components` | 在具名插槽追加或替换内容 | 槽位须由宿主实际开放；替换依赖槽位适配器 |
| 模块 `modules` | 声明 `route/title` 与界面挂载函数 | `route` 是元数据，不自动创建左侧导航或路由 |
| 命令、服务 | 提供可调用逻辑、精确版本服务 | 使用插件命名空间，处理调用取消和提供者撤销 |
| `beforeTaskSubmit` | 变换或拒绝公开任务提交 | 只影响宿主实际接入钩子的提交链，不拦截任意网络请求 |
| 主题 `themes` | CSS 变量、可信 CSS、明暗模式 | 登记后须显式选择；卸载撤销并恢复宿主基础样式 |
| 操作与任务 | 发现操作、提交、查询、显式取消任务 | 以实际操作目录和 JSON Schema 为准，接受不等于成功 |
| 设备、产物、历史 | 通过可选 SDK 扩展读取和操作 | 先判断字段存在，按当前能力与代次准入 |

当前产品装配的具名插槽为 `workshop.extensions`；它是工坊扩展区，不代表每个内置页面都开放任意插入点。其他宿主可以装配不同槽位，安装后应查询贡献与宿主支持情况。插件页提供面板、模块和贡献操作入口，不能据此假定自己的模块已加入产品导航。

## 前后端配套

已有后端操作可直接经 `context.listOperations/submit/getJob/cancelJob` 组合。需要新增设备协议、本机命令、采集、文件系统或持续运行能力时，应制作配套服务器插件，再由浏览器界面通过公开操作、设备能力或宿主服务消费。不要在浏览器代码导入 Rust 工程、Node 内置模块、宿主私有状态、服务器路径或服务令牌。

浏览器包和服务器包分别部署、启用与停用。浏览器停用不会自动取消已接受的服务器任务，也不会停用配套服务器插件；要取消任务须显式 `cancelJob` 后重查状态。默认部署免鉴权，可选服务令牌由宿主管理，不能放进包、URL 或前端状态中。

## 开发顺序

1. 根据目标选择浏览器、服务器或配套开发，并读取相应指南。
2. 读取真实操作目录或服务目录，确定输入、版本、取消及日志契约。
3. 使用独立清单和 ESM 入口，声明 SDK 2 与插件命名空间。
4. 所有异步 SDK 调用传入 `AbortSignal`，所有监听、订阅、DOM 和外部资源登记释放。
5. 打包后检查实际归档，再通过插件页上传、启用、挂载和停用。
6. 分别记录静态、打包、真实宿主行为、界面和设备验证，不能用构建通过替代运行验收。

SDK 成功结果为 `{ data, logId }`，错误保留 `kind/code/status/logId/retryAfter`。日志 ID、任务 ID、产物 ID 各有用途，不可相互替代。扩展状态属于当前运行注册表的内存状态，命名空间隔离不是持久化或安全沙箱。
