# 插件开发者快速开始

从 [browser-device-tools](../../../examples/browser-device-tools/README.md) 开始：它是自包含的原生 ESM 浏览器插件，使用公开 SDK v2 登记 8 个命令、2 个服务和 1 个任务提交前钩子。插件没有页面、运行依赖或宿主私有导入。本说明给出第三方开发者可执行的打包、在线启停与公开能力消费流程；文档编写角色未执行这些命令，具体产品界面仍等待设计稿。

## 先区分宿主与插件

宿主生产 ESM `/assets/plugin-host.js` 真实导出 `createFrontendRuntime` 和 `createNamedSlotAdapter`，源码入口见 [public-runtime.ts](../../src/app/public-runtime.ts)。宿主 app 负责 `runtime.pluginPackages/serverPlugins/artifacts` 的包管理、服务器管理和产物传输。当前 `main.ts` 没有自动装配产品 runtime，也没有安装/操作页面；下面在已部署静态页面的开发者工具中创建一个独立实例，不把它当产品 UI。

插件入口由宿主调用 `activate(context)`，只消费 [HostContext](../../src/plugin-sdk/index.ts)：`listOperations/submit/getJob/cancelJob`、`subscribeOperations`、`signal/onDispose` 及可选 `devices/extensions/artifacts/taskHistory`。SDK 不存在 `context.tasks`、包管理或服务令牌字段。跨插件调用使用 `extensions` 的公开命令/服务，不能导入 app/features/shared/plugins 源码取得私有能力。

## 1. 确认包描述与 ESM 入口

示例的 [package.json](../../../examples/browser-device-tools/package.json) 如下，`name` 是 npm 包名，安装身份来自独立清单的插件 ID：

```json
{
  "name": "deviceforge-browser-device-tools-example",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "description": "通过公开 SDK v2 消费设备能力、任务和生命周期的浏览器插件示例",
  "files": ["src", "plugin.json", "tests", "README.md"],
  "scripts": { "test": "node --test tests/example.test.mjs" },
  "engines": { "node": ">=22" },
  "deviceforge": {
    "kind": "browser",
    "manifest": "plugin.json",
    "entrypoints": {
      "any": { "runtime": "browser", "path": "src/index.mjs" }
    }
  }
}
```

[plugin.json](../../../examples/browser-device-tools/plugin.json) 为：

```json
{ "id": "browser_device_tools", "version": "0.1.0", "api_version": 2 }
```

入口 [src/index.mjs](../../../examples/browser-device-tools/src/index.mjs) 的默认导出使用同一 `id/version`、camelCase `apiVersion: 2`、必填 `panels: []` 和实际 `activate(context)`；它通过相对导入 `./session.mjs`、`./contributions.mjs` 装配功能。新插件应同时修改包名、清单、默认导出和贡献命名空间，保留一致版本，不直接覆盖别人的插件 ID。

浏览器包使用 `entrypoints.any`、`runtime: 'browser'` 和存在的 `.js/.mjs` 入口。路径相对于包根，依赖也必须随包发布；原生浏览器不能直接加载 TypeScript 或 Node 内置模块。宿主不执行 npm 安装脚本、不下载 npm 依赖。使用构建工具的第三方须事先生成自包含浏览器 ESM，本示例无需构建或安装依赖。

## 2. 打包并在线加载

在工程根目录，开发者可运行以下命令。`private: true` 防止误发布 npm registry，不妨碍标准打包：

```powershell
npm test --prefix examples/browser-device-tools
npm pack ./examples/browser-device-tools --ignore-scripts --pack-destination ./artifacts
```

得到 `artifacts/deviceforge-browser-device-tools-example-0.1.0.tgz`；npm TGZ 的内容根为 `package/`。本轮主代理已经打包的只读正式版本为 `artifacts/browser-example-20261010-004118/deviceforge-browser-device-tools-example-0.1.0.tgz`，SHA256 `79DE721D199B1BA71923EF8FEA6AAF93F162A5C5F0145905B186DD604ABF7726`。验证原冻结版本时选择该原包；自行修改后的包应有独立版本和摘要，不能复用旧验收结果。

打开当前部署的 DeviceForge HTTP 静态页面，在浏览器开发者工具 Console 中依次执行。API 与静态 ESM 使用当前页面 origin；宿主已由部署者构建并启动，这里不启动服务：

```js
const { createFrontendRuntime } = await import(
  new URL('/assets/plugin-host.js', location.origin).href);
const controller = new AbortController();
const signal = controller.signal;
const runtime = createFrontendRuntime({
  baseUrl: location.origin,
  transport: fetch.bind(globalThis),
  panelTarget: () => null,
  async esmImporter(url, current) {
    current.throwIfAborted();
    const module = await import(url);
    current.throwIfAborted();
    return module;
  },
});
```

以下文件选择仅取得本地归档 `File`（也是 `Blob`），不创建产品页面，也不依赖安全上下文文件系统 API：

```js
function chooseTgz() {
  return new Promise((resolve, reject) => {
    const picker = document.createElement('input');
    picker.type = 'file'; picker.accept = '.tgz';
    picker.addEventListener('change', () => {
      const file = picker.files?.[0];
      if (file) resolve(file);
      else reject(new Error('没有选择归档'));
    }, { once: true });
    picker.addEventListener('cancel', () => reject(new Error('归档选择已取消')), { once: true });
    picker.click();
  });
}
const tgz = await chooseTgz();
const installed = await runtime.pluginPackages.upload('browser', tgz, 'application/gzip', signal);
if (installed.data.id !== 'browser_device_tools') throw new Error('所选归档不是本示例');
await runtime.pluginPackages.refresh('browser', signal);
const loaded = await runtime.pluginPackages.enable('browser', installed.data.id, signal);
console.log(loaded.data, runtime.extensions.catalog());
```

上传只部署，`enable` 才执行入口。SDK v2 示例需要插件专属 `extensions.register`；过旧宿主缺少该扩展会明确激活失败。`panels: []` 使此实例无需面板 DOM，不能据此认为组件或模块已被自动挂载。

## 3. 运行命令、服务与任务

沿用上面的 `runtime/signal`，先读取目录：

```js
const execute = (name, input) => runtime.extensions.executeCommand(
  'browser_device_tools.' + name, input, signal);
const catalog = await execute('catalog', {});
console.log(catalog.data, catalog.logId);
const viaService = await runtime.extensions.callService(
  'browser_device_tools.catalog-service', '1.0.0', {}, signal);
console.log(viaService.data);
```

实际命令输入如下，详细实现见 [contributions.mjs](../../../examples/browser-device-tools/src/contributions.mjs) 和 [use-cases.mjs](../../../examples/browser-device-tools/src/use-cases.mjs)：

| 命令后缀 | 输入 | 用途 |
| --- | --- | --- |
| `catalog` | `{}` | 当前操作、已接收设备观测和有限 Job ID |
| `refresh-devices` | `{}` | 查询提供者与已有目录，不执行发现 |
| `discover` | `{providerId,generation}` | 发现指定提供者当代设备 |
| `select` | `{providerId,generation,localId}` 或 `null` | 选择完整引用或清除选择 |
| `invoke-read` | `{providerId,generation,deviceId,capability,version,input}` | 精确版本且声明为 read 的设备能力 |
| `submit` | `{operation,input}` | 通过公开任务提交链提交业务输入 |
| `get-job` | `{jobId}` | 独立查询服务器历史 |
| `cancel-job` | `{jobId}` | 显式请求服务器取消 Job |

`history-service` 同样使用版本 `1.0.0`，输入 `{jobId}`，通过 `runtime.extensions.callService` 调用。第三方浏览器插件在自己的命令回调中使用 `context.extensions.callService(id, version, input, signal)`；实际消费者见 [consumer.mjs](../../../examples/browser-device-tools/acceptance/consumer.mjs)。该文件仅作为公开接口用法参考，不是本示例包的生产入口。

普通操作须从当前 `catalog.data.operations` 取得完整 ID，再按其 `input_schema` 提供业务 input；不能自动选中陌生操作并提交。当前目录的可选 `operation.execution` 使用 `apiVersion/totalTimeoutMs/source`，缺省或 null 映射后省略，不猜测补默认值，不给提交增加预算覆盖字段。提交返回的是 Job，尚不代表执行成功；显式 `get-job` 读取 `status/result/error`，本示例没有自动轮询或事件重连协议。

示例 `require-current-operation` 钩子在每次任务提交前重新查操作目录，缺失或查询失败时停止后续钩子及 HTTP 提交。多个钩子按 `priority` 升序（缺省 0）再按 `id.localeCompare` 排序。它返回原业务输入；卸载后撤销这项规则，不自动停用其他插件。

## 4. 对接真实服务器提供者

可用自包含 [device-provider-node](../../../backend/examples/device-provider-node/README.md) 演示对接。它是模拟设备的真实 Node 进程插件，清单 ID 为 `device_node_example`，不是 Android/Harmony/iOS 真机。服务器须具备该示例要求的 Node 环境。开发者可从工程根目录标准打包：

```powershell
npm pack ./backend/examples/device-provider-node --ignore-scripts --pack-destination ./artifacts
```

在同一 Console 中调用 `chooseTgz()` 选择本次生成的服务器 TGZ，再由宿主上传并启用；插件自身没有这些管理入口：

```js
const serverTgz = await chooseTgz();
const serverInstalled = await runtime.pluginPackages.upload('server', serverTgz, 'application/gzip', signal);
if (serverInstalled.data.id !== 'device_node_example') throw new Error('所选归档不是 Node 提供者示例');
await runtime.pluginPackages.enable('server', serverInstalled.data.id, signal);
await execute('refresh-devices', {});
const observed = (await execute('catalog', {})).data;
const provider = observed.devices?.providers.find((entry) => entry.id === serverInstalled.data.id);
if (!provider) throw new Error('目录尚未接受该提供者，请显式刷新');
const capability = provider.definition.capabilities.find((entry) =>
  entry.id === 'provider.describe' && entry.version === 1
  && entry.scope === 'provider' && entry.access === 'read');
if (!capability) throw new Error('当前目录未声明示例所需的精确能力');
const submitted = await execute('invoke-read', {
  providerId: provider.id, generation: provider.generation,
  deviceId: null, capability: capability.id, version: capability.version, input: {},
});
const jobId = submitted.data.id;
const queried = await execute('get-job', { jobId });
console.log(queried.data.status, queried.data.result, queried.logId);
```

这是提供者作用域能力，必须传 `deviceId: null`。设备作用域先调用 `discover`，再从当前接受目录的设备 `reference` 取得 `providerId/generation/localId`；动作改用 `deviceId: reference.localId`，能力必须同时满足定义的精确版本、作用域、访问性质和该设备的可用声明。具体设备调用可沿用 [示例的能力驱动流程](../../../examples/browser-device-tools/README.md)，业务参数按真实能力约定填写。

公开 SDK 为 camelCase；HTTP 的 `provider_id/device_id/raw_state/execution_timeout_ms` 等字段由宿主映射，插件不导入生成 DTO 重造封套。`provider.definition.apiVersion` 与浏览器 SDK `context.apiVersion` 是两个版本；能力预算可选 `executionTimeoutMs` 只读，不能由 action/input 覆盖。API3 的可选 `device.rawState` 是原始说明，不代替归一化 `state` 或能力准入。

只有 `refreshProvider`（示例命令 `discover`）触发发现；`refreshDirectories` 读取已有观测。发现返回自己的回执，目录是否接受该结果仍应读取当前 snapshot，不能拿成功 Job 或旧回执重建当前目录。刷新开始会撤销本地旧观测与选择；其他客户端变更靠显式刷新获知，没有远端推送保证。

若本次 Job 仍 queued/running，显式 `cancel-job` 请求服务器取消，再 `get-job` 查询；不能用客户端 Abort 代替。卸载服务器提供者后仍可按已知 Job ID 查询历史，历史不补当前 provider、rawState 或预算。需要输入产物时，宿主可继续通过 `runtime.artifacts` 上传；自己的插件也可通过下述可选 SDK 扩展取得 ID，再按服务器声明传入业务 input（如 `artifact_id`），不能给服务器路径；见 [插件开发契约中的嵌套输入产物](插件开发.md#设备动作的嵌套输入产物)。

### 插件自己的原字节上传下载

以下用于自己插件的异步命令/服务或挂载回调，context 和 signal 来自宿主公开参数。冻结 browser-device-tools 示例及正式 TGZ 没有因此新增命令或改包。接口依据 [产物传输第一批裁定](../implementation/插件产物传输第一批裁定.md) 与 [公开模型](../../src/plugin-sdk/artifacts.ts)；本次源码、回归及说明已落盘，生成/check/test/build 和真实浏览器仍由主代理执行，不能复用后面的旧 LAN 九项报告宣称此次产物加法已验收。

```ts
if (!context.artifacts) throw new Error('当前宿主没有可选产物传输扩展');
const caller = AbortSignal.any([signal, context.signal]);
const source = new Blob(['{"value":1}'], { type: 'application/json' });
const uploaded = await context.artifacts.upload('input.json', source, caller);
const artifactId = uploaded.data.id;
const uploadLogId = uploaded.logId;
const downloaded = await context.artifacts.download(artifactId, caller);
const originalBytes = await downloaded.data.arrayBuffer();
const downloadLogId = downloaded.logId;
```

上传返回 `Artifact` 的 `id/filename/mediaType/size/sha256/createdAt`，与原宿主 `runtime.artifacts` 的 snake_case 响应分别消费。文件正文为 JSON 也不会按 HTTP data/result 拆包，NUL 或非法 UTF-8 原字节仍保留。插件自己的解析由业务契约决定；元数据协议错误和服务器错误保留本次 logId，本地取消未得到响应时日志可为 null。

卸载插件或退出挂载子作用域会撤销等待与旧入口，晚到成功不交付旧代。Abort 不保证已接纳上传回滚，也不自动删除产物或取消服务器 Job。SDK 不创建下载 URL；需要 `URL.createObjectURL(blob)` 时自己通过 `context.onDispose(() => URL.revokeObjectURL(url))` 登记清理。此次不增加元数据查询、ZIP 预览、删除、任务列表/事件或服务器管理接口，旧 API2 可省略 artifacts。

## 5. 开放贡献入口与所有权

下面均来自 SDK 真实导出。示例自身登记命令/服务/钩子，未登记组件、模块或面板；新增这些能力须在自己的插件中实现，并由宿主提供实际挂载位置，不修改冻结示例：

| 公开贡献 | 插件实现签名与字段 | 宿主调用入口 |
| --- | --- | --- |
| `commands` | `id/title/execute(input,context,signal)`，返回 `HostResult<JsonValue>` | `runtime.extensions.executeCommand(id,input,signal)` |
| `services` | `id/version/invoke(input,context,signal)`，返回同上；版本精确匹配 | `runtime.extensions.callService(id,version,input,signal)` |
| `components` | `id/title/slot/mode/mount(target,context)`，异步返回 `Dispose` | `runtime.extensions.mountComponent(id)` |
| `modules` | `id/title/route/mount(target,context)`，异步返回 `Dispose` | `runtime.extensions.mountModule(id)` |
| `beforeTaskSubmit` | `id/priority/transform(submission,context,signal)`，异步返回 `{operation,input}` | `runtime.tasks.submit(...)` 或 `HostContext.submit(...)` 所走提交链 |
| `panels` | `id/title/mount(target,context)`，异步返回 `Dispose` | `runtime.webPlugins.mount(pluginId,panelId)` |

静态贡献放在默认导出的可选 `contributions` 中；动态贡献由插件专属 `context.extensions.register(contributions)` 登记并取得撤销函数。根宿主上下文只消费贡献，没有动态 register。贡献 ID 必须以 `<插件ID>.` 开头，同次登记的 ID、全局贡献 ID 与模块 route 都须避免冲突；所有贡献绑定运行所有者和代次，不将旧回调留给新代使用。

组件 `mode` 缺省为 `append`，`replace` 需要宿主注入 `SlotAdapter`。公开 `createNamedSlotAdapter([{id,target,renderDefault}])` 提供默认 renderer；`renderDefault(target)` 返回释放函数，替换贡献卸载后恢复默认渲染。具名 slot 必须由实际宿主事先定义，不能把示例测试用 slot 当所有部署都有的产品入口。插件只在 `mount` 得到的 target 内渲染，不通过私有 DOM monkeypatch 宣称受控替换。

模块 `route` 是元数据，不自动创建页面或路由器。宿主注入 `moduleTarget(route,pluginId,moduleId)`，进入调用 `mountModule(id)`，退出调用 `runtime.extensions.unmount(id)`，取消挂载子请求并移除 DOM，但保留模块登记和插件其他逻辑；插件卸载撤销整代。组件也通过 `unmount(id)` 退出；面板使用 `webPlugins.unmount(pluginId,panelId)`。框架无关挂载接口不要求新增 UI 库，具体产品 UI 继续等设计稿。

`extensions` 还公开 `catalog/subscribeEvent/emitEvent/getState/setState/subscribeState`。插件只能发射自身命名空间事件并读写自身命名空间状态；跨插件数据通过服务获取，事件回调带 `pluginId/generation`。示例使用 `browser_device_tools.catalog` 状态和 `browser_device_tools.changed` 事件，不把本地激活 runId 当服务器 generation。

## 6. 取消、日志和退出

每次 SDK 异步调用传入显式 AbortSignal。命令/服务/钩子的 `signal` 已涵盖调用者等待和提供者作用域；插件自己的异步工作继续合并 `context.signal`，设备相关工作也绑定完整 provider/generation。使用回调收到的上下文，不用激活时保存的根上下文绕过挂载子生命周期。

插件用 `context.onDispose` 或注册返回的 `Dispose` 登记自有事件、订阅、定时器和外部资源；清理应可重复调用，并真实等待需要等待的释放过程。所有登记资源随卸载撤销；激活/挂载失败回滚整代，清理错误会汇总并传播，不能吞掉后宣称释放成功。宿主装配的 slot adapter 由宿主另行 `dispose`，不是任意插件接管的资源。

调用者取消、提供者卸载、调用插件卸载或注册表关闭时，宿主等待会及时拒绝，晚 resolve/reject 不再交付旧结果。新请求可能收到 `command_unavailable/service_unavailable`；服务按精确版本重新查询。B 卸载不会自动停用消费者 A，B 重载不复活旧调用；A 按 ID/版本重新发起的请求可解析新 B。可信插件代码若忽略信号，自己的副作用仍可能运行，宿主停止等待不等于强制终止代码或完成外部清理。

成功 SDK 返回 `{data,logId}`，HTTP v2 原响应为 `{log_id,data}`；错误为公开 `HostError`，保留 `kind/code/status/logId/retryAfter`。SDK camelCase 与 HTTP snake_case 不混用。协议 2/3 带产物的公开 `Job.result` 可为 `{result,artifacts}`，包装内 `result` 才是业务结果；读取前按 JSON 结构检查，不把 HTTP data、Job.result 和业务 result 混成一层。

本地参数/代次准入错误可能没有服务器日志 ID，`select` 等本地操作也返回 `logId:null`。示例 `example_*` 参数错误是本地 Error，不假造服务器 HostError。不能把 Job ID、产物 ID、运行路径标记或任意字符串当日志 ID。示例 catalog 的日志 ID 来自操作目录查询，其设备观测是已接收本地快照，并非同一服务器原子快照。

沿用前文变量，正常停用、重载与部署删除如下；最后关闭整个独立宿主：

```js
await runtime.pluginPackages.disable('browser', 'browser_device_tools', signal);
const reloaded = await runtime.pluginPackages.enable('browser', 'browser_device_tools', signal);
console.log(reloaded.data.generation);
await runtime.pluginPackages.remove('browser', 'browser_device_tools', signal);
await runtime.pluginPackages.disable('server', 'device_node_example', signal);
const historical = await runtime.host.getJob(jobId, signal);
console.log(historical.data.status, historical.data.result);
await runtime.pluginPackages.remove('server', 'device_node_example', signal);
controller.abort();
await runtime.dispose();
```

历史按 Job ID 独立读取，不要求浏览器插件、旧操作或旧设备提供者仍存在；卸载不删除服务器历史，也不自动取消已接受 Job。`controller.abort()` 只取消该调用者等待；需要服务器取消时显式调用 `cancelJob` 并查询状态。在线管理等待取消后应重查实际目录，不能推断事务回滚或自动重放。

### 插件查询任务历史与状态事件

SDK API2 新增可选 `context.taskHistory`，真实签名见 [task-history.ts](../../src/plugin-sdk/task-history.ts)，实施边界见[第一批裁定](../contracts/任务历史与事件公开接口第一批裁定.md)。旧宿主可能省略，插件先检测；原 getJob 返回原 Job，历史扩展的 get 另返回包含持久化 input/createdAt 的 HistoricalJob，不补当前操作预算或设备代次。冻结 browser-device-tools 示例及其正式 TGZ 没有为此加法改包，下述代码供新插件自身逻辑使用，不表示旧包已经登记历史命令。

```js
async function readTaskHistory(context, callerSignal) {
  const history = context.taskHistory;
  if (!history) throw new Error('宿主未提供任务历史扩展');
  const signal = AbortSignal.any([context.signal, callerSignal]);
  const recent = await history.list({ limit: 20 }, signal);
  const first = recent.data[0];
  if (!first) return { recent, job: null, events: null, nextAfter: 0 };
  const job = await history.get(first.id, signal);
  const events = await history.events(first.id, { after: 0 }, signal);
  const last = events.data[events.data.length - 1];
  return { recent, job, events, nextAfter: last?.sequence ?? 0 };
}
```

list 的 limit 显式值须为 1..200 安全整数，省略传 `{}` 交服务端默认 50；没有列表游标或平台筛选。events 的 after 为非负安全整数，每次最多 200 条状态记录；显式下次查询传最后一条 sequence，取消/失败不推进消费方游标。事件公开 jobId/status/timestamp，sequence 为正安全整数；允许序号间隙与时间不单调。时间为 Unix 毫秒，SDK 不猜单位或改数值。这里只读取状态事件，不是日志/百分比进度、推送订阅或自动重连。

三方法均返回 `{data,logId}`。get 和 events 精确验证请求任务关联，协议映射失败保留该次日志；本地无效查询为 `protocol/invalid_history_query`，历史和事件映射错误分别为 `invalid_history/invalid_job_events`。未取得响应的取消没有服务器日志 ID。调用者、runtime、插件实例或挂载子作用域撤销会及时拒绝等待，忽略 signal 的端口晚 resolve/reject 不交付旧结果，重载不复活旧引用。历史查询退出不删除记录或调用 cancelJob，已经交付的记录不会因后来卸载追溯撤回；插件自行管理选择/定时器，并登记清理。

本批任务历史源码与独立回归已落盘，生成/check/test/build 和真实生产浏览器由主代理另验；前文旧九项 LAN 与产物报告不能充当任务历史扩展证据。没有新增产品界面、轮询协议或服务器 API。

## 7. ESM 换代与局域网部署

默认部署免鉴权，宿主 `tokenProvider` 可省略；非空服务令牌由部署者另行配置请求头，插件不读取令牌，不将其放入 URL、localStorage 或归档。已安装静态 ESM 资源在可选令牌模式仍公开，包内不可包含服务凭据。在线浏览器代码按可信代码运行，不增加隔离或来源审批；清理和资源限额服务于运行稳定性。

LAN 页面应使用部署机器实际非 loopback IPv4 的 HTTP origin。普通 LAN HTTP 可能 `window.isSecureContext === false`，不能假定 `crypto.randomUUID`、安全文件系统等 API 存在。宿主 loader 和冻结示例的本地激活标记均不再依赖安全 UUID；标记只是本模块运行身份，不承担鉴权。开发者自有插件若需要浏览器特定 API，应显式检查可用性，不能要求同事把 LAN URL 改为 loopback 才能运行。

宿主每次实际加载从 `/api/v2/browser-plugins/{id}/runs/{run_id}/assets/{entry_path}` 导入，`run_id` 是合法独立路径段，不保证 UUID 格式。包内 `./dependency.mjs`、相对动态导入及相对资源沿用同一运行前缀；原生 ESM 的相对路径应以模块 URL 为基准。对资源可用 `new URL('./resource.json', import.meta.url)`，不要把模块资源路径误解析为当前页面路径。

重载使用新运行路径，避免入口与相对依赖复用旧模块状态。只对入口加 `?generation=...` 不能清除其相对依赖缓存；包内绝对 URL 或固定跨包引用也不自动获得此运行前缀，插件需自行保证引用生命周期。重复 enable 已加载插件不重复导入，先 disable 再 enable 才创建新代。不可把路径换代称为把已执行 ESM 从浏览器内存卸出。

更新同 ID 包时先停用并删除旧部署，再上传新版；同 ID 不覆盖。browser remove 只先停当前 runtime 并撤销其加载源，不能强制停止另一台同事浏览器中已运行的代码。独立实例、自有副作用、服务器 Job 与部署文件各有生命周期，不能用删除文件代替资源清理。
