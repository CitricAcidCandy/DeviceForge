# 前端目录与组件约束

采用 Ant Design Pro 的页面就近组织原则：业务界面归 pages，跨页面逻辑归 features，公共展示归 components，公共请求归 services/api。features 是本工程的复用扩展，上游没有同名规范。上一轮 feature 业务组件与展示入口规则由本约束覆盖。

## 页面与应用装配

`src/pages/<功能页>/index.tsx` 是路由公开入口，局部组件、hooks、类型和样式放页面内部；例如 packages 页的 AppsPanel 留在 pages/packages/components。只用一页的实现不提升为公共组件。app 负责启动、路由与装配，仅通过页面 index.tsx 引用页面，不能读取页面私有组件。

页面另可消费 shared/jobs/index.ts 的公共作业能力，以及 plugin-sdk/index.ts、plugin-sdk/json.ts 的公开契约；不开放其他 shared 文件或 SDK 私有路径。

页面可读自身私有文件、feature 核心 index.ts、公共组件入口、services/api 和 utils；不读取其他页面的实现。既有页面保留精确的 app/product 支撑过渡清单：services.ts、hooks.ts、feedback.tsx、capabilities.tsx、device-target.ts。此项保护现有行为，不开放任意 app 私有访问；后续按职责迁出。

## 跨页面业务逻辑

features/<功能> 根目录只保留薄 index.ts 和 README，按需建 models/services/types/utils。models 放业务状态、用例和编排；services 放请求适配和解码；types 放类型；utils 放纯规则。types/utils 不依 models/services，services 不依 models，models 可依 services/types/utils。跨 feature 只引用对方 index.ts 核心公开入口，不读取内部路径；类型导入同样执行入口与循环检查。

features 不放 components 或 TSX，不引用 pages、公共展示或 app，核心入口不重导出 UI。页面私有逻辑优先留页面，实际跨页面复用的业务合同才提升；无界面消费者不因此加载 TSX。

## 公共组件与请求

components/<PascalCase组件>/index.tsx 只承载实际跨页面通用展示。官方、组合和第三方封装使用相同结构，私有文件留组件内；外部可用具体组件入口或 components/index.ts，组件内部不导入汇总，也不读其他组件私有文件。

公共组件只依公共组件和顶层 utils 纯工具，不能读取 pages/features/app/业务 API/SDK。公共请求在 services/api 集中错误、取消、生成类型和日志语义；页面和 feature 请求适配经公共客户端，不直接新建网络调用。现有共享基础设施按原边界保留。

## 可执行检查

AST 门禁覆盖值与类型导入、动态导入、重导出和别名解析；执行页面入口、组件入口、feature README、源码位置、全工程循环及网络检查，strict 由 TypeScript 完整检查。真实临时夹具验证页面组合请求、feature 核心和第三方公共组件，并拒绝私有入口绕过、跨页读取和 feature UI 回流。

不创建空目录或镜像测试。普通异常直接修正结构或门禁，不新增审批；目录整理不替代业务、浏览器、设备或性能验收。
