# 前端目录与组件约束

按用户参考的 React 脚手架结构组织实际代码；上一轮 DDD 与 ui/common/integrations 分类已由本约束覆盖。TypeScript AST 门禁检查值导入、类型导入、重导出和动态导入的真实目标路径，路径别名不能绕过。

## 公共组件与纯工具

公共组件统一使用 `src/components/<PascalCase组件>/index.tsx`。官方基础组件、组合展示和第三方通用封装一视同仁；私有 children/types/styles/hooks 放同一组件目录。外部可导入组件入口或 `components/index.ts` 汇总，组件内部不导入汇总，跨组件不读取私有文件。

公共组件只能引用公共组件和 `src/utils` 纯工具，不能读取 shared/api、features、app、plugins 或 SDK。顶层 utils 仅放纯工具并只依赖 utils，不承接业务状态、任务或网络副作用；例如组件类名组合放 utils/classnames.ts。只在真实需要时建组件或工具目录，不造空目录。

## 功能模块

模块为 `src/features/<功能>`，根目录仅保留薄 index.ts 核心入口和 README；目录按用途建立。

| 目录 | 职责 | 同功能允许依赖 |
| --- | --- | --- |
| models | 用例、状态、订阅、编排 | models、services、types、utils |
| services | 适配器、网关、字节解码 | services、types、utils |
| types | 类型 | types、utils |
| utils | 纯规则、验证、转换 | utils、types |
| components/<PascalCase组件> | 专属展示及其私有文件 | components、models、types、utils、公共组件 |

专属组件使用 index.tsx 入口，展示汇总为功能 components/index.ts；组件不直接引用 services。app 的值和类型导入只使用 features/<功能>/index.ts 或 features/<功能>/components/index.ts，不能读取任意内部组件。核心入口不依赖或重导出 components，保障 Node 原生测试和无界面消费者不加载 TSX。

不同功能不直接互相引用；跨功能协作由 app 注入公开端口。现有共享基础设施和公开 SDK 继续保留原边界，本次不额外扩大业务剥离。测试可以读取内部实现，生产限制不因此放宽。

## 门禁与普通异常

架构检查执行源码位置、组件入口、功能 README、依赖方向、全工程循环、网络与 strict 边界。真实临时目录用例验证第三方同级封装和双入口可用，并拒绝私有入口绕过、核心泄露 UI、组件引用服务及类型/路径别名绕过。

发现普通结构或约束异常直接修正文件职责、导入或门禁并补证据，不增加用户审批。无法完成的外部条件如实报告；目录重排和文档不能代替业务、视觉、真机或性能验收。
