# 设备发现原始状态的前端接入方案

## 门禁、依据与范围

模式为 architecture-first / Hybrid，仅设计。依据后端 [操作绑定第一批契约](../../backend/docs/操作绑定第一批契约.md)、[平台适配器迁出实施](../../backend/docs/平台适配器迁出实施.md) 和本端 [设备第一阶段实施](设备提供者第一阶段实施.md)。本轮只新增本文，未修改源码、生成 DTO 或公开契约，也未运行 npm、Cargo、构建、服务或生成器。

2026-10-09 主代理已报告上一批 operations 失效的 check、88 项测试及 build 通过；这是目录撤销增量的证据，不证明原始设备状态或本批 Rust 行为已验收。本文不依赖当前后端批次测试结束；待冻结选择交由主代理与后端确认，确认和文件解冻后再实施。

目标是在保留现有归一化状态、完整设备引用和能力准入的同时，让下一版本发现结果保留 recovery/sideload/bootloader 等原始观测，并可消费未来未知状态。推荐在版本化的设备观测中增加可选原始信息，保持归一化 state 的既有职责。直接扩张 state 枚举会影响现有解码、SDK、准入和旧插件分支，不能仅为展示文字修改；若特殊模式执行规则需要改变，须另行冻结双方准入语义。

本文中的“原始状态信息”“来源”“观测版本”均为语义描述，字段名称、JSON 结构、版本号、可选/null 规则及限额尚未冻结，不是新增 HTTP/SDK 字段或可直接实现的 DTO。具体产品 UI 等待设计稿，不创建页面或占位界面。

## 当前真实代码与消费缺口

| 单元 | 已有事实 | 对下一批的限制 |
| --- | --- | --- |
| backend domain/devices/mod.rs、plugin-sdk/devices.rs | DeviceState 为 online/offline/unauthorized/unknown；发现设备包含身份、state、model 和能力可用性，未承载原始状态 | API 1/2 没有原始观测，浏览器不能从 unknown 推回被丢失的工具状态 |
| backend infrastructure/devices.rs | 旧 ADB 解析接受 device/offline/unauthorized/recovery/sideload/bootloader，其他状态行被过滤；旧 HDC 解析为每个目标合成 device | 保留未知状态须从后端解析与发布开始；合成状态不等于工具原始报告，解析支持也不证明真机能发现每种模式 |
| frontend plugin-sdk/devices.ts | ProvidedDevice.state 同样为四值；DeviceRef 使用 providerId/generation/localId | 不新增平台字符串分支或以展示状态代替设备身份 |
| shared/api/device-validation.ts | 校验 API 1/2、四值 state、目录提供者/代际及精确能力版本 | 未来原始信息应按冻结模式校验；不能放宽所有未知规范字段或接受未支持的声明版本 |
| app/device-gateway.ts | 显式映射 state、reference、model 和 capabilities；没有原始信息适配 | HTTP 自动带上未知字段不等于 SDK 已透传；生成后仍须逐字段映射 |
| features/devices/rules.ts | select 要求当前目录有引用；invoke 的设备范围还要求 state=online 和能力 available | 能展示特殊/未知状态不等于可调用；仅 available=true 也不能绕过当前在线条件 |
| features/devices/index.ts、state.ts、plugins/device-access.ts | 刷新清旧观测，修订/代际防晚到，选择与作用域取消/订阅收敛 | 原始信息应随整份观测撤销、替换，不新建跨代缓存或长期监听源 |

后端第一批契约明确禁止绑定旧发现入口，因为发现副作用与原始状态还需下一批一起版本化。本文不把普通 operation 绑定、直接 Job 输出或浏览器操作目录当作发现已经兼容的证据，也不发布旧枚举入口建议。

## 状态语义与未知观测

归一化 state 服务于通用状态与准入；原始观测服务于说明、诊断和平台插件消费。归一化由后端提供者/宿主按照冻结规则产生，浏览器保留其结果，不自行根据原始文字重新归一化。同一原始词在不同提供者中可能具有不同语义，不能按词或 platform 自动选执行器。

| 原始观测样本 | 下一批应保留的信息 | 当前前端及待冻结问题 |
| --- | --- | --- |
| device、offline、unauthorized | 保留真实来源的状态文字，避免混同归一化与工具原词 | 不在浏览器固化 device→online 映射；HDC 合成值需与真实报告区分 |
| recovery | 恢复环境状态，不能只显示成“普通在线”而丢失模式 | 后端冻结归一化值及该模式能力；当前非 online 设备动作仍拒绝 |
| sideload | 侧载模式状态，不宣称普通安装、应用管理或输入全部可用 | 不按 sideload 文字放行安装；需要精确能力及统一准入契约 |
| bootloader | 引导加载模式及有效观测来源 | 明确实际发现工具和引用稳定性，不能以旧 ADB 解析接受该词证明完整发现实现 |
| 将来未识别但有效的状态文字 | 在同一设备观测中原样保留，提供通用未知提示 | 不丢设备、不替换成正常状态，也不从未知词推导能力或错误码 |
| 未提供原始信息 | 明确表示来源未提供或旧版本没有该信息 | 不能将归一化 unknown 当作原始文字，更不能从上一份目录补出原值 |

推荐把未知状态作为正常观测的一种，而不是协议错误：前提是其原始信息满足冻结的文字/结构限制、规范 state 与引用等仍合法。未识别文字和非法载荷必须区分；错误类型、过量数据或控制字符的处理由契约规定，不能用类型断言吞掉异常。

未来展示建议为“归一化状态 + 原始说明”，原始信息缺失时明确提示未提供；未知文字保留原值、展示用通用提示及受控文本输出，不能作为 HTML、脚本或命令。展示可缩略，但给插件消费的数据在约定限额内保留原始语义，不在前端静默改大小写、trim、拼接为能力名，亦不透传整个工具输出或本机路径。字段限额及允许字符须由后端冻结，本文不指定数值。

对 recovery/sideload/bootloader 的归一化映射，推荐先保持保守准入，直到后端明确哪些能力在该模式允许执行。若未来需要非 online 模式动作，需同时调整宿主与前端能力准入并版本化；原始信息只能解释观测，不能成为浏览器覆盖 state/available 的参数。provider 范围能力、设备范围能力和动作总预算保持各自既有职责。

## 版本兼容与 SDK 扩展建议

HTTP /api/v2 响应版本、设备提供者声明 apiVersion、浏览器 HostContext.apiVersion、能力 version 和包 version 互相独立。原始观测建议通过明确的设备声明/发现版本加法交付；具体版本号、采用现版本加法还是新声明版本由主代理冻结，本轮不称其为已支持版本，也不新增端点。

| 组合 | 设计要求与现状限制 |
| --- | --- |
| 现有 API 1/2 提供者 + 下一批宿主/前端 | 保留旧目录和动作行为；原始信息缺失可正常消费，不能凭空补值；API 1/2 能力预算原兼容规则不变 |
| 扩展声明提供者 + 下一批宿主/前端 | 仅在冻结版本和载荷规则后接受，统一生成 HTTP 类型并显式 SDK 映射；若新版本延续预算，须明确继承 API 2 的预算语义 |
| 下一批前端 + 旧服务器 | 消费现有四值状态，无原始信息时降级说明；不猜字段、不把私有 Job 输出作为原始信息替代入口 |
| 当前前端 + 未来声明版本 | 当前 validator 只接受 API 1/2，可能拒绝整个提供者/目录响应，不能宣称自动前向兼容或已能局部忽略新提供者 |
| 当前前端 + 未来可选观测加法 | 当前校验不意味着保留未知附加字段，网关仍只映射现有字段；必须独立验证其是否可安全降级，不能称为 SDK 已透传 |
| 旧服务器 + 扩展声明/消息 | 当前 Rust DTO 对未知字段采用严格结构，旧宿主未必接受；部署与插件版本要求须显式记录，不靠字段可选宣称前向兼容 |

优先建议保持浏览器 SDK v2 及现有 DeviceAccess 方法，在 ProvidedDevice 的公开观测模型中添加经过冻结的可选只读信息；这里不命名新增属性或类型。既有 reference/state/model/capabilities 的含义不改变，动作请求不携带原始状态覆盖参数。若改动会改变 state 枚举或动作准入，则须单独评审 SDK 兼容，不能沿可选元数据加法直接放行。

HTTP 类型仍由主代理生成，shared/api 校验 unknown，app 映射独立 camelCase SDK，插件仅从 snapshot、订阅和 refresh 结果消费。缺省、null、空文字与真实 unknown 字样是否等价须先冻结；建议未提供时保持可选信息省略，不赋 undefined 或用归一化文字造原值。现有引用优先承担提供者来源，是否另需区分真实工具报告和适配器合成观测也待冻结，不重复设计身份 DTO。

## 目录失效、状态变化与热装卸

原始观测随同一 DeviceDirectory 的 providerId/generation/localId、observedAt 和目录修订一起发布，不能以 localId 单独缓存。刷新清旧目录时同步撤销原始信息；刷新失败或取消保持既有空观测，不能拿历史原始文字补当前状态。新成功观测缺少可选信息时也要替换旧值，不能残留上一版本的数据。

同一引用的新观测只改变状态文字时，selected 应读取最新目录设备；不会仅因原词变化制造新设备引用。若归一化状态或能力可用性变得不再满足准入，现有 validateAction 会取消受影响的动作等待。原始说明单独变化是否需要额外取消，建议不扩规则；如其意味着模式变化影响执行，后端须把这一语义正式反映到准入契约，而不是只给展示信息让浏览器猜。

提供者消失、卸载、代变与本实例管理撤销必须清除原始信息、目录、选择及相关等待；新代即使同名 localId 也不继承旧原值。替代发现、旧聚合目录和旧代晚到不能回写任何新增观测信息。退出面板/组件/模块仅释放挂载子作用域，卸载浏览器插件释放实例请求与订阅；不为原始状态另开脱离插件生命周期的监听源。

本实例管理继续使用已冻结的操作目录失效与设备撤销/重查装配；下一批不借机修改通用资源状态。其他同事实例或远端变更仍显式刷新，没有后台推送或常驻热拔插承诺。GET 聚合目录读取已有观测，refreshProvider 才触发发现；未来旧发现入口如何在同一任务内发布目录、返回兼容原始状态和处理失败由后端一起冻结，前端不嵌套提交第二个 Job 补发现。

## 最小验证矩阵（待契约冻结后执行）

| 场景 | 前端最小验证目标 | 独立后端/集成证据 |
| --- | --- | --- |
| API 1/2 原目录，无原始信息 | 原模型正常映射/选择/调用，可选信息按冻结缺省规则处理；预算兼容不回归 | 旧提供者清单与消息实际可加载，未提供的信息不被宿主伪造 |
| recovery/sideload/bootloader 各一个观测 | 原始语义进入刷新结果、snapshot 和订阅；归一化 state 仍取服务结果，不混用 | 真实发现适配输出及宿主目录发布，不只伪造浏览器响应 |
| 未识别但有效文字 | 保留未知原值和完整引用，通用提示不替换其语义，不能由文字放行动作 | 后端解析不静默丢行，按冻结规则归一化并保留信息 |
| 合成值、缺省、null、空值 | 按冻结规则区分，不从旧目录、normalized state 或 model 反推原值 | 原始与派生来源、缺省/null 的序列化行为一致 |
| 非法类型、控制字符、超限或未知规范枚举 | 受控响应错误并保留可用的真实 logId；不截断后假装数据合法 | 约定限制及错误路径有稳定证据，不要求浏览器自行清洗全部工具输出 |
| 新/旧宿主、声明、客户端组合 | 只接受支持的冻结版本；不支持时受控失败，元数据缺失安全降级 | 精确记录各声明/模式版本，不能用包 version 或 HTTP v2 代替 |
| 同名设备、同引用状态更新 | 不同 provider 的同名 localId 不混用原值；当前选择读取新观测，新结果缺省时不残留旧值 | 模式切换后的身份与归一化规则按冻结契约验证 |
| 刷新在途/失败/取消及替代响应 | 原始信息随旧目录清空；自己成功可发布，旧结果不能复活，新代不继承旧原值 | 发现失败清目录及成功发布共享原有代际门禁 |
| 状态准入与动作在途 | 当前非 online 仍拒绝；若获准改变规则，前后端拒绝/允许矩阵一致；raw 说明变化不自行授权 | 特殊模式精确能力、权限状态及取消行为由宿主验证 |
| 提供者热卸载与本地管理重查失败 | 提供者/目录/选择/原值及关联等待撤销；新成功刷新恢复，没有后台推送假设 | 装卸后当前目录与代际真实一致，清理未确认仍保留状态 |
| 面板退出、浏览器实例卸载 | 释放订阅、取消设备请求，晚到原始状态不能恢复旧挂载或旧上下文 | 生产公开 SDK 行为可独立验证；不证明后台连接或设备事务退出 |
| 后续旧发现兼容 | 第一批禁止绑定发现的行为不回退；下一批只按冻结入口消费单次发现/目录结果 | 同任务发现副作用、目录发布与旧结果无损兼容，不能靠前端二次提交补齐 |

矩阵是最低设计验收条件，没有创建测试文件或执行命令。特殊模式文字展示的产品视觉、真实工具版本、Android/Harmony 真机、常驻连接、远端推送和下一批 release/npx 必须另记录，上一批 88 项测试和分发报告不覆盖这里的新语义。

## 提请主代理冻结的未决选择

1. 原始观测的准确载荷、字段位置/名称、设备声明或发现版本，以及现 API 1/2 对附加载荷是否允许；不预定新版本号。
2. 未提供、null、空文字与字面 unknown 的含义及 SDK 可选信息省略规则；是否只需单个状态文字，还是确有来源/派生说明需求。
3. 真实工具报告与适配器合成值如何区分，未知原值的长度、字符/结构限额及失败映射；完整工具输出不作为原始状态接口。
4. recovery/sideload/bootloader 的归一化值、跨模式设备身份及能力准入矩阵；是否需改变当前“非 online 拒绝设备动作”的双方规则。
5. 旧发现的同任务副作用、目录发布、旧 Device 结果恢复及失败/取消语义；第一批禁止发现绑定的边界保持到新契约正式落地。
6. 不支持声明版本或非法观测是整份响应受控失败还是允许局部隔离；当前 validator 的整体拒绝行为不能被无依据地写成自动隔离。
