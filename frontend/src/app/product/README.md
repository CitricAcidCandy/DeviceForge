# 产品页面装配

本目录负责产品启动编排与显式旧页面兼容，不再由根工厂装配全部业务。正常入口使用 `platform-services.ts` 创建唯一纯平台运行实例，组合根消费独立官方插件登记的页面、工作区、导航和外壳；网络及任务仍复用公开平台适配。

`services.ts`、`legacy-services.ts` 和 `legacy-business.ts` 只供旧调用或设备画面桥显式使用，按需创建旧业务并归属自己的作用域；释放适配不关闭平台，平台关闭会兜底释放。不得展开带访问器的对象来组装服务，避免把按需业务变为提前创建。

`route-address.ts` 提供不依赖业务清单的地址解析，`route-catalog.ts` 消费公开动态目录。`routes.ts` 和 `legacy-route-definitions.ts` 保留旧 UI 图标、默认回落及十一项槽位兼容合同，不作为新增业务入口。完整状态见[开放插件工作区实施](../../../docs/implementation/开放插件工作区实施.md)。

错误反馈由 `error-feedback.ts` 统一分类和保留任务、提交及查询日志归属，直接展示已确认的具体原因；`error-reasons.ts` 兼容旧服务内部术语。不能用“失败”“409”或日志编号替代原因，不能将未知错误猜成部署配置问题。页面升级、真实资源占用、应用未安装、设备离线、未授权、取消等待和任务最终失败分别说明；刷新按钮只由用户主动点击，不重放动作。技术原文和错误码留在诊断详情，旧日志不改写。

components/ui 中的官方组件于2026-10-14获得用户逐项批准。插件渲染根与 React 工作区独立，公开主题变量作用于文档根，覆盖官方弹层；业务选择和任务不归主题所有。页面状态以服务器实际目录、能力和任务为准，不用演示设备或固定进度冒充真实功能。

## 历史页面布局兼容

用户于2026-10-14授权采用常规中后台工作台。navigation 只负责四组路由展示与导航回调；shell 负责服务器状态、设备上下文及折叠/抽屉/专注的展示状态。App 保留已访问页面节点，切页与专注不清空草稿或重建业务 runtime。现有背景作为环境层，主题贡献和插件挂载根继续独立。布局合同、响应式与验收要求见 [中后台工作台布局](../../../docs/中后台工作台布局.md)。
