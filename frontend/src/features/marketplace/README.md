# 市场目录

市场功能读取独立资源服务的 `market.json` 目录，负责筛选、模糊搜索、上传发布和当前浏览器的地址覆盖。市场页的“上传发布”默认接收包含 `release.json`、组件和工具的完整功能 ZIP；也可以切换为“独立组件或其他资源”，沿用“选择资源—填写描述—确认发布”三步流程。完整发布先检查本地资源，再确认服务器能力、复用资源、上传缺失资源与在线清单，最后提交一个市场条目。运行时 `manifest.json` 仍由现有插件安装器管理，市场展示字段不会混入执行协议。

## 页面与目录职责

`services/catalog.ts` 解码目录并标记不完整元数据，`utils/metadata.ts` 校验发布字段，`services/download.ts` 流式计算 SHA-256，`services/publication.ts` 校验完整发布能力和资源复用的响应。`services/transport.ts` 统一网络等待、取消、结构化错误及日志 ID；不编排发布、不重放请求，也不把取消等待解释为服务器回滚。完整 ZIP 检查、资源计划与发布编排、卡片、筛选、详情、配置和上传表单位于 `pages/marketplace`；公共 Dialog、Stepper、文件选择和表单组件不依赖市场业务。

目录默认隐藏内部资源。发现页支持类型、分类、适用项目及高级兼容性筛选；已安装页从真实服务器包和浏览器包目录读取，并独立获取市场描述。市场描述缺失或不完整时，服务器插件回退到宿主返回的本地 `metadata`，显示插件自行声明的名称、简介和完整描述；只在 ID 和已安装版本一致时复用本地描述，插件 ID 保留为辅助标识。旧宿主未提供展示声明时继续使用 ID 和缺失说明。当前实现连接一个有效市场地址，浏览器覆盖独立保存在当前站点的本地存储中；没有完成多个外部市场的聚合去重。

## 插件安装、更新与配置

完整功能条目通过 `details.release_format_version: 1` 与 `details.host_api_version: 2` 标记，以 `resource_id` 引用锁定的在线发布清单，交给统一安装服务准备组件与依赖。独立组件自动安装仍要求完整元数据、有效资源摘要及 `details.plugin_kind`，后者必须明确为 `server` 或 `browser`，不能按主题或界面分类推断。安装前先展示来源、摘要、平台、权限和重启要求；缺失市场描述的本地插件仍可显示和卸载。

更新仅对更高语义版本开放。公开 PUT 更新接口暂存并验证新包后替换，失败保留旧目录，不使用先卸载再安装。更新后按运行状态与界面提示到插件页启用，不自动恢复旧实例。

已安装插件的配置入口按 `details.plugin_kind` 确定服务器或浏览器目标，不依赖远端市场描述。服务器配置通过 `/api/v2/plugin-configurations/server/{id}` 读取插件清单中的 Schema 与当前值，并使用修订号保存、恢复默认或应用；浏览器配置使用独立插件配置存储。无配置字段的插件明确提示无需配置。旧服务器返回路由不存在时提示升级服务器，并保留真实错误和可复制日志 ID，不能把接口缺失解释为无需配置。

工具、配置和分发条目目前提供详情及校验后下载，尚未实现通用工具安装器、任意配置自动应用或这些类型的已安装清单。

## 下载、上传与取消

条目下载固定使用其来源地址；一次上传与发布也固定使用开始时的地址，避免中途切换市场导致跨来源交付。旧独立资源入口及下载暂存上限为 256 MiB；完整功能 ZIP 入口允许 4 GiB 以内的归档，以切片及流式校验建立资源计划，不将整包读入 JavaScript 数组。单资源仍受清单 2 GiB 上限和市场能力声明的更低限额约束，超限或摘要不匹配明确失败；资源服务器下载支持 Range。

中文文件名以 `encodeURIComponent` 编码发送，并携带 `x-resource-filename-encoding: percent`。响应存在该标记才解码，兼容旧 ASCII 文件名与字面百分号。关闭上传对话框或离开市场会撤销等待并忽略晚到结果；已经到达服务器的上传不保证回滚。

完整发布在任何资源写入之前调用 `releaseCapabilities(signal, source?)`，请求 `/api/v1/capabilities`。服务必须声明 API 版本 1、格式版本 1、宿主 API 版本 2、正整数单资源上限，并保证目录最后提交及同版本不可覆盖；旧端点或不满足能力时明确提示升级市场服务器。`probeResource(digest, size, signal, source?)` 只发送 HEAD；只有 404 表示缺少资源，200 必须同时具备与摘要一致的强 ETag 和精确 Content-Length。其他 HTTP 失败、缺头和错配均停止发布。错误保留可用的服务器日志 ID；取消不等待忽略信号的传输，也不承诺远端写入回滚。
