# 功能插件安装

功能插件是用户安装和管理的单位，一个功能可包含服务器及浏览器组件。领域模型使用独立 camelCase 字段，HTTP 服务只能从生成契约映射，不能维护并行 DTO。

安装与更新先取得服务器计划，再提交安装 Job。新安装成功后重新读取目录，缺少业务配置时保留“已安装、需要配置”，不当作安装失败；用户完成配置后的显式启用仍提交服务器启用 Job 重新评估。仅服务器确认可启用时才启动浏览器组件。浏览器启用失败保留独立客户端状态、日志与错误，收回本次已启动的其他浏览器组件。

更新只等待旧浏览器组件清理，由宿主更新任务保留服务器原启停意图，不额外 PATCH 停用或自动启用。更新返回后，仅原来启用且实际仍处于已启用状态的发布才激活浏览器；停用发布更新后继续停用。卸载仍先清理浏览器并等待服务器停用 Job，失败不继续删除。

等待取消不自动撤销服务器任务，也不自动重放请求；失败后以独立生命周期重新读取实际目录。无令牌参数的服务器选择继承 runtime 原有 ApiClient。不可变修订属于浏览器资源地址和请求头，不混入业务 input schema。

`restore` 只恢复目录中已有启用意图且可运行的浏览器组件，不修改服务器启用意图。`recovery_blocked` 的纯组件历史告警由公开 `isLegacyCleanupWarning` 判定，页面展示“上次组件操作告警，可重试”，不宣称清理已完成，不阻断显式新操作或已有启用意图的浏览器恢复。允许阶段为 `component_cleanup`、`activation_cleanup`、`enable_cleanup`、`activation_reload`、`startup_activation`、`unload_rollback`、`configuration_rollback`、`disable_rollback`；`activation_rollback`、`commit_rollback`、`transaction_*` 等文件事务故障、未知或缺失原因仍不能启用、更新或恢复，原状态与原因不改写。未知状态在 HTTP 边界拒绝。浏览器失败后 `retryBrowser` 只重试当前客户端，不重复安装或服务器启用任务。目录快照与客户端运行快照分别订阅，快照引用在通知之间保持稳定。启动默认恢复先读取统一安装目录，旧包默认流程排除已归属组件，目录不可读时不会绕过安装意图启动底层包。

安装等待按事件序号增量读取阶段、资源和字节进度，进度独立订阅并保留任务及日志标识；取消等待后忽略晚到事件。资源总量可以未知，非法阶段或字节在 API 边界拒绝。进度读取失败只结束本地等待，随后重读目录，不重放服务器安装。

`cleanup(dryRun, signal)` 使用公开托管资源清理任务。界面先提交检查并展示服务器报告，再允许用户显式提交清理；清理任务执行时服务器重新核对引用。它不负责解除 `recovery_blocked`，恢复仍应依据服务器恢复日志处理。

市场按功能外显名称、描述和真实组件列表展示。配置选择使用组件的 `kind/id`；统一卸载后刷新底层包和运行目录，避免已移除组件从旧缓存重新出现。发布修订只放在请求头：产品任务、会话创建及设备写请求按已安装目录匹配；浏览器插件 HostContext 捕获加载时修订，旧代码不能冒用更新后的身份。

测试覆盖安装后按需启用、配置阻断、恢复受阻、未知状态拒绝、部分浏览器启动失败清理、旧修订拒绝、卸载顺序、进度边界、取消晚到结果、HTTP 适配、本地导入、配置和市场交互。JSDOM 与模拟传输的结果不等于真实浏览器执行、视觉、设备或分发验收。
