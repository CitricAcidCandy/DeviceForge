# 插件配置

浏览器配置通过公开 GET/PATCH `/api/v2/browser-plugin-configurations/{id}` 写入当前服务器的用户目录，插件标识在该宿主目录内隔离。页面不能推断浏览器所在电脑的存储路径；实际根目录由后端启动装配解析，默认 `<home>/.deviceforge`，显式隔离使用 `DEVICEFORGE_USER_DIR`。浏览器记录位于 `plugin-configurations/browser/<id>/state.json`，不跟随初始包或在线部署目录。

服务端记录始终优先；仅在无记录时首次读取旧 localStorage，完整迁移版本、值、修订、已应用修订和历史敏感路径，并保留旧字节。没有旧记录时也首次保存当前声明的默认值，使用 `defaults` 修订，防止包升级改变已使用的默认配置。首次创建统一以 `expected_revision: null` 比较后写入；409 只重读胜方，不自动重放。API 失败不能降级为浏览器本地保存。

插件通过公开 `HostContext.configuration` 同步读取自身配置并订阅更新；宿主激活前异步准备远端记录并校验声明版本及 JSON Schema。需要重载的保存不会提前改变运行中插件的值。无配置声明的插件不访问配置 API，保留离线宿主场景。相关流程及集成验证入口见 [浏览器插件用户配置](../../../docs/implementation/浏览器插件用户配置.md)。

服务器适配只消费公开 API 生成类型；页面视图使用 camelCase 字段。公共 SchemaForm 与配置对话框不读取该 feature，由页面注入配置回调。

旧宿主返回 `404/not_found/接口不存在` 时，服务器适配器增加升级提示，同时保留 HTTP 状态、错误码、原始错误及日志 ID。插件尚未部署等其他 404 保持原语义。公共对话框展示并支持复制真实日志 ID，失败后可重新读取；成功返回空声明才显示无需配置。

敏感字段与只读约束沿本地 `$ref`、组合 schema、数组及字典解析。读取时同时遮蔽值、schema 默认值和根对象默认值；服务端记录保留敏感字段的 JSON Pointer 集合，升级删除注解后仍遮蔽已有值，保存原占位继续保留原值。历史路径不保存敏感值副本。

浏览器插件配置重载固定用户选中的修订，等待原代清理成功，再激活新代；失败清理在当前运行实例中阻止再次启用、重载与删除，避免重复操作绕过资源收敛。新代激活成功后重读并核对准备时的修订，再以 CAS 确认已应用；确认失败回滚新代，成功后恢复仍有效的原主题选择。取消和销毁会结束宿主等待，晚到结果不得覆盖运行值或恢复订阅；已经被服务器接纳的写入仍以重新读取结果为准。
