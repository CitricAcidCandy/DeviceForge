# 本机浏览器调试桥

该功能负责浏览器实例登记、按明确会话消费命令、目录变化和结果回执。DOM 动作、断言与业务投影检查由注入的本地执行端口完成。网络边界消费 Rust 契约生成的类型，复用宿主公共通信与 API 客户端，不另外启动端口或进程。

完整分层、任务订阅、MCP 示例及验证范围见[实时通信与调试确认](../../../docs/implementation/实时通信与调试确认.md)。

## WebSocket 首选与 HTTP 兼容

- `start()` 由产品装配显式调用，独立工厂创建时没有调试网络副作用。
- 注入宿主实时客户端后，先查询 `/api/v2/realtime/capabilities`。当前支持协议使用 `/api/v2/realtime/socket.io` 下的 `/debugger` 命名空间，与 `/tasks` 共用宿主 Manager 和底层 WebSocket。
- 能力接口明确返回 `404/405/501` 时，继续使用原 HTTP 桥；未注入实时客户端的旧装配也沿用原实现。
- 网络错误、协议不匹配和加载失败仅报告调试不可用，不建立竞争的 HTTP 桥。已经选择 WebSocket 后，临时断线走有界恢复。
- 正常实时连接不发周期性 HTTP 调试心跳。目录在登记或变化时上报，无活动会话不扫描 UI。旧 HTTP 兼容路径仍有原轻量心跳和命令领取。

入口分别为 `models/bridge.ts` 的协议选择、`models/socket-bridge.ts` 的实时适配，以及 `models/http-bridge.ts` 的旧协议兼容。它们复用同一业务执行端口，不复制本地调试状态机。

## 恢复与释放

每个调试实例最多有 4 项在途命令或待补交回执；执行使用服务器返回的剩余预算，普通命令最多 10 秒，重载和自动化最多使用原 30 秒预算。本页最多保留 4096 项已见命令记录，达到上限时报告受控结果。

同页面重连保留实例恢复信息及原命令编号。已交付动作不重新执行，结果核对或补交使用原命令编号和期限，旧连接的晚到回调不能覆盖新代。实例过期或宿主重启需要新身份，页面刷新也建立新实例；旧实例的在途动作不能迁移后重放。

回执超时只能说明结果未知，按原命令编号查询。恢复等待、控制请求及关闭收尾都有期限。`dispose()` 撤销本桥订阅、延迟与等待，释放调试命名空间租约；任务消费者仍在时宿主公共连接继续存在。取消等待不能证明可信回调的实际副作用停止。

调试业务插件与任务业务插件分别消费宿主能力，互不作为启用前提。调试面板启停也不改变宿主 MCP 桥的独立生命周期。任务插件通过公开 `taskHistory.subscribeChanges?` 取得 `ready/changed/unavailable` 提示，按“先订阅、再读快照、恢复补查、不可用时降级”处理；不会取得本调试桥或 Socket。

## 动作检查点

`deviceforge.debug_ui_action` 顶层使用 `session_id` 与 `parameters`。下面是 `parameters` 的界面检查示例，会话、根和完整节点引用均需来自本次查询：

```json
{
  "root_id": "当前挂载根标识",
  "action": {
    "type": "fill",
    "target": { "id": "当前节点标识", "generation": 1, "revision": 1 },
    "value": "示例名称",
    "confirmed": true
  },
  "expect": {
    "kind": "ui",
    "assertion": {
      "condition": "value_equals",
      "query": { "role": "textbox", "name": "名称" },
      "expected": "示例名称"
    },
    "timeout_ms": 3000
  }
}
```

`expect` 与 `action` 同级，默认最多等待 3 秒、允许 0～10000 毫秒，继续消耗原调用预算。等待只读状态，不再次派发动作。参数在派发前校验；原确认、未知副作用授权及产品保护继续生效。

业务检查改用 `expect: { "kind": "data", "source_id": "已登记状态源", "checks": [{ "pointer": "/running", "equals": true }] }`。字段必须实际存在于当前目标的公开投影，不能用示例字段推断已有投屏回读能力。完整示例及 JSON Pointer 约束见实施文档。

回执保留原动作状态和 `businessOutcome: "unknown"`，可附 `verification` 的 `status/scope/reason`。`control`、`ui`、`business` 分别说明控件、界面和明确业务字段的检查范围；`dispatched` 只说明事件派发。敏感控件不回读或回显原值，缺少状态源时明确结果未知。

自动化复用 `debug_automation_run`，最多 32 步并在首步前检查整计划。固定节点与步骤绑定互斥；每个检查点关联自己的动作，独立成功断言不能替其他动作作证。不可确认时停止无效扩查，不自动追加日志、视觉、设备探测或重复点击。

## 本次验证边界

前端动作、自动化、检查点及相关严格类型检查共 25 项定向测试已通过。任务订阅作用域漏接修复另有 9 项定向测试及必要严格类型检查通过，保留宿主的可选推送能力；本次没有重复运行此前四个调试测试文件。两批证据和具体范围分别记录在实施文档中。

Socket bridge、共享通信客户端与服务端测试由主代理最终汇总；本子任务未做真实 WebSocket、浏览器、设备、完整构建、全量回归或压测，未部署或重启用户服务。上述契约不能替代这些运行证据或具体性能测量。
