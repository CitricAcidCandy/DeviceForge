# 已安装插件的默认启用

本功能在产品启动时显式调用一次 `start(signal)`，为当前已安装服务器包和浏览器包执行默认启用。构造工厂不发送网络请求，不设轮询或定时恢复；用户当前实例停用插件后，重复 `start` 不会重新启用。新上传包仍由插件页显式启用，用户可以显式“重新执行默认启用”开启新一轮。

## 职责与依赖

| 单元                                     | 输入、输出与职责                                                | 不负责                                         | 副作用                 |
| ---------------------------------------- | --------------------------------------------------------------- | ---------------------------------------------- | ---------------------- |
| `types/index.ts`                         | 从现有功能公开入口派生注入端口；定义本功能状态与结果            | 复制服务器 DTO、应用装配                       | 无                     |
| `models/plugin-defaults.ts`              | 一次性串行启用、当前状态核对、逐项失败与日志 ID、重试和取消撤销 | 启动服务、安装包、设备发现、选择主题、挂载组件 | 调用注入的公开功能端口 |
| `pages/plugins/index.tsx`                | 展示默认启用结果与显式重试入口                                  | 维护启动策略或调用私有实现                     | 页面交互               |
| `app/product/services.ts` 与产品启动入口 | 注入运行实例、显式启动、优先释放本工厂                          | 本功能生产代码不反向依赖 app                   | 装配与生命周期         |

`createPluginDefaults({packages,serverPlugins,browserPlugins,signal?})` 返回 `start`、`retryFailures`、`restart`、`snapshot`、`subscribe`、`dispose`。状态含 `round`、`phase` 和逐项 `results`；结果含插件种类、ID、`enabled/already_enabled/failed`、失败文本和 `logId`。目录读取失败使用空 ID，明确为目录失败，不假装某个包启用失败。

## 启用规则

服务器端先查询公开运行目录，已启用且无清理失败者记录 `already_enabled`，包括由 CLI/宿主启动装配的运行插件。运行目录中的 `cleanup_failed` 或 `draining` 记录为失败并附目录日志 ID，即使该插件不在在线安装包目录中也不能漏报。候选未运行包仅来自公开安装包目录，不猜测服务器文件路径。每次启用前重查运行状态，当前已加载则跳过；排空或清理失败记录失败，不重载旧代。浏览器包使用既有 `pluginPackages.enable` 动态装载，已运行包不重复激活。

两类包串行消费，单包失败继续其余包；目录失败继续另一种目录。`retryFailures` 只重试失败包，失败目录可重新读取该目录；不会把曾成功后被用户停用的包当成失败自动启用。`restart` 是用户主动重新对全部当前已安装候选执行策略，同一运行期间重复入口共用一份 Promise。头部“重新连接服务器”在服务刷新成功后只重试当前失败项；清理未确认或排空的服务器代次仍由既有保护拒绝，不自动重载。

调用方取消、实例关闭及销毁均结束本地等待，忽略信号的晚到结果不能发布到本工厂状态。取消等待不表示服务端加载、可信 JavaScript 副作用或资源清理回滚；真实状态仍由既有管理用例重查。默认启用不选择任何插件主题，不挂载组件/模块，不进行设备发现，不执行插件业务任务。

## 验证范围

定点测试验证构造零请求、同轮重复调用、已运行代次保护、两类启用、单包失败隔离、失败日志与限定重试、当前实例停用后不恢复、取消/关闭及晚到保护。真实动态模块、当前 Rust 服务、产品浏览器和完整前端门禁由集成负责人分别记录；定点测试不替代这些证据。
