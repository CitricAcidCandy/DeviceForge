# 投屏页面

`index.tsx` 编排截图、WebRTC/兼容投屏、分享和录制。私有控制逻辑只在本页消费，不进入公共组件或插件 SDK。

| 文件 | 职责 |
| --- | --- |
| `MediaOwnershipControls/index.tsx` | 控制申请、当前控制者批准或拒绝、服务器认定的主控抢回及主动释放 |
| `media-controls.ts` | 顺序输入队列与有界合并；控制修订变化清理待发输入 |
| `media-keyboard.ts`、`use-media-keyboard.ts` | 画面内键盘焦点、组合键、失焦与换代清理 |
| `media-clipboard.ts`、`use-media-clipboard.ts` | 校验当前控制修订、写入本机剪贴板及浏览器权限降级；兼容旧请求回传 |
| `media-share.ts` | 分享链接的设备与可控制标记解析、只读链接继续分享时禁止升级 |

WebRTC 画面与控制权分别维护。收到所有权前和失权后禁止触摸、键盘与粘贴，视频继续观看；具有控制权限的分享接收者可以申请接管，主控身份完全由服务端判断。当前独占控制者在设备原生菜单复制时，正文仅进入当前控制者的浏览器并写入本机剪贴板；交接清除旧修订正文、未完成复制与待发输入。自动写入被浏览器拒绝时保留当前本人正文供手动复制。

接管相关按钮在服务端返回匹配 `request_id` 的回执前保持等待，拒绝、5 秒超时和取消只结束本次操作，不停止观看。传输方式变化只改变控制队列的当前发送目标，不触发取消正在打开的分享会话；退出活动页面才执行会话释放。

分享对话框默认只读，勾选控制表示允许申请接管。当前链接仍是可信局域网下的明文功能选择参数，不是服务端签名授权凭据。首期实时画面保持无声。

局域网联调时，开发前端默认直接访问当前页面主机名的 `7031` 后端端口，可用 `VITE_API_BASE_URL` 指定直连地址。不要通过统一开发代理转发设备控制连接，否则服务器只能看见代理 IP，可能将同事误判为主控；主控始终由后端根据可信连接地址确认。
