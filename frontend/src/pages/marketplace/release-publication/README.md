# 完整功能插件发布

本页面私有模块将完整 ZIP 转成在线发布计划，再通过市场功能的公开客户端完成发布。

| 单元 | 职责 |
| --- | --- |
| `manifest-fields.ts`、`manifest.ts` | 校验未知清单、物化默认字段、检查绑定、生成在线资源引用 |
| `dependency-manifest.ts`、`dependency-types.ts` | 从生成清单索引第二版统一依赖类型，校验声明、公开标识和配套闭包 |
| `resource.ts` | 校验 ZIP 本地文件头、有界流式 SHA-256/CRC、准备可上传 Blob |
| `prepare.ts` | 复用离线导入的切片目录读取，验证所有声明资源，建立按摘要去重的固定计划 |
| `publish.ts` | 检查市场能力及资料身份，复用或上传资源，最后提交清单和唯一目录条目 |
| `types.ts`、`index.ts` | 使用生成的清单契约，向上传界面提供稳定入口 |

资源校验在任何远端写入之前完成。原样 ZIP 成员保留文件切片；Deflate 成员通过浏览器原生解压流和 Blob 存储承接，不在 JavaScript 中建立整包或整资源数组。压缩格式不受浏览器支持时明确报错，用户可使用发布器生成的未压缩完整 ZIP。目录、清单、单资源及展开大小均有边界，取消会传播到读取与网络请求。

发布来源在请求开始时固定，后续操作不会跟随用户切换市场。资源和清单由 SHA-256 复用；只有所有资源就绪才提交目录。取消等待或目录响应丢失不表示市场回滚，界面应提示重新查询目录再重试。上传只创建一个完整插件条目，内部组件及工具以内部资源保存。

第二版依赖声明中的市场来源转换为摘要资源引用；ZIP 已含同名 `blobs/<sha256>` 时优先验证内嵌原包，不误判为远端资源。没有内嵌包的摘要及市场地址只在当前固定市场 HEAD 校验，不跨市场抓包；任一远端摘要缺失时在首次写入前失败。官方 HTTPS 来源保留元数据且不从浏览器下载，供后端安装时使用。兼容旧版 `tools` 资源，不把旧清单写入仅支持第二版的市场。
