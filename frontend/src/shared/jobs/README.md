# 业务任务消费接缝

`types.ts` 从生成的 HTTP 任务契约索引所需字段，兼容公开 SDK 的三个任务方法；不依赖任何 feature 或宿主私有实现。`http.ts` 复用现有 endpoint，`runner.ts` 负责一次提交、真实终态等待、恢复查询和显式取消，`values.ts` 负责 JSON 及常用纯校验，`errors.ts` 保留任务、日志与原始失败，`artifacts.ts` 校验真实产物封套及原字节下载。

每个 feature 用本模块的执行器并自行解码业务结果。`JobOutcome` 分别保留提交日志和最后查询日志；`JobWaitFailure` 保留最后已确认任务、`submitLogId`、当次失败的 `logId` 和最后确认响应的 `lastKnownLogId`，调用者可由任务身份恢复查询。HTTP 查询失败使用该失败请求日志，不拿旧查询日志冒充；本地等待取消没有新的服务响应时 `logId:null`，旧关联仍由另外两个字段保存。`cancel` 的响应是当次真实状态，需要终态时继续 `resume`。取消信号和 `dispose` 只结束客户端等待，不宣称服务器回滚或资源释放完成。提交响应丢失时没有可确认的任务 ID，不自动重试提交。

输入保持 JSON 原值；不允许循环、非有限数值和非 JSON 对象。没有 UI、订阅、隐藏重试或共享业务缓存。

协议 2/3/4 插件成功结果无条件为 `{result,artifacts}`，无输出时仍是空产物数组。校验生成契约的元数据、重复身份和文件名；下载核对原字节大小与 SHA-256，不按业务 JSON 拆包或暴露服务器路径。已收到下载响应后，字节处理被取消仍保留下载日志；解码与摘要处理完成后再次检查生命周期，拒绝晚到成功。特定 feature 自行核对约定产物名和业务结果；性能等专用宿主源路径不能替代普通插件封套合同。
