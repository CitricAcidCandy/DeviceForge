# 官方市场插件迁移记录

## 已完成的独立能力

一份 `manifest.json` 注入身份和版本。`@deviceforge/marketplace/model` 提供市场目录、资源上传、摘要验证下载、发布前能力核对、已有资源探测及条目发布；`workbench` 持有完整市场页面与编排。生产源码只依赖公开 SDK、生成 HTTP 契约和公开业务包，不读取宿主源码。

原始市场 HTTP 仍直接访问用户指定的市场服务器，不建立第二调用总线。读取与请求显式接受取消信号，发布不自动重放；未知发布回执提示查询原目录。上传资源回执、返回条目身份显式校验，不再使用断言越过边界。坏存储不删除原值，保存失败不偷偷更新内存地址。

插件发布 `<插件身份>.preferences@1` 地址服务，输入为 `get`、`set` 或 `reset`，输出 `{ url }`。设置插件和市场页面共享同一个模型；地址变化通知页面取消旧来源查询。构造和激活不联网。

## 工作区和真实业务流程

工厂通过功能级依赖等待 `host.browser-plugins@1` 与 `host.ui-directory@1`，齐备后登记 `/marketplace` 页面、工作区和延迟挂载视图。依赖撤销只收回这一工作区，地址服务继续可用。旧 SDK v2 缺少可选工作区或服务组合能力时仅保留地址服务，不伪造可用页面。

已迁入本工程的实际流程：

- 搜索、筛选、分页、发现与已安装列表、条目详情、下载与摘要验证。
- 浏览器包及随附来源启停、包上传更新和移除；完整发布安装、更新、停用、卸载和本客户端激活；服务器目录和管理继续走公开 HTTP。
- 安装进度与浏览器当前状态订阅；目录未知不当空，旧快照晚到不覆盖新读取。等待可取消且有固定期限。
- 浏览器和服务器配置编辑、修订冲突、保存及重载，保留字段错误、脱敏与只读约束；依赖扫描、安装、已有任务查询和结果未知时的回读。
- 文件夹、ZIP/TGZ、完整发布包、工具、业务配置及服务器插件配置的本地导入；预览固定原修订，确认后按该修订执行，不把已停用安装改成启用。
- 旧独立组件发布与完整功能发布、manifest 转换、归档准备、资源复用、发布能力核对及托管资源引用检查和清理。
- 导入后通过可发现的 `host.debugger@1` 定位目标；调用前重读安装修订与组件版本，不启用被测插件、不创建执行会话。
- 通过真实 `host.ui-directory@1` 读取晚注册槽位、开放扩展点和工作区目录，不复制宿主槽位白名单。未知或尚未挂载只提示等待，不判贡献名称非法。

页面隐藏保留筛选、导入文件、发布草稿和配置编辑内容，门户弹窗同时隐藏；正在等待的操作停止等待，不能据此认定后台变更回滚。发布或导入结果未知时先查询，不自动重放。销毁释放视图自有目录订阅、设置模型、任务观察、下载 URL 与期限；不接管其他插件的资源。

原宿主页面与旧装配未由本工程删除；默认来源和公开包别名由主代理统一集成。浏览器实际交互、真实服务器安装及发行产物验收尚未执行，源码迁入和单元通过不能替代这些证据。

## 浏览器管理公开边界

`@deviceforge/marketplace/browser-management` 导出 `host.browser-plugins@1` 服务引用、请求联合及客户端。宿主接线使用现有浏览器管理器、包目录、完整安装控制器及配置控制器，不创建另一套执行器。

- `snapshot` 只读本实例快照；`refresh` 读取浏览器包与完整安装目录。目录分别给出 `known/pending/entries/error/logId`，未知不当空。刷新遇到已有读取时订阅其最终快照，不刷新撤销它。
- `setEnabled` 明确选择 `package` 或 `bundled` 来源。完整安装所属组件必须按安装身份和修订启停，不能单独扫卸。随附来源交回原启停偏好入口，不直接装载一个同名独立包。
- `package` 支持浏览器包 `upload/update/remove`。浏览器更新和移除必须交原包控制器撤销本地来源，不能只替换服务器文件。字节先经公开产物上传，调用中仅携带产物 ID、媒体类型及预览得到的插件 ID／版本；原控制器继续校验服务器包回执。服务器包上传和更新仍直接使用公开 HTTP。
- `configuration` 支持浏览器配置 `get/save/reset/apply`，保存和应用携带原修订；复用原配置校验、脱敏和应用策略。
- `installation` 只代理既有完整安装的 `install/update/enable/disable/remove/retryBrowser`，保留原计划、Job、修订核对及本实例客户端激活。安装上传、服务器目录、工具、依赖和服务器配置仍使用公开 HTTP，不加入万能服务动作。
- `host.browser-plugins.changed` 仅提示目录、客户端进度或运行状态变化，不携带一次调用的长期信号；消费者自行登记事件释放并重读快照。

所有调用复用现有服务期限、取消和日志。错误或结果未知不自动重放，读取或新的显式操作可以继续。注册与激活不联网，只有显式刷新／操作或挂载视图后才开始请求。宿主薄适配由主代理接入原管理对象，本工程不创建第二套管理器或执行器。

宿主集成入口为 `registerBrowserManagementServices({ host, extensions }, { runtime, bundled? })`。`extensions` 使用现有注册层，`runtime` 仅取已有 `webPlugins/pluginPackages/pluginInstallations/pluginConfigurations/bundledPlugins/artifacts`。可选 `bundled` 提供随附目录快照、偏好启停和撤销订阅；缺少入口时随附动作明确不可用，不偷偷改用独立包装载。

目录中的 `runtime.source` 描述本实例实际仍在运行的来源，`installedSource` 描述安装元数据来源，两者可能暂时不同。`packages/installations` 的 `known` 为假时不证明条目不存在，不能据此启用同名随附来源。
