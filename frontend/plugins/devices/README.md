# 设备工作区插件

设备工作区通过公开 SDK 登记 `/devices`、工作区、目录视图和工具扩展点。新插件不导入宿主 `app`、`features` 或 `pages`，不接收私有 `ProductServices`，不依设备平台分支决定功能。

## 组合与目标

- 插件：`deviceforge_devices`；工作区：`deviceforge_devices.workspace`。
- 默认工作台根：`deviceforge_devices.workbench.main`，提供者视图为 `deviceforge_devices.workbench`。原舞台常驻，右栏在画面参数与应用之间切换；最终用户无需拼装工作区。
- 自有设备目录视图：`deviceforge_devices.directory`。创建与激活只读取公开内存快照；刷新与发现由用户明确触发。
- 默认画面实例：`deviceforge_devices.screen.main`；默认应用实例：`deviceforge_devices.apps.main`。
- 目录实例：`deviceforge_devices.directory.main`。由原竖工具显式打开，不常驻占列；连接与能力入口分别打开自身业务表单，不拿目录假冒这些功能。
- 工作区目标为 `{ kind: "device", reference: { providerId, generation, localId } | null }`。三个引用字段必须完整保留；`localId` 不跨提供者或代次唯一。
- 在设备工作区新开且目标为空的视图继承当前设备；显式的非设备目标不覆盖。目标变化通过既有实例代次撤销旧挂载，旧回执不能污染新目标。
- 关闭的视图不会因热重载强行恢复；保留布局的实例重新认领，插件缺失时保留位置。恢复本身不触发设备动作、采集或写入。
- 默认根通过公开 `ui.open/ui.mount` 拥有子实例，父级负责可见性；外壳只管理布局直接节点。旧默认三视图布局精确迁回工作台，其他插件扩展、明确关闭、自选提供者及自定义布局保留。
- 额外工作台使用独立子实例，不争主应用的旧单挂载槽位；这不解除画面过渡提供者目前的单实例资源限制。

## 画面与应用的公开提供者

设备组合层只保存公开视图引用。应用已迁入独立插件，画面仍使用宿主过渡适配；不据此宣称投屏内部已独立迁移：

| 内容 | 提供者插件 | 公开视图 |
| --- | --- | --- |
| 投屏与画面参数 | `deviceforge_device_views` | `deviceforge_device_views.screen` |
| 应用工作台 | `deviceforge_device_apps` | `deviceforge_device_apps.main` |

适配器使用公开 `WorkspaceMount`，从传入实例的 `snapshot().target` 读取完整目标引用，合并 `context.signal` 与 `instance.signal`，依可见性通知暂停自身采集。未选择设备时展示等待，不自行补选或发起业务。

画面适配器可在自身作用域内消费旧业务实现；设备组合插件不能反向导入适配器或私有工厂。应用及画面提供者缺失或停用后，布局保留真实的提供者缺失状态，不恢复隐藏的旧实现。

旧布局中的精确引用 `deviceforge_device_views.apps` 在组合层激活时迁到独立应用提供者，保留实例身份、目标、可见性和布局；不会改写用户选择的其他提供者，也不重新打开已经关闭的默认视图。原 `devices.apps` 追加和替换由主实例的兼容装饰保留；额外独立应用实例不争用这一旧单挂载槽位。

画面组合目标在设备引用之外携带 `presentation: { version: 1, applicationsInstanceId }`，提供者可以消费这份公开领域描述把应用实例接到原右栏；普通设备目标继续兼容。目标同步只更新设备引用，不擦除组合元数据或插件显式自有目标。应用首次打开才挂载，后续切面仅隐藏并保留草稿，提供者停用不回退宿主旧应用。

`deviceforge_devices.workbench.pane` 由设备插件自身发出，数据为 `{ screenInstanceId, pane: "params" | "apps" }`，用于能力抽屉跳回指定画面实例的原页签；其他实例忽略。消费者使用既有公开事件订阅，其他插件不能越过命名空间冒充设备插件发事件。

## 连接与高级能力

- 原“连接与断开设备”表单使用公开提供者声明、操作输入模式及 `HostContext.devices.invoke`，不按平台名称硬编码地址格式。断开须显式确认；打开表单只读取能力目录，不自动连接、发现或选择设备。
- 原“能力与原始结果”抽屉展示完整引用、提供者代次、观测和原始状态，按实际能力版本提供JSON输入、服务器输入模式及原始任务结果。输入必须是有效JSON对象，缺声明、离线、旧引用和操作目录缺失时不提交。
- `actions.ts` 复用公开业务库的Job等待器及宿主查询管线。提交接纳与最终成功分开，单次等待有界；停止等待不调用后台取消、不自动重放写入，已知任务只读查询。未取得可信任务票据时提示核对任务记录，不伪造任务ID。
- 连接任务已完成与目录刷新结果分别报告。任务完成后尝试显式目标的重新发现；目录失败保留独立日志，不把已成功任务改写为失败。结果未知时不自动发现，用户先查询任务，再自行决定是否重新发现。
- 操作模式或完整目标换代撤销旧等待，晚到回执不污染当前界面；历史未知任务不冻结后续显式新动作。显示与尺寸只使用Tailwind，窄抽屉按实际容器重排。

## 扩展方式

设备页面的任务归属由本插件读取公开设备提供者的发现/能力操作，并与精确版本的 `deviceforge_devices.task-operations@1` 贡献汇总。追加数据为 `{ operations: ["my_plugin.inspect"] }`，不按命名空间前缀猜测。应用插件自行贡献包分析操作，画面过渡提供者自行贡献投屏操作；第三方同样登记即可，先加载时等待设备扩展点出现，卸载后撤回。宿主不维护这些业务清单。

目录变化通过可选公开 `ui.updatePage` 原位更新页面 `operations`，保留路由、工作台实例与草稿；只切设备而操作集合不变时不重复发布。旧宿主缺少原位更新能力时只保留激活时快照，不靠撤销重建页面模拟更新，也不能声称后续归属已动态生效。

任何插件可登记公开视图，并在加载时通过公开工作区接口或工具扩展点自动加入设备工作区。不需要修改本插件或宿主槽位清单，也不要求用户点击“添加功能”、编辑布局或选择停靠方式。

需要设备工作区自动显示完整工具视图时，贡献精确版本的 `deviceforge_devices.tools@1`：

```ts
context.extensions?.points?.contribute({
  id: "my_plugin.monitor_tool",
  point: { id: "deviceforge_devices.tools", version: "1" },
  data: {
    title: "性能观察",
    pluginId: "my_plugin",
    viewId: "my_plugin.monitor"
  }
});
```

贡献激活后自动建立所属视图实例，更新不重复创建，撤销只移除自身贡献并保留其他布局。视图出现不代表自动开始设备观察或写入。组合能力开放给插件；插件可用公开接口声明分栏、页签、浮窗或覆盖层，不向普通用户暴露搭建流程。

`deviceforge_devices.target@1` 返回当前目标 JSON，输入为 `{}`。`deviceforge_devices.target.changed` 在完整设备引用变化时发出同形数据；插件使用已有服务目录和事件机制，不创建平行总线。挂载 UI 不授予设备控制能力，执行仍经原公开设备或版本化服务入口。

## 独立工程与验证边界

身份和版本只在 `manifest.json` 维护，入口工厂由装载器传入身份。当前源码开发依赖使用实际本地 SDK 制品，不宣称已发布到 registry。清单指向构建后的 `dist/index.js`，源码登记和单元通过不表示该分发文件已生成。

直接单元覆盖无请求激活、自动工具、目标完整性与换代、旧回执隔离、卸载布局保留、不重放、原工作台挂载、连接确认和能力原始输入输出。JSDOM的原生对话框方法使用夹具，不据此宣称浏览器原生弹层、视觉、真机或投屏内部验收完成。
