# 统一依赖发布校验

## 范围与职责

本轮只处理市场资源服务和发布工具，不修改公开依赖 schema、宿主准备钩子、前端发布引擎或插件内部 Rust。第一版资源闭包及永久版本身份保留；第二版复用相同目录提交路径。

- `dependency_sources.rs` 只验证官方 HTTPS 和本市场摘要 URL，不访问网络、不解析归档。
- `releases.rs` 验证清单与目录身份，并对全部市场组件、旧工具及第二版依赖流式核对真实 SHA-256 和长度；相同摘要及长度复用本次核验。
- `http.rs` 把请求 authority/Host 传给存储边界；`store.rs` 在来源和闭包成功后才记录永久版本身份。没有请求上下文的直接存储调用只使用摘要引用。
- 发布工具先验证离线 `blobs/<sha256>` 与来源摘要一致，再改写为捕获的市场 URL；原离线清单、官方固定元数据与原包字节不改写。

来源地址错误、跨市场主机或端口、缺失资源、真实字节损坏、长度不符及占位元数据均不得创建目录或预占版本身份。HTTP 与 HTTPS 均用于可信局域网市场；经 TLS 反向代理部署时要求保留公开 Host，不把该 Host 校验扩大成多租户或来源审批。

## 安装合同

一次正常安装先发现环境、PATH、服务器用户根和共享工具，仅下载缺失必需项，再绑定配置。依赖面板用于补救与可选补装，不是额外必经步骤。市场服务只存储发布，不执行发现、工具或安装钩子。

没有可信来源的工具保持不可下载；有官方元数据也不表示联网可达、当前机器可运行或用户已授权。固定版本数据文件缺少探测时不靠同名文件伪造版本。官方来源与本地重包各自固定 SHA/大小，不能互相替换。

## 本轮验证边界

Node 发布与原生包回归保留第一版覆盖，增加离线到线上 URL 重写、来源解耦、DLL 入口、厂商版本及接口标识一致性。主 npm 包另以禁用生命周期脚本的真实 dry-run 核对，不携带迁移工具或开发期库存。具体数量由本轮最终执行结果记录，不引用历史批次冒充。

`tests/publication_http.rs` 增加同市场来源、跨主机/端口与离线 URL 拒绝、版本身份未预占、第二版依赖字节/长度损坏等真实路由回归。本代理按所有权约定不运行 Cargo 或 formatter，因此这些新增 Rust 测试尚未执行，也未重建或部署市场程序；主代理串行编译、执行测试后才能计入运行证据。保留并行的 Cargo.lock，不回滚其改动。

尚须主代理验证宿主一次安装、跨插件零下载共享、失败状态与重试、当前页面、双 npm 缓存及真实工具；本地声明、模拟传输、包清单或旧二进制通过不能替代该集成验收。
