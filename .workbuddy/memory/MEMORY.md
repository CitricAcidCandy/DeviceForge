# 项目长期约定

## 前端界面设计方向（2026-10-20，用户明确反馈后确立）

- 用户对界面的判断标准：**克制、沉浸、少字、少卡片**。明确否掉「文字太多 / 卡片密集 / AI 味重」的通用后台稿。
- 因此：优先单一主导区域（如投屏舞台），能力入口用图标轨承载而不是带说明的卡片网格；列表用发丝分隔线，不用底色卡片；副标题、功能说明、字段标签能删则删。
- 插件可改性必须在界面里可见：侧栏「插件模块」注入组、工具轨末端插槽、主题走 CSS 变量、插件页展示贡献与代次。
- 标识类信息（job id、端口、代次、耗时、日志 id）一律等宽字体，作为「仪器感」来源；这是沉浸感的一部分，不属于多余文字。
- **但「仪器感」不能靠缩小字号换**（2026-10-21 用户反馈「字体都太小了，看不清」；2026-10-22 再次反馈「字体有点小，不易于阅读」，因此整体上调一档）。
  - 现行标尺（rem 基准 16px）：辅助 11–12 / 正文 13–14 / 强调 15 / 面板标题 17–18 / 页标题 24。
  - Tailwind 侧必须同一把尺子：`text-xs` = 0.8125rem(13)、`text-sm` = 0.9375rem(15)、`text-base` = 1.0625rem(17)，在 `styles.css` 的 `@theme` 里改，别只改手写 font-size。
  - **禁止 9px、10px**：`0.5625rem` / `0.625rem` 一律按下限抬到 11–12px，等宽字体在这些档位直接糊成一片。

## 设备工作台：画面尺寸与右栏（2026-10-22 用户要求放大画面后确立）

- 画面框尺寸**不写死 px**：`.workbench-stage` 做容器查询容器（`container-type: size`），框高 = `min(100cqh, 100cqw × 高/宽)`，竖屏受高度限、横屏受宽度限，一条公式通吃两种方向。
- 用户可自定义画面大小：拖画面**四角弧线**改 `--frame-zoom`（0.6–3，存档到 localStorage），放大后超出部分由舞台自己滚；双击复位。右下角单个手柄已被否（不直观）。
  - 弧线 = 方盒 + 只给朝外两条边描边 + `border-radius` 给对应角。**必须缩进机身内侧 3px**，贴边会和机身描边重合，等于看不见。
  - 拖动方向按角取号：`outward = signX*dx + signY*dy`，增益 `clamp(画面高*0.62, 240, 560)`。
- 读数、操作胶囊一律**浮在上下两条预留带子里**（`padding: 28px 20px 52px`），不要再让它们做流内元素——那是画面被压小的主因。
- 右栏 `--workbench-rail-width` = 384px（296 × 1.3）。改它要同时改 1240px（344）与 1180px（312）两处断点。
- 设备页 `.workplane` 必须 `overflow: hidden; scrollbar-gutter: auto`：默认的 `stable` 会在右缘常留 15px 空带，用户会直接读成「右边没占够」。
- 右栏两个面（`画面参数` / `应用`）的排版约定：标签页 = 等分两格 + 图标 + 44px 高；参数用 2×2 发丝网格（标签在上）、组标题 13/600、折叠标题 13/500（**不能比组标题更响**）；应用 = 一行一个应用 + 行尾菜单 + 增量加载 + 折叠安装区，**别再把多个操作摊成一行按钮**。
- 堆叠布局（≤1024）下 `.device-toolrail` 不能再 `top: 50%`：会压在右栏参数网格上，改成贴左上角并让读数条右移。

## 设备身份的视觉语言（2026-10-23 统一，跨界面复用）

- **平台徽标**：圆角方块 + 单字母等宽（A=Android 绿 `#0E9F78`/`#E6F7F1`、i=iOS 灰 `#3F4757`/`#EEF1F6`、H=鸿蒙橙 `#C2410C`/`#FDF0E8`、E=模拟器灰 `#8A93A6`/`#F4F5F8`）；离线一律降饱和（如 `#5FA891`/`#F1F7F4`）。尺寸：列表 44、弹窗 32、胶囊 16。
- **状态色**：在线 `#0E9F78`、离线 `#A6AEBE`、待授权 `#F59E0B`。状态只用「色点 + 文字」表达，不做彩色胶囊底。
- **等宽只给标识**：设备 id、provider id、端口、代次。名称用 Noto Sans SC。
- 选择设备页（列表 + 右栏）与顶栏胶囊弹窗共用这套语言：白卡 + `#E6EAF3` 发丝线 + 圆角 12–14 + 主色 `#6C4CF5` 只用于选中态与主按钮。

## 工作流约定：先设计稿，后代码（2026-10-22 用户明确要求）

- 任何界面改版**必须先出设计稿**（Ardot 画布），用户看过之后再动代码。跳过设计直接改代码会被要求回退重做。
- 例外：设备工作台页上的逐项微调（尺寸、字号、某个面板的局部重构）用户是直接下指令的，边改边看即可。
- 设计稿按 1424×805 画整页（侧栏 236 + 顶栏 54 + 内容区 260–1400），复用既有视觉语言：白卡 + 发丝线 `#E6EAF3`、主色 `#6C4CF5`、等宽字体只用于标识类信息。
- 实现阶段仍遵守：布局用 Tailwind 工具类、行内样式只放图表几何、页面必须响应式（`npm run check` 里的 ui-policy 与 check:responsive 门禁）。
- **界面样式只用 Tailwind，禁止写 CSS**（2026-10-23 用户硬性要求，已写进根 `AGENTS.md` 与 `frontend/AGENTS.md`）：
  - 不新增 CSS 文件，也不在现有 CSS 文件里追加规则块；唯一例外是 `app/styles.css` 的 `@theme` / `:root` 设计令牌（属配置，不属样式实现）。
  - 缺语义色就先在 `@theme` 加 `--color-*`，再用 `bg-xxx / text-xxx / border-xxx`；组件变体用 `cva` 或类名映射写在 TSX；条件样式用 `cn()` 合并。
  - 现存 CSS 文件只减不增：改到哪个组件就把它的规则翻成 Tailwind、删掉对应块，并从 `check-ui-policy` 白名单里同步删除该文件。
  - 2026-10-23 因新增 `device-context.css` / `DeviceDirectory/workspace.css` 被点名批评；两处已全部改为 Tailwind 并删除文件。

## 每个页面必须有只属于它的「形态锚点」（2026-10-23 用户否定统一壳之后确立）

- 用户原话：「失去了特色，每个界面长一样……设备和性能界面是做得最好的」。起因是我把 AI 助手/任务与日志/设置三页统一成同一套「白面板 + 标题行 + 发丝线 + 左/右栏」，形态被抹平。
- **设备页为什么好**：不是配色好，是**有独占视野的结构**——深色媒体舞台占满 + 浮层胶囊（工具轨、设备目录浮卡、读数条），内容不排队、不套卡。**性能页为什么好**：图表/多轨/采样帧本身就是形态，密度靠数据而不是靠卡片。
- 因此定规矩：**同一套设计语言（等宽标识、发丝线、`#6C4CF5`、Noto Sans SC）可以在页面间复用的是"材质"，不是"骨架"**。骨架必须按页面职责各自长出来：
  - AI 助手 = 会话纸面 + 右侧「运行旁批」窄栏（工具调用清单 + token 读数）。
  - 任务与日志 = 等宽双栏（次色列表｜白色明细），明细内用**浅色代码块**承载日志与提交内容。
  - 设置 = **参数卡阵列**（label 在上、控件在下）+ 一块浅色 JSON 预览块；不用「左侧二级导航 + 长表单」这种通用后台形态。
- 判断标准：把三张稿并排，如果遮住标题就分不出谁是谁，就是失败。

### ⛔ 不要用深色块做区分（2026-10-23 用户第三次纠正，优先级最高）

- 用户原话：「**为什么要有黑色，我让你学习是那几个界面的设计，而不是要把底色搬过来，太丑了**」。
- 我犯的错：把设备页的深色**当成可复用的"设计语言"**搬到另外三页（AI 旁批深柱、任务明细深卡、设置深色 JSON 窗），结果三页变成「白卡 + 黑块」混搭。设备页的深色**只属于投屏画面本身**，是内容属性，不是版式语言，不能外溢。
- 现行结论：**除设备页的投屏舞台外，全站只用浅色体系**（`#F4F6FB` 底 / `#FFFFFF` 面板 / `#FBFCFE`·`#F7F8FC` 次色 / `#E6EAF3`·`#E9EDF5` 发丝线 / `#6C4CF5` 主色）。要区分页面，靠**卡片数量与主次关系、栏位比例、控件密度**，不靠明暗反差。
- 向设备/性能"学习"的正确对象是**排版品质**：等宽标识只给 id/端口/代次/读数、发丝线而非描边、留白节奏、读数行、浮层不排队、按内容定密度。**不是**把它们的主色/底色复制过来。

### ⚠️ 但也不能"寡淡"：用 tag / 语义色做活泼（同日第四次反馈）

- 用户原话：「颜色很寡淡，不过活泼，可以加一点 tag 啥的加一点活泼，太单调现在问题」「布局排版也不行」。
- 结论：**素 ≠ 灰白到没有信息色**。允许并鼓励的活泼手段（都在浅色体系内）：
  - **彩色图标块**：24×24 圆角 6，浅底 + 同色图标，做分组视觉索引。配色：紫 `#EFEBFF`/`#6C4CF5`、蓝 `#E8F1FD`/`#2F7FE0`、橙 `#FDF3E4`/`#D98A00`、绿 `#E6F7F1`/`#0E9F78`、红 `#FDECEF`/`#D9415E`。
  - **tag / chip**：11–12px、高 22–26、圆角 5–6、浅底同色字。用于：输入区能力提示（`@ 设备` `# 日志` `/ 命令`）、状态（`已连接` 带 5px 点）、分组锚点导航、读数（耗时绿/橙）。
  - **语义色只上在"值"上**：耗时/百分比/状态文字染色，标签仍灰。
- 排版要点（这轮修掉的）：卡片用 `height:hug_contents` + 列内 `primaryAxisAlignItems:SPACE_BETWEEN` 分布，**不要用 fill 拉高**（会拉出大空洞）；表格/列表才用 fill 撑满。
- 每页的"活泼配额"：AI 输入区 3 个能力 chip + 旁批耗时三色；设置 4 个图标块 + 4 个分组 chip + 1 个状态 chip。够了，再多就是花。

### 三页现行的浅色构图（2026-10-23 定稿）

- AI 助手：`[fill 留白 24][白纸 720 通高、圆角 2、1px 投影][1px 线][次色栏 300 #F7F8FC]`。纸装会话，次色栏装运行旁批。
- 任务与日志：底色上**两块并排卡**——次色列表卡 400 + 8px 底色缝 + 白色明细卡 flex，两卡各 `cornerRadius:8`。标题与筛选行直接浮在底色上。
- 设置：底色上浮着**四块白色参数卡**（圆角 8、`#E9EDF5` 描边、padding 18、组内行统一 `label 上 / 控件下`），右列底部一块同规格的浅色 JSON 块。
- 设备：整片深色舞台 + 浮层胶囊（仅此一页，深色属于投屏内容）。



## 满幅页面的隐形陷阱（2026-10-23 两次踩到）

- `layout.css` 的 `workplane > [data-route]` 带 `max-width:1600px; margin-inline:auto`。在弹性容器里 `margin-inline:auto` 会让**子项宽度收缩成内容宽度**，页面看着像「右边没占满」而不是报错。
- 仪器型页面（performance / ai / terminal / marketplace）与任务页都已在 layout.css 里显式写 `width:100%; margin-inline:0; max-width:none`。**新增满幅页面必须补这三条**，光在 TSX 里写 `w-full` 覆盖不了——未分层 CSS 优先于 Tailwind utilities。
- 同理，`.workplane` 默认有 `padding: 22px 24px 28px` 与 `scrollbar-gutter: stable`；舞台型页面要自己管边距时，也是在 layout.css 里按 `data-route` 关掉，不在页面里写负边距。
